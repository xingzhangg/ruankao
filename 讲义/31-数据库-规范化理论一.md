# 31 · 数据库：规范化理论(一)——函数依赖、候选码与 1NF/2NF/3NF

## 定位

一张大宽表为什么会插不进、删不掉、改不干净，以及拆到哪一步算完。第一节把业务规则写成**函数依赖**当尺子，第二节用**属性闭包**求出**候选码**当基准，第三节认出冗余的两种病灶，第四节走 1NF→2NF→3NF 三道关、判一关拆一次，第五节用无语义的字母关系把流程再走一遍。全课反复用的只有一个动作：算闭包。

## 一、烂表与函数依赖

全课跟着同一张表走：教务系统把学生、系、课程、成绩全塞进一张表。

**选课表(学号, 姓名, 系名, 系主任, 课程号, 课程名, 成绩)**

| 学号 | 姓名 | 系名 | 系主任 | 课程号 | 课程名 | 成绩 |
|---|---|---|---|---|---|---|
| S01 | 张三 | 计算机系 | 王主任 | C01 | 数据库 | 85 |
| S01 | 张三 | 计算机系 | 王主任 | C02 | 操作系统 | 78 |
| S02 | 李四 | 计算机系 | 王主任 | C01 | 数据库 | 90 |
| S03 | 王五 | 数学系 | 赵主任 | C03 | 高等数学 | 88 |

术语：一行叫**元组**（一条记录），一列叫**属性**（一个字段），行列交叉的格子叫**分量**。只描述"表名和有哪些列"、不管数据的骨架叫**关系模式**，写成 R(学号, 姓名, …)；`R(U, F)` 中 U 是全部属性集合，F 是函数依赖集合。

学号在表里重复（S01 两行），不能当主键（唯一钉住一行、不重复不为空的列或列组）；能唯一钉住一行的是 **(学号, 课程号)**——"谁 + 哪门课"对应一个确定的成绩。主键定下来，四个毛病现形：

- **数据冗余**：张三的姓名、系名各存 2 遍，"计算机系的主任是王主任"存 3 遍。它是下面三个异常的**共同根源**。
- **更新异常**：计算机系换主任要改 3 行，漏改一行，同一个系就有两个主任。
- **插入异常**：新成立物理系还没有学生选课，主键 (学号, 课程号) 填不出来，**这个系进不了库**。
- **删除异常**：王五退学删掉最后一行，数学系和赵主任跟着**陪葬**。

规范化理论要给一套能判定、可执行的规则：「属于第几范式」「毛病出在哪条依赖上」谁来判答案都一样。尺子就是函数依赖。

**函数依赖**用"两行相等"来说"决定"：从表里任取两行，只要学号相等，姓名就必须相等；能找到两行学号相同而姓名不同，就违反这条规则。

原话｜设 X、Y 是关系模式 R 的属性集，若 R 的任意一个合法实例中，任意两个元组只要在 X 上取值相等、在 Y 上取值就必然相等，则称 **X 函数决定 Y**，记作 **X→Y**，也说"Y 函数依赖于 X"。X 叫**决定因素**。类比 Y = X²：给一个 X 唯一算出一个 Y，多对一可以，一对多不行。

- 函数依赖是**语义约束，不是从数据里统计出来的**。四行里成绩恰好互不相同，也不能写"成绩→学号"。给定 F 时不许自己往里加。
- Y 是 X 子集的依赖（如 (学号,课程号)→学号）永远成立、不提供信息，叫**平凡函数依赖**。判范式只看**非平凡**的。
- 左边可以是属性组：`(学号,课程号)→成绩`。

选课表的函数依赖集：

> **F = { 学号→姓名，学号→系名，系名→系主任，课程号→课程名，(学号,课程号)→成绩 }**

F 只写业务直接规定的几条，能推出的远不止这些：学号→系名、系名→系主任 串起来，学号→系主任 照样成立。所以判范式不能只盯 F 的字面，要先把"能推出的一切"摊开——这就是属性闭包。

## 二、码与属性闭包

### （概念）码与完整性约束

"码"和"键"是同一个 key 的两种译法，含义一样。

| 名称 | 是什么 |
|---|---|
| **超键（超码）** | 能唯一标识每一行的属性组合；(学号, 课程号) 是，(学号, 课程号, 姓名) 也是，只是带了废物 |
| **候选键（候选码）** | **极小的超键**：再删一个属性就不唯一；一张表**可能不止一个** |
| **主键（主码）** | 候选键里被指定为正式主键的那个 |
| **主属性 / 非主属性** | 在**某一个**候选键里出现过就是主属性；一个都没进过的是非主属性 |
| **外键（外码）** | 本表里指向另一张表主键的属性（组），取值必须来自那张表的主键；不是本表候选码，但**可以是候选码的一部分** |

外键例子：学生(学号, 姓名, 系名) 里的"系名"指向 系(系名, 系主任)；选课(学号, 课程号, 成绩) 里的学号既是外键又是主属性。

| 约束 | 含义 |
|---|---|
| **实体完整性** | 主键约束：主键值不能为空、不能重复 |
| **参照完整性** | 外键约束：外键值要么是被参照表里已存在的主键值，要么为空 |
| **用户自定义完整性** | 业务规定的表达式约束，如"年龄必须在 0 到 150 之间" |

开头"物理系进不了库"的插入异常，卡住它的正是实体完整性——主键 (学号, 课程号) 没值可填。

2NF、3NF 的条件都是"**非主属性**对**码**如何如何"，所以判范式先求码。

### （计算）属性闭包与候选码

判"某组属性是不是超键"，等价于问它顺着 F 能推出的属性够不够全部。

**属性闭包 X⁺（滚雪球）**：把 X 放进袋子；反复扫 F，**哪条依赖的左边已经整个在袋子里，就把右边倒进袋子**；扫完一整轮没有新属性进袋就停。袋子里的全部属性记作 **X⁺**。

- 左边要**全部**在手：`AB→C` 是 A、B 一起才定得了 C。
- 要**反复**扫：新进袋的属性会让原本用不上的依赖变得可用。
- 一定会停：属性有限，袋子只增不减，最多 |U| 轮。

算例：(学号, 课程号)⁺，初始 `{学号, 课程号}`

```
学号→姓名          左边在袋 → 收 姓名     {学号,课程号,姓名}
学号→系名          左边在袋 → 收 系名     {…,系名}
课程号→课程名      左边在袋 → 收 课程名   {…,课程名}
(学号,课程号)→成绩  两个都在 → 收 成绩     {…,成绩}
系名→系主任        系名刚进袋 → 收 系主任  {全部 7 个}   ← 要反复扫的理由
再扫一轮无新增 → 停
```

- (学号, 课程号)⁺ = 全部 7 个 ⇒ **超键**。
- 真子集：(学号)⁺ = {学号, 姓名, 系名, 系主任}，(课程号)⁺ = {课程号, 课程名}，都不全 ⇒ 删无可删 ⇒ **(学号, 课程号) 是候选码**。
- 主属性：学号、课程号；非主属性：姓名、系名、系主任、课程名、成绩。

**求候选码三步法**（属性组合有 2ⁿ 种，先按出现位置砍掉大部分）：

1. **左独必在码**：只出现在依赖左边的属性（以及左右都不出现的属性）没有任何依赖能推出它，**每一个**候选码都必须含它。
2. **右独必不在**：只出现在右边的属性一定能被别人推出，放进码里就是多余的，**任何**候选码都不含它。
3. **两边出现试着补**：先把第 1 类属性合起来求闭包，推全了就是唯一候选码；推不全，就从两边都出现的"待定"属性里逐个补进去再算闭包（一个不够就两个两个补），找出所有**极小**组合。

选课表只在左边出现的是学号、课程号，合起来一次推全，候选码唯一；"逐个补"的完整走法见第五节。

## 三、冗余的两种病灶

| 依赖长这样 | 判成 | 后果 |
|---|---|---|
| X→Y 里 Y 是 X 的子集 | 平凡函数依赖 | 判范式跳过 |
| 码的**一部分**就推得出某个非主属性 | **部分函数依赖** | 卡 2NF |
| 去掉码里任何一个属性都推不出它 | **完全函数依赖** | 没毛病 |
| 码→Y→Z，且 Y↛码、Z 不在 Y 里、Y 不是码的子集 | **传递函数依赖** | 卡 3NF |
| 中间项 Y 里含主属性 | 照样是传递依赖 | 卡 3NF |
| 候选码**全是**单属性 | 不可能有部分依赖 | 至少 2NF |
| 一个非主属性都没有 | 部分、传递都无从违反 | 自动 3NF |

原话｜X→Y 成立时，若 X 的**某个非空真子集** X′ 也能推出 Y，称 Y **部分函数依赖**于 X；若 X 的任何非空真子集都推不出 Y，称 Y **完全函数依赖**于 X。X→Y，Y 不是 X 的子集且 Y↛X，又有 Y→Z 且 Z 不在 Y 里，称 Z **传递函数依赖**于 X。

**易混对①：完全依赖 vs 部分依赖**

- 判据｜遮住码的一部分，剩下半个码还推得出它 ⇒ 部分；必须整个码一起才推得出 ⇒ 完全。左边是单属性时没有非空真子集，不可能是部分依赖，所以**候选码全是单属性时不可能有部分依赖**；但一张表若既有单属性码又有组合码，组合码那边照样可能有部分依赖。另一种说法"A 可确定 C，(A,B) 也可确定 C，则 C 部分依赖于 (A,B)"是同一件事。
- 例子｜`(学号,课程号)→姓名` 是部分依赖——光学号就够。于是张三每多选一门课，姓名、系名、系主任就重抄一遍，**抄多少遍由选课门数决定，而这几列跟课程无关**（课程名同理，只由课程号决定，每多一个学生选"数据库"就多抄一行）。`(学号,课程号)→成绩` 是完全依赖——只知道张三或只知道"数据库"都推不出分数。若码换成单属性学号，`学号→姓名` 就成了完全依赖——完全/部分是**相对码**说的。

**易混对②：部分依赖 vs 传递依赖**

- 判据｜毛病出在"只用了半个码" ⇒ 部分；毛病出在"码和它中间隔了一层" ⇒ 传递。看到 X→Y→Z 还要验三个附加条件（见下表），中间项 Y 含主属性不影响判传递。
- 例子｜学号→系名，系名→系主任：系主任跟码隔了一层，"计算机系的主任是王主任"被该系每个学生的每一行各抄一遍，学生删光这条事实也消失——**删除异常就是这么来的**。若业务改成系主任由学号直接指定，`系名→系主任` 没了，传递依赖和删除异常一起消失。

| 传递依赖的附加条件 | 少了它会怎样 |
|---|---|
| **Y↛X** | Y 也能推回 X，说明 X、Y 互相决定（等价），Z 对 X 是直接依赖，不叫传递 |
| **Z 不在 Y 里** | 否则 Y→Z 是平凡依赖 |
| **Y 不是 X 的子集** | X 是组合码 AC、Y 只取 A 时，毛病是"只依赖半个码"，记在部分依赖账上 |

## 四、三道关：判一关，拆一次

**范式**（Normal Form，NF）是关系模式的合格等级，条件逐级变严，满足高一级必然满足低一级。本课管前三关，BCNF 在讲义 32。

**1NF：每一格都是不可再分的原子值**，表里不许嵌小表。反例：

| 员工编号 | 员工姓名 | 出生日期 | 薪资/月（基本工资/月 · 补贴/月） | 所属部门 |
|---|---|---|---|---|
| 1 | 王红 | 19900908 | 9000 · 1000 | 101 |

"薪资/月"一格塞两个数，不满足 1NF，改法是拆成"基本工资""补贴"两列。同类反例：一格塞"电话13800000000；邮箱a@b.com"，或一格塞三门课的成绩。关系数据库建出来的表默认满足 1NF，所以判定结果"最高 1NF"几乎都是**卡在 2NF**，不是真嵌了小表。

**2NF：1NF，且每个非主属性都完全函数依赖于每一个候选码**（无部分依赖）。

- 检查：候选码是单属性 → 直接过；是组合 → 对它的每个非空真子集 K′ 求 K′⁺，里面有非主属性就是部分依赖。多个候选码**每个都要查**，一个码上查出即违反。
- 分解：**把只依赖半个码的属性连同那半个码搬出去另立一张表，原表留那半个码当外键。**

**3NF：2NF，且每个非主属性都不传递依赖于任何候选码**（教材第 5 版以 2NF 为前提）。

- 检查：分解后**逐表回头重判**。
- 分解：**把被中间项决定的属性连同中间项搬出去，原表留中间项当外键。**
- 等价判据：F 中每条依赖右边拆成单属性，逐条看非平凡 X→A，出现"**X 不是超码且 A 是非主属性**"即违反 3NF；每条都"左边是超码或右边是主属性"即满足。它本身蕴含 2NF，不用找中间项、不用验 Y↛X。
- 前提必须是 2NF：若只要求"1NF + 无传递依赖"，R(A,B,C)、F={A→C}（码 AB）里 C 部分依赖于码却找不出任何传递依赖，会被误判为 3NF，实际是 1NF。判定固定走"先查部分、再查传递、卡住即停"，或直接用等价判据。

**算例：选课表一路拆到 3NF**

1. 1NF：每格单值 ✓。
2. 2NF：码 (学号, 课程号)，(学号)⁺ 含姓名、系名、系主任三个非主属性 ⇒ 部分依赖 ⇒ **整表卡在 1NF**。（违反 2NF 的理由是非主属性只依赖半个码，不是"学号不能完全确定课程号和成绩"——后者只说明码必须是组合的。）
3. 按 2NF 分解：
   ```
   学生(学号, 姓名, 系名, 系主任)     码：学号
   课程(课程号, 课程名)               码：课程号
   选课(学号, 课程号, 成绩)           码：(学号,课程号)；外键：学号、课程号
   ```
4. 逐表判 3NF：
   - 课程：码是单属性，唯一非平凡依赖的左边就是码 ✓
   - 选课：唯一非主属性"成绩"由整个码完全决定 ✓
   - **学生**：码是单属性学号 → 过 2NF；学号→系名、系名→系主任，(系名)⁺ = {系名, 系主任} 推不回学号 ⇒ 系主任传递依赖于码 ⇒ **卡在 2NF**。症状仍在：系主任随每个学生重抄，某系最后一名学生退学、系和主任一起消失——**删除异常 2NF 治不好**。等价判据核对：`系名→系主任`，系名非超码、系主任非主属性 ⇒ 违反，结论一致。
5. 按 3NF 分解学生表，终点四张表：
   ```
   学生(学号, 姓名, 系名)     码：学号；外键：系名 → 系
   系(系名, 系主任)           码：系名
   课程(课程号, 课程名)       码：课程号
   选课(学号, 课程号, 成绩)   码：(学号,课程号)；外键：学号、课程号
   ```
6. 回测：新成立物理系没学生 → 直接插"系"表 ✓；某系学生删光 → 系表不受影响 ✓；换主任 → 只改系表一行 ✓。

3NF 只管非主属性，主属性之间的毛病归 BCNF；BCNF、4NF 以及分解的两笔代价（无损连接、保持依赖）在讲义 32，工具仍是闭包。

## 五、字母关系：同一套流程再走一遍

没有业务语义时只能纯机械地走流程；而选课表候选码唯一，绕过了三步法最容易错的第 3 步，所以再走一个抽象例子。

**R(A,B,C,D)，F = { AB→C，C→D，D→A }**，常见错误是只写出 AB 一个候选码。

1. **分类**：左边出现 A、B、C、D；右边出现 C、D、A。只在左边：**B**（必在每个候选码中）；只在右边：无；两边都有：A、C、D（待定）。
2. **从必在码的属性起步**：(B)⁺ = {B}，必须补。
3. **逐个补待定属性，每补一个算一次闭包**：
   ```
   (AB)⁺：AB→C 收 C，C→D 收 D → {A,B,C,D} 全 ✓
           (A)⁺={A}、(B)⁺={B} 都不是超码 ⇒ AB 极小 ⇒ 候选码
   (BC)⁺：C→D 收 D，D→A 收 A → 全 ✓
           (C)⁺={A,C,D} 缺 B ⇒ BC 极小 ⇒ 候选码
   (BD)⁺：D→A 收 A，A、B 齐了 → AB→C 收 C → 全 ✓
           (D)⁺={A,D} 缺 B ⇒ BD 极小 ⇒ 候选码
   ```
4. 三个待定属性各补一次都推全了，不必两个两个补——更大的组合都包含上面某个候选码，不可能极小。

**候选码 AB、BC、BD 三个**，四个属性全是主属性，没有非主属性 ⇒ **自动满足 3NF**。（到不了 BCNF：`C→D` 的左边 C 不是超码，见讲义 32。）

判超键、验极小、查部分依赖（码的真子集的闭包）、验传递依赖的 Y↛X，全都是**算闭包**。

## 速记

- 三宗罪：**插不进 = 插入异常，陪葬 = 删除异常，改漏 = 更新异常**，根源都是数据冗余
- 求码三句：**左独必在码，右独必不在，两边出现试着补**；闭包滚雪球：**左边凑齐才能收，滚不动就停**
- 候选码 = 极小的超键，**可能不止一个**；主属性 = 进过**某一个**候选码就算，其余为非主属性
- **一范原子、二消部分、三消传递**；四步走：求码 → 分主/非主 → 查部分 → 查传递，**卡住即停，答上一级**
- 候选码**全是**单属性 ⇒ 无部分依赖 ⇒ 至少 2NF；无非主属性 ⇒ 自动 3NF；传递依赖别忘验 **Y↛X**，且中间项不能只是码的一部分
- 3NF 等价判据：每条非平凡 X→A，**要么左边是超码，要么右边是主属性**
- 分解动作只有一个：**病灶属性 + 它真正的决定者一起搬出去，原表留外键**；分解完必须逐表重判
- 三类约束：**实体** = 主键非空不重，**参照** = 外键有出处或为空，**用户自定义** = 业务表达式
