# 47 · 穿插小板块：专业英语

## 定位

专业英语读的是计算机类英文短文，题材以软件工程与项目管理为主，其次是云计算与虚拟化、信息安全、数据库/Web、虚拟现实、语义网。这类短文多是技术随笔（如《人月神话》《没有银弹》的摘段）：句子长、修辞多、术语反而少，难点在读懂逻辑而不在词汇量。本课三节：按主题分组的词汇速查、易混词与反义词组、读长难句的方法。

## 一、专业词汇速查（按主题）

**项目管理 / 软件过程**

| 英文 | 中文 |
|---|---|
| project | 项目 |
| sequence | 序列（统领一串活动） |
| activity / task / work | 活动 / 任务 / 工作 |
| specification(s) | 规格说明 |
| requirement / expectation | 需求 / 期望 |
| estimate | 估算 |
| deadline / time frame | 截止期 / 时间框架 |
| budget / cost | 预算 / 成本 |
| scoping / planning / staffing / organizing / directing / controlling | 确定范围 / 计划 / 人员配备 / 组织 / 指导 / 控制 |
| process management | 过程管理 |
| methodology | 方法论 |
| deliverable | 交付物 |
| quality standard | 质量标准 |
| acceptable | 可接受的 |
| resources / managers | 资源 / 管理者 |
| communicate / communication | 沟通 |

**原话｜** A project is a temporary sequence of unique, complex, and connected activities having one goal or purpose and that must be completed by a specific time, within budget, and according to specifications.（项目＝一次性的、唯一的、复杂且相互关联的活动序列，有一个目标，须按时、在预算内、按规格说明完成。）

**原话｜** Project management 是 scoping, planning, staffing, organizing, directing, and controlling 的过程，目标是以最低成本（minimum cost）、在限定时间（specified time frame）内开发出**可接受的**（acceptable）系统。过程管理（process management）管的是一个组织选定的方法论，其活动、交付物、质量标准适用于该组织的**全部**项目。

**信息安全（访问控制）**

| 英文 | 中文 |
|---|---|
| access control | 访问控制（对地点或资源的选择性限制访问） |

## 二、易混词与反义词组

**同向一组 vs 反向词**：下列每行左边三个意思相近，右边一个意思相反或异类。

| 同向的三个 | 反向 / 异类 |
|---|---|
| trivial / minor / insignificant（不重要的） | **crucial**（关键的） |
| by themselves / separately / alone（各自） | **together**（一起） |
| frequently / usually / commonly（经常） | **rarely**（很少） |
| almost / often / usually | **barely**（几乎不） |
| worthless / valueless / useless（没价值） | **invaluable**（无价的） |
| other / different / another（别的） | **same**（相同的） |
| occasionally / infrequently / rarely（偶尔） | **periodically**（定期地） |
| possible / sensible / practical（可行的） | **impossible**（不可能的） |
| surface / outside / exterior（表面的） | **essential**（本质的） |
| agreement / cooperation / collaboration（合作） | **competition**（竞争） |
| total / complete / entire（全部的） | **partial**（部分的） |
| a single / a particular / some（某个、某些） | **all**（全部） |

**invaluable vs valueless**
判据｜in- 在这里不是否定：invaluable＝价值大到无法估量；valueless / worthless＝没价值。
例子｜an invaluable tool 是「极宝贵的工具」，换成 a valueless tool 意思正相反。

**barely / rarely vs frequently / often**
判据｜barely、rarely 自带否定义（几乎不、很少），句中没有 not 也是否定。
例子｜Such errors are rarely found＝这类错误很少出现；换成 frequently 就是经常出现。

**periodically vs occasionally**
判据｜periodically 有固定周期（定期）；occasionally / infrequently 无规律（偶尔）。
例子｜备份 periodically＝按计划定期做；occasionally＝想起来才做。

**authenticate vs authorize**
判据｜认证解决「你是谁」，授权解决「你能干什么」；先认证后授权。
例子｜输入口令登录是 authentication；登录后能否读某个文件由 authorization 决定。

**mediate vs connect**
判据｜mediate 是夹在中间做判定（放行或拦下）；connect 只是连通，没有控制含义。
例子｜access control mechanism mediates between a user and system resources——是仲裁，不是连接。

**component vs mechanism**
判据｜component 是具体的、可以有多个并协同工作的部件；mechanism 是抽象的机制，常用单数。
例子｜操作系统的访问控制部件、附加安全包、DBMS、防火墙是若干 components；「一种访问控制机制」是 a mechanism。

**add-on vs native**
判据｜add-on＝后加上去的；native＝本来自带的，两者成对出现构成对照。
例子｜add-on security packages add to the native capabilities of the OS：附加包补充的是 OS 自带的能力。

**acceptable vs perfect**
判据｜项目管理追求在最低成本、限定时间内做出可接受的系统，「完美」与这两个约束矛盾。
例子｜develop an acceptable system at a minimum cost；把 acceptable 换成 perfect 就与 minimum cost 冲突。

**sequence vs activity / task**
判据｜sequence 统领一串东西；activity、task 本身就是单个活动。
例子｜a sequence of activities＝一串活动；an activity of activities 语义空转。

**deadline / budget / specifications**
判据｜项目三约束：时间、成本、规格，各管一个维度，并列时不会重复。
例子｜meets the deadline（时间）、within budget（成本）、fulfills specifications（规格）。

其余认名即可：grant（授予）、permit（允许）、estimate（估算）、requirement（需求）、expectation（期望）、robust（健壮的）、rudimentary（基本的）。

## 三、读长难句的方法

技术随笔句子长、修辞多，逐词翻译慢且定不了意思。按下面顺序读：

1. **先读首句和末句定主题。** 认出在讲项目管理还是访问控制，中文学过的知识就能兜底推断生词。
2. **找谓语，拆骨架。** 先找主句谓语，再把并列成分竖着排开；并列的几项是不同维度，不会重复。
   ```
   ensure that the project ┬ meets the deadline                       ← 时间
                           ├ is developed within an acceptable budget ← 成本
                           └ fulfills customer expectations and specifications ← 期望与规格
   ```
3. **看词性与搭配。** 介词后只能接名词或 -ing 形式（the technology of interacting with a computer）；`at the ___ of` 中间只能是名词（worth / value / cost 可以，形容词 invaluable 不行）；固定搭配直接定义：grant access、according to specifications、on behalf of。
4. **找上下文复现。** 关键词常在同篇别处原样或以变形（单复数、时态、词尾）再次出现，可借那一处理解；但眼熟的词不一定是这里要的意思，复现后还要核语法位置和语义。
5. **找对照信号。** add-on ↔ native、but、instead 这类词提示前后意思相反；一组近义词里单独反向的那个往往是作者要强调的点。
6. **用常识与领域知识验证。** 「最低成本＋限定时间」与「完美系统」矛盾；「方法论」是给组织全部项目用的，`project(s)` 的 (s) 也在提示复数。

## 速记

> **短文**：以软件工程、项目管理为主，随笔体，句长术语少，难在逻辑不在词汇。
> **项目三约束**：deadline（时间）/ budget（成本）/ specifications（规格）；项目管理目标是 acceptable system，不是 perfect。
> **安全**：authentication 你是谁 → authorization 能干什么；mediate 居中仲裁，grant access 授予访问，auditing 记录。
> **易错词**：invaluable＝无价的；barely / rarely 自带否定；periodically＝定期；add-on ↔ native。
> **反义组**：三个近义＋一个反向，反向的那个是强调点（crucial、rarely、partial、competition……）。
> **读法**：首末句定主题 → 找谓语拆并列 → 看词性搭配 → 找复现 → 找对照 → 常识验证。
