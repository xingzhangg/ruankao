## 第 1 层 · 理解

### 一句话

> 结构化方法就一个信条：**跟着数据走**。把整个系统看成一条"数据加工流水线"——**分析阶段只画数据怎么流（DFD），设计阶段再把流水线切成模块（结构图）**。它不关心"有哪些对象"，只关心"数据从哪来、被谁加工、到哪去"。

### 痛点：三个人对同一份需求文档，理解出三个系统

你一定见过这种场景：

- **需求文档三十页纯文字**，写着"系统应支持考生报名并统计成绩"。产品经理脑子里想的是一回事，你脑子里想的是另一回事，测试同学想的是第三回事。**争论到最后发现，大家连"报名单交给谁、存在哪"都没对齐。**
- **"这个字段哪来的？"** —— 排查线上问题时，你顺着代码一层层往上翻，翻了两小时才发现某个字段是三个模块之前从一张临时表里读出来的。**没有人画过一张"数据从哪流到哪"的图。**
- **接口对不上**：A 组说"我给你传的是考生名册"，B 组说"我要的是正式报名单"。**两边说的是不是同一份数据？没人能一句话说清。**

结构化方法给出的答案很朴素：**别写散文，画图**。而且规定死了这张图只能用四种符号，谁画都一样，谁看都一个意思。

### 一条主线（本课的骨架，看懂这条就懂了整章）

```
业务的本质 = 一堆"数据被加工"的过程
   ↓ 用文字描述会走样 → 改成画图，且只允许四种符号
   ↓
【DFD 四元素】外部实体（数据从哪来/到哪去）
              加工（数据在这里被变换）
              数据存储（数据在这里歇脚）
              数据流（数据本身，带名字的箭头）
   ↓
   四种符号一组合，就能自动暴露三类荒谬：
        只进不出 = 黑洞    只出不进 = 奇迹    进得太少不够产出 = 灰洞
   ↓ 但真实系统一张图画不下（几十个加工挤成蜘蛛网）
   ↓
【分层 DFD】顶层图（整个系统缩成 1 个加工，只看它和外界怎么交互）
            0 层图（拆成若干加工 P1…Pn，数据存储 D1…Dn 在这一层首次出现）
            1 层图（把某个加工再拆开）
   ↓ 一分层就冒出新麻烦：拆开的子图，会不会和父图对不上？
   ↓
【平衡原则】子图的输入输出，必须和父图那个加工的输入输出**一模一样**
   ↓ 图画完了，但图只说了"流向"，没说"内容"和"细节"
   ↓
【数据字典 DD】给每条数据流/数据项/数据存储写清楚"由什么组成"（= + [|] {} 四个符号）
【加工逻辑】  给每个最底层加工写清楚"到底怎么算"（结构化语言 / 判定表 / 判定树）
   ↓ 分析结束。可这还是"业务视角"，不是"程序视角"
   ↓
【DFD → 结构图】把数据流图翻译成模块调用树
        流水线型（输入→变换→输出）  → 变换型分析
        中央调度型（收到请求分发给不同分支）→ 事务型分析
   ↓ 翻译出来的模块切得好不好？
   ↓
【回到讲义 16】用"高内聚、低耦合"这把尺子量
```

**一句话收口**：`DFD 是"数据视角的业务地图"，数据字典是这张地图的"图例"，结构图是这张地图翻译成的"施工图"。`

## 第 2 层 · 考点：考试怎么问

### 考点① DFD 四元素识别 + 三种错误（上午 + 下午都考）

**四元素**：

| 元素 | 画法 | 含义 | 一句话抓手 |
|---|---|---|---|
| **外部实体**（外部主体） | 方框 □ | 存在于**软件系统之外**的人员或组织，是数据的**发源地（源）**和**归宿地（宿）** | 「**系统管不着的人/系统**」 |
| **加工**（处理） | 圆 ○ 或圆角矩形 | 描述输入数据流 → 输出数据流之间的**变换** | 「**动词**」：检查报名表、统计成绩 |
| **数据存储**（文件） | 双横线 ═ 或右开口框 | 暂存数据 | 「**名词+表/册/库**」：考生名册 |
| **数据流** | 带名字的箭头 → | 一组固定成分的数据，表示流向 | 「**名词**」：报名单、准考证 |

**题目长什么样（上午）**：
> 在结构化分析中，用数据流图描述（ ）。当采用数据流图对一个图书馆管理系统进行分析时，（ ）是一个外部实体。
> A. 数据对象之间的关系，用于对数据建模
> B. **数据在系统中如何被传送或变换，以及如何对数据流进行变换的功能或子功能，用于对功能建模**
> C. 系统对外部事件如何响应，如何动作，用于对行为建模
> D. 数据流图中的各个组成部分
> —— A. **读者**　B. 图书　C. 借书证　D. 借阅
> **答案：B　A**　【真题·年份待核实】（该题在外部培训资料的软件工程、结构化开发方法两章重复出现，均未标年份）

**怎么解**：
- 第一空是**三选一的固定辨析**，背死这张对照表即可：

| 模型 | 图 | 建什么模 |
|---|---|---|
| **功能模型** | **数据流图 DFD** | **数据如何被传送/变换 → 对功能建模** |
| 行为模型 | 状态转换图 STD | 系统对外部事件如何响应 → 对行为建模 |
| 数据模型 | E-R 图 | 数据对象之间的关系 → 对数据建模 |

- 第二空找外部实体，判据只有一条：**它是不是系统管不着的？** 读者是人，系统管不着他，是外部实体；图书/借书证是数据，借阅是动作（加工）。

**陷阱**：
- ⚠️ **别把"数据"当外部实体**。图书、借书证都是系统内部要存的数据，不是实体。
- ⚠️ **DFD 不是流程图**。流程图有判断菱形、有执行顺序；**DFD 没有任何控制逻辑，箭头只表示数据流向，不表示先后**。

---

**三种错误（下午题第四问的简答，可能出现在第四问，务必背名字）**：

| 错误名 | 表现 | 记法 |
|---|---|---|
| **黑洞**（black hole） | 加工**只有输入、没有输出** | 数据掉进去出不来 |
| **奇迹**（miracle） | 加工**只有输出、没有输入** | 数据凭空变出来 |
| **灰洞**（grey hole） | 加工**输入不足以产生输出** | 输入两个字段却要输出十个字段 |

![DFD 三种常见错误：黑洞 / 奇迹 / 灰洞（外部资料原图）](../外部资源/转录md/images/fig_d15_s005.png)

**陷阱**：⚠️ **灰洞最不容易看出来**，因为它形式上"有进有出"。判断灰洞要看**内容**够不够，不是看**有没有**。

### 考点② DFD 的八条设计原则（下午题改错与判题的依据）

这八条是下午题第三问"补充缺失数据流"时的**判据**，也是上午题辨析题的出处：

1. **数据守恒原则**：任何一个加工，**所有输出数据流中的数据必须能从该加工的输入数据流中直接获得**，或通过该加工产生。
2. **守恒加工原则**：同一个加工，**输入与输出的名字必须不同**——即使组成成分完全相同。
3. 每个加工，必须**既有输入数据流，又有输出数据流**（这条直接排除黑洞和奇迹）。
4. **外部实体与外部实体之间不存在数据流**。
5. **外部实体与数据存储之间不存在数据流**。
6. **数据存储与数据存储之间不存在数据流**。
7. **父图与子图的平衡原则**：**子图的输入输出数据流，同父图相应加工的输入输出数据流必须一致**。
8. **数据流与加工有关，且必须经过加工**。

**四五六三条可以合并成一句口诀**：
> **「实体、存储之间不直连，凡数据流必过加工」**
> 即：□↔□ ✗，□↔═ ✗，═↔═ ✗，任何箭头两端**至少有一端是加工○**。

**题目长什么样**：下午题第三问给你一张 0 层图，问"补充缺失的数据流及其起点和终点"，答案要填成表格：

| 序号 | 起点 | 终点 | 名称 |
|---|---|---|---|
| 1 | P5 | E2 | 物流信息 |

**怎么解**：**不要一上来就套八条原则**。外部资料的解题技巧明确指出——
> **详细阅读题目描述，依据题目描述对涉及的数据流图进行一一核对，这是最为简单直接的方法**。因为即使开始就去考虑数据守恒、父图子图平衡等原则，最终还是要根据题目描述核对，不如一开始就直接核对。

八条原则的真正用途是**验算**：填完之后，拿原则 4/5/6 快速扫一眼，凡是"实体连实体""存储连存储"的必定填错了。

**陷阱**：
- ⚠️ **原则 7（父子平衡）只在"父图-子图之间"成立，单张图内不存在平衡问题**。这是上午辨析题的常见错误选项。
- ⚠️ **原则 2 容易被忽略**：某加工输入"成绩清单"、输出也叫"成绩清单"——即使数据一模一样也算错，必须改名（如"已校验成绩清单"）。

### 考点③ 分层数据流图

| 层 | 里面有什么 | 关键特征 |
|---|---|---|
| **顶层图**（上下文图 / 上下文无关图） | **有且仅有一个加工**，代表整个系统 | **描述系统与外部实体的交互**；**顶层图里不出现数据存储** |
| **0 层图** | 系统拆成若干加工 P1…Pn | **数据存储 D1…Dn 在这一层首次出现** |
| **1 层图**及以下 | 把 0 层某个加工再拆开 | 加工编号继承父编号：P1 拆成 1.1、1.2、1.3 |

![分层数据流图：顶层图 / 0 层图 / 加工 1 的 1 层图 / 加工 2 的 1 层图（外部资料原图）](../外部资源/转录md/images/fig_d13_s012.png)

**这张图务必看懂三件事**：
1. (a) **顶层图**只有一个大方框（系统），四周是考生、考试中心、阅卷站三个外部实体——**没有任何数据存储**。
2. (b) **0 层图**里出现了加工 1（报名登记表）、加工 2（统计成绩），以及数据存储"考生名册"。
3. (c)(d) **1 层图**把加工 1 拆成 1.1/1.2/1.3，把加工 2 拆成 2.1~2.5——**编号带父级前缀**。

**题目长什么样（上午）**：
> 下列关于分层数据流图的叙述中，**错误**的是（ ）。
> A. 顶层图中只有一个加工，代表整个系统
> B. 数据存储从 0 层图开始出现，顶层图中不画数据存储
> C. **父图与子图之间要平衡，同一张图内部也存在平衡问题**
> D. 子图的加工编号继承父图加工的编号
> **答案：C**　【模拟】

**怎么解**：抓三个判据——① 顶层图**几个加工**（答案：1 个）；② 数据存储**从哪层开始**（答案：0 层）；③ 平衡**存在于哪两者之间**（答案：只在父图与子图之间，单张图内不存在）。

**陷阱**：
- ⚠️ **顶层图不画数据存储**。这是下午题第二问（补数据存储）为什么总是"出现在 0 层图"的原因。
- ⚠️ 加工编号是 **1、1.1、1.1.1** 这样带层级的，不是从头连续编。

### 考点④ 数据字典 DD（四类条目 + 四个符号）

**数据字典就是为 DFD 中的每个数据流、文件、加工，以及组成它们的数据项做出说明。** DFD 描述了系统的分解，但没有对图中各成分进行说明——DD 补的就是这块。

**四类条目**：**数据流、数据项、数据存储、基本加工**。

**四个符号（下午题第四问可能直接考写法）**：

| 符号 | 含义 | 举例 |
|---|---|---|
| **=** | 被定义为 | |
| **+** | 与 | `x = a + b`，表示 x 由 a 和 b 组成 |
| **[…\|…]** | 或 | `x = [a\|b]`，表示 x 由 a **或** b 组成 |
| **{……}** | 重复 | `x = {a}`，表示 x 由 **0 个或多个** a 组成 |

![数据字典符号表（外部资料原图）](../外部资源/转录md/images/fig_d13_s013.png)

**题目长什么样（下午题第四问的一种变体）**：
> 根据说明中术语，给出图 1-1 中数据流"客户信息"、"房源信息"的组成。
> **答案**：客户信息 = 身份证号 + 姓名 + 手机号 + 需求情况 + 委托方式；房源信息 = 基本情况 + 配套设施 + 交易类型 + 委托方式 + 业主。
> 【真题·2018下】（来源：外部培训资料"历年典型真题 2·房屋中介信息系统"；年份 2026-09-06 审核核实）

**怎么解**：**直接回题干找那句话**。这类问法本质是阅读理解——题干里必定有一句"客户信息包括身份证号、姓名、手机号、需求情况、委托方式等"，照抄即可。

**陷阱**：⚠️ `{a}` 是 **0 个或多个**，不是"1 个或多个"。

### 考点⑤ 加工逻辑（小说明）的三种描述方法

加工逻辑也称为「**小说明**」，描述**最底层加工**到底怎么算。常用三种方法：

| 方法 | 长什么样 | 什么时候用 |
|---|---|---|
| **结构化语言** | 用 if/else/while 这样的伪代码写 | **下午题第四问最常考的形式** |
| **判定表** | 条件桩/动作桩组成的表格 | 条件多、组合复杂时 |
| **判定树** | 树形分支 | 条件层次清楚时，比判定表直观 |

> 📌 **判定表**已在讲义 17（软件测试）作为黑盒用例设计方法讲过；**判定树本课补讲**（讲义 17 未涉及）：
>
> **判定树**是判定表的树形画法，从左到右按条件逐层分叉，叶子是动作。同样的规则：
> ```
>              ┌─ 学时≥60 ─┬─ 成绩≥60 → 发结业证
>   学员类型 ──┤            └─ 成绩<60 → 补考
>              └─ 学时<60  ─────────────→ 不予结业
> ```
> **判定表 vs 判定树怎么选**：条件多、组合密 → 判定表（不易漏组合）；条件有明显层次 → 判定树（更直观）。下午题第四问若点名要「判定表」或「判定树」，就按对应形式画；只说「加工逻辑」时，**优先写结构化语言**。

**题目长什么样（下午题第四问的两种形态之一）**：
> 根据说明，采用**结构化语言**对"P5：寻找物流商"的加工逻辑进行描述。（3 分）

**怎么解**：把题干里那段业务规则**逐句翻译成 if/else/while**。评分按点给，写成伪代码即可，不要求语法正确。

**陷阱**：⚠️ 题目要求"结构化语言"时**不要画判定树**，也不要写大段中文散文——必须是**带缩进的伪代码结构**。

### 考点⑥ DFD 转结构图：变换型与事务型

> ⚠️ **本考点外部培训资料未展开讲**，但它是官方大纲「**1.2 数据流图变换**」的明确内容，且是"分析产物如何变成设计产物"这条主线的收口。**未检索到已核实的真题年份，按大纲固定内容处理，标注为待核实。**

分析阶段画完 DFD，设计阶段要把它变成**模块结构图**（谁调用谁的树）。教材给了两条转换路线，先判断 DFD 属于哪一型：

| 类型 | DFD 长什么样 | 转换出的结构图 |
|---|---|---|
| **变换型**（transform） | 一条**流水线**：输入流 → **变换中心** → 输出流。能明显切出"取数据 / 加工数据 / 送数据"三段 | 顶层主模块下挂**输入模块、变换模块、输出模块**三个分支 |
| **事务型**（transaction） | 一个**事务中心**接收输入，根据类型**分发**给若干条互不相干的活动路径 | 顶层主模块下挂**接收模块 + 调度模块**，调度模块再分发给各事务处理模块 |

**题目长什么样**：
> 某系统的数据流图如下：读取原始订单 → 校验订单 → 计算折扣与总价 → 生成发货单 → 输出发货单。若采用变换分析设计其模块结构图，则顶层主模块下应划分为（ ）三个分支。
> A. 接收模块、调度模块、执行模块　B. **输入模块、变换模块、输出模块**
> C. 主控模块、事务模块、数据模块　D. 取数模块、判断模块、分发模块
> **答案：B**　【模拟】

**怎么解**：先判型（这条是流水线、中心在「计算折扣与总价」→ **变换型**），再套该型的顶层三分支。

**一句话判别**：
> 看那个中心加工——**它是在"加工"数据（变换型），还是在"分发"数据（事务型）**？
> 出现"根据……类型，分别执行……"的字眼，基本就是事务型。

**陷阱**：⚠️ 真实系统往往是**混合型**——整体是事务型，某个分支内部是变换型。教材做法是**先按事务型切出分支，再对每个分支单独做变换分析**。

### 考点⑦ 结构化设计的四项任务 + 结构图的五种符号

> ⚠️ 本考点是**上次遗漏的缺口**：外部资料转录 13「结构化设计方法」整节此前未纳入本课，而它正是下面那道真题的考点。

**结构化设计（SD）是一种面向数据流的设计方法**，用**结构图**描述软件体系结构。

**结构图由五种基本符号组成**：**模块、调用、数据、控制、转接**。

**结构化设计的四项任务**：

| 任务 | 干什么 |
|---|---|
| **体系结构设计** | 定义软件的**主要结构元素及其关系** |
| **数据设计** | 基于 **E-R 图**确定文件系统结构与数据库表结构 |
| **接口设计** | 描述**用户界面、软硬件外部接口、构件间内部接口** |
| **过程设计** | 确定各组成部分内的**算法及内部数据结构** |

**题目长什么样**：
> 在采用结构化开发方法进行软件开发时，设计阶段**接口设计**主要依据需求分析阶段的（ ）。接口设计的任务主要是（ ）。
> A. **数据流图**　B. E-R 图　C. 状态-迁移图　D. 加工规格说明
> A. 定义软件的主要结构元素及其之间的关系
> B. 确定软件涉及的文件系统的结构及数据库的表结构
> C. **描述软件与外部环境之间的交互关系，软件内模块之间的调用关系**
> D. 确定软件各个模块内部的算法和数据结构
> **答案：A　C**　【真题·年份待核实】（外部资料转录 13，未标年份）

**怎么解**：把四项任务与四个选项**一一对号**——A 选项=体系结构设计、B=数据设计、C=接口设计、D=过程设计。第一空记住「**接口设计依据数据流图**」（因为 DFD 画的就是数据在系统内外怎么流）。

**陷阱**：⚠️ **数据设计依据 E-R 图，接口设计依据数据流图**，两者别对调。

## 完整算例

### 算例 A：给一段业务描述，判断三种错误

**题目【改编·外部资料原图】**：下图是某会员系统 DFD 的一个片段，三个加工各有问题。指出各属于哪类错误。

```
            雇员信息表(存储) ──雇员地址──▶ ( 3.1.1 生成雇员银行结算表 ) ──银行结算表──▶ 雇员(实体)

  雇员(实体) ──会员应用───▶ ┐
  会员账号(存储) ─现有账号─▶ ├─▶ ( 3.1.2 创建新的会员账号 )      ← 三条输入，零输出
  雇员信息表(存储) ─雇员状态─▶ ┘

                              ( 3.1.3 冻结会员账号 )  ← 零输入
                                   │
                    ┌──────────────┴──────────────┐
            冻结账号通知▼                      回写▼
              应收账部门(实体)                会员账号(存储)
```

**分步解**：

**第 1 步**：逐个加工数一数进出箭头。

| 加工 | 输入 | 输出 |
|---|---|---|
| 3.1.1 | 雇员地址（1 条） | 银行结算表（1 条） |
| 3.1.2 | 会员应用、现有账号、雇员状态（**3 条**） | **0 条** |
| 3.1.3 | **0 条** | 冻结账号通知、回写会员账号（**2 条**） |

**第 2 步**：套判据。
- 3.1.2：**有输入、无输出** → **黑洞**。
- 3.1.3：**有输出、无输入** → **奇迹**。
- 3.1.1：有进有出，形式上没问题。但**要生成「银行结算表」，光有「雇员地址」够吗？** 银行结算表至少还需要账号、金额、结算周期，而这些在图中没有任何来源 → **输入不足以产生输出 = 灰洞**。

**第 3 步**：对照原图确认。

![会员应用 DFD 的三处错误（外部资料原图，已标注"这个加工没有输出""这个加工没有输入"）](../外部资源/转录md/images/fig_d13_s011.png)

**答案**：3.1.1 灰洞；3.1.2 黑洞；3.1.3 奇迹。

> 💡 **这个算例的价值**：黑洞和奇迹是"数箭头"就能发现的机械活，**灰洞必须读懂业务**——这也是为什么解题技巧强调"回题干核对"而不是"套原则"。

### 算例 B：判断加工是否违反守恒原则

**题目【模拟】**：下列加工的输入输出，哪些违反了 DFD 设计原则？违反哪一条？

| 编号 | 加工名 | 输入数据流 | 输出数据流 |
|---|---|---|---|
| ① | 检查报名表 | 报名单 | 报名单 |
| ② | 统计成绩 | 成绩清单、合格标准、考生名册 | 统计分析表、考生通知单 |
| ③ | 登记考生 | 正式报名单 | 考生名单、**准考证号规则** |
| ④ | — | 考生名册（数据存储） | 考生档案（数据存储） |

**分步解**：

**① 违反原则 2（守恒加工原则）**。输入输出同名"报名单"。即使内容真的没变，也必须改名——正确做法是把输出改成「**合格报名单**」和「**不合格报名单**」两条。

**② 不违反**。三条输入（成绩清单、合格标准、考生名册）足以产出统计分析表和考生通知单——通知单需要的考生姓名来自考生名册、是否合格来自合格标准。

> ⚠️ **注意对比**：如果这里的输入**只有「成绩清单」一条**，那就产不出「考生通知单」（缺姓名、缺合格标准），**那就是灰洞了**。灰洞和正常加工的差别只在「输入够不够」，务必逐项核对。

**③ 违反原则 1（数据守恒原则）**。输出里的"准考证号规则"**不可能从"正式报名单"里获得**，它是系统的配置/标准，必须另有输入来源（比如从数据存储"编号规则"读入），否则就是凭空产生。

**④ 违反原则 6**。数据存储 ═ 直接连到数据存储 ═，中间没有加工。正确画法是中间插一个加工○。

**答案**：①违反原则 2；③违反原则 1；④违反原则 6；②正确。

### 算例 C：用结构化语言写加工逻辑（下午题第四问实战）

**题目**【真题·2019下】（来源：外部培训资料"历年典型真题 1·二手车物流系统"；年份 2026-09-06 审核核实）：

题干业务规则原文：
> 系统根据订单的类型（保卖车、全国购和普通二手车）、起止城市，需要的服务模式进行自动派发或以竞拍体系方式选择合适的物流商。即：**有新订单时，若为保卖车或全国购，则直接分配到竞拍体系中；否则，若符合固定路线和/或包车路线，系统自动分配给合约物流商，若不符合固定路线和包车路线，系统将订单信息分配到竞拍体系中。** 竞拍体系接收到订单后，将订单信息推送给有相关路线的物流商，物流商对订单进行竞拍出价，最优报价的物流商中标。最后，**给承运的物流商发送物流消息，更新订单的物流信息，给车辆交易系统发送物流信息。**

要求：采用结构化语言对"P5：寻找物流商"的加工逻辑进行描述。（3 分）

**分步解**：

**第 1 步：找循环**。题干说"**有新订单时**"——这是个持续触发的动作 → 外层用 `while (有新订单)`。

**第 2 步：找第一层分支**。"**若为保卖车或全国购**，则直接分配到竞拍体系中；**否则**……" → `if / else`。

**第 3 步：找第二层分支**。else 里面还有一层："**若符合固定路线和/或包车路线**……**若不符合**……" → 嵌套 `if / else`。

**第 4 步：找收尾动作**。"最后，给承运的物流商发送物流消息，更新订单的物流信息，给车辆交易系统发送物流信息"——这三句在循环内、分支外。

**第 5 步：竞拍体系是独立的一段**（题干单独描述），另写一个 while。

**答案**：
```
while (有新订单) {
    if (订单类型 == "保卖车或全国购")
        分配到竞拍体系;
    else {
        if (订单路线 == "固定路线和/或包车路线")
            分配给合约物流商;
        else                       // 不符合固定路线和包车路线
            分配到竞拍体系;
    }
    给承运的物流商发送物流消息;
    更新订单的物流信息;
    给车辆交易系统发送物流信息;
}

竞拍体系:
while (收到订单) {
    订单信息推送给有相关路线的物流商;
    物流商对订单进行竞拍出价;
    最优报价的物流商中标;
}
```

> 💡 **踩分要点**：这题 3 分，评分看的是**三个分支是否齐全**（保卖车/全国购、固定包车路线、都不符合），以及**是否有循环结构**。伪代码写中文完全可以，不必纠结语法。

### 算例 D：变换型 vs 事务型识别

**题目【模拟】**：判断下列两个 DFD 属于变换型还是事务型，并说出转换后结构图的顶层长什么样。

**（1）** 读取原始成绩单 → 校验格式 → 计算加权总分 → 生成排名表 → 输出排名表

**（2）** 接收用户请求 → 判断请求类型 →
　　　　├─ 类型=查询 → 查询处理
　　　　├─ 类型=录入 → 录入处理
　　　　└─ 类型=删除 → 删除处理

**分步解**：

**（1）** 五个加工连成**一条直线**，没有任何分发。中间的"计算加权总分"是**变换中心**（数据在这里发生实质变化，前面是取数据、后面是送数据）→ **变换型**。

结构图顶层：
```
            主控模块
      ┌────────┼────────┐
   输入模块   变换模块   输出模块
  (读取+校验) (计算总分) (生成+输出排名表)
```

**（2）** "判断请求类型"是**事务中心**，它不加工数据，只**根据类型把请求分发出去**，三条分支互不相干 → **事务型**。

结构图顶层：
```
            主控模块
      ┌────────┴────────┐
   接收模块          调度模块
                ┌──────┼──────┐
             查询处理  录入处理  删除处理
```

**判别口诀**：**中心在"变"就是变换型，中心在"分"就是事务型。**

## 速记

**1. DFD 四元素**
> **实体方框、加工圆、存储双线、流是箭头**

**2. 三种错误**
> **只进不出黑洞，只出不进奇迹，进得不够灰洞**

**3. 八条原则压缩成三句**
> ① **两守恒**：输出必有来源（数据守恒）、进出不能同名（守恒加工）
> ② **三不连**：实体↔实体、实体↔存储、存储↔存储，一律不直连
> ③ **一平衡**：父图子图输入输出必须一致（**只在父子之间，单张图无平衡问题**）

**4. 分层**
> **顶层一个加工不画存储，0 层才出存储，编号带父级前缀**

**5. 数据字典四符号**
> **= 是定义，+ 是与，[|] 是或，{} 是重复（0 个或多个）**

**6. 加工逻辑三方法**
> **结构化语言、判定表、判定树**（下午题要写的是**结构化语言**）

**7. 转结构图**
> **中心在"变"→变换型（输入/变换/输出）；中心在"分"→事务型（接收/调度）**

**8. 三种模型别记混**
> **DFD→功能模型，STD→行为模型，E-R→数据模型**

A. 数据流图用于对系统的功能建模
B. 顶层数据流图中只有一个加工，且不出现数据存储
C. 父图与子图之间必须平衡，同一张图内部也存在平衡问题

**练习 2【模拟】** 某加工的输入数据流为"订单"，输出数据流为"订单"，该设计违反了数据流图的（ ）。
A. 数据守恒原则　B. 守恒加工原则　C. 父子平衡原则　D. 加工必有输入输出原则

**练习 3【模拟】** 数据字典中，`报名单 = 考生编号 + 姓名 + [身份证号|军官证号] + {报考科目}`。下列理解正确的是（ ）。
A. 报名单必须同时包含身份证号和军官证号
B. 报考科目至少填写 1 项
C. 身份证号与军官证号二选一，报考科目可以为 0 项或多项
D. 该表达式语法错误，`{}` 不能用于科目

**练习 4【模拟·下午题型】** 某图书管理系统的 0 层 DFD 中有加工"P2：借阅处理"，题干描述为：
> 读者提交借书请求后，系统检查读者的借阅资格（依据读者信息表），若资格有效且该图书库存大于 0，则生成借阅记录并写入借阅记录表，同时将库存减 1；若资格无效或库存为 0，则向读者返回拒绝通知。

请用**结构化语言**描述"P2：借阅处理"的加工逻辑。

---

### 参考答案

**练习 1：C**
父子平衡原则**只存在于父图与子图之间**，单张图内部不存在平衡问题。A/B/D 均正确。

**练习 2：B**
输入输出同名，违反**守恒加工原则**（原则 2）——同一个加工的输入与输出名字必须不同，即使组成成分相同。
注意与 A 的区别：数据守恒原则说的是"输出的数据必须能从输入获得"，讲的是**内容有无来源**；守恒加工原则讲的是**名字不能重复**。

**练习 3：C**
- `[身份证号|军官证号]` 中 `[|]` 表示**或**，二选一 → 排除 A。
- `{报考科目}` 中 `{}` 表示**重复 0 个或多个**，不是"至少 1 个" → 排除 B。
- 语法完全合法 → 排除 D。

**练习 4：**
```
while (收到借书请求) {
    读取读者信息表，检查读者借阅资格;
    if (资格有效 && 图书库存 > 0) {
        生成借阅记录;
        写入借阅记录表;
        图书库存 = 图书库存 - 1;
    }
    else                          // 资格无效 或 库存为 0
        向读者返回拒绝通知;
}
```
**踩分点**：① 有循环或触发结构；② 条件是**两个条件同时成立**（资格有效 **且** 库存>0）；③ 成功分支三个动作齐全（生成记录、写表、减库存）；④ 失败分支有拒绝通知。
