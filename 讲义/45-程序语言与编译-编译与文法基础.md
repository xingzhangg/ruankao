## 第 1 层 · 理解

### 一句话

> 这一章讲的是：你写的那行代码，从一串文本变成能跑起来的东西，**中间被谁、按什么规则、拆成几步处理过**——本质上就是 `gcc` / `javac` 这个黑盒子的内部说明书，外加"程序跑起来时参数是怎么传的"这条运行时规则。

### 痛点：你天天用它，却从没看过它里面

- **报错是谁报的你分不清**：`error: expected ';'` 和 `error: incompatible types` 看着都是"编译报错"，但它们其实是**两个不同阶段**抓到的，考试专门考这个归属。
- **正则天天写，不知道它是什么东西**：你写 `^1[0-9]{10}$` 很熟练，但"正规式和有限自动机是等价的""词法分析器就是一台自动机"这句话对不上号——于是考到就只能猜。
- **`swap(x, y)` 改不动变量**：C 里写了个 swap，调用完发现 x、y 纹丝没动；换成传指针就好了。你知道"要传指针"，但说不清**为什么 C 传指针也仍然是值传递**——考试恰好考这一层。
- **最根本的**：这些知识点（编译器、六阶段、正规式、自动机、文法、乔姆斯基分类、参数传递）在教材里像一堆互不相干的碎片，**背下来第二天就散架**。它们其实是一条链子上的珠子。

### 一条主线

```
高级语言 ≠ 机器指令 → 中间必须有一道【翻译】
   │
   ├─① 翻译的【时机】怎么选？——两条路，这是第一个考点
   │     一次性全译完再跑 = 编译器（跑得快；改一行就要重编）
   │     边译边跑         = 解释器（改完立刻能跑；跑得慢）
   │     Java 两头都占：javac 编译成字节码 → JVM 解释/JIT 执行
   │
   └─② 选了"编译"这条路，一步从源码跳到机器码做不到 → 只能拆成【流水线】

            ↓

            ↓
      ┌─────────────────────────┴─────────────────────────┐

      │  可正规式是写给人看的，机器要能       │  → 升级成【上下文无关文法 CFG】      │
      │  逐字符执行 → 造出【有限自动机 DFA】  │     产生式 A→α，靠【推导】生成句子   │
      │  二者【等价】：同一类语言的两种写法   │                                     │
      │  （一个是说明书，一个是流程图）       │                                     │
      │  ↑ 这就是【词法分析】的实现原理       │  ↑ 这就是【语法分析】的实现原理      │
      └─────────────────────────┬─────────────────────────┘
            ↓
```

### 考点① 正规式匹配判定（本课第一优先级）

**题目长相**：
> "正规式 `(a|b)*abb` 能够匹配的字符串是（ ）。A. `abb` B. `aab` C. `bab` D. `abbb`"
> 或反过来："下列字符串中，不能被正规式 X 匹配的是（ ）"。

**先认三个记号**（会读比会写重要）：

| 记号 | 名称 | 含义 | 读法举例 |
|---|---|---|---|
| 并列书写 | **连接** | 前后顺序拼接 | `ab` 表示先 `a` 后 `b`，即串 "ab" |
| `\|` | **或 / 选择** | 二选一 | `a\|b` 表示 "a" 或 "b" |
| `*` | **闭包**（Kleene star） | 前面的东西重复 **0 次或多次**（可以一次都不出现） | `a*` 表示 ""、"a"、"aa"、"aaa"…… |

**运算优先级**：`*`（闭包）最高 → **连接**次之 → `|`（或）最低；圆括号可强行改变结合顺序。

**怎么解（三步，别硬看）**：
1. **按优先级把式子断成"结构句"**：先圈出 `*` 管到哪（`*` 只管紧挨着它的那一个单元或括号），再看连接顺序，最后才是 `|` 的分支。
2. **先对锚点**：把式子里**不带 `*` 的固定部分**当锚点，先去对候选串的开头/结尾。如 `(a|b)*abb` 的锚点是"必须以 `abb` 结尾"，`a(a|b)*b` 的锚点是"a 开头、b 结尾"。
3. **再看可变部分能否吃掉剩余字符**：锚点对上后，剩下的中间部分交给 `*` 判断"能不能由它重复出来"。

**陷阱**：
- **忘了 `*` 可以取 0 次**——最高频错误。`(a|b)*abb` 匹配 `"abb"` 就是靠 `(a|b)*` 取 0 次；很多人以为"星号前面的东西必须至少来一遍"，于是把正确答案划掉。
- **结尾锚点看错位**：`"abbb"` 看着"有 a 有 bb"，但它的**最后三个字符是 `bbb` 不是 `abb`**，不匹配。数尾巴要从后往前数。
- **`|` 的作用域搞错**：`a|b*` ≠ `(a|b)*`。前者是"要么一个 a，要么任意个 b"，后者是"a 和 b 任意混排任意长"。

### 考点② 有限自动机（DFA）：走状态 + 与正规式的等价关系

**题目长相**：
> 给一张状态转移图（圆圈+带字母的箭头，接受态画**双圈**），问"下列哪个串能被该自动机接受"；
> 或问"该自动机识别的语言（对应的正规式）是（ ）"；
> 或考结论句："正规式与有限自动机在描述能力上是（等价的 / 前者更强 / 后者更强）"。

**组成**（三样东西）：一组**状态**（其中一个是**初始状态**，某些被标记为**接受状态/终止状态**）；一个输入字符集；一套**转移规则**（当前状态 + 输入字符 → 下一个状态）。

**怎么解**：从初始状态出发，按输入串**逐字符**走，每读一个字符按转移规则跳一次，**手边写下"当前状态"这一列**别在脑子里记。读完整个串后：
- 停在**接受状态** → 该串被接受（匹配）；
- 停在非接受状态 → 拒绝；
- 中途**无路可走**（当前状态对这个字符没有转移规则）→ 立即拒绝。

**核心结论（等价性，考选择题就考这一句）**：任何一个正规式都能构造出一个接受**完全相同字符串集合**的有限自动机；反过来，任何一个有限自动机也能写出与它等价的正规式。二者是描述同一类语言（**正规语言**）的两种表达形式——**正规式是"紧凑的书面写法"，自动机是"可执行的操作流程图"**。编译器**词法分析**的实际做法，正是先把 token 规则写成正规式，再自动构造成 DFA 去逐字符扫描源程序——这就是本考点和"编译六阶段第①站"能对上号的地方。

**陷阱**：
- **"走完 = 接受"是错的**：必须**停在接受态**才算接受。串走完了停在中间状态一样是拒绝（见第3层算例 B 的 `"a"`）。
- **接受态标记看漏**：图上接受态是**双圈**，只看单圈会把答案判反。
- **无路可走要立刻停**，不要自作主张"跳过这个字符继续走"。
- 严格定义的 DFA 转移函数是全函数（会补一个"陷阱/死状态"吸收所有非法输入）；考试层面按"**无路可走即拒绝**"处理即可，两种讲法结论一致。

### 考点③ 上下文无关文法（CFG）的推导与语言归纳

**题目长相**：
> "文法 `G: S→aSb | ab` 能够推导出的串是（ ）"；
> 或"该文法生成的语言是（ ）A. aⁿbⁿ B. (ab)ⁿ …"；
> 或给一个串让你**写出推导过程**（关联练习第 3 题就是这型）。

**先认记法**：产生式形如 `A → α`，读作"非终结符 A 可以被替换/推导为符号串 α"。**非终结符**是还能继续展开的符号（通常用大写字母），**终结符**是不能再展开的最终符号（相当于词法分析给出的 token）。同一个非终结符的多条候选产生式用 `|` 并列写：`A → α | β`。

**推导过程的定义**：从指定的**开始符号**出发，反复挑当前串里的一个非终结符、用它的某条产生式替换掉，直到串里**不再含任何非终结符**为止，得到的就是该文法能生成的一个合法句子。

**怎么解（两个方向，哪个快用哪个）**：
- **正推**：递归产生式（如 `S→aSb`）看"每用一次增加什么"——这里是**左边多一个 a、右边多一个 b**，所以增长模式是"两侧对称各加一个"；终止产生式（`S→ab`）给出**最小串**。两者合起来直接归纳出语言通式：`aⁿbⁿ`（n≥1）。有了通式，选项一眼对号。
- **反推（归约）**：拿候选串从两端往里剥——`aabb` 剥掉外层 a…b 得 `ab`，`ab` 正好是终止产生式 → 可推导。剥不干净的就不可推导。

**陷阱**：
- **数量不等**：`aaabb`（3 个 a 配 2 个 b）看着很像，但 `S→aSb` 每次左右**必须同步各加一个**，数量永远相等 → 不可推导。
- **顺序交错**：`abab` 是 `(ab)ⁿ` 形态，不是"先全 a 后全 b"，不符合本文法。
- **n 的起点**：`S→aSb|ab` 的最小串是 `ab`，即 **n≥1**，**不生成空串**。看到选项里有 ε 要警惕。
- **别把 CFG 的能力和正规式混为一谈**："两侧数量必须相等"这种配对计数关系，正规式/有限自动机**做不到**（它们不会计数），只有 CFG 能描述——这正对应程序里"括号、`begin...end` 必须配对"的语法规则。这一句本身也是常考的辨析点。

### 考点④ 乔姆斯基文法四类型（0–3 型）与对应自动机

**题目长相**：
> "上下文无关文法对应的识别装置（自动机）是（ ）"；
> "3 型文法又称（ ）文法，用于编译的（ ）阶段"；
> "下列关于 0/1/2/3 型文法的叙述，错误的是（ ）"。

**怎么解**：**只看产生式左边的限制有多严**，数字越大、限制越强、能描述的语言范围越小。

| 类型 | 名称 | 产生式限制（一句话） | 对应的自动机 | 编译器里对应哪个阶段 |
|---|---|---|---|---|
| **0 型** | 短语结构文法（无限制文法） | 左边可以是任意非空符号串，几乎不设限 | 图灵机 | （能力最强，理论层面） |
| **1 型** | 上下文有关文法 | 形如 `αAβ → αγβ`，A 只能在"上下文 α…β"环境里换成 γ（γ 非空） | 线性有界自动机 | （软考较少深入） |
| **2 型** | **上下文无关文法（CFG）** | 左边必须是**单个非终结符** `A → α`，不看上下文 | **下推自动机** | **语法分析**（考点③） |
| **3 型** | **正规文法** | 形如 `A→aB` 或 `A→a`（右线性，最简单） | **有限自动机（DFA）** | **词法分析**（考点①②） |

**包含关系**：3 型 ⊂ 2 型 ⊂ 1 型 ⊂ 0 型（范围逐级扩大）。**限制越少，能表达的语言越复杂**。

**陷阱**：
- **方向记反**：数字越大 = 限制越**强** = 语言类越**小**。很多人记成"数字大 = 能力强"，全盘做反。
- **自动机对错位**：2 型↔**下推**自动机、3 型↔**有限**自动机、1 型↔线性有界自动机、0 型↔图灵机。最常见的错项是把 CFG 配给有限自动机。
- **阶段对错位**：3 型管**词法**，2 型管**语法**——顺序和"3 比 2 简单、词法比语法先做"一致，用这个自洽关系防错。

### 考点⑤ 编译的六个阶段 + 三类错误归属

**题目长相**：
> "在编译过程中，检查 `int x; x = "hello";` 这类类型不匹配错误是在（ ）阶段完成的"【真题·2025上】；
> "编译器报错'`if` 语句缺少右括号'，属于（ ）阶段发现的错误"；
> "编译过程中，（ ）阶段的任务是把源程序的字符流切分成记号（token）"；
> "下列不属于编译阶段任务的是（ ）"。

**为什么要分阶段**：编译的翻译工作量很大，直接从源代码"一步跳到"机器码既不现实也不利于分工排错。工程上拆成六个连续阶段，每阶段只关心一类问题，上一阶段的输出是下一阶段的输入。

```
源程序
 → ① 词法分析 → ② 语法分析 → ③ 语义分析
 → ④ 中间代码生成 → ⑤ 代码优化 → ⑥ 目标代码生成
 → 目标程序
        （符号表管理 + 出错处理 贯穿全过程）
```

**逐站职责**：

| 阶段 | 干什么 | 抓什么错 | 依据/实现 |
|---|---|---|---|
| **① 词法分析**<br>Lexical Analysis | 把源程序的**字符流**切成一个个不可再分的"单词"（**记号/token**）：标识符、关键字、常量、运算符、界符。相当于中文分词 | **非法字符**——出现了这门语言字符集之外的符号（全角标点等） | 用**有限自动机**逐字符扫描（考点②） |
| **② 语法分析**<br>Parsing | 把 token 序列按语言的**语法规则**组织成一棵**语法树**，检查整体结构是否合法。相当于检查一句话的主谓宾对不对 | **结构不对**——括号不配对、`if` 缺条件、语句缺分号、表达式不完整 | 依据**上下文无关文法**（考点③） |
| **③ 语义分析**<br>Semantic Analysis | 结构合法 ≠ 意思合理。检查类型是否匹配、变量是否先声明后使用、运算对象是否合法 | **类型不匹配**（`int x = "abc";`）、变量未声明、函数实参个数/类型不符 | 查**符号表**（考点⑦）｜**本课唯一有明确年份真题依据的阶段**【真题·2025上】 |
| **④ 中间代码生成** | 翻译成**不依赖具体机器**的中间表示（三地址码、四元式）——先出一份"通用草稿" | — | 便于统一优化，也便于移植（换机器只需换第⑥站） |
| **⑤ 代码优化** | 对中间代码做**等价变换**提高效率：删公共子表达式、循环不变式外提等 | — | **不改变程序的功能语义** |
| **⑥ 目标代码生成** | 把（优化后的）中间代码译成特定机器的目标代码（汇编/机器指令） | — | 要考虑寄存器分配、指令选择 |

**怎么解（错误归属题，一句话判据）**：
> **词法管"字"（非法字符）、语法管"句"（结构/括号/分号）、语义管"意"（类型/声明）。**

**陷阱**：
- **把类型不匹配归到语法分析**——最高频错项。`x = "hello";` 这行**结构完全合法**，token 也全合法，错在"意思不通"，所以是**语义分析**。
- **以为代码优化会改变程序功能**——优化必须是**等价变换**，只改效率不改语义。
- **以为六个阶段一个都不能少**——《软件设计师教程》（第5版）的口径是：**中间代码生成和代码优化并不是必需的**（可以省略，由语义分析的结果直接生成目标代码）；词法、语法、语义、目标代码生成才是必备环节。题干里"编译必须完整经过全部六个阶段"属错项。
- 阶段**顺序**记岔：中间代码生成在优化**之前**（先有中间代码才能优化它）。
- "预处理""链接"不属于编译的六阶段（预处理在编译前，链接在编译后），出现在选项里要认得出。

### 考点⑥ 编译器 vs 解释器（含 Java 混合模式）

**题目长相**：
> "关于编译程序和解释程序，以下说法正确的是（ ）"【真题·2022下】；
> "以下语言中，通常采用解释方式执行的是（ ）"；
> "Java 程序的执行方式属于（ ）"。

**编译器（Compiler）**：把整个源程序**一次性**翻译成目标程序（机器码或汇编），翻译完成后**目标程序可脱离编译器独立、反复运行**。类比：把一整本中文书完整翻译成英文书出版，读者以后直接看英文书，不需要译者在场。
- 优点：运行时不再有翻译开销，**执行速度快**；语法/类型错误在编译期集中暴露，不带到运行时。
- 缺点：每次改源码都要重编才能跑，"改一下试一下"的周期长；目标程序通常与特定平台绑定（跨平台要重新编译）。
- 代表：C/C++（gcc/g++）、Go、Rust。

**解释器（Interpreter）**：**不生成独立的目标程序**，边翻译边执行——读一句、译一句、马上执行一句，**每次运行都要解释器实时在场**。类比：同声传译，译者和听众必须同时在场，说一句译一句，不产出一份独立的"译文书"。
- 优点：改完立刻能跑，**开发调试快**；天然跨平台（只要目标机器上有解释器）。
- 缺点：每次运行都要重新翻译，**执行速度通常比编译型慢**；语法/类型错误往往执行到那一行才暴露。
- 代表：Python、JavaScript（早期）、Shell 脚本。

**程序员类比**：`gcc hello.c -o hello` 再 `./hello`——这是编译；`python hello.py` 直接执行——这是解释。

**怎么解（一句话判据）**：
> 只问一句——**有没有产出一份能脱离翻译程序独立运行的目标程序？** 有 → **编译**；没有、每次运行都要翻译程序在场边译边跑 → **解释**。抓住这一条，"速度快/慢""改完要不要重编""跨不跨平台"三组优缺点都能当场推出来，不必分别死背。

**Java 的特殊之处（常考对比点）**：Java 源码先被 `javac` **编译**成与平台无关的**字节码**（`.class`），运行时再由 JVM **解释**执行字节码（现代 JVM 还会用 **JIT** 把热点代码即时编译成本机机器码提速）。所以 Java 是"**先编译、后解释（或再编译）**"的混合模式，这也是"一次编译、到处运行"跨平台的原理。

**陷阱**：
- **两者说反**——最常见的错项："编译程序边翻译边执行不生成目标程序""解释程序生成独立目标程序、运行时无需解释器"，都是把定义对调。
- **把 Java 说成"纯编译"或"纯解释"**：它是混合模式，字节码那一步是编译，JVM 那一步是解释/JIT。
- "编译型一定比解释型好"是错的——各有优缺点，题干若出现绝对化表述基本是错项。

### 考点⑦ 符号表（Symbol Table）

**题目长相**："符号表在编译的哪个阶段建立？""符号表中不包含下列哪项信息？"

**是什么**：一张贯穿编译全过程的表，记录程序中每个**标识符**（变量名、函数名、类名等）的属性——**类型、作用域、内存地址**等。

**怎么解**：记住它的生命周期——**从词法分析识别出标识符起就开始登记**，**语义分析**靠它查类型做类型检查，**代码生成**靠它查地址生成访存指令，即**贯穿全程，全程都要查它、改它**。

**一句话记忆**：符号表是编译器给源程序里所有"名字"建的**档案库**。

**陷阱**：说它"只在语义分析阶段使用"或"编译结束前才建立"都是错的；与它并列贯穿全程的还有**出错处理**。

### 考点⑧ 参数传递：值调用 vs 引用调用

**题目长相**：
> "以下关于值调用和引用调用的说法，正确的是（ ）"【真题·2021上】；
> 给一段带 `swap` 的代码问"调用结束后 x、y 的值是（ ）"。

**要解决的问题**：函数调用时，实参（调用者传入的值/变量）和形参（函数定义里的参数名）怎么建立联系？联系方式不同，**函数内对形参的修改是否影响调用者手里的实参**，结果完全相反。

**值调用（Call by Value，传值）**：把实参的**值拷贝一份**给形参。形参是独立的存储单元，函数内怎么改形参**都不影响实参**——改的是拷贝，不是原件。

**引用调用（Call by Reference，传引用/传地址）**：把实参的**地址/引用**给形参，形参和实参是**同一个存储单元的两个名字**（别名）。函数内对形参的修改**直接反映到实参**。

**怎么解**：一句话判据——**"传的是副本还是别名"**。传副本 → 改不到；传别名 → 改得到。

**C 语言的特殊之处（必考细节）**：C **只有值传递**，没有原生的引用语法。想"能改到原变量"要靠**传指针**（`swap(int *a, int *b)`，调用时传 `&x, &y`）——但这**本质上仍是值传递**：传的是**指针变量的值（一个地址）**，指针本身也是被拷贝的，只是这个"值"恰好是原变量的地址，函数内通过 `*a = ...` 按地址**间接**改到原变量。
> **考试口径**：C 没有语言层面的引用调用，"传指针"是用**值传递模拟**出引用调用的效果。

**陷阱**：
- **两者效果说反**："值调用中改形参会影响实参""引用调用中形参实参是各自独立的存储单元"，都是对调定义。
- **"C 原生支持引用调用"** → 错（C++ 才有 `&` 引用形参）。
- 别把"传指针能改到原值"当成"C 有引用传递"——这正是本考点的分界线。

## 第 3 层 · 完整算例

> 本课无数值计算，但三类题都必须"按规则一步步走"。以下算例一步不跳，请照着走一遍，**手写"当前状态/当前串"这一列**，不要在脑子里过。

### 算例 A · 正规式匹配判定（两例）

**A1：正规式 `a(a|b)*b` 表示什么样的串？**

**读法（按优先级断句）**：`*` 只管紧挨着它的 `(a|b)` 这一个括号单元 → 整式 = `a` 连接 `(a|b)*` 连接 `b`，即**先一个 `a` 开头，中间是任意个（含 0 个）"a 或 b"，最后以 `b` 结尾**。

逐串判断：

| 串 | 开头 `a`？ | 中间部分 | 结尾 `b`？ | 结论 |
|---|---|---|---|---|
| `"ab"` | ✓ | 空串（`*` 取 **0 次**，合法） | ✓ | **匹配** |
| `"aab"` | ✓ | `"a"`（`(a\|b)` 重复 1 次） | ✓ | **匹配** |
| `"abba"` | ✓ | — | ✗（最后一个字符是 `a`） | **不匹配** |
| `"ba"` | ✗（开头是 `b`） | — | — | **不匹配** |

**A2：正规式 `(0|1)*1` 表示什么样的串？**

**读法**：任意个（含 0 个）"0 或 1"，最后**必须以 `1` 结尾** → 即**所有以 1 结尾的 0/1 串**。

| 串 | 判断依据 | 结论 |
|---|---|---|
| `"101"` | 前缀 `"10"` 由 `(0\|1)*` 取 2 次得到，结尾是 `1` | **匹配** |
| `"1"` | `(0\|1)*` 取 **0 次**，直接接结尾的 `1` | **匹配** |
| `"110"` | 结尾是 `0`，不是 `1` | **不匹配** |

> **本算例的题眼**：两例的"匹配"结论都用到了 **`*` 可以取 0 次**。这一条是正规式题的第一大陷阱。

### 算例 B · 有限自动机逐字符走状态

**构造正规式 `ab*b` 对应的自动机**——即"`a` 开头、中间任意个 `b`、以 `b` 结尾"。它是算例 A1 中 `a(a|b)*b` 的**简化子集**（中间只允许 b，不允许 a），读法完全相同、规则更少，便于把每一步走清楚。

```
状态：S0（初始）→ S1 → S2（接受）
转移规则：
  S0 遇 a → S1
  S1 遇 b → S2
  S2 遇 b → S2（自环，继续吃 b）
其余情况（如 S0 遇 b、S1 遇 a）→ 无定义转移，直接拒绝
```

**走串 `"abb"`**：
```
第1步：当前 S0，读入 a → 按「S0 遇 a」规则跳到 S1
第2步：当前 S1，读入 b → 按「S1 遇 b」规则跳到 S2
第3步：当前 S2，读入 b → 按「S2 遇 b」自环，仍在 S2
读完，停在 S2 —— S2 是接受状态 → 该串【被接受】
```

**走串 `"ab"`**：
```
第1步：当前 S0，读入 a → 跳到 S1
第2步：当前 S1，读入 b → 跳到 S2
读完，停在 S2 —— 接受状态 → 该串【被接受】
```

**走串 `"a"`**：
```
第1步：当前 S0，读入 a → 跳到 S1
读完，停在 S1 —— S1【不是】接受状态 → 该串【被拒绝】
```
> ← 这一条就是"走完 ≠ 接受"的反例，必须停在接受态。

**走串 `"ba"`**：
```
第1步：当前 S0，读入 b → S0 没有「遇 b」的转移规则，无路可走 → 【直接拒绝】
```

**验算习惯**：走完后回头用正规式复核一遍——`ab*b` 要求"a 后面至少一个 b"，所以 `"abb"` ✓、`"ab"` ✓、`"a"` ✗（一个 b 都没有）、`"ba"` ✗（开头不是 a）。**自动机的结论和正规式的结论必须一致**，不一致说明有一步走错了——这正是"正规式与自动机等价"这条结论在做题时的实际用法。

### 算例 C · 文法推导

**文法 `G`**：开始符号 `S`，产生式：
```
S → aSb | ab
```

**推导串 `"aaabbb"`**：
```
S
⇒ aSb                （用第一条产生式 S→aSb，把 S 换成 aSb）
⇒ a(aSb)b = aaSbb    （再对里面剩下的 S 用第一条产生式）
⇒ aa(ab)bb = aaabbb  （最后对 S 用第二条产生式 S→ab，结束，已无非终结符）
```
写成一行：`S ⇒ aSb ⇒ aaSbb ⇒ aaabbb`。

**归纳与验算**：每用一次 `S→aSb`，左边多一个 `a`、右边多一个 `b`（**严格同步**）；用 `S→ab` 收尾贡献最小的一对。所以该文法生成的正是"**n 个 a 后面跟 n 个 b**"这一整族串（`aⁿbⁿ`，**n≥1**）。数一下 `"aaabbb"`：3 个 a、3 个 b，n=3 ✓。

> **这个算例真正的价值**：`aⁿbⁿ` 这种"两边数量必须相等"的嵌套配对关系，**正规式/有限自动机做不到**（它们没有计数能力），只有上下文无关文法能描述——这正对应程序里"括号 / `begin...end` 必须配对"这类语法规则，也就是主线里"从 A 层升级到 B 层"的那一步。

### 算例 D · 参数传递（swap 对照，C++ 语法示范）

```cpp
// 值调用版本
void swap_by_value(int a, int b) {
    int t = a; a = b; b = t;   // 只交换了 a、b 这两个"拷贝"
}
int x = 1, y = 2;
swap_by_value(x, y);
// 调用结束后：x = 1, y = 2 —— 没有变化！
// 因为 a、b 是 x、y 的独立副本，函数内的交换只发生在副本上
```

```cpp
// 引用调用版本（C++ 用 & 声明引用形参）
void swap_by_ref(int &a, int &b) {
    int t = a; a = b; b = t;   // a 就是 x 本身、b 就是 y 本身
}
int x = 1, y = 2;
swap_by_ref(x, y);
// 调用结束后：x = 2, y = 1 —— 真的交换了！
// 因为 a 是 x 的别名、b 是 y 的别名，改 a/b 就是改 x/y
```

**分步复核（值调用版为什么没换成）**：
```
调用前：x=1, y=2
进函数：a ← 拷贝 x 的值 = 1；b ← 拷贝 y 的值 = 2   （a、b 是两个【新】存储单元）
执行：t=a=1 → a=b=2 → b=t=1                        （变的只有 a、b）
出函数：a、b 随栈帧销毁；x、y 从头到尾没被碰过
结果：x=1, y=2  ——【未交换】
```

**C 语言怎么办**：写成 `void swap(int *a, int *b)`，调用 `swap(&x, &y)`，函数内用 `*a`、`*b` 间接访问。**注意它仍是值传递**——被拷贝的是"地址"这个值，只不过顺着这个地址能摸到原变量。

## 第 4 层 · 速记

> **翻译两条路**：编译一次翻译完整跑（快，但改完要重编）；解释边译边跑（慢，但改完立刻见效）。**Java = javac 编译成字节码 + JVM 解释/JIT**，混合模式。
> **六阶段一条线**：**词法 → 语法 → 语义 → 中间代码 → 优化 → 目标代码**；**符号表 + 出错处理贯穿全程**。
> **三类错误对号入座**：**词法管"字"（非法字符），语法管"句"（结构不对、括号/分号），语义管"意"（类型不匹配、未声明）**。
> **代码优化是等价变换**——只改效率，不改功能语义。
> **符号表**：给所有"名字"建的档案库（类型、作用域、地址），词法阶段开始建，语义查类型、生成查地址。
> **正规式三件套**：**连接顺序拼、`|` 选一个、`*` 闭包重复 0 次以上**；优先级 **`*` > 连接 > `|`**。
> **`*` 可以取 0 次**——正规式题第一大陷阱，别把它忘了。
> **自动机走一遍**：从初态按输入串逐字符跳转，**停在接受态（双圈）才算接受**；走完停在非接受态、或中途无路可走，都是拒绝。
> **正规式 ⟺ 有限自动机**：描述同一类语言（正规语言），**等价**；一个是说明书，一个是流程图。
> **正规式不会计数**：`aⁿbⁿ`、括号配对只能用 **CFG**。
> **文法看产生式左边**：**0 型任意串（图灵机）、1 型看上下文（线性有界）、2 型单个非终结符（下推自动机·语法分析）、3 型最简单右线性（有限自动机·词法分析）**；**数字越大限制越强、语言类越小**，3⊂2⊂1⊂0。
> **3 型配词法、2 型配语法**——和"3 比 2 简单、词法比语法先做"一致，用它自查防记反。
> **参数传递记效果**：**值调用传拷贝、改形参不影响实参；引用调用传别名、改形参 = 改实参**。**C 语言只有值传递**，传指针是把"地址当成值"拷过去、再间接改，**不是语言层面的引用调用**。

## 考题回顾

> 标注说明：**【模拟·重现年份考点】＝按计划文件已核实的该年考点自编的重现题，非原题原文**；【模拟】＝自编题。

**1.【模拟·重现2022下考点】** 关于编译程序和解释程序，以下说法正确的是（ ）。
A. 编译程序边翻译边执行，不生成目标程序
B. 解释程序生成独立的目标程序，之后运行无需解释器
C. 编译程序生成目标程序后，运行该程序不再需要编译程序参与
D. 两者在功能和实现方式上完全相同

> **答案：C**。编译程序把源程序**整体**翻译成目标程序，之后目标程序可脱离编译程序独立运行；解释程序不产生独立目标程序，**每次运行都要解释器在场**边译边执行。A、B 恰好是把两者的定义**对调**了——这是本考点的标准错项造法。D 显然错，两者实现方式和优缺点都不同。

**2.【模拟·重现2025上考点】** 在编译过程中，检查表达式 `int x; x = "hello";`（把字符串常量赋给整型变量）这类类型不匹配错误，是在（ ）阶段完成的。
A. 词法分析　B. 语法分析　C. 语义分析　D. 目标代码生成

> **答案：C**。按"字/句/意"三分判据走：词法只管切出合法 token——`int`、`x`、`=`、`"hello"`、`;` **每个 token 本身都合法**；语法只管赋值语句的**结构**对不对——`变量 = 常量;` **结构完全合法**；"整型变量装字符串"错在**含义不合理**，属于语义分析。**最高频错选 B**，就是没分清"结构合法"和"意思合理"。

**3.【模拟·重现2021上考点】** 正规式 `(a|b)*abb` 能够匹配的字符串是（ ）。
A. `abb`　B. `aab`　C. `bab`　D. `abbb`

> **答案：A**。该正规式 = "任意个 a 或 b（**含 0 个**）" + "固定结尾 `abb`"。先用锚点法看结尾三个字符：
> A `abb` → `(a|b)*` 取 **0 次**，剩下正好是 `abb` ✓
> B `aab` → 末三位是 `aab` ✗
> C `bab` → 末三位是 `bab` ✗
> D `abbb` → 末三位是 **`bbb`** 不是 `abb`（多出一个 b）✗
> **陷阱点**：A 之所以对，全靠"`*` 可以取 0 次"；忘了这条就会把正确答案排除。

**4.【模拟·重现2021上考点】** 文法 `G: S→aSb | ab` 能够推导出的串是（ ）。
A. `aabb`　B. `aaabb`　C. `abab`　D. `aaab`

> **答案：A**。该文法生成的语言是 `aⁿbⁿ`（n 个 a 后跟同样多个 b，n≥1）：`S ⇒ aSb ⇒ a(ab)b = aabb`，即 n=2 时得到 `aabb` ✓。
> B `aaabb`：3 个 a 配 2 个 b，而 `S→aSb` 每次左右**同步各加一个**，数量必然相等 ✗
> C `abab`：是 `(ab)ⁿ` 形态，不符合"先全 a 后全 b" ✗
> D `aaab`：3 个 a 配 1 个 b，数量不等 ✗

**5.【模拟·重现2021上考点】** 以下关于值调用和引用调用的说法，正确的是（ ）。
A. 值调用中，函数内部对形参的修改会直接影响实参
B. 引用调用中，形参和实参是各自独立的存储单元
C. 值调用中，形参得到的是实参的一份拷贝，修改形参不影响实参
D. C 语言原生支持引用调用，无需借助指针

> **答案：C**。值调用把实参的值**拷贝**给形参，形参、实参是两份独立存储，改形参不影响实参。A、B 把两者效果**说反**；D 错——**C 语言只有值传递**，要达到"改到原变量"的效果必须**传指针**（而传指针本质上还是传值，传的是地址这个值）。

## 自测练习

1. 【模拟】某编译器在处理源程序时报错："第10行，`if` 语句缺少右括号"，这属于编译六阶段中哪个阶段发现的错误？
2. 【模拟】正规式 `1(0|1)*` 能匹配以下哪个串：`"0"`、`"10"`、`"11"`？分别说明能或不能匹配的理由。
3. 【模拟】写出文法 `S → 0S1 | 01` 推导串 `"000111"` 的完整推导过程，并说出该文法描述的语言规律是什么。

### 参考答案

1. **语法分析阶段**。括号是否配对、语句结构是否完整，属于"**结构是否合法**"的检查，由语法分析（依据上下文无关文法）负责；词法分析只管切出合法 token（`if`、`(` 本身都是合法 token），语义分析管类型/声明等**含义层面**的检查。
2. `1(0|1)*` = "必须以 `1` 开头，后面跟任意个（含 0 个）0 或 1"。
   - `"0"`：**不能匹配**——开头是 `0`，不满足"以 1 开头"的锚点。
   - `"10"`：**能匹配**——开头 `1` ✓，后面 `(0|1)*` 取一次重复得 `0` ✓。
   - `"11"`：**能匹配**——开头 `1` ✓，后面 `(0|1)*` 取一次重复得 `1` ✓。
   （附：`"1"` 也能匹配，`(0|1)*` 取 0 次。）
3. 推导过程：`S ⇒ 0S1 ⇒ 0(0S1)1 = 00S11 ⇒ 00(01)11 = 000111`（先两次用 `S→0S1`，再一次用 `S→01` 结束）。该文法描述的语言规律是 **`0ⁿ1ⁿ`（n≥1）**——n 个 0 后面跟同样多个 1，**两侧数量必须相等**，与第 3 层算例 C 的 `aⁿbⁿ` 是同一类"**配对计数**"结构，也同样是正规式/有限自动机描述不了、只有上下文无关文法能描述的典型例子。
