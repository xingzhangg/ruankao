## 第 1 层 · 理解

### 一句话

> 前 6 课都在回答"CPU 这一亩三分地怎么更快"；本课回答的是整机层面的另外两个问题——**机器会坏**（可靠性算的是"整套系统还活着的概率"），**数据不在内存里**（I/O 方式与磁盘存取算的是"CPU 得等多久"）。一句话贯穿：**整机好不好用，不由最强的 CPU 决定，由「结构」和「最弱/最慢的那一环」决定。**

### 痛点：三个你多半拍过脑袋的场景

- **可用性拍脑袋**：文档上写"每个节点可用率 99%"，老板问"整套系统可用多少"，你答"大概 99%"——错。三个 99% 的节点串在同一条链路上，整体只有 0.99³ ≈ **97%**；而把两个 99% 的节点做成双活并联，能到 1−0.01² = **99.99%**。**部件没变，只是接法变了——不可用率从 3% 掉到 0.01%，差两个数量级**，这就是可靠性计算存在的理由。
- **CPU 跑满却没吞吐**：写个循环 `while (!device.ready());` 读设备，CPU 占用 100%，吞吐低得可怜——因为代码在**忙等**。同样的逻辑改成"设备好了叫我"（中断），再改成"根本别让 CPU 搬"（DMA/零拷贝），CPU 立刻闲下来。**慢的不是 CPU，是 CPU 等设备的姿势。**
- **把磁盘当内存估耗时**：随机小文件读写按内存访问估算，线上慢了三个数量级——因为机械盘每读一次都要**真的**把磁头挪过去、再**真的**等盘片转过来。这几段物理动作，就是磁盘存取时间公式的全部来源。

### 一条主线

```
前 6 课：CPU 内部怎么更快（编码 / Cache / 流水线 / 指令）
   ↓ 可是一台真机器还有两件事没人管：会坏，以及数据在慢设备上
   ↓
【问题一】机器会坏 → 用「可靠度 R」= 这个部件正常工作的概率，来算整机
   ↓
   最朴素的结构：所有部件【都得好】系统才好  →  串联
        R = R1 × R2 × … × Rn        （概率相乘）
   ↓ 可是相乘只会越乘越小 —— 部件接得越多，纯串联系统越不可靠
   ↓ 怎么办？给关键部件【配备份】，坏一个还有另一个  →  并联
   ↓ 但"至少有一个是好的"不好正面算（要枚举一堆情况），于是【反着算】：
        "全都坏了" = (1-R1)(1-R2)…(1-Rn)
        R = 1 − 全都坏的概率          （这就是并联公式的来历，不是硬背的）
   ↓ 真实系统从来不是纯串或纯并，而是【串并混合】
   ↓ 应对办法只有一个：分层化简 ——
        先把内层的并联小块算成一个数，把它当作【一个等效部件】，再参与外层计算
   ↓ 这也解释了工程直觉：串联降可靠性，并联提可靠性（冗余备份的数学依据）

【问题二】数据在慢设备上 → CPU 到底要等多久、要陪多久
   ↓
   最笨的办法：CPU 自己站在旁边一直问"好了没"  →  程序查询（轮询）
        CPU 全程被一个慢设备拴死，效率最低
   ↓ CPU 白等太亏了 —— 改成【好了你叫我】
   ↓  中断驱动：设备准备好才打断 CPU，CPU 平时干别的
   ↓ 可是每传一个字节就中断一次，大批量数据 = 中断风暴，
     "每次都要 CPU 亲自介入"的开销累积起来还是不行
   ↓ 再想一层：搬运数据这件苦力活，根本就【不该 CPU 亲自干】
   ↓  DMA：专用控制器直接在 主存 ↔ 外设 之间搬，搬运全程不经过 CPU，
        整块数据搬完才中断 CPU 一次
   ↓ 三种方式排成一条轴，规律只有一句：【CPU 参与程度递减 → 效率递增】

   ↓ 那 DMA 最典型的服务对象是谁？——【磁盘】。磁盘为什么慢到非 DMA 不可？
   ↓
   因为它慢在【机械运动】上。一次读盘拆成三段各自耗时的物理动作：
        ① 磁头横向移动到目标磁道            → 寻道时间（题目一般直接给）
        ② 等目标扇区转到磁头正下方          → 旋转延迟，平均转半圈
        ③ 数据随盘片转过磁头被逐位读出      → 数据传输时间
   ↓ 关键洞察：②③【同源】—— 都由转速决定。
     只要先算出"转一圈 = 60/n 秒"这一个数：
        ② = 转一圈时间 ÷ 2                  （= 30/n 秒）
        ③ = 转一圈时间 × (数据量 ÷ 磁道容量)（数据占磁道多大比例，就要转过多少圈的比例）
   ↓
   存取时间 = ① + ② + ③
```

## 第 2 层 · 考点：考试怎么问

> 排序按考频：可靠性计算（原文件标注"几乎每次都考"）→ 磁盘存取时间 → I/O 方式辨析。

### 考点① 系统可靠性计算（本课第一高频）

**题目长相**：
- "某系统由如图所示的部件组成，各部件可靠度均为 R，则系统可靠度为（ ）"，选项全是**表达式**（如 `R³`、`1-(1-R)³`、`2R²-R³`）；
- 或给具体数值："部件可靠度分别为 0.9、0.8、0.95，串联组成的系统可靠度为（ ）"；
- 或反过来考概念："为提高系统可靠性采用冗余备份，其数学依据是（ ）"。

**怎么解**（固定三步）：

1. **判结构**。判据只看一句话：
   - "**所有**部件都正常，系统才正常" / 一条链路走到底 → **串联**
   - "**只要有一个**正常，系统就能工作" / 冗余、备份、双机热备 → **并联**
2. **从最内层算起**。先把被"包"在里面的并联（或串联）小块单独算出一个数。
3. **等效替换，逐层向外**。把上一步的结果当成"一个新部件"，代入外层继续算。

| 结构 | 公式 | 记法来源 |
|---|---|---|
| 串联 | `R = R1 × R2 × … × Rn` | 都得好 → 概率相乘 |
| 并联 | `R = 1 − (1−R1)(1−R2)…(1−Rn)` | 反着算："全都坏"的概率，再用 1 减 |
| 混合 | 分层化简，内层先算，结果当一个等效部件 | 没有第三个公式 |

**陷阱**：

- ❌ 并联写成 `R1 + R2`（概率不能直接相加，两个 0.8 相加就 >1 了）或写成 `1 − R1R2`（这是"不是全好"，不是"全坏"）。**并联只有 `1−(1−R1)(1−R2)` 一种写法。**
- ❌ **漏项**：三个并联要写 `1−(1−R)³`，写成 `1−(1−R)²` 就少了一路。
- ❌ **层次做反**：混合系统必须**先算内层子系统**，先动外层一定错。
- ❌ **串并判反**：题干"只要有一个正常即可"是并联，被读成串联；反之亦然。这类题往往连图都没有，**全靠这一句话定结构**。
- ❌ 字母表达式题算完**忘了展开**去对选项形式（选项给的是 `2R²−R³`，你算成 `R(1−(1−R)²)` 就对不上——两者相等，要会化开）。

**零成本自检（务必养成）**：
- 串联结果必须 **< 所有分量中最小的那个 R**；
- 并联结果必须 **> 所有分量中最大的那个 R**；
- 任何可靠度结果都必须落在 **0 与 1 之间**。
三条里破了任何一条，一定是算错或结构判错了。

### 考点② 磁盘存取时间计算

**题目长相**："某磁盘转速为 7200 转/分钟，平均寻道时间为 8ms，每个磁道存储 12KB，现读取一个 4KB 的数据块（不跨磁道），则平均存取时间约为（ ）ms"。也常单独只问"平均旋转延迟时间"或只问"数据传输时间"。

**怎么解**（固定四步，先把转速化成"转一圈时间"是关键）：

```
存取时间 = 寻道时间 + 平均旋转延迟时间 + 数据传输时间

第1步：寻道时间 —— 题目直接给（"平均寻道时间"就是它），照抄
第2步：转一圈时间 = 60/n 秒，立刻换算成毫秒（× 1000）
第3步：平均旋转延迟 = 转一圈时间 ÷ 2 = 30/n 秒（平均要转半圈）
       数据传输时间 = 转一圈时间 × (数据量 ÷ 每磁道容量)
第4步：三项单位统一为 ms 后相加
```

- **寻道时间**：磁头移动到目标磁道所需时间（题目通常直接给出，作为已知条件）
- **平均旋转延迟时间**：磁头到位后还要等目标扇区转到磁头正下方——最好不用等、最坏等一整圈，**平均是半圈**
- **数据传输时间**：与"要传的数据占整个磁道的比例"成正比——因为读数据同样是靠盘片转过磁头完成的

**陷阱**：

- ❌ **旋转延迟忘了除以 2**。题目问的是"**平均**存取时间"，就必须用半圈（30/n）。按整圈算是本考点第一错因。
- ❌ **单位**。`60/n` 出来的是**秒**，选项几乎都是 **ms**，忘了 ×1000 直接差 1000 倍。
- ❌ **漏项**。只加了旋转延迟和传输时间，把给出的寻道时间晾在一边（或反过来只算寻道+旋转，漏掉传输）。
- ❌ **传输时间乘错基数**：必须是「**转一圈时间** × 数据占比」，不是「寻道时间 × 占比」，也不是「旋转延迟 × 占比」。
- ❌ 题目若给的是"**最大**旋转延迟"，那是**整圈**（60/n），不再除以 2——看清"平均"两个字。

**自检**：数据传输时间必须 **< 转一圈时间**（因为读的数据量小于一整个磁道）；平均旋转延迟必须**正好是转一圈时间的一半**。

> 范围说明：磁盘**调度算法**（FCFS / SSTF / SCAN 等）属于操作系统板块的设备管理内容，不在本课范围，本课只算时间、不排调度顺序。

### 考点③ I/O 方式对比（辨析题，纯记忆）

**题目长相**："关于 DMA 方式，下列描述正确的是（ ）"；"下列 I/O 控制方式中，CPU 参与程度最低的是（ ）"；"在（ ）方式下，外设与主存之间传送数据不需要 CPU 干预"。

**怎么解**：把三种方式挂到**同一条轴**上——CPU 参与程度递减、效率递增，答案自然落位。

| 方式 | CPU 干什么 | 中断次数 | 生活类比 | 效率 |
|---|---|---|---|---|
| **程序查询**（轮询、程序直接控制方式） | 主动不停地问"你好了没"，**全程傻等** | 不用中断 | 你站在打印机旁死盯着它打完，这段时间干不了别的 | 最低 |
| **中断驱动**（程序中断方式） | 平时干自己的活，设备好了才被打断；但**每传一次数据都要 CPU 介入一次** | 每传一个数据中断一次 | 你在写作业，外卖到了按门铃，你去开门取餐再回来——不用守门口，但**每次**取餐都占你时间 | 居中 |
| **DMA**（直接存储器访问） | **搬运全程不经过 CPU**，由 DMA 控制器直接在外设与主存间搬；**整块传完才中断 CPU 一次** | 每批数据 1 次 | 快递员直接把外卖放进你家冰箱，放好在群里说一声 | 最高 |

```
程序查询 < 中断驱动 < DMA        （CPU 参与程度递减，效率递增）
```

DMA 常用于**大批量数据传输**（磁盘读写是最典型场景）；本课标注的【真题·2021上】考的正是 DMA 的特征描述，出题落点通常就在这一端。

**陷阱**：

- ❌ "DMA 传送过程中需要 CPU **逐字节**传送数据" → 错，那是程序查询/中断方式的做法。
- ❌ "DMA **完全不产生中断**" → 错，一整块数据传完仍要**中断 CPU 一次**报告"搬完了"。
- ❌ "DMA **完全不需要 CPU 参与任何工作**" → 也错。传送**前** CPU 要初始化 DMA 控制器（设定主存起始地址、传送字节数、传送方向），传送**后**要响应中断；只是**中间的搬运过程**不经过 CPU。考试问"数据传送过程"时答"不经过 CPU"是对的，问"全过程完全无需 CPU"则是错的。
- ❌ **效率排序颠倒**（把 DMA 说成低于程序查询）。
- ⚠️ **"不经过 CPU" ≠ "对 CPU 零影响"**：DMA 控制器搬数据时要**占用系统总线**（常见实现是"周期挪用/周期窃取"，也有"停止 CPU 访问内存""与 CPU 交替访存"两种），此期间 CPU 访问主存会被让路。所以"数据传送不经过 CPU"指的是**不由 CPU 执行传送**，选择题这样问答"是"没错；但若选项说"DMA 对 CPU 完全没有任何开销"，那是错的。
- ⚠️ **同义词与层级**：程序查询方式 = 轮询 = **程序直接控制方式**；中断驱动 = **程序中断方式**。教材里的"**程序控制方式**"是个**上位类**，它下面除程序查询外还有"**无条件传送**"（默认外设永远就绪，连状态都不查）——软考语境里说"程序控制方式"一般就指程序查询，但**当选项里"程序查询"和"无条件传送"同时出现时，两者是并列的两个选项**，别当成同一个。

> 延伸（了解即可，不必展开）：在 DMA 之上还有**通道方式 / I/O 处理机（IOP）**，把 I/O 控制进一步交给专用处理部件。理解方向不变，仍是"CPU 参与程度继续递减"。

## 第 3 层 · 完整算例

> 以下 6 个算例已于 2026-09-02 逐步复算，**结果与原讲义完全一致，无修正**。

### A 组 · 可靠性计算

**算例 A1（串联）**：系统由三个部件串联组成，可靠度分别为 0.9、0.8、0.95，求系统可靠度。

```
结构判定：串联（三个都得正常）
R = R1 × R2 × R3
  = 0.9 × 0.8 × 0.95
  = 0.72 × 0.95
  = 0.684

自检：0.684 < 最小分量 0.8 ✓（串联必然小于最弱的那一个）
```

**算例 A2（并联）**：系统由两个部件并联组成，可靠度都是 0.9，求系统可靠度。

```
结构判定：并联（有一个正常即可）
第1步：单个部件失效概率 = 1 − 0.9 = 0.1
第2步：两个【同时】失效的概率 = 0.1 × 0.1 = 0.01
第3步：系统可靠度 = 1 − 0.01 = 0.99

自检：0.99 > 最大分量 0.9 ✓（并联必然大于最强的那一个）
```
并联后可靠度从单个部件的 0.9 提升到 0.99——这就是"冗余备份提高可靠性"的原理，真题常借此考"为什么要做冗余设计"。

**算例 A3（混合）**：系统由部件 A（可靠度 0.9）与"B、C 并联后的子系统"串联组成，B、C 可靠度都是 0.8，求整个系统可靠度。

```
结构判定：内层 B‖C 并联，外层 A 与该子系统串联 → 先内后外

第1步：算内层并联子系统 BC
       R_BC = 1 − (1−0.8)(1−0.8) = 1 − 0.2×0.2 = 1 − 0.04 = 0.96
       自检：0.96 > 0.8 ✓
第2步：把 BC 当成【一个等效部件】，与 A 串联
       R = R_A × R_BC = 0.9 × 0.96 = 0.864
       自检：0.864 < min(0.9, 0.96) = 0.9 ✓
```
> 若题目把可靠度统一写成字母 R（A、B、C 都是 R），同样的两步是：`R_BC = 1−(1−R)² = 2R−R²`，`R_系统 = R(2R−R²) = 2R² − R³`。**记得展开去对选项。**

### B 组 · 磁盘存取时间

**算例 B1（只求平均旋转延迟）**：某磁盘转速为 6000 转/分钟，求平均旋转延迟时间。

```
第1步：转一圈时间 = 60/6000 秒 = 0.01 秒 = 10 毫秒
第2步：平均旋转延迟（转半圈）= 10 ÷ 2 = 5 毫秒

自检：正好是转一圈时间的一半 ✓
```

**算例 B2（只求数据传输时间）**：某磁盘转速 7200 转/分钟，每磁道容量 12KB，读取一个 4KB 的数据块（假设不跨磁道），求数据传输时间。

```
第1步：转一圈时间 = 60/7200 秒 ≈ 0.008333 秒 ≈ 8.33 毫秒
第2步：数据占磁道的比例 = 4KB ÷ 12KB = 1/3
第3步：数据传输时间 = 8.33ms × 1/3 ≈ 2.78 毫秒

自检：2.78ms < 转一圈 8.33ms ✓（只读了磁道的三分之一，当然不到一圈）
```

**算例 B3（综合，三部分相加）**：某磁盘转速 6000 转/分钟，平均寻道时间为 8ms，每磁道容量 10KB，读取一个 2KB 数据块，求平均存取时间。

```
第1步：寻道时间 = 8ms                       （题目直接给定，照抄）
第2步：转一圈时间 = 60/6000 × 1000 = 10ms
       平均旋转延迟（半圈）= 10 ÷ 2 = 5ms
第3步：数据传输时间 = 10ms × (2KB ÷ 10KB) = 10ms × 0.2 = 2ms
第4步：平均存取时间 = 8 + 5 + 2 = 15ms

自检：三项单位都是 ms ✓；传输 2ms < 一圈 10ms ✓；旋转延迟 5ms = 10ms 的一半 ✓
```

## 第 4 层 · 速记

> **可靠性**
> 串联：`R = R1×R2×…×Rn` —— 一环坏全盘坏，**越乘越小**
> 并联：`R = 1−(1−R1)(1−R2)…` —— **先算"全都坏"，再用 1 减**（冗余备份提高可靠性）
> 混合：**先算局部子系统，把结果当"一个新部件"往上层继续串/并联**
> 自检：**串联结果小于最小分量，并联结果大于最大分量**，且必在 0~1 之间
>
> **I/O 方式**
> **程序查询 < 中断驱动 < DMA**（CPU 参与程度递减，效率递增）
> **DMA 核心：数据搬运不经过 CPU，只在一整批传完后中断一次**（选择题最爱考的干扰点）
> 但传送**前**要 CPU 初始化 DMA 控制器、传送**后**要响应中断——"完全不需要 CPU"是错的
>
> **磁盘存取**
> `存取时间 = 寻道 + 旋转延迟 + 传输`
> 转一圈 = **60/n 秒**；平均旋转延迟（半圈）= **30/n 秒**；传输 = **转一圈时间 × 数据占磁道比例**
> **先把秒换成毫秒再相加**；看清"平均"（半圈）还是"最大"（整圈）

**1.【模拟·重现2022下考点】** 某系统由部件 A 与"部件 B、C 并联构成的子系统"串联而成，各部件可靠度均为 R，则该系统的可靠度为（ ）。
A. R³　B. 2R − R²　C. 2R² − R³　D. 1 − (1−R)³
**解**：**C**。先算内层并联 `R_BC = 1−(1−R)² = 2R − R²`；再与 A 串联 `R = R × (2R−R²) = 2R² − R³`。
干扰项来源：**A** 是把三个部件全当串联；**B** 只算完并联子系统就交卷、忘了再串 A；**D** 是把三个部件全当并联。

**2.【模拟·重现2021上/2022下考点】** 某磁盘转速为 6000 转/分钟，平均寻道时间为 8ms，每个磁道存储 10KB，现读取一个 2KB 的数据块（不跨磁道），则平均存取时间约为（ ）。
A. 10ms　B. 13ms　C. 15ms　D. 20ms
**解**：**C**。转一圈 = 60/6000 = 10ms → 平均旋转延迟 5ms；传输 = 10ms × (2/10) = 2ms；合计 8+5+2 = **15ms**。
干扰项来源：**A** 漏掉旋转延迟（8+2）；**B** 漏掉传输时间（8+5）；**D** 旋转延迟按**整圈** 10ms 算（8+10+2）——即"忘了除以 2"这个第一错因。

**3.【模拟】** 某磁盘转速 7200 转/分钟，每磁道容量 12KB，读取一个 4KB 的数据块（不跨磁道），其**数据传输时间**约为（ ）。
A. 2.78ms　B. 4.17ms　C. 5.56ms　D. 8.33ms
**解**：**A**。转一圈 = 60/7200 ≈ 8.33ms，数据占磁道 4/12 = 1/3，传输 = 8.33 × 1/3 ≈ **2.78ms**。
干扰项来源：**B** 是把转一圈时间当旋转延迟除以 2（8.33/2）；**C** 是按 2/3 比例算反了；**D** 是整圈时间没乘比例。

**4.【模拟·重现2021上考点】** 需要在磁盘与主存之间高速传输大批量数据时，最合适的 I/O 控制方式是（1），该方式的特点是（2）。
(1) A. 程序查询　B. 中断驱动　C. DMA　D. 无条件传送
(2) A. CPU 逐字节搬运数据　B. 每传送一个数据中断 CPU 一次　C. 数据传送不经过 CPU，整批传完中断 CPU 一次　D. 全过程完全不需要 CPU 做任何事
**解**：**C / C**。大批量传输是 DMA 的典型场景。(2) 中 **A** 是程序查询的做法；**B** 是中断驱动的特征；**D** 说过头了——传送前 CPU 仍要初始化 DMA 控制器（主存起始地址、字节数、方向），传送结束还要响应一次中断。

   A. DMA 传送过程中需要 CPU 逐字传送数据

   C. DMA 方式效率低于程序查询方式
   D. DMA 需要 CPU 参与每一次数据的读写
4. 【模拟】某磁盘转速为 9000 转/分钟，求平均旋转延迟时间（单位：毫秒，保留两位小数）。

### 参考答案

**（2026-08-18 批改，4/4 一次通过；2026-09-02 复算无误）**

1. R = 0.95×0.9×0.9 = **0.7695**。自检：0.7695 < 最小分量 0.9 ✓
