## 定位
**这一课回答**：数据躺在磁盘上，读一次要等多久、多个请求怎么排队；它怎么搬进内存、走哪条线；这台机器整体靠不靠得住。
**前后关系**：计算机系统板块最后一课。前 6 课都在 CPU 和内存里打转，这一课走出 CPU 看外设、总线和整机可靠度；下午题不直接考。

## 开讲：一次 read() 背后，机器忙了些什么

全课跟着**一台机房里的文件服务器**走：它的机械硬盘转速 **7200 转/分**，平均寻道时间 **8ms**，每个磁道存 **12KB**。程序发一次 `read()` 要读 **4KB**。我们从"这 4KB 要等多久"一路问到"这台服务器会不会挂"。

### 一、这 4KB 要等多久：磁盘存取时间

先看盘长什么样。机械硬盘里叠着几张**盘片**，每张盘片有正反两个**盘面**；每个盘面上刻着一圈圈同心圆，每一圈叫一条**磁道**（track），越靠外的圈越长；每条磁道又被切成一段段小弧，每段叫一个**扇区**（sector），数据就存在扇区里。

每个盘面上方悬着一个**磁头**（读写数据的小探针），所有磁头装在同一根机械臂上，**一起横向移动**，所以"把 3 号盘面的磁头挪到第 500 圈"这件事做不到——挪一次，全部盘面都到第 500 圈。这些半径相同的磁道摞在一起叫一个**柱面**（cylinder）。考题里说"柱面号"还是"磁道号"，在计算上是一回事。

于是读一个扇区，机器必须干三件事，一件都省不掉：

1. **把磁头挪到目标磁道**——机械臂横向移动，这段时间叫**寻道时间**（seek time），题目一般直接给"平均寻道时间 8ms"，照抄即可。
2. **等目标扇区自己转过来**——磁头挪到位了，但要读的那个扇区可能刚刚转过去，只能等盘片带着它转回磁头正下方。这段等待叫**旋转延迟**（也叫等待时间、转动延迟）。
3. **把数据读出来**——数据不是"一下子"读走的，是盘片继续转、扇区一位位从磁头下划过去被读出来的。这段叫**传输时间**。

第 2 步要等多久？**先别往下看，你猜一下：7200 转/分的盘，磁头到位后平均还要等多少毫秒。**

手算一遍。7200 转/分，意思是一分钟转 7200 圈，那么**转一圈的时间** = 60 秒 ÷ 7200 = 1/120 秒 = **8.33ms**。

现在看两个极端：运气最好，要读的扇区正好就在磁头下面，等 0；运气最差，它刚刚滑过去，得等整整一圈，8.33ms。请求落在哪个位置是随机的，所以**平均等半圈**：8.33 ÷ 2 = **4.17ms**。

公式就是从这儿长出来的，不用背：

```
转一圈时间 = 60 / n 秒          （n = 转速，单位 转/分）
平均旋转延迟 = 转一圈 ÷ 2 = 30 / n 秒
```

第 3 步呢？磁道整整一圈存 12KB，我们只要 4KB，占磁道的 4/12 = 1/3。既然数据是靠盘转过去读出来的，读走 1/3 个磁道就只需要转 1/3 圈：8.33ms × 1/3 = **2.78ms**。所以：

```
传输时间 = 转一圈时间 × (数据量 ÷ 每磁道容量)
```

三段加起来，这就是我们那次 `read()` 的代价：

```
存取时间 = 寻道 + 旋转延迟 + 传输
         = 8ms  +  4.17ms  + 2.78ms = 14.94ms ≈ 15ms
```

**用公式再算一个验证。** 换成另一块盘：6000 转/分，平均寻道 8ms，每磁道 10KB，读 2KB。转一圈 = 60/6000 = 10ms；平均旋转延迟 = 5ms；传输 = 10ms × (2÷10) = 2ms；合计 8 + 5 + 2 = **15ms**。数换了，三步没换。

> 口径提醒：教材与培训资料写的是"**存取时间 = 寻道时间 + 等待时间**"，只有两段，因为它把"等扇区转过来 + 把数据转过去"合称等待时间。题目只给转速时按两段算；一旦题目给了"每磁道容量"和"数据块大小"，就必须把传输时间单列出来加上。另外培训资料在这句公式后面加了个括号"（平均定位时间+转动延迟）"，其中"平均定位时间"指的就是前面已经算过的寻道，塞进"等待时间"的括号里会让人把寻道算两遍——按"寻道 + 转动延迟（+ 传输）"记，别按那个括号记。

### 二、同一块盘上排了一队请求：磁盘调度

上面算的是**一个**请求。真实的文件服务器上，同一瞬间会有一堆进程都在读盘，请求落在不同磁道上。三段时间里**寻道最慢**（机械臂真的要动），所以先服务谁、后服务谁，直接决定总耗时。这就是**磁盘调度算法**要解决的事——注意它调的是**顺序**，不是单次时间，和第一节是两种问法。

还是这台服务器，把磁道号缩小到 0–49 便于手算。磁头当前停在 **20** 号磁道，刚从 15 号过来（所以它正在往大号方向走），等待队列按**到达先后**是：**30、8、45、12、38**。

**先来先服务 FCFS**：谁先到谁先服务，最公平也最笨。
`20→30→8→45→12→38`，移动 10+22+37+33+26 = **128 道**。磁头来回横跳，全在做无用功。

**最短寻道时间优先 SSTF**：每次挑离当前磁头最近的。
`20→12→8→30→38→45`，移动 8+4+22+8+7 = **49 道**。快了一多半。代价是**饥饿**：如果近处请求源源不断地来，远处那个 45 可能永远轮不上。

**扫描算法 SCAN（电梯算法）**：像电梯——认准一个方向一直走到头，顺路的都捎上，到头再掉头。磁头现在朝大号方向，那就先把 30、38、45 服务掉，走到磁道边界 49，掉头回来服务 12、8。
移动 (49−20) + (49−8) = 29 + 41 = **70 道**。比 SSTF 多，但没有人会被饿死——最坏也就等磁头跑一个来回。

**单向扫描 CSCAN**：SCAN 掉头回来的路上又服务一遍，会让中间磁道的请求被"照顾两次"，两端反而吃亏。CSCAN 干脆**只朝一个方向服务**：走到 49 之后不服务地快速退回 0，再从 0 往大号方向重来。
`20→30→38→45→(49)→(0)→8→12`，移动 29（20→49）+ 49（49→0）+ 12（0→8→12）= **90 道**。总道数最多，换来的是各磁道等待时间最均匀。

> 注意两个容易被绕的地方。其一，SCAN/CSCAN 掉头点，有的教材算到**磁盘物理边界**（本例 49），有的只算到**最远的那个请求**（本例 45，这种变体叫 LOOK，总道数变成 25+37=62 道）。考题若明确给出"磁盘共 N 个磁道"，按走到边界算。其二，本例里 SSTF 恰好最省，并不代表它永远最省——它省的是这一批请求，赔的是公平性。

**移臂调度和旋转调度分两层。** 真题的问法是：先按柱面号决定机械臂往哪挪（**移臂调度**，用上面几种算法），同一个柱面里的多个请求再按**扇区号**先后决定谁先读（**旋转调度**，因为它们不用再挪臂，只等盘转）；扇区号还一样就再按**磁头号**从小到大。这三层顺序不能颠倒。

**还有一种问法：把记录摆在磁道上的顺序也能优化。** 假设一个磁道分 11 个物理块，每块存 1 条逻辑记录 R0…R10，盘的**旋转周期 33ms**（转一圈 33ms，所以一个块划过磁头正好 3ms），磁头此刻停在 R0 开头。系统用**单缓冲区**——内存里只有一块中转区，磁盘先把记录读进它，CPU 再从它取走处理，**读和处理不能同时进行**，每条记录处理 3ms。

顺序存放（块 1..11 依次放 R0..R10）时：读 R0 占 0–3ms，处理 R0 占 3–6ms。可这 3ms 里盘没停，R1 所在的块已经从磁头下溜过去了，等它再转回来要一整圈。

所以每条记录的节奏是"**读 3ms + 处理 3ms + 白等 30ms = 36ms**"，最后一条记录处理完就结束：`10 × 36 + 3 + 3 = ` **366ms**。

优化的思路很直白：既然处理一条要 3ms（正好一个块的时间），那就让下一条记录**隔一个块**存放。

改成 `R0 R6 R1 R7 R2 R8 R3 R9 R4 R10 R5`，处理完 R0 时磁头刚好到 R1 头上，一圈不用白等，每条记录只花 3+3=6ms：`11 × 6 = ` **66ms**。从 366ms 掉到 66ms，盘没换、算法没换，只是**摆放顺序**换了。

### 三、这 4KB 怎么进内存：编址方法与三种 I/O 方式

数据在盘上算好了，接下来是 CPU 怎么把它弄进内存。第一个问题是**CPU 怎么"喊"到磁盘控制器**。外设不直接连 CPU，中间隔着**接口**（也叫 I/O 端口，是控制器上的一组寄存器，用来放命令、状态和数据）。CPU 要跟接口说话，就得有地址。有两种给法：

- **独立编址**：内存地址和接口地址是**完全独立的两个地址空间**，访问接口要用专门的 I/O 指令（如 `IN`/`OUT`），其余指令全是访问内存的。好处是读程序时一眼能分清哪句在动内存、哪句在动外设；**缺点是专用于接口的指令太少、功能太弱**。
- **统一编址**（内存映射 I/O）：内存和接口**共用一个地址空间**，接口寄存器就当成几个内存单元。好处是**原则上所有访存指令都能用来操作接口**，操作能力大大增强，指令上也不再区分；**缺点是地址空间被切走一块给接口，内存地址会不连续**。

地址有了，第二个问题是**搬运由谁来干**。三种做法，是一条"CPU 越管越少"的进化线：

**① 程序控制（查询）方式。** 最朴素：CPU 写个循环反复读接口的状态寄存器，"好了没？""好了没？"，直到设备就绪再搬一个数据。代码就是 `while (!ready);`。CPU 占用率 100%，实际吞吐低得可怜，**效率极低**。同一类里还有个更极端的**无条件传送**：干脆假定外设永远就绪，连状态都不查，只用于按键、指示灯这类"随时能用"的简单设备。考试里"程序查询"和"无条件传送"是**并列的两个选项**，别当成一个。

**② 程序中断方式。** CPU 白等太亏，改成"你好了叫我"。设备准备好就向 CPU 发**中断**（一个电信号，逼 CPU 暂停手头的指令流去处理它），CPU 平时干别的活。配套的几个名词一并认掉：从设备发出中断请求到 CPU 开始执行中断处理程序，这段叫**中断响应时间**；从处理开始到处理结束叫**中断处理时间**；CPU 靠**中断向量**（一张表里存着各中断源对应处理程序的入口地址）知道该跳去哪；被打断的那条指令位置叫**断点**，寄存器里的值叫**现场**，多级中断嵌套时用**堆栈**保存断点和现场，这样后进先出正好能层层返回。转录本给的处理流程是：

```
中断请求 → 中断响应 →（关中断）→ 保存断点 → 识别中断源 → 保存现场 →（开中断）
→ 中断服务程序 →（关中断）→ 恢复现场 →（开中断）→ 中断返回
```

效率相对高了，但**每传一个数据仍要 CPU 亲自介入一次**。读一个 4KB 的块要中断几千次，开销照样吃不消。

**③ DMA 方式（Direct Memory Access，直接主存存取）。** 再想一层：搬运这种苦力活根本不该 CPU 干。加一个专用的 **DMA 控制器**，在**主存和外设之间建立直接的数据通路**，CPU **只做必要的初始化**（告诉它主存起始地址、传多少字节、什么方向），剩下整块数据的搬运全程不经过 CPU，**搬完才中断 CPU 一次**报告完工。效率最高，磁盘正是它最典型的服务对象。

```
程序查询  <  程序中断  <  DMA        CPU 参与程度递减，效率递增
```

还有个考过的时间点差别：**CPU 在一个总线周期结束后响应 DMA 请求，而响应中断请求是在一条指令执行结束时**。总线周期是总线上完成一次数据传输所占的那一小段时间，一条指令通常要占好几个总线周期。原因不难想——DMA 要的只是总线使用权，一个总线周期用完就能让出来；中断要打断的是程序流，必须等当前这条指令做完，否则寄存器状态会残缺。

延伸一句（了解即可）：DMA 之上还有**通道**和 **I/O 处理机（IOP）**，把 I/O 控制进一步交给专门的处理部件，方向仍是 CPU 越管越少。

### 四、数据走的那条线：总线

DMA 说的"直接通路"，物理上就是**总线**（Bus）：**计算机设备和设备之间传输信息的公共数据通道**。关键词是**公共**——总线上所有设备**共享**它，所以同一时刻只能有一对设备在用，这也解释了为什么 DMA 搬数据时 CPU 访存会被挤一下。按覆盖范围分三类：

- **内部总线**：芯片级别，芯片与处理器之间通信用。
- **系统总线**：板级，连接机器内各部件。它按传的内容再分三组：**数据总线**（有多少根线就能并行传多少位数据）、**地址总线**（位数决定系统可管理的内存空间大小，32 根地址线能寻址 2³² = 4GB）、**控制总线**（传送控制命令）。代表：ISA、EISA、PCI。
- **外部总线**：设备级，微机和外部设备之间。代表：RS232（串行）、SCSI（并行）、USB（通用串行总线，即插即用、支持热插拔——插上不用装驱动、不用关机就能拔）。

还有两组辨析，考过：**并行总线**多根线同时传，适合**近距离**高速传输，线拉长了线间干扰（串扰）会让速率上不去；**串行总线**一根线一位位传，没有串扰问题，反而容易把时钟频率提上去，适合**长距离**——USB、SATA 走的都是这条路。

另外单工/半双工/全双工别混：**单工**只能一个方向传，**半双工**两个方向都能传但不能同时，**全双工**才是同时双向。

### 五、这台服务器会不会挂：系统可靠性

最后一层。这台服务器由网卡、电源、磁盘、主板一堆部件组成，每个部件都可能坏。**可靠度 R** 就是"这个部件在规定时间内正常工作的概率"，是个 0 到 1 之间的数。

**先猜一个：两个可靠度都是 0.9 的部件串起来用，整套还剩多少？** 直觉常答 0.9，实际是 **0.81**。为什么——"串起来"意味着两个都得好，系统才好；两件独立的事同时发生，概率相乘：0.9 × 0.9 = 0.81。不可靠度从 10% 直接涨到 19%。

于是**串联系统**的公式自己就出来了，它不是背来的，是"都得好 → 概率连乘"：

```
串联：R = R1 × R2 × … × Rn        一个设备不可靠，整个系统崩溃
```

代进去试试：三个部件 0.9、0.8、0.95 串联，R = 0.9 × 0.8 × 0.95 = **0.684**，比最弱的 0.8 还低。串联的规律就是**越乘越小，部件越多越不可靠**。

要救它，只能给关键部件**配备份**：两个电源并排接，坏一个还有另一个顶着——这叫**并联**（冗余）。可"至少有一个是好的"不好正面算，要枚举"只有 A 好""只有 B 好""都好"三种情况。**反着算**就一步到位：系统崩溃当且仅当**全都坏了**，全坏的概率是 (1−R1)(1−R2)…，拿 1 减掉就是能用的概率。

```
并联：R = 1 − (1−R1)(1−R2) … (1−Rn)   所有设备都不可靠，整个系统才崩溃
```

两个 0.9 并联：1 − 0.1 × 0.1 = **0.99**，比单个 0.9 还高。这就是"冗余备份提高可靠性"的全部数学依据。

真实系统当然是**混合**的。我们这台服务器：网卡（0.9）→ 双电源并联（各 0.8）→ 磁盘（待定）。没有第三个公式，只有一个做法：**分层化简，先算内层，把结果当成一个等效部件再往外算**。

```
第1步 内层并联：R双电源 = 1 − (1−0.8)(1−0.8) = 1 − 0.04 = 0.96      自检 0.96 > 0.8 ✓
第2步 当成一个部件，与网卡串联：0.9 × 0.96 = 0.864                  自检 0.864 < 0.9 ✓
第3步 若要求整机 ≥ 0.85，磁盘可靠度 x 需满足 0.864x ≥ 0.85
      x ≥ 0.85 / 0.864 ≈ 0.9838
```

这正是【真题·2019下】的原题结构，选项给的就是 `0.85/(0.9×[1−(1−0.8)²])` 这个式子，不用算到小数。**若题目把可靠度统一写成字母 R**，同样两步：内层 `1−(1−R)² = 2R−R²`，外层 `R(2R−R²) = 2R²−R³`——选项给的是展开式，**算完记得展开去对形状**。

**三条零成本自检**（考场上花两秒，能挡掉大半错误）：串联结果必须**小于最小的那个分量**；并联结果必须**大于最大的那个分量**；任何可靠度都必须落在 0 与 1 之间。破了任何一条，一定是结构判反或算错了。

**再补一种结构：N 模冗余系统。** 由 **N 个（N = 2n+1，奇数）相同的子系统和一个表决器**组成，表决器把 N 个结果里**占多数**的那个输出出去。所以只要有 **n+1 个或以上**子系统正常，系统就正常——它比并联严（并联只要 1 个好），比串联松（串联要全好）。3 模冗余（N=3，n=1，至少 2 个好）时，R系统 = 3R² − 2R³；单模 R=0.9 代进去得 **0.972**，比单模高、比两个 0.9 并联的 0.99 低，位置正好在串联和并联之间。

**最后是可靠性的四个指标**，全是定义题，认名字即可：

| 指标 | 含义 | 公式 |
|---|---|---|
| MTTF 平均无故障时间 | 平均能连续跑多久才坏一次 | 1 / 失效率（失效率＝单位时间内坏掉的比例） |
| MTTR 平均故障修复时间 | 坏一次平均修多久 | 1 / 修复率（修复率＝单位时间内能修好的比例） |
| MTBF 平均故障间隔时间 | 两次故障之间隔多久 = 跑的时间 + 修的时间 | MTTF + MTTR |
| 系统可用性 | 任意时刻抓过去，它正在正常服务的比例 | MTTF / (MTTF + MTTR) × 100% |

代个数：某服务器 MTTF = 1000 小时、MTTR = 10 小时，则 MTBF = 1010 小时，可用性 = 1000/1010 = **99.01%**。注意可用性只看"跑的时间占总时间的比例"，和可靠度 R 不是一回事——一台三天两头坏但五分钟就修好的机器，可用性可以很高，可靠度很低。

回头看那一次 `read()`：数据在盘上等寻道、等旋转，排队等调度，再由 DMA 控制器接管、走总线搬进内存。前四节算的都是「某一个环节要花多久」，只有第五节换了个问法——「这一串环节今天还在不在」。这也是为什么可靠性题给的永远是一张结构框图而不是一个部件：整机好不好用，从来不由最强的那一环决定。

## 考试怎么考

**考点① 系统可靠度计算（本课最高频）。** 三种问法：给结构框图求整体表达式（选项是 `R³`、`2R²−R³`、`1−(1−R)³` 这类式子）；给具体数字求值；给整体要求反推某个部件（2019 下就是这一种，答案本身是个算式，不用算到底）。固定三步：**判结构 → 最内层先算 → 等效替换往外**。判据只看一句话："**所有**部件都正常系统才正常"是串联，"**只要有一个**正常就能工作"、"冗余""备份""双机热备"是并联。常见错法：并联写成 `R1+R2`（概率相加，两个 0.8 就超过 1 了）或写成 `1−R1R2`（那是"不是全好"，不是"全坏"）；三路并联漏写成 `1−(1−R)²`；混合系统先动外层；算出 `R(1−(1−R)²)` 忘了展开成 `2R²−R³` 去对选项。

**考点② 磁盘存取时间。** 题干给转速 + 平均寻道时间 +（可能有）每磁道容量与数据块大小，问平均存取时间，或只问平均旋转延迟、只问传输时间。常见错法：**旋转延迟忘了除以 2**（这是第一错因，题目问"平均"就必须半圈；若问"最大旋转延迟"才是整圈）；60/n 出来是**秒**，选项是 **ms**，忘了 ×1000 差一千倍；传输时间乘错基数（必须乘转一圈时间，不是乘寻道时间或旋转延迟）；只加两项漏掉第三项。

**考点③ 磁盘调度。** 给一组磁道/柱面号和当前磁头位置，问响应序列或总移动道数。先分层：**移臂调度按柱面号，同柱面内旋转调度按扇区号**；若扇区号还相同，主流解析再按**磁头号从小到大**排（2018 下架构师那道题正是靠这一层才定出唯一答案）。常见错法：同柱面内忘了再按扇区号排；SCAN/CSCAN 漏算掉头或空返那一段道数（CSCAN 的空返是**满程**，从边界回到另一端全算）；把 SSTF 的"最近"理解成"编号最小"。

**考点④ I/O 方式对比。** 认准那条轴：程序查询 < 程序中断 < DMA。DMA 的三个高频干扰项：说"DMA 传送过程需要 CPU 逐字节搬运"（那是查询/中断的做法）、说"DMA 完全不产生中断"（整块传完仍要中断一次）、说"DMA 全过程完全不需要 CPU"（传送前要 CPU 初始化控制器、传送后要响应中断，只有中间搬运不经过 CPU）。还有一类专问响应时机，把 DMA 与中断的时间点对调来设错。

**考点⑤ 总线与编址。** 总线题多是四选一的叙述判断，错项就三种造法：把型号挂错类（把 USB 说成系统总线、把 PCI 说成外部总线）、把并行与串行的适用距离对调、把半双工说成"只能一个方向"（那是单工）。编址题只问优缺点，两条各记一个短板即可。

### 参考答案

1. **A**。内层并联 1−(1−0.8)² = 0.96，与 0.9 串联得 0.864，再乘部件 4 的 x 要 ≥ 0.85，故 x ≥ 0.85/0.864 ≈ 0.9838，形式上就是 A。B 把并联写成了"全坏"的概率（少了 1 减），算出来 23.61 > 1，一眼就该排除；C 把并联写成两个可靠度相加，0.8+0.8 = 1.6 超过 1；D 把并联写成"不可靠度翻倍"（2×0.2 = 0.4），算出来 2.36 也超过 1。三个错项的共同破绽都是**分母不是一个合法的可靠度**。
2. **D**。DMA 由控制器直接在主存与外设间搬运，CPU 不执行传送指令。中断和程序查询都得 CPU 执行指令搬每一个数据；无条件传送同样是 CPU 执行指令传送，只是不查状态。
3. **D**。从 21 号柱面出发按最短移臂：23（距 2）→ 17（距 6）→ 32（距 15）→ 38。同柱面内按扇区号升序做旋转调度：23 号上是 ②(3)、⑧(4)、③(6)；17 号上是 ⑤(4)，然后 ⑦ 与 ① 扇区号同为 9，再按磁头号升序 ⑦(7) 先于 ①(8)；32 号上是 ④(5)、⑥(10)。拼起来 ②⑧③⑤⑦①④⑥⑨。
4. **C、B**。旋转周期 33ms ÷ 11 块 = 每块 3ms。顺序存放时读一条 3ms、处理 3ms，处理期间下一块已溜走，要再等 30ms 才转回来，每条 36ms，共 10×36+3+3 = 366ms。优化分布成 R0 R6 R1 R7 R2 R8 R3 R9 R4 R10 R5，处理完正好接上下一条，每条 6ms，共 11×6 = 66ms。
5. **C**。A、B 把串行与并行说反了：并行适合近距离（线间干扰限制了距离和速率），串行适合长距离且易提高时钟频率。D 说的是单工；半双工是两个方向都能传但不能同时。C 正确：单总线上挂各种速度、各种协议的设备，仲裁与适配复杂，整体性能被拖低。
6. **C**。内层 1−(1−R)² = 2R−R²，再与 A 串联乘 R 得 2R²−R³。A 是把三个全当串联；B 是只算完并联就交卷、忘了再串 A；D 是把三个全当并联。
7. **C**。转一圈 60/7200 = 8.33ms；平均旋转延迟 4.17ms；传输 8.33 × (4/12) = 2.78ms；合计 8+4.17+2.78 = 14.94ms。A 是漏掉旋转延迟（8+2.78），B 是旋转延迟按 4.17 却漏掉传输（8+4.17），D 是旋转延迟按整圈算（8+8.33+2.78）。
8. **FCFS 128 道**（10+22+37+33+26），**SSTF 49 道**（20→12→8→30→38→45，即 8+4+22+8+7）。参考：SCAN 走到边界为 (49−20)+(49−8) = 70 道，CSCAN 走到边界再空返为 29+49+12 = 90 道。
9. **10ms**。转一圈 60/10000 = 6ms；旋转延迟 3ms；传输 6 × (8/16) = 3ms；合计 4+3+3 = 10ms。
10. **0.999**。1 − (1−0.9)³ = 1 − 0.001。自检：0.999 > 最大分量 0.9 ✓。
11. **MTBF = 1010 小时，可用性 = 1000/1010 ≈ 99.01%**。别把可用性的分母写成 MTTF。
12. **B**。A 是程序查询/中断的做法；C 效率排序颠倒；D 说过头了——传送前 CPU 要初始化 DMA 控制器（主存起始地址、字节数、方向），传送后要响应一次中断。

## 速记

- 磁盘：`存取时间 = 寻道 + 旋转延迟 + 传输`；转一圈 = **60/n 秒**（记得 ×1000 变 ms），平均旋转延迟 = **半圈**，传输 = 转一圈 × 数据量/磁道容量；"最大旋转延迟"才是整圈
- 调度：先**移臂**（按柱面）后**旋转**（按扇区，再同则按磁头号）；FCFS 公平最慢、SSTF 最近优先会**饿死**远处、SCAN 电梯到头掉头、CSCAN 只单向服务空返
- 单缓冲顺序存放每条要多等一整圈；**优化分布**＝按处理时间隔块摆放
- 编址：独立编址**接口指令少功能弱**，统一编址**内存地址不连续**
- I/O：**程序查询 < 程序中断 < DMA**；DMA 只在传前初始化、传完中断一次；**DMA 在总线周期结束响应，中断在指令结束响应**
- 总线：内部/系统（数据·地址·控制）/外部；**地址总线位数定寻址空间**（32 位→4GB）；并行近距离、串行长距离；半双工＝双向不同时
- 可靠性：串联 `R1R2…Rn`（**越乘越小**）、并联 `1−(1−R1)(1−R2)…`（**先算全坏再 1 减**）、混合**先内后外**、N 模冗余（N=2n+1）需 **n+1 个正常**，3 模为 `3R²−2R³`
- 指标：`MTBF = MTTF + MTTR`，`可用性 = MTTF/(MTTF+MTTR)`；自检：串联结果 < 最小分量，并联结果 > 最大分量
