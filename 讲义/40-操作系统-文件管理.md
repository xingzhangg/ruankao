# 40 · 操作系统：文件管理与设备管理

## 定位

操作系统板块最后一环（CPU → 内存 → 磁盘）：文件怎么按名字找到（一至三节）、内容落在哪些盘块上（四、五节）、谁有权限动它（第六节）；第七节换主题讲外设管理。39 位示图管"哪些块还空着"，本课管"这个文件占了哪些块"。两条线做的是同一件事：在裸硬件上盖一层抽象——文件系统把"第 3721 块"藏成 `report.doc`，I/O 软件把设备寄存器藏成一次 `read()`。

## 一、文件与文件系统（概念）

原话｜**文件**是具有符号名的、在逻辑上具有完整意义的一组相关信息项的集合。**信息项**是构成文件内容的基本单位，可以是一个字符，也可以是一条记录（记录可等长也可不等长）；"逻辑上完整"指对用户是一个整体，哪怕散在几十个盘块上。

| 组成 | 是什么 |
|---|---|
| **文件体** | 真实内容（数据） |
| **文件说明** | 元数据：文件名、文件内部标识、类型、存储地址、长度、访问权限、建立时间、访问时间（`ls -l` 那一行除文件名外全是它） |

裸磁盘只提供"读第 N 块、写第 N 块"。程序直接用块号：块号得硬编码、一挪位置全废；两个程序可能互相覆盖同一块；无法表达"只有我能改"。

原话｜**文件管理系统**（文件系统）是操作系统中实现文件统一管理的一组软件和相关数据的集合，专门负责管理和存取文件信息。功能：**按名存取**、统一的用户接口、并发访问和控制、安全性控制、优化性能、差错恢复。

| 分法 | 类别 |
|---|---|
| 按性质和用途 | 系统文件、库文件、用户文件 |
| 按保存期限 | 临时文件、档案文件、永久文件 |
| 按保护方式 | 只读、读/写、可执行、不保护文件 |
| UNIX | 普通文件、目录文件、设备文件（特殊文件）——目录和设备也当文件管 |

## 二、文件控制块与目录（概念）

**文件控制块 FCB**（File Control Block）就是操作系统给每个文件记的那份文件说明。

| FCB 信息类 | 内容 |
|---|---|
| **基本信息类** | 文件名、文件的物理地址、文件长度、文件块数 |
| **存取控制信息类** | 存取权限；UNIX 把用户分成文件主、同组用户、一般用户三类，各有一套 RWX |
| **使用信息类** | 建立日期、最后修改日期、最后访问日期、当前打开该文件的进程数、文件上的等待队列 |

**FCB 的有序集合就是文件目录**；目录自己也存在磁盘上，本身也是文件。

| 目录结构 | 做法 | 解决 / 遗留 |
|---|---|---|
| **一级目录** | 全盘一张表 | 两人都想叫 report.doc 就冲突 |
| **二级目录** | 主文件目录（MFD）+ 每个用户一张用户文件目录（UFD） | 用户之间可重名；单个用户的几百个文件仍平铺一层 |
| **树形目录** | 目录里再套目录 | 不同目录下可同名（`/usr/work/report.doc` 与 `/home/zhang/report.doc` 共存），要靠路径指认 |

| 术语 | 是什么 |
|---|---|
| **根目录** | 树的起点，Linux 记 `/`，Windows 记 `\` |
| **绝对路径** | 从根目录写起，不管身在何处，指向唯一 |
| **当前工作目录** | 进程此刻所在的目录（`pwd` 打出来的） |
| **相对路径** | 从当前工作目录写起；`.` 当前目录，`..` 上一级（父）目录 |
| **全文件名** | 绝对路径 + 文件名；**绝对路径、相对路径都不含最后那个文件名** |

**易混对：硬链接 vs 软链接**（都是给同一文件挂第二个名字）
- 判据｜硬链接是另一个目录项指向**同一份文件说明**，两个名字平等，删到最后一个名字文件才消失（`ln`）；软链接（符号链接）是个小文件，里面存另一个文件的**路径**，相当于 Windows 快捷方式，原文件一删就悬空（`ln -s`）。
- 例子｜`report.doc` 有一个硬链接 `r2` 和一个软链接 `r3`，删掉 `report.doc` 后，`r2` 照样能打开，`r3` 打不开。

## 三、相对路径（计算）

```
/
├── usr
│   ├── work            ← 当前工作目录
│   │   ├── report.doc
│   │   └── data
│   │       └── b.txt
│   └── temp
│       └── c.txt
└── home
    └── zhang
        └── report.doc  ← 与上面同名，另一个文件
```

**算例：当前目录 `/usr/work`，访问 `c.txt`**

1. 写出目标绝对路径：`/usr/temp/c.txt`。
2. 与当前目录逐层比，最近共同祖先是 `/usr`（`temp` 和 `work` 是并列兄弟，所以 `temp/c.txt` 是错的，它指"当前目录下的 temp"）。
3. 从 `/usr/work` 退到 `/usr` 要 1 级 → 写一个 `..`，再照抄祖先往下那段 → `../temp/c.txt`。
4. 回代：`/usr/work` --`..`--> `/usr` --`temp`--> `/usr/temp` --`c.txt`--> ✔。

规则：**退到最近共同祖先几级就写几个 `..`，再抄下行段；写完从当前目录走一遍，每个 `..` 上跳一层、每个名字下进一层，必须正好落在目标上。**

| 目标（绝对路径） | 共同祖先 | 退几级 | 相对路径 |
|---|---|---|---|
| `/usr/work/report.doc` | `/usr/work`（当前目录） | 0 | `report.doc`（`./report.doc` 亦可） |
| `/usr/work/data/b.txt` | `/usr/work` | 0 | `data/b.txt` |
| `/usr/temp/c.txt` | `/usr` | 1 | `../temp/c.txt` |
| `/home/zhang/report.doc` | `/`（根） | 2 | `../../home/zhang/report.doc` |

## 四、逻辑结构与物理结构（概念）

**易混对：逻辑结构 vs 物理结构**
- 判据｜讲"用户和程序怎么看"是逻辑结构，与磁盘怎么摆无关；讲"在物理存储设备上怎么存放、占哪些物理块"是物理结构；**带"分配"二字的一律是物理结构**。
- 例子｜"流式文件"是逻辑结构；"索引分配"是物理结构。

| 逻辑结构 | 是什么 |
|---|---|
| **有结构的记录式文件** | 内容是一条条记录，像数据库表 |
| **无结构的流式文件** | 一串字节，如 `.txt`、`.bin`，Linux 下几乎全是这类 |

三种物理结构（又叫连续分配 / 链接分配 / 索引分配）。以 `report.doc` 的 6 个**逻辑块**（文件自己从 0 数起的第 0～5 块）为例：

| 物理结构 | 怎么放 | 定位 | 优点 | 代价 |
|---|---|---|---|---|
| **连续结构**（顺序结构） | 放在连续编号的物理块上，如 18～23 | 目录项记"起始块 18 + 长度 6"，第 i 块在 18+i | 一次加法定位，顺序读写最快 | 变长时后面被占就要整体搬家；删建之后留下**碎片** |
| **链接结构**（串联结构） | 散在不连续的块上，每块设指针指向下一块：18→57→3→99→… | 顺着指针从头爬 | 不要求连续空间、易扩展、无外部碎片 | **不支持随机访问**（读第 5 块要先读 0～4）；指针占空间，断一环后面全丢 |
| **索引结构** | 块照样散落，每个文件建一张**索引表**（逻辑块号 → 物理块号），表的起始地址放进目录项 | 查一次表直接跳 | **顺序、随机访问都支持** | 多占一张表的空间 |

索引表在文件创建时由系统自动建立，与文件存在同一文件卷上；文件大时它本身占一个或几个物理块。

**易混对：链接结构 vs 索引结构**（块都不连续）
- 判据｜能否直接跳到第 k 块：索引结构查表即可（随机访问）；链接结构只能从头沿指针走（仅顺序访问）。
- 例子｜读 `report.doc` 的第 5 块：索引结构读索引表一次、再读 1 块；链接结构要把第 0～4 块依次读一遍才拿到第 5 块的块号。

## 五、inode 多级索引与最大文件容量（计算）

UNIX/Linux 把每个文件的 FCB 和索引表合成一个**定长**结构，叫**索引结点 inode**——**inode 就是 UNIX 里 FCB 的实现形式**。例外：**文件名不在 inode 里**，目录项存的是"文件名 + inode 号"；硬链接就是两个目录项写不同名字、填同一个 inode 号。

定长意味着地址项个数写死（下例 13 个）。块 1KB 时 13 项若全部直接指数据块，最大文件只有 13KB。解决办法是让后几项**不指数据块，改指一个专门装地址的块**（间接块，也叫索引块）：**前 10 个直接 + 第 11 个一级间接 + 第 12 个二级间接 + 第 13 个三级间接**。

**算例：块大小 1KB，地址 4 字节**

1. m = 一个间接块能装的地址数 = 块大小 ÷ 地址字节数 = 1024 ÷ 4 = **256**。
2. 直接：10 项各管 1 块 → **10** 块。
3. 一级间接：指向 1 个间接块，内装 m 个数据块地址 → **256** 块。
4. 二级间接：指向的块里装 m 个一级间接块地址，每个再装 m 个 → 256 × 256 = **65536** 块。
5. 前 12 项合计：10 + 256 + 65536 = **65802 块** × 1KB = **65802KB ≈ 64.26MB**。
6. 加第 13 项三级间接：256³ = **16777216** 块；13 项合计 16843018 块 ≈ **16.06GB**。

> **最大文件 = (直接块数 + 一级数×m + 二级数×m² + 三级数×m³) × 块大小**

为什么长这样：每多套一级间接，管的块数就乘一个 m。

- **先全化成块数相加，最后一次乘块大小**；中途换 KB/MB 最易错。
- 单位一律按 1024 折算（1KB = 1024B、1MB = 1024KB、1GB = 1024MB，严格写法 KiB/MiB/GiB）。
- **m 每次现算**：块 4KB、地址 4B 时 m = 4096 ÷ 4 = 1024；块 1KB 时是 256。
- 量级自检：二级项压倒性大（65536 对 266），结果应"比 64MB 大一点"；恰好 64MB 说明漏了前两项。
- **逻辑块号归哪一级**：块号从 0 起按段排队——直接 0～9，一级间接 10～265，二级间接 266～65801。

## 六、Linux 权限（计算）

身份三段，顺序固定 **u→g→o**：**属主 u**（owner，通常是创建者）、**属组 g**（group，组内共享一套权限）、**其他人 o**。每段三个开关：**r 读、w 写、x 执行**。`ls -l` 的 `-rwxr-x--x` 共 10 位：**第 1 位是文件类型**（`-` 普通文件、`d` 目录、`l` 链接），后 9 位每 3 位一段。

每段三个开关就是三个二进制位，**r=4、w=2、x=1 是位权**，一段拼成一个八进制数字（0～7）：

```
r w x
1 0 0 → 4   只读
0 1 0 → 2   只写
0 0 1 → 1   只执行
1 1 1 → 7   全有
```

**算例：`chmod 751 report.doc`**

1. 拆成三个八进制位：7 / 5 / 1。
2. 7 = 111 → `rwx`：属主可读、可写、可执行。
3. 5 = 101 → `r-x`：属组可读、**不可写**、可执行（5 = 4+1，读+执行）。
4. 1 = 001 → `--x`：其他人只能执行。
5. 权限串 **`rwxr-x--x`**。

```
644 = 110/100/100 = rw-r--r--   普通文本文件
755 = 111/101/101 = rwxr-xr-x   可执行程序和目录
反向：rw-rw-r-- → 4+2 / 4+2 / 4 = 664
```

正着算完再反着换一遍，对得上才算完。

**目录的 rwx 含义不同：**

| 位 | 对目录意味着 |
|---|---|
| `r` | 能**列出**里面有哪些名字（`ls`） |
| `w` | 能在里面**新建 / 删除 / 改名** |
| `x` | 能**进入**（`cd`）并按已知名字访问其中文件 |

有 r 没 x：看得见清单却进不去；有 x 没 r：进得去、按名字读得到，却列不出清单。

其余认名即可：`/etc` 配置文件、`/dev` 设备文件、`/home` 用户主目录、`/bin` 基本命令的可执行程序（binary）。

## 七、设备管理（概念）

外设要专门管，是因为：型号杂 → 用**分层**屏蔽；快慢差几个数量级（CPU 纳秒、磁盘毫秒、打印机秒）→ 用**缓冲**抹平；有的一次只能给一个进程 → 用 **SPOOLING** 破独占。

原话｜**设备**是计算机系统与外界交互的工具，负责计算机与外部的输入/输出，常称**外部设备**。**I/O 系统**由**设备、控制器、通道（有通道的系统才有）、总线和 I/O 软件**组成。控制器是设备与总线之间的电路，CPU 读写它的寄存器来指挥设备。

**易混对：通道 vs DMA**（都让 CPU 少管 I/O）
- 判据｜通道是专管 I/O 的小处理部件，有自己的**通道程序**，CPU 发一条启动命令，**一组 I/O 操作、多台设备**都由它管完；DMA 由专用控制器在主存与外设间直接搬**一块连续数据**，传送中数据不经 CPU，但每次传送前后仍要 CPU 设定和收尾。通道更自治。
- 例子｜一次从磁盘读入一个数据块 → DMA 足够；连续执行"读磁带、写磁盘、再打印"一串操作而 CPU 只启动一次 → 通道。（四种 I/O 控制方式完整对比见讲义 07。）

| 分法 | 类别 |
|---|---|
| **按数据组织** | **块设备**：按固定大小的块存取、可随机定位（磁盘）；**字符设备**：字符流、只能顺序（键盘、打印机、串口） |
| **按资源分配角度** | **独占设备**：同一时间只能一个进程用（打印机）；**共享设备**：多进程交替使用（磁盘）；**虚拟设备**：独占设备经技术手段变成人人有份（SPOOLING） |
| 按功能 | 输入、输出、存储、网络联网、供电设备 |
| 按数据传输速率 | 低速、中速、高速设备 |

原话｜**设备管理的任务**：多道程序环境下多个进程竞争使用设备时，按一定策略分配和管理各种设备，控制设备的各种操作，完成 I/O 设备与主存之间的数据交换。

| 要解决的问题 | 主要功能 |
|---|---|
| 不知道谁空着 | 动态掌握并记录设备状态 |
| 多个进程抢 | 设备分配与释放 |
| 快慢不匹配 | 缓冲区管理 |
| 寄存器怎么写 | 实现物理 I/O 设备的操作 |
| 上层不该关心细节 | 提供设备使用的用户接口及设备的访问和控制 |

**I/O 软件层次**（越上越像人话，越下越像寄存器）：

| 层次 | 职责 |
|---|---|
| 用户进程 | 发起 I/O 调用、格式化 I/O、Spooling |
| 设备无关软件 | 命名、保护、阻塞、缓冲、分配 |
| 设备驱动程序 | 置设备寄存器；检查状态 |
| 中断处理程序 | I/O 结束时唤醒驱动程序 |
| 硬件 | 执行 I/O 操作 |

- **设备驱动程序**：唯一知道某型号设备寄存器怎么写的代码；换牌子只换驱动、上层不改，所以上一层叫"设备无关"。
- **中断处理程序**：I/O 完成后硬件发中断，CPU 停下当前工作转去执行的代码。
- **缓冲**：在内存开一块暂存区，抹平 CPU 与外设的速度差，并减少中断次数。

用户程序读一个硬盘文件的流程：
1. 设备无关软件先检查高速缓存里有没有该数据块；
2. 没有 → 调用设备驱动程序向 I/O 硬件发请求；
3. 用户进程**阻塞**等待；
4. 磁盘操作完成，硬件产生中断，转入中断处理程序；
5. 中断处理程序认出读取完成，**唤醒用户进程**取回数据，进程继续运行。

原话｜**I/O 软件隐藏了 I/O 操作实现的细节，方便用户使用 I/O 设备。**

**SPOOLING**（外围设备联机操作，又译**假脱机技术**）：打印机是独占设备，一个进程用时别人只能干等。SPOOLING 在磁盘上建两个缓冲区——**输入井**和**输出井**；进程要打印只把命令和数据放进输出井排队，打印机按序取出打印。每个进程都感觉自己在用一台打印机，即**物理设备的虚拟化**，虚拟出的那台叫**虚拟设备**——把独占设备变成了共享设备。作业流程：作业 → 输入设备 → 预输入程序 → 输入井 → 作业调度程序 → 当前运行的作业 → 井管理程序 → 输出井 → 缓输出程序 → 输出设备。

## 速记

- 全文件名 = 绝对路径 + 文件名，路径本身不含文件名；相对路径：退到最近共同祖先几级写几个 `..`，写完回代走一遍
- FCB 三类：基本 / 存取控制 / 使用信息；FCB 的有序集合 = 文件目录；目录演进 一级 → 二级（MFD+UFD）→ 树形
- inode = UNIX 的 FCB，文件名在目录项不在 inode；硬链接同 inode，软链接存路径
- 逻辑结构 = 用户怎么看（记录式 / 流式），物理结构 = 磁盘怎么摆（带"分配"即物理）；连续快但难扩展有碎片、链接无外部碎片但只能顺序、索引顺序随机都行但多一张表
- m = 块大小 ÷ 地址字节数；最大文件 = (直接 + 一级×m + 二级×m² + 三级×m³) × 块大小，先加块数再乘
- r=4 w=2 x=1，u→g→o；751 = `rwxr-x--x`（5 = 读+执行）；`ls -l` 第 1 位是类型；目录 r = 列清单、x = 进得去
- 块 / 字符设备、独占 / 共享 / 虚拟设备；通道管一组 I/O 操作、DMA 搬一个数据块；SPOOLING = 输入井 + 输出井，独占变共享
- I/O 层次：用户进程 → 设备无关软件 → 设备驱动（置寄存器）→ 中断处理（唤醒驱动）→ 硬件；隐藏细节、方便使用
