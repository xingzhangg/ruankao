## 第 1 层 · 理解

### 一句话

> 数据结构是在回答两个先后相扣的问题：这堆数据**彼此是什么关系**（逻辑结构）、这些数据**实际摆在内存哪里**（存储结构）。线性表就是这套思路最简单的样板——它把"连续地存 还是 用指针串起来"这一个取舍，一次讲透。

### 痛点：你天天在用，但说不清代价

你写代码时早就在用数组和链表了，可下面这些问题拍脑袋答，一半会错：

- `ArrayList` 从中间 `add(i, x)` 为什么慢？`LinkedList.get(i)` 为什么慢？**慢在哪一步**？
- `ArrayList` 为什么要预先分配 capacity、还要扩容拷贝？
- "随机存取"到底指什么——是"随便取一个"吗？（不是，是**取任意位置的代价都相同**）
- 常见的想当然：以为链表哪儿都快、以为顺序表空间利用率一定高、以为链表插入删除**永远**是 O(1)。这三条在考试里全是错误选项的原料。

这些不是记忆题，是**从"存的时候连不连续"一路推出来的**。

### 一条主线

```
一堆数据要交给程序处理
   ↓ 第一个问题：它们【彼此是什么关系】？—— 逻辑结构
        一对一 → 线性结构（线性表、栈、队列、串）
        一对多 → 树
        多对多 → 图
   ↓ 关系定了，还得回答第二个问题：它们【实际摆在内存哪里】？—— 存储结构
        顺序（挨着放）／链式（指针串）／索引（另建表）／散列（算出地址）
   ↓ 关键认识：这是【两条互相独立的维度】，不是一条
        同一个逻辑关系（线性表），换一种存储方式，性能特点完全不同
        —— 所以"线性表"不是存储结构，"散列"也不是逻辑结构（考点④就考这个）
   ↓ 拿最简单的线性表当样本，其实只做一个选择：【存的时候连不连续】
        ├── 连续存 = 顺序表（数组）
        │      地址有规律 → LOC(ai) = LOC(a1) + (i−1)×L → 一步定位
        │                 → 【随机存取，取任意元素代价相同，快】
        │      但"连续"意味着中间不许有洞
        │                 → 插入要先把后面的元素整体腾开 → 移动 n−i+1 个
        │                 → 【增删慢】
        │      还得预先占下一整块连续空间 → 可能浪费，也可能不够用
        └── 不连续 = 链表
               每个结点自带指针指向下一个 → 插入删除只改指针，不搬数据
                                 → 【增删快】（前提：已经站在那个位置上）
               但地址不再有规律 → 公式失效 → 只能从头顺着指针一步步走
                                 → 【存取慢】
               每个结点还要多存一个指针 → 额外空间开销
   ↓
所以"顺序表存取快增删慢、链表存取慢增删快"根本不是两句要背的话，
它是【连不连续】这一个选择推出来的必然结果 —— 题目怎么变着问都能当场现推
   ↓
后面 W2 的每一课都在重复这套动作：
   换一种逻辑关系（树、图），再各自挑一种存储结构
   （二叉树的顺序存储 vs 链式存储、图的邻接矩阵 vs 邻接表）
   本课把这套动作在最简单的线性表上走一遍，后面就是复用
```

## 第 2 层 · 考点：考试怎么问

### 考点① 顺序表地址计算（计算类，阶段B）

**题目长相**：
> "已知一维数组（顺序表）a1,a2,…,an 采用顺序存储，每个元素占 **L** 个字节，a1 的存储地址为 **X**，则 ai 的存储地址为（ ）"
> 变形：给 `a[0]` 的地址求 `a[k]`；给出两个元素的地址反求元素长度 L；地址用十六进制给出。

**怎么解**（三步，第三步别省）：

```
下标从 1 开始（数学记法，a1 是第一个）： LOC(ai) = LOC(a1) + (i − 1) × L
下标从 0 开始（贴近 C 语言数组）：       LOC(ai) = LOC(a0) + i × L
```

1. **先认下标基准**：题干写 `a1` 是第一个 → 用 `(i−1)`；题干写 `a[0]` → 用 `i`。这一步定错，整题必错。
2. **套公式**：首地址 + 偏移量 × 单元长度。
3. **验算（必做）**：把 i 取回第一个元素代进去，结果必须等于首地址。例如 `1000 + (1−1)×4 = 1000` ✓ ——这一步能挡掉绝大部分"多加一个 L / 少加一个 L"的错。

> 这套"首地址 + 偏移 × 单元长度"的逻辑和讲义 05 的主存地址计算是同一套；后面稀疏矩阵的压缩存储地址也照用。会一次，通用。

**陷阱**：
- **下标基准弄反**（最高频错法）：把 `(i−1)×L` 写成 `i×L`，答案正好差一个 L。
- **单位没换算**：题目说"每个元素占 2 个字，1 个字 = 2 字节"，L 应取 4 字节而不是 2。
- **"第 i 个元素" ≠ "下标为 i 的元素"**：前者从 1 数，后者从 0 数。
- 地址给成十六进制时忘了按十六进制加。

### 考点② 顺序表 vs 链表对比（辨析，常考点）

**题目长相**：
> "下列关于顺序表和链表的叙述中，**正确的是**（ ）" / "**错误的是**（ ）"

**怎么解**：不背表，回到"连不连续"现场推：**连续 → 地址能算 → 随机存取；连续 → 中间不能有洞 → 插入删除要搬家**。

| 对比项 | 顺序表（数组） | 链表 |
|---|---|---|
| 按序号随机存取 | **快**，套公式一步算出地址 | **慢**，必须从头顺着指针一步步走 |
| 插入/删除（**已知位置**） | **慢**，要搬移后面的元素 | **快**，只改指针，不搬数据 |
| 空间 | 需**预先分配连续空间**，可能浪费也可能不够 | **按需申请**，但每个结点多存一个指针 |

**陷阱**（这几条几乎就是错误选项的全部来源）：
- ❌"链表也可以随机存取" —— 链表**没有**随机存取能力，只能顺序存取。
- ❌"顺序表的插入删除效率高于链表" —— 说反了。
- ❌"顺序表的存储空间利用率**一定**比链表高" —— 带"一定"的先警惕：链表每结点多一个指针是开销，但顺序表预分配的闲置空间同样是浪费，**不能一概而论**。
- ⚠️"链表插入删除是 O(1)" —— **只对一半**：只有当你**已经拿到该位置的指针**时才是 O(1)；如果还要"先找到第 i 个结点再插"，查找那步仍然是 O(n)。上表标注的"已知位置"三个字就是为这条准备的。

### 考点③ 插入/删除需移动的元素个数（计算类，阶段B）

**题目长相**：
> "长度为 n 的顺序表，在第 i 个位置插入一个新元素，需要移动（ ）个元素" / "删除第 i 个元素需要移动（ ）个元素" / "等概率下平均需移动（ ）个元素"

**怎么解**：

| 操作 | 移动个数 | 等概率下的平均值 |
|---|---|---|
| 在第 i 个位置**插入** | **n − i + 1** | **n / 2**（插入点有 n+1 种） |
| 删除第 i 个元素 | **n − i** | **(n − 1) / 2**（删除点有 n 种） |

> 平均值两条为线性表顺序存储的标准结论（等概率假设下对所有位置求平均），本次校订补入，原文件只有"插入 n−i+1"一条。

**验算习惯**：拿小例子当场数一遍。n=5、i=3：要挪的是第 3、4、5 个，共 3 个，`5−3+1=3` ✓。

**陷阱**：
- **插入和删除差 1**（`n−i+1` vs `n−i`），最容易记混。用小例子数一次就不会错：删第 3 个，只需把第 4、5 个往前挪，是 2 个 = `5−3`。
- i 从 **1** 起算，不是从 0。

### 考点④ 逻辑结构 vs 存储（物理）结构的归属（定义辨析）

**题目长相**：
> "下列属于**物理（存储）结构**的是（ ）A. 线性表　B. 树　C. 散列　D. 图"
> "关于数据的逻辑结构与存储结构，叙述**错误**的是（ ）"

**怎么解**：一句话判：
- **逻辑结构**回答"元素之间是什么**关系**"：线性表、栈、队列、串（线性）；树（一对多）；图（多对多）。
- **存储结构**回答"元素实际**摆在内存哪里、怎么找到彼此**"：顺序、链式、索引、散列。

四种存储结构各自是什么：
- **顺序存储**：元素紧挨着放进连续内存，用数组实现。好比小区门牌号连续排列，知道 1 号在哪，往后数几步就知道 5 号在哪。
- **链式存储**：元素分散存放，每个元素额外存一个指针指向下一个元素的地址。好比击鼓传花，每人只知道"下一个是谁"，不知道整体布局。
- **索引存储**：另建一张"索引表"记录 关键字 → 地址 的对应关系。
- **散列存储（哈希）**：用哈希函数直接把关键字算成存储地址。

**陷阱**：
- 把 **栈、队列、串** 当成存储结构 —— 它们是**线性逻辑结构**，各自都有顺序、链式两种存法。
- 把 **散列、索引** 当成逻辑结构 —— 它们是**存储方式**。
- "同一逻辑结构只能有一种存储结构" → 错，正是本课的主线所反对的。

### 考点⑤ 数据结构三要素与线性表定义（送分）

**题目长相**：
> "数据结构包括（ ）" / "线性表中，除第一个和最后一个元素外，每个元素（ ）"

**怎么解**：
- **三要素 = 逻辑结构（关系）+ 存储结构（怎么摆进内存）+ 运算（能做哪些增删改查）**。
- **线性表**：n（**n ≥ 0**）个数据元素的**有限序列**，记作 (a1, a2, …, an)；n = 0 时称**空表**，空表也是合法的线性表。**除首尾元素外，每个元素有且仅有一个直接前驱和一个直接后继**。线性表是一种**逻辑结构**，落到内存有两种实现：顺序表、链表。
- 链表的三种常见形式：
  - **单链表**：每结点一个"指向下一个"的指针，只能向后走。
  - **双链表**：每结点两个指针（前驱 + 后继），可双向走。
  - **循环链表**：最后一个结点的指针不指 NULL，而是指回第一个结点，成环。

**陷阱**：说成"每个元素都有一个直接前驱和一个直接后继"——**漏掉了首尾例外**（第一个无前驱、最后一个无后继），这是标准错误选项。

## 第 3 层 · 完整算例

### 算例 1：顺序表地址（下标从 1 起）

> 顺序表 a1, a2, …, a10，每个元素占 **4** 字节，LOC(a1) = **1000**，求 LOC(a6)。

```
第1步 认基准：题干第一个元素是 a1 → 用 (i−1)
第2步 代入：  LOC(a6) = LOC(a1) + (6−1) × 4
                     = 1000 + 5×4
                     = 1000 + 20
                     = 1020
第3步 验算：  令 i=1 → 1000 + (1−1)×4 = 1000 = LOC(a1) ✓ 公式没用反
答案：1020
```

### 算例 2：C 数组地址（下标从 0 起）

> `int a[20]`，每个 int 占 **4** 字节，`a[0]` 的地址是 **2000**，求 `a[8]` 的地址。

```
第1步 认基准：首元素是 a[0] → 用 i，不减 1
第2步 代入：  LOC(a[8]) = 2000 + 8×4 = 2000 + 32 = 2032
第3步 验算：  令 i=0 → 2000 + 0×4 = 2000 = LOC(a[0]) ✓
答案：2032
```

**对照算例 1 和算例 2**：算例 1 的 a6 是第 **6** 个元素，偏移要写 `(6−1)`；算例 2 的 `a[8]` 其实是第 **9** 个元素，偏移却直接写 `8`、不减 1——**差别只在题干把首元素写成 `a1` 还是 `a[0]`**。这就是考点①第一个陷阱的全部内容。

正因为地址一步就能算出来，顺序表才叫**随机存取**：访问第几个元素代价都一样，不用像链表那样一个个"顺藤摸瓜"。

### 算例 3：顺序表插入要移动几个元素

> 顺序表 a1..a5 = 10, 20, 30, 40, 50，要在**第 3 个位置**插入 25（变成 10, 20, 25, 30, 40, 50），需要移动几个元素？

```
第1步 数一遍（从后往前挪，避免覆盖）：
        50 从位置5 → 位置6
        40 从位置4 → 位置5
        30 从位置3 → 位置4     ← 位置3 空出来了
        把 25 放进位置3
        实际移动的元素：30、40、50，共 3 个
第2步 套公式验证： n − i + 1 = 5 − 3 + 1 = 3 ✓ 与手数结果一致
答案：3 个
```

**顺带把删除也数一遍**（考点③的易混点）：从 10,20,30,40,50 中**删除第 3 个**（30），只需把 40、50 各往前挪一位，共 **2** 个 = `n − i = 5 − 3 = 2`。**插入比删除多移动 1 个**，因为插入要额外腾出一个空位。

### 算例 4【模拟·变形】：反求元素长度 L

> 某顺序表 LOC(a1) = 1000，LOC(a6) = 1020，求每个元素占多少字节。

```
第1步 列式：LOC(a6) − LOC(a1) = (6−1) × L
第2步 代入：1020 − 1000 = 5L  →  20 = 5L  →  L = 4
第3步 验算：1000 + (6−1)×4 = 1020 ✓
答案：4 字节
```

> 变形题的通用做法：**公式只有一个，未知量换个位置而已**，别慌着找新公式。

## 第 4 层 · 速记

> **三要素**：逻辑结构 + 存储结构 + 运算
> **逻辑结构**：线性（线性表/栈/队列/串）、非线性（树 = 一对多，图 = 多对多）
> **存储结构**：顺序、链式、索引、散列
> ⚠️ 逻辑结构与存储结构是**两条不同维度**，别混：线性表/树/图是逻辑，散列/索引是存储
> **地址公式**：`LOC(ai) = LOC(a1) + (i−1)×L`（下标从 1）／`LOC(a0) + i×L`（下标从 0）
> 算完必验：i 取首元素代回去，必须还原成首地址
> **顺序表存取快、增删慢；链表存取慢、增删快**（根源：连不连续）
> **插入移动 n−i+1，删除移动 n−i**；等概率平均：插入 n/2，删除 (n−1)/2
> "链表插入 O(1)"的前提是**已知位置**；先按序号找位置仍要 O(n)
> 带"**一定**"的选项先警惕（如"顺序表空间利用率一定更高" → 错）
> 线性表定义："**除首尾外**，每个元素有且仅有一个直接前驱和一个直接后继"——漏掉"除首尾外"就是错误选项

## 考题回顾

**1.【模拟】** 下列关于顺序表和链表的说法，正确的是（ ）
A. 顺序表可以随机存取，链表也可以随机存取
B. 顺序表插入删除效率高于链表
C. 链表比顺序表更适合频繁进行插入和删除操作的场景
D. 顺序表的存储空间利用率一定比链表高

**解**：**C**。
- A 错：链表**不能**随机存取，只能从头顺着指针走。
- B 错：说反了，已知位置时链表插入删除只改指针，更高效。
- D 错："一定"过于绝对——链表每结点要多存一个指针，顺序表要预分配可能大量闲置，**两边各有各的浪费，不能一概而论**。
- C 对：链表增删只改指针、不搬数据，正适合频繁增删。

## 自测练习

1. 【模拟】顺序表 b1, b2, …, b20，每个元素占 2 字节，LOC(b1) = 3000，求 LOC(b15)。
2. 【模拟】顺序表长度为 8，在第 4 个位置插入一个新元素，需要移动多少个元素？若改为**删除**第 4 个元素呢？

### 参考答案

1. **3028**。`LOC(b15) = 3000 + (15−1)×2 = 3000 + 28 = 3028`。验算：i=1 时 `3000 + 0 = 3000` ✓。
2. 插入 **5** 个：`n − i + 1 = 8 − 4 + 1 = 5`（第 4~8 共 5 个元素各后移一位）。
   删除为 **4** 个：`n − i = 8 − 4 = 4`（第 5~8 共 4 个元素各前移一位）。**插入比删除多 1**。
