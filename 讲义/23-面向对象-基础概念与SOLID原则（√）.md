## 开讲：报销系统的"审批"，一开始只是一个大 if-else

还是讲义 15、16 那套内部报销系统。现在轮到写"审批"这件事，最朴素的写法每个人都写过——一个字典装单子，一个函数管审批：

```python
单据 = {"类型": "差旅", "金额": 6000, "状态": "草稿"}

def 审批(单据):
    if 单据["类型"] == "差旅":
        return "二级审批" if 单据["金额"] > 5000 else "一级审批"
    elif 单据["类型"] == "招待":
        return "二级审批" if 单据["金额"] > 2000 else "一级审批"
    elif 单据["类型"] == "办公":
        return "一级审批"
```

跑得起来，逻辑也没错。但它会在十个地方翻车。**本课的全部名词，就是这十个坑各自的补丁**——前三个坑靠三大特性补（那是"能力"），后七个坑靠设计原则补（那是"用这些能力的规矩"）：

- ① 谁都能写一句 `单据["状态"] = "已审批"`，绕开所有校验直接改数据；
- ② 三种类型的处理逻辑大段重复，改一处得记着改三处；
- ③ 调用方必须先判断类型才知道该怎么办，这种判断遍地开花；
- ④ 加第四种报销类型（培训费），必须回来撬开这个函数；
- ⑤ 新加的"实习生报销单"偷偷收窄了规矩，老代码套在它身上就崩；
- ⑥ 审批里写死了往 MySQL 存、用钉钉通知，换一个就得动业务代码；
- ⑦ 一个报销单类同时管算钱、存库、导 Excel，三件事各自都能让它改；
- ⑧ 只管签字的主管，被迫实现了"打款""对账"这些他根本不用的方法；
- ⑨ 为了复用一个"金额格式化"，让报销单去继承工具类；
- ⑩ 报表功能只用了公共包里的一个类，却被迫把整包拖进来。

### 一、坑①：先把数据和操作绑成一个整体——对象、类、抽象、封装

上面那段代码的病根，是**数据（字典）和操作（函数）分家**。把它们绑在一起，就得到**对象**：转录本的定义是"由**数据及其操作所构成的封装体**，是系统中用来**描述客观事物的一个实体**，是构成系统的一个基本单位"，通常由**对象名、属性和方法** 3 个部分组成。

张三那张 6000 元的差旅单就是一个对象：对象名是它自己，属性是类型和金额，方法是"算审批级别"。

一张张单子长得都一样，没必要每张都重写一遍，于是有**类**——"现实世界中**实体的形式化描述**，类将该实体的属性（数据）和操作（函数）封装在一起"。**对象是类的实例，类是对象的模板**。写成代码就是：

```python
class 差旅单:
    def __init__(self, 金额):
        self._金额 = 金额          # 属性：前面一根下划线，约定"外面别碰"
        self._状态 = "草稿"
    @property
    def 金额(self): return self._金额        # 只读接口：能看，不能写
    def 审批级别(self):                       # 方法
        return "二级审批" if self._金额 > 5000 else "一级审批"

d = 差旅单(6000)      # d 是对象，差旅单 是类
d.审批级别()          # → '二级审批'
d.金额 = 999999       # → AttributeError：没有 setter，改不动
```

最后那一行就是坑①被堵上的样子。堵它的机制叫**封装**：转录本原话是"**一种信息隐蔽技术**，将相关的概念组成一个单元模块，并通过一个名称来引用；面向对象封装是将数据和基于数据的操作封装成一个整体对象，**对数据的访问或修改只能通过对象对外提供的接口进行**"。想改金额？走 `修改金额()` 方法，方法里可以先查"这单是不是已经审过了"。

还剩一个词要说清，因为它和封装几乎总被混为一谈。**先别往下看，你觉得下面哪句是抽象、哪句是封装？**

> 甲：从张三、李四、王五这些具体的报销人身上，只抽出"工号、姓名、部门"三个共有字段定义成"员工"类，至于谁爱吃辣一概不管。
> 乙：员工类里的余额字段设成私有，外面想动它必须调 `扣款(金额)`，这个方法里先查余额够不够。

甲是**抽象**——"通过**特定的实例抽取共同特征以后形成概念的过程**，它强调主要特征，**忽略次要特征**"；一个对象是现实世界中一个实体的抽象，一个类是一组对象的抽象。乙是封装。

**一句判据：抽象是造类的时候决定"留哪些特征"，封装是类造好以后决定"露哪些接口"；抽象在前管内容，封装在后管边界。** 常见错法是看见"隐藏细节"四个字就选封装——抽象也在丢细节，但它丢的是"不相关的特性"，不是"不给外人看的实现"。

顺带把**类的三种角色**立住，考试直接考过：**实体类**的对象表示**现实世界中真实的实体**，如人、物（报销单、员工）；**接口类（也叫边界类）**的对象**为用户提供一种与系统合作交互的方式**，分人和系统两大类，人的接口是显示屏、窗口、Web 窗体、对话框、菜单、列表框、条形码、二维码等，系统接口涉及把数据发送到其他系统或从其他系统接收数据；**控制类**的对象用来**控制活动流，充当协调者**（比如"审批流程引擎"）。

2018 年下半年就考了"客户扫二维码支付"这个场景：客户是真实的人，实体类；二维码是人机交互的入口，接口类。

### 二、坑②：三份重复代码——继承，以及覆盖与重载

差旅单、招待单、办公单三个类，`__init__`、`金额`、状态流转全一样，只有"多少钱以上要二级审批"这条线不同。

把相同的提到上一层，就是**继承**——"表示**类之间的层次关系（父类与子类）**，这种关系使得某类对象可以继承另外一类对象的特征"，分**单继承**（一个类只有一个直接父类，Java 的类是这样）和**多继承**（可以有多个直接父类，C++ 支持）。

```python
class 报销单:                        # 父类，也叫超类、基类
    def __init__(self, 金额): self._金额 = 金额
    def 二级线(self): raise NotImplementedError    # 留给子类填
    def 审批级别(self):
        return "二级审批" if self._金额 > self.二级线() else "一级审批"

class 差旅单(报销单):                 # 子类，也叫派生类
    def 二级线(self): return 5000
class 招待单(报销单):
    def 二级线(self): return 2000
class 办公单(报销单):
    def 二级线(self): return float("inf")   # 办公费永远只走一级
```

子类里的 `二级线` 就是**覆盖**（override，也叫重写）——"子类在原有父类接口的基础上，用**适合于自己要求的实现去置换父类中的相应实现**，即在子类中重定义一个与父类**同名同参**的方法"。

这里必须停下来分一对东西，因为天天写代码的人反而最容易含糊：**覆盖 override 和重载 overload 不是一回事**。转录本把这一句单列出来提醒：**函数重载与子类父类无关，且函数是同名不同参数**。用一段真跑过的 Java 看差别最快：

```java
class Bill { String type() { return "通用单据"; } }
class TravelBill extends Bill { @Override String type() { return "差旅报销单"; } }

static String route(Bill b)       { return "route(Bill)"; }        // ┐同名不同参
static String route(TravelBill t) { return "route(TravelBill)"; }  // ┘这才叫重载

Bill b = new TravelBill();      // 声明类型是 Bill，实际对象是 TravelBill
b.type();                       // 输出 "差旅报销单"  ← 看【实际对象】
route(b);                       // 输出 "route(Bill)" ← 看【声明类型】
route((TravelBill) b);          // 输出 "route(TravelBill)"
```

**同一个 `b`，覆盖看它实际是什么，重载看它声明成什么。** 原因在**绑定**这个词：绑定是"把**过程调用和响应调用所需要执行的代码加以结合**的过程"，在一般的程序设计语言中，绑定**在编译时进行，叫作静态绑定**；**动态绑定则是在运行时进行的**，一个给定的过程调用和代码的结合直到调用发生时才进行。重载在编译期就靠参数表选定了版本（静态绑定），覆盖要等到运行时看清对象才敢选（动态绑定）。

| | 覆盖 override | 重载 overload |
|---|---|---|
| 出现在哪 | **子类与父类之间** | **同一个类里面**，与父子类无关 |
| 参数表 | **同名同参** | **同名不同参**（类型、个数或类型顺序不同） |
| 什么时候定下来 | **运行时**按对象实际类型 | **编译时**按参数表 |
| 哪种绑定 | 动态绑定 | 静态绑定 |

### 三、坑③：调用方还得判断类型——多态、消息、接口

类都分好了，调用处仍然写着 `if 类型 == "差旅": …`。真正把这个 if 消掉的是**多态**："**不同的对象收到同一个消息时产生完全不同的结果**"。

```python
for 单 in [差旅单(6000), 招待单(6000), 办公单(6000)]:
    print(单.审批级别())     # 二级审批 / 二级审批 / 一级审批
```

**同一条 `审批级别()`**，三个对象给出两种答案，调用方一个 if 都没写。转录本补了一句机制上的话：**多态由继承机制支持，将通用消息放在抽象层，具体不同的功能实现放在低层**——"通用消息"就是父类那个 `审批级别()`，"低层实现"就是各子类的 `二级线()`。

`单.审批级别()` 这个动作有个正式名字叫**消息**："体现**对象间的交互**，通过它向目标对象发送操作请求。"注意它和"函数调用"的差别：消息一定有一个**接收者**，是"对 `单` 这个对象说一句话"，而不是"执行某段代码"；正因为接收者可以换，同一句话才可能有不同回答。2023 年上半年直接考的就是这一句：不同类的对象之间通过什么通信——答消息。

父类那个只写了名字、没写实现的 `二级线()`，起的是**接口**的作用：接口"描述对操作规范的说明，其**只说明操作应该做什么**，并没有定义操作如何做"。

多态在考试里还要按四种形式认名字，转录本给的分法是**参数多态**（不同类型参数多种结构类型）、**包含多态**（父子类关系）、**过载多态**（类似于重载，一个名字不同含义）、**强制多态**（强制类型转换）。四个例子各跑一遍就分得开：

| 形式 | 转录本口径 | 一个跑得出来的例子 |
|---|---|---|
| 参数多态 | 不同类型参数多种结构类型 | `max([3,9,2])` 得 9，`max(["a","z"])` 得 `"z"`——同一段代码吃多种类型；Java 的泛型 `List<T>`、C++ 的模板都是把类型当参数传进去，属这一类 |
| 包含多态 | 父子类关系 | 上面那三张单子，`审批级别()` 各答各的 |
| 过载多态 | 一个名字不同含义 | `1+2` 得 3、`"报"+"销"` 得 `"报销"`——同一个 `+` 在不同上下文含义不同（含方法重载、运算符重载） |
| 强制多态 | 强制类型转换 | `1 + 2.5` 得 `3.5`，int 先被转成 float 才算得下去；不转的话 `"1" + 1` 直接报错 |

**常见错法是把"过载多态"和"包含多态"对调**：过载看的是**名字**（一名多义，编译期就定），包含看的是**对象**（一消息多果，运行期才定）。

### 四、坑④～⑩：能力有了，规矩是什么——设计原则

三大特性只是能力，用歪了照样一团糟。设计原则就是这套能力的使用规矩，它们全都在回答同一个问题：**需求一定会变，怎么让变化的代价最小**。转录本按 **SOLID**（单一责任、开闭、里氏替换、接口分离、依赖倒置这五条原则英文名首字母拼成的缩写）给了五条，另有四条要补——其中"共同重用"2023 年上半年考过原题。

**④ 开放—封闭原则（开闭）**：软件实体（类、模块、函数等）应该是**可以扩展的，即开放的；但是不可修改的，即封闭的**。回到坑④：朴素版加"培训费"必须撬开那个 `if-else`；面向对象版只需 `class 培训单(报销单): def 二级线(self): return 3000`，三个老类一个字不动。**判据是"加新东西时，老代码要不要改"。**

**⑤ 里氏替换原则**：**子类必须能够替换掉他们的基类型**，在任何父类可以出现的地方，都可以用子类的实例来赋值给父类型的引用。**先别往下看，猜一下下面这段违反了哪条原则**：

```python
class 审批人:
    def 可审(self, 金额): return 金额 > 0                  # 父类：正数金额都能审
class 实习审批人(审批人):
    def 可审(self, 金额):
        if 金额 > 1000: raise ValueError("超出实习生权限")   # 子类：收窄 + 抛父类没声明的异常
        return True

def 批一批(p, 金额): return p.可审(金额)
批一批(审批人(), 5000)        # → True
批一批(实习审批人(), 5000)     # → 抛 ValueError，整条老流程崩了
```

很多人答开闭，因为"感觉是扩展出了问题"。**答案是里氏替换**：老代码 `批一批` 一行没改，它是被"换进来的子类不认父类的规矩"坑死的。

**开闭管的是"改不改老代码"，里氏替换管的是"子类替父类站岗顶不顶得住"。** 子类**收窄参数取值范围、抛出父类没声明的异常、把父类的承诺打折**，都是违反里氏替换的典型样子。改法是别硬认爹：实习生审批不是审批人的一种特例，就让它单独成类。

**⑥ 依赖倒置原则**：**抽象不应该依赖于细节，细节应该依赖于抽象**，即**高层模块不应该依赖于低层模块，二者都应该依赖于抽象**。坑⑥的样子是 `class 审批服务: def __init__(self): self.渠道 = 钉钉客户端()`——业务里写死了具体实现。改法是只认抽象、由外面塞进来：

```python
class 通知渠道:                                   # 抽象：只规定"要能发"，不说怎么发
    def 发(self, 文本): raise NotImplementedError
class 邮件(通知渠道):
    def 发(self, 文本): return "MAIL:" + 文本
class 钉钉(通知渠道):
    def 发(self, 文本): return "DING:" + 文本

class 审批服务:                                    # 高层模块，只认 通知渠道 这个抽象
    def __init__(self, 渠道): self.渠道 = 渠道     # 由外面把具体渠道塞进来，自己不 new
    def 通过(self): return self.渠道.发("审批通过")

审批服务(邮件()).通过()      # → 'MAIL:审批通过'
审批服务(钉钉()).通过()      # → 'DING:审批通过'，审批服务的代码一个字没动
```

**⑦ 单一责任原则**：就一个类而言，应该**仅有一个引起它变化的原因**；当需要修改某个类的时候原因有且只有一个，**让一个类只做一种类型责任**。坑⑦那个报销单类，报销政策变要改它、换数据库要改它、财务想换 Excel 模板还要改它——三个原因，该拆成"报销单（业务）+ 报销单仓储（存储）+ 报销单导出器（报表）"。

**⑧ 接口分离原则**：**不应该强迫客户依赖于它们不用的方法**；接口属于客户，不属于它所在的类层次结构；即**依赖于抽象，不要依赖于具体**，同时在抽象级别不应该有对于细节的依赖。坑⑧就是一个胖接口 `审批流程 { 签字(); 打款(); 对账(); }`，只签字的主管被迫写两个空方法；拆成 `可签字`、`可打款`、`可对账` 三个小接口就好了。

> ⚠️ 这一条最后半句"依赖于抽象，不要依赖于具体"读着像依赖倒置，但它**不是转录本抄串了**——2021 年上半年的原题题干就是这么印的，题库参考答案给的是接口分离。**做题只认前半句：出现"不应该强迫客户依赖于它们不用的方法""接口属于客户"，一律选接口分离；出现"抽象不应该依赖于细节，细节应该依赖于抽象""高层模块不依赖低层模块""针对接口编程而不是针对实现编程"，才选依赖倒置。**

**⑨ 合成复用原则**（也叫合成聚合复用原则）：**优先使用组合、聚合，而不是继承，来达到复用的目的**。组合与聚合说的都是"甲这个对象里装着一个乙"（报销单里装着一个金额工具），两者的细微差别属于 UML 关系那一块，归 25；这里只需抓住它和继承的对比。坑⑨那种"为了用一个格式化方法就去继承工具类"，代价是把工具类的全部方法都挂到报销单身上对外暴露了，而且报销单根本不是一种金额工具，`is-a` 关系不成立。改成"报销单**持有**一个金额工具"（`has-a`），复用照样拿到，方法却不外泄。**判据一句：继承答的是"我是一种什么"，组合答的是"我有一个什么"。**

**⑩ 共同重用原则与共同封闭原则**，这两条管的是**包**（一组类打包在一起发布的单位）而不是单个类，正好对着坑⑩。**共同重用**：一个包里的类应当是一起被重用的，**如果重用了包中的一个类，就要重用包中的所有类**——所以别把用不着的类硬塞进同一个包。**共同封闭**：包中的类应对**同一类变化**共同封闭，一个变化若影响到某个包，就影响该包里所有的类，而不影响其他包。两条常互为干扰项：**问"重用"选共同重用，问"变化/封闭"选共同封闭。**

还有一条不在这条链上，认得即可：**最少知识原则（也叫迪米特法则）**——一个对象应当对其他对象有尽可能少的了解，只和自己的直接朋友说话。它没有对应上面十个坑中的任何一个，但常年在选项里当干扰项，见到"最少知识""不和陌生人说话"能认出来就够。

收口：十个坑对十件东西——封装堵①、继承堵②、多态堵③，开闭堵④、里氏替换堵⑤、依赖倒置堵⑥、单一责任堵⑦、接口分离堵⑧、合成复用堵⑨、共同重用与共同封闭堵⑩。抽象、消息、接口、绑定、覆盖、重载是描述前三样东西时绕不开的词，最少知识是编外的一条。

## 考试怎么考

**考点① 给定义句式认名词。** 题干几乎照抄教材原句，认句式就够：出现"把数据和操作**封装**成整体""只能通过对外接口访问"选封装；"在已存在的类的基础上创建新类""父类与子类的层次关系"选继承；"不同对象收到同一消息产生不同结果"选多态；"不同类的对象之间**通信**"选消息。错项造法只有两种：把三大特性互换（把"通信"答成继承），或塞一个不是特性的词（"信息""聚合""组合"）。

**考点② 覆盖与重载、动态与静态绑定。** 最常见的错误选项是"**重载在运行时根据对象的实际类型确定调用哪个方法**"——重载在编译时就按参数表定了。反向的错项是"覆盖后的方法在编译时确定"，同样错。记法：**同类不同参＝重载＝编译期；父子同签名＝覆盖＝运行期。**

**考点③ 多态四形式。** 题干给一句描述让你填形式名。"操作具有相同的名称、在不同的上下文中含义不同"是过载；"父子类关系、同一消息不同响应"是包含；"同一段代码作用于多种类型"是参数；"类型转换后才能运算"是强制。过载与包含对调是最常见的错法。

**考点④ 实体类／接口类（边界类）／控制类。** 判据是这个类**站在哪儿**：代表现实世界里真实存在的人或物，实体类；跟用户或外系统打交道的入口（屏幕、窗体、菜单、二维码、对外收发数据），接口类；不代表任何实物、只负责把流程串起来，控制类。

**考点⑤ SOLID 及其外围，给描述选原则。** 这是本课分值最集中的一处，判别词是封闭清单：

| 题干里出现 | 选 |
|---|---|
| 修改的原因有且只有一个／只做一种类型责任 | 单一责任 |
| 可以扩展但不可修改／对扩展开放对修改关闭 | 开放—封闭 |
| 子类必须能替换基类型／父类出现处都能换成子类 | 里氏替换 |
| 抽象不依赖细节、细节依赖抽象／高层不依赖低层／针对接口编程 | 依赖倒置 |
| 不应强迫客户依赖它们不用的方法／接口属于客户 | 接口分离 |
| 优先使用组合聚合而不是继承来复用 | 合成复用 |
| 重用了包中一个类就要重用包中所有类 | 共同重用 |
| 包中的类对同一类变化共同封闭 | 共同封闭 |
| 对其他对象了解尽可能少／不和陌生人说话 | 最少知识（迪米特） |

两个坑要单独记：**接口分离的题干后半截也会写"依赖于抽象，不要依赖于具体"**，别被带去选依赖倒置，只认前半句；**共同重用与共同封闭**只差"重用/封闭"两个字，看题干问的是复用还是变化。

15.【模拟】"从一批具体的报销人身上只留下工号、姓名、部门三个字段"和"把余额设为私有、只留一个扣款方法"，分别是抽象还是封装？判据是什么？

### 参考答案

1. **A**。继承是"在已存在的类的基础上创建新类"，得到的是一个**新类**。B、C 说的是往老类里加方法或属性，那是改老类，不是继承；D 把类换成了状态。
2. **C**。"相同的名称、不同上下文含义不同"是过载多态的定义原句。包含多态强调的是父子类关系下同一消息不同响应，参数多态强调同一段代码吃多种类型，强制多态强调类型转换。
3. **B、A**。客户是现实世界中真实的人，实体类；二维码是用户与系统交互的入口（属于人机接口那一类），接口类（边界类）。控制类只负责协调流程，本题没有这样的角色。
4. **C**。只认前半句"不应该强迫客户依赖于他们不用的方法"——这是接口分离的定义原句。后半句"依赖于抽象，不要依赖于具体"读着像依赖倒置，是本题最大的陷阱。
5. **C、D**。第一空：cat、bird、parrot 各自是 Animal 某个子类的对象，都可以当作 Animal 的对象；parrot 是 Parrot 的对象、Parrot 又是 Bird 的子类，所以 parrot 也可以看作 Bird 的对象。只有 C 把方向反过来了——bird 是 Bird 的对象，而 Bird 是 Parrot 的**父类**，父类的对象顶不了子类的位置（是鸟不一定是鹦鹉）。这正是里氏替换那句话的反面：能替换的方向只有"子类替父类"。第二空：不同对象收到同一条 move() 消息给出各自不同的结果，是多态的定义句；B 继承是支撑多态的机制而不是这个现象本身，C 消息传递说的是通信手段。
6. **A、D**。(37) 鸭子类实现公共的呱呱叫和游泳、把显示颜色留给野鸭和红头鸭各自实现，这是父类子类的层次关系，即继承；聚合和组合是"整体—部分"关系，不是"是一种"。(38) 一组不同对象收到同一条显示颜色消息、各显各的色，正是多态的定义句。动态绑定是多态在运行时的实现机制，题干问的是"这种现象称为"，答多态。
7. **A**。"修改的原因有且只有一个""只做一种类型的功能"是单一责任的定义原句。
8. **A、C**。(37) 姓名、成绩这些数据连同"查看成绩"这个操作一起装进对象，是封装的定义。(38) 对象之间的通信手段叫消息；继承和多态是机制不是通信手段，重载只是同名不同参。
9. **B**。"重用了一个类就要重用整包"是共同重用原则。A 共同封闭讲的是同一类变化封闭在一个包内，问的是变化不是重用。
10. **C**。同一个类里同名不同参，是方法重载；方法覆盖要求子类与父类同名同参，题干里根本没有父子类。
11. **D**。"抽象不应该依赖于细节，细节应该依赖于抽象""针对接口编程而不是针对实现编程"是依赖倒置的定义原句。C 最少知识讲的是对象之间了解越少越好。
12. **C**。调用方一行代码没改，是被"换进来的子类不守父类承诺"坑的，属里氏替换。答开闭是最常见的错法——开闭问的是"加新东西时老代码改没改"，这里老代码没改。
13. **B**。重载在**编译时**按参数表就能定，属静态绑定；运行时按实际类型定的是覆盖。
14. **B**。把"继承来复用"改成"持有对象来复用"，正是合成复用原则（优先用组合聚合而非继承）。选依赖倒置的常见理由是"都在讲别写死"，但 DIP 讲的是高层别依赖低层的**具体实现**，本题压根不涉及抽象层。
15. 前者是**抽象**（抽取共同特征、忽略次要特征），后者是**封装**（信息隐蔽，只能通过对外接口访问）。判据：抽象在造类时决定留哪些特征，封装在类造好后决定露哪些接口。
16. `b.type()` 走 **TravelBill** 的实现，看的是对象的**实际类型**，属**动态绑定**；`route(b)` 走 **`route(Bill)`**，看的是引用的**声明类型**，属**静态绑定**。同一个 `b`，覆盖看实际是什么，重载看声明成什么。

## 速记

- 对象＝数据+操作的封装体（对象名/属性/方法）；类是模板、对象是实例；实体类是人和物、接口类（边界类）是交互入口、控制类是流程协调者
- 抽象管"留哪些特征"（造类前），封装管"露哪些接口"（造类后）；继承是父子层次、分单继承多继承；多态是同一消息不同结果，由继承支持
- 消息＝对象间的交互手段，有接收者；接口只说做什么不说怎么做
- 覆盖：父子同名同参、运行时定、动态绑定；重载：同类同名不同参、编译时定、静态绑定
- 多态四形式：参数（一段代码多种类型）、包含（父子类）、过载（一名多义）、强制（类型转换）
- SOLID：一个原因改＝单一责任、可扩展不可改＝开闭、子类替父类＝里氏替换、抽象不依赖细节＝依赖倒置、不强迫客户依赖不用的方法＝接口分离
- 补四条：组合优先于继承＝合成复用；重用一个就重用整包＝共同重用；同类变化封闭在包内＝共同封闭；了解越少越好＝最少知识（迪米特）
- 两个高发陷阱：接口分离题干后半截也写"依赖于抽象不依赖具体"，只认前半句；"重载在运行时按实际类型确定"必错
