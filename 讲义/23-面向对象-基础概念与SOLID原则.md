## 第 1 层 · 理解

### 一句话

> 换一种组织代码的方式：不再是"数据 + 一堆加工数据的函数"，而是"一个个自带状态和行为的东西，互相发消息"。三大特性各治结构化方法的一种病，SOLID 则是用好这套东西的价值观。

### 痛点：结构化方法的病

结构化方法里，**数据和函数是分离的**。一个数据结构改了，散落在各处使用它的函数全要跟着改——改动会像波纹一样扩散，你根本不知道波及到哪。

面向对象换了个视角：**现实世界本来就是一个个"东西"在互相打交道**，每个东西自带自己的状态（属性）和能做的事（方法）。软件按同样方式组织，模型和现实对得上，改动被关在"东西"的边界内，牵连就小。

### 一条主线（三大特性不是三个并列名词，是三副药）

```
结构化的病：数据与函数分离 → 改一处，散落各处的调用全要跟着改
      ↓
换个组织法：类 = 图纸，对象 = 按图纸造出来的具体东西
            消息 = 东西之间【唯一】的沟通手段（本质就是方法调用）
      ↓
三大特性，各治一种病：
   封装 ── 治「内部细节被外界乱动」→ 藏起实现，只露接口
   继承 ── 治「重复代码」        → 公共部分提到父类，子类自动获得
   多态 ── 治「调用方被具体类型绑死」→ 同一句话喊出去，各对象自己决定怎么应
      ↓
   多态靠什么实现？→ 动态绑定：编译时只知道"调 cry()"，
                    运行时才按对象【实际类型】找到具体版本
      ↓
三大特性只是「能力」，用得好不好还得有「价值观」
      ↓
SOLID 等设计原则 ── 它们全都在回答同一个问题：
                   需求一定会变，怎么让变化的代价最小？
```

**最后那句话是理解 SOLID 的钥匙**：七八条原则看着零散，其实全是"抗变化"的不同角度——变化来自哪个方向，就有一条原则挡在那儿。

### 类与对象（词汇表，先立住）

- **类（Class）**：一类对象的模板/图纸，定义有哪些属性、哪些方法
- **对象（Object）/ 实例（Instance）**：按图纸造出来的具体个体。软考语境下"对象"和"实例"基本同义

```java
class Dog {                    // 类：图纸
    String name;               // 属性（状态）
    void bark() { System.out.println(name + "：汪！"); }   // 方法（行为）
}
Dog d1 = new Dog();            // d1、d2 是两个不同的对象，各有各的 name
Dog d2 = new Dog();
```

## 第 2 层 · 考点：考试怎么问

### 考点① 三大特性——给定义句式认名词（送分，必考）

考试**几乎逐字使用教材定义句式**，把句式和名词对应起来就能秒选：

| 特性 | **教材定义句式（题干长这样）** | 它治什么病 |
|---|---|---|
| **封装** | "把**数据和操作数据的方法**结合为一个整体，并**尽可能隐蔽内部细节**" | 内部细节被外界乱动 |
| **继承** | "子类**自动获得**父类的属性和方法"（父类=超类=基类；子类=派生类） | 重复代码 |
| **多态** | "**同一消息**发送给**不同对象**，产生**不同的操作行为/响应**" | 调用方被具体类型绑死 |
| **消息** | 对象之间**唯一的通信手段**（接收者 + 方法名 + 参数），`a.cry()` 即"给 a 发 cry 消息" | — |

```java
// 封装：private 挡住非法操作
class Account {
    private double balance;              // 藏起来
    public void deposit(double x) {      // 只能走接口，接口里能做校验
        if (x > 0) balance += x;
    }
}
// a.balance = -100;  ✗ 编译不过

// 多态：调用方不用为每种类型写分支，新增类型也不用改调用方
class Animal { void cry() {} }
class Dog extends Animal { void cry(){ System.out.println("汪"); } }
class Cat extends Animal { void cry(){ System.out.println("喵"); } }
Animal a = new Dog();
a.cry();     // 输出"汪"——运行时看 a 实际指向什么对象
```

**补充**：一个子类只有一个直接父类 = **单继承**（Java 类）；允许多个直接父类 = **多继承**（C++ 支持；Java 用实现多个接口达到类似效果）。

### 考点② 多态 + 动态绑定（常合并成一道两空题）

**题目长相**："同一消息发送给不同对象引起不同操作行为，这种特性称为（1）；它通常通过（2）机制在运行时实现。"
**答案**：(1) **多态** (2) **动态绑定**。

- **静态绑定**：**编译阶段**就把调用和具体方法绑死。**重载、static 方法、private 方法**都是静态绑定。
- **动态绑定**：编译时只知道"要调 cry()"，**运行时**才按对象实际类型找到具体版本。**覆盖后的方法通过父类引用调用**时就是动态绑定——**多态的实现基础**。

### 考点③ 覆盖 vs 重载（最容易被绕晕的一对）

| 对比项 | **覆盖 override（重写）** | **重载 overload** |
|---|---|---|
| 发生位置 | **子类 ↔ 父类**之间 | **同一个类**内部 |
| 方法签名 | 方法名、参数**完全相同** | 方法名相同、**参数不同**（个数或类型） |
| 决定时机 | **运行时**按对象实际类型选 | **编译时**按实参就能选定 |
| 属于哪种多态 | **运行时多态（动态）** | **编译时多态（静态）** |

```java
class Printer {
    void print(int x)    {}   // ┐ 重载：同名不同参
    void print(String s) {}   // ┘ 编译时看实参类型就知道调哪个
}
class ColorPrinter extends Printer {
    @Override void print(String s) {}   // 覆盖：签名完全相同，运行时按实际对象选
}
```

**陷阱选项**："重载在运行时根据对象的实际类型确定调用哪个方法" → **错**。重载是编译时定的。这是本考点最常见的错误选项。

### 考点④ 多态的四分法（认名字即可）

| 大类 | 种类 | 含义 | 程序员对应物 |
|---|---|---|---|
| **通用多态** | **参数多态** | 同一段代码可作用于多种类型 | 泛型 `List<T>` / C++ 模板 |
| **通用多态** | **包含多态** | 子类型可当父类型用，同一操作在不同子类型上行为不同 | 继承 + 覆盖 |
| **特定多态** | **过载多态** | 同一名字在不同上下文含义不同 | 方法重载、运算符重载 |
| **特定多态** | **强制多态** | 通过类型转换让操作适用 | int 自动转 double 参与运算 |

**记法**：**通用 = 参数 + 包含；特定 = 过载 + 强制**。

### 考点⑤ SOLID——给描述认原则（本课最高频）

考试基本不让你写代码，而是**给一句描述让你选原则名**。所以关键是把"句式 → 原则"练成条件反射。每条我给"违反的样子 → 改法"帮助理解。

**① 单一职责 SRP：一个类只有一个引起它变化的原因**
```java
// 违反：工资规则变、数据库变、报表格式变——三种原因都要改这一个类
class Employee { double calcPay(){} void saveToDb(){} String toReportXml(){} }
// 改法：拆成 Employee（业务）、EmployeeRepository（存储）、ReportFormatter（报表）
```

**② 开闭原则 OCP：对扩展开放，对修改关闭**
```java
// 违反：每加一种图形，都要回来改这个 if-else
double area(Shape s){ if(s.type==CIRCLE){...} else if(s.type==RECT){...} }
// 改法：Shape 定义抽象 area()，各子类实现；新增 Triangle 只加新类，老代码一行不动
```

**③ 里氏替换 LSP：子类必须能替换父类，且程序行为不出错**
```java
// 违反：正方形继承长方形，setWidth 时偷偷把高也改了——按长方形预期用它就出错
class Square extends Rect { void setWidth(int w){ width = height = w; } }
// 改法：不强行继承，让 Square、Rect 各自独立（或共同实现 Shape 接口）
```
> 判据：继承必须是真正的 **is-a**，不能只是"长得像"。

**④ 接口隔离 ISP：多个专门的小接口，好过一个大而全的总接口**
```java
// 违反：Robot 被迫实现自己根本不需要的 eat()
interface Worker { void work(); void eat(); }
// 改法：拆成 Workable、Eatable，Robot 只实现 Workable
```

**⑤ 依赖倒置 DIP：依赖抽象，不依赖具体实现**
```java
// 违反：业务层写死 MySQL——换数据库就要改业务代码
class OrderService { MySqlDao dao = new MySqlDao(); }
// 改法：只认 Dao 接口，具体实现由外部注入
class OrderService { private Dao dao; OrderService(Dao d){ this.dao = d; } }
```
> 口径：**高层模块不依赖低层模块，二者都依赖抽象；针对接口编程，不针对实现编程。**

### 考点⑥ 其他常考原则

| 原则 | 一句话 | **题干关键词** |
|---|---|---|
| **组合重用原则**（合成/聚合复用） | 优先用组合/聚合达到复用，而非继承 | "尽量使用组合，而不是继承" |
| **迪米特法则**（最少知识法则） | 一个对象对其他对象了解越少越好，只和直接朋友说话 | "最少知识""不和陌生人说话" |
| **共同重用原则 CRP**（包级） | 一个包中的类要一起被重用；重用了其中一个就要重用全部 | "包中的类共同重用" |
| **共同封闭原则 CCP**（包级） | 包中的类对**同一类变化**共同封闭：一个变化影响本包所有类，但不影响其他包 | "同一类变化封闭在一个包内" |

**认原则速查表（背这张就够应付选择题）**：
> 只有一个变化原因 → **单一职责**
> 扩展开放、修改关闭 → **开闭**
> 子类替换父类 → **里氏替换**
> 专门的小接口 → **接口隔离**
> 依赖抽象 / 针对接口编程 → **依赖倒置**
> 组合代替继承 → **组合重用**
> 最少了解 / 不和陌生人说话 → **迪米特**
> 包中类一起重用 → **共同重用**；同类变化封闭在包内 → **共同封闭**

## 第 4 层 · 速记

> 类是图纸对象是货；封装藏私、继承省活、多态一句喊出去各家应答各不同
> 消息 = 对象间**唯一**通信手段
> 重载：同类不同参，**编译**就定（静态）；覆盖：父子同签名，**运行**才定（动态）
> 通用多态 = 参数 + 包含；特定多态 = 过载 + 强制
> SOLID：**单**一职责一因改、**开**闭扩展不动老、**里**氏子替父不倒、**接**口拆小别贪大、**依**赖抽象不依实
> 组合优先于继承；只跟直接朋友说话（迪米特）；包内类共进退（共同重用）
> **所有设计原则都在回答同一个问题：需求会变，怎么让变化最便宜**

## 考题回顾

**1.【模拟·重现2022下考点】** 把数据和操作数据的方法封装在一起作为整体、并尽可能隐蔽内部细节的机制称为（ ）。
A. 继承　B. 多态　C. 封装　D. 消息传递
**解**：**C**。这是封装的定义句式。

**2.【模拟·重现2021上考点】** 同一消息发送给不同对象可引起不同操作行为，这种特性称为（1）；通常通过（2）机制在运行时实现。
A. 封装/静态绑定　B. 多态/动态绑定　C. 继承/动态绑定　D. 多态/静态绑定
**解**：**B**。定义句式 + 运行时按实际类型选版本 = 动态绑定。

**3.【模拟·重现2023上考点】** "对扩展开放，对修改关闭"描述的是（1）；"子类型必须能够替换掉它们的基类型"描述的是（2）。
A. 开闭/里氏替换　B. 单一职责/依赖倒置　C. 开闭/依赖倒置　D. 接口隔离/里氏替换
**解**：**A**。两句都是教材原句式。

**4.【模拟】** 关于覆盖与重载，**错误**的是（ ）。
A. 重载发生在同一个类中，方法名相同而参数不同
B. 覆盖要求子类方法与父类方法具有相同签名
C. 重载在运行时根据对象的实际类型确定调用哪个方法
D. 通过父类引用调用被覆盖的方法时发生动态绑定
**解**：**C**。重载在**编译时**按参数即可确定，是静态绑定/编译时多态。

**5.【模拟】** `PayService` 原本直接 `new AlipayClient()`，现改为依赖统一的 `PayClient` 接口、由外部注入具体实现，以便接入微信支付时不改已有代码。这主要体现（ ）原则。
A. 单一职责　B. 依赖倒置　C. 接口隔离　D. 里氏替换
**解**：**B**。"不依赖具体类、依赖抽象接口、外部注入"是依赖倒置的典型改造（同时顺带满足开闭，但"依赖接口而非实现"最直接对应 DIP）。

## 自测练习

1. 【模拟】"一个类中定义了多个同名方法，参数个数或类型不同"属于覆盖还是重载？属于编译时多态还是运行时多态？
2. 【模拟】"一个包中的所有类应该是共同重用的：如果重用了包中的一个类，就要重用包中的所有类"——这是哪条原则？
3. 【模拟】`Animal a = new Cat(); a.cry();` 输出了 Cat 版本的叫声。请用"动态绑定"一词解释为什么。

### 参考答案

1. **重载（overload）**；**编译时（静态）多态**——编译器按参数即可确定调用哪个版本。
2. **共同重用原则（CRP）**。注意与**共同封闭原则（CCP）**区分：CCP 说的是"同一类变化封闭在一个包内"。
3. 编译时 `a` 的**声明类型**是 Animal，只能确认"有 cry() 可调"；**运行时** JVM 根据 `a` **实际指向的对象类型**（Cat）把这次调用绑定到 Cat 覆盖后的 `cry()` 上。这种"运行时才把消息与具体方法绑定"的机制就是**动态绑定**。
