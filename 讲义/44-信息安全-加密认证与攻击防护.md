# 44 · 信息安全：加密、认证与攻击防护

> 真题：加密算法 2021上/2022下/2024上；证书与签名 2022下；攻击类型 2021上/2022下/2024上/2025上；协议 2021上/2022下；病毒 2024下；防火墙/IDS 2022下/2025上（考题为考点重现）｜基本无计算｜未讲（自学讲义）

## 第 0 层 · 定位

**这一课回答**：报文在一条谁都能偷看、能改、能冒充的网络上怎么活：加密（对称/非对称/混合）→摘要→数字签名→证书与 CA，协议在哪一层，攻击与病毒识别，防火墙/DMZ/IDS。

**前后关系**：第一轮主线的收口课；建立在 41/42 的分层与 ARP 之上；每个考点彼此独立，背一个得一个。

**分值与去向**：板块 7–9 分，加密/签名/攻击/协议/防火墙在 2021上–2025上 多场出现；下午不考。唯一公式 n(n−1)/2，基本零计算。

## 第 1 层 · 理解

### 一句话

> 你的报文要在一条**任何人都能偷看、都能改、都能冒充你**的网络上跑到对方手里。这一章就是人类为这件事攒出来的一整套工具箱——**先让别人看不懂，再让改动露馅，再让冒充者签不出字，最后在网络边界上盖一道墙**。

### 痛点：你写过的代码里，这四个坑至少踩过两个

- **密码明文进库** —— 库被拖走那天，全站用户的密码直接就是明文。（→ 摘要该干的活）
- **自己签的证书本地跑通、线上浏览器一片红** —— 你以为证书是"加密用的"，其实它是**证明公钥归属**用的，跟加密根本不是一回事。（→ CA / X.509）
- **SQL 拼字符串** —— `"select * from user where name='" + name + "'"`，你知道不该这么写，但说不清它到底属于哪种"攻击"、考试里叫什么名字。（→ 攻击类型识别）
- **拍脑袋答"HTTPS 用 RSA 加密数据"** —— 错。RSA 慢得跑不动正文，它只负责把 AES 的钥匙送过去。（→ 混合加密）

这一章的题不难，**难在名词太多、彼此像**：加密和签名都在用公钥私钥、装饰在证书里；蠕虫木马宏病毒都是病毒；防火墙 IDS IPS 都在拦。**平铺着背必混。**所以下面这条主线的作用，是让每个名词都挂在"它是来解决上一步剩下的哪个问题"上。

### 一条主线

一切从三个问题开始——报文要在一条不安全的网络上跑：

```
  ① 别人看得懂吗？           → 保密性
  ② 半路被改了吗？           → 完整性
  ③ 真是他发的吗？他能赖吗？  → 来源真实 / 不可否认
   │
   ▼
① 要「看不懂」= 加密
   最直觉的做法：双方共用一把钥匙
      → 【对称加密】DES / 3DES / AES / RC4 / SM4     —— 快，正文跑得动
      但留下两个死穴：钥匙本身怎么送过去？（网上明传等于没加密）
                      n 个人两两通信要 n(n−1)/2 把钥匙，根本管不过来
   │  密钥分发扛不住
   ▼
   改成【一人一对钥匙】：公钥公开给全世界，私钥只有自己有
      → 【非对称加密】RSA / ECC / SM2
      密钥分发问题消失（公钥随便发），n 个人只要 n 对
      代价：慢几个数量级，拿它加密正文跑不动
   │  一个快但送不了钥，一个能送钥但跑不快 —— 那就各干各的
   ▼
   【混合加密】：非对称负责送对称密钥，对称负责加密正文   ← HTTPS 就是这么干的
   │
   ▼
② 「看不懂」≠「没被改」。要验有没有被改，逐字节比对太贵
   → 把任意长报文压成一个定长指纹：【报文摘要】MD5(128位) / SHA-1(160位) / SM3(256位)
      单向不可逆 + 雪崩效应：改一位，指纹面目全非
   │  可是摘要没有「作者」—— 攻击者把报文和摘要【一起换掉】，你照样验得过
   ▼
③ 给摘要绑上身份：用【自己的私钥】把摘要加密一遍 = 【数字签名】
      私钥只有我有 → 凡是能用我的公钥解开的，必定是我签的
      → 一次拿到三样：完整 + 来源真实 + 不可否认
      ⚠️ 方向和加密【正好相反】：加密用「收方」的钥，签名用「发方」的钥
   │  可是……我手里这把「他的公钥」，凭什么相信真是他的？
   │  攻击者塞一把假公钥给你，后面全套白做（这就是【中间人攻击】）
   ▼
   请一个大家都信的第三方【CA】，给「某人 ↔ 某公钥」这条绑定关系签个字
   → 签出来的文件就是【数字证书】，标准格式 X.509
   → 验证它的真伪，用的是【CA 的公钥】（不是持有者的公钥！）
   │  到这里密码学工具箱齐了。但工具从不散着用 ——
   ▼
   被打包进【安全协议】，按 OSI 层次部署：
      IPSec（网络层） / SSL·TLS（传输层） / SSH·HTTPS（应用层）
   │  通道一旦焊死，攻击者就【不打通道了，绕过去打】
   ▼
   → 攻击类型：打输入、打对端、打人和上游、砸资源与搬数据（下面归成 4 类）
   │  其中「跑起来的那段恶意代码」单独成一类
   ▼
   → 病毒分类：蠕虫（自主传播）/ 木马（潜伏窃控）/ 宏病毒（寄生文档）
   │  逐点去防防不住，得在【网络边界】上工程化布防
   ▼
   → 防火墙（门口按规则拦）+ DMZ（对外服务器的缓冲区）
     + IDS（旁路，只看只报警）+ IPS（串联，能实时阻断）
```

### 九种攻击不要平铺背——归成 4 类「攻击者在骗你什么」

考试题干给的是一段**场景描述**，你要做的不是回忆九个名词，而是先问一句"**这题在问哪一类**"，把候选从 9 个收窄到 2–3 个：

| 类 | 攻击者利用的是你的哪个"信任" | 属于本类的攻击 |
|---|---|---|
| **A 类：信输入** | 你把**用户送来的数据**当成**代码/语句**执行了 | **SQL 注入**（拼进 SQL）、**XSS**（塞进网页当脚本跑） |
| **B 类：信对端** | 你以为线那头是他，其实是别人 / 是旧录音 | **ARP 欺骗**（局域网冒充网关）、**中间人**（插在中间双向转发）、**重放**（原样重发旧的合法报文） |
| **C 类：信来源** | 你以为这个页面/这个依赖包是正经的 | **钓鱼**（假网站骗你**主动**交密码）、**供应链投毒**（上游依赖包被下毒） |
| **D 类：不骗，直接砸或直接搬** | 不需要你信任什么 | **DDoS**（人海耗资源，只让你用不了、不偷数据）、**拖库**（整库搬走）、**撞库**（拿别处泄露的密码来试你） |

**收窄口诀**：题干出现"**输入框 / 参数 / 脚本**"→ A 类；出现"**冒充 / 截获后重发 / 双方都以为在直连**"→ B 类；出现"**假页面 / 邮件链接 / 第三方组件**"→ C 类；出现"**大量请求瘫痪 / 整库泄露 / 拿泄露密码试别家**"→ D 类。

## 第 2 层 · 考点：考试怎么问

> 排序依据：本文件头部「真题依据」里标注的**出现场次数**（攻击类型 4 场 > 加密算法 3 场 > 协议/防火墙各 2 场 > 签名证书/病毒各 1 场）。这是**本讲义标注口径下的排序，不是官方考频统计**；其中"数字签名方向"虽只标了 1 场，但它是全章**最易混**的点，故仍前置。

### 考点① 攻击类型识别（标注场次最多：2021上 / 2022下 / 2024上 / 2025上）

**题目长相**：
- "攻击者在登录框用户名处输入 `admin' or '1'='1`，成功绕过口令验证。这属于（ ）攻击。"
- "攻击者操纵大量傀儡主机同时向目标发起请求，使其无法对外提供服务，属于（ ）。"
- "员工点击'银行'邮件中的链接，进入与官网几乎一样的页面并输入了网银密码，属于（ ）。"

**怎么解**：先用上面的 4 类收窄，再对一句话特征。

| 攻击 | 一句话特征 |
|---|---|
| **SQL 注入** | 在输入框/参数里拼接 SQL 语句片段（如 `' or 1=1 --`），骗服务器执行非授权数据库操作 |
| **XSS 跨站脚本** | 把恶意脚本注入网页，在**其他浏览者**的浏览器里执行（窃取 Cookie、冒充会话） |
| **DDoS 分布式拒绝服务** | 操纵大量傀儡机同时发请求，耗尽目标带宽/资源使服务瘫痪——**不偷数据，只让你用不了** |
| **钓鱼** | 伪造以假乱真的网站/邮件，**诱骗用户主动交出**账号密码等敏感信息 |
| **ARP 欺骗** | 在局域网内伪造 ARP 应答冒充网关或主机，劫持/窃听本网段流量（利用 ARP 无验证的弱点） |
| **重放攻击** | 截获一段**合法**报文原样重发，骗过身份认证（**防御：加时间戳 / 随机数 / 序号**） |
| **中间人攻击** | 攻击者插在通信双方中间双向转发，两头都以为在和对方直连，实则全程被窃听篡改 |
| **拖库 / 撞库** | 拖库：攻破网站数据库整库窃走；撞库：拿 A 站泄露的账号密码去 B 站批量尝试登录（赌用户到处用同一密码） |
| **供应链投毒** | 在开发工具、第三方依赖包等上游环节植入恶意代码，随正常软件分发扩散到下游 |

**陷阱**：
- **重放 vs 中间人**：重放是**事后原样重发**（攻击者不必看懂内容，也不必在场）；中间人是**实时插在中间双向转发**。题干出现"截获后重新发送"→ 重放；"双方都以为在与对方直接通信"→ 中间人。
- **钓鱼 vs XSS**：钓鱼是**受害者自己去了假站点主动输入**；XSS 是**在真站点的页面里**跑了恶意脚本。题干里网站是真是假，是分水岭。
- **DDoS 不偷数据**。凡是选项里出现"窃取信息""获取数据"，DDoS 就该排除。
- **拖库 vs 撞库**：拖库是"从**这一家**搬走整库"；撞库是"拿**别家**泄露的密码来试这一家"。方向相反。

### 考点② 对称 vs 非对称加密，与混合加密（2021上 / 2022下 / 2024上）

**题目长相**：
- "以下加密算法中，属于非对称加密算法的是（ ）。A. DES B. AES C. RSA D. RC4"
- "某系统用 RSA 传送 AES 密钥，再用 AES 加密业务数据，则 RSA 的作用是（ ）、AES 的作用是（ ）。"

**怎么解**：先把算法按阵营对号入座，再看题干问的是"谁快""谁能解决密钥分发""谁负责正文"。

**动机复述（为什么会有两套东西）**：加密要解决**保密性**——密文被截获也读不懂。最自然的做法是双方共用一把钥匙，这就是对称加密；但"这把钥匙本身怎么安全交给对方"成了新问题（当面交换不现实，网上明文传等于没加密），而且 n 个人两两通信要维护 n(n−1)/2 把密钥。非对称加密改变规则：每人一对钥匙，**公钥公开给全世界、私钥只有自己有**，任何人用我的公钥加密的内容只有我的私钥能解——密钥分发问题消失，n 个人只需 n 对密钥。代价是运算量大、速度比对称慢几个数量级。

| 对比项 | 对称加密 | 非对称加密（公钥加密） |
|---|---|---|
| 密钥 | 加解密**同一把** | 一对：**公钥公开、私钥保密** |
| 速度 | **快**，适合加密大量数据 | **慢**，只适合加密少量数据（如密钥本身） |
| 密钥分发 | **困难（死穴）** | 容易（公钥随便发） |
| n 人两两通信 | **n(n−1)/2 把** | **n 对** |
| 代表算法 | **DES**（有效密钥 56 位，已不安全）、**3DES**（对 DES 做三次运算，常见 EDE＝加密-解密-加密，密钥 112/168 位）、**AES**（现行主流，密钥 128/192/256 位）、**RC4**（流密码）、**国密 SM4** | **RSA**（基于大整数因子分解难题）、**ECC**（椭圆曲线，密钥更短而安全性相当）、**国密 SM2**（基于椭圆曲线） |

**混合加密——实际系统的通行做法（HTTPS 思路）**：通信开始时用**非对称**加密把一个随机生成的**对称会话密钥**安全送到对方手里（体积小，慢一点无所谓），之后的大量正文数据全部用这把**对称**密钥加解密（快）。

**陷阱**：
- **"HTTPS 用 RSA 加密数据"→ 错**。RSA 只加密**会话密钥**，正文是 AES 之类的对称算法加密的。
- **国密最容易记反**：**SM4 是对称**（对标 AES），**SM2 是非对称**（椭圆曲线，对标 ECC/RSA），**SM3 是摘要**（对标 SHA）。数字小的反而是非对称，别按数字顺序推。
- **RC4 是对称**（流密码），名字短不代表它是"轻量非对称"。
- **DES 与 3DES 都是对称**；"3DES 比 DES 安全"是对的，"3DES 是非对称"是错的。

### 考点③ 报文摘要与数字签名——方向与加密相反（2022下；全章最易混）

**题目长相**：
- "用户 A 要向 B 发送一份**不可否认**的报文，A 应使用（ ）对报文摘要签名；B 收到后使用（ ）验证。"
- "关于报文摘要的叙述，错误的是（ ）。"（常混进"摘要可以还原原文""摘要保证保密性"这类错项）

**怎么解——先摘要，后签名，两步不能颠倒**：

**摘要的动机**：加密解决"别人看不懂"，但还有一个**独立需求**——内容有没有被改过（完整性）。逐字节比对原文太贵，办法是用哈希函数把任意长报文压成定长"指纹"，比对指纹即可。

摘要的**三条性质**：
1. **单向**——由摘要无法反推原文；
2. **定长输出**——**MD5 = 128 位**，**SHA-1 = 160 位**（SHA-256 = 256 位；国密对应算法为 **SM3**，输出 **256 位**）；
3. **雪崩效应**——原文改动一位，摘要面目全非，且极难找到两段不同报文有相同摘要（抗碰撞）。

摘要的**用途**：完整性校验（下载文件核对哈希值）、口令不明文存储（存哈希）、以及作为数字签名的第一步。**摘要不提供保密性**，报文本身可以是明文。

**签名的动机**：加密防"偷看"，摘要防"篡改"，但还有一个问题两者都管不了：**这份报文到底是不是你发的、你事后能不能抵赖**？现实中靠手写签名/盖章解决，数字世界的对应物就是数字签名。核心洞察：**私钥只有本人持有**——凡是能用你的公钥成功解开的东西，必然经你的私钥处理过，等于你签了字，赖不掉（不可否认性）。

**签名/验签四步**：
1. 发送方对报文求**摘要**（全文太长，签摘要即可）；
2. 用**自己的私钥**加密该摘要——这就是数字签名，附在报文后发出；
3. 接收方用**同样的哈希算法**对收到的报文重算摘要；
4. 用**发送方的公钥**解开签名得到原摘要，两个摘要一致 → 报文完整且确系对方所发。

**方向对比表（必背，考的就是这张）**：

| 目的 | 用谁的什么钥操作 | 对方用什么钥还原 | 保证什么 |
|---|---|---|---|
| **加密**（保密） | 接收方的**公钥**加密 | 接收方的**私钥**解密 | 只有接收方读得懂（保密性） |
| **签名**（认证） | 发送方的**私钥**签名 | 发送方的**公钥**验签 | 来源真实、完整、**不可否认** |

记法：加密是"**寄进对方的保险箱**"——锁（公钥）人人有，钥匙（私钥）只有收件人有；签名是"**按自己的手印**"——手印（私钥）只有我按得出，比对方法（公钥）人人可查。

**陷阱**：
- **"数字签名同时保证保密性"→ 错**。签名**不加密正文**，报文照样是明文可读。既要保密又要签名，就**两者叠加**使用。
- **方向搞反**：把"B 的公钥加密 / B 的私钥解密"当成签名答案——那是**加密**场景。一句话定生死：**加密用收方的钥，签名用发方的钥**。
- **"由摘要可以还原原文"→ 错**（单向）；**"摘要保证保密性"→ 错**（只保完整性）。
- **签的是摘要不是全文**——问"签名对什么做运算"，答摘要。

### 考点④ 数字证书与 CA（2022下）

**题目长相**："要验证某网站数字证书的真伪（是否被篡改、是否确由权威机构签发），应使用（ ）。"

**动机**：非对称体系有个隐藏漏洞——你以为拿到的是银行的公钥，其实是攻击者塞给你的假公钥（后续通信全被他解密，即中间人攻击）。**公钥本身需要"验明正身"**。办法：引入一个大家都信任的第三方——**CA（Certificate Authority，认证中心）**，由它出具"此公钥确属此人/此网站"的证明文件，这就是**数字证书**。

**怎么解**：
- 证书标准格式是 **X.509**，内含：版本号、序列号、签名算法、**颁发者（CA）**、有效期、**主体（证书持有者）**、**主体的公钥**，以及 **CA 用自己私钥对以上内容做的数字签名**。
- **验证证书真伪 = 用 CA 的公钥验证证书上 CA 的签名**。验证通过 → 证书没被篡改、确系该 CA 签发 → 证书里携带的公钥可信。
- HTTPS 建连时：服务器先把自己的证书发给浏览器 → 浏览器用**内置的 CA 公钥**验证证书 → 从证书中取出**服务器公钥** → 走考点②的混合加密流程。

**陷阱**：
- 问"验证证书用什么"，**选"该网站的公钥"是最常见错项**——网站公钥恰恰是**待验证的对象**，用它验自己毫无意义。答案永远是 **CA 的公钥**。
- **CA 的私钥是用来"签发"证书的，不是用来"验证"的**。签发用私钥、验证用公钥，与考点③的签名方向完全一致——证书本质就是"CA 对一条绑定关系的数字签名"。
- 证书里放的是**公钥**，绝不含持有者私钥。

### 考点⑤ 安全协议在哪一层（2021上 / 2022下）

**题目长相**："IPSec 工作在（ ）层"／"以下协议中工作在应用层的是（ ）"／"HTTPS 使用的默认端口是（ ）"。

**怎么解**：背这张四行表，问层次就查层次，问端口就查端口。

| 协议 | 所在层 | 一句话说明 |
|---|---|---|
| **IPSec** | **网络层** | 对 IP 分组加密认证，VPN 常用；**对上层应用透明** |
| **SSL/TLS** | **传输层**（介于传输层与应用层之间） | 为应用数据提供加密通道，**TLS 是 SSL 的标准化后继** |
| **HTTPS** | **应用层** | ＝ HTTP + SSL/TLS，端口 **443** |
| **SSH** | **应用层** | 加密远程登录，**取代明文的 Telnet**，端口 **22** |

**陷阱**：
- **IPSec 常被误答成"传输层"**。记它的定位是"加密 **IP 分组**"——名字里就带 IP，当然在网络层。
- **HTTPS 不是一个新协议**，是 HTTP 套在 SSL/TLS 上；问"HTTPS 属于哪层"答**应用层**，问"HTTPS 的安全性由谁提供"答 **SSL/TLS**。
- 端口别记混：**HTTPS 443，SSH 22**（HTTP 80、Telnet 23 作对照）。
- "IPSec 需要修改应用程序"→ **错**，它对上层应用**透明**，这正是它相对 SSL 的特点。

> ⚠️ **待核实（本课已知缺口）**：计划文件与本文件头部把这条真题依据写作"**认证方式**与安全协议 SSH/IPSec"，但本讲义的"认证"是由**考点③数字签名**（报文来源认证）和**考点④数字证书/CA**（身份与公钥绑定认证）承载的，**没有单列"身份认证方式分类"一节**（口令、生物特征、Kerberos、双因素等）。核实到的只是"这个考点在 2021上/2022下 考过"，未确认它考的是签名/证书还是身份认证手段。**做真题时若遇到单独考"认证方式分类"的题，本课需要补一节**——在核实清楚之前，此处不写任何未经确认的清单。

### 考点⑥ 防火墙、DMZ 与 IDS/IPS（2022下 / 2025上）

**题目长相**："某公司要上线一台面向互联网的 Web 服务器，应部署在（ ）区域"／"关于 IDS 与 IPS 的叙述，正确的是（ ）"／"工作在应用层、内外主机不直接连接的防火墙是（ ）"。

**动机**：内网与互联网之间需要一道可控的关卡，按规则决定什么流量能进出——这就是防火墙。但防火墙是"门卫"，只能按既定规则拦截，对绕过大门的、或看起来合规实则恶意的行为无能为力，于是还需要"监控摄像头"（IDS）乃至"能出手的保安"（IPS）。

**怎么解**：先看题干问的是**三件套里的哪一件**——问"服务器放哪个区"→ 答 **DMZ**；问"能不能阻断"→ **IDS 只报警 / IPS 能阻断**；问"工作在哪一层、内外主机是否直连"→ **包过滤（网络层、直连、快粗）vs 代理型（应用层、不直连、细慢）**。三条判据互不重叠，对上一条就能定选项。

**防火墙两种基本类型**：

| 类型 | 工作层次 | 特点 |
|---|---|---|
| **包过滤** | **网络层** | 按 IP 地址、端口、协议等规则逐包检查——**速度快、对应用透明，但检查粗**，不理解应用层内容 |
| **代理型（应用级网关）** | **应用层** | 内外主机**不直接连接**，由代理转接并检查应用层内容——**控制细、安全性高，但速度慢** |

（介于两者之间还有**状态检测**防火墙：动态跟踪连接状态，比纯包过滤聪明。）

**三个部署概念**：
- **DMZ（隔离区 / 非军事区）**：内网与外网之间划出的缓冲地带，**对外提供服务的服务器（Web、Mail、FTP）放这里**——即使被攻破，攻击者也没有直通内网的路。典型部署：外网 — 防火墙 — DMZ — 防火墙 — 内网（另一种常见做法是**单防火墙三接口**，外网口/DMZ 口/内网口各接一边）。
- **IDS（入侵检测系统）**：**旁路**部署（如接在交换机镜像口），监听流量、发现攻击特征后**报警，但不主动阻断**；探测器通常部署在**尽可能靠近攻击源或受保护资源**、需要重点监控的网段。
- **IPS（入侵防御系统）**：**串联**在链路上，检测到攻击可**实时阻断**。

**陷阱**：
- **"IDS 能主动阻断攻击"→ 错**，那是 IPS。一字之差：**IDS 只看不拦（Detection），IPS 又看又拦（Prevention）**。
- **"防火墙能防住所有攻击"→ 错**。防火墙防不了**不经过它的攻击**（如内部人员作案）和**藏在合法流量里的应用层攻击**（如从 443 端口进来的 SQL 注入）。
- **"包过滤在应用层"→ 错**，包过滤在**网络层**；"代理型速度快"→ 错，代理型**慢**。快粗 vs 细慢，是一对。
- **对外服务器"放内网更安全"→ 错**。放内网意味着必须在防火墙上给互联网开一条直通内网的口子，一旦沦陷内网门户洞开；放 **DMZ** 才是正解。

### 考点⑦ 病毒分类：蠕虫 / 木马 / 宏病毒（2024下）

**题目长相**：给一段病毒行为描述、或给一个病毒名称前缀（Worm./Trojan./Macro.），判断类别。

**怎么解**：只问一句"**它靠什么活、靠什么传**"——**自己顺着网络往外爬** → 蠕虫；**伪装成正常程序趴着不动、等人来控** → 木马；**寄生在 Office 文档里、打开就触发** → 宏病毒。若题干直接给了名称前缀（Worm./Trojan./Macro.），前缀就是答案。

| 类别 | 特征一句话 | 辨认要点 |
|---|---|---|
| **蠕虫** | **自主通过网络传播**的独立程序，不需寄生宿主文件，疯狂复制自己、消耗网络与系统资源 | 名称前缀常为 **Worm**；典型如"熊猫烧香"、震网（Stuxnet） |
| **木马（特洛伊木马）** | **伪装成正常程序潜伏**，为攻击者开后门，**窃取信息/远程控制**；**一般不自我复制** | 名称前缀常为 **Trojan**；典型如"冰河" |
| **宏病毒** | **寄生在文档的宏**（Word/Excel 等 Office 文件）中，**打开带毒文档即触发** | 感染对象是**文档文件**而非可执行程序；名称前缀常为 **Macro** |

**陷阱**：
- **蠕虫 vs 木马**：判据是"**会不会自己复制传播**"。会自主传播 → 蠕虫；潜伏不动、等着窃取和被控 → 木马。
- **宏病毒的感染对象是文档，不是可执行文件**。看到"打开 Word 文档就中招"直接选宏病毒。
- 别把**引导区病毒**（感染磁盘引导扇区）和宏病毒混——载体一个是磁盘扇区，一个是 Office 文档。

## 第 3 层 · 完整算例（本课唯一带公式的地方）

> 本课整体是定义/辨析类，**不列入阶段B**。唯一沾"计算"的是密钥数量，写一遍就够，不需反复刷。

**题面（模拟）**：某单位有 **100 名员工**，任意两人之间都要能保密通信。
(1) 若全部采用**对称加密**，系统中共需多少把密钥？
(2) 若改用**非对称加密**，共需多少对密钥？

**第 1 步 · 想清楚"一把钥匙对应什么"**
对称加密里，**一对通信双方共用一把、且只能这一对用**（若三个人共用一把，甲乙的通信丙也能解，就不叫保密了）。所以"密钥数 = 不同的两两组合数"。

**第 2 步 · 写出组合式**
从 n 个人里任取 2 个人组成一对，组合数为
```
C(n,2) = n × (n−1) / 2
```
（直观理解：每个人要和其余 n−1 人各存一把，共 n(n−1) 把；但甲—乙和乙—甲是同一把，重复算了一遍，所以除以 2。）

**第 3 步 · 代入 n = 100**
```
100 × (100 − 1) / 2
= 100 × 99 / 2
= 9900 / 2
= 4950（把）
```

**第 4 步 · 第 (2) 问**
非对称加密里，**每人只需要自己的一对（公钥 + 私钥）**，公钥公开给所有人用，不因通信对象增加而增加。
```
n = 100 → 100 对（合计 200 把钥匙：100 把公钥 + 100 把私钥）
```

**第 5 步 · 验算习惯（两条）**
1. **小数验证公式**：拿 n = 3 手工数一遍——甲乙、甲丙、乙丙共 3 把；代公式 3×2/2 = 3 ✓。n = 2 应为 1 把，2×1/2 = 1 ✓。公式没记反。
2. **量级自检**：4950 ≈ 100²/2，符合"对称密钥数按 **n² 量级**增长、非对称按 **n 量级**增长"的定性结论。若算出的数比 n 还小，一定错了。

**这道算例真正的考点不是数字，是那句结论**：对称密钥数随人数**平方级爆炸**，这就是"密钥分发/管理是对称加密死穴"的量化证据，也是非对称加密存在的理由。

## 第 4 层 · 速记

> **算法阵营**：对称快——**DES / 3DES / AES / RC4 / SM4**；非对称慢——**RSA / ECC / SM2**；摘要——**MD5 / SHA / SM3**
> **国密三兄弟**：**SM2 非对称、SM3 摘要、SM4 对称**（数字小的反而非对称）
> **混合加密**：**非对称送钥匙，对称跑正文**（HTTPS 就这么干）
> **密钥数**：对称 **n(n−1)/2** 把（平方级爆炸），非对称 **n** 对
> **方向必背**：**加密用收方钥（公加私解），签名用发方钥（私签公验）**
> **签名三保证**：**完整、真实、不可否认**——但**不保密**；签的是**摘要**不是全文
> **摘要**：**单向 + 定长 + 雪崩**；**MD5 = 128 位，SHA-1 = 160 位，SM3 = 256 位**
> **证书链**：**CA 私钥签证书，CA 公钥验证书**（格式 **X.509**）；证书里装的是**公钥**
> **协议站位**：**IPSec 网络层，SSL/TLS 传输层，SSH / HTTPS 应用层**；**HTTPS = HTTP + SSL/TLS = 443**，**SSH = 22**
> **攻击四类收窄**：信输入（注入/XSS）｜信对端（ARP/中间人/重放）｜信来源（钓鱼/供应链）｜砸与搬（DDoS/拖库撞库）
> **病毒三兄弟**：**蠕虫自己爬，木马藏着偷，宏毒住文档**
> **边界三件套**：**防火墙门口拦，IDS 旁路看（只报警），IPS 串联拦（能阻断）**；对外服务器进 **DMZ**
> **防火墙快慢**：**包过滤在网络层，快而粗；代理型在应用层，细而慢**

## 考题回顾

**1.【模拟·重现2021上考点】** 以下加密算法中，属于非对称加密算法的是（ ）。
A. DES　B. AES　C. RSA　D. RC4

> **答案：C**。RSA 基于大整数因子分解难题，是非对称（公钥）加密算法；DES、AES 是分组对称加密，RC4 是流式对称加密。同类考法还会把国密拉进来：**SM4 是对称，SM2 是非对称（椭圆曲线），SM3 是摘要**。

**2.【模拟·重现2022下考点】** 用户 A 要向用户 B 发送一份不可否认的报文，A 应使用（ ）对报文摘要进行签名；B 收到后使用（ ）验证签名。
A. A 的私钥 / A 的公钥　B. A 的公钥 / A 的私钥　C. B 的公钥 / B 的私钥　D. B 的私钥 / B 的公钥

> **答案：A**。签名用**发送方自己的私钥**（只有 A 持有，签了赖不掉），验签用**发送方的公钥**（人人可验）。选项 C 的"B 的公钥加密、B 的私钥解密"是**加密保密**场景而非签名——**加密用收方的钥，签名用发方的钥**，两条路方向相反。

**3.【模拟·重现2022下考点】** 要验证某网站数字证书的真伪（是否被篡改、是否确由权威机构签发），应使用（ ）。
A. 该网站的公钥　B. 该网站的私钥　C. CA 的公钥　D. CA 的私钥

> **答案：C**。证书由 CA 用**自己的私钥**签名，验证时用 **CA 的公钥**验签；验证通过后才能信任证书里携带的网站公钥。别选 A——**网站公钥恰恰是待验证的对象**；也别选 D——CA 私钥只有 CA 有，是签发用的。

**4.【模拟·重现2024上考点】** 攻击者在某网站登录框的用户名处输入 `admin' or '1'='1`，成功绕过口令验证登入系统。这种攻击属于（ ）。
A. DDoS 攻击　B. SQL 注入　C. 钓鱼攻击　D. 重放攻击

> **答案：B**。输入内容被拼进 SQL 查询语句，`'1'='1'` 恒真使 WHERE 条件失效——典型 SQL 注入（**A 类：信输入**）。DDoS 是耗资源瘫痪服务、不偷数据；钓鱼是假网站骗用户主动交信息；重放是重发截获的合法报文。

**5.【模拟·重现2024下考点】** 某病毒寄生在 Word 文档中，用户打开带毒文档时被触发感染，该病毒属于（ ）。
A. 蠕虫病毒　B. 特洛伊木马　C. 宏病毒　D. 引导区病毒

> **答案：C**。寄生于 Office 文档的宏、随文档打开触发——宏病毒的标志性特征。蠕虫是自主网络传播的独立程序；木马伪装潜伏、开后门窃控，一般不自我复制；引导区病毒感染的是磁盘引导扇区。

## 自测练习

1. 【模拟】HTTPS 为什么既用非对称加密又用对称加密？各自负责什么？
2. 【模拟】某公司员工收到"银行"邮件，点击链接进入与官网几乎一样的页面并输入了网银密码，随后账户被盗。这属于哪种攻击？若攻击者是截获合法登录报文后原样重发骗过认证，又属于哪种？
3. 【模拟】公司要上线一台对互联网提供服务的 Web 服务器，从网络安全部署角度它应放在哪个区域？为什么？

### 参考答案

1. **非对称加密负责在通信开始时安全传送对称会话密钥**（公钥公开、无密钥分发难题，但运算慢，只处理小数据）；**对称加密负责用该会话密钥加密后续大量正文**（速度快）。两者组合＝既解决密钥分发、又保证传输效率。
2. 前者是**钓鱼攻击**（伪造可信站点诱骗用户**主动**交出敏感信息，属"信来源"C 类）；后者是**重放攻击**（不破解内容，原样重发截获的合法报文骗过认证，属"信对端"B 类，防御手段是**时间戳/随机数/序号**）。
3. 应放在 **DMZ（隔离区）**——内外网之间的缓冲区。对外服务必须允许互联网访问，暴露面大、被攻破风险高；放在 DMZ 后即使沦陷，攻击者与内网之间仍隔着防火墙，不会直接威胁内部网络。
