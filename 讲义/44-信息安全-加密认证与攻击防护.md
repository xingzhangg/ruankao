# 44 · 信息安全：加密、认证与攻击防护

## 定位

一份数据走在谁都能偷看、篡改、冒充的网络上，要堵五个洞：被读到 → 对称/非对称加密与数字信封（二、三）；被改 → 信息摘要（四）；来源不明、事后赖账 → 数字签名（五）；手里的公钥本身是假的 → 数字证书与 CA（六）；整张网的边界和门内敌人 → 防火墙、IDS/IPS、攻击与病毒（八、九）。第一节先立安全属性的坐标，第七节把工具按 OSI 层装进协议。只有对称密钥数一处要动笔算。

---

## 一、安全属性、安全需求与安全空间

**原话｜** 保护信息的保密性、完整性、可用性，另外也包括其他属性，如：真实性、可核查性、不可抵赖性和可靠性。

| 属性 | 原话 / 要点 |
|---|---|
| **保密性** | 信息不被泄漏给未授权的个人、实体和过程或不被其使用的特性。措施：最小授权原则、防暴露、信息加密、物理保密 |
| **完整性** | 信息未经授权不能改变的特性。影响因素：设备故障、误码、人为攻击、计算机病毒。保证方法五条：**协议**（检测出被删除、失效、被修改的字段）、**纠错编码**（校验码检错纠错，即讲义 01 的海明码/CRC）、**密码校验和**、**数字签名**（识别发送方来源）、**公证**（请系统管理或中介机构证明真实性） |
| **可用性** | 需要时，授权实体可以访问和使用的特性；用系统正常使用时间 ÷ 整个工作时间度量 |
| **真实性** | 对信息的来源进行判断，能对伪造来源的信息予以鉴别 |
| **可核查性** | 系统实体的行为可以被独一无二地追溯到该实体，要求该实体对其行为负责 |
| **不可抵赖性** | 建立有效的责任机制，防止用户否认其行为；电子商务中极其重要 |
| **可靠性** | 规定时间、给定条件下无故障地完成规定功能的概率（即讲义 07 的 R(t)） |

**安全需求四层**（原话｜可划分为物理线路安全、网络安全、系统安全和应用安全）：

| 关键词 | 属于 |
|---|---|
| 物理设备、物理环境：机房安全、防雷、线路 | 物理线路安全 |
| 网络上的攻击、入侵：入侵检测 | 网络安全 |
| 操作系统漏洞、补丁：漏洞补丁管理 | 系统安全 |
| 上层应用软件，**包括数据库软件**：数据库安全 | 应用安全 |

**易混对① 系统安全 vs 应用安全**
- 判据｜管操作系统本身的漏洞与补丁 → 系统；管跑在操作系统之上的软件（含数据库）→ 应用。
- 例子｜给服务器打操作系统补丁 → 系统安全；给数据库做账号权限加固 → 应用安全。

**安全空间**：信息安全系统体系架构画成三维立方体——**X 轴"安全机制"**（为提供某些安全服务，利用各种安全技术和技巧所形成的较为完善的机构体系）、**Y 轴"OSI 网络参考模型"**、**Z 轴"安全服务"**（从网络各层次提供给信息应用系统所需的安全服务支持），三轴围出的空间叫信息系统的"**安全空间**"，五大要素：**认证、权限、完整、加密、不可否认**。原图：Z 轴 7 项服务（对等实体认证、访问控制、数据保密、数据完整性、数据源点认证、禁止否认、犯罪证据提供）；X 轴 **9** 项机制（基础设施、平台、数据、通信、应用、**运行**、管理、授权和审计安全，安全防范体系），图注漏了"运行安全"，以图为准。

## 二、对称加密

### （概念）

**明文**＝原始能读懂的内容；**密文**＝加密后的乱码；**密钥**＝控制加解密的秘密参数。

**原话｜** 密码体制由五部分组成：明文空间 M、密文空间 C、密钥空间 K（每个密钥 K 由加密密钥 Ke 和解密密钥 Kd 组成，K=<Ke, Kd>）、加密算法 E（一组由 M 至 C 的加密变换）、解密算法 D。
**C = E(M, Ke)**，**M = D(C, Kd) = D(E(M, Ke), Kd)**。

示意图上 Ke 与 Kd 之间要走一条**安全信道**——对称加密的麻烦全在这里。

**对称加密**：原话｜数据的加密和解密的密钥（密码）是相同的，属于**不公开密钥加密算法**。**优点**：加密速度快，适合加密大数据；**缺点**：加密强度不高（密钥位数少），且**密钥分发困难**（密钥还要传给接收方，也要保密）。

| 算法 | 特征 |
|---|---|
| **DES** | 替换+移位、**56 位密钥、64 位数据块**、速度快，密钥易产生 |
| **3DES** | 三重 DES，两个 56 位密钥 K1、K2（记作 112 位）。加密：K1 加密 → K2 解密 → K1 加密；解密：K1 解密 → K2 加密 → K1 解密（加密一趟是"加—解—加"） |
| **AES** | 美国联邦政府采用的区块加密标准，替代 DES，要求"至少像 3DES 一样安全" |
| **RC-5**（及 RC-4） | RSA 数据安全公司的很多产品使用 RC-5；RC 家族是**对称**的，"RSA 公司出品"≠ RSA 算法 |
| **IDEA** | **128 位密钥、64 位数据块**，比 DES 加密性好，对计算机功能要求相对低 |
| **SM4** | 国密，对称 |

### （计算）两两保密通信要多少把对称密钥

一对通信双方独占一把钥。

1. 每人与其余 n−1 人各存一把：共 n(n−1) 把。
2. 甲—乙与乙—甲是同一把，每把算了两次：除以 2 → **n(n−1)/2**。
3. n=100：100×99/2 = 9900/2 = **4950 把**。
4. 验：n=2 → 1 把；n=3 → 3 把（甲乙、甲丙、乙丙）。

对称密钥数按 n² 量级增长，这就是"密钥分发难"的量化证据（非对称每人一对，按 n 增长）。

## 三、非对称加密与数字信封

**非对称加密**：原话｜数据的加密和解密的密钥是不同的，分为公钥和私钥，是**公开密钥加密算法**。**公钥**可以公开给所有人，**私钥**只有本人持有、从不外传。缺点：加密速度慢；优点：安全性高，不容易破解。

**原话｜** 发送者发送数据时，**使用接收者的公钥作加密密钥，私钥作解密密钥**，这样只有接收者才能解密密文得到明文。安全性更高，因为无需传输密钥。但**无法保证完整性**。
道理：只有接收者有私钥，加密就只能用与之配对的接收者公钥。

示意图：A →加密（**pk_B**）→ 密文 → 解密（**sk_B**）→ B；pk＝公钥、sk＝私钥，**两把钥都属于 B**。

| 算法 | 特征 |
|---|---|
| **RSA** | 512 位（或 1024 位）密钥，计算量极大，难破解 |
| **Elgamal、ECC（椭圆曲线）、背包算法、Rabin、D-H** | 非对称，认名即可 |
| **DSA** | 数字签名算法，公开密钥算法 |
| **SM2** | 国密，非对称（椭圆曲线） |

**国密三件**：**SM2 非对称、SM3 摘要、SM4 对称**——数字小的反而是非对称，不能按数字顺序推。

| | 对称 | 非对称 |
|---|---|---|
| 密钥 | 加解密相同 | 公钥、私钥不同 |
| 密钥长度 | 一般 56 位 | 1024 位 |
| 速度 / 强度 | 加密过程简单、快；强度不高 | 解密计算量庞大、慢；难以破解 |
| 适合 | 加密大数据 | 不适合大数据，一般用来加密对称算法的密钥 |

**数字信封**：原话｜信是对称加密的密钥，数字信封就是对此密钥进行非对称加密。
过程：发送方用对称密钥加密数据；用**接收方公钥**加密对称密钥，一起发出；接收方用自己的私钥解开信封取出对称密钥，再解密得原文。
**本质**：对称密钥加密数据，非对称密钥加密对称密钥，解决了对称密钥的传输问题。HTTPS 就这样做——RSA 只送钥匙，不加密网页内容。

## 四、信息摘要

**原话｜** 所谓信息摘要，就是一段数据的特征信息，当数据发生了改变，信息摘要也会发生改变。发送方将数据和信息摘要一起传给接收方，接收方根据收到的数据重新生成摘要，两者相同则说明数据正确。**信息摘要是由哈希函数生成的**（哈希函数：把任意长输入压成定长输出）。

| 特点 | 原话 |
|---|---|
| 定长 | 不管数据多长，都产生固定长度的信息摘要 |
| 唯一 | 任何不同的输入数据，都会产生不同的信息摘要（教材口径；数学上碰撞不可避免） |
| 单向 | 只能由数据生成摘要，不能由摘要还原数据 |

| 算法 | 输出长度 |
|---|---|
| **MD5** | **128 位** |
| **SHA-1**（安全散列算法，安全性更高） | **160 位** |
| **SM3** | 256 位 |

**摘要不是加密**：原文照旧明文可读，摘要只回答"改没改"（目的是**防止报文被篡改**），不回答"看没看见"。口令哈希存库靠的就是单向性。

## 五、数字签名

摘要没有作者：报文和摘要一起被换掉，重算照样对得上。

**原话｜** 数字签名：唯一标识一个发送方。发送方发送数据时，使用**发送者的私钥进行加密**，接收者收到数据后，只能**使用发送者的公钥进行解密**，这样就能唯一确定发送方。但**无法保证机密性**。

示意图：A →签名（**sk_A**）→ S → 验证（**pk_A**）→ B。与加密图比变两处：钥匙主人 B → A，左右框公私对调；只换主人不换公私，仍是加密不是签名。

**流程（先摘要、后签名）**：
1. 发送方对报文求摘要（全文太长，签摘要即可）；
2. 用自己的私钥加密摘要得到签名，附在报文后发出；
3. 接收方用同一哈希算法对收到的报文重算摘要；
4. 用发送方公钥解开签名得原摘要，两份一致 → 报文完整且确系对方所发。

| 这一步 | 谁做 | 用哪把钥 | 为什么只能是它 |
|---|---|---|---|
| **加密**（保密） | 发送方 | **接收方的公钥** | 只有接收方有配对私钥，只有它解得开 |
| **解密** | 接收方 | **接收方自己的私钥** | 私钥没外传过 |
| **签名**（认证） | 发送方 | **发送方自己的私钥** | 只有发送方签得出，赖不掉 |
| **验签** | 接收方 | **发送方的公钥** | 公钥人人可取，人人可验 |

竖看：**保密路两把钥都属于接收方，认证路两把钥都属于发送方**；横看：**私钥永远由主人自己用，公钥永远由别人用**。

签名提供：**完整性、发送者身份认证、防止交易中的抵赖**；**不提供保密性**（正文仍是明文）。既要保密又要不可否认，就把加密和签名叠起来用（见第七节 PGP）。

**易混对② 加密 vs 签名**
- 判据｜目的是"只让对方读" → 用对方的钥（公钥加）；目的是"证明是我发的" → 用自己的钥（私钥签）。
- 例子｜小李给公司服务器发报销单要保密 → 用服务器的公钥加密、服务器的私钥解；要让服务器确认是小李发的 → 用小李的私钥签、服务器用小李的公钥验。

**易混对③ 数字证书 vs 数字签名**
- 判据｜确认对方身份（公钥属于谁）→ 数字证书；确保消息不可否认 → 数字签名。
- 例子｜A、B 通信前先互验身份 → 数字证书；A 事后不能否认发过某条消息 → 数字签名。

## 六、数字证书与 CA

若攻击者一开始就塞来自己的公钥，每步都验得过，报文却被他解开再加密转发——**中间人攻击**（插在双方之间实时双向转发，两头都以为在直连）。所以公钥要第三方担保。

**PKI（公钥基础设施）** 原话｜以不对称密钥加密技术为基础，以数据机密性、完整性、身份认证和行为不可抵赖性为安全目的，来实施和提供安全服务的具有普适性的安全基础设施。

**数字证书**：原话｜一个数据结构，是一种由可信任的权威机构签署的信息集合。**公钥证书主要用于确保公钥及其与用户绑定关系的安全。** 任何用户只要知道签证机构的公钥，就能检查证书签名的合法性；检查正确，就可以相信证书携带的公钥是真实的。比方：驾照本身不难伪造，难的是伪造车管所的钢印。
**X.509 证书 8 项**：版本号、序列号、签名算法标识符、认证机构、有效期限、主题信息、**认证机构的数字签名**、**公钥信息**（末两项是要害）。

**签证机构 CA**：负责签发证书、管理和撤销证书。原话｜CA 在给用户签发证书时要加上自己的数字签名，以保证证书信息的真实性。任何机构可以用 CA 的公钥来验证该证书的合法性。

证书＝CA 对"某公钥属于某主体"这条绑定做的一次数字签名，遵守第五节的表：**CA 用自己的私钥签发，任何人用 CA 的公钥验证 CA 的签名**。网站自己的公钥是**待验证对象**，不能用它验证书。两个不同 CA 的用户证书要互认：**两个 CA 互换公钥**（绝不能互换私钥）。

## 七、安全协议按 OSI 层次定位

**原话｜** 物理层主要使用物理手段，隔离、屏蔽物理设备等，其它层都是靠协议来保证传输的安全。

| 层 | 安全协议 / 设施 |
|---|---|
| 应用层 / 表示层 / 会话层 | PGP、HTTPS |
| 传输层 | TLS、SET |
| 网络层 | 防火墙、IPSec |
| 数据链路层 | 链路加密、PPTP、L2TP |
| 物理层 | 隔离、屏蔽 |

**SSL** 在原图上从应用层一直画到传输层，所以"在传输层"和"在应用层与传输层之间"两种说法都成立。

| 协议 | 关键词 |
|---|---|
| **SSL** | 安全套接字协议，加强 Web 安全传输（HTTP/HTTPS）；与 HTTP 结合成 **HTTPS，端口 443**；TLS 是 SSL 标准化后的后继版本。HTTPS 基于的是 SSL 协议，不是 RSA、DES 这类算法 |
| **IPSec** | 网络层，**为 IP 数据报文本身加密**（SSL/TLS 保一条应用连接，IPSec 保每个 IP 包） |
| **SSH** | 安全外壳协议，**加强 Telnet/FTP 安全**（Telnet 明文）；**端口 22** |
| **SET** | 安全电子交易协议，**B2C 电子商务中保障支付信息安全**，保证机密性、真实性、完整性和不可否认性，是 PKI 框架下的典型实现 |
| **Kerberos** | **网络身份认证协议**，基于**信任第三方**，在开放型网络中进行身份认证，认证实体可以是用户或用户服务；不依赖宿主机操作系统或 IP 地址，假定数据包可被随机窃取和篡改；**报文加时间戳防重放** |
| **PGP** | **RSA 公钥证书**做身份认证、**IDEA（128 位）**做数据加密、**MD5** 做完整性验证 |
| **S/MIME** | MIME（多用途互联网邮件扩展）的安全扩展，提供**安全电子邮件**；MIME 本身不是安全协议 |

第三方认证的两种体制：**Kerberos**（密钥分发中心 KDC）与 **PKI**（CA）——KDC 属 Kerberos，CA 属 PKI。

**PGP 流程**：发送方 A 有三把钥（A 的私钥、B 的公钥、一次性对称密钥），接收方 B 有两把（B 的私钥、A 的公钥）。发送：邮件 X 散列得摘要 H → H 用 **A 的私钥**签名（图上标作"报文鉴别码 MAC"）→ MAC 与 X 合并用**一次性密钥**加密 → 一次性密钥用 **B 的公钥**加密（数字信封）→ 发出。接收倒着走，最后两个 H 比较。A 私签、B 公封、B 私拆、A 公验，正好走遍第五节方向表四行。

## 八、边界防护：防火墙、IDS/IPS、DMZ

**防火墙**：原话｜在内部网络和外部因特网之间增加的一道安全防护措施，分为网络级防火墙和应用级防火墙。

| 类型 | 层次 | 手段 | 得失 |
|---|---|---|---|
| **网络级**（包过滤、状态监测） | 低 | 只检验网络包外在属性（起始地址、状态），异常则过滤 | **效率高**，对应用和用户透明；遇到**伪装的危险数据包**过滤不了 |
| **应用级**（应用级网关） | 高 | 把网络包拆开，检查里面的数据 | **安全强度高**；耗时，**效率低**；内外主机不直接连接，由它代转 |

"状态监测"是原件用词，通行写法"状态检测"：动态跟踪一条连接的状态，不只看孤立的包。
防火墙功能：控制进出的数据包与流向、日志审计、隐藏内部 IP 与网络结构；**不包括漏洞扫描**；防不了不经过它的攻击和藏在合法流量里的应用层攻击。

| 设施 | 要点 |
|---|---|
| **IDS 入侵检测** | 防火墙分隔外网威胁，**对来自内网的直接攻击无能为力**；IDS 是防火墙之后的**第二道屏障**。原理：监控系统/用户行为，分析引擎配知识库匹配，是入侵就记录证据并上报。原话｜IDS 是一个监听设备，没有跨接在任何链路上，无须网络流量流经它便可以工作。部署：挂接在所有所关注流量都必须流经的链路上，位置尽可能靠近攻击源或尽可能靠近受保护资源 |
| **IPS 入侵防御** | IDS 和防火墙都是入侵发生后检测分析；IPS 能提前发现，在入侵进入安全网络之前防御——挂在安全网络之前的链路上，实时检测并**直接阻断** |
| **杀毒软件** | 检测和解决计算机病毒（防火墙处理的是网络上的非法攻击） |
| **蜜罐** | 伪造蜜罐网络引诱黑客攻击，被攻击不影响安全网络，借此了解攻击手段和原理，升级优化安全系统 |
| **DMZ**（隔离区/非军事区） | 内外网之间的缓冲地带，**对外提供服务的服务器放这里**（Web、Mail、FTP）；受保护程度 **内网 > DMZ > 外网**。放 DMZ 后攻击者与内网之间还隔一道关卡 |

**易混对④ IDS vs IPS**
- 判据｜旁路监听、只报警 → IDS；串联在链路上、能阻断 → IPS。
- 例子｜接在交换机镜像口上旁听并告警 → IDS；串在出口链路上发现攻击直接丢包 → IPS。

**易混对⑤ 网络级 vs 应用级防火墙**
- 判据｜只看地址、状态等包外属性 → 网络级（包过滤）；拆包检查应用层数据流内容 → 应用级网关。
- 例子｜按源 IP 拦截某网段 → 包过滤；检查 HTTP 请求内容里有没有恶意数据 → 应用级网关。

## 九、攻击手法与病毒

**分类判据**：被动攻击**只看不动**（难被发现，靠加密防）；主动攻击**动了数据或服务**。

| 类型 | 攻击 | 描述 |
|---|---|---|
| **被动** | 窃听（网络监听） | 用各种合法或非法手段窃取系统中的信息资源和敏感信息 |
| | 业务流分析 | 长期监听，统计分析通信频度、信息流向、通信总量的变化，发现有价值的信息和规律 |
| | 非法登录 | 有些资料归为被动攻击 |
| **主动** | 假冒身份 | 非法用户冒充合法用户，或特权小的冒充特权大的；黑客大多采用假冒 |
| | 抵赖 | 来自用户的攻击，如否认自己发布过的消息、伪造对方来信 |
| | 旁路控制 | 利用系统安全缺陷或脆弱之处获得非授权的权利或特权 |
| | **重放攻击** | 所截获的某次合法通信数据拷贝，出于非法目的而被重新发送 |
| | 拒绝服务（DoS） | 对信息或其它资源的合法访问被无条件地阻止 |

| 较新的攻击 | 特征 |
|---|---|
| **DDoS** | 分布式拒绝服务，操纵大量傀儡主机同时发请求耗尽目标资源；**目标是让服务不可用，不偷数据**（不会造成密码泄漏） |
| **SQL 注入** | 把 SQL 片段拼进输入框或参数（如 `' or '1'='1`），骗服务器执行非授权数据库操作；**首要目标是获得数据库权限** |
| **跨站脚本 XSS** | 把恶意脚本注入网页，在**其他浏览者**的浏览器里执行 |
| **拖库 / 撞库** | 拖库：把某站数据库整个搬走；撞库：拿别处泄露的账号密码批量试本站 |
| **供应链投毒** | 在开发工具、第三方依赖包等上游植入恶意代码，随正常软件分发到下游 |
| **钓鱼** | 伪造以假乱真的网站或邮件，诱骗用户**主动**交出账号密码 |

**易混对⑥ 重放 vs 中间人**
- 判据｜事后把截获的报文原样重发 → 重放（不必看懂内容、不必在场）；实时插在中间双向转发 → 中间人。
- 例子｜截下一段合法登录报文，隔一小时原样再发 → 重放；伪造对方公钥、在线转发双方报文 → 中间人。防重放：让报文只能用一次——**时间戳**、随机数或序号（Kerberos 用时间戳）。

**易混对⑦ 钓鱼 vs XSS**
- 判据｜用户访问的站点是假的 → 钓鱼；站点是真的、被注入了脚本 → XSS。
- 例子｜仿冒银行域名的登录页 → 钓鱼；真论坛帖子里嵌脚本、偷看帖人的会话 → XSS。

**病毒**：原话｜编制或者在计算机程序中插入的**破坏计算机功能或者破坏数据，影响计算机使用并且能够自我复制**的一组计算机指令或者程序代码。特征：**隐蔽性、传染性、潜伏性、触发性、破坏性**（没有"自毁性"）。
**木马**：一种**后门程序**（后门＝绕开正常认证、留给攻击者的秘密通道），常被用作控制远程计算机的工具，隐藏在被控电脑上监控一切操作并盗取信息。

| 类型 | 判据 | 代表 |
|---|---|---|
| **蠕虫**（感染 EXE 文件） | 自主顺网络爬 | 熊猫烧香、罗密欧与朱丽叶、恶鹰、尼姆达、冲击波、欢乐时光、爱虫 |
| **木马** | 伪装潜伏，等人远程控制，不自主传播 | QQ 消息尾巴木马、特洛伊木马、X 卧底、冰河 |
| **宏病毒** | 寄生在 Office 文档的宏（文档里能自动跑的脚本）里，感染 Word、Excel 等 | 美丽沙（Melissa）、台湾 1 号 |
| **CIH** | 史上唯一破坏硬件的病毒 | — |
| **红色代码** | 蠕虫 + 木马（仍算蠕虫） | — |

**病毒命名**：前缀·名称·后缀。**前缀＝类型**：`Macro.` 宏病毒、`Worm.` 蠕虫、`Trojan.` 木马、`Backdoor.` 后门；中段是家族名，后段是变种号。如 `Macro.Melissa` → 宏病毒，感染 Word 或 Excel 文件。

**按感染途径四分类**：**文件型**（感染 EXE、COM 可执行文件）、**引导型**（影响软盘或硬盘的引导扇区）、**宏病毒**（感染文档、数据库、电子表格）、**目录型**（修改硬盘上所有文件的地址）。

## 速记

- **算法三筐**：对称＝DES(56位钥/64位块)、3DES(两把56位)、AES、RC-4/RC-5、IDEA(128位钥/64位块)、SM4｜非对称＝RSA(512/1024)、ECC、Elgamal、背包、Rabin、D-H、DSA、SM2｜摘要＝MD5(128)、SHA-1(160)、SM3(256)；能签名的只在非对称筐
- **方向表**：保密走收方两把钥（收方公钥加、私钥解）；认证走发方两把钥（发方私钥签、公钥验）；证书用 CA 公钥验 CA 签名，两 CA 互认靠互换公钥；对称密钥数 n(n−1)/2
- **数字信封**＝对称加数据、非对称加对称密钥；**摘要只保完整**（单向、定长）；**签名保完整+认证+不可否认、不保密**；身份认证靠证书，不可否认靠签名
- **X.509 八项**，要害是认证机构的数字签名和公钥信息；第三方认证两体制：Kerberos(KDC、时间戳) 与 PKI(CA)
- **协议站位**：物理层隔离屏蔽｜链路层链路加密/PPTP/L2TP｜网络层防火墙/IPSec｜传输层 TLS/SET｜应用层 PGP/HTTPS；SSL 跨应用层到传输层；HTTPS=HTTP+SSL=443，SSH=22，安全邮件 S/MIME 与 PGP
- **边界**：网络级防火墙低层高效（包过滤/状态检测），应用级高层低效（拆包）；IDS 旁路只报警、IPS 串联能阻断；内网 > DMZ > 外网，对外服务器进 DMZ
- **攻击**：被动只看（窃听、业务流分析）；主动动手（假冒、抵赖、旁路控制、重放、拒绝服务）；重放防御＝时间戳/随机数/序号；DDoS 不偷数据，SQL 注入夺数据库权限
- **病毒**：蠕虫自己爬（熊猫烧香、红色代码、爱虫…），木马潜伏偷（冰河、X 卧底、QQ 尾巴），宏病毒住文档（美丽沙、台湾 1 号），CIH 毁硬件；五特征无"自毁性"；命名＝前缀(类型)·名称·后缀
