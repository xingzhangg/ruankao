## 结论

部分能一遍读懂。开讲的「两个模块改到打架」困境立得住，SOLID 五条各有正反例，第二节是全篇最稳的一节。

一个 🔴：**「接口」一个词在本篇有三个意思，正文一处没拦。**

## 🔴 接口三义（已修）

三处同名不同物：① 封装语境下「对象对外暴露的那组操作」；② 面向对象方法论里的**接口类**（边界类，MVC 的 V 那层）；③ 只声明不实现、留给别人去实现的那种接口。②③ 尤其危险——读者是程序员，看到「接口类」会条件反射读成 Java 的 `interface`，而 2018 下那道二维码题考的正是 ② 的含义。更险的是速记里 ② 和 ③ 隔着一行并排放，读者复习时两句连着看，必然串。

改法：三处各自加围栏。① 处改称「只读**出口**」避免和后两个抢词；② 处加 ⚠️「和 Java 的 `interface` 关键字、和只声明不实现的那种接口，都不是一回事……心里念「**边界类**」不容易错」；③ 处点明「这是「接口」的**第三种**含义」；速记两行重新起头，②那行以「边界类」打头。

## 其余已改

- **三大特性（封装、继承、多态）在开讲里没有点名**，读者读完开讲不知道这一课的主线是哪三样 → 开讲收口处补齐。
- **SOLID 五条只有中文名**，而卷面和面试都用 SRP/OCP/LSP/ISP/DIP → 五条各自补英文缩写。
- **里氏替换的方向性缺失**：原文只说「子类能顶父类的位置」，没说反过来不成立 → 补「父类的实例顶不了子类的位置（是鸟不一定是鹦鹉）」。
- **依赖倒置、单一责任、共同封闭三条只有定义没有判据**，读者做题时无从下手 → 各补一句可执行的判据：依赖倒置看「抽象有没有反过来依赖细节」；单一责任数「有几种人会来提改动需求」；共同封闭补正反例（它的定义句字面读着像反话）。
- **单一责任 vs 接口分离分不开** → 补边界：单一责任拆的是**类**、按「谁会来要求改它」拆；接口分离拆的是**接口**、按「谁在用它」拆。

开讲的困境→五条原则一一对应的链条闭合完整；第二节的正反例配对是全篇性价比最高的一段。
