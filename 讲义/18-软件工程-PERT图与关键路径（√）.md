## 开讲：报销系统排期，老板问"什么时候能上线"

拿一个内部报销系统当例子。可行性过了、需求谈完了，老板问一句"什么时候能上线"。这一课的全部名词，都是在把这个问题算出来。

### 一、"排期"要做哪几件事：进度管理的六个过程

要回答"什么时候上线"，你得先知道：要干哪些活、谁必须等谁、每件活要几个人、每件活要几天。把这四件事做完才能排出表，排完还得盯着别走样。这正好就是**进度管理**的六个过程。

进度管理的定义是：用科学的方法确定进度目标、编制进度计划和资源供应计划、进行进度控制，在与质量、成本目标协调的基础上**实现工期目标**。

| 过程 | 回答什么 | 报销系统里是什么 |
|---|---|---|
| ① 活动定义 | 为做出各项**可交付成果**（＝要交出去的东西，需求文档、能跑的系统都算）要开展哪些**活动**（活动＝要占用时间和资源的一件具体工作） | 需求调研、建库、写提单模块…… |
| ② 活动排序 | 各活动之间的先后关系和逻辑关系，谁必须等谁 | 数据库没建好就写不了提单模块 |
| ③ 活动资源估算 | 各活动所需的资源类型和数量 | 提单模块要 2 个后端 1 个前端 |
| ④ 活动历时估算 | 各活动所需的具体时间 | 提单模块 5 天 |
| ⑤ 进度计划编制 | 综合顺序、历时、资源和制约因素，出计划 | 画出下面的甘特图/网络图 |
| ⑥ 进度控制 | 干起来发现偏了怎么办：分析原因或调整 | 原型拖了 4 天，还能不能按时上线 |

其中过程③的**活动资源估算方法**是纯记忆的送分点，五个：

- **专家判断法**：项目管理专家凭以往类似项目的经验预测
- **替换方案的确定**：某项活动有替代做法或资源有替代支持时要明确声明
- **公开的估算数据**：有些公司定期公开生产率、人工费率、各地劳动力与设备信息
- **估算软件**：用软件定义资源可用性、费率和资源日历
- **自下而上的估算**：把复杂活动拆成更小的工作，逐个估完再汇总

过程④历时怎么估（代码行、COCOMO 那一套）属于成本估算，不在本课；本课和考试一样，**默认每个活动要几天已经给你了**。真正要算的是把①②④拼起来之后的事。

> 考试这样问：六个过程哪个在前哪个在后；下列不属于活动资源估算方法的是（ ）。

### 二、把它画出来：甘特图和 PERT 图

报销系统拆成 8 个活动。表里的"**紧前活动**"就是必须先干完、本活动才能开工的那些活动；反过来，必须等本活动干完才能开工的，叫**紧后活动**。

| 活动 | 干什么 | 紧前活动 | 历时（天） |
|---|---|---|---|
| A | 需求调研 | — | 3 |
| B | 数据库设计 | A | 4 |
| C | 页面原型 | A | 2 |
| D | 提单模块 | B、C | 5 |
| E | 审批模块 | B | 6 |
| F | 报表模块 | B | 3 |
| G | 集成测试 | D、E、F | 4 |
| H | 上线培训 | G | 2 |

**画法一：甘特图（Gantt 图）。** 横轴是时间，一个活动一根横条，条的左端是开工日、右端是完工日。条涂黑一半表示做了一半，还能标"今天"这条竖线看实际进度。

```
      1234567890123456789   ← 第几天
   A  ███
   B     ████
   C     ██
   D         █████
   E         ██████
   F         ███
   G               ████
   H                   ██
```

这张图一眼看得出每个活动什么时候开始结束、要几天、**哪些活动在同一段时间里并排干（并行关系）**、做到什么程度了。但它有一处致命盲区：D 为什么排在第 8 天开工？图上没有任何东西告诉你 D 在等 B 和 C。**甘特图不能清晰地反映各活动之间的依赖关系**——这句话本身就是考点。

**画法二：PERT 图（Program Evaluation & Review Technique，项目计划评审技术），一张有向网络图。** 它专门画依赖：谁指向谁，谁就必须等谁。有两种画法，考试都会遇到：

- **AON（活动在节点，又叫前驱图、单代号网络图）**：一个圆圈就是一个活动，圈里写活动名和历时；箭线只表示"必须先做完"，本身不占时间。
- **AOA（活动在箭线，又叫双代号网络图）**：一根箭线是一个活动，线上标活动名和历时；圆圈是**事件**（也叫节点），表示"指向它的活动全部完成、从它出发的活动可以开始"的那个**瞬间**，不消耗任何时间。

**两种题面都考过**：有的题直接给活动表（紧前活动 + 历时），有的题给一张画好的网络图。识别方法：题干说"活动 **d-i** 延期了 2 周""活动 **a-c** 实际工期 6 周"——用两个节点名拼起来命名活动的，那张图一定是 AOA。

报销系统的 AON 长这样（箭头一律自左向右，C 那条竖线是汇入 D）：

```
                     ┌── E(6) ──┐
    A(3) ── B(4) ────┼── F(3) ──┼── G(4) ── H(2)
      │              └── D(5) ──┘
      │                   │
      └──── C(2) ─────────┘
```

换成 AOA 就多出一个东西：**虚活动**——用虚线画的箭线，**历时为 0、不消耗资源，只用来表示一条依赖约束**。这里非用它不可，因为 D 要等 B 和 C 两个，而 E、F 只等 B（为什么不加虚活动就画不出来，见本节末的推演，跳过不影响后面）。

| 箭线（活动） | 从 | 到 | 历时 |
|---|---|---|---|
| A 需求调研 | ① | ② | 3 |
| B 数据库设计 | ② | ③ | 4 |
| C 页面原型 | ② | ④ | 2 |
| **虚活动 1** | ③ | ④ | **0** |
| E 审批模块 | ③ | ⑥ | 6 |
| F 报表模块 | ③ | ⑤ | 3 |
| **虚活动 2** | ⑤ | ⑥ | **0** |
| D 提单模块 | ④ | ⑥ | 5 |
| G 集成测试 | ⑥ | ⑦ | 4 |
| H 上线培训 | ⑦ | ⑧ | 2 |

画成图是这样（虚线是虚活动）：

```
        A(3)      B(4)           E(6)
   ①───────→②───────→③─────────────────→⑥───→⑦───→⑧
              │         │  F(3)      ┊虚2       G(4)  H(2)
              │         └──────→⑤┈┈┈┘
              │  C(2)   ┊虚1
              └──────→④←┈┈┈┘
                       │  D(5)
                       └──────────────→⑥
```

节点④要等 C 到达、也要等虚活动 1 从③过来（即 B 完成），D 从④出发，就同时等到了 B 和 C，而 E、F 仍从③出发只等 B。这是虚活动的第一个用途。

虚活动 2 演示第二个用途：E 和 F 都从③出发、都汇入⑥，若两条都画成 ③→⑥，AOA 里活动是用节点对命名的，两个活动就重名了；插一个节点⑤和一条虚箭线把它们岔开，写成 3-6 和 3-5 就区分得开。

**拿到一张 AOA 图，两步就能换回活动表**，后面四节的算法照用：

1. **一根箭线抄成一行**：箭线上标的名字和历时，就是活动名和历时。
2. **紧前活动这么找**：某活动从节点 X 出发，那么**所有终点落在 X 上的箭线（虚线也算）**就是它的紧前活动。比如 D 从④出发，终点落在④上的是 C 和虚活动 1，虚活动 1 又来自 B，所以 D 的紧前是 B 和 C。

**事件（节点）本身也有两个时间**，题目会直接问"节点⑥最早在第几天发生"：

- **节点的最早发生时间 = 指向它的各条箭线 EF 的最大值**（全部到齐它才发生）
- **节点的最迟发生时间 = 从它出发的各条箭线 LS 的最小值**（最急的那个等不起）

拿节点⑥试：指向它的是 E（EF=13）、D（EF=12）、虚活动 2（F 的 EF=10 加 0），取最大得 **13**；从它出发的只有 G（LS=13），所以最迟也是 **13**。两个数相等，说明⑥在关键路径上——这和"活动的总时差为 0"是同一回事。（EF、LS 这几个时间怎么算，第四节讲。）

**虚活动要不要参与计算？** 换回活动表时它就还原成一条依赖关系、不再出现。但**题目若直接给 AOA 图问某条虚箭线**，它照样有自己的四个时间，只是历时为 0 所以最早开始等于最早完成；它的总时差为 0 时，它也算在关键路径上。

反过来，PERT 图的盲区是**不能清晰地表达并行关系**——图上没有时间轴，你看不出 E、F、D 恰好在第 8 到第 13 天挤在一起。两张图的长短处正好互补，这是本课最稳的送分点。

> 考试这样问：Gantt 图不能清晰地反映（ ）、PERT 图不能清晰地表达（ ）；双代号网络图中虚活动的作用是（ ）。

#### 推演 · 不加虚活动为什么画不出来

B 后面挂着 D、E、F 三个活动，但 D 还要额外等 C。若让 D、E、F 都从 B 的终点节点出发，E 和 F 就被迫也要等 C，凭空多出依赖；若让 B 直接指到 C 的终点节点，E 和 F 就没地方出发了。

AOA 的规矩是一个活动只能从一个节点出发、到一个节点结束，遇到这种"部分共享前置"就表达不出来，只能另加一条历时为 0 的虚箭线，把"等 B"这一条约束单独送到④去。

### 三、这个项目最快多久做完：关键路径怎么长出来

**先别算，凭感觉说一个数：报销系统最快几天上线？**

两种直觉都会错。把 8 个活动全加起来 3+4+2+5+6+3+4+2 = 29 天，虚高了，因为 D、E、F 能同时干；取最长的那个活动 E 的 6 天，荒唐，A 没做完谁也开不了工。

正确的想法从"结束"往回倒：H 干完项目才算完，H 要等 G，G 要等 D、E、F 全干完，它们又各自等前面的……于是从起点到终点，每一条"串起来的活动链"都必须整条走完，项目才结束。所以工期就是**所有链条里最长的那一条**。

**怎么保证一条不漏**：从每个**没有紧前活动**的活动出发（起点可能不止一个），每遇到一个分叉点就分支，一直走到没有紧后活动为止。本图分叉只有两处——A 之后分 B、C，B 之后分 D、E、F，2 和 3 组合正好 4 条：

```
A→B→E→G→H = 3+4+6+4+2 = 19  ←最长
A→B→D→G→H = 3+4+5+4+2 = 18
A→B→F→G→H = 3+4+3+4+2 = 16
A→C→D→G→H = 3+2+5+4+2 = 16
```

**19 天**。最长的这条 A→B→E→G→H 就叫**关键路径**，它上面的活动叫**关键活动**。有一句常见的说法："关键路径是项目的最短工期，但却是从开始到结束时间最长的路径"——听起来自相矛盾，其实不矛盾：19 是所有链条都能走完的最早时刻，比 19 早哪怕一天，A→B→E→G→H 这串就干不完。**工期**指的就是这个从开工到全部完成的总时长。

关键路径一定下来，三条结论跟着就出来了：

1. **关键活动拖 x 天，工期就拖 x 天**（不额外加人加班去赶工的话）。这条链一点余地都没有。
2. **要压缩工期，只能压关键路径上的活动。** 压 C、压 F 一天都省不下来，纯属白花钱。
3. **压完之后关键路径可能换人。** 因为原来第二长的那条会顶上来。

第 3 条最容易想当然，**再猜一次**：把审批模块 E 从 6 天压到 5 天，工期变几天？答 18，对——而且这一压，A→B→E→G→H 和 A→B→D→G→H 就都是 18 天了，**关键路径变成两条**。那再压到 4 天呢？

工期**还是 18**：E 那条掉到 17，A→B→D→G→H 这条 18 天的路顶上来，成了唯一的关键路径，多压的那一天完全白压。所以"压出第二条关键路径"就是止损点，再往下压是白花钱。**关键路径可能不止一条，几条一样长就都算**，题目问"关键路径是"而只答一条，就丢分了。

> 考试这样问：项目工期为（ ）天；关键路径是（ ）。

### 四、每个活动的四个时间：正推一遍、倒推一遍

枚举法只回答了"什么时候上线"。老板还会问："报表模块 F 能不能晚点开工，先把人借给审批模块？晚几天？"这就要给每个活动算四个时间：

- **ES 最早开始时间**：这个活动最早能在第几天开工。
- **EF 最早完成时间**：最早能在第几天干完，**EF = ES + 历时**。
- **LF 最迟完成时间**（也叫最晚完成时间，两种叫法考卷上都出现）：为了不拖累总工期，最晚必须在第几天完成。
- **LS 最迟开始时间**：为了不拖累总工期，最晚必须在第几天开工，**LS = LF − 历时**。

**计时口径先说死**：这四个数都是"从项目启动算起过了多少天"，起点记 0。ES(A)=0 表示 A 一启动就能干，EF(A)=3 表示 A 在第 3 天末干完；ES=7 就读作"要等到第 7 天末才轮到它"，落到上面那张甘特图，就是它的第一格画在第 8 天那一列。

下文一律用这套数字说话（"ES 是 7"），不再说"第几天开工"，免得和甘特图的天数差一格。考试给的图表也是这个口径，只要首尾一致就不会错。

**第一遍，正推求 ES/EF，从起点往终点走。**

> **ES = 所有紧前活动 EF 的最大值**（没有紧前活动就取 0），**EF = ES + 历时**。

为什么取 max：G 要等 D、E、F 三个**全部**做完才能开始，只要有一个没完，G 就开不了工，所以三个里**最晚**的那个说了算。取 min 就成了"有一个做完就能开工"，那不是依赖关系的意思。

| 活动 | 紧前 | ES = max(紧前的 EF) | EF = ES + 历时 |
|---|---|---|---|
| A | — | 0 | 3 |
| B | A | 3 | 7 |
| C | A | 3 | 5 |
| D | B、C | max(7, 5) = **7** | 12 |
| E | B | 7 | 13 |
| F | B | 7 | 10 |
| G | D、E、F | max(12, 13, 10) = **13** | 17 |
| H | G | 17 | 19 |

末活动 H 的 EF = **19**，和枚举法的 19 对上了。**这是第一处验算**：正推出来的总工期必须等于最长路径长度，不等就是算错了。

**第二遍，倒推求 LF/LS，从终点往起点走。**

> **LF = 所有紧后活动 LS 的最小值**（没有紧后活动就取总工期，**末活动可能不止一个，都取总工期**），**LS = LF − 历时**。

这里默认题目没有给外部交付期限。若题干另给"合同要求 25 天内交付"，末活动的 LF 就取 25，全部活动的总时差一起加 6，判据要改成**总时差最小**的那条是关键路径。中级很少这么出，认得即可。

为什么取 min：B 后面挂着 D、E、F 三个，B 晚一点，这三个的开工都得跟着往后挪。算完发现 D 的 LS 是 8、E 的 LS 是 7、F 的 LS 是 10——B 必须迁就**最急**的那个 E，所以 LF(B)=7。取 max 就等于"只要不耽误其中一个就行"，另外两个照样被耽误。

**记法：正推等最慢的紧前（取 max），倒推迁就最急的紧后（取 min）。** 常见错法是把两个方向记反，算出来的 LS 会比 ES 还小。

| 活动 | 紧后 | LF = min(紧后的 LS) | LS = LF − 历时 |
|---|---|---|---|
| H | —（末） | 19 | 17 |
| G | H | 17 | 13 |
| F | G | 13 | 10 |
| E | G | 13 | 7 |
| D | G | 13 | 8 |
| C | D | 8 | 6 |
| B | D、E、F | min(8, 7, 10) = **7** | 3 |
| A | B、C | min(3, 6) = **3** | 0 |

**第二处验算**：倒推回到起点活动 A，LS(A) 必须是 0。不是 0，说明中间某一步取错了 max/min。

> 考试这样问：活动 C 最迟应在第几天开始（答 LS 这个数字本身，C 是 6；软考的表格与选项都按这个口径）、第几天完成。

### 五、时差：这个活动到底能拖几天

> **总时差（松弛时间、总浮动时间）= LS − ES = LF − EF**
> 含义：在**不延误项目完工时间、也不违反其他进度制约因素**的前提下，本活动可以从最早开始时间往后推迟多久。

先从 F 数出来，不套公式：报表模块 F 的 ES 是 7、LS 是 10，也就是它在 7、8、9、10 这四个时刻里挑哪个开工都行，项目照样 19 天完工——往后挪的余地是 **3** 天。换个数法：EF 是 10、LF 是 13，还是 3 天。两个式子必然相等，因为 LF−EF = (LS+历时)−(ES+历时) = LS−ES。

> **自由时差（自由浮动时间）= 所有紧后活动 ES 的最小值 − 本活动的 EF**
> 含义：在**不延误任何紧后活动的最早开始时间、也不违反进度制约因素**的前提下，本活动可以推迟多久。（没有紧后活动的，用总工期减）

把两个时差和四个时间摊在一张表上：

| 活动 | 历时 | ES | EF | LS | LF | **总时差** | **自由时差** |
|---|---|---|---|---|---|---|---|
| A 需求调研 | 3 | 0 | 3 | 0 | 3 | **0** | 0 |
| B 数据库设计 | 4 | 3 | 7 | 3 | 7 | **0** | 0 |
| C 页面原型 | 2 | 3 | 5 | 6 | 8 | 3 | 2 |
| D 提单模块 | 5 | 7 | 12 | 8 | 13 | 1 | 1 |
| E 审批模块 | 6 | 7 | 13 | 7 | 13 | **0** | 0 |
| F 报表模块 | 3 | 7 | 10 | 10 | 13 | 3 | 3 |
| G 集成测试 | 4 | 13 | 17 | 13 | 17 | **0** | 0 |
| H 上线培训 | 2 | 17 | 19 | 17 | 19 | **0** | 0 |

**关键路径这回是自己浮出来的**：总时差为 0 的活动是 A、B、E、G、H，正好是第三节枚举出来的那条 A→B→E→G→H，一个不多一个不少。所以"**关键活动的最早开始时间 = 最晚开始时间**"和"总时差为 0"是同一件事的两种说法（为什么两者必然等价，见本节末的推演，跳过不影响后面）。

由此还长出**第三个求总时差的式子**，选择题只问某一个活动时最快：

> **总时差 = 总工期 − 经过该活动的最长路径长度**

查 C：经过 C 的路径只有 A→C→D→G→H = 16，19 − 16 = **3** ✓。查 D：经过 D 的最长路径是 A→B→D→G→H = 18，19 − 18 = **1** ✓。三个式子必然一致，考场上用哪个都行，但题目问"最迟什么时候开工"时只能老老实实正推倒推。这一式还有一种省略写法，减数取哪一条最容易出错，见本节末的深入。

**总时差和自由时差差在哪，用 C 演示一遍**（这是全课最容易含糊的一处）。C 的总时差是 3，自由时差是 ES(D) − EF(C) = 7 − 5 = **2**：

- C 拖 1 天、2 天：EF(C) 变成 6 或 7，而 D 本来就要等 B 干完（EF(B)=7）才开得了工，**ES(D) 纹丝不动，仍是 7**，下游一点感觉都没有。这 2 天就是自由时差。
- C 再拖第 3 天：EF(C)=8，ES(D) 被从 7 顶到 8，**下游被动挪窝了**；但 D 自己还有 1 天总时差，这一天正好被它吃掉，EF(D)=13，G 照样 13 开工，工期仍是 19。
- C 再拖第 4 天：ES(D)=9、EF(D)=14，G 只能等到 14，**工期变成 20**。

所以：**自由时差是"拖到什么程度下游要被动挪窝"，总时差是"拖到什么程度整个项目要延期"。** 前者是对邻居负责，后者是对项目负责，要求更严的当然更小，**自由时差 ≤ 总时差恒成立**。

再看两个特例。F 的紧后只有 G，自由时差 = 13 − 10 = 3，和总时差相等——因为 G 是关键活动，一天也挪不得，"不动 G"和"不拖工期"就成了同一件事。关键活动两者都是 0：总时差已经是 0，而自由时差被夹在 0 和总时差之间，只能是 0。

> 考试这样问：活动 C 的总时差（松弛时间、总浮动时间）是（ ）天；活动 B 的自由时差是（ ）天。

#### 推演 · 总时差为 0 为什么就一定在关键路径上

不是巧合。关键路径是最长的链，它上面每一天都被顶满了，一点余地都没有，所以关键活动的总时差只能是 0；反过来一个活动若总时差为 0，说明经过它的最长链就是全图最长的链，它就在关键路径上。两个方向都成立，"总时差为 0"和"在关键路径上"才是同一件事。

#### 深入 · "关键路径 − 非关键路径时长"是省略说法

有的资料把第三个式子写成"关键路径 − 非关键路径时长"，那是省略说法：减数必须取**经过该活动的那几条路径里最长的一条**。像 D 同时落在 A→B→D→G→H 和 A→C→D→G→H 上，随手挑短的那条 16 就会把总时差算成 3，错。

### 六、干起来之后偏了：进度控制怎么算

**又是一处直觉陷阱**。假设报销系统实施中，页面原型 C 实际用了 6 天（原计划 2 天），审批模块 E 提前 1 天完成（6 天变 5 天）。**只有这两个数变了**：C 由 2 改 6、E 由 6 改 5。直觉：C 不在关键路径上，无所谓；E 是关键活动提前了 1 天，工期应该是 18 天。

把四条路径全部重算（**加粗的是改过的数**）：

```
A→C→D→G→H = 3+**6**+5+4+2 = 20  ←新的关键路径
A→B→E→G→H = 3+4+**5**+4+2 = 18
A→B→D→G→H = 3+ 4 +5+4+2 = 18   ←这条没改，凑巧也是 18
A→B→F→G→H = 3+ 4 +3+4+2 = 16
```

**工期 20 天**，比原计划还慢了 1 天，关键路径换成了 A→C→D→G→H。原因：C 的总时差只有 3 天，实际拖了 4 天，超出的那 1 天直接加到工期上；而 E 省下的那 1 天完全白省，因为它早已不是瓶颈。

所以这类题唯一可靠的做法是：**把受这几处变动影响的路径全部重算一遍，再取最大**——原来那条关键路径只是候选之一，它甚至可能已经不是最长的了。

> 考试这样问：某活动比计划延期 x 天、某活动提前 y 天，此时项目历时总时长是多少。

## 速记

- 进度管理六过程：活动定义 → 活动排序 → 资源估算 → 历时估算 → 计划编制 → 进度控制；资源估算五法：专家判断、替换方案、公开数据、估算软件、自下而上
- 关键路径 = 起点到终点最长的路 = 最短工期；选择题先枚举全部路径求和取最大，可能不止一条
- 正推等最慢（ES = max 紧前 EF，EF = ES + 历时），倒推迁就最急（LF = min 紧后 LS，LS = LF − 历时）
- 总时差 = LS − ES = LF − EF = 总工期 − 经过它的最长路径；自由时差 = min(紧后 ES) − 本活动 EF；自由时差 ≤ 总时差
- 总时差为 0 ⇔ 关键活动 ⇔ ES = LS；关键活动自由时差也为 0
- 压工期只压关键路径，压完可能换路；非关键活动只在总时差内可拖；多活动同时变要重算全部路径取最大
- Gantt 见并行与进度、不见依赖；PERT 见依赖与关键路径、不见并行；虚活动只在 AOA 里，虚线、历时 0
