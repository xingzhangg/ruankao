# 49 · 下午题 1：数据流图 DFD 实战

## 定位

下午题 1（DFD，15 分必答）：一段业务说明 + 两张挖了空的数据流图，把空填回去——是阅读理解，不是设计。第一节认图上的元素和规则，第二节是四问的解题步骤，第三节是第四问的三种形态，第四节是检查法与技术要点。

## 一、图上有什么

**四类元素**（靠编号前缀认，不靠形状）：

| 编号 | 元素 | 画法 | 是什么 |
|---|---|---|---|
| E1、E2… | 外部实体 | 方框 | 系统之外的人、部门、组织或另一个系统，数据的源或宿。判据：系统管不着它 |
| P1、P2… | 加工 | 圆或圆角矩形 | 把输入数据流变成输出数据流的动作 |
| D1、D2… | 数据存储 | 双横线或右开口矩形（扫描图上常是方框，和 E 一样，所以认编号） | 系统要记住的东西，一张表或一个文件 |
| 箭头 | 数据流 | 箭头 | 一组固定成分的数据在流动；一根箭头标 A/B/C 表示三条流共用一根线 |

**分层**：

| 层 | 内容 |
|---|---|
| 顶层图（上下文数据流图，图 1-1） | 只有一个加工代表整个系统，画系统与外部实体之间的数据流，一般不画数据存储 |
| 0 层图（图 1-2） | 系统拆成加工 P1～Pn；数据存储从这层开始出现；外部实体照样出现，为避免交叉同一实体可画多次 |

上一层叫父图，拆出来的下一层叫子图。

**八条原则**：
1. **数据守恒原则**：加工的输出必须能从输入得到。
2. **守恒加工原则**：同一加工的输入输出名字必须不同，即使成分相同。
3. 每个加工既有输入又有输出。
4. 外部实体之间无数据流。
5. 外部实体与数据存储之间无数据流。
6. 数据存储之间无数据流。
7. **父图与子图平衡**：子图的输入输出必须和父图对应加工的一致。
8. 数据流必须经过加工（4–6 条的总括）。

**加工的三种错误**：只进不出＝**黑洞**；只出不进＝**奇迹**；输入不足以产生输出＝**灰洞**。

**数据字典**：为每个数据流、文件、加工和数据项做说明。符号：`=` 被定义为，`+` 与，`[a|b]` 或，`{a}` 重复 0 到多次。例：客户信息 = 姓名 + 手机号。

**小说明**（加工内部逻辑）三种写法：结构化语言、判定表、判定树。

## 二、四问的解题步骤

题的结构固定：说明（若干条编号功能）→ 图 1-1 顶层图 → 图 1-2 0 层图 → 四问：①外部实体名称 ②数据存储名称 ③缺失数据流 ④结构化语言 / 数据字典 / 概念简答。

1. **先读问题**：数清要填几个 E、几个 D、几条流，第四问是哪种形态。"使用说明中的词语"是约束——答案必须用说明原词。
2. **再看图**：数 0 层图上的 P，把说明的每条功能和 P 对上号（一条功能可能拆成两个加工，如"订单管理"对应"抓取线索""发起订单"两个 P）。对上号后，说明的每句话都知道该去哪个加工附近找。
3. **找外部实体**（看顶层图）：看实体**流进系统**的箭头名，回说明搜"谁上传/发起/注册了什么"。
   - 入流名说的是实体提供什么，说明里能直接搜到；出流名泛，图上标签还可能和说明不一致，不当锚点。
   - 多个入流指向同一个角色时就是它（如"路线、合约、订单"都由同一个顾问操作 → 该实体就是这个顾问）。
   - 非人的来源也是外部实体：外部网站、另一个系统。
4. **找数据存储**（看 0 层图）：看每个 D 的进出——流进去的是它存的内容，流出来的是谁读它。
   - 命名：说明给了存储名就直接抄；只给内容没给名字的，用内容原词加"表"或"信息表"。
   - 说明区分了两个概念就是两张表（如"潜在房源"与确认后的"房源"）。
   - 只进不出、只出不进的 D，说明有箭头没画，直接是下一步的线索。
5. **补缺失数据流**：拿说明**逐句**去图上核对，每读到一句"谁把什么给了谁"，就找那根箭头；找不到就记一条。直接逐句核对比先想守恒、平衡更快，那些最后也要回到说明核对。
   - 方向：
     - "给 X 发送 Y" → 加工 → X。
     - "根据 X" → X → 加工；X 通常是数据存储（前文说过"在系统中存储"，读的是存下来的那份）。
     - 流进存储是写，流出存储是读；"更新 X 状态" → 加工 → 存储 X。
   - 格式：起点 / 终点 / 名称三列；名称优先复用图上已有的同类标签。
   - 标签用词和说明不一致但方向、端点对得上的箭头，算已有，不算缺。
6. **第四问**：按问的形态写，见第三节。

## 三、第四问的三种形态

| 形态 | 怎么写 |
|---|---|
| 结构化语言写加工逻辑 | 带缩进的伪代码，中文可以；不写散文、不画判定树。从说明那条功能抄结构 |
| 数据字典问数据流组成 | 回说明找"××信息包括……"那句，用 `=`、`+` 照抄，列全 |
| 概念简答 | 用定义和八条原则一两句答。如：为什么 X 不能作外部实体、哪条数据流多余、哪个加工是黑洞、父图与子图怎么平衡 |

**结构化语言的写法**：触发条件作外层循环（"有新订单时" → `while (有新订单)`），说明里的"若……否则……"原样变成嵌套 `if/else`，收尾动作逐句照抄。说明里属于该加工的子流程（如竞拍：推送 → 出价 → 最优者中标）也要写进去。极简示意：

```
while (有新订单) {
    if (订单类型 == A 类) 分配到竞拍;
    else if (符合合约路线) 分配给合约商;
    else 分配到竞拍;
    发送通知; 更新订单;
}
```

## 四、检查法与技术要点

**填完后的检查**：
- 扫三条禁连：实体连实体、实体连存储、存储连存储都不能有。
- 扫每个加工：补完后不能还是黑洞、奇迹、灰洞；0 层图上某加工完全没有入流（奇迹）或某存储只进不出，都说明还缺流。
- 父图与子图平衡：0 层图上某条实体—加工箭头方向看不清时，回顶层图查——顶层图上是实体流向系统，0 层图上就是实体 → 加工。

**技术要点**：
- 几分写几条，可以多写；每条都必须能指到说明里的一句原话，同一句话只补一条。
- 缺失流里常有"加工 → 外部实体"（如发送结果给某系统、给另一角色的反馈），0 层图上同样有实体。
- 同一句说明发给两个对象（"向客户和经纪人发送反馈"），图上只画了一条时，缺的是另一条。
- 读存储判定条件的加工（"根据学习进度判断……"）必须有对应存储 → 加工的读流。
- 部分题目本身有二义性，参考答案有出入时以能指到说明原句为准。

## 速记

- 顺序：先看问题 → 看图数 E、D、P 并与说明对号 → 逐句读说明
- 实体看入流回说明搜角色；存储看进出流，有名抄名、无名原词加"表"
- 数据流逐句核对；"发送给 X"＝加工 → X，"根据 X"＝X → 加工；进存储写、出存储读
- 几分写几条，多写要能指到原句
- 第四问：结构化语言写伪代码 / 数据字典抄"包括"那句 / 概念简答用八条原则
- 验算：三条禁连 + 无黑洞、奇迹、灰洞 + 父子图平衡
