# 53 · 下午题 6：Java + 设计模式实战

## 定位

下午试题六（Java 代码填空，15 分选做）：一段说明（直接点名用哪个设计模式）＋一张类图＋一段挖了五个空的 Java 代码。不用设计、不用算，本质是**在类图或代码里找到对应的那个格子，把名字抄进空里**。模式的意图与分类在讲义 28、29，类图读法在 25、51；48 把它排在答题顺序第 1 位、用时 10 分钟。第一节认题面与类图记号，第二节是必备 Java 语法，第三节是解题步骤，第四节按空位类型给判据，第五节是常见模式在代码里的骨架。

## 一、题面结构与类图记号

- **选做规则**：试题五、试题六是同一场景、同一模式，一道 C++、一道 Java，任选一道。原话｜若多涂或者未涂题号框，则对题号最小的一道试题进行评分。所以必须明确选定；机考怎么表示"选这道"官方未公开，事先在官网模拟平台确认（讲义 48 第五节）。
- **认题头不认题号**：常见是试题五 C++、试题六 Java，但有年份整个反过来。看题头"阅读下列说明和 **Java** 代码"。
- **分值**：没有小问，只一句"将应填入 (n) 处的字句写在答题纸的对应栏内"。五空各 3 分，按点给分，互相独立，卡住一个不影响其余。

| 类图记号 | 代码里是 |
|---|---|
| `子 ──▷ 父`（实线＋空心三角，三角贴父） | `class 子 extends 父` |
| `类 ⇢▷ 接口`（虚线＋空心三角，三角贴接口） | `class 类 implements 接口` |
| `A ──▶ B`（实线＋细箭头，箭头贴被使用方） | A 里有一个 B 类型的成员变量 |
| `整体 ◇── 部分`（空心菱形贴整体）＝聚合，整体没了部分还在；可叠成 `整体 ◇──▶ 部分` | 整体里持有部分的引用 |
| `A ── B` 光实线 | 关联 |
| 方法前 `+` | `public` |
| **类名或方法名印成斜体** | `abstract` |
| 方法没写返回类型 | `void` |

代码末尾常有一个只为跑 `main` 的测试类（如 `XxxTest`），不在类图上；除它之外，类图的框、线与代码里的类型、`implements/extends`、成员变量一一对应。

## 二、必备 Java 语法

1. **构造方法**：原话｜在创建一个对象的时候，至少要调用一个构造方法。构造方法的名称必须与类同名，一个类可以有多个构造方法。没有返回类型；没写时编译器给一个默认的。
2. **造对象**：`Dog d = new Dog("tom");`——`Dog d` 声明、`new Dog(...)` 实例化、括号参数交给构造方法初始化。
3. **调方法、访问变量**：都用点号，`d.setAge(2);`、`d.age`。
4. **访问修饰符**：原话｜private：在同一类内可见；public：对所有类可见；protected：对同一包内的类和所有子类可见。`protected` 成员子类里可直接用；父类中声明为 public 的方法在子类中也必须为 public，漏写 `public` 编译不过。
5. **abstract**：原话｜抽象类不能用来实例化对象；如果一个类包含抽象方法，那么该类一定要声明为抽象类；抽象方法是一种没有任何实现的方法，该方法的具体实现由子类提供；抽象方法的声明以分号结尾。写法 `public abstract void run();`，无花括号。
6. **继承**：原话｜继承可以使用 extends 和 implements 这两个关键字来实现继承。`extends` 只能跟一个类（类的继承是单一继承），`implements` 可跟多个接口、逗号分隔。**接口**是只写方法签名的清单，实现它的类必须把清单上的方法全部写出。
7. **泛型**：`List<Shape> list;` 尖括号里是"这张表只准装什么类型"，声明和 `new ArrayList<Shape>()` 两边类型须一致。
8. **遍历集合**：`for (Shape s : list) { s.draw(); }`，循环变量类型就是泛型里那个类型。
9. **this**：指代当前对象。参数名与成员变量同名时，光写名字指的是参数，成员变量必须写 `this.名字`；把自己交给别人时写 `this` 作实参。

## 三、解题步骤

1. **读说明，记模式名和角色名**。模式名题干必点，认出它就能预判代码骨架（见第五节）：比如看到"观察者"就知道会有观察者表、注册方法、遍历通知的循环。
2. **扫类图**：记下每个框、每个方法名、每条线；**斜体单独记一笔**（必然对应一个 `abstract` 空）。
3. **类图与代码对一遍**：框数＝代码类型数（除测试类），`⇢▷` 条数＝`implements` 句数，`──▷`＝`extends`，每根 `──▶` 找到对应成员变量或构造参数。
4. **从上往下扫代码，遇空先判类型**（第四节五类），再去类图或代码里已写死的地方抄名字。
5. **顺着 `main` 走一遍验算**：对象怎么造、谁先被塞进去、调用链最后打印什么，与说明里给的输出对得上，空就基本没错。
6. **时间**：读说明和类图 3 分钟、填空 5 分钟、走 `main` 验算 2 分钟。

总原则：**类图给线索，代码里已写死的那一行才是判据；两边打架以代码为准。**

## 四、五类空位与判据

| 空位长相 | 怎么填 | 依据 |
|---|---|---|
| ① 接口里 `public ( n );` | `返回类型 方法名(参数)`，不带花括号 | 类图该接口框里的方法；返回类型、参数从实现类同名方法反抄 |
| ② 抽象类里 `public ( n );` | `abstract 返回类型 方法名()` | 类图上印斜体的方法；子类里 `public void xxx(){…}` 给出返回类型 |
| ③ 类型名：`List<( n )>`、成员声明、参数表 | 多半填**接口名/抽象类名**，不填具体类 | 代码里已写死的 `new ArrayList<…>()`、调用处实参的声明类型 |
| ④ 方法体里孤零零一个 `( n );` | `对象.方法(...)` 一行调用，不写业务逻辑 | 该方法体里能用的对象（循环变量、成员变量、参数）＋该对象类型上还没用过的方法 |
| ⑤ 赋值、`main` 里的装配 | `this.x = x;`、`obj.setXxx(...)`、`obj.run()` | 同名要 `this.`；先装配再运行 |

逐类要点：

- **① 接口方法**：接口方法不能有方法体，写成 `void draw(){}` 错。接口里多个方法挖成两空时，两空互换也对——接口中方法顺序没有语法含义。
- **② 抽象方法**：漏 `abstract` 就成了没方法体的普通方法，编译不过。
- **③ 类型名**：设计模式的要害是**只依赖抽象那一层**，目标只认接口、不认具体是谁。判据看赋值和调用，不看类图上离得最近的框。例：

  ```java
  Shape s = new Circle();
  new Painter(s);        // Painter(( n ) sh) 里 ( n ) 只能填 Shape
  ```
  声明为 `Shape` 的变量传不进 `Circle` 类型的参数（父类型不能自动当子类型用），填 `Circle` 编译不过。
- **④ 一行调用**：循环变量类型的接口上只有一个方法时，只有一种写法（`for (Shape s : list) { s.draw(); }`）。方法多时用排除法：看这行在哪个方法里、那一刻在做什么（构造中、流程第几步），逐个排掉语义不符的；再用反证——如果不这样调用，`main` 走下来是否没有任何输出。只填方法名漏掉对象前缀（`setA(...)` 而不是 `product.setA(...)`）不算对，本类里没有这个方法。模板只给了 `( n );` 的，括号和参数由自己写；模板给了 `( n )("A")` 的，只填到方法名。
- **⑤ 赋值与装配**：

  ```java
  public void setBuilder(Builder builder) { this.builder = builder; }
  ```
  写成 `builder = builder;` 语法合法、编译照过，但只是参数自己赋自己，成员仍为 `null`，后面一调用就空指针。`main` 里 `w.setBuilder(b); w.construct();` 顺序反了同样空指针。这两种错误**编译发现不了**，只能靠走 `main` 查出。多个具体类可选时（塞哪个生成器），以说明里给的输出结果对上哪个子类填的内容为准。

书写要点：

- 只写标识符或一行语句，不写理由。
- **大小写照抄**：代码里若印的是 `Attach`、`Notify`（首字母大写，不合惯例也照抄），写成 `attach` 就是另一个方法。变量名照抄代码里已有的，不自己起名。
- 末尾分号、空格可有可无；模板没给分号的整行空，带上分号更稳。
- 后面跟着"代码省略"的空，填该对象上任一合理的构建方法都算对，按流程第一步写最自然。
- 代码里常有印刷毛病（全角分号、`Lists<`、`system.out`、`viod`、`∥` 代替 `//`、数字 1 印成字母 l、类收尾花括号缺失），几乎不落在空上，照常做。

## 五、常见模式在代码里的骨架

| 模式 | 代码里的识别特征 | 高频空位 |
|---|---|---|
| **观察者** | `interface Subject{attach/detach/notify}`、`interface Observer{update()}`；目标类里 `List<Observer>`；`notify()` 里 `for(Observer o : list) o.update();`；观察者构造方法里 `sub.attach(this)` 把自己注册上去 | 接口里 `void update()`、泛型填 `Observer`、`o.update()`、构造参数类型填 `Subject`、`attach(this)` |
| **生成器** | 抽象生成器（斜体）含 `createNew…()`、抽象 `buildParts()`、`getResult()`；具体生成器 `extends`/`implements` 它、各自填不同内容；指挥者持有生成器引用（`◇──▶`），`construct()` 依次调构建步骤 | 抽象方法声明、`this.builder = builder`、`builder.buildParts()`、`main` 里先 `set` 后 `construct` |
| 策略 | 上下文类持有 `Strategy` 接口引用，方法里 `strategy.算法()`；多个具体策略 `implements` 它 | 引用类型填接口、委托调用一行 |
| 组合 | 抽象构件被叶子和容器共同继承；容器里 `List<Component>`，`add/remove`，操作时遍历子节点逐个调用 | 泛型填抽象构件、遍历调用 |
| 装饰器 | 装饰类既继承/实现构件，又持有一个构件引用，方法里先调被包对象再加自己的行为 | `extends` 构件、`component.operation()` |
| 适配器 | 适配器 `implements` 目标接口，内部持有被适配者，目标方法里转调被适配者的方法 | `implements` 目标、转调语句 |
| 工厂方法 | 抽象创建者声明抽象工厂方法，具体创建者 `return new 具体产品()` | 抽象方法声明、`new` 语句 |

观察者：目标一变，所有登记过的观察者自动收到通知、各自刷新；目标只依赖 `Observer` 接口，新增一种观察者目标类不用改。生成器：把"按固定步骤造复杂对象"拆成两半——指挥者管顺序，生成器管每步内容；原话｜将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示。
