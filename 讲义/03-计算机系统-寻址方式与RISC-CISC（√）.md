## 开讲：指令里就那么十位数字，它到底代表什么

全课跟着**同一台小机器**走：机器字长 16 位，一条指令也是 16 位——前 **6 位是操作码**（告诉 CPU 干什么，比如"取数""相加"），后 **10 位是地址码**（告诉 CPU 对谁干）。主存**按字编址**（一个门牌号对应一个 16 位的字，不是一个字节），容量 **64K 字**，也就是 2¹⁶ = 65536 个单元，门牌号从 0 排到 65535。

这后 10 位数字，全课就盯着它一个问题：**它到底代表什么？** 每换一种回答，就是一种寻址方式。

### 一、先把一条指令拆开，看它是怎么被执行的

转录本 2-1 的原话：一条指令由**操作码和操作数**两部分组成，操作码**决定要完成的操作**，操作数指**参加运算的数据及其所在的单元地址**；在计算机中这两样都用二进制数码表示，分别叫**操作码**和**地址码**，整条指令以二进制编码的形式存放在存储器里。

执行一条指令固定三步：**取指令 → 分析指令 → 执行指令**。展开说：先把**程序计数器 PC**（CPU 里专门存"下一条指令在内存哪个门牌号"的那个小格子）里的地址送上**地址总线**（CPU 用来告诉内存"我要访问哪一格"的那组线），按这个地址从内存把指令内容取回来，存进**指令寄存器 IR**（存当前正在执行的这条指令本身）；再由**指令译码器 ID** 分析操作码，弄清这是加法还是取数；最后执行，取出指令执行所需的**源操作数**（就是这条指令要拿来算的那个数）。这几个部件的分工在 02 已经按"运算器 / 控制器"劈开讲过，这里只借它们把流程串起来。

流程走到这儿分出**两个完全不同的问题**，考试也分开考，别混：

- **指令寻址**——下一条**指令**从哪来。只有两种：**顺序寻址方式**是一条接一条顺序执行（PC 自动 +1）；**跳跃寻址方式**是下一条指令的地址**不由程序计数器给出，而由本条指令直接给出**，跳过去之后 PC 的内容也必须相应改掉，才能接着从新位置顺序往下跑。
- **操作数寻址**——这条指令要算的那个**数**从哪来。这才是本课主线，也就是那八种寻址方式。

### 二、最朴素的回答：这十位数字就是操作数本身

指令的地址码字段写着 `200`。最省事的解释是：它压根不是地址，**它就是那个数**，200。这叫**立即寻址方式**——转录本原话是"指令的地址码字段指出的不是地址，而是操作数本身"。C 语言里 `a = a + 200` 编译出来的那个 200，就是立即数。

好处很实在：取指令的时候操作数已经跟着一起回来了，**一次内存都不用再跑**。

但它只能到这儿为止，两条短板堵死了：

- **短板①**：这个 200 是刻在指令里的，程序跑起来**改不了**。变量做不了，只有常量能这么放。
- **短板②**：地址码就 10 位，能装下的数只有 0～1023（2¹⁰ = 1024 个），**大一点的数根本塞不进去**。

### 三、退一步：这十位数字是操作数的门牌号

既然装不下数，那就装地址——**直接寻址方式**：地址字段中**直接指出操作数在主存中的地址**。地址码 200 的意思变成"去 200 号单元把东西取出来"。设内存 `[200] = 5000`，那么操作数就是 5000。

①②两条短板一起补上了：5000 存在内存里，程序随时能改（变量成立）；内存单元有整整 16 位，多大的数都装得下。代价是要**跑一趟主存**，1 次访存。

但直接寻址又冒出四条新短板，后面每一种寻址方式都是在补其中一条：

- **短板③ 够不着**：地址码 10 位，只能指到 0～1023 这 1024 个单元，而主存有 65536 个单元——**只够得着 1/64**（65536 ÷ 1024 = 64），剩下 63/64 的内存这条指令看都看不见。
- **短板④ 算不出来**：`arr[i]` 这种访问，`i` 每轮循环都在变，真正要访问的地址**要到运行时才知道**；可指令一旦编译出来，地址码就是死的。难道每轮循环去改指令自己？那叫自修改代码，既危险，又让代码段没法设成只读、没法多个进程共享。
- **短板⑤ 慢**：每取一个操作数都要跑一趟主存，而主存比 CPU 慢得多。
- **短板⑥ 挪不得**：程序被操作系统装到内存哪个位置，编译的时候根本不知道。指令里写死 `jmp 800`，程序整体往后挪 100 个单元，所有绝对地址就全错位了。

### 四、补短板③：把地址搬到一个字长够用的地方去

地址码只有 10 位，那就**别让地址待在地址码里**。有两个搬法。

**搬到内存单元里 —— 间接寻址方式**。转录本原话："指令地址码字段所指向的存储单元中存储的是操作数的地址"。也就是地址码 200 指的那一格里，装的不是操作数，是操作数的**地址**。

```
第 1 趟：按地址码 200 去读 → 读回 5000。这个 5000 不是操作数，是地址
第 2 趟：按 5000 再去读   → 读回 88。这才是操作数
```

（设 `[200] = 5000`、`[5000] = 88`。）为什么这样就够得着全部内存了？因为**内存单元是 16 位**，装得下 0～65535 任何一个门牌号——短板③解除。代价是**要跑两趟主存**，是八种里最慢的一种。

这里有个最值得停一下的地方：`[200]` 那一格里躺着的就是 `5000` 这一串比特，**直接寻址把它当成"数"**（操作数就是 5000），**间接寻址把它当成"地址"**（拿它当门牌号再跑一趟，取回 88）。同一串比特，两种解释，得到两个完全不同的结果。判断标准只有一条：**读回来的东西还要不要再当地址用一次**。

**搬到寄存器里 —— 寄存器间接寻址方式**。**寄存器**是 CPU 内部速度最快、数量极少的小格子，其中不挑用途、装地址装数都行的那十几个叫**通用寄存器**；设通用寄存器 `R1 = 5000`，指令的地址码里写的是"R1"这个编号，意思是"真正的地址在 R1 里"。读 R1 拿到 5000，再按 5000 读一次内存拿到 88——**只跑 1 趟主存**（读寄存器在 CPU 内部完成，不算访存），而 R1 同样是满字长，同样够得着全部 64K。所以它是短板③更划算的解法。

> ⚠️ 转录本 2-2 只列了立即、直接、间接、寄存器、基址、变址六种，**漏了"寄存器间接"和"相对"**。这两种都是考点，相对寻址还正是常见考题里"拿程序计数器的内容加偏移量"那一问的答案，所以本课按《软件设计师教程》第 5 版补齐。

### 五、补短板⑤：干脆把操作数本身放进寄存器

**寄存器寻址方式**——转录本原话是"指令中的地址码是寄存器的编号"，操作数就在那个寄存器里，直接读出来用。**一趟主存都不用跑**。

顺带白捡一个好处：机器有 16 个通用寄存器，编号只要 **4 位**（2⁴ = 16）就够；而写一个内存地址要 10 位。同样一条指令，用寄存器号比用地址码**省 6 位**，指令还能做得更短。

**先别往下看，猜一下：立即寻址和寄存器寻址都不用跑主存，那这两个谁更快？** 再加上直接寻址，三个排个序。

2021 下半年真题第 1 题问的就是这个，答案是 **立即寻址最快、寄存器寻址次之、直接寻址最慢**。道理在于"访存次数"排的只是粗档，同为 0 次时还要再比一层：立即寻址的操作数是**跟着指令一起被取回来的**，取指结束它就已经在手上，一次额外动作都不用；寄存器寻址还要按编号**去寄存器读一次**；直接寻址则要老老实实跑一趟主存。所以速度榜是 **立即 > 寄存器 > 直接 > 间接**。

### 六、补短板④：让有效地址在运行的时候才算出来

先把两个词分清，后面全靠它们：**形式地址**是指令里明明白白写着的那个数（本例是 200），**有效地址 EA** 是 CPU 最终真正拿去访问内存的那个地址。前面几种里两者要么无关（立即）、要么相等（直接），从这一节起，EA 要**算**出来。

**变址寻址方式**：转录本原话——"将**变址寄存器**的内容加上指令中的形式地址而形成操作数的有效地址"。变址寄存器就是专门用来放"下标"的那个寄存器，通常记作 IX。

```
EA = 形式地址(数组首地址 200) + 变址寄存器 IX 的内容(下标 i)
```

拿 `arr[i]` 跑一遍：数组 `arr` 从 200 号单元开始放，循环 10 轮，IX 依次取 0、1、2、…、9：

```
i = 0 → EA = 200 + 0 = 200     i = 5 → EA = 200 + 5 = 205
i = 1 → EA = 200 + 1 = 201     ⋮
i = 3 → EA = 200 + 3 = 203     i = 9 → EA = 200 + 9 = 209
```

设 `[203] = 17`，那么 `i = 3` 这一轮取到的操作数就是 17。关键在于：这 10 轮跑的是**同一条指令、一个字都没改过**，改的只是 IX 这个寄存器。短板④解除——数组和循环从此不用自修改代码。取操作数仍然只要 1 次访存（读寄存器、做加法都在 CPU 内部）。

### 七、补短板⑥：让基准也在运行的时候才填

短板⑥有两种表现，各配一种寻址方式。

**程序整体被装到哪儿不确定 → 基址寻址方式**。转录本原话——"将**基址寄存器**的内容加上指令中的形式地址而形成操作数的有效地址，其优点是**可以扩大寻址能力**"。基址寄存器（记作 BR）里装的是**程序被装入内存的起点**，由操作系统在装入时填一次。

```
EA = 基址寄存器 BR 的内容(程序装入起点 4000) + 形式地址(段内偏移 200) = 4200
```

程序被挪到别处去，只要改 BR 这一个数，所有指令一字不动——这就是**重定位**（程序在内存里换个位置照样能跑）。"扩大寻址能力"也在这儿：BR 是满字长 16 位，指得到 64K 里任何一处，形式地址只负责段内那一小段偏移。

**变址和基址长得一模一样，都是"寄存器 + 形式地址"，怎么分？** 不能看加法，只能看**谁是基准、谁在变、给谁用**：变址是**用户程序在改下标**（`i++`，基准是数组首址，写在形式地址里），基址是**系统在挪程序**（装入时填一次，基准是程序起点，放在寄存器里）。两者的基准和偏移**正好互换了位置**，这也是最常见的设错点。

**转移指令要能跟着代码一起搬家 → 相对寻址方式**。基准换成 PC 本身：

```
EA = PC 的内容 + 形式地址（偏移量，可正可负）
```

跳转不再写"跳到 300 号单元"，而是写"往后跳 200"。整段代码搬到内存哪儿去，"往后跳 200"都还是对的。注意它和第一节的**跳跃寻址**不在同一层：跳跃寻址回答"下一条指令从哪来"，相对寻址回答"地址码怎么解释"；转移指令拿相对寻址算跳转目标，是跳跃寻址最常见的一种实现，但不是唯一一种。

算一遍：转移指令自己躺在 100 号单元，偏移量 +200。取指之后 PC 已经自动 +1 变成 101（一条指令占 1 个字），所以按"PC 当前内容"算，目标是 101 + 200 = **301**；若按"本条指令自己的地址"算则是 100 + 200 = **300**，两种口径**差 1**。软考题干一般直接写"有效地址 = PC 的内容 + 偏移量"，**按题干口径直接加即可**，不必自作主张补那个 1。偏移量取负就是往回跳：−60 → 101 − 60 = 41，循环就是这么实现的。

### 八、六条短板，七种回应：链条到这里闭合

八种解释全长出来了，回头对一遍账。这张表的每一行都在回答"它是被哪条短板逼出来的、代价是什么"：

| 短板 | 回应它的方式 | 地址码 200 的含义 | 有效地址怎么来 | 取操作数访存 | 本例得到 |
|---|---|---|---|---|---|
| —（起点） | **立即** | 操作数本身 | 不需要 | **0 次** | 200 |
| ①改不了 ②装不下大数 | **直接** | 操作数的地址 | EA = 200 | 1 次 | 5000 |
| ③地址码够不着 64K | **间接** | 地址的地址 | EA = [200] = 5000 | **2 次** | 88 |
| ③（更划算的解法） | **寄存器间接** | 寄存器编号，寄存器里是地址 | EA = R1 = 5000 | 1 次 | 88 |
| ⑤每次都跑主存太慢 | **寄存器** | 寄存器编号，寄存器里是数 | 不需要 | **0 次** | 5000 |
| ④地址要运行时才算 | **变址** | 形式地址（数组首址） | EA = 200 + IX | 1 次 | [203] = 17 |
| ⑥程序位置不固定 | **基址** | 形式地址（段内偏移） | EA = BR + 200 | 1 次 | [4200] |
| ⑥转移指令要能搬家 | **相对** | 偏移量（可正可负） | EA = PC + 200 | 跳转时不取数 | 目标 301 |

一条通用的自查：**访存次数 = 从地址码出发到摸到操作数为止，中间跨过几次内存**——表里那一列就是这么数出来的（相对寻址用在转移指令上时不取操作数，不参与这个排队）。注意这个次数**不含取指令本身那一次**——真要把取指令算进去，全部再加 1（间接就成 3 次），按题干口径答。

### 九、指令集该做厚还是做薄：CISC 与 RISC

链条走完，新问题跟着来了：既然有八种解释，**一台机器要不要把八种全支持？更进一步，整套指令集是该做厚还是做薄？** 这就是七十年代真真切切吵过的一场路线之争。

拿一件具体的活来看：算 `a = b × c + d`。

**做厚的一派叫 CISC（复杂指令系统计算机）**：既然乘加是常用组合，就专门造一条指令包办它。

```
MAC  a, b, c, d        ← 一条指令，硬件内部把乘、加、访存全干完
```

**做薄的一派叫 RISC（精简指令系统计算机）**：机器只提供最基础的动作，复杂功能靠**把简单指令组合起来**。

```
LOAD  R1, b            ← 把 b 从内存搬进寄存器 R1
LOAD  R2, c
MUL   R3, R1, R2       ← R3 = R1 × R2，全在寄存器里算，不碰内存
LOAD  R4, d
ADD   R5, R3, R4       ← R5 = R3 + R4
STORE a, R5            ← 把结果写回内存
```

6 条对 1 条。**做厚省了什么**：程序短——七十年代内存极贵，这一条能省很多钱；编译器好写——高级语言里一句 `a=b*c+d` 直接对上一条机器指令；老程序还能一直兼容跑下去，所以转录本说 CISC "兼容性强"。

**赔了什么**，四笔账：其一，指令包办的事有多有少，**长度就没法统一**（x86 的指令 1 到 15 个字节都有），CPU 不把这条译完就不知道下一条从哪个字节开始；其二，这么复杂的指令没法用简单电路直接实现，只能靠**微程序控制**——把一条复杂指令再翻译成一串更小的"微指令"，存在 CPU 里的一小块 ROM（只读存储器，出厂写死、只能读不能改）里逐条查表执行，多绕一层就慢一层；其三，指令**使用频率差别极大**，堆进去的复杂指令绝大多数编译器根本不生成；其四，硬件复杂，转录本记的"研制周期长"就是这个。

**先别往下看，猜一道题**：下面四条里，哪几条是 RISC 的特点？①指令数量少　②寻址方式多　③指令格式种类少　④指令长度固定。

多数人会把②也勾上——"精简的是指令条数，寻址方式总该多给几种方便点吧"。**恰恰反了**。想想第八节那张表：寻址方式一多，同一个操作码后面跟着的那几位就得按好几种规矩分别解释，译码电路必须分岔，指令也很难做成一样长。**寻址方式多正是 CISC 的特征**，是 RISC 头一个要砍掉的东西。答案是 ①③④。

于是 RISC 那一串特点全都能从"砍"字推出来，不用死记：指令**数量少**、**使用频率接近**（只留大家真在用的）、**定长格式**、**大部分为单周期指令**（**时钟周期**是 CPU 打一拍的时间，它计时的最小单位；一条指令一拍做完）、运算**只操作寄存器**、**只有 Load/Store 两类指令能访问内存**——既然只能在寄存器里算，就必须**增加大量通用寄存器**（在两边的特性对照表里，通用寄存器是 RISC 唯一"多"的一项，砍指令省下来的芯片面积正好拿去堆它）；格式统一、译码简单，控制器就不必再绕微程序那一层，可以用**硬布线逻辑控制**（也叫组合逻辑控制器，用一片组合逻辑电路直接产生控制信号，不查微码表），快得多；指令定长、每条耗时接近，**天生适合流水线**（把一条指令切成几段、让不同指令的不同段重叠着跑，怎么切、怎么算时间是 06 那一课的事）；代价是同一件事要用更多条指令，程序体积变大，还得靠**优化编译**把指令排好——所以转录本把"优化编译，有效支持高级语言"记在 RISC 名下。

### 十、体系结构分类：不在这条链上，认得即可

转录本还有一节按别的维度给计算机分类，和上面的链条接不上，考到就是给个描述让你选名字，认得即可。

**按处理机的数量**分三种：**单处理系统**（一个处理单元和其他设备集成）、**并行处理系统**（两个以上的处理机互联）、**分布式处理系统**（物理上远距离且松耦合的多计算机系统）。

**Flynn 分类法**按两个因素分：**指令流**和**数据流**。指令流由**控制部分**处理，一个控制部分处理一条指令流，所以多指令流就得有多个控制部分；数据流由**处理器**处理，一个处理器处理一条数据流，多数据流就得有多个处理器；而**主存模块只管存**，指令和数据对它都一样，所以只要有一样是"多"，主存模块就得是多个。四类的差别就是这三个数：

| 类型 | 控制部分 | 处理器 | 主存模块 | 关键特性与代表 |
|---|---|---|---|---|
| **SISD** 单指令流单数据流 | 一个 | 一个 | 一个 | 单处理器系统 |
| **SIMD** 单指令流多数据流 | 一个 | 多个 | 多个 | 各处理器以异步的形式执行同一条指令；并行处理机、阵列处理机、超级向量处理机 |
| **MISD** 多指令流单数据流 | 多个 | 一个 | 多个 | 被证明不可能，至少是不实际；目前没有，有文献称流水线计算机为此类 |
| **MIMD** 多指令流多数据流 | 多个 | 多个 | 多个 | 能实现作业、任务、指令等各级全面并行；多处理机系统、多计算机 |

**MISD 为什么不可能**，转录本给的理由很好记：计算机是**由指令来控制数据的传输**，一条指令可以控制一条或多条数据流，但**一条数据流不能被多条指令控制**，否则会出错——就像上级命令太多还互相冲突，不知道该执行哪个。

这一课两半其实是同一个动作的两个方向：前半是**加法**，地址码只有一种解释不够用，于是一条一条往上加解释，加到八种；后半是**减法**，解释加得越多译码越分岔、指令越难做齐，于是 CISC 继续加、RISC 砍回去。现实里两条路线早已互相借用（x86 对外是 CISC 指令集，内部却把复杂指令拆成一串类 RISC 的微操作再上流水线），但考试要的是两条路线各自的**原始主张**，不是混血产物。

## 考试怎么考

**考点① 寻址方式识别：只问一句"指令里装的是数还是地址"。** 题干给一句定义让你选名字，靠信号短语直接对，不需要推理。三对最容易互换的：

| 容易互换的一对 | 分界线 | 判法 |
|---|---|---|
| 立即 ↔ 直接 | 指令里装的是**数**还是**地址** | "操作数**包含在指令中**"→立即；"指令中给出操作数的**地址**"→直接 |
| 直接 ↔ 间接 | 读回来的东西**还要不要再当地址用一次** | "所指向的**存储单元中存的是操作数的地址**"→间接（2 次访存）；直接只跑 1 次 |
| 寄存器 ↔ 寄存器间接 | 寄存器里装的是**数**还是**地址** | "操作数在寄存器中"→寄存器寻址；"操作数的**地址**在寄存器中"→寄存器间接 |

**考点② 三个"加法"分不清：变址、基址、相对。** 三者形式全是"某寄存器 + 形式地址"，只能看基准是谁：题干出现**数组、循环、下标**选变址；出现**重定位、程序浮动、多道程序装入、扩大寻址能力**选基址；出现 **PC、程序计数器、转移指令**选相对。常见错法是变址与基址整个对调——口诀是"变址是用户在改下标，基址是系统在挪程序"。

**考点③ 访存次数与速度排序。** 数的是"从地址码到操作数中间跨过几次内存"：**0 次是立即和寄存器，2 次只有间接（最慢），直接、寄存器间接、变址、基址都是 1 次**（相对寻址用于转移指令时不取操作数，不排进这个榜）。三个高频错法：把**取指令那一次也算了进去**（题干没写"包括取指令"就不算）；把**读寄存器当成访存**（读寄存器在 CPU 内部，不算）；同为 0 次时不再往下比，导致"最快的是哪个"答成寄存器——正确答案是**立即**。

**考点④ RISC/CISC 判断题，错误选项只有三种造法。** 四道真题正好把三种造法各示范了一遍，认出造法就不用逐字比对：

- **造法一：把 CISC 的特征安到 RISC 头上。** "RISC 指令种类多、指令功能强"（2022下 B）、"RISC 寻址方式多"、"RISC 指令长度可变"。2024下换成反着问——"不属于 CISC 特征的是"，答案是"指令长度固定"，即把一条 RISC 特征塞进一堆 CISC 特征里让你挑出来，判据没变。
- **造法二：把两边整个对调。** "RISC 普遍采用微程序控制器，CISC 则普遍采用硬布线控制器"（2022上 B）、"RISC 采用很少的通用寄存器，CISC 采用很多的通用寄存器"（2021上 C）、"RISC 使用复杂的指令，CISC 使用简单的指令"（2021上 B）。
- **造法三：绝对化否定。** "RISC 不采用流水线技术，CISC 采用流水线技术"（2021上 A）——**两者都用流水线**，只是 RISC 更适合；2022上 D 把"RISC 和 CISC 都采用流水线技术"作为**正确**表述放进选项，正是同一个知识点的正反两面。

**考点⑤ 两个小考点，一句话各自认清。** 一是**指令寻址 vs 操作数寻址**：题干问的是"下一条指令怎么找"就只在**顺序寻址 / 跳跃寻址**两个里选，别把立即、直接那一串答上去。二是 **Flynn 分类**：给"一个控制部分 + 多个处理器"选 SIMD，给"被证明不实际、现实中不存在"选 MISD，给"全面并行、多处理机系统"选 MIMD；干扰项常写成"MISD 是阵列处理机"（阵列处理机是 SIMD）。

### 参考答案

1. **A**。三种都不需要"绕一道弯"，但快慢仍分三档：立即寻址的操作数随指令一起被取回，取指结束就在手上，最快；寄存器寻址还要按编号去寄存器读一次，次之；直接寻址要跑一趟主存，最慢。B、D 把寄存器排到立即前面，是只数"访存次数"、同为 0 次时不肯再往下比一层的结果；C 把最慢的排到了最前面。
2. **D**。**组合逻辑控制器就是硬布线控制器的另一个名字**——RISC 用它，CISC 用微程序控制器，D 写的正是这个口径，所以 D 正确。A 错在"RISC 不采用流水线"（两者都用流水线，RISC 只是更适合）；B 把复杂与简单整个对调；C 把通用寄存器的多少对调，RISC 才是寄存器多的那一边。
3. **B**。造法二（两边对调）：RISC 用硬布线（组合逻辑）控制器，CISC 才普遍用微程序控制器。A 对——RISC 大部分是单周期指令；C 对——指令种类和寻址方式 RISC 都更少；D 对——两者都用流水线，只是 RISC 更适合。
4. **B**。造法一（把 CISC 的特征安到 RISC 头上）：RISC 的指令都是基本功能指令，数量少、功能基本。A 对——只有 Load/Store 能访存正是"对存储器操作进行限制"；C 对——大量通用寄存器是 RISC 在特性表里唯一"多"的一项；D 对——只留使用频率较高的指令。
5. **A**。题目问的是**不属于 CISC** 的那一条。指令长度固定是 RISC 的特征，CISC 是变长格式，选 A。B、C、D 三条——寻址方式多、一条指令占的时钟周期多、指令类型多——全是 CISC 的原口径。本题反着问，判据不变，但要盯紧问的是哪一边。
6. **B**（①③④）。②"寻址方式多"是 CISC 的特征：寻址方式一多，同一个操作码后面那几位就要按多种规矩分别解释，译码必须分岔、指令也难以定长，正是 RISC 头一个砍掉的东西。判断口诀是"特性表里 RISC 只有通用寄存器是多的"，看见别的"多"先怀疑。
7. **B**。"操作数**包含在**指令中"是立即寻址的定义原话。A 直接寻址给的是操作数的**地址**不是操作数；C 操作数在寄存器里；D 给的是"地址的地址"。
8. **C**。基准是 PC 就是相对寻址。基准换成变址寄存器是变址（A），换成基址寄存器是基址（B）；D 的地址整个来自寄存器，不做加法。
9. **B、C**。间接寻址要先按地址码读回一个地址、再按这个地址读回操作数，跑两趟主存，是八种里最多的；直接、变址、寄存器间接都是 1 次。第二空只有寄存器寻址不访存（操作数就在寄存器里），立即寻址虽然也不访存但不在选项里；D 基址寻址算完 EA 还要去内存取一趟。
10. **B、C**。第一空看关键词"按下标依次访问数组""指令无需改动"——变址寻址的有效地址 = 数组首址 + 变址寄存器里的下标，循环中只改寄存器不改指令。第二空看"装入主存的任意位置后都能正确运行"，这是重定位，靠基址寻址：程序挪走只需改基址寄存器一个数。两空互换是最常见的错法。
11. **立即 300（0 次）｜直接 700（1 次）｜间接 25（2 次）｜寄存器 700（0 次）｜寄存器间接 25（1 次）**。间接的两趟是：先读 [300] 得 700，这个 700 是地址不是操作数，再读 [700] 才得到 25。寄存器间接只跑第二趟，因为地址已经在 R1 里，读寄存器不算访存。
12. **SIMD；MISD**。一个控制部分对应一条指令流，多个处理器对应多条数据流，就是单指令流多数据流 SIMD（阵列处理机是它的代表）。MISD 是多指令流单数据流，一条数据流被多条指令控制会冲突，被证明不可能、至少不实际。
13. **B**。这是**指令寻址**里的跳跃寻址方式，说的是"下一条指令从哪来"。C、D 是"地址码怎么解释"那一层的名字（操作数寻址），和题干问的不是同一层——相对寻址常被转移指令拿去算跳转目标，但它本身不是指令寻址方式的名字；A 顺序寻址的下一条地址正是由 PC 给出的，与题干相反。

## 速记

- 指令 = **操作码**（干什么）+ **地址码**（对谁干）；执行三步 **取指令 → 分析指令 → 执行指令**
- **指令**寻址只有两种：**顺序**（PC 自动 +1）／**跳跃**（下一条地址由本条指令给出）；下面八种全是**操作数**寻址
- 立即＝操作数就在指令里｜直接＝指令给操作数**地址**｜间接＝指令给**地址的地址**｜寄存器＝操作数在寄存器｜寄存器间接＝**地址**在寄存器
- 三个"加法"只差基准：**EA = 变址寄存器 + 形式地址**｜**EA = 基址寄存器 + 形式地址**｜**EA = PC + 偏移量**
- 访存次数（**不含取指令**）：**0 次**＝立即、寄存器；**1 次**＝直接、寄存器间接、变址、基址；**2 次**＝间接（最慢）
- 速度榜（2021下真题）：**立即 > 寄存器 > 直接 > 间接**；同为 0 次访存时立即仍快过寄存器
- RISC＝**砍**：指令数量少、使用频率接近、**定长**格式、多为单周期、寻址方式少、**只有 Load/Store 访存**、**硬布线（组合逻辑）控制**、适合流水线、靠优化编译；特性表里**只有通用寄存器是"多"的**。CISC 反之：指令多而复杂、**变长**、寻址方式多、**微程序控制**、兼容性强、研制周期长
- Flynn 按**指令流 × 数据流**分四类，看"控制部分几个、处理器几个"：SISD 一一｜**SIMD 一控多处理器**（阵列处理机）｜MISD 多控一处理器（**不可能**）｜MIMD 全多（多处理机）
