## 开讲：一张已经是 3NF、却还在反复抄同一句话的表

全课跟着一张三列小表走。学校排课，一门课可以由多位教师各开一个班，但**每位教师只教一门课**；学生选定一门课之后，就被分到这门课的某一位教师名下。

**STJ(学生S, 教师T, 课程J)**

| S 学生 | T 教师 | J 课程 |
|---|---|---|
| 张三 | 王老师 | 数据库 |
| 李四 | 王老师 | 数据库 |
| 王五 | 王老师 | 数据库 |
| 张三 | 李老师 | 操作系统 |

把两条业务规则翻译成函数依赖：**F = { (S,J)→T，T→J }**。前一条是"某个学生的某门课对应唯一一位教师"，后一条是"教师只教一门课"。

> 培训资料那张依赖图把 (S,J)→T 画成 S、J 两条线先汇到一个中间点、再由该点出一支箭头指向 T，容易被拆读成 `S→T`、`S→J` 两条独立依赖。别这么读——那是**一条**联合依赖，资料正文也写明依赖集就是上面这两条。

### 一、3NF 漏在哪：把探照灯从"非主属性"挪到"每条依赖的左边"

**先别往下看：这张表最高属于第几范式？**

肉眼看它明显在重复，"王老师教数据库"抄了三遍，多数人第一反应是卡在 2NF 甚至 1NF。按讲义 31 的四步走一遍，结论恰恰相反：

① 求候选码（候选码＝能唯一钉住一行、且去掉其中任何一个属性就钉不住的最小属性组）：S 只在依赖左边出现过 ⇒ 必在码中；T、J 两边都出现，待定。(S)⁺={S} 不够，逐个补：(S,J)⁺ 用 (S,J)→T 收 T ⇒ 全 ✓；(S,T)⁺ 用 T→J 收 J ⇒ 全 ✓。**候选码两个：SJ 和 ST**。
② 分主/非主：S、T、J 各自都进过某个候选码 ⇒ **全是主属性，非主属性一个都没有**。
③ 2NF、3NF 的条件全都是"**非主属性**对码不许部分依赖 / 不许传递依赖"。这里没有非主属性，条件**无从违反** ⇒ **STJ 自动满足 3NF**。

判据全过，冗余却明摆着：王老师每多带一个学生，"王老师教数据库"就多抄一行（更新异常：改课名要改一片）；王老师这学期没人选，这条师课对应关系在表里**没地方存**（插入异常）。

**问题出在哪？** 把 ③ 那句话再读一遍——2NF 和 3NF 只盯着非主属性，**主属性之间怎么互相决定，它们一概不管**。这张表的病灶正是 `T→J`：T 是主属性，J 也是主属性，整条依赖躲在 3NF 的视线之外。

补法很直接：**别再区分主属性和非主属性，改成对每一条依赖的左边提要求**。一条依赖 X→Y 的左边 X 叫**决定因素**（讲义 31 已定义：X 一确定，Y 就跟着确定，X 就是那个"说了算的人"）。冗余为什么会发生？

因为 `T→J` 说"王老师"这三个字一出现，"数据库"就必然跟着出现；而"王老师"本身钉不住一整行（(T)⁺={T,J}，缺 S），所以它只能寄生在别人的行里，有多少行就抄多少遍。反过来，如果每个决定因素都能钉住一整行，它决定的东西每组只会出现一次，没有重复的余地。

这就是 **BCNF（Boyce-Codd 范式，BC 范式）**：R∈1NF，且 F 中**每一条非平凡函数依赖 X→Y**（"非平凡"指 Y 不是 X 的子集）的决定因素 X 都是**超码**——即 X⁺ = 全体属性。

培训资料的说法"每一个依赖的左边决定因素都必然包含候选键"是同一件事：包含某个候选码 ⇔ 是超码；它另一句"在第三范式的基础上进一步消除主属性对于码的部分函数依赖和传递依赖"说的也是 BCNF，选项里见到这句就是它。

**判 BCNF 的动作，就是逐条算依赖左边的属性闭包**（滚雪球，讲义 31 第二节）：

```
(S,J)→T ：(SJ)⁺ = {S,J,T} = 全体属性 ⇒ SJ 是超码 ✓
T→J     ：(T)⁺  = {T,J}   ≠ 全体属性 ⇒ T 不是超码 ✗
```

**STJ 是 3NF，不是 BCNF**，违反点是 `T→J`。分解办法和 31 一样——把病灶依赖连同它的决定因素整个搬出去：

```
TJ(教师, 课程)   码 T，唯一依赖 T→J 的左边就是码 ⇒ 自身已是 BCNF
ST(学生, 教师)   码 (S,T)，没有非平凡依赖 ⇒ 自身已是 BCNF
```

"王老师教数据库"从此只在 TJ 表里存一行，插入异常也没了。（培训资料还给了另一条路：把语义改成 `TS→J`，依赖集变成 F={SJ→T, ST→J}，两条依赖的左边 SJ、ST 各自就是候选码，算下来确实是 BCNF。

**但资料原文那句"其左边决定因素就包含了候选键之一 S"要打个折**——S 单独并不是候选码（(S)⁺={S}，什么也推不出），真正起作用的是 TS 合起来正好等于候选码 ST。而且这是**改业务规则**，不是分解，考试问"如何分解"时不能这么答。）

**3NF 与 BCNF 的分界线一句话**：3NF 允许"非超码的决定因素决定主属性"，BCNF 不允许。所以考题里"某个主属性反过来决定另一个主属性"就是标准的**3NF 但非 BCNF**。

### 二、两个闭包，别混：属性闭包 X⁺ 和依赖集闭包 F⁺

上一节反复在算 X⁺。接下来要讲的 F⁺ 只差一个字母，却是完全不同的东西，这是本课最容易混的一处。

- **属性闭包 X⁺**：从属性集 X 出发，用 F 滚雪球能推出的**全部属性**。它是**属性的集合**，例如 (T)⁺ = {T,J}。
- **函数依赖集闭包 F⁺**：F 能推出的**全部函数依赖**（包括 F 自己写出来的那几条）。它是**依赖的集合**，例如 F⁺ 里装的是 `T→J`、`SJ→T`、`ST→J`、`S→S`……

一个装属性，一个装依赖。"F 能推出某条依赖"这件事有个正式说法叫**逻辑蕴含**，推导规则就是 **Armstrong 公理系统**：

- **自反律**：Y⊆X ⇒ X→Y（右边是左边的一部分，白给，这就是平凡依赖）
- **增广律**：X→Y ⇒ XZ→YZ（两边同时添上同一批属性仍成立）
- **传递律**：X→Y 且 Y→Z ⇒ X→Z

由这三条推出三条常用推论：**合并**（X→Y 且 X→Z ⇒ X→YZ）、**分解**（X→Y 且 Z⊆Y ⇒ X→Z）、**伪传递**（X→Y 且 WY→Z ⇒ XW→Z）。这套公理是**完备**的——F⁺ 里的每一条依赖都能由这三条律反复套出来，一条不漏。

**先别往下看：R(A,B,C)，F = {A→B, B→C}，F⁺ 里一共有多少条依赖？**

左边可以是 {A,B,C} 的 7 个非空子集之一，右边同样 7 种，逐对验一遍：**含平凡依赖共 35 条，非平凡的 16 条**。三个属性、两条依赖就滚出这么多，属性一多 F⁺ 直接爆炸。所以**考试不会让你把 F⁺ 列出来**，只会问"某条依赖在不在 F⁺ 里"。而这个问题有个一步到位的判法：

> **X→Y 属于 F⁺ ⇔ Y ⊆ X⁺**

道理就是滚雪球的定义：X⁺ 装的正是"手上握着 X 能推出的一切属性"，Y 全在里面就说明 X 推得出 Y，缺一个就说明推不出。**这条桥梁把 F⁺ 的问题全部转成 X⁺ 的计算**，下面三节全靠它。

验一下：`AB→DE` 能否由 F={A→B, AB→C, D→AC, D→E} 推出？(AB)⁺ = {A,B,C}（D 不在手，后两条用不上），D、E 都不在里面 ⇒ **推不出**。

### 三、两个依赖集是不是同一件事：F⁺ = G⁺

同一套业务规则，两个人写出的依赖集可能长得不一样：一个写全了，一个把能推出来的冗余条目删掉了。**依赖集等价**指两者约束能力完全相同，记作 F⁺ = G⁺。

真去算两个 F⁺ 再比对是不可能的（上一节已经看到它有多大）。但有个省力的做法，而且它不是硬记的步骤：

> **F⁺ = G⁺ ⇔ F ⊆ G⁺ 且 G ⊆ F⁺**

为什么只验原始的那几条就够：如果 F 里每一条都能被 G 推出来，那么由 F 推出的任何东西，G 都能沿着同一条推导路径推出来（先用 G 推出 F 的那几条，再照抄 F 的推导），所以 F⁺ ⊆ G⁺；反方向同理。两个方向合起来就是相等。**F 只有几条，G 也只有几条，验完就完事。**

配上第二节的桥梁，动作变得很机械：**验 F ⊆ G⁺，就是对 F 的每一条 X→Y，用 G 求 X⁺，看 Y 在不在里面**；反过来验 G ⊆ F⁺。

**算例（等价）**：F = {A→B, B→C, A→C}，G = {A→B, B→C}。

```
验 F⊆G⁺（用 G 算）：A→B：(A)⁺_G={A,B,C} ⊇{B} ✓
                     B→C：(B)⁺_G={B,C}   ⊇{C} ✓
                     A→C：(A)⁺_G={A,B,C} ⊇{C} ✓   ← A→C 靠 A→B→C 传递推出
验 G⊆F⁺（用 F 算）：A→B：(A)⁺_F={A,B,C} ✓ ； B→C：(B)⁺_F={B,C} ✓
两方向都过 ⇒ F⁺=G⁺
```

**算例（不等价）**：F = {A→B, B→C}，H = {A→B, A→C}。验 F⊆H⁺ 时，第二条就卡住：(B)⁺_H = {B}——H 里两条依赖的左边都要 A，光有 B 一条也触发不了，C 推不出来。**一条不过立刻判不等价**，另一个方向不用再算。直觉上：H 知道"A 同时决定 B 和 C"，但完全没有依据说"B 自己就能决定 C"。

两个提速点：**F 若是 G 的子集，F⊆G⁺ 天然成立，只需验反方向**；判某条是不是冗余，就是把它从集合里删掉再验等价。

### 四、拆表的代价（一）：连回去会不会多出假行

31 和上面拆了这么多次表，一直默认"拆完还能连回来"。真的吗？把 STJ 换一种拆法：拆成 **SJ(学生,课程)** 和 **ST(学生,教师)**，属性一个没少。取原表里张三的两行做实验：

```
原表                        SJ 表              ST 表
张三 王老师 数据库           张三 数据库         张三 王老师
张三 李老师 操作系统          张三 操作系统        张三 李老师
```

**先别往下看：按公共属性 S 做自然连接（把公共属性取值相同的行两两拼起来），连出来是几行？**

2×2 = **4 行**：张三-王老师-数据库、张三-王老师-操作系统、张三-李老师-数据库、张三-李老师-操作系统。原表只有 2 行，凭空多出 2 行数据库里根本不存在的记录，叫**假元组**。更糟的是"张三-王老师-操作系统"连 `T→J` 都违反了——分解把数据搞坏了。

**分解后自然连接能精确还原原表、不多不少，才叫无损连接分解**（多出来才是问题，少是不可能的）。为什么这次会多：连接是按公共属性配对的，公共属性相同的行**两两全配**。要想不多配，公共属性就必须能唯一确定至少一边的剩余部分——同一个 S 值下，另一边只剩一行可配，配对就没得选。这正好是判据：

> 分解成两张表 R1、R2，令 X = R1∩R2。若 **X→(R1−X)** 成立**或** **X→(R2−X)** 成立，则无损；两个都不成立就是有损。（是"或"，不是"且"。判某条成不成立仍然是算 X⁺ 看包不包含。）

复验：SJ+ST 的公共属性 X={S}，(S)⁺={S}，既推不出 J 也推不出 T ⇒ **有损**，和实验一致。上一节的 ST+TJ：X={T}，(T)⁺={T,J} ⊇ {J} = TJ−T ⇒ **无损**。同一张原表，公共属性取 S 就散架，取 T 就完好。**公共属性为空时两条都不可能成立，必定有损。**

**分解成三张及以上，用表格法（追踪法）**。培训资料的例：成绩(学号,姓名,课程号,课程名,分数)，F={学号→姓名，课程号→课程名，(学号,课程号)→分数}，拆成 成绩(学号,课程号,分数)、学生(学号,姓名)、课程(课程号,课程名)。

画一张"子表 × 属性"的表，某子表含某属性就打 √（表示这一格已经能确定成原表该列的值），不含就打 ×（还确定不了）。然后拿 F 里的依赖反复"传染"：**若某条 X→Y 的 X 那几列上有几行取值完全相同，则这几行的 Y 列可以统一——只要其中一行的 Y 是 √，其余行的 Y 就都改成 √**。

```
初始          学号 姓名 课程号 课程名 分数        用 学号→姓名：成绩行与学生行的学号列相同(都是√)，
成绩(学,课,分) √    ×    √     ×     √         学生行姓名是√ ⇒ 成绩行姓名改√
学生(学,姓)    √    √    ×     ×     ×         用 课程号→课程名：成绩行与课程行的课程号列相同，
课程(课,课名)  ×    ×    √     √     ×         课程行课程名是√ ⇒ 成绩行课程名改√

结果          学号 姓名 课程号 课程名 分数
成绩          √    √    √     √     √   ← 整行全 √ ⇒ 无损
```

某一行全部变成 √，就说明这张子表连接其余子表后能还原出原表的任意一行，分解无损；反复传染到不再变化仍没有全 √ 的行，就是有损。

### 五、拆表的代价（二）：原来的约束还看得住吗

回到那个**无损**的分解 ST(S,T) + TJ(T,J)。看上去很完美，但原来的 `(S,J)→T` 出事了：S 在 ST 表里，J 在 TJ 表里，**这条约束的两头分散在两张表**，谁也没法单独检查它。

后果是实打实的。假设赵老师也开一个数据库班（`T→J` 允许一门课多位教师），往 TJ 插 (赵老师,数据库)、往 ST 插 (张三,赵老师)：ST 表没有任何非平凡依赖，合法；TJ 表仍满足 T→J，合法。

**两张表各自都挑不出毛病**，可连起来看，张三的数据库课同时挂着王老师和赵老师，`(S,J)→T` 被违反了。数据库管不了，只能靠应用层代码或触发器兜着。

> **保持函数依赖**：分解后，F 里的每一条依赖都能**只看某一张子表自身的数据**验证出来，不必先把表连回去。

判法（考试规模够用的充分条件）：**看每条依赖的左右两边属性是不是同时落在同一张子表里**。`T→J` 的 T、J 同在 TJ 表 ✓；`(S,J)→T` 的 S、J 不同框 ✗ ⇒ **这个分解无损，但不保持依赖**。

同框只是**充分条件**——不同框的依赖仍可能被其余子表联手推出来。培训资料的例子：R(A,B,C)，F={A→B，B→C，A→C}，分解成 R1(A,B)、R2(B,C)。

`A→B` 在 R1、`B→C` 在 R2，都同框；`A→C` 两头分开，但它是**冗余依赖**——A→B 和 B→C 一传递就得到它，删掉不改变约束能力，所以这个分解照样保持依赖（它也无损：交集 {B}，(B)⁺={B,C} ⊇ R2−{B}={C}）。

遇到这种不同框的依赖，用培训资料的通用算法核实：对每条 α→β，令 `result=α`，反复对每张子表 Ri 做 `result = result ∪ ((result∩Ri)⁺ ∩ Ri)`，直到 result 不再变化，最后看 β 是否 ⊆ result。练习 1、2 各走一遍。

**必须记住的两条结论（选项就长这样）**：

- **BCNF 分解总能做到无损连接，但不一定保持函数依赖**（本课的 ST+TJ 就是活标本）
- **3NF 分解有算法可以同时做到无损连接 + 保持依赖**

这就是工程上"规范化到 3NF 就够了"的真正含义：不是 3NF 更干净，而是**再往上走要拿约束保持去换**。另外，无损和保持依赖是**两个互相独立**的性质：可以无损而不保持（ST+TJ），可以两者兼得（刚才的 R1(A,B)+R2(B,C)，以及自测 9），也可以两头落空（练习 2）。

### 六、BCNF 也管不到的冗余：多值依赖与 4NF

**这里必须换例子**——STJ 里每条依赖都是"一个 X 定死一个 Y 值"的函数依赖，而下面这种冗余的形状是"一个 X 对应一整组 Y"，在 STJ 上造不出来。

仓库表 **WPM(仓库W, 保管员P, 产品M)**：一个仓库有多名保管员，也存放多种产品，但**保管员不按产品分工**——每名保管员都负责本仓库的全部产品，保管员和产品之间没有任何对应关系。

| 仓库 | 保管员 | 产品 |
|---|---|---|
| W1 | 张三 | 螺丝 |
| W1 | 张三 | 螺母 |
| W1 | 李四 | 螺丝 |
| W1 | 李四 | 螺母 |

**先别往下看：如果 W1 有 3 名保管员、存 4 种产品，这张表要占多少行？**

**12 行**——每名保管员必须和每种产品配一遍，行数是**乘积**。新来一名保管员王五，得同时插 4 行；漏插一行，数据就不完整。5 名保管员 8 种产品是 40 行，拆开只要 5+8=13 行。

先确认 BCNF 真的管不了它：这张表**一条非平凡函数依赖都没有**（W 定不了 P，P 定不了 M，任意两列也定不了第三列），唯一的候选码是三列全体 (W,P,M)。没有非平凡依赖，BCNF 的条件无从违反 ⇒ **WPM 已经是 BCNF**，冗余照旧。

新的形状要用新的语言描述：**多值依赖 X→→Y**（读作"X 多值决定 Y"）——对 X 的每一个取值，Y 都对应**一整组**值，而且这组值的构成**只跟 X 有关，与其余属性 Z = U−X−Y 的取值无关**。

这里 W→→P（W1 对应 {张三,李四}，跟存什么产品无关）、W→→M（W1 对应 {螺丝,螺母}，跟谁保管无关）。多值依赖总是成对出现，所以也写成 W→→P|M。若 Z 为空（Y 把剩下的属性占全了）或 Y⊆X，叫**平凡多值依赖**，不产生冗余。

两个必背关系：**函数依赖是多值依赖的特例**——X→Y 成立时 X→→Y 必然成立（"一整组"退化成只有一个值）。方向别记反。

补法和 BCNF 一模一样，还是对决定因素提要求：

> **4NF**：在 **BCNF** 基础上，要求每个**非平凡**多值依赖 X→→Y 的 X 都是超码。

WPM 里 (W)⁺ 推不出全体属性，W 不是超码 ⇒ 不满足 4NF。分解就是**把两组互不相干的多值属性各自带走**：**WP(仓库,保管员) + WM(仓库,产品)**。新增保管员只需在 WP 加一行。这个分解也是无损的（两表分解的无损定理对多值依赖同样成立：公共属性 W 满足 W→→P）。

回头看这一路：1NF 到 3NF 管的是非主属性，BCNF 把要求提到每一条函数依赖的左边，4NF 又把同一句要求套到多值依赖上——**三级台阶的补法其实是同一个动作，只是被检查的对象一次比一次宽**。而每上一级台阶都得靠拆表换，拆表又得回头验无损与保持依赖，这两件事在 31 里被跳过了，现在补齐。规范化理论到这里就完整了。

## 考试怎么考

**考点① 判 BCNF（本课最高频）。** 题目长相："关系模式 R(X,Y,Z)，F={XY→Z, Z→X}，R 的候选码是（ ），R 属于（ ）"，选项形如"候选码 XY 和 YZ，属于 3NF 但不属于 BCNF"。四步：求候选码（31 的三步法）→ 分主/非主 → 判 2NF/3NF（**没有非主属性就自动 3NF**）→ **逐条**算 F 中每条依赖左边的闭包，有一条不是全体属性就卡在 BCNF。常见错法：**候选码只找到一个就往下走**（这类题的候选码几乎总有两个，漏一个连主属性都判错）；**看见主属性被非码决定就说不满足 3NF**（3NF 只管非主属性，这正是分界线）；判 BCNF 时只查候选码那条依赖。

**考点② 依赖能否由 F 推出 / 依赖集等价。** 前者问"下列依赖中不能由 F 推出的是"，算 X⁺ 看右边包不包含即可。后者给 F、G 问是否等价、或问哪条是冗余依赖，**双向各验一遍**。常见错法：**只验一个方向**（F 是 G 子集时那个方向天然成立，说明不了等价）；**用错闭包依据的集合**（验 F 的条目必须用 G 滚雪球，用自己验自己永远都过）。

**考点③ 无损连接判断。** 分解成两张表时求交集 X，算 X⁺，看它是否包含某一边的独有部分，**满足其一即可**。三张及以上用表格法。常见错法：把"或"当成"且"；凭直觉判 X→(R1−X) 而不算闭包；忘了交集为空必定有损。

**考点④ 保持依赖判断。** 几乎总和考点③拼在同一道题的四个选项里（无损且保持 / 无损不保持 / 有损但保持 / 都不），所以**两个判断各做一遍才能定选项**。看每条依赖左右是否同框；不同框再用通用算法确认。常见错法：看见"属性都还在"就说保持依赖（关键是同一条依赖的两头在不在同一张表）；把无损和保持依赖当成一回事。

**考点⑤ Armstrong 公理与推论辨析。** 给一条推导问用了哪条规则，或直接问某条律的定义——2018上就考过"Armstrong 公理系统的伪传递律是指（ ）"。三律三推论对上名字即可：`BC→A` 由 `C→A` 增广得 `BC→AB`、再分解得到。

**考点⑥ 多值依赖与 4NF（概念题，不用动笔算）。** 问"下列关于多值依赖与 4NF 的说法不正确的是"。四条真值背牢：函数依赖是多值依赖的特例（不是反过来）；X→→Y 要求那组 Y 的取值与其余属性无关；**4NF 的台阶是 BCNF→4NF，不是 3NF→4NF**（最高频错误选项）；只有平凡多值依赖时自动满足 4NF。

### 参考答案

**1. D**。**无损**：交集 X={A}，(A)⁺={A,B,C} ⊇ R1−X={B} ⇒ 满足其一，无损（表格法复算同样为无损）。**不保持**：`A→B` 的 A、B 同在 R1 ✓；`B→C` 的 B 在 R1、C 在 R2，不同框 ✗。再用通用算法确认：result={B}；对 R1(A,B)：(B∩AB)⁺∩AB = (B)⁺∩{A,B} = {B,C}∩{A,B} = {B}，无新增；对 R2(A,C)：B∩{A,C}=∅，∅⁺∩{A,C}=∅，无新增；result 不再变化 = {B}，不含 C ⇒ 确实不保持。选 D。

**2. A、D**。**候选码**：只在左边出现的是 C、D ⇒ 必在码中；只在右边的是 E ⇒ 必不在码；(CD)⁺ = {C,D} —D→A→ {A,C,D} —A→E→ 加 E，此时 AC 齐了 —AC→B→ 加 B ⇒ 全 ✓。CD 已是"必在码"属性的合集，不可能更小，候选关键字唯一 = **CD**，选 A。**分解**：交集 X = ABCE∩CD = {C}，(C)⁺={C}，既不含 R1−X={A,B,E} 也不含 R2−X={D} ⇒ **有损**（表格法复算亦为有损）。保持依赖：B→A、A→E、AC→B 三条的属性都落在 R1 里 ✓，但 `D→A` 的 D 在 R2、A 在 R1，不同框；通用算法：result={D}，R1 那边交集为空无贡献，R2 那边 (D∩CD)⁺∩CD = {A,D,E}∩{C,D} = {D}，不变 ⇒ 不含 A，**不保持**。两头都不成立，选 D。

**3. B**。Y 只在左边出现 ⇒ 必在码；(XY)⁺ 用 XY→Z 收 Z ⇒ 全 ✓；(YZ)⁺ 用 Z→X 收 X ⇒ 全 ✓；(X)⁺={X}、(Z)⁺={X,Z} 都不是超码 ⇒ 两个候选码 **XY 和 YZ**（漏掉 YZ 就会误选 C）。X、Y、Z 全是主属性，无非主属性 ⇒ 自动 3NF。判 BCNF：`Z→X` 的 (Z)⁺={X,Z} ≠ 全体属性 ⇒ Z 不是超码，违反。选 B。

**4. 候选码 PD 和 PM；属于 3NF，不属于 BCNF；分解为 MD(负责人,部门) + PM(项目,负责人)。** 这题和正文的 STJ 结构完全同构（P↔S、D↔J、M↔T）。P 只在左边出现必在码；(PD)⁺ 收 M ⇒ 全 ✓，(PM)⁺ 收 D ⇒ 全 ✓，两个候选码。三个属性全是主属性 ⇒ 无非主属性 ⇒ 自动 3NF。`M→D`：(M)⁺={M,D} ≠ 全体属性 ⇒ M 不是超码 ⇒ 违反 BCNF。按正文办法把 M→D 整个搬走。（顺带：这个分解无损——交集 {M}，(M)⁺⊇{D}；但 `(P,D)→M` 的 P 与 D 不同框 ⇒ 不保持依赖，又一个"BCNF 分解保无损不保依赖"的实例。）

**5. 等价，F⁺=G⁺**。F 恰是 G 的子集 ⇒ F⊆G⁺ 方向天然成立，只需验 G⊆F⁺（用 F 算）：`AB→C`：(AB)⁺_F={A,B,C} ⊇{C} ✓；`C→A`：(C)⁺_F={A,C} ⊇{A} ✓；`BC→A`：(BC)⁺_F 由 C→A 收 A ⇒ {A,B,C} ⊇{A} ✓。三条全过 ⇒ 等价。BC→A 是冗余依赖：由 C→A 用**增广律**两边加 B 得 BC→AB，再用**分解规则**取出 BC→A。

**6. C**。A 正确（函数依赖是多值依赖的特例）；B 正确（多值依赖的定义就是那组 Y 值与其余属性 Z 无关）；**C 错误**——4NF 是在 **BCNF** 基础上消除非平凡多值依赖，台阶不能跳过 BCNF；D 正确（只有平凡多值依赖时约束无从违反）。

**7. 候选码 A 和 B，属于 BCNF。** C 只在右边出现 ⇒ 必不在码；(A)⁺ 由 A→BC 收 B、C ⇒ 全 ✓；(B)⁺ 由 B→A 收 A，再由 A→BC 收 C ⇒ 全 ✓。两个单属性候选码 A、B，C 是唯一非主属性。逐条判 BCNF：`A→BC` 左边 A 是候选码即超码 ✓；`B→A` 左边 B 是候选码 ✓ ⇒ 每个决定因素都是超码 ⇒ **BCNF**（自然也满足 2NF、3NF）。

**8. 不等价。** 验 F⊆G⁺ 时第二条就卡住：`B→C` 要 (B)⁺_G，而 G 的三条依赖左边分别要 A、A、C，光有 B 一条都触发不了 ⇒ (B)⁺_G={B}，不含 C ✗ ⇒ 立刻判不等价。（反方向其实也过不了：`C→B` 的 (C)⁺_F={C}。但判定只需一条不过就收工。）

**9. 无损，且保持依赖。** 表格法：初始 R1 行 (√√××)、R2 行 (×√√×)、R3 行 (××√√)；用 A→B 无新增，用 B→C 使 R1 行的 C 变 √（R1、R2 的 B 列同为 √，R2 的 C 是 √），此时 R1=(√√√×)；用 C→D 使 R1 行的 D 变 √（R1、R3 的 C 列同为 √，R3 的 D 是 √）⇒ R1 行全 √ ⇒ **无损**。保持依赖：A→B 在 R1、B→C 在 R2、C→D 在 R3，三条各自同框 ⇒ **保持**。（顺带：R 的候选码是 A，非主属性 B、C、D；`B→C` 左边不是超码、右边是非主属性 ⇒ 原 R 连 3NF 都不到，这个分解正是把它一路拆到 BCNF 的标准做法。）

**10. 仍然无损，但不再保持依赖。** 三张子表都含 A，而 (A)⁺ = 全体属性，连接时 A 能唯一钉住每一边 ⇒ 表格法复算为无损。可是 `B→C` 的 B、C 不同框，`C→D` 的 C、D 也不同框，通用算法确认两条都推不回来 ⇒ 不保持依赖。**同一张表、同一个 F，只换了拆法，无损保住了、依赖丢了**——这就是第五节说的两条性质互相独立。

## 速记

- BCNF：**每条非平凡依赖的决定因素都得是超码**；判法＝逐条算左边的 X⁺，有一条不是全体属性就卡住
- "3NF 非 BCNF"的脸：**没有非主属性（自动过 3NF）＋ 某个主属性又反过来决定别的属性**；候选码常有两个，别只找一个
- **X⁺ 装属性，F⁺ 装依赖**；桥梁：**X→Y ∈ F⁺ ⇔ Y ⊆ X⁺**。Armstrong 三律：自反、增广、传递；三推论：合并、分解、伪传递
- 等价判断**双向**：F 的每条用 **G** 算闭包，G 的每条用 **F** 算；一条不过立刻否决；F⊆G 时只验反方向
- 无损（两表）：**交集能决定至少一方的独有部分**，满足**其一**即可，交集为空必有损；三表以上用表格法，**某行全 √ 即无损**
- 保持依赖：**每条依赖的左右两边同框**（不同框再用通用算法）
- 代价口诀：**BCNF 分解保无损、不保依赖；3NF 分解可以两全**；两条性质互相独立
- 多值依赖：**一个 X 对应一整组 Y，且与其余属性无关**，行数是乘积；**函数依赖是多值依赖的特例**；台阶是 **BCNF→4NF**，不是 3NF→4NF
