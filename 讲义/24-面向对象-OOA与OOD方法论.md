# 24 · 面向对象：OOA 与 OOD 方法论

> 真题：OOA/OOD 活动顺序 2021上/2022下、面向对象测试层次 2023上/2023下｜无计算｜未讲（自学讲义）

---

## 第 0 层 · 定位

**这一课回答**：拿面向对象怎么做分析和设计：从一段需求文本到一组类，OOA 的五个活动、OOD 的层次顺序是什么。

**前后关系**：23 讲「是什么」，本课讲「怎么做」，25–27 讲「怎么画出来」；下午题 3 本质就是现场做一次 OOA。

**分值与去向**：板块 9–11 分，本课约 1 题，考法固定（排顺序、给场景认阶段）。零计算，背下顺序即得分。

---

## 第 1 层 · 理解

### 一句话

> 需求是一段中文，代码是一堆类。这一课就是那条把中文变成类的**流水线**：先按名词挑出候选类（OOA），再补上界面、存储、并发这些实现层的东西（OOD），最后按 OO 自己的结构重新划分测试层次。

### 痛点：结构化方法在"分析→设计"这一步会走样

结构化方法里，分析的产物是**数据流图**，设计的产物是**模块结构图**——两种完全不同的模型。中间那次转换是靠人脑硬翻的，很容易翻走样、翻丢信息。

面向对象方法的核心优势就在这儿：**分析和设计用的是同一套概念（对象 / 类）**。OOA 画的是类，OOD 还是类，只是把类补细了。所以说 OO 各阶段之间是**平滑（无缝）过渡**——这句话本身就是考点。

### 一条主线

```
需求文本（一段自然语言）
   ↓ 怎么从中文变出一组类？—— 名词识别法：
   ↓    名词 → 候选类；动词 → 候选操作；再做三条剔除
   ↓
【OOA · 做什么】五步流水线：
   认定对象 → 组织对象 → 描述相互作用 → 确定操作 → 定义内部信息
  （先找有谁 → 理清关系 → 看怎么打交道 → 派活 → 补上各自的数据）
   ↓ 产出：问题域模型——只有业务概念，
   ↓        不管界面长什么样、数据存哪、用不用多线程
   ↓ 离能编码还差一截
【OOD · 怎么做】补齐实现层的四个部分：
   问题域部分（把分析模型细化）+ 人机交互 + 任务管理 + 数据管理
   ↓ 全程用的都是"类"这一套概念 → 分析到设计【无缝过渡】
   ↓ 做出来要测
【OO 测试】结构变了，测试分层也跟着变（由小到大）：
   算法层(单个方法) → 类层(类内配合) → 模板层(多类协作) → 系统层(整体)
```

**这条链就是本课全部**：一条从"中文"到"能跑的系统"的流水线，每一段有它自己的名字。

## 第 2 层 · 考点：考试怎么问

### 考点① OOA 五步的顺序（排序题，最高频）

> **认定对象 → 组织对象 → 描述对象间的相互作用 → 确定对象的操作 → 定义对象的内部信息**

| 步骤 | 干什么 |
|---|---|
| ① **认定对象** | 从需求陈述中找出问题域里的对象/类（用名词识别法） |
| ② **组织对象** | 分析对象间关系，抽出**一般-特殊**（继承）结构、**整体-部分**（组成）结构 |
| ③ **描述相互作用** | 谁给谁发什么消息、事件如何在对象间传递 |
| ④ **确定对象的操作** | 在交互脚本基础上，确定每个对象该提供哪些操作（方法） |
| ⑤ **定义对象的内部信息** | 补上类内部的数据结构与属性（类图里"属性"那一层） |

**不用死背，按这个逻辑推**：
> 先得知道**有谁**（认定）→ 才能理清**谁和谁什么关系**（组织）→ 再看**他们怎么打交道**（相互作用）→ 接着落实**每人具体干什么活**（操作）→ 最后补上**每人内部装了什么数据**（内部信息）。跟你接手一个新项目读代码的顺序完全一样。

**真题提示**：【真题·2021上】等排序题常**只给前 4 项**让你排。但"不包括哪项"这类反向提问会用到第 5 项，所以 5 步都要有印象。

**另一套表述**（Coad/Yourdon 法）：标识对象和类 → 标识结构 → 定义主题 → 定义属性 → 定义服务。两套表述教辅里都有，**考试按题面给的选项对号入座**，核心逻辑一致：先找对象 → 再理结构 → 最后定服务。

### 考点② 名词识别法——从需求文本挑类（高频）

**题目长相**："采用面向对象方法分析需求'……'时，最适合识别为**类**的一组名词是（ ）"。

**基本规则**：
> **名词 → 候选对象/类；动词 → 候选操作（方法）**

**三条剔除规则（这是解题的真正关键）**：
1. ✂️ 剔除**系统边界外**的事物（系统本身、场所）
2. ✂️ 剔除**只是属性值**的名词（一个数值、一个编号）
3. ✂️ 剔除**重复/同义**的名词、泛指过程的抽象名词

**实操演示**（图书馆借书系统）：

> "读者凭借书证在图书馆借阅图书。图书管理员扫描借书证和图书条码，为读者办理借书手续；读者归还图书时，图书管理员办理还书手续，若图书逾期则计算罚金。"

圈名词：读者、借书证、图书馆、图书、图书管理员、条码、手续、罚金
圈动词：借阅、扫描、办理借书、归还、办理还书、计算罚金

| 名词 | 判定 | 理由 |
|---|---|---|
| 读者、图书、借书证、图书管理员 | ✅ **候选类** | 系统内有状态、有行为的业务实体 |
| 罚金 | ⚠️ 降级为**属性**/计算结果 | 更像"借阅记录"的一个金额属性 |
| 图书馆 | ✂️ **剔除** | 系统本身 / 边界，不是系统内部要管理的对象 |
| 条码 | ✂️ 降级为**属性** | 是"图书"的一个属性值 |
| 手续 | ✂️ **剔除** | 泛指动作过程的抽象名词，无独立状态 |

> **补充意识**：分析中常要补上文本**没直说**的类（如上例的"借阅记录"）——需求文本不会把所有类都写成名词。

### 考点③ OOA vs OOD 的分界（辨析题）

| 对比项 | **OOA 分析** | **OOD 设计** |
|---|---|---|
| 回答 | **做什么**（What） | **怎么做**（How） |
| 关注 | **问题域**：业务里有哪些对象、什么关系、什么行为 | **解决方案域**：怎么用类/接口/子系统实现 |
| 产出 | 问题域对象模型（分析类图、用例） | 可编码的设计模型（细化的类、接口、包结构） |
| 管实现细节吗 | **不管**（不涉及数据库、界面、语言） | **管**（补上人机交互、数据存储、任务管理） |

**判别口径（一句话解题）**：
> 题目提到**界面怎么设计、数据存哪、用不用多线程** → **OOD**；
> 只谈**业务里有哪些对象、什么关系** → **OOA**。

**OOD 四部分**（Coad/Yourdon 法，常考"OOD 包括哪几部分"）：
**问题域部分**（分析模型的细化）、**人机交互部分**（界面）、**任务管理部分**（进程/线程、并发）、**数据管理部分**（持久化存储）。

程序员类比：OOA ≈ 和产品对齐后的领域模型草图（只有业务概念）；OOD ≈ 开始定 service/dao 分层、接口签名、字段类型的详细设计。

### 考点④ 面向对象测试的四个层次（高频）

**为什么要重新分层**：OO 程序的行为分散在类、继承层次和对象协作里，传统"函数→模块→系统"的划分对不上，所以按 OO 自己的结构重新分。

**由低到高**：

| 层次 | 测什么 | 对应传统测试 |
|---|---|---|
| **算法层** | 类中定义的**每个方法**本身对不对 | ≈ 单元测试 |
| **类层** | 封装在**同一个类**中的**方法与属性之间**的相互作用 | ≈ 模块测试（OO 的"模块"就是类） |
| **模板层**（别名"类树层"待核实） | **一组协同工作的类**之间（含继承层次）的相互作用 | ≈ 集成测试 |
| **系统层** | 各子系统**组装成完整系统**后测试 | ≈ 系统测试 |

**记忆逻辑（由小到大）**：单个方法 → 一个类内部配合 → 多个类协作 → 整个系统。
**考法**：给一句描述让你选层次。抓关键词——"每个方法"→算法层；"同一个类中方法与属性"→类层；"一组协同工作的类"→模板层；"子系统组装"→系统层。

## 第 4 层 · 速记

> **OOA 做什么、OOD 怎么做**；分析只看问题域，设计补上界面/存储/任务
> OOA 五步：**认定 → 组织 → 相互作用 → 定操作 → 定内部信息**
> （先找有谁 → 再理关系 → 再看协作 → 然后派活 → 最后补数据）
> 名词识别法：**名词当类、动词当操作**；剔边界外、剔属性值、剔同义词
> OOD 四部分：**问题域、人机交互、任务管理、数据管理**
> OO 测试四层：**算法(方法) → 类(类内) → 模板(类间) → 系统(整体)**，对应 单元→模块→集成→系统
> OO 的独门优势：分析设计**同一套概念**，阶段间**无缝过渡**

## 考题回顾

**1.【模拟·重现2021上考点】** 面向对象分析的活动包括：①描述对象间的相互作用；②认定对象；③确定对象的操作；④组织对象。正确顺序是（ ）。
A. ②④①③　B. ②①④③　C. ④②①③　D. ②④③①
**解**：**A**。认定(②)→组织(④)→相互作用(①)→定操作(③)。

**2.【模拟·重现2022下考点】** 分析需求"顾客在收银台通过收银员结账，收银员扫描商品条码，系统计算总价并打印小票"时，最适合识别为**类**的一组名词是（ ）。
A. 顾客、收银员、商品、小票　B. 扫描、计算、打印　C. 条码、总价　D. 结账、收银台
**解**：**A**。B 全是动词（应为操作）；C 的条码/总价是商品/小票的**属性**；D 中"结账"是动作、"收银台"接近边界/场所。

**3.【模拟·重现2023上考点】** 测试"封装在同一个类中的方法与属性之间的相互作用"属于（1）；测试"一组协同工作的类之间的相互作用"属于（2）。
A. 算法层/类层　B. 类层/模板层　C. 类层/系统层　D. 模板层/系统层
**解**：**B**。类内方法与属性 = 类层；一组协同类（类树/继承层次）= 模板层。

**4.【模拟】** 下列工作中属于 **OOD** 而不属于 OOA 的是（ ）。
A. 从需求陈述中认定问题域中的对象
B. 识别对象间的一般-特殊结构
C. 设计人机交互界面类和数据存储方案
D. 描述对象之间的消息传递关系
**解**：**C**。界面（人机交互部分）与存储（数据管理部分）是 OOD 补充的实现层内容；A/B/D 分别是 OOA 的认定对象、组织对象、描述相互作用。

## 自测练习

1. 【模拟】需求句："会员使用积分兑换礼品，系统扣减相应积分。"用名词识别法列出候选类，并说明哪个名词应降级为属性。
2. 【模拟】"测试类中定义的每一个方法是否正确实现"属于 OO 测试的哪一层？大体对应传统测试的哪一层？
3. 【模拟】判断对错："OOA 阶段应确定系统采用哪种数据库存储对象数据。"

### 参考答案

1. 名词：会员、积分、礼品、系统。**候选类：会员、礼品**（通常还需补充文本未直说的"兑换记录"类）；**"积分"降级为会员类的属性**（本质是一个数值）；**"系统"是边界本身，剔除**。动词"兑换/扣减"→候选操作。
2. **算法层**；对应传统的**单元测试**——两者都以"最小可测单位（单个方法/函数）"为对象。
3. **错**。选择数据库/存储方案是实现层决策，属 **OOD（数据管理部分）**；OOA 只建立问题域模型，不考虑实现细节。
