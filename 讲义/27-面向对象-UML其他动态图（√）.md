## 开讲：顺序图画完了，可报销单自己的命运还没人管

继续用讲义 15、21 那套内部报销系统——同一个系统一路讲下来，才看得出每张 UML 图各自补的是哪一块，换个系统就得重新交代业务，反而看不清。

到这一步，类图说清了系统里有哪些类，顺序图说清了一次报销里"谁调谁、消息按什么时间顺序走"。但有两件事，这两张图一个字都答不了：

- **一张报销单自己的一辈子**：它在草稿、待审批、已驳回、已打款之间来回跳。顺序图画的是"一次交互"这一段横切面，画不出这张单子从生到死的全部走法。
- **整个报销流程该怎么走**：谁先干、谁后干、哪两步能同时干、哪一段归谁管。类图和顺序图都是围着"对象和消息"转的，答不了"流程"。

前一件是本课的第一张图，后一件是第二张。下面八个短板，八个补丁，一个接一个长出来。

### 一、盯住一张单子：状态图

**短板①：状态列得出来，谁能到谁列不出来。**

最朴素的做法你天天在干：给报销单表加一个 `status` 字段，在文档里列一张清单——草稿、待一级审批、已通过、已驳回、已打款。清单只回答"有哪些状态"。可代码里真正要判的是另一件事：**现在处于 A，允许不允许跳到 B**。清单不写这个，于是就有了"已取消的订单被发货""已驳回的单子被打款"这种 bug。

**先猜一下**：上面那张清单里，"已驳回"能不能到"已打款"？先别急着答"业务上当然不能"——问题在于，清单上根本没有地方能表达"不能"。

**状态图**就是把"允许的跳法"全部画出来的那张图。转录本 2-10 的原话是：状态图"展现了一个状态机，描述**单个对象在多个用例中的行为**"。**状态机**就是"有哪些状态 + 什么事件让它从这个状态跳到那个状态"这一整套规则，程序员写的 `switch(status)` 就是它的代码形态。另外三个术语当场说清：**状态**指对象在某一段时间里稳定的样子，比如报销单"处于待一级审批"；**转换**（也叫迁移）是从一个状态到另一个状态的那条带箭头实线；**事件**是让这条转换真的发生的那件事，比如"提交""审批驳回"。转录本还给了认图口诀：**图中方框代表状态，箭头上的代表触发事件，实心圆点为起点和终点**（教材把这两个圆点叫**初态**和**终态**；初态是实心圆，终态是圆环套实心圆，一张图只有一个初态，终态可以有多个、也可以没有）。

报销单先画主干——五个状态、五条转换，外加一条从初态进来、一条通向终态：

```
  ●
  │ 新建
  ▼
┌──────┐ 提交/冻结额度 ┌────────────┐ 审批通过/记审批日志 ┌────────┐ 打款成功/发到账短信 ┌────────┐
│ 草稿 │─────────────►│ 待一级审批  │───────────────────►│ 已通过 │──────────────────►│ 已打款 │──►◉
└──────┘              └────────────┘                    └────────┘                   └────────┘
                        │        ▲
   审批驳回/释放额度      │        │ 修改后重交
                        ▼        │
                      ┌──────────────┐
                      │    已驳回     │
                      └──────────────┘
```

（图上还少了"待二级审批"，短板②补。）现在回头看刚才那一猜：**图上没有从"已驳回"直接指向"已打款"的箭头，这就等于"不许"**。状态图的价值全在这句话上——它是**白名单**，画了的才允许，没画的一律禁止。

顺带说清一个易错点：从"已驳回"沿着"修改后重交"回到"待一级审批"、再审批通过、再打款，是**能**走到"已打款"的；直接跳不行，绕路行。题目问"能否到达"要看有没有一条路径，问"能否直接迁移"才是看有没有那一条边。

**短板②：同一个事件，要去两个不同的地方。**

"审批通过"这个事件在"待一级审批"状态下发生，金额 5000 元以内就直接到"已通过"，超过 5000 元还得转"待二级审批"。同一个状态、同一个事件，两条出边——光写事件名，图就自相矛盾了。

补丁是给转换加**监护条件**（写在方括号里的一句布尔判断，有的资料译作"守卫条件""警戒条件"，指的是同一样东西），转录本 2-10 说得很准："转换可以通过**事件触发器触发**，事件触发后相应的**监护条件**会进行检查。"顺序是**先有事件，再查条件**。加上转换那一瞬间要执行的**动作**（比如"记审批日志"），转换标注就凑齐了教材的三段式：

> **`事件 [监护条件] / 动作`** —— 事件负责触发，条件负责放行，动作跟着发生；三段都可以省略。
> （这个写法转录本没写出格式，是按教材第 5 版补的；转录本只点了"事件触发器""监护条件"两个名词。）

于是那两条出边就分得开了：

```
                             ┌── 审批通过 [金额≤5000] / 记审批日志 ──► 已通过
┌────────────┐               │
│ 待一级审批  │───────────────┤
└────────────┘               │
                             └── 审批通过 [金额>5000] / 记审批日志 ──► 待二级审批

            待二级审批 ── 审批通过 / 记审批日志 ──► 已通过
```

注意最后那一步别漏：**"待二级审批"必须自己也有一条出边**，二审通过后同样进"已通过"（这条边和上面同名，只是不必再判金额）。状态图里凡是画出来却没有出边的状态，就等于告诉读代码的人"进去出不来"，是画状态图最常见的低级错。

补上这两支，整台状态机就是**六个状态、七条转换**（其中两条带监护条件），外加一条从初态进来、一条通向终态；这时"已打款"才是唯一没有出边的状态。

**这里藏着上午题最爱设的一个错项**：条件自己**不会**触发转换。选项要是写成"只要金额大于 5000，即使没人点审批通过，也会自动转到待二级审批"，就是错的——事件没发生，闸门再开也没人走。反过来，事件发生了而条件为假，转换同样不发生。

事件还有一类要认得：**时间事件**，写成 `after(3 天)`、`when(超时)` 这种。2021 上半年那道题就把"`When(...)` 称为时间事件"当作**正确**说法，考场上照这个口径答。

**短板③：状态框里那段时间，系统在干什么？**

"待一级审批"可能挂三天。这三天里系统要每天给审批人发提醒；刚进这个状态要发一封通知邮件；离开时要把提醒任务取消。这些都不是"转换那一瞬间的动作"，写在箭头上不对。

教材的补丁是把状态框横着分成两格，上格写状态名，下格写三种**内部活动**（**转录本正文和它的配图都没有这三个词**，这一段按《软件设计师教程》第 5 版补）：

- **`entry/`**：一进入这个状态就执行一次（发通知邮件）
- **`do/`**：待在这个状态期间持续执行（每天发提醒）
- **`exit/`**：离开这个状态时执行一次（取消提醒任务）

```
┌─────────────────────────┐
│ 待一级审批              │   ← 上格：状态名
├─────────────────────────┤
│ entry / 发通知邮件      │   ← 下格：三种内部活动，一格里按 entry→do→exit 顺序写，都可省略
│ do    / 每天发提醒      │
│ exit  / 取消提醒任务    │
└─────────────────────────┘
```

考试认这套写法：2021 上半年那道状态图题就把"**动作可以在状态内执行，也可以在状态转换时执行**"当作**正确**说法——"在状态内执行"指的正是 entry/do/exit，"在转换时执行"指的是箭头上那个动作。

**短板④：一堆状态共用同一条出边，要画 N 条一模一样的箭头。**

"待一级审批"和"待二级审批"都得支持"员工撤回"，撤回后都回"草稿"。两个状态就要画两条，将来加个"待复核"就是三条。

补丁是**组合状态**：把这几个状态圈进一个大框，给大框起个名字叫"审批中"，大框里面的叫**嵌套状态**，撤回那条出边只画在大框上，就代表框里任何一个状态都能撤回。转录本 2-10 明确说状态"包括**简单状态和组合状态**"，**简单状态**就是里面不再套别的状态的普通状态。

转录本 2-10 的配图画的正是这一对：左边 `Idle`、`Transmiting`（原图把 Transmitting 印成 `Transmiting`，照录）是两个简单状态；右边那个大框标着"组合状态"，框内的 `Connected`、`Processing`、`Cleaning Up` 标着"嵌套状态"；图上另两处标注是"转换"（那条带箭头的线）和"事件"（`ringing`、`CheckSum` 这类线上的名字）：

![培训资料原图：UML 状态图，图上标出转换、事件、组合状态、嵌套状态四处](../外部资源/转录md/images/fig_d14_s021.png)

报销系统对应过来：

```
┌─ 审批中（组合状态）───────────────────────────┐
│  ●→┌────────────┐          ┌────────────┐  │
│    │ 待一级审批  │─────────►│ 待二级审批  │  │   ← 两个嵌套状态
│    └────────────┘          └────────────┘  │
└──────────────────────────────────────────────┘
     │ 撤回 / 释放额度          ← 一条出边顶原来的两条
     ▼
   草稿
```

最后补一句转录本里一句容易被跳过、却正好是考点的话：**"状态图中转换和状态是两个独立的概念。"** 意思是转换不是状态的一部分，它是连接两个状态的那条边——所以"一个转换可以包含事件触发器、监护条件和一个状态"这种说法是**错**的——转换要连两头，源状态和目标状态**两个**都少不了，"一个状态"的转换根本画不出来。这句是练习 2 的题眼。

### 二、盯住整个流程：活动图

**短板⑤：状态图答不了"这件事该怎么办"。**

老板问的是另一个问题："报销这件事，从员工填单到财务打款，一共几步、先后怎么排？"状态图上每个方框写的是"单子**处于**什么状态"，不是"人**在做**什么"。要回答流程，节点得换一批。

换掉之后就是**活动图**。转录本 2-11 的定义要背下来，2022 下半年直接考的就是这句：活动图"是一种**特殊的状态图**，展现了**在系统内从一个活动到另一个活动的流程**"。

**活动**（也叫动作）就是流程里的一步，画成圆角矩形，名字是动词短语，比如"校验金额""打印凭证"；连接活动的带箭头实线叫**流**（控制流），表示上一步做完接着做下一步。同样用实心圆点起、圆环套实心圆点止。

**短板⑥：流程里有岔路。**

金额 5000 元以内走一级审批，超过就走二级——两条路只能走一条。补丁是**分支**：画一个菱形，出边上各写一个方括号条件（这个条件转录本叫**监护表达式**），条件互斥，只走一条；几条岔路走完再汇拢回一条，那个菱形叫**合并**。

**短板⑦：把本来能同时干的两件事，画成了假先后。**

打款前财务要"打印凭证"和"登记台账"，这两件事互不依赖，谁先谁后都行，甚至可以同时干。画成一条直线就等于强行规定了顺序，图就骗人了。

补丁是**分岔与汇合**。转录本 2-11 说："活动的分岔和汇合线是一条**水平粗线**"，教材补充这条粗线叫**同步线**，可以水平也可以垂直；**分岔是一个进入转换、两个或多个离开转换**（从这里开始并发），**汇合是两个或多个进入转换、一个离开转换**（等分支全到齐才继续）。

转录本还给了两句非常具体的判据：**"每个分岔的分支代表了可同时运行的线程数"**、**"活动图中能够并行执行的是在一个分岔粗线下的分支上的活动"**。

**分支的菱形和分岔的粗线是本课头号易混点**，两者都是"一条进、多条出"，区别只在语义：

| | 分支（菱形 ◇） | 分岔（同步线 ▬） |
|---|---|---|
| 走几条 | 互斥，**只走一条** | 并发，**每条都走** |
| 出边写什么 | 各带监护表达式 `[条件]` | 不带条件 |
| 收口的那一头 | **合并**（菱形）：哪条来了都直接过 | **汇合**（同步线）：**等全部到齐**才放行 |
| 代码里是什么 | `if / else` | 多个线程同时跑 |

**先猜第二次**。2022 下半年考的就是这一对，图的结构是：开始 → A1 → 菱形 → 上支去 A2 直接结束；下支去 A3，A3 后面接一条同步线分岔出 A4 和 A5，两者再汇合后结束。**先别往下看：A1 之后一共有几种可能的执行序列？**

答案是三种：`A2`／`A3→A4→A5`／`A3→A5→A4`。但按"走过哪些活动"归类只有**两类**：要么只走 A2，要么走 A3、A4 和 A5。所以标准答案写成"**A2 或 A3、A4 和 A5**"。两个坑各绊倒一批人：把菱形当成分岔的，会以为 A2 和 A3 都要走；把同步线当成分支的，会以为 A4、A5 只走一条。

**短板⑧：图上看不出谁负责哪一段。**

填单是员工干的，审批是主管干的，打印凭证和打款是财务干的。上面那张流程图把三个角色的活儿混在一起，出了问题都不知道找谁。

补丁是**泳道**（swimlane）：用竖线把画布分成几栏，每栏一个名字，就是一个负责人或部门；**每个活动节点、每个分支必须只属于一个泳道，而流、分岔与汇合可以跨泳道**。

（**转录本 2-11 没有收泳道**，这一段按教材第 5 版补；同样只在教材里的还有**对象流**——用虚线箭头把活动和它产出/消费的对象连起来，不在本课这条链上，认得名字即可。）报销流程带上泳道就是这样：

```
│   员工       │        主管         │            财务             │
│──────────────│─────────────────────│─────────────────────────────│
│  ● 开始      │                     │                             │
│  填写报销单   │                     │                             │
│      └───────►  校验金额            │                             │
│              │      ◇  ← 分支      │                             │
│              │ [≤5000]   [>5000]   │                             │
│              │  一级审批   二级审批  │                             │
│              │      ◇  ← 合并      │                             │
│              │      └──────────────►  ▬▬▬▬▬▬▬▬  ← 分岔（同步线）  │
│              │                     │   打印凭证 ┃ 登记台账         │
│              │                     │  ▬▬▬▬▬▬▬▬  ← 汇合           │
│              │                     │        打款                  │
│              │                     │        ◉ 结束               │
```

转录本 2-11 的配图是同一套元素的另一个例子（订单处理），八个名词全标在图上，**认图就照这张认**：

![培训资料原图：UML 活动图，标出开始、流、并发分岔、动作、分支、监护表达式、并发汇合、结束](../外部资源/转录md/images/fig_d14_s022.png)

培训资料 2-14 后的【考试真题】第 2 题考的就是这套元素：给一张活动图，问它是哪种图（答活动图），再问"（Ⅰ）表示什么"（答**合并分叉**，即并发分岔）、"（Ⅱ）表示什么"（答**监护表达式**）。那道题的原配图没有随资料转录下来，所以这里不当练习出；要记的就是上图这几个标注名。

顺带说清活动图和流程图（程序流程图）的差别，选项里常出现：最硬的一条是**活动图能表达并发**（同步线），流程图不能；另一条教材口径是活动图属面向对象的行为建模、流程图是面向过程的处理过程描述。

### 三、同一个报销系统，两张图怎么分

**先猜第三次**。下面两句业务描述，各该画哪张图？

> 甲：报销单提交后进入待审批；主管驳回则变为已驳回，员工改完可以重新提交；审批通过后打款，打款成功即结束。
> 乙：员工填单后系统校验金额，5000 元以内走一级审批、超过走二级；审批完财务打印凭证并登记台账（两件事可同时做），最后打款。

甲是**状态图**、乙是**活动图**。三条判据可以当场判，不用凭感觉：

1. **看方框里写的是什么。** 能在前面加"正处于"读通的是状态（正处于**待审批**）→ 状态图；能在前面加"正在"读通的是活动（正在**校验金额**）→ 活动图。
2. **看主语换不换人。** 状态图全图只有一个主语，就是那一个对象（这张报销单）——转录本给状态图的定义就是"描述**单个对象**在多个用例中的行为"；活动图的主语往往一路在换（员工 → 主管 → 财务），所以它才需要泳道。
3. **看并发写在哪张图上。** 出现"可同时进行""并行""几步互不依赖"，答活动图——分岔／汇合（同步线）这套东西，转录本和历年题都是挂在活动图名下讲的。（UML 的状态图理论上也有并发子状态，但考试没考过，不必纠结。）

题干信号词也很固定：出现"生命周期""状态变迁""事件触发"选状态图；出现"流程""工作流""并发""谁负责"选活动图。

八个短板收口：状态图用**状态 + 转换**补①、**事件[监护条件]/动作**补②、**entry/do/exit**补③、**组合状态**补④；活动图用**活动 + 流**补⑤、**分支/合并**补⑥、**分岔/汇合**补⑦、**泳道**补⑧。

## 考试怎么考

**考点① 给定义选图。** 2022 下半年那道题四个选项各是一张图的定义原句，只有一句是活动图的："系统内从一个活动到另一个活动的流程"。其余三句要能反认：**"系统在它的周边环境的语境中所提供的外部可见服务"说的是用例图（用例图正是对系统对外可见的那些服务建模）；"某一时刻一组对象以及它们之间的关系"说的是对象图；"对象的生命周期中某个条件或者状态"是教材给"状态"下的定义，指向状态图。**

**考点② 读活动图数执行序列。** 步骤固定三步：先找出所有菱形（只走一条）、再找出所有同步线（每条都走），最后按"分支选一、分岔全走"拼出集合。答案通常写成"X 或 Y、Z"的形式，"或"字前后就是两条互斥分支。**常见错法**：把两条互斥分支的活动都算进去，或者把并发的两个活动只算一个。

**考点③ 认活动图的元素名。** 粗线段=分岔/汇合（同步线），菱形=分支/合并，方括号里那句=监护表达式，箭头=流。**易错点是"分岔配汇合、分支配合并"这两组不能交叉**：等人到齐的是汇合，来了就走的是合并。

**考点④ 状态图叙述判断。** 错项只有三种造法：**把条件说成能触发转换**（"条件成立即使事件没发生也会迁移"）；**把转换和状态混为一谈**（"一个转换可以包含事件触发器、监护条件和一个状态"）；**主谓对调**（"状态由事件触发"——被事件触发的是**转换**，不是状态）。反过来，"活动既可以在状态内执行、也可以在转换时执行""事件触发转换发生时对象离开当前状态且 do 动作终止""`when(...)` 称为时间事件"这几句都是**对的**，别误伤。

**考点⑤ 状态图对什么建模。** 2021 上半年问"当 UML 状态图用于对系统、类或用例的动态方面建模时，通常是对什么建模"，答**反应型对象**——即行为完全由外部事件驱动、平时静静等着的那种对象（报销单就是：没人点提交它就一直躺在草稿里）。干扰项"系统的词汇"是类图、"对象快照"是对象图。

### 参考答案

1. **C、D**。(41) 四个选项分别指向用例图、对象图、活动图和状态图，题干问活动图，选转录本 2-11 的定义原句"系统内从一个活动到另一个活动的流程"。(42) A1 之后先遇菱形，互斥选一：走 A2 就直接结束；走 A3 则进入同步线，A4 与 A5 并发、必须都走完才汇合。所以完整序列只有 `A2`、`A3→A4→A5`、`A3→A5→A4` 三条，按走过的活动归类只剩两类，正是 D 的写法。A 把互斥的 A2、A3 都算上；C 的"A2、A4和A5"把互斥支的 A2 和并发支的 A4、A5 拼在一起，这条路不存在；B 给了两组，第一组"A3、A4和A5"是对的，可第二组同样是"A2、A4和A5"，一样走不出来，所以整个选项错。
2. **C**（不是培训资料印的 B）。同题另一种流传措辞把 C 写成"一个转换可以有事件触发器、监护条件和**一个**状态"，错就错在"一个"——转换是连接**两个**状态（源状态和目标状态）的那条边，只挂一个状态的转换不存在；培训资料自己在 2-10 也写着"**状态图中转换和状态是两个独立的概念**"，同样容不下 C。A、B、D 三句都对——活动确实可以写在状态内（entry/do/exit）也可以写在转换上；事件触发一条无监护条件的迁移时对象就是会离开当前状态；转换本来就由事件触发。**培训资料这一处答案有误，按 C 记。**
3. **B、D**。(1) 状态图刻画的是"被外部事件推着走"的对象，教材叫**反应型对象**；"系统的词汇"是类图的说法、"对象快照"是对象图。(2) D 主谓对调了——被事件触发的是**转换**不是状态；A、B、C 三句都是教材与考试认可的正确表述，C 那句"`when(...)` 称为时间事件"照考试口径记。
4. **①A ②B**。①盯的是电梯这**一个对象**在自己的几个状态间按事件切换，方框里能加"正处于"；②盯的是一件事怎么办完、主语从员工换到主管再换到财务，而且出现"可同时进行"——考试里画并发的就是活动图。
5. **B**。粗线段一进多出且出边无条件 = **分岔**（并发全走）；菱形多出且各带监护表达式 = **分支**（互斥选一）。C、D 把收口的那一头（汇合／合并）当成了出口。
6. **D**。监护条件只是闸门，不是发动机：必须先有事件发生，才轮到检查条件。A、B、C 正是"事件 [监护条件] / 动作"三段式的逐段解释。
7. **D**。教材口径是：每个活动节点、每个分支只能属于一个泳道，而流（转换）、分岔与汇合都可以跨泳道——流本来就是用来表示活儿从员工交到主管手上的，不跨泳道反而没法画。A、B、C 三句都对。
8. **汇合**（同步线）收的是并发：必须**等所有**汇入分支都到达才放行，带同步等待。**合并**（菱形）收的是互斥分支：几条路实际只走过一条，**到了就直接过**，不存在等待。一句话——汇合等人到齐，合并来了就走。
9. `打款失败 [重试次数<3] / 记失败日志`，画成一条从"已通过"出发又指回"已通过"的带箭头实线（这种起点终点相同的转换叫自转换），线上标这三段文字。
10. "能否**到达**"看有没有一条路径，答**能**（已驳回 → 待一级审批 → 已通过 → 已打款）；"能否**直接迁移**"看有没有那一条边，答**不能**。题干里"直接"两个字是唯一的开关。

## 速记

- 状态图管**一个对象**：方框=状态、箭头=转换、实心圆=初态、圆环套实心圆=终态；转换标注三段式 **`事件 [监护条件] / 动作`**，事件触发、条件放行、动作随行——条件自己不触发转换
- 状态框内三种内部活动：**entry/ 进入时、do/ 期间持续、exit/ 离开时**；状态分**简单状态**与**组合状态**，组合状态里面的叫嵌套状态，出边画在大框上顶里面每一个
- 转换与状态是**两个独立的概念**：说"转换包含一个状态"错；说"状态由事件触发"也错（被触发的是转换）；状态图是对**反应型对象**建模
- 活动图管**一个流程**，定义原句"系统内从一个活动到另一个活动的流程"，是一种**特殊的状态图**
- **菱形分支互斥选一（配合并），粗线段分岔并发全走（配汇合）**；粗线段=同步线，出边不带条件；一个分岔下的分支上的活动才是能并行的
- **泳道**分栏表示谁负责：活动节点与分支只能属一个泳道，流与分岔汇合可跨泳道（教材补，转录本无）
- 选图三条判据：方框加"正处于"通=状态图／加"正在"通=活动图；主语只有一个=状态图／一路换人=活动图；出现并发=活动图
- 四句定义反认：外部可见服务→用例图，某一时刻一组对象及关系→对象图，一个活动到另一个活动的流程→活动图，生命周期中某个条件或者状态→状态（指向状态图）
