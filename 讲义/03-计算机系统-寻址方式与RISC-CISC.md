# 03 · 计算机系统：寻址方式、指令系统与 RISC/CISC

> 真题：寻址方式 2021下（近5年频率待核实）、RISC/CISC 2021上/2022上/2022下/2024下｜无计算｜已讲 2026-08-05

**这一课回答**：CPU 拿到一条指令后怎么找到要操作的那个数（寻址方式），以及指令集该做多还是做少（RISC/CISC）。

## 第 1 层 · 理解

### 一句话

> 一条指令 = **操作码**（干什么）+ **地址码**（对谁干）。**寻址方式，就是"地址码里那串数字该怎么解释"的几种约定**——同样写着 `100`，可能表示"就用 100 这个数"，可能表示"去 100 号房间把东西取出来"，还可能表示"去 100 号房间拿一张纸条，纸条上写的才是真正的房间号"。

### 痛点：为什么不能只留一种寻址方式

假设全世界只有"直接寻址"（地址码里写的就是操作数地址），你马上会撞上三堵墙——每一堵墙，程序员都在代码里踩过：

- **常量也要占内存**：`x = x + 1` 里的 `1`，得先在内存某处存一个 1，再多访存一次去取它。为一个常数付一次内存往返，亏。
- **数组下标是变的，指令是死的**：`arr[i]`，`i` 每轮循环都变，可指令一旦编译出来，地址码就写死了。难道每轮循环都去**改指令本身**？（自修改代码，既危险又没法共享代码段。）
- **程序挪个位置就跑不了**：程序被加载到内存哪个位置由操作系统说了算。如果跳转指令里写的是绝对地址 `jmp 8000`，程序整体挪 100 字节，全部跳转就都错位了。

这三堵墙，正好对应下面主线里的三类解法。

**程序员的等价物（这一条能省掉一半记忆量）**：

| 寻址方式 | C 语言的样子 |
|---|---|
| 立即寻址 | `a = 100;` |
| 寄存器寻址 | `a = R1;` |
| 直接寻址 | `a = mem[100];` |
| 寄存器间接寻址 | `a = *R1;`（R1 是指针） |
| 间接寻址 | `a = mem[mem[100]];`（二级指针） |
| 变址寻址 | `a = arr[i];`（首址 + 下标） |

### 一条主线

```
一条指令 = 操作码(干什么) + 地址码(对谁干)
   ↓
地址码位数有限，而且指令一旦生成就是死的 ——
光靠"地址码里写的就是操作数地址"(直接寻址) 会撞上三堵墙：

  ① 常量也要单独占一个内存单元、还多访存一次
        → 干脆把【值本身】塞进指令里 ……………… 立即寻址（0 次访存，最快）

  ② 数组 arr[i] 的地址每轮都在变，指令却是死的
        → 让有效地址在【运行时算出来】：形式地址 + 某寄存器的内容
             寄存器里放"下标/偏移"  → 变址寻址（数组、循环）
             寄存器里放"程序装入起点" → 基址寻址（装入时重定位）
             寄存器换成 PC 本身      → 相对寻址（转移指令、程序浮动）

  ③ 地址码装不下、或真正的地址要到运行时才知道
        → 指令里只给【地址的地址】…………………… 间接寻址（2 次访存，最慢）
   ↓
再叠上一个正交的维度：这个"数/地址"是放在【内存】还是【寄存器】里？
   放寄存器 → 快得多、还省地址码位数 …… 寄存器寻址 / 寄存器间接寻址
   ↓
于是上午题几乎只考一个量：【拿到操作数要访问几次内存？】
      0 次：立即、寄存器
      1 次：直接、寄存器间接、变址、基址
      2 次：间接
   ——"谁最快""谁访存最多"问的都是这一个表
   ↓
但寻址方式给得越多、指令越花哨，译码电路就越复杂 → 引出路线之争：
   CISC：多给寻址方式、多给复杂指令，让【硬件包办】
         → 指令变长、格式多、微程序控制、难流水线
   RISC：反过来【砍】——指令少而精、定长、寻址方式少、
         只有 Load/Store 能访存，砍出来的芯片面积拿去堆通用寄存器
         → 译码简单 → 硬布线控制 → 【天生适合流水线】（接第 6 课）
```

## 第 2 层 · 考点：考试怎么问

### 考点① 寻址方式识别：一句定义 → 选名字（最高频）

**题目长相**：

- "操作数**包含在指令中**的寻址方式是（ ）"
- "指令中给出**操作数地址**的寻址方式是（ ）"
- "指令的**有效地址 = 程序计数器 PC 的内容 + 地址码中的偏移量**，这种寻址方式是（ ）"

**怎么解**：题干里必有一个"信号短语"，一一对应，不需要推理：

| 题干信号短语 | 寻址方式 |
|---|---|
| 操作数**就在指令中** / 立即数 | **立即寻址** |
| 指令中给出**操作数的地址** | **直接寻址** |
| 指令中给出的是**地址的地址** / 存放操作数地址的**内存单元**的地址 | **间接寻址** |
| 操作数在**寄存器**中 | **寄存器寻址** |
| **寄存器中存放的是操作数的地址** | **寄存器间接寻址** |
| **变址寄存器 + 形式地址**、适合**数组 / 循环** | **变址寻址** |
| **基址寄存器 + 偏移**、程序**重定位 / 多道程序装入** | **基址寻址** |
| **PC + 偏移量**、**转移指令 / 程序浮动** | **相对寻址** |

**陷阱**：

- **"立即"和"直接"最容易互换**——"操作数**是**指令的一部分"=立即；"操作数的**地址**是指令的一部分"=直接。看的是"指令里装的是**数**还是**地址**"。
- 相对寻址严格说来，PC 在取指后已自动指向**下一条**指令，所以基准是"下一条指令的地址"；软考题一般直接按"PC 的内容 + 偏移"处理，**按题干口径答即可**。

### 考点② 访存次数与速度比较

**题目长相**："下列寻址方式中，**执行速度最快**的是（ ）"、"**访问内存次数最多**的是（ ）"、"取一个操作数需要访问几次主存"。

**怎么解**：只数一件事——**从地址码出发，到拿到操作数为止，中间跨了几次内存**。

| 访存次数 | 寻址方式 | 记法 |
|---|---|---|
| **0 次** | 立即、寄存器 | 东西就在手边（指令里 / 寄存器里） |
| **1 次** | 直接、寄存器间接、变址、基址 | 地址已知或算得出，去取一趟 |
| **2 次** | **间接** | 先取地址、再取数，跑两趟 |

- **最快**：**立即寻址**（不访存，操作数随指令一起取回来了）；其次是寄存器寻址。
- **最慢 / 访存最多**：**间接寻址**（2 次）。

分步演算见 **第 3 层**（同一组数据把八种方式全跑一遍）。

**陷阱**：

- 题目问的是"**取操作数**"的访存次数，**不含取指令本身那一次**。若题干特意写明"包括取指令"，全部再加 1——**按题干口径**。
- 变址/基址虽然要"算"有效地址，但读寄存器**不算访存**，所以仍是 1 次，别误记成 2 次。

### 考点③ 变址 / 基址 / 相对 三兄弟辨析（最容易混）

**题目长相**：

- "在**数组处理 / 循环**中，最适合使用的寻址方式是（ ）"
- "为便于程序在内存中**浮动（重定位）**，应采用的寻址方式是（ ）"
- "有效地址由**变址寄存器内容与形式地址相加**得到的寻址方式是（ ）"

**怎么解**：三者形式完全一样——**有效地址 = 某个基准 + 某个偏移**，所以不能看"加法"，只能看**谁是基准、谁在变、给谁用**。按下表对号入座：

| 寻址方式 | 基准来自 | 偏移来自 | 谁在变 | 典型用途 |
|---|---|---|---|---|
| **变址寻址** | 形式地址（数组首地址） | **变址寄存器**（下标 i） | 寄存器内容（用户程序改，如 `i++`） | **数组处理、循环** |
| **基址寻址** | **基址寄存器**（程序装入的起始地址，系统设定） | 形式地址 | 基址寄存器（装入时由系统填） | **程序重定位、多道程序** |
| **相对寻址** | **PC**（当前指令位置） | 形式地址（偏移量，可正可负） | PC 随执行自动变 | **转移指令、程序整体浮动** |

**陷阱**：变址与基址被互换是最常见错法。一句话分辨——**变址是"用户在变下标"，基址是"系统在挪程序"**。

### 考点④ RISC vs CISC 特征对照（常年考点，2021上/2022上/2022下/2024下 均出现）

**题目长相**："关于 RISC 的叙述，**正确/错误**的是（ ）"、"RISC 指令系统的特点包括（ ）①指令数量少 ②寻址方式多 ③指令格式种类少 ④指令长度固定"。

**怎么解**：**不要背表格，从一句设计哲学推**——

> CISC = 让硬件用**一条复杂指令**包办一件事（如假想指令 `IMUL_ADD a,b,c,d` 一步算完 `a = b×c + d`，内部靠**微程序**翻译执行）；
> RISC = 只留基础动作，复杂功能靠**组合多条简单指令**实现：

```
LOAD R1,b   LOAD R2,c   MUL R3,R1,R2   LOAD R4,d   ADD R5,R3,R4   STORE a,R5
```

这 6 条里**只有 LOAD/STORE 碰内存**，其余全在寄存器里算——这就是"只有 Load/Store 能访存"的来源；也正因为要在寄存器里算，**通用寄存器必须多**；指令格式统一、定长 → 译码电路简单 → 能**硬布线**控制、能上**流水线**。

| 维度 | CISC 复杂指令集 | RISC 精简指令集 |
|---|---|---|
| 指令数量 | 多而全 | **少而精** |
| 指令长度 | 变长 | **定长** |
| 指令格式/寻址方式 | 种类多 | **种类少** |
| 通用寄存器 | 少 | **多** |
| 访存指令 | 大多数指令都能访存 | **只有 Load/Store** 能访存 |
| 控制方式 | **微程序**控制为主 | **硬布线**为主 |
| 流水线 | 难 | **非常适合** |

代表产品：**x86**（PC/笔记本）是 CISC 代表；**ARM**（手机、苹果 M 系列）、**RISC-V** 是 RISC 代表。

**陷阱**（错误选项几乎都是把 CISC 的特征安到 RISC 头上）：

- ✗「RISC **寻址方式丰富**」——反了，RISC 是**少**
- ✗「RISC 采用**微程序**控制」——反了，RISC 是**硬布线**
- ✗「RISC **大多数指令可访存**」——反了，只有 Load/Store
- ✗「RISC 指令**长度可变**」——反了，**定长**才好流水
- 唯一"多"的是**通用寄存器多**——记住"**只有寄存器是多的，其他全是少的**"，多选题就不会挑错。

## 第 3 层 · 完整算例：一组数据跑通全部寻址方式

**设定**（全部方式共用这一组数据，便于横向对比）：

- 内存 `[100] = 200`，内存 `[200] = 6`
- 寄存器 `R1 = 100`
- 指令的**地址码写的都是 `100`**——只有寻址方式不同

**逐条演算**：

| 寻址方式 | 「100」的含义 | 取操作数过程 | 得到 | 访存次数 |
|---|---|---|---|---|
| 立即 | 操作数本身 | 直接用 | **100** | 0 |
| 寄存器 | 寄存器号 | 读 R1 | **100** | 0 |
| 直接 | 操作数的地址 | 读内存[100] | **200** | 1 |
| 寄存器间接 | R1 内是地址 | 读内存[R1] = 读内存[100] | **200** | 1 |
| 间接 | 地址的地址 | 先读内存[100] 得 200 → 再读内存[200] | **6** | 2 |
| 变址 | 形式地址（数组首址） | 读内存[变址寄存器 Rx + 100] | 随 Rx 变 | 1 |
| 基址 | 形式地址（相对基址的偏移） | 读内存[基址寄存器 BR + 100] | 随 BR 变 | 1 |
| 相对 | 相对 PC 的偏移 | 有效地址 = PC + 100 | 见下 | 见下 |

**三条容易跳步的地方，逐步写清**：

1. **直接 vs 寄存器间接为什么得数相同**：直接寻址读的是"内存[地址码 100]"；寄存器间接读的是"内存[R1]"，而 R1 恰好 = 100，所以读的是同一个单元 → 都得 **200**。**得数相同不代表方式相同**：前者地址来自指令，后者地址来自寄存器。
2. **间接寻址的两趟**：第 1 趟按地址码 100 去读，读回来的 **200 不是操作数，是地址**；第 2 趟再按 200 去读，才拿到操作数 **6**。**看到"读回来的还是个地址"就说明还要再跑一趟**——这就是 2 次访存的由来。
3. **相对寻址那一行为什么写"见下"**：相对寻址主要用在**转移指令**上，此时 `PC + 100` 算出来的有效地址**就是跳转目标**，CPU 直接把它送进 PC，**并不需要再去取一个操作数**，所以不产生"取操作数"的访存。若相对寻址被用来**取数**（而非跳转），则和直接寻址一样是 **1 次**访存。

**验算习惯**：算完对一遍"访存次数是不是等于**从地址码到操作数中间跨过的内存次数**"——立即/寄存器跨 0 次、直接/寄存器间接跨 1 次、间接跨 2 次。次数对不上，说明中间少走或多走了一跳。

## 第 4 层 · 速记

> **指令 = 操作码 + 地址码（操作数）**
> **立即**：操作数就在指令里，**最快、不访存**
> **直接**：指令给操作数的**地址**，访存 **1** 次
> **间接**：指令给「地址的地址」，访存 **2** 次
> **寄存器**：操作数在寄存器，**不访存**；**寄存器间接**：寄存器里是地址，访存 **1** 次
> **变址**：有效地址 = **变址寄存器 + 形式地址**，适合**数组/循环**
> **相对**：有效地址 = **PC + 偏移量**，适合**转移指令**、程序浮动
> **基址**：**基址寄存器 + 偏移**，用于程序**重定位**
> 访存次数三档：**0（立即、寄存器）／1（直接、寄存器间接、变址、基址）／2（间接）**
> 三兄弟：**变址看用户改下标，基址看系统挪程序，相对看 PC**
> RISC 记法：**R 当 Reduce（砍）**——指令数量、指令长度种类、寻址方式全砍掉；砍出来的面积拿去堆**寄存器**；简单齐整所以能**硬布线**、能上**流水线**、**只有 Load/Store 访存**
> RISC 只有一样是"多"的：**通用寄存器多**；CISC 与之相反：**指令多而复杂、变长、微程序控制**
> 陷阱句式（全错，都是 CISC 的特征）：「RISC 寻址方式丰富」「RISC 采用微程序控制」「RISC 大多数指令可访存」

1. 【模拟】操作数直接包含在指令中的寻址方式是（ ）
   A. 直接寻址　B. 立即寻址　C. 寄存器寻址　D. 间接寻址
2. 【模拟】指令的有效地址 = 程序计数器 PC 的内容 + 地址码中的偏移量，这种寻址方式是（ ）
   A. 变址寻址　B. 基址寻址　C. 相对寻址　D. 间接寻址
3. 【真题·年份待核实】（信管网题库在库原题）RISC 指令系统的特点包括（ ）
   ①指令数量少　②寻址方式多　③指令格式种类少　④指令长度固定
   A. ①②③　B. ①③④　C. ②③④　D. ①②④

### 参考答案

1. **B**（立即寻址）——操作数就在指令里，不用查内存。干扰项 A 直接寻址：指令里给的是**地址**不是数。
2. **C**（相对寻址）——有效地址 = **PC** + 偏移量，公式直接对应。若基准换成变址寄存器就是变址寻址、换成基址寄存器就是基址寻址（见考点③三兄弟表）。
3. **B**（①③④）——②「寻址方式多」是 **CISC** 的特征，RISC 恰好相反，是"**少**"。套用速记："RISC 只有通用寄存器是多的"，②立刻可以排除。
