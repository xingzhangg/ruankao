# 03 · 计算机系统：寻址方式与 RISC/CISC

## 定位

一条指令里那几位地址码该怎么解释——每种解释就是一种寻址方式，共八种，要能一步步算出有效地址、数出访存次数；整套指令集做厚还是做薄——CISC 与 RISC 两条路线。末尾「RISC 指令定长、译码简单」是 06 流水线成立的前提；Flynn 分类与主线无关，认名即可。

---

## 一、指令的组成与两类寻址（概念）

**原话｜** 一条指令由**操作码和操作数**两部分组成，操作码**决定要完成的操作**，操作数指**参加运算的数据及其所在的单元地址**；二者都用二进制表示，分别叫**操作码**和**地址码**，整条指令以二进制编码形式存放在存储器里。

执行三步：**取指令 → 分析指令 → 执行指令**。

| 部件 | 在这三步里干什么 |
|---|---|
| **程序计数器 PC** | 存下一条指令的内存地址，送上**地址总线**（CPU 告诉内存「访问哪一格」的那组线） |
| **指令寄存器 IR** | 存取回来的这条指令本身 |
| **指令译码器 ID** | 分析操作码，弄清是加法还是取数 |
| 执行 | 取出指令所需的**源操作数**（这条指令要拿来算的那个数）并运算 |

**易混对 指令寻址 vs 操作数寻址**
- 判据｜找的是「下一条**指令**从哪来」→ 指令寻址，只有两种；找的是「这条指令要算的那个**数**从哪来」→ 操作数寻址，即第二节的八种。
- 例子｜**顺序寻址方式**：一条接一条执行，PC 自动 +1；**跳跃寻址方式**：下一条指令的地址**不由程序计数器给出，而由本条指令直接给出**，跳过去后 PC 也要相应改掉，才能从新位置接着顺序执行。二者都属指令寻址；立即、直接、相对等都属操作数寻址。

---

## 二、八种操作数寻址方式（计算）

八种方式回答同一个问题：地址码那几位**到底代表什么**。前一种的短板逼出后一种。

**贯穿例子**：机器字长 16 位，指令 16 位＝前 **6 位操作码** + 后 **10 位地址码**；主存**按字编址**（一个地址对应一个 16 位字），**64K 字**＝2¹⁶＝65536 个单元。设地址码＝**200**，`[200] = 5000`，`[5000] = 88`，`R1 = 5000`，`[203] = 17`。**寄存器**是 CPU 内部最快、数量极少的小格子，不挑用途的那十几个叫**通用寄存器**。

**形式地址**＝指令里写着的那个数（200）；**有效地址 EA**＝CPU 最终拿去访问内存的地址。

1. **立即寻址**：原话｜「指令的地址码字段指出的不是地址，而是操作数本身」。操作数＝**200**（如 C 语言 `a = a + 200` 里的 200），随指令一起取回，**0 次访存**。
   短板：① 刻在指令里，运行时改不了，只能放常量；② 10 位只装得下 0～1023（2¹⁰＝1024），大数塞不进。
2. **直接寻址**：地址字段**直接指出操作数在主存中的地址**。EA＝200，读 `[200]` → 操作数＝**5000**，**1 次访存**。存在内存里可改、16 位装得下大数，①② 解除。
   新短板：③ **够不着**——10 位只指到 1024 个单元，65536 ÷ 1024＝64，只够得着 1/64；④ **算不出**——`arr[i]` 的地址运行时才知道，改指令本身＝自修改代码，危险，且代码段没法设只读、没法多进程共享；⑤ **慢**——每次都跑主存；⑥ **挪不得**——程序装到哪编译时不知道，写死 `jmp 800`，程序整体挪 100 个单元就全错位。
3. **间接寻址**（解 ③）：原话｜「指令地址码字段所指向的存储单元中存储的是操作数的地址」。
   ```
   第 1 趟：读 [200] → 5000（这是地址，不是操作数）
   第 2 趟：读 [5000] → 88（这才是操作数）
   ```
   内存单元 16 位，能装 0～65535 任一地址，③ 解除；代价 **2 次访存**，八种里最慢。
   同一格 `[200]` 里的 5000：直接寻址当「数」（操作数 5000），间接寻址当「地址」（再跑一趟得 88）。判据：**读回来的东西还要不要再当地址用一次**。
4. **寄存器间接寻址**（③ 的更划算解法）：地址码写寄存器编号 R1，R1 里装的是地址。EA＝R1＝5000，读 `[5000]` → **88**，**1 次访存**（读寄存器在 CPU 内部，不算访存）；R1 满字长，同样够得着全部 64K。
5. **寄存器寻址**（解 ⑤）：原话｜「指令中的地址码是寄存器的编号」，操作数就在寄存器里。读 R1 → **5000**，**0 次访存**。16 个通用寄存器编号只要 4 位（2⁴＝16），比 10 位地址码**省 6 位**，指令还能更短。
6. **变址寻址**（解 ④）：原话｜「将**变址寄存器**的内容加上指令中的形式地址而形成操作数的有效地址」。变址寄存器（IX）放下标：
   ```
   EA = 形式地址(数组首址 200) + IX(下标 i)
   i = 0 → 200    i = 1 → 201    i = 3 → 203    i = 5 → 205   …   i = 9 → 209
   ```
   `i = 3` 时读 `[203]` → **17**。10 轮跑的是同一条指令、一字未改，只改 IX；**1 次访存**（读寄存器、做加法在 CPU 内部）。
7. **基址寻址**（解 ⑥：程序整体装在哪不确定）：原话｜「将**基址寄存器**的内容加上指令中的形式地址而形成操作数的有效地址，其优点是**可以扩大寻址能力**」。基址寄存器 BR 装**程序装入内存的起点**，由操作系统装入时填一次：
   ```
   EA = BR(装入起点 4000) + 形式地址(段内偏移 200) = 4200
   ```
   程序挪走只改 BR，指令一字不动＝**重定位**；BR 满 16 位能指到 64K 任一处，形式地址只管段内偏移＝扩大寻址能力。**1 次访存**。
8. **相对寻址**（解 ⑥：转移指令要能跟代码一起搬家）：
   ```
   EA = PC 的内容 + 形式地址（偏移量，可正可负）
   转移指令在 100 号单元，偏移 +200，取指后 PC 已 +1 = 101（一条指令占 1 字）
   按 PC 当前内容：101 + 200 = 301     按本条指令地址：100 + 200 = 300（两种口径差 1）
   偏移 −60：101 − 60 = 41（往回跳，循环就这么实现）
   ```
   常用口径直接写「有效地址 = PC 的内容 + 偏移量」，照此直接相加，不自行补 1。整段代码搬到哪，「往后跳 200」都对。用于转移指令时不取操作数，不参与访存排队。

《软件设计师教程》第 5 版列全八种；转录本 2-2 只列了立即、直接、间接、寄存器、基址、变址六种，漏了寄存器间接和相对。

### 总账

| 方式 | 解决的短板 | 地址码 200 的含义 | EA 怎么来 | 取操作数访存 | 本例得到 |
|---|---|---|---|---|---|
| **立即** | —（起点） | 操作数本身 | 不需要 | **0** | 200 |
| **直接** | ① 改不了 ② 装不下 | 操作数的地址 | EA = 200 | 1 | 5000 |
| **间接** | ③ 够不着 64K | 地址的地址 | EA = [200] = 5000 | **2** | 88 |
| **寄存器间接** | ③（更划算） | 寄存器号，寄存器里是地址 | EA = R1 = 5000 | 1 | 88 |
| **寄存器** | ⑤ 慢 | 寄存器号，寄存器里是数 | 不需要 | **0** | 5000 |
| **变址** | ④ 运行时才知道 | 形式地址（数组首址） | EA = 200 + IX | 1 | [203] = 17 |
| **基址** | ⑥ 程序位置不固定 | 形式地址（段内偏移） | EA = BR + 200 | 1 | [4200] |
| **相对** | ⑥ 转移指令要能搬家 | 偏移量（可正可负） | EA = PC + 200 | 跳转时不取数 | 目标 301 |

**访存次数**＝从地址码出发到摸到操作数，中间跨过几次内存；**不含取指令本身**那一次，若要求算上，全部 +1（间接就成 3 次）。读寄存器不算访存。

**速度**：立即 > 寄存器 > 直接 > 间接。同为 0 次访存时再比一层：立即的操作数随指令一起取回，取指结束就在手上；寄存器寻址还要按编号去寄存器读一次。

**易混对 变址 vs 基址**（都是「寄存器 + 形式地址」，看谁是基准、谁在变、给谁用）
- 判据｜用户程序在改下标（基准＝数组首址，在形式地址里；寄存器里是下标）→ 变址；系统在挪程序（基准＝程序起点，在寄存器里；形式地址是段内偏移）→ 基址。两者基准与偏移位置正好互换。
- 例子｜循环访问 `arr[i]`、指令不改只改寄存器 → 变址；程序被装入主存任意位置都能正确运行 → 基址。

**易混对 相对寻址 vs 跳跃寻址**
- 判据｜相对寻址回答「地址码怎么解释」（操作数寻址一层，基准＝PC）；跳跃寻址回答「下一条指令从哪来」（指令寻址一层）。
- 例子｜转移指令用相对寻址算跳转目标，是跳跃寻址最常见的一种实现，但不是唯一一种。

## 三、CISC 与 RISC（概念）

同一件活 `a = b × c + d`：

```
CISC：MAC  a, b, c, d        ← 一条指令，硬件内部把乘、加、访存全干完

RISC：LOAD  R1, b            ← 把 b 从内存搬进寄存器
      LOAD  R2, c
      MUL   R3, R1, R2       ← 全在寄存器里算，不碰内存
      LOAD  R4, d
      ADD   R5, R3, R4
      STORE a, R5            ← 结果写回内存
```

6 条对 1 条。CISC（复杂指令系统计算机）把常用组合做成一条指令；RISC（精简指令系统计算机）只给基础动作，复杂功能靠简单指令组合。

| 维度 | CISC | RISC |
|---|---|---|
| 指令数量 / 功能 | 多、复杂、功能强 | **少**，基本功能指令；只选**使用频率较高**的，各条使用频率接近 |
| 使用频率 | 差别极大，大多数复杂指令编译器根本不生成 | 接近 |
| 指令长度 / 格式 | **变长**（x86 为 1～15 字节，不译完不知下一条从哪开始），格式多 | **定长**，格式种类少 |
| 寻址方式 | **多**（译码要分岔、指令难定长） | **少** |
| 每条指令时钟周期 | 多 | **大部分为单周期**（时钟周期＝CPU 打一拍的时间，一拍做完） |
| 访存 | — | 运算**只操作寄存器**，**只有 Load/Store 能访存**（对存储器操作进行限制，使控制简单化） |
| 通用寄存器 | 少 | **大量**（RISC 特性里唯一「多」的一项，砍指令省下的芯片面积拿来堆它） |
| 控制器 | **微程序控制**：复杂指令再译成一串微指令，存在 CPU 内一小块 ROM（出厂写死、只读）里逐条查表执行，多绕一层就慢一层 | **硬布线逻辑控制**＝组合逻辑控制器：组合逻辑电路直接产生控制信号，不查微码表，快 |
| 流水线 | 也用 | 也用，且**天生更适合**（定长、耗时接近；怎么切段算时间见 06） |
| 程序 / 编译 | 程序短（七十年代内存贵）；编译器好写（一句高级语言对一条指令）；**兼容性强**（老程序一直能跑） | 同样的事指令更多、程序体积大；靠**优化编译，有效支持高级语言** |
| 研制 | 硬件复杂，**研制周期长** | — |

**易混对 RISC「精简」精简了什么**
- 判据｜RISC 各项特征都是「少 / 定长 / 简单」，唯一的「多」是通用寄存器；看到 RISC 配「寻址方式多、指令长度可变、指令功能强、微程序控制、通用寄存器少」都是把 CISC 特征安错了边。
- 例子｜「指令数量少、指令格式种类少、指令长度固定」都是 RISC；「寻址方式多」是 CISC——寻址方式一多，同一操作码后的几位要按多种规矩解释，译码分岔、指令难以定长，正是 RISC 头一个砍掉的东西。

**易混对 两者都用流水线**
- 判据｜流水线不是二者的分界，只是 RISC 更适合。
- 例子｜「RISC 和 CISC 都采用流水线技术」成立；「RISC 不采用流水线，CISC 采用」不成立。

现实中两条路线已互相借用：x86 对外是 CISC 指令集，内部把复杂指令拆成一串类 RISC 微操作再上流水线。这里讲的是两条路线各自的**原始主张**。

整课两半是同一动作的两个方向：前半做加法，地址码一种解释不够，加到八种；后半做减法，解释越多译码越分岔、指令越难做齐，CISC 继续加，RISC 砍回去。

## 四、体系结构分类（概念）

**按处理机数量**：**单处理系统**（一个处理单元和其他设备集成）｜**并行处理系统**（两个以上处理机互联）｜**分布式处理系统**（物理上远距离且松耦合的多计算机系统）。

**Flynn 分类法**按**指令流**和**数据流**分。指令流由**控制部分**处理，一个控制部分一条指令流；数据流由**处理器**处理，一个处理器一条数据流；**主存模块只管存**，指令流、数据流有一样是「多」，主存模块就是多个。

| 类型 | 控制部分 | 处理器 | 主存模块 | 关键特性与代表 |
|---|---|---|---|---|
| **SISD** 单指令流单数据流 | 一个 | 一个 | 一个 | 单处理器系统 |
| **SIMD** 单指令流多数据流 | 一个 | 多个 | 多个 | 各处理器以异步的形式执行同一条指令；并行处理机、**阵列处理机**、超级向量处理机 |
| **MISD** 多指令流单数据流 | 多个 | 一个 | 多个 | 被证明不可能，至少是不实际；目前没有，有文献称流水线计算机为此类 |
| **MIMD** 多指令流多数据流 | 多个 | 多个 | 多个 | 能实现作业、任务、指令等各级全面并行；多处理机系统、多计算机 |

**MISD 为什么不可能**：计算机**由指令来控制数据的传输**，一条指令可控制一条或多条数据流，但**一条数据流不能被多条指令控制**，否则冲突出错。

## 速记

- 指令＝**操作码**（干什么）+ **地址码**（对谁干）；执行三步 **取指令 → 分析指令 → 执行指令**
- **指令**寻址只有两种：**顺序**（PC 自动 +1）／**跳跃**（下一条地址由本条指令给出）；八种全是**操作数**寻址
- 立即＝操作数在指令里｜直接＝指令给**地址**｜间接＝**地址的地址**｜寄存器＝操作数在寄存器｜寄存器间接＝**地址**在寄存器
- 三个加法只差基准：**变址寄存器 + 形式地址**（数组下标）｜**基址寄存器 + 形式地址**（重定位、扩大寻址能力）｜**PC + 偏移量**（相对，转移指令）
- 访存（**不含取指令**）：0 次＝立即、寄存器；1 次＝直接、寄存器间接、变址、基址；2 次＝间接。速度 **立即 > 寄存器 > 直接 > 间接**
- RISC＝砍：指令少、频率接近、**定长**、多单周期、寻址方式少、**只 Load/Store 访存**、**硬布线（组合逻辑）控制**、更适合流水线、靠优化编译；**只有通用寄存器是多的**。CISC 反之：指令多而复杂、**变长**、寻址方式多、**微程序控制**、兼容性强、研制周期长；两者**都用流水线**
- Flynn 看控制部分与处理器个数：SISD 一一｜**SIMD 一控多处理器**（阵列处理机）｜MISD 多控一处理器（**不可能**）｜MIMD 全多（多处理机）
