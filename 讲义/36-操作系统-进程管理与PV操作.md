## 一、操作系统概述（概念）

**原话｜** 操作系统能有效地组织和管理系统中的各种软/硬件资源，合理地组织计算机系统工作流程，控制程序的执行，并向用户提供一个良好的工作环境和友好的接口。**两个作用**：通过资源管理提高系统效率（对机器）；改善人机界面，给用户友好的工作环境（对人）。

| 四个特征 | 含义 |
|---|---|
| **并发性** | 宏观同时、微观轮流（单窗口任一瞬间只有一人） |
| **共享性** | 资源被多个进程共用 |
| **虚拟性** | 一个物理实体变成多个逻辑实体：一个 CPU → 多个虚拟处理机，物理内存 → 更大的虚存 |
| **不确定性** | 事件发生次序事先无法确定，但条件相同时结果应当相同 |

| 五大功能 | 管什么 | 包括 |
|---|---|---|
| **进程管理** | 处理机的**时间** | 进程控制、同步、通信、调度 |
| **存储管理** | 主存的**空间** | 分配回收、存储保护、地址映射、主存扩充 |
| **文件管理** | **信息** | 存储空间管理、目录管理、读写管理、存取控制 |
| **设备管理** | **硬件** | I/O 设备的分配、启动、完成、回收 |
| **作业管理** | **人机** | 任务与界面管理、人机交互、图形界面、语音控制、虚拟现实 |

| 六类系统 | 区分特征 |
|---|---|
| **批处理** | 分单道、多道；多道使主机与外设可并行 |
| **分时** | 一台机连多个终端，CPU 时间切成很短的时间片轮流为各终端服务 |
| **实时** | 对外来信息足够快地响应、在被控对象允许的时间内做出反应；**对交互能力要求不高，但要求可靠性有保障** |
| **网络操作系统** | 让联网计算机方便有效地共享网络资源；集中、客户端/服务器、对等三种模式 |
| **分布式** | 计算机**无主次之分**，任意两台可通信交换信息 |
| **微机操作系统** | Windows、Mac OS、Linux |

**易混对① 并发 vs 并行**
- 判据｜同一瞬间是否真有多个在执行：只有一个、轮流推进 → 并发；真有多个 → 并行。
- 例子｜一个打饭窗口轮流招呼几个学生 → 并发；开两个窗口同时打饭 → 并行。

**嵌入式操作系统**五特点：**微型化**（占用资源和代码量少）、**可定制**（能跑在不同微处理器平台、可按硬件裁剪配置）、**实时性**（用于过程控制、数据采集、传输通信等要迅速响应的场合）、**可靠性**（关键领域还要容错和防故障）、**易移植性**（靠硬件抽象层和板级支撑包）。**初始化**自底向上、从硬件到软件：**片级 → 板级 → 系统**。

## 二、进程与状态转换（概念）

| 概念 | 要点 |
|---|---|
| **程序** | 静态指令序列（菜谱） |
| **进程** | **程序的一次执行过程**，动态，有创建、运行、消亡；一个程序可对应多个进程 |
| **PCB**（进程控制块） | **进程的唯一标志**，记状态与所占资源 |
| 进程组成 | **PCB + 程序**（做什么）**+ 数据**（执行所需数据） |

三态判据：**把 CPU 给他，他能不能马上跑？**

| 状态 | 含义 |
|---|---|
| **运行** | 正占 CPU，单 CPU 同一时刻**最多 1 个** |
| **就绪** | 万事俱备，只欠 CPU |
| **阻塞**（等待） | 在等某事件，给 CPU 也跑不了 |

```
    ┌────┐ ──被调度程序选中（分派）─▶ ┌────┐
    │就绪│ ◀─时间片到 / 被高优先级抢占─ │运行│
    └────┘                          └────┘
       ▲                               │
  事件发生了（I/O 完成、别人 V 了）  等待某事件（等 I/O、P 申请不到）
       │        ┌────┐                 │
       └─────── │阻塞│ ◀───────────────┘
                └────┘
```

**不存在的两条箭头**：**就绪 → 阻塞**（没在运行，就没机会发起等待，只有运行中的进程能把自己变成阻塞）；**阻塞 → 运行**（等的事件到了只能回就绪队列）。所以别的进程释放了某资源，等它的进程只能变就绪，不会直接变运行。

**易混对② 运行→就绪 vs 运行→阻塞**
- 判据｜是 CPU 被收走（外因、被动，本人随时能跑）→ 就绪；是自己要等一件事（自因、主动，给 CPU 也没用）→ 阻塞。
- 例子｜时间片用完、被高优先级抢占 → 就绪；发起磁盘 I/O、执行 P 时 S<0 → 阻塞。

**五态**：三态外加**新建**（正在创建、未进就绪队列）和**终止**（执行完或被撤销、等待回收）；新建 → 就绪 → 运行 → 终止，运行与阻塞之间两条不变。

## 三、互斥与信号量

### 为什么要信号量（概念）

黑板上「红烧肉剩 1 份」，卖一份要三步：读 → 减 1 → 写回，中间可被时间片打断：

```
时刻  甲             乙             黑板
 1   读到 1                          1
 2                 读到 1            1
 3   算 1−1=0                        1
 4   写回 0，卖给甲                    0
 5                 算 1−1=0          0
 6                 写回 0，卖给乙      0
```

一份卖了两次。根子不在减法，在这三步之间不该被别人插进来。

| 术语 | 是什么 |
|---|---|
| **临界资源** | 各进程之间必须以**互斥方式**访问的资源（共享变量、打印机、磁带机） |
| **临界区** | 进程中**对临界资源实施操作的那一段程序**——是代码，不是资源 |
| **互斥** | 某资源**同一时间内只能由一个任务单独使用**，用前加锁、用完解锁（打印机） |
| **同步** | 多个任务**可以并发执行，只是速度有差异**，某些情况下停下来等一等，**不存在资源独占问题**（培训资料：自行车和汽车各走各的，某些路口互相等一下） |
| **原子操作／原语** | 一旦开始就不会被中途打断的操作 |

挂 `busy` 牌子不够：「看牌 + 翻牌」是两步，仍会两人同时进；即使合成原子操作，还剩两个缺口——没抢到的人原地反复看牌（**忙等**）浪费 CPU，应当进阻塞态睡下、资源来了再唤醒；牌子只有两态，表达不了「资源还剩几份」。所以需要一个**能计数、能让进程阻塞、能唤醒**的原子设施：

**信号量（semaphore）**：一个整数变量 S，**只能**被原子操作（原语）P、V 访问。P = Passeren（申请），V = Vrijgeven（释放）；Java 的 `Semaphore.acquire()/release()` 即其工程实现。

- **P(S)**：S = S − 1。若 **S ≥ 0**，继续执行；若 **S < 0**，本进程置为阻塞态，插入 S 的阻塞队列。
- **V(S)**：S = S + 1。若 **S > 0**，继续执行；若 **S ≤ 0**，从阻塞队列**唤醒一个**进程放入就绪队列，自己继续执行。

### S 的取值推演（计算）

2 台微波炉，S 初值 2；P1–P4 依次 P，然后 P1、P2 各 V 一次：

| 动作 | S | 判断 → 结果 |
|---|---|---|
| 初始 | **2** | 2 台空着 |
| P1 P(S) | 2→**1** | 1 ≥ 0 → 拿到 |
| P2 P(S) | 1→**0** | 0 ≥ 0 → 拿到（恰好用完） |
| P3 P(S) | 0→**−1** | < 0 → 阻塞 |
| P4 P(S) | −1→**−2** | < 0 → 阻塞 |
| P1 V(S) | −2→**−1** | ≤ 0 → 唤醒 P3 |
| P2 V(S) | −1→**0** | ≤ 0 → 唤醒 P4；此后无人等待 |

从表中读出：
1. **S > 0**：还有 S 个资源可用。
2. **S = 0**：恰好用完，无人等待。
3. **S < 0**：**|S| 就是阻塞队列中的进程数**。
4. 自检式：`S = 初值 − P 次数 + V 次数`，本例 2 − 4 + 2 = 0。
5. **P 判 S < 0，V 判 S ≤ 0**：V 后 S = 0 说明是从 −1 加上来的，队里确实有人，仍要唤醒。

变形：S 初值 1，三个进程依次 P（无 V）：

```
P①：1→0   0 ≥ 0，拿到
P②：0→−1  阻塞
P③：−1→−2 阻塞      → S = −2，阻塞 2 个（不是 3 个）
```

取值范围：n 个进程共享 m 个资源，S 最大 m（初值），最小 m − n（n 个都执行过 P），即 m, m−1, …, 0, …, −(n−m)。

**信号量两类，区别只在初值**：**互斥信号量**初值恒为 **1**；**同步信号量**初值 = **共享资源数**（微波炉例为 2）。

## 四、生产者-消费者（计算）

后厨（生产者）做一份放进保温台一个空格，学生（消费者）取走一份，保温台共 **n 格**。三件事各对应一个信号量：满了后厨等、空了学生等、同一时刻只能一人动保温台。

| 信号量 | 初值 | 管什么 | 谁 P / 谁 V |
|---|---|---|---|
| **S0（mutex）** | **1** | 保温台独占（互斥信号量） | 双方都是动手前 P、离手后 V |
| **S1（empty）** | **n** | 空格数（同步信号量） | 生产者放前 P；消费者取后 V |
| **S2（full）** | **0** | 产品数（同步信号量） | 消费者取前 P；生产者放后 V |

培训资料写 S0/S1/S2，教材写 mutex/empty/full，是同一组。Java 的 `BlockingQueue`（`put()` 满则阻塞、`take()` 空则阻塞、内部线程安全）就是这三个信号量的封装。

```
生产者：                    消费者：
while(true){              while(true){
  生产一份;                   P(S2);  // P(full)
  P(S1);  // P(empty)         P(S0);  // P(mutex)
  P(S0);  // P(mutex)         取出一份;
  放入缓冲区;                  V(S0);  // V(mutex)
  V(S0);  // V(mutex)         V(S1);  // V(empty)
  V(S2);  // V(full)          消费;
}                         }
```

两条规则：
1. **方向**：消耗什么就 P 什么，产出什么就 V 什么。生产者消耗空格、产出产品 → `P(empty)`、`V(full)`；消费者反之 → `P(full)`、`V(empty)`。
2. **顺序**：**先 P 资源信号量（empty/full），后 P 互斥信号量（mutex）**；出来先 `V(mutex)` 再 V 资源信号量。

**顺序反了的推演**（n=3，保温台已满：empty=0，full=3，mutex=1；生产者先 P(mutex) 后 P(empty)）：

```
生产者 P(mutex)：mutex 1→0   ≥0 通过 —— 拿到锁
生产者 P(empty)：empty 0→−1  <0 阻塞 —— 抱着锁睡着
消费者 P(full) ：full  3→2   ≥0 通过
消费者 P(mutex)：mutex 0→−1  <0 阻塞 —— 锁在生产者手里
```

生产者等 `V(empty)`，消费者等 `V(mutex)`，互相等待 → **死锁**。正确顺序下同样满：生产者 `P(empty)` 0→−1 阻塞但手里没锁；消费者 `P(full)` 3→2、`P(mutex)` 1→0 通过，取走后 `V(empty)` 唤醒生产者。

口诀：**先申请资源，后申请互斥**。两个 V 的先后不会引起死锁（V 从不阻塞），标准写法仍先 V(mutex)。培训资料转录件第 4-3 节的流程表把 `P(S0)` 写在 `P(S1)`／`P(S2)` 前面，正是上面会死锁的错序。

## 五、前趋图与进程资源图

### 前趋图填 PV（计算）

**前趋图**：有向无环图，表示**哪些任务可以并行、哪些有先后**；A → B 读作「A 做完 B 才能开始」。例：洗菜、切配、熬汤三件可同时做，全完成才能炒菜，炒完才能开档。

把「互斥」换成「先后」，PV 照用：
1. **每条边一个信号量，初值 0**（0 = 前趋还没做完）。
2. 前趋任务**结束时** V 该边信号量（通知完成）。
3. 后继任务**开始前** P 该边信号量（未完成就阻塞）。

算例：A 先做；B、C 都等 A；D 等 B 和 C。

```
  A     4 条边 → 4 个信号量、初值全 0：S1(A→B) S2(A→C) S3(B→D) S4(C→D)
 ↙ ↘    A：执行A; V(S1); V(S2);   // 0 入边→不 P；2 出边→V 两次
B   C   B：P(S1); 执行B; V(S3);   // 1 入 1 出
 ↘ ↙   C：P(S2); 执行C; V(S4);   // 1 入 1 出
  D     D：P(S3); P(S4); 执行D;   // 2 入边→P 两次；0 出边→不 V
```

验算：4 条边 ↔ 4 个 V（A 二、B 一、C 一）和 4 个 P（B 一、C 一、D 二）；逐个任务核对**入边数 = 开头 P 数，出边数 = 结尾 V 数**：A(0/2)、B(1/1)、C(1/1)、D(2/0)。

### 进程资源图读图（计算）

**进程资源图**表示**进程和资源之间的分配与请求关系**，是 37 判死锁的图示法，本课只到读图。

| 图元 | 含义 |
|---|---|
| 圆圈 P | 进程 |
| 方框 R，内画几个圆球 | 资源，圆球数 = 资源实例数 |
| **R → P** | R 已分配一个实例给 P |
| **P → R** | P 还在请求一个 R |

判据：看进程请求的那类资源还有没有剩。

算例：R1 有 2 个实例、R2 有 3 个实例；边 R1→P1、R1→P3、R2→P2、R2→P3（已分配），P2→R1、P1→R2（请求）。
1. R1 共 2，分给 P1、P3 → 剩 **0**；R2 共 3，分给 P2、P3 → 剩 **1**。
2. **P2** 请求 R1，R1 不剩 → **阻塞节点**（所请求的资源已全部分配完毕，无法获取，进程被阻塞）。
3. **P1** 请求 R2，还剩 1 → **非阻塞节点**（所请求的资源还有剩余，可分配给它继续运行）。
4. **P3** 无请求边 → 非阻塞节点。

**原话｜当一个进程资源图中所有进程都是阻塞节点时，即陷入死锁状态。** 本图有非阻塞节点，不死锁。用「化简」正式判定见 37。

## 六、进程调度

### 调度方式、三级调度与算法（概念）

| 调度方式 | 高优先级进程来了 |
|---|---|
| **可剥夺（抢占式）** | 强行把 CPU 从运行进程手里收走 |
| **不可剥夺（非抢占式）** | 等当前进程自己释放 CPU |

| 三级调度 | 别名 | 决定 |
|---|---|---|
| **高级调度** | 长调度／作业调度／接纳调度 | **输入池里哪个后备作业调入主系统**（变成一组就绪进程）；一个作业只经历一次 |
| **中级调度** | 中程调度／对换调度 | **交换区里哪个就绪进程调入内存** |
| **低级调度** | 短程调度／进程调度 | **内存里哪个就绪进程占用 CPU**；**最活跃、最重要**，「进程调度算法」即指它 |

| 算法 | 怎么挑 | 强／弱 |
|---|---|---|
| **FCFS 先来先服务** | 按到达顺序，非抢占 | 最简单公平，用于宏观调度／**有利于长作业和 CPU 繁忙型**，短作业干等 |
| **SJF 短作业优先** | 估计运行时间最短的先上 | **平均周转时间最短**／长作业可能**饥饿**（一直等不到资源）；需预知运行时间 |
| **时间片轮转** | 轮流用大小相同的时间片 | 公平、响应及时，**适合分时交互**，用于微观调度／片**过大退化为 FCFS**，**过小则上下文切换**（保存再恢复现场）**开销大** |
| **优先级调度** | 优先级高的先上，分抢占与非抢占 | 能表达紧急程度／静态优先级使低优先级**饥饿**，动态优先级（等越久越升）缓解 |
| **多级反馈队列** | 多个就绪队列，优先级与时间片各不相同；新进程进队列 1 末尾按 FCFS，时间片用完没做完降到队列 2 末尾，依此类推 | 轮转 + 优先级结合，**兼顾长短作业与响应时间**／实现最复杂 |

场景对应：交互／分时／响应时间 → 时间片轮转；平均周转最短 → SJF；公平简单 → FCFS；紧急任务 → 优先级。

### 周转时间（计算）

- **周转时间 = 完成时间 − 到达（提交）时间**，含排队时间。
- **带权周转时间 = 周转时间 ÷ 服务时间**（服务时间＝真正占 CPU 的时间），恒 **≥ 1**，等于 1 表示没等。

算例：到达／服务 P1(0/3)、P2(1/6)、P3(2/2)、P4(3/1)。

**FCFS**：`[P1 0→3] [P2 3→9] [P3 9→11] [P4 11→12]`

| | P1 | P2 | P3 | P4 | 平均 |
|---|---|---|---|---|---|
| 完成 | 3 | 9 | 11 | 12 | |
| 周转＝完成−到达 | 3−0=**3** | 9−1=**8** | 11−2=**9** | 12−3=**9** | 29/4=**7.25** |
| 带权＝周转÷服务 | 3÷3=**1** | 8÷6≈**1.333** | 9÷2=**4.5** | 9÷1=**9** | ≈**3.958** |

P4 只服务 1 却周转 9，带权 9：短作业被长作业堵住。

**SJF（非抢占）**：只在 CPU 空出的那一刻，从**已到达**的进程里挑服务时间最短的。
1. t=0 只有 P1 到 → P1 0→3。
2. t=3，P2(6)、P3(2)、P4(1) 均已到 → P4 3→4。
3. t=4 → P3 4→6。
4. 最后 P2 6→12。

| | P1 | P4 | P3 | P2 | 平均 |
|---|---|---|---|---|---|
| 周转 | 3 | 4−3=**1** | 6−2=**4** | 12−1=**11** | 19/4=**4.75** |
| 带权 | 1 | 1 | 2 | ≈1.833 | ≈**1.458** |

**优先级（非抢占，P2 > P4 > P1 > P3）**：`[P1 0→3] [P2 3→9] [P4 9→10] [P3 10→12]`，周转 3、8、7、10，平均 **7.0**。

对比 **FCFS 7.25 / SJF 4.75 / 优先级 7.0**：总工作量不变，只换挑人规则，变的是谁在等；SJF 最短，代价是长作业 P2 排到最后。

## 七、线程（概念）

传统进程**既是可拥有资源的独立单位，又是可独立调度和分配的基本单位**；创建、撤销、切换进程时空开销大（建 PCB、分内存、换页表），所以进程数目不宜过多、切换频率不宜太高，并发度上不去。线程把两个属性拆开：

| | 进程 | 线程 |
|---|---|---|
| 角色 | **独立分配资源的单位** | **调度和分配的基本单位** |
| 拥有 | 全部资源 | **基本上不拥有资源**，只有必不可少的**程序计数器、一组寄存器和栈** |
| 共享 | — | 共享所属进程的公共数据、全局变量、代码、打开的文件；**不共享**各自的栈指针等私有标识数据 |
| 切换开销 | 大 | 远小于进程（只换 PC、寄存器、栈） |

例：一个学生（进程）领一个餐盘（资源），三只手（线程）分别打饭、盛汤、拿餐具——被调度的是手，盘子共有。Java 里多个线程改同一个静态变量会冲突（共享），局部变量天然线程安全（各在各的栈）。

**易混对③ 用户级线程 vs 内核级线程**（教材内容，培训资料未展开）
- 判据｜内核是否知道线程存在：不知道（线程库在用户空间创建、调度）→ 用户级，切换不陷内核所以快，但**一个线程阻塞式系统调用堵住整个进程**，且同进程线程不能分到多个 CPU 并行；知道 → 内核级，一个线程阻塞不影响兄弟线程、能多核并行，但**每次切换都要陷入内核，开销更大**。
- 例子｜某线程发起阻塞式读文件：用户级下同进程其他线程全停；换成内核级，其他线程照常运行。

## 速记

- **三态**：运行（单核最多 1）／就绪（只欠 CPU）／阻塞（给 CPU 也跑不了）；**无 就绪→阻塞、阻塞→运行**；运行→就绪外因，运行→阻塞自因；五态加新建、终止
- **PV**：P 减 1，**S<0** 阻塞；V 加 1，**S≤0** 唤醒一个；S>0 剩 S 个，**S<0 则 |S| 个在等**；`S = 初值 − P + V`；n 进程 m 资源范围 m ～ m−n；互斥初值 1，同步初值 = 资源数
- **生产者-消费者**：mutex=1／empty=n／full=0；消耗什么 P 什么、产出什么 V 什么；**先 P 资源后 P 互斥**，反了缓冲区满时死锁
- **前趋图**：一边一信号量、初值 0，前趋结束 V、后继开始 P；入边数 = 开头 P 数，出边数 = 结尾 V 数
- **进程资源图**：R→P 已分配、P→R 请求；请求的那类有剩＝非阻塞，不剩＝阻塞；全是阻塞节点才死锁
- **调度**：高（作业进系统）／中（进程进内存）／低（进程上 CPU，最活跃）；周转 = 完成 − 到达，带权 = 周转 ÷ 服务（≥1）；SJF 只在已到达里挑；时间片过大退化 FCFS、过小开销大
- **线程**：进程拥有资源、线程被调度；线程只有 PC、寄存器、栈；用户级快但一堵全堵，内核级可并行但切换陷内核
- **原句**：四特征 并发/共享/虚拟/不确定；五功能 时间/空间/信息/硬件/人机；实时「交互要求不高、可靠性有保障」；分布式「无主次之分」；嵌入式 片级→板级→系统；PCB 唯一标志
