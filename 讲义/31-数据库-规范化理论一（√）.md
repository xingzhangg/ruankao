## 开讲：一张什么都塞在一起的表

全课跟着同一张烂表走：一个教务系统图省事，把学生、系、课程、成绩全塞进一张表。

**选课表(学号, 姓名, 系名, 系主任, 课程号, 课程名, 成绩)**

| 学号 | 姓名 | 系名 | 系主任 | 课程号 | 课程名 | 成绩 |
|---|---|---|---|---|---|---|
| S01 | 张三 | 计算机系 | 王主任 | C01 | 数据库 | 85 |
| S01 | 张三 | 计算机系 | 王主任 | C02 | 操作系统 | 78 |
| S02 | 李四 | 计算机系 | 王主任 | C01 | 数据库 | 90 |
| S03 | 王五 | 数学系 | 赵主任 | C03 | 高等数学 | 88 |

先把几个词对上程序员熟悉的东西。表里的一行叫**元组**（一条记录），一列叫**属性**（一个字段），行列交叉的那个格子叫**分量**。只描述"表叫什么、有哪些列"而不管里面装了什么数据，这个骨架叫**关系模式**，写成 R(学号, 姓名, …)；考试题里的写法 `R(U, F)` 中，U 是全部属性的集合，F 是下面要讲的函数依赖集合。

**先别往下看：这张表的主键（能唯一钉住一行、不允许重复也不允许为空的那一列或那几列）该定成什么？**

多数人第一反应是学号。但表里 S01 出现了两行，学号根本不唯一。姓名、课程号也各自重复。真正能唯一钉住一行的是 **(学号, 课程号)** 这个组合——"谁 + 哪门课"才对应一个确定的成绩。这个直觉后面要变成可计算的步骤，先记住结论。

主键定下来，四个毛病就现形了：

- **数据冗余**：张三的姓名、系名各存了 2 遍，"计算机系的主任是王主任"这条事实存了 3 遍。它是下面三个异常的**共同根源**。
- **更新异常**：计算机系换主任，要改 3 行；漏改一行，同一个系就冒出两个主任，数据自相矛盾。
- **插入异常**：新成立物理系，还没有学生选课。主键 (学号, 课程号) 填不出来，**这个系的信息根本进不了库**。
- **删除异常**：王五退学删掉最后一行，数学系和赵主任跟着**陪葬**，再也查不到。

凭感觉知道这表该拆，可拆到哪一步算完？规范化理论要给的就是一套能判定、可执行的规则：同一张表交给谁判，「它属于第几范式」「毛病出在哪条依赖上」的答案都得一样。而要判定，先得有把尺子。

### 一、把"学号决定姓名"说成机器能判的话

**先别往下看：机器不认识"决定"两个字，它只会比较值。你能不能只用"某两行的某几列相等或不等"，把"学号决定姓名"这句话说出来？**

答案是：**从表里任取两行，只要这两行的学号相等，它们的姓名就必须相等**。反过来说，只要能在表里找到两行学号相同而姓名不同，这张表就违反了这条规则。这句话机器一遍扫描就能判。

这就是**函数依赖**的定义：设 X、Y 是关系模式 R 的属性集，若 R 的任意一个合法实例中，任意两个元组只要在 X 上取值相等、在 Y 上取值就必然相等，则称 **X 函数决定 Y**，记作 **X→Y**，读作"X 决定 Y"，也说"Y 函数依赖于 X"。

X 叫**决定因素**。培训资料拿 Y = X² 打比方：给一个 X 就唯一算出一个 Y，多对一可以，一对多不行。

三件容易忽略的事：

- 函数依赖是**语义约束，不是从数据里统计出来的**。上面这四行里成绩恰好互不相同，但绝不能因此写"成绩→学号"。判依赖要问业务规则，不是数当前有几行。考试题里 F 是直接给你的，**不许自己往里加**。
- Y 是 X 子集的那类依赖（比如 (学号,课程号)→学号）永远成立，什么信息都不提供，叫**平凡函数依赖**。判范式时一律跳过，只看**非平凡**的。
- 左边可以是属性组：`(学号,课程号)→成绩`。

把这张表的业务规则逐条翻译过来，就得到它的函数依赖集：

> **F = { 学号→姓名，学号→系名，系名→系主任，课程号→课程名，(学号,课程号)→成绩 }**

（培训资料的原例没有"课程名"这一列，所以它只有四条依赖。多这一列能多演示一次分解，其余结论完全一致。）

注意 F 只写了业务直接规定的那几条，**它能推出的依赖远不止这几条**：把 学号→系名 和 系名→系主任 串起来，学号→系主任 照样成立，只是没写进 F。所以判范式绝不能只盯着 F 的字面几行，得先有办法把"能推出来的一切"一次摊开——这就是下一节要造的工具。

### 二、量之前先立基准：码

"码"和"键"是同一个 key 的两种译法，考试两种写法都出现，含义一样。

- **超键（超码）**：能唯一标识表中每一行的属性组合。选课表里 (学号, 课程号) 是超键；(学号, 课程号, 姓名) 也是——多带几列照样唯一，只是带了废物。
- **候选键（候选码）**：把超键里多余的属性一个个删掉，删到"再删一个就不唯一了"为止，剩下的就是候选键。所以候选键 = **极小的超键**。一张表的候选键**可能不止一个**。
- **主键（主码）**：候选键里任选一个，被指定为正式主键的那个。
- **主属性**：只要在**某一个**候选键里露过面就算（哪怕只进了其中一个候选键）；一个候选键都没进过的，叫**非主属性**。
- **外键（外码）**：本表里的某个属性（组），它自己不是本表的候选码（但**可以是候选码的一部分**——后面拆出来的 选课(学号, 课程号, 成绩) 里，学号就既是外键又是主属性），取值必须来自另一张表的主键。培训资料简写成"其他表中的主键"，准确说是"本表里那个指向别人主键的列"——比如后面拆出来的 学生(学号, 姓名, 系名) 里的"系名"，就是指向 系(系名, 系主任) 的外键。

配套的三类**完整性约束**是选择题的送分点，认脸即可：**实体完整性**＝主键约束，主键值不能为空、不能重复；**参照完整性**＝外键约束，外键的值要么是被参照表里已经存在的主键值，要么为空；**用户自定义完整性**＝业务自己规定的表达式约束，例如"年龄必须在 0 到 150 之间"。

开头那条"物理系进不了库"的插入异常，卡住它的正是**实体完整性**——主键 (学号, 课程号) 没值可填，这一行就写不进去。

为什么要在这里插一段讲码：因为 2NF、3NF 的条件从头到尾都是"**非主属性**对**码**如何如何"。不先求出码，这两句话一个字都判不了。

**要判"某组属性是不是超键"，等价于问它顺着 F 能推出的属性够不够全部。** 所以先解决这个更基础的问题。

**属性闭包 X⁺：滚雪球。** 手上握着 X 这几列的值，能推出哪些列的值？做法：把 X 扔进袋子；反复扫 F，**哪条依赖的左边已经整个在袋子里，就把它的右边也倒进袋子**；扫完一整轮没有新东西进袋，停。袋子里最后装的全部属性记作 **X⁺**。

三个"为什么"：为什么左边要**全部**在手上——`AB→C` 说的是"A 和 B 一起才定得了 C"，光有 B 定不了；为什么要**反复**扫——新进袋的属性会让原本用不上的依赖变得可用（下面马上就撞到）；为什么一定会停——属性总数有限，袋子只增不减，最多滚 |U| 轮。

拿选课表算 (学号, 课程号)⁺，初始袋子 `{学号, 课程号}`：

```
学号→姓名        左边"学号"在袋 → 收 姓名     {学号,课程号,姓名}
学号→系名        左边"学号"在袋 → 收 系名     {…,系名}
课程号→课程名    左边"课程号"在袋 → 收 课程名 {…,课程名}
(学号,课程号)→成绩  两个都在袋 → 收 成绩      {…,成绩}
系名→系主任      "系名"是刚才才进袋的 → 收 系主任  {全部 7 个}   ← 这就是"要反复扫"的理由
再扫一轮，无新增 → 停
```

(学号, 课程号)⁺ = 全部 7 个属性 ⇒ 它是**超键**。再算两个真子集：(学号)⁺ = {学号, 姓名, 系名, 系主任}，不全；(课程号)⁺ = {课程号, 课程名}，不全。两个真子集都不是超键，说明它已经删无可删 ⇒ **(学号, 课程号) 是候选码**。于是主属性是学号、课程号，非主属性是姓名、系名、系主任、课程名、成绩。

**求候选码的三步法，以及它为什么成立。** 属性组合有 2ⁿ 种，不能一个个试闭包。先按属性在 F 里出现的位置把大部分砍掉：

1. **左独必在码**——只出现在依赖左边的属性（以及左右都不出现的属性），没有任何一条依赖能推出它，别人带不出它，它只能自己进码，而且**每一个**候选码都必须含它。
2. **右独必不在**——只出现在右边的属性，一定能被别人推出来。把它塞进码里，去掉它剩下的部分照样推得全，说明它是多余的，所以**任何**候选码都不含它。
3. **两边出现试着补**——既在左又在右的属性说不准。先把第 1 类属性合起来求闭包：推全了就结束，它是唯一候选码；推不全，就从这类"待定"属性里逐个补进去再算闭包（一个不够就两个两个补），把所有**极小**的组合全找出来。

选课表里"只在左边出现"的正好是学号和课程号，把它俩合起来求闭包（第 3 步的头一句）一次就推全了，所以候选码唯一，后面"逐个补待定属性"根本用不上。那半截长什么样，第五节的字母题会完整走一遍。

### 三、冗余的两种病灶形状

有了码，回头看这张表，就能说清冗余到底是怎么冒出来的。

**病灶① 部分依赖。** 姓名只要学号一个人就能定，可码是 (学号, 课程号)。于是张三每多选一门课，姓名、系名、系主任就跟着重抄一遍——**抄多少遍由他选了几门课决定，而这几列跟课程根本没关系**。课程名同理——每多一个学生选"数据库"，"数据库"这三个字就多抄一行，而它只由课程号决定。

定义：X→Y 成立时，若 X 的**某个非空真子集** X′ 也能推出 Y，就称 Y **部分函数依赖**于 X；若 X 的任何非空真子集都推不出 Y，就称 Y **完全函数依赖**于 X。培训资料的说法"A 可确定 C，(A,B) 也可确定 C，则是部分依赖"是同一件事。

- `(学号,课程号)→成绩` 是**完全**依赖：只知道张三，推不出他哪门课的分；只知道"数据库"课，也推不出是谁的分。
- `(学号,课程号)→姓名` 是**部分**依赖：光学号就够，课程号是白带的。
- **候选码全是单属性时不可能有部分依赖**——单属性没有非空真子集，条件根本无从满足。注意是「全部候选码」：一张表若既有单属性码又有组合码，组合码那边照样可能冒出部分依赖。

**病灶② 传递依赖。** 系主任跟码隔了一层：学号→系名，系名→系主任。于是"计算机系的主任是王主任"这条事实，被这个系每个学生的每一行各抄一遍；而这个系的学生一旦删光，这条事实也跟着消失——**删除异常就是这么来的**。

定义：X→Y，其中 Y 不是 X 的子集、且 Y↛X（Y 推不回 X），又有 Y→Z 且 Z 不在 Y 里，则称 Z **传递函数依赖**于 X。

三个附加条件都不是摆设。**Y↛X**：如果 Y 也能推回 X，说明 X 和 Y 互相决定、是同一件事的两个名字，Z 对 X 就是直接依赖，不叫传递（培训资料写作"当 A 和 B 不等价时"，同一个意思）。

**Z 不在 Y 里**：否则 Y→Z 是平凡依赖，谈不上传递。**Y 不是 X 的子集**：中间项若只是 X 的一部分（X 是组合码 AC、Y 只取其中的 A），那毛病是"只依赖半个码"，该记在上面的部分依赖账上，不叫传递。

这两种形状就是三宗罪的全部元凶。1NF/2NF/3NF 要做的，就是逐级把它们赶出去。

### 四、三道关：判一关，拆一次

**范式**（Normal Form，NF）是给关系模式定的合格等级，条件一级比一级严，满足高一级必然满足低一级。上午题考到 3NF/BCNF，本课管前三关。

**第一关 1NF：每一格必须是不可再分的原子值。** 通俗说就是表里不许再嵌小表。培训资料的反例：

| 员工编号 | 员工姓名 | 出生日期 | 薪资/月（基本工资/月 · 补贴/月） | 所属部门 |
|---|---|---|---|---|
| 1 | 王红 | 19900908 | 9000 · 1000 | 101 |

"薪资/月"这一格里塞了两个数，一列当两列用，不满足 1NF；改法是拆成"基本工资"和"补贴"两列。另一类常见反例是一格里塞"电话13800000000；邮箱a@b.com"，或一格里塞三门课的成绩。关系数据库建出来的表默认都满足 1NF，所以考试问"最高属于第几范式"、答案是 1NF 时，几乎都意味着**卡在 2NF 上**，而不是格子里真嵌了小表。

选课表每格都是单值 ✓ 过 1NF。

**第二关 2NF：1NF，且每个非主属性都完全函数依赖于每一个候选码**（换句话说，没有部分依赖）。

检查动作：候选码是单属性 → 这个码直接过。候选码是组合 → 把它的每个非空真子集 K′ 拿出来求 K′⁺，看里面有没有非主属性，有就是部分依赖。有多个候选码时**每个都要查**，只要在其中一个码上查出部分依赖就违反 2NF。

选课表：(学号)⁺ 里装着姓名、系名、系主任三个非主属性 ⇒ 存在部分依赖 ⇒ 违反 2NF，**整表卡在 1NF**。

> 培训资料这里的原话是"学生表不满足 2NF，因为学号不能完全确定课程号和成绩"。这句话解释的是"码为什么必须是组合的"，不是 2NF 被违反的理由；真正的理由是姓名、系名这些非主属性只依赖码的一半。按上面的检查动作走，别照抄这句话答题。

分解动作：**把只依赖半个码的那堆属性，连同那半个码一起搬出去另立一张表，原表留下那半个码当外键。**

```
学生(学号, 姓名, 系名, 系主任)     码：学号
课程(课程号, 课程名)               码：课程号
选课(学号, 课程号, 成绩)           码：(学号,课程号)；外键：学号、课程号
```

现在张三的姓名只存一遍，新开的课没人选也能先进课程表。**先别往下看：三宗罪清干净了吗？**

**第三关 3NF：2NF，且每个非主属性都不传递依赖于任何候选码。**

关键动作是**逐表回头重判**——这一步最容易被跳过，而本例的毛病恰恰藏在这里：

- 课程(课程号, 课程名)：码是单属性，唯一一条非平凡依赖的左边就是码 ✓
- 选课(学号, 课程号, 成绩)：唯一的非主属性"成绩"由整个码完全决定 ✓
- **学生(学号, 姓名, 系名, 系主任)**：码是单属性学号 → 过 2NF；但 学号→系名、系名→系主任，且 (系名)⁺ = {系名, 系主任} 推不回学号 ⇒ 系主任传递依赖于码 ⇒ **卡在 2NF**

症状确实还在：系主任跟着每个学生重抄；某个系最后一名学生退学，这个系和它的主任一起消失。**删除异常并没有被 2NF 治好。**

分解动作还是同一个：**把被中间项决定的属性，连同中间项一起搬出去，原表留中间项当外键。**

```
学生(学号, 姓名, 系名)    码：学号；外键：系名 → 系
系(系名, 系主任)          码：系名
```

**判 3NF 有一条更好用的等价判据**：把 F 里每条依赖的右边拆成单个属性，逐条看非平凡依赖 X→A，只要出现"**X 不是超码，而且 A 是非主属性**"，就违反 3NF；反过来，每条依赖要么左边是超码、要么右边是主属性，就满足 3NF。用它扫学生表：`系名→系主任`，系名不是超码、系主任是非主属性 ⇒ 违反，结论一致，而且不用去找中间项、不用验 Y↛X，快得多。

> 口径差异：培训资料把 3NF 写成"在满足 **1NF** 的基础上不存在非主属性对码的传递依赖"，教材（第 5 版）以 **2NF** 为前提。这个差别不是抠字眼：照培训资料的字面读，像 R(A,B,C)、F={A→C}（码 AB）这种表——非主属性只有 C，它只依赖半个码 A，是标准的部分依赖，而整张表里**找不出任何一条传递依赖**——就会被判成 3NF，正确答案却是 1NF。**一律按教材口径记**，或者干脆用上面那条等价判据——它本身就蕴含了 2NF，漏不掉。做题固定走"先查部分依赖、再查传递依赖、卡住即停"。

**终点，四张表**：

```
学生(学号, 姓名, 系名)     码：学号；外键：系名
系(系名, 系主任)           码：系名
课程(课程号, 课程名)       码：课程号
选课(学号, 课程号, 成绩)   码：(学号,课程号)；外键：学号、课程号
```

拿三宗罪回测：新成立物理系还没学生 → 直接插"系"表 ✓；某系学生删光 → 系表不受影响 ✓；换主任 → 只改系表一行 ✓。

3NF 不是终点——它只盯着非主属性，主属性之间互相捣乱它一概不管。那部分归 BCNF，连同 4NF、以及拆表要付的两笔代价（无损连接、保持依赖），都在讲义 32。滚雪球这把工具到那边接着用，不用再学新的。

### 五、换成字母题：同一套流程再走一遍

上面这张表有业务语义撑着，你能凭直觉判个八九不离十。可**考试给的多半是 R(A,B,C,D) 加一串字母依赖，没有语义可依托，只能纯机械地走流程**；而且中文表的候选码唯一，正好把三步法里最容易错的第 3 步绕过去了。所以必须再看一个抽象的。

**R(A,B,C,D)，F = { AB→C，C→D，D→A }。先别往下看：候选码有几个？**

绝大多数人只写出 AB，然后交卷。走流程：

① **分类**：左边出现过 A、B、C、D（A 出现在 AB 里）；右边出现过 C、D、A。所以——只在左边：**B**（必在每个候选码中）；只在右边：**没有**；两边都有：A、C、D（待定）。

② **从必在码的属性起步**：(B)⁺ = {B}，差得远，必须补。

③ **逐个补待定属性，每补一个算一次闭包**：

```
(AB)⁺：AB→C 收 C，C→D 收 D → {A,B,C,D} 全 ✓
        (A)⁺={A}、(B)⁺={B} 都不是超码 ⇒ AB 极小 ⇒ 候选码
(BC)⁺：C→D 收 D，D→A 收 A → 全 ✓
        (C)⁺={A,C,D} 缺 B ⇒ BC 极小 ⇒ 候选码
(BD)⁺：D→A 收 A，此时 A、B 齐了 → AB→C 收 C → 全 ✓
        (D)⁺={A,D} 缺 B ⇒ BD 极小 ⇒ 候选码
```

三个待定属性各补一次就都推全了，不必再两个两个补——任何把它们凑成对的更大组合都包含着上面某个候选码，不可能极小。

**候选码是 AB、BC、BD 三个。** 四个属性全都进过候选码，全是主属性，非主属性一个都没有 ⇒ 2NF 和 3NF 的条件都是"对非主属性的要求"，没有非主属性就无从违反，**自动满足 3NF**。（它到不了 BCNF，因为 `C→D` 的左边 C 不是超码——留给讲义 32。）

一整套流程从头到尾其实只在反复用同一个动作：**算闭包**。判超键是算闭包，验极小是算闭包，查部分依赖是算码的真子集的闭包，验传递依赖的 Y↛X 还是算闭包。把滚雪球滚熟，这一课的题就全是体力活。

## 考试怎么考

**考点① 求候选码。** 题目长相："关系模式 R(U,F)，U={…}，F={…}，则 R 的候选关键字为（ ）"，或者给一段业务描述让你先写 F 再求码。按三步法走（见第二节）。常见错法：**找到一个候选码就交卷**——只要有属性"两边都出现"，就必须把待定属性逐个试完；**忘了验极小性**——(ABC)⁺ 是全属性，但它包含 AB，只是超键不是候选码；**闭包滚雪球时左边只凑齐一半就用**，`AB→C` 必须 A、B 都在手才能收 C；**漏掉"左右都不出现"的属性**，它同样必在码中，因为谁也推不出它。

**考点② 判"R 最高属于第几范式"（本课主考点）。** 题目长相："关系模式 R(…)，函数依赖集 F={…}，R 最高属于（ ）A.1NF B.2NF C.3NF D.BCNF"，或者先问候选码、再问范式（练习 4 就是这种两问式）。固定四步：求候选码 → 分主属性/非主属性 → 查部分依赖（卡 2NF）→ 查传递依赖（卡 3NF），**一旦在某级卡住就停手，答案是它的上一级**。两个秒杀结论要用熟：**候选码全是单属性 ⇒ 一定没有部分依赖 ⇒ 至少 2NF**；**一个非主属性都没有 ⇒ 自动满足 3NF**。常见错法：**没求码就开始判**（"部分""传递"全是相对码定义的，没有码这两个词没有意义）；**过了 2NF 就停**，题目问的是"最高"，还得再查传递依赖；**把传递依赖的中间项 Y 想成必须全是非主属性**，Y 里含主属性照样构成传递依赖（练习 4 的中间项是 (商店编号, 部门编号)，其中商店编号就是主属性）。

**考点③ 完全/部分/传递依赖辨析。** 题目长相：给一条具体依赖问它属于哪一种，或问下列哪个说法正确。常见错法：**左边是单属性也说成部分依赖**（没有非空真子集，部分依赖无从发生）；**看见 X→Y→Z 就判传递**，忘了验 Y↛X（求一下 (Y)⁺ 看含不含 X 就行）；把平凡依赖也拿来判。

**考点④ 三种异常与三类完整性约束认脸。** 异常题给一个场景问它属于哪种异常，例如"某系最后一名学生被删除后系主任信息丢失，属于（ ）"，按第一节那三条定义对号入座，三者的根源都是数据冗余。约束题给一句约束描述问它属于哪一类，例如"外键的值必须是被参照表中已存在的主键值或为空"，答**参照完整性**。常见错法：选到"检索异常"这种规范化理论里根本不存在的编造项；把"主键不能为空"错记成参照完整性（那是实体完整性）；把"年龄必须在 0 到 150 之间"这类业务规则也往参照完整性上套（那是用户自定义完整性）。

**考点⑤ 分解到 2NF / 3NF。** 上午问"下列分解方案正确的是"，下午题 2 让你写出分解后的关系模式并标主键外键。两级的动作是同一个：把病灶属性连同它真正的决定者一起搬出去，原表留决定者当外键。常见错法：**搬完忘了留外键**，两张表接不回去；**只分解一次就收工**——消完部分依赖必须回头逐表再判一遍，往往还卡在传递依赖上（第四节的学生表就是）。

### 参考答案

**1. C、A**。只在左边出现的是 A、D（B、C 都是两边出现，没有只在右边的），A、D 必在每个候选码中。(AD)⁺ = {A,D}，不够，逐个补待定属性：(ABD)⁺ 由 AB→C 收 C，全 ✓；(ACD)⁺ 由 CD→B 收 B，全 ✓。两个都极小（去掉任一属性都推不全），所以候选关键字是 **ABD 和 ACD** 两个，选 C。四个属性全都进过候选码，全是主属性，非主属性 0 个，选 A。

**2. A、D**。只在左边：E、M；只在右边：N、L、Q。(EM)⁺ = {E,M} → E→N 收 N → EM→Q 收 Q → M→L 收 L → 全 ✓，候选码是 **EM**（唯一）。非主属性 N、L、Q。`E→N` 里 E 是码 EM 的非空真子集、N 是非主属性 ⇒ **存在部分依赖** ⇒ 卡在 **1NF**。第二空的 C 说"不存在部分函数依赖"，与刚才算出来的直接矛盾，属于典型的"前半句就错了"的干扰项；A、B 与结论相反。存在冗余和三种异常正是要分解的理由，选 D。

**3. A**。只在左边：C、D；只在右边：E；两边都有：A、B。C、D 必在码中，(CD)⁺ = {C,D} → D→A 收 A → A→E 收 E → AC 齐了，AC→B 收 B → 全 ✓。CD 本身就是"必在码"的属性合集，不可能更小，所以候选关键字唯一，就是 **CD**。（顺带：`D→A` 中 D 是 CD 的非空真子集、A 是非主属性，所以这个 R 也只到 1NF。）

**4. 候选码 = (商店编号, 商品编号)；R 最高属于 2NF。** 只在左边出现的是商店编号、商品编号，必在码中；(商店编号,商品编号)⁺ 先收库存数量、部门编号，此时 (商店编号,部门编号) 凑齐，再收负责人 → 全 ✓，且两个真子集的闭包都只有它自己，所以是唯一候选码。非主属性为库存数量、部门编号、负责人；(商店编号)⁺、(商品编号)⁺ 都推不出任何非主属性 ⇒ 无部分依赖 ⇒ 过 2NF。再看传递：码 →(商店编号,部门编号)→ 负责人，而 (商店编号,部门编号)⁺ = {商店编号, 部门编号, 负责人} 推不回商品编号 ⇒ 负责人传递依赖于码 ⇒ 不到 3NF。**注意中间项里含主属性"商店编号"，这不影响传递依赖成立**，用等价判据看更省事：`(商店编号,部门编号)→负责人` 左边不是超码、右边是非主属性，直接判违反 3NF。

**5. B**。只在左边出现的是 A，(A)⁺ = {A,B,C} 全 ✓，码 = A（单属性）。非主属性 B、C。单属性码没有非空真子集 ⇒ 无部分依赖 ⇒ 过 2NF。`A→B`、`B→C`，且 (B)⁺ = {B,C} 推不回 A ⇒ C 传递依赖于码 ⇒ 不到 3NF。答案 B。

**6. B**。删掉了不想删的东西（删学生却把系的信息一起带走）是删除异常；"想插插不进"（新系没学生）是插入异常；"一处改多处、漏改就打架"是更新异常。D 不是规范化理论里的术语，是编造出来的干扰项。

**7. 候选码 = AC，最高 1NF。** 只在左边：A、C（必在码）；只在右边：B、D（必不在码）。(AC)⁺：A→B 收 B，C→D 收 D → 全 ✓，且 A、C 都是必在码的属性，所以 AC 唯一且极小。非主属性 B、D；`A→B` 中 A 是 AC 的非空真子集、B 是非主属性 ⇒ 部分依赖 ⇒ 卡在 1NF。

**8. 最高 1NF。** 只在左边：学号、课程号；(学号,课程号)⁺ = 全 ✓，码 = (学号, 课程号)。非主属性成绩、教师名。`课程号→教师名` 中课程号是码的非空真子集、教师名是非主属性 ⇒ 部分依赖 ⇒ 1NF。把只依赖课程号的教师名跟着课程号搬出去：**选课(学号, 课程号, 成绩)**，码 (学号,课程号)、外键课程号；**课程(课程号, 教师名)**，码 课程号。回头再判一次：选课表唯一的非主属性成绩完全依赖整个码 ✓，课程表码是单属性且唯一一条依赖左边就是码 ✓，**两张表都已经到 3NF**（本例一次分解就同时消掉了部分依赖，没有残留传递依赖）。

**9. 候选码 = AD，最高 1NF。** 只在左边：A、D（必在码）；只在右边：C；两边都有：B。(AD)⁺：A→B 收 B，B→C 收 C → 全 ✓；A、D 都是必在码属性，所以 AD 唯一。非主属性 B、C。`A→B` 中 A 是 AD 的非空真子集、B 是非主属性 ⇒ 部分依赖 ⇒ 卡在 1NF。（常见错法是只看到 A→B→C 就答 2NF，漏了 A 只是半个码。）

**10. 候选码 = XY 和 YZ，最高 3NF。** 只在左边：Y（必在码）；X、Z 两边都有；没有只在右边的。(Y)⁺={Y} 不够，逐个补：(XY)⁺ 由 XY→Z 收 Z → 全 ✓；(YZ)⁺ 由 Z→X 收 X → 全 ✓；(X)⁺={X}、(Z)⁺={X,Z} 都不是超码，两个组合都极小。X、Y、Z 全是主属性，非主属性为空 ⇒ 2NF、3NF 的条件无从违反 ⇒ **自动满足 3NF**。（`Z→X` 左边不是超码，所以到不了 BCNF，见讲义 32。）

**11.** 部分依赖的定义要求"码的某个**非空真子集**能推出该非主属性"。单属性码的真子集只有空集，压根不存在非空真子集，条件无法被满足，所以在这个码上部分依赖无从发生。而 2NF 要求对**每一个**候选码都不出部分依赖，所以必须全部候选码都是单属性才能一口咬定——这就是"全单属性码 ⇒ 至少 2NF"这条秒杀结论的来历。

## 速记

- 三宗罪：**插不进 = 插入异常，陪葬 = 删除异常，改漏 = 更新异常**，根源都是数据冗余
- 求码三句：**左独必在码，右独必不在，两边出现试着补**；闭包滚雪球：**左边凑齐才能收，滚不动就停**
- 候选码 = 极小的超键，**可能不止一个**；主属性 = 进过**某一个**候选码就算，其余为非主属性
- **一范原子、二消部分、三消传递**；四步走：求码 → 分主/非主 → 查部分 → 查传递，**卡住即停，答上一级**
- 候选码**全是**单属性 ⇒ 无部分依赖 ⇒ 至少 2NF；无非主属性 ⇒ 自动 3NF；传递依赖别忘验 **Y↛X**，且中间项不能只是码的一部分
- 3NF 等价判据：每条非平凡 X→A，**要么左边是超码，要么右边是主属性**
- 分解动作只有一个：**病灶属性 + 它真正的决定者一起搬出去，原表留外键**；分解完必须逐表重判
- 三类约束：**实体** = 主键非空不重，**参照** = 外键有出处或为空，**用户自定义** = 业务表达式
