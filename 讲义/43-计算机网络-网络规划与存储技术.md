# 43 · 计算机网络：网络规划与存储技术

## 定位

一家公司的网从一间办公室扩到三层楼（120 人、分财务研发两个部门），"多买几台交换机串起来"这个朴素做法会在八处不够用，每处补一组名词：广播互相干扰（冲突域与广播域）、按部门隔开又不重拉线（VLAN）、交换机怎么摆（三层模型）、线怎么走楼（综合布线）、一个公网 IP 带全屋上网（NAT 与默认网关）、出差的人进内网（VPN 与 PPP 认证）、盘坏一块不停业务（RAID）、存储怎么接（DAS/NAS/SAN）。只有 RAID 的容量与容错要动笔算。前接 41（设备工作在第几层）、42（IP 地址计算），后接 44（网络安全）。

## 一、冲突域与广播域

| 术语 | 是什么 |
|---|---|
| **广播** | 不指定收件人，向本网段所有机器发。典型是 ARP：知道 192.168.1.1 却不知道它的 MAC，就广播"谁是 192.168.1.1，把 MAC 报给我" |
| **广播域** | 能收到同一个广播的机器合起来的范围 |
| **冲突** | 两台机器同一时刻往同一根线上送信号，波形叠加谁都读不出，各等一会儿重发 |
| **冲突域** | 会互相撞车的那一片范围 |

判据：**设备看得懂第几层，就隔到第几层**。

| 设备 | 为什么 | 隔离冲突域 | 隔离广播域 | 24 口接满：冲突域 / 广播域 |
|---|---|---|---|---|
| 集线器（物理层） | 只放大电信号复制到所有端口，读不懂地址 | ✗ | ✗ | 1 / 1 |
| 交换机（数据链路层） | 看得懂 MAC，每端口独立收发；广播帧只能向所有端口**泛洪** | ✓ | ✗ | 24 / 1 |
| 路由器（网络层） | 看得懂 IP，默认不把广播转到别的接口 | ✓ | ✓ | 每接口各一个广播域 |

**原话｜** "路由器可以阻断广播域和冲突域，交换机只能阻断冲突域，因此一个路由器下可以划分多个广播域和多个冲突域；一个交换机下整体是一个广播域，但可以划分多个冲突域；而物理层设备集线器下整体作为一个冲突域和一个广播域。"

"机器一多网就卡"的机制：120 台机器串在交换机上就是一个 120 台规模的广播域，每个 ARP、DHCP 广播都要送到其余 119 块网卡上拆开看一眼再丢——不是带宽满了，是每台机器都在替别人处理广播。

## 二、VLAN（虚拟局域网）

**原话｜** "是一组逻辑上的设备和用户，这些设备和用户并不受物理位置的限制，可以根据功能、部门及应用等因素将它们组织起来，相互之间的通信就好像它们在同一个网段中一样。"

线一根不动，在交换机上给端口打标记（"这 20 个口算财务、那 30 个口算研发"），财务的广播只在财务的口里转。

**原话｜** "VLAN 工作在 OSI 参考模型的第 2 层和第 3 层，一个 VLAN 就是一个广播域，VLAN 之间的通信是通过第 3 层的路由器完成的。"

| 要点 | 内容 |
|---|---|
| VLAN 数与广播域 | **VLAN 数 = 广播域数**。"一台交换机下整体一个广播域"的前提是没划 VLAN；划 3 个就是 3 个广播域 |
| 跨 VLAN 通信 | 默认不通，必须经第 3 层路由器（或交换机的三层模块）转发 |
| 隔离方式 | **物理上不隔离、逻辑上隔离** |
| 划分依据 | 功能、部门及应用等因素 |
| 优点（原话） | "网络设备的移动、添加和修改的管理开销减少；可以控制广播活动；可提高网络的安全性。" |

三条优点对应：员工换楼层只改端口的 VLAN 标记不重拉线；广播只在本 VLAN 内转；默认隔离，要通就得显式配一条，配时顺带加访问控制。

## 三、层次化网络模型

**原话｜** "三层模型将网络划分为核心层、汇聚层和接入层"。

| 层 | 关键词 | 原话 |
|---|---|---|
| **核心层** | 快，不做检查 | "提供不同区域之间的最佳路由和高速数据传送" |
| **汇聚层** | 策略 | "将网络业务连接到接入层，并且实施与安全、流量、负载和路由相关的策略" |
| **接入层** | 用户 | "为用户提供了在本地网段访问应用系统的能力，还要解决相邻用户之间的互访需要，接入层要负责一些用户信息（例如用户 IP 地址、MAC 地址和访问日志等）的收集工作和用户管理功能（包括认证和计费等）" |

**易混对：核心层 vs 汇聚层**
- 判据｜过滤、检查、访问控制这类"拆开看一眼再决定放不放"的动作归汇聚层；核心层只做高速转发。原因：所有跨区域流量都过核心层，它是全网最忙的一段，在那里检查会拖慢全网；汇聚层流量已分成几股，慢一点只影响一股。
- 例子｜"将分组从一个区域高速转发到另一个区域"→ 核心层；"对分组进行有效性检查"→ 汇聚层。

教材示意图是一棵倒树：Internet → 防火墙 → 1 台核心交换机 → 2 台汇聚交换机 → 各接 2 台、共 4 台接入交换机。

## 四、综合布线系统 PDS

**信息插座**＝墙上插网线的方口，办公区与楼内布线的分界；**配线架**＝弱电间里把几十根线卡住、再跳线到交换机的铁架子。

沿"从工位走回机房"的路排六个子系统（原话在右栏）：

| 走到哪一段 | 子系统 | 原话 |
|---|---|---|
| 电脑 → 墙上插座 | **工作区子系统** | 实现工作区终端设备到水平子系统的信息插座之间的互联 |
| 插座 → 本层弱电间配线架（楼层内横走） | **水平布线子系统** | 实现信息插座和管理子系统之间的连接 |
| 弱电间的配线架与跳线本身 | **管理子系统** | 连接各楼层水平布线子系统和垂直干缆线，负责连接控制其他子系统为连接其他子系统提供连接手段 |
| 各层弱电间 → 楼底机房（楼层间竖走） | **垂直干线子系统**（图上也叫"干线子系统"，同一个） | 实现各楼层设备间子系统之间的互连 |
| 机房主配线架 → 路由器、交换机、服务器 | **设备间子系统** | 实现中央主配线架与各种不同设备之间的连接 |
| 本楼 → 隔壁楼 | **建筑群子系统** | 各个建筑物通信系统之间的互联 |

**易混对：工作区 vs 水平布线**
- 判据｜看连接的两端：终端↔插座是工作区；插座↔管理子系统是水平布线。
- 例子｜桌上电脑到墙上插座那根跳线 → 工作区；从这个插座穿过本层天花板到弱电间配线架 → 水平布线（它向上经管理子系统接干线、向下接工作区）。

教材的结构化布线示意图：三块斜置平面代表三层楼，分别标出管理、工作区、干线、水平布线、建筑群、设备间子系统，三层之间一束竖直粗线串起。

## 五、NAT 与默认网关

私有地址（192.168 开头等，地址计算见 42）在公网上无法路由，包发出去回不来。

**NAT 原话｜** "公司内有很多电脑，在公司局域网内可以互联通信，但是要访问外部因特网时，只提供固定的少量 IP 地址能够访问因特网，将公司所有电脑这个大的地址集合映射到能够访问因特网的少量 IP 地址集合的过程就称为 NAT。很明显，使用了 NAT 后，一个公司只有少量固定 IP 地址可以上网，大大减少了 IP 地址的使用量。"

做法：出口设备把出去的包的源地址换成公网 IP 并记账（"这条是三楼小王的"），回包按账换回私有地址。方向是**大量私网地址 → 少量公网地址**。

**默认网关原话｜** "一台主机可以有多个网关。默认网关的意思是一台主机如果找不到可用的网关，就把数据包发给默认指定的网关，由这个网关来处理数据包。现在主机使用的网关，一般指的是默认网关。默认网关的 IP 地址必须与本机 IP 地址在同一个网段内，即同网络号。"

**必须同网段的原因**：主机要把包交给网关，得先在本网段广播 ARP 问网关的 MAC；ARP 广播出不了广播域，网关不在本网段就问不到，包一步也发不出去。网关配错网段就是"网线插好了却上不了网"。

## 六、VPN 与 PPP 认证

**VPN 原话｜** "是在公用网络上建立专用网络的技术。其之所以称为虚拟网，主要是因为整个 VPN 网络的任意两个节点之间的连接并没有传统专网所需的端到端的物理链路，而是架构在公用网络服务商所提供的网络平台，如 Internet、ATM（异步传输模式）、Frame Relay（帧中继）等之上的逻辑网络，用户数据在逻辑链路中传输。"

"虚拟"＝中间没有一根专属的线，数据裹起来当普通流量走公网，到对端拆开还原。加密与防篡改算法见 44。

**PPP**（点对点协议）是拨号和专线上最常用的数据链路层协议。

**原话｜** "PPP 的 NCP 可以承载多种协议的三层数据包。PPP 使用 LCP 控制多种链路的参数（建立、认证、压缩、回拨）。"

| 缩写 | 全称 | 干什么 |
|---|---|---|
| **LCP** | 链路控制协议 | 把链路谈拢：建立、认证、压缩、回拨 |
| **NCP** | 网络控制协议 | 链路谈拢后决定跑哪种三层协议（IP、IPX 等） |

**原话｜** "pap 认证是通过二次握手建立认证（明文不加密），chap 挑战握手认证协议，通过三次握手建立认证（密文采用 MD5 加密）。PPP 的双向验证，采用的是 chap 的主验证风格。PPP 的加固验证，采用的是两种（pap,chap）验证同时使用"

**易混对：PAP vs CHAP**
- 判据｜口令原文上不上线：上线（明文）＝PAP，二次握手；不上线（只传摘要）＝CHAP，三次握手。
- 例子｜PAP：①被认证方发用户名+明文口令 → ②认证方回通过/不通过，截获即可冒充。CHAP：①认证方发随机**挑战值** → ②被认证方用挑战值+口令算出**摘要**发回 → ③认证方用存的口令照算比对、回通过；挑战值每次换，录下重放也无用。

MD5 是把任意长内容压成固定长度"指纹"的算法，算得出、推不回原文（分类与安全性归 44）。双向验证用 CHAP 的主验证风格；加固验证是 PAP 与 CHAP 同时使用。

## 七、RAID

### （概念）级别对比

**原话｜** "RAID 即磁盘冗余阵列技术，将数据分散存储在不同磁盘中，可并行读取，可冗余存储，提高磁盘访问速度，保障数据安全性。"

RAID 是**硬件层面的冗余**，目标是盘坏了业务不停；每天拷一份到别的盘叫**备份**，恢复要停机、当天改动会丢；数据库的转储与恢复是软件层面的事，归 35。

| 级别 | 原理 | 原话 |
|---|---|---|
| RAID 0 | 数据分散到各盘（条带），无冗余 | "磁盘利用率 100%，访问速度最快，但是没有提供冗余和错误修复技术" |
| RAID 1 | 成对**镜像**，两盘内容逐块相同 | "在成对的独立磁盘上产生互为备份的数据，增加存储可靠性，可以纠错，但磁盘利用率只有 50%" |
| RAID 2 | 条块化 + 海明码（01 讲的能定位错位的校验码） | "将数据条块化的分布于不同硬盘上，并使用海明码校验" |
| RAID 3 | 奇偶校验，校验放**单块专用盘** | "使用奇偶校验，并用单块磁盘存储奇偶校验信息（可靠性低于 RAID5）" |
| RAID 5 | 奇偶校验，校验**分散**在所有盘 | "在所有磁盘上交叉的存储数据及奇偶校验信息（所有校验信息存储总量为一个磁盘容量，但分布式存储在不同的磁盘上），读/写指针可同时操作" |
| RAID 1+0 | **先镜像、后条带** | 安全性高于 0+1，"不允许同一组中的两个磁盘同时损坏" |
| RAID 0+1 | **先条带、后镜像** | "若一个磁盘损坏，则当前 RAID0 无法工作，即有一半的磁盘无法工作" |

**易混对：RAID 3 vs RAID 5**
- 判据｜只看校验放哪：单块专用盘＝3，分散在所有盘＝5。容量、容错两者相同。
- 例子｜RAID 3 每次写数据都要改那块校验盘，它既是性能瓶颈又是单点，所以可靠性低于 5；RAID 5 校验摊开，才有"读/写指针可同时操作"。

**易混对：RAID 1+0 vs RAID 0+1**
- 判据｜1+0 先两两镜像再条带；0+1 先条带成两组再互为镜像。
- 例子｜4 块盘，1+0：Disk0、Disk1 都是 A1 A3 A5 A7，Disk2、Disk3 都是 A2 A4 A6 A8；0+1：Disk0 是 A1 A3 A5 A7、Disk1 是 A2 A4 A6 A8 组成一条 RAID 0，Disk2、Disk3 是一模一样的另一条。

RAID 6 培训资料未收，工程上常见：两份不同算法的校验，最少 4 块盘，可用 (n−2)×C，能坏 2 块。

### （计算）可用容量与容错盘数

解决：给定级别、盘数 n、单盘容量 C，求能用多少、能坏几块。以 4 块 1TB 为例。

**RAID 0**（文件切 A1…A8，奇数块写 Disk0、偶数块写 Disk1）
1. 可用 = 2 × 1TB = 2TB（利用率 100%）
2. 坏一块，奇数块或偶数块全没，拼不成文件 → 能坏 **0** 块
3. 最少 2 块（1 块无所谓分散）

**RAID 1**（Disk0、Disk1 都写 A1 A2 A3 A4）
1. 可用 = 2 × 1TB × 50% = 1TB
2. 坏任一块，另一块有全套 → 能坏 **1** 块
3. 最少 2 块

**RAID 5**（4 块盘，每条带一个校验块，沿对角线轮换）

| Disk 0 | Disk 1 | Disk 2 | Disk 3 |
|---|---|---|---|
| A1 | A2 | A3 | **Ap** |
| B1 | B2 | **Bp** | B3 |
| C1 | **Cp** | C2 | C3 |
| **Dp** | D1 | D2 | D3 |

1. 校验：`Ap = A1 ⊕ A2 ⊕ A3`（⊕ 按位异或，让每一位上 1 的个数凑成偶数，即"奇偶校验"）
2. Disk1 坏、A2 丢：`A2 = A1 ⊕ A3 ⊕ Ap`，一位不差还原
3. A2、A3 同时丢：一条方程两个未知数，解不出 → 能坏 **1** 块
4. 每条带 1 块被校验占，合计正好一块盘的容量（摊在 4 块上）→ 可用 = (4 − 1) × 1TB = **3TB**，利用率 75%

提炼：**RAID 5 可用 = (n − 1) × C，利用率 (n − 1)/n，容错固定 1 块，最少 3 块**（n = 2 时只剩 1 块盘可用，和镜像一样却更绕）。RAID 3 校验也只有一份，同样 (n − 1) × C、坏 1 块。盘越多利用率越高，能坏的仍只有 1 块。

| n × C | 可用 | 利用率 |
|---|---|---|
| 6 × 2TB | (6−1)×2 = 10TB | 83.3% |
| 8 × 600GB | 7×600 = 4200GB = 4.2TB | 87.5% |

**RAID 1+0 / 0+1**（4 块 1TB）
1. 可用都是 4 × 1TB ÷ 2 = 2TB（利用率 50%），最少 4 块，都保证能坏 1 块
2. 坏 2 块共 C(4,2) = 6 种组合
3. 1+0：只要坏的两块不在同一对镜像里就活 → 6 − 2 = **4 种**存活
4. 0+1：第一块坏，它所在的整条 RAID 0 下线；第二块只有也落在这条上才活 → **2 种**存活
5. 4/6 对 2/6，这就是"1+0 安全性更高"

| 级别 | 最少盘数 | 可用容量（n 块，单盘 C） | 保证能坏几块 |
|---|---|---|---|
| RAID 0 | 2 | n × C（100%） | 0 |
| RAID 1 | 2 | n × C ÷ 2（50%） | 1 |
| RAID 2 | — | 随校验位数变化 | —（原文只说用海明码校验） |
| RAID 3 | 3 | (n − 1) × C | 1（可靠性低于 5） |
| RAID 5 | 3 | (n − 1) × C | 1 |
| RAID 1+0 | 4 | n × C ÷ 2（50%） | 1（坏 2 块存活面更大） |
| RAID 0+1 | 4 | n × C ÷ 2（50%） | 1（坏 2 块存活面较小） |

（最少盘数与容错块数培训资料未给，由上面推出；利用率中 RAID 0、1 和两种组合级是原文明写，RAID 5 由"所有校验信息存储总量为一个磁盘容量"折算。）

## 八、DAS / NAS / SAN

| | DAS（直接附加存储） | NAS（网络附加存储） | SAN（存储区域网） |
|---|---|---|---|
| 怎么连 | SCSI 接口**直连一台服务器** | 网络接口接入**普通 TCP/IP 网络**，和服务器平级 | **专用交换机**组成的高速专用子网，躲在服务器背后，客户机看不见 |
| 存取粒度 | 无共享，只服务那台服务器 | **文件级**（小文件级共享存取） | **块（block）级** |
| 独立存储系统 | **不带任何存储操作系统** | **有独立的存储系统**，类似专用文件服务器 | 独立的存储区域网络 |
| 短板 | 距离／连接数／速率受限，服务器异常会波及存储器 | 经济、即插即用，但**难以获得满意的性能** | 要单独一张网，成本最高 |

**DAS 原话｜** "是指将存储设备通过 SCSI 接口直接连接到一台服务器上使用，其本身是硬件的堆叠，存储操作依赖于服务器，不带有任何存储操作系统。"问题："在传递距离、连接数量、传输速率等方面都受到限制。容量难以扩展升级；数据处理和传输能力降低；服务器异常会波及存储器。"（SCSI：比 USB 粗壮得多的一种机内／机旁高速设备接口。）

**NAS 原话｜** "通过网络接口与网络直接相连，由用户通过网络访问，有独立的存储系统。NAS 存储设备类似于一个专用的文件服务器，去掉了通用服务器大多数计算功能，而仅仅提供文件系统功能。以数据为中心，将存储设备与服务器分离，其存储设备在功能上完全独立于网络中的主服务器。客户机与存储设备之间的数据访问不再需要文件服务器的干预，同时它允许客户机与存储设备之间进行直接的数据访问，所以不仅响应速度快，而且数据传输速率也很高。"性能特点："进行小文件级的共享存取；支持即插即用；可以很经济的解决存储容量不足的问题，但难以获得满意的性能。"

**SAN 原话｜** "SAN 是通过专用交换机将磁盘阵列与服务器连接起来的高速专用子网。它没有采用文件共享存取方式，而是采用块（block）级别存储。SAN 是通过专用高速网将一个或多个网络存储设备和服务器连接起来的专用存储系统，其最大特点是将存储设备从传统的以太网中分离了出来，成为独立的存储区域网络 SAN 的系统结构。根据数据传输过程采用的协议，其技术划分为 FC SAN（光纤通道）、IP SAN（IP 网络）和 IB SAN（无线带宽）技术。"（IB 即 InfiniBand，服务器间的高速互连总线；"无线带宽"照原文录。）

**易混对：文件级 vs 块级**
- 判据｜向它要文件名＝文件级（NAS）；向它要裸扇区＝块级（SAN），文件系统由使用它的服务器自己建。
- 例子｜要"/财务/2026年9月报表.xlsx"，它替你找到散在各**扇区**（磁盘最小读写单位，一格几百到几千字节）的内容拼好给你 → NAS；"从第 10000 号扇区起给我 8 个" → SAN，数据库、虚拟机要自己安排盘上布局，必须用块级。

教材结构图：NAS 头（处理器、内存、网络接口、硬盘接口）+ 磁盘子系统，挂在 TCP/IP 网络上与服务器并列；SAN 是客户机 → 服务器 → 由 FC 交换机互连的专用云 → 磁盘阵列、磁带库。

## 九、URL 结构

`协议://域名:端口号/路径`；地址栏不写协议默认 http。`www.abc.com` 中 `www` 是主机名、`abc.com` 是域名、`com` 是顶级域名。**主机名与域名不是一回事**：同一域名下可有多个主机名，可解析到不同机器，`www.abc.com` 与 `abc.com` 未必是同一个页面。

## 速记

- 集线器 1 冲突域 1 广播域；交换机每端口一个冲突域、整体一个广播域；路由器每接口一个广播域。看得懂第几层就隔到第几层
- **一个 VLAN 就是一个广播域**；工作在第 2、3 层；跨 VLAN 要过第 3 层路由器；按功能、部门、应用划分；物理不隔离、逻辑隔离
- 核心层只管快（最佳路由 + 高速传送）、汇聚层管策略（安全流量负载路由）、接入层管用户（认证计费、收集 IP/MAC/日志）
- 布线：工作区（终端↔插座）→ 水平（插座↔管理）→ 管理 → 垂直干线（楼层间）→ 设备间（主配线架↔设备）→ 建筑群（楼与楼）
- NAT：大量私网地址 → 少量公网地址；**默认网关必须与本机同网段**；VPN 无端到端物理链路
- **PAP 二次握手明文，CHAP 三次握手 MD5 密文**；双向验证用 CHAP 主验证风格，加固验证两种同用
- RAID：0 是 n×C 坏 0；1、1+0、0+1 是 n×C÷2 坏 1；3、5 是 (n−1)×C 坏 1；3 校验单盘（低于 5）、5 分散；1+0 比 0+1 更耐两盘同损
- **DAS 直连一台服务器无存储 OS；NAS 普通网、文件级；SAN 专用交换机、块级**
