## 第 1 层 · 理解

### 一句话

> CPU 一个时钟周期能干一件事，去主存取一趟数却要等上几十到上百个周期。**存储层次结构就是一套障眼法：用一堆便宜的慢存储装下所有数据，再用一小块很贵的快存储，装住你"当下正在用的那一点点"。而 Cache 命中率，就是在算这套障眼法到底成不成立。**

### 痛点：这事的直觉是会骗人的

先说程序员熟悉的版本：本地缓存 / Redis 挡在数据库前面，命中就快、不命中就回源。**Cache 挡在主存前面，是同一件事的硬件版。**

真正的痛点是：**"命中率 90%"听起来已经很高了，直觉会觉得"那就是接近全速了"——但这个直觉是错的。**

设 Cache 10ns、主存 100ns、命中率 90%：

```
平均访存时间 T = 0.9×10 + 0.1×100 = 9 + 10 = 19 ns
                 └ 命中贡献 9ns ┘  └ 未命中贡献 10ns ┘
```

**只占 10% 的未命中，却吃掉了 10 ÷ 19 ≈ 53% 的平均时间**——比命中那 90% 还多。所以"命中率高不高"不能拍脑袋看，**必须真的按公式算**。这就是本课非算不可的原因，也是考试出题的着力点。

### 一条主线

```
CPU 快，主存慢（差一到两个数量级）→ CPU 大半时间卡在"等数据"
   ↓
能不能全用快的？ 不能 —— 越快的存储越贵、集成度越低，做不大（寄存器就那么几十个）
能不能全用慢的？ 不能 —— CPU 白等，算力全浪费
   ↓
唯一出路：【分层】。让绝大多数访问落在快的那层，少数才去慢的那层
      寄存器  →  Cache  →  主存  →  外存(硬盘/SSD)
      ←──────  越往上：越快、越贵、越小
      ──────→  越往下：越慢、越便宜、越大
   ↓
可是凭什么"绝大多数访问"就能落在一小块存储上？
凭程序访问地址的统计规律 ——【局部性原理】：
      时间局部性：刚用过的，马上还会再用       （循环里的同一个变量）
      空间局部性：用了这个，接着就用它旁边的   （数组遍历、顺序取指）
   → 所以把"刚用过的那一块，连同它的邻居一整块"搬进 Cache，就能大概率再次命中
   ↓
命中就走快车道(Tc)，不命中就走慢车道(Tm) —— 那平均下来到底多快？
      按概率加权：  T = H × Tc + (1-H) × Tm      ← 全章唯一公式
   ↓
考试就在这一条公式上来回出：
      正着问：给 H、Tc、Tm 求 T
      反着问：要让 T 不超过某值，H 至少要多少
      不算的那道：给一句场景，问体现的是【时间】还是【空间】局部性
   ↓
最后闭环：H 是被局部性决定的 —— 程序写得越符合局部性（按行遍历二维数组、
数据结构紧凑），H 越高，T 越接近 Tc。这也是 W6 页面置换算法的同一套逻辑。
```

## 第 2 层 · 考点：考试怎么问

### 考点① 平均访存时间计算（本课主考点，阶段B 必练）

**题目长相**：

- "某计算机系统中 Cache 的存取时间为 **10ns**，主存的存取时间为 **100ns**，若 Cache 命中率为 **95%**，则 CPU 的平均访存时间为（ ）ns。"
- 反向问法："若要使平均访存时间**不超过 20ns**，Cache 命中率**至少**应达到（ ）。"

**怎么解**：

**T = H × Tc + (1−H) × Tm**

- **H**＝命中率，**Tc**＝访问 Cache 耗时，**Tm**＝访问主存耗时
- 含义：**H 的概率走快车道，(1−H) 的概率走慢车道，按概率加权求平均**

三步走：① 抄下 H、Tc、Tm 三个数并**核对单位**（统一成 ns）→ ② 代入求和 → ③ **验算**（见下方陷阱第 2 条）。

反着问就把公式解开：

```
T = H×Tc + (1-H)×Tm = Tm - H×(Tm - Tc)
⇒  H = (Tm - T) / (Tm - Tc)
```

**"数次数"替代法**（概率加权算不直观时用，本质完全等价）：假设总共访问 **100** 次 → 命中 `100H` 次各花 Tc、未命中 `100(1−H)` 次各花 Tm → 求和再除以 100。

**陷阱**：

1. **把 (1−H) 乘错对象**——写成 `H×Tm + (1−H)×Tc` 就整个反了。记牢：**命中配 Cache，未命中配主存**。
2. **结果必须落在 Tc 与 Tm 之间**（因为它是两者的加权平均）。算出来比 Tc 还小、或比 Tm 还大，**一定是算错了**——这是最快的验算手段。而且 H 越高，结果越靠近 Tc。
3. **串行/并行口径**：教程与历年题的默认口径就是 `T = H×Tc + (1−H)×Tm`。只有当题干明确描述"未命中时**先查 Cache 未果、再去访问主存**"这类**串行**过程时，未命中项才写成 `(Tc + Tm)`。**无特别说明一律用默认口径**，不要自作主张加。
4. 命中率可能以"**失效率/缺失率**"给出——`失效率 = 1 − H`，先换算再代入。

### 考点② 局部性原理：时间还是空间（送分题）

**题目长相**："一个循环体在被反复执行的过程中，**同一变量被反复读写**，这体现了（ ）"、"数组元素**按内存连续地址顺序被依次访问**，这主要体现了（ ）"。

**怎么解**：**只看题干里的那个关键词**，一秒判断：

| 题干关键词 | 结论 |
|---|---|
| **同一个**、反复、重复、又一次 | **时间局部性**（同一地址在**时间**上被反复访问） |
| **相邻、连续、依次、顺序、挨着** | **空间局部性**（**位置**相邻的地址被接连访问） |

- **时间局部性**：**同一个**数据/变量刚被访问过，很可能马上又被访问一次。例：循环体里反复读写的同一变量、循环体本身的指令。
- **空间局部性**：**不同但挨着**的地址，一个接一个被访问。例：遍历数组、顺序执行的指令。

**类比看小说**：反复翻回**同一页**查前文人名 → **时间**局部性；一页页**顺着往后翻**（内容不同但位置连续）→ **空间**局部性。

**陷阱**：

- 选项里的"**顺序局部性**""**随机局部性**""**因果局部性**"**都是编出来的**，教程只有**时间**与**空间**两种。看到这类词直接排除。
- 顺序执行的指令流**两种都沾**（取指连续=空间；循环体重复执行=时间）——**看题干强调的是"同一条"还是"接着下一条"**，按它强调的那个词答。

### 考点③ 存储层次结构的属性排序

**题目长相**："关于存储器层次结构的叙述，**正确/错误**的是（ ）"、"由高层到低层，下列说法正确的是（ ）"。

**怎么解**：记住层次

```
寄存器 → Cache（高速缓存）→ 主存（内存）→ 外存/辅存（硬盘/SSD）
```

**自上而下**四个量的单调方向（一起记，一个都别漏）：

| 量 | 自上而下的变化 |
|---|---|
| 存取速度 | **递减**（越来越慢） |
| 容量 | **递增**（越来越大） |
| 每位（单位）价格 | **递减**（越来越便宜） |
| 被 CPU 访问的频度 | **递减** |

**陷阱**：

- ✗「越往下**单位成本越高**」——反了，是**递减**。注意区分**每位价格**（往下递减）与**整体总价**（大容量硬盘总价可能更高），题目问的一般是**每位价格/单位成本**。
- ✗ 把 Cache 和主存的管理者搞混：**Cache–主存**这一层由**硬件**自动完成、**对程序员透明**（程序里不需要也无法直接指定"把这个变量放进 Cache"）；**主存–外存**这一层靠**硬件 + 操作系统**共同实现（即虚拟存储，W6 讲义 38 的分页就是它）。

## 第 3 层 · 完整算例

### 算例一：正向求平均访存时间（原讲义算例，逐步版）

**已知**：Cache 存取时间 Tc = **10ns**，主存存取时间 Tm = **100ns**，命中率 H = **95%**。求平均访存时间 T。

**第 1 步 · 抄数并统一单位**：H = 0.95（95% 化成小数，别忘了这一步）；未命中率 1 − H = **0.05**；Tc = 10ns，Tm = 100ns，单位已统一。

**第 2 步 · 代入公式**（概率加权版）：

```
T = H×Tc + (1-H)×Tm
  = 0.95×10  +  0.05×100
  = 9.5      +  5
  = 14.5 ns
```

- `0.95×10 = 9.5`：95% 的访问走 Cache，每次 10ns，摊到每次访问头上是 9.5ns
- `0.05×100 = 5`：5% 的访问要跑主存，每次 100ns，摊下来是 5ns

**第 3 步 · 换个算法自查（"数次数版"，概率不直观时用，本质等价）**——假设访问 100 次：

```
命中 95 次：95 × 10ns  =  950 ns
未命中 5 次： 5 × 100ns =  500 ns
──────────────────────────────
100 次总共：            1450 ns
平均每次：  1450 ÷ 100 =  14.5 ns
```

**第 4 步 · 验算**：14.5 落在 **Tc=10 与 Tm=100 之间** ✔，且**明显靠近 10**（因为命中率高达 95%）✔ —— 两条都对得上，答案可信。

### 算例二：反向求最低命中率（同一组参数，自编【模拟】算例）

**已知**：Tc = 10ns，Tm = 100ns。要求平均访存时间 **T ≤ 20ns**，问命中率 H 至少多少？

**第 1 步 · 把公式解开**（不用背，现推）：

```
T = H×Tc + (1-H)×Tm = Tm - H×(Tm - Tc)
⇒  H = (Tm - T) / (Tm - Tc)
```

**第 2 步 · 代入**：

```
H = (100 - 20) / (100 - 10) = 80 / 90 ≈ 0.8889 = 88.89%
```

**第 3 步 · 验算（把结果代回正向公式）**：

```
T = 0.8889×10 + 0.1111×100 = 8.889 + 11.11 ≈ 20.0 ns ✔ 正好卡在上限
```

结论：命中率**至少要 88.9%**。注意方向——要求 T **越小**，需要的 H **越大**；若算出来"要求更快反而只需更低命中率"，一定是符号弄反了。

## 第 4 层 · 速记

> 存储层次：**寄存器 → Cache → 主存 → 外存**；自上而下**速度递减、容量递增、单位（每位）成本递减、访问频度递减**
> **Cache–主存层次由硬件管、对程序员透明；主存–外存层次由硬件+操作系统管（虚拟存储）**
> 局部性原理两种：**时间局部性**（反复用**同一个**）、**空间局部性**（**挨着的、顺着来**）
> 干扰项"顺序局部性/随机局部性/因果局部性"**都不存在**
> 核心公式：**T = H×Tc + (1−H)×Tm**（H 命中率，Tc 访问 Cache 耗时，Tm 访问主存耗时）
> 反解：**H = (Tm − T) / (Tm − Tc)**
> 口诀：**命中配 Cache，未命中配主存**；百分数先化小数
> 算不清"概率加权"就换成**"数次数"**：假设访问 100 次，命中次数×Tc + 未命中次数×Tm，求和再除以 100
> **验算铁律：结果必须落在 Tc 与 Tm 之间，且命中率越高越靠近 Tc**；出界就是算错
> 分层的本质：**快存储放常用数据，慢存储放不常用数据**——省的是"跑一趟慢存储"的时间

### 参考答案

1. **38ns**。概率加权：`0.9×20 + 0.1×200 = 18 + 20 = 38`；数次数版：`90×20 + 10×200 = 1800 + 2000 = 3800`，`3800 ÷ 100 = 38`。**验算**：38 落在 20（Tc）与 200（Tm）之间 ✔，且靠近 20 ✔。
2. **B**（时间局部性）——关键词"**同一变量**"+"**反复**"。C、D 两个选项是编造的名词。
3. **B**（空间局部性）——关键词"**连续地址**"+"**依次**"。C、D 同样是编造的名词。
