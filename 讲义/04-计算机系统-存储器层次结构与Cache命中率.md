# 04 · 计算机系统：存储器层次结构与 Cache 命中率

## 定位

存储器为什么分层、一小块 Cache 凭什么挡住大多数访问（局部性、地址映像、替换算法），以及挡完之后平均访问一次要多久。全课跟着一台机器走：Cache 一次 **20ns**、主存一次 **200ns**，最后一节算出它平均访存 **38ns**。02 讲了存储器是五大部件之一，05 接着讲主存怎么用芯片拼；局部性和 LRU 在操作系统的分页、页面置换里原样再用。

## 一、分级存储体系（概念）

目的：解决**存储容量、成本和速度之间的矛盾**。越快越贵、集成度越低做不大；全用慢的 CPU 白等。于是摞成金字塔：

```
        CPU 内部通用寄存器      ← 最快、最贵、最小（几十个，与运算同步）
             Cache（高速缓存）
             主存储器（内存）
          联机磁盘存储器（硬盘）
      脱机光盘、磁盘存储器      ← 最慢、最便宜、最大
```

自上而下：**存取速度递减、容量递增、每位价格递减、被 CPU 访问的频度递减**。"每位价格"不是整块总价——16TB 硬盘总价比内存条贵，摊到每一位便宜得多。

| 两级存储 | 解决 | 由谁实现 | 备注 |
|---|---|---|---|
| **Cache–主存** | 速度 | 全部**硬件**自动完成 | **对程序员透明**：程序里既不需要也无法指定"放进 Cache" |
| **主存–辅存** | 容量 | **硬件＋操作系统** | 即**虚拟存储体系**：装不下的先放硬盘，程序以为内存更大 |

其余认名即可：联机＝插在机器上随时能读（硬盘）；脱机＝平时拔下、要用才装（光盘、磁带、可拆卸移动硬盘）。

## 二、局部性原理（概念）

这台机器 Cache 只有 512B，主存 1MB（1/2048），却能挡住九成以上访问，靠的是**局部性原理**：CPU 运行时所访问的数据，会趋向于集中在一个较小的局部地址空间里。

| 关键词 | 是什么 |
|---|---|
| 同一个 / 反复 / 重复 / 又一次 | **时间局部性**：一个数据项正在被访问，近期很可能被再次访问（相邻时间访问同一数据项） |
| 相邻 / 连续 / 依次 / 顺序 / 挨着 | **空间局部性**：马上要用的数据地址很可能与当前地址挨着（相邻空间地址被连续访问） |

**时间 vs 空间**
判据｜反复用**同一个** → 时间；**挨着的**依次来 → 空间。
例子｜`for (i=0;i<1000;i++) sum += a[i];`：`sum`、`i` 和循环体指令每轮重复 → 时间；`a[0]`、`a[1]`…地址依次 → 空间。顺序执行的指令流两者都沾（取指连续是空间、循环重复是时间）。

局部性只有时间、空间两种；"顺序局部性""随机局部性""因果局部性"不是教材名词。

由此定策略：**把刚用过的一段连同邻居整块搬进 Cache**——整块搬吃空间局部性，搬进来不急着扔吃时间局部性。

## 三、Cache 与块（概念）

**Cache**：位于 CPU 与主存之间，半导体材料，容量小，速度是内存的 5–10 倍，存放**当前最活跃的程序和数据**，**直接与 CPU 交互**；内容是主存的**副本拷贝**。

原话｜Cache 由**存储器**（存数据）和**控制部分**（判断数据在不在）组成；在＝**命中**，直接读 Cache；不在＝**未命中**，去主存取，并按一定算法把主存内容替换进来。

搬运单位是**块**（Cache 侧也叫"行"），主存与 Cache 按同样大小等分编号。这台机器块大小 64B：

```
主存 1MB = 1048576 B ÷ 64 → 16384 块，编号 0～16383
Cache 512 B          ÷ 64 →     8 块，编号 0～7      （真机几十 KB～几 MB，这里缩小便于验算）
```

## 四、地址映像

CPU 送出的是**主存地址**，数据却要从 Cache 读写，中间把主存地址翻译成 Cache 地址的动作叫**地址映像**（地址映射），**由硬件自动完成**——不是操作系统、应用软件，也不是程序员编程。

### 4.1 三种方式（概念）

| 方式 | 规则 | 块冲突概率 | 地址变换 |
|---|---|---|---|
| **直接映像** | 主存第 j 块只能进 Cache 第 `j mod Cache块数` 块 | **最高**（不灵活，易浪费） | 最简单、最快 |
| **组相联映像** | Cache 分组，**组间直接映像**（进第 `j mod 组数` 组），**组内全相联**；每组几块叫几路 | 中间 | 中间 |
| **全相联映像** | 主存任一块可进 Cache 任一块；只有 Cache **全满**才冲突 | **最低** | 最复杂、最慢、硬件贵（要比所有标记） |

"相联"＝不按位置算、挨个比对内容去找。**块冲突**＝两块抢同一 Cache 位置，先来的被挤走。**标记**（tag）＝Cache 为每块记下"装的是主存第几块"。

**冲突概率 vs 地址变换复杂度**
判据｜位置钉得越死越容易撞：冲突 直接 > 组相联 > 全相联；变换复杂度恰好倒过来，"变换最简单"的直接映像冲突最多。
例子｜主存第 100、108 块：直接映像（8 块）`100 mod 8 = 108 mod 8 = 4`，只能抢第 4 格，交替访问反复未命中，哪怕另 7 格全空；2 路组相联（4 组）`mod 4` 都得 0，进同一组但组内 2 个位置，能共存。

原话修正｜培训资料写直接映像"二者块号相同才能命中"、组相联"主存中组号与 Cache 中组号相同的组才能命中"，都漏了取模：准确说法是**主存块号 mod Cache 块数（组数）＝ Cache 块号（组号）**，即主存块号低几位与之相同。原件"组组相连映像"应作**组相联映像**。

### 4.2 地址位数拆分（计算）

1. 主存 1MB = 2²⁰ → 地址 **20 位**。
2. 块 64B = 2⁶ → **块内地址 6 位**（三种方式都不变）。
3. 主存块号 = 20 − 6 = **14 位**（2¹⁴ = 16384 块）。
4. 按组数分账：组号位数 = log₂(组数)，**标记 = 14 − 组号位数**。

```
直接映像：  [ 标记 11 ] [ Cache 块号 3 ] [ 块内 6 ] = 20 ✓
2 路组相联：[ 标记 12 ] [ 组号 2 ]       [ 块内 6 ] = 20 ✓
全相联：    [ 标记 14 ]                  [ 块内 6 ] = 20 ✓
```

| | 组数 × 每组块数 | 组号位数 | 标记位数 | 每次比几个标记 |
|---|---|---|---|---|
| 直接映像 | 8 × 1 | 3 | 11 | 1 |
| 2 路组相联 | 4 × 2 | 2 | 12 | 2 |
| 全相联 | 1 × 8 | 0 | 14 | 8 |

规则：**标记位数 = 主存块号位数 − 组号位数**，三段相加 = 主存地址总位数。直接映像是"组数拉满"，全相联是"组数为 1"：组越多，组号越长、标记越短、比较越少越快，但冲突越多。

## 五、替换算法

### 5.1 四种算法（概念）

目标：使 Cache 获得**尽可能高的命中率**。

| 算法 | 换出谁 |
|---|---|
| 随机替换 | 随机数发生器产生的块号；实现最简单 |
| 先进先出（FIFO） | **最先进入** Cache 的块；不看最近是否在用 |
| 近期最少使用（LRU） | **近期最少使用**的块；理由是时间局部性 |
| 优化替换 | 须**先执行一次程序**统计替换情况，第二次执行才能最有效替换；要预知未来，只作衡量其他算法的**理论上限** |

### 5.2 FIFO 与 LRU 走表（计算）

Cache 临时缩到 3 块（8 块要十几次才装满，看不出替换）、全相联，依次访问主存块 **1, 2, 3, 1, 2, 4, 1, 2**：

| 次 | 块 | FIFO 内容 | FIFO | LRU 内容 | LRU |
|---|---|---|---|---|---|
| 1 | 1 | 1 | 未命中 | 1 | 未命中 |
| 2 | 2 | 1,2 | 未命中 | 1,2 | 未命中 |
| 3 | 3 | 1,2,3 | 未命中 | 1,2,3 | 未命中 |
| 4 | 1 | 1,2,3 | 命中 | 1,2,3 | 命中 |
| 5 | 2 | 1,2,3 | 命中 | 1,2,3 | 命中 |
| 6 | 4 | 2,3,4 | 未命中，**换出 1** | 1,2,4 | 未命中，**换出 3** |
| 7 | 1 | 1,3,4 | 未命中，换出 2 | 1,2,4 | **命中** |
| 8 | 2 | 1,2,4 | 未命中，换出 3 | 1,2,4 | **命中** |

**FIFO 2/8 = 25%，LRU 4/8 = 50%**。分歧在第 6 次：FIFO 看**进入顺序**，扔掉刚用过的热点 1；LRU 看**最近使用顺序**，扔掉最久没碰的 3。这条序列的优化替换上限也是 4 次命中，LRU 已达最优。

## 六、命中率与平均访存时间（计算）

**命中率 H**＝访问落在 Cache 上的比例；**1 − H** 叫失效率（缺失率），给的是失效率时先做 H = 1 − 失效率。

**算例**：Tc = 20ns，Tm = 200ns，H = 90%，按访问 100 次数：

```
命中   90 次 × 20ns  = 1800 ns
未命中 10 次 × 200ns = 2000 ns
             合计      3800 ns ÷ 100 = 38 ns
```

只占 10% 的未命中吃掉 2000/3800 ≈ **52.6%** 的时间。把"次数 ÷ 总次数"换成比例即得公式：

> **T = H × Tc + (1 − H) × Tm**（命中配 Cache，未命中配主存；百分数先化小数）
> 0.9×20 + 0.1×200 = 18 + 20 = **38ns**

**第二组数**（培训资料 3-4 节，原文只列式未算）：Tc = 1ns，Tm = 1000ns，H = 90%：`90%×1 + 10%×1000` = **100.9ns**。同样 90%，前者 T 是 Tc 的 1.9 倍，这里是 100.9 倍——差在 Tm/Tc（10 倍 vs 1000 倍）：**主存越慢，未命中越致命**。注：该例的 1000 倍是为放大差距设的，与 3-2 节"Cache 速度为内存 5–10 倍"口径不同，计算一律按给定数字。

**自查**：① T 是加权平均，必落在 Tc 与 Tm 之间；② H 越大越靠近 Tc。38 在 20～200 且偏向 20 ✓。

**并行与串行**

| 口径 | 适用 | 公式 | 本例 |
|---|---|---|---|
| **并行**（默认） | 同时启动 Cache 查找和主存访问；只给 Tc、Tm、H，未描述访问过程 | T = H×Tc + (1−H)×Tm | 38 ns |
| **串行** | 明确描述"先访问 Cache，未命中再访问主存" | T = H×Tc + (1−H)×(Tc+Tm) = **Tc + (1−H)×Tm** | 0.9×20 + 0.1×220 = 40 ns |

两者差 **(1 − H) × Tc**，本例 2ns。没有先后过程描述时，未命中项不加 Tc。

**反求命中率**：给平均时间上限求最低 H，把原式解开：

```
T = Tm − H×(Tm − Tc)   ⇒   H = (Tm − T) / (Tm − Tc)
T ≤ 40ns：H ≥ (200 − 40)/(200 − 20) = 160/180 = 88.89%
回代：0.8889×20 + 0.1111×200 ≈ 40 ✓
```

方向：**要求越快，所需命中率越高**；分子写成 (T − Tc) 就反了。

## 速记

- 分层解决**容量、成本、速度**矛盾；寄存器→Cache→主存→外存，**速度↓ 容量↑ 每位价格↓ 访问频度↓**
- **Cache–主存**：硬件、对程序员透明；**主存–辅存**：硬件＋操作系统＝**虚拟存储体系**
- 局部性：**反复用同一个＝时间**，**挨着依次来＝空间**
- 地址映像**由硬件自动完成**；**标记 = 主存块号位数 − 组号位数**，三段相加 = 地址总位数
- 块冲突 **直接 > 组相联 > 全相联**；变换复杂度倒过来
- 替换：随机、FIFO（最早进来）、**LRU**（最久没碰）、优化替换（先跑一遍，理论上限）
- **并行 T = H×Tc + (1−H)×Tm**（默认）；串行 **T = Tc + (1−H)×Tm**，差 (1−H)×Tc
- 反解 **H = (Tm − T)/(Tm − Tc)**；T 必在 Tc～Tm 之间，算不动就数 100 次
