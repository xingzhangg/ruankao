# 50 · 下午题 2：数据库设计实战

## 定位

下午试题二（数据库设计，15 分必答）：一段业务需求 + 一张残缺的 E-R 图 + 一组残缺的关系模式，三问依次是补 E-R 图、补关系模式（含主外键）、按新需求改图改模式。不用算、不写 SQL；转换规则的来由在讲义 30，候选码与范式在 31/32，SQL 在 33。第一节认符号，第二节是解题步骤，第三节是新增需求的改法。

## 一、题面结构与符号

| 形状 / 写法 | 是什么 |
|---|---|
| 长方形 | **实体**：客观存在、能相互区别的东西（员工、商品） |
| 椭圆 | **属性**：实体或联系的特性。多数情况下不画，改在需求里用文字列属性，要补属性时才画 |
| 菱形，两端标 `1` / `*` | **联系**。`*`＝多个；`1 … *` 即 1:N，`* … *` 即 M:N，与上午题的 `1:1／1:N／M:N` 是同一件事的两种写法 |
| 双线长方形 | **弱实体**：依赖强实体才有意义（顾客地址离开顾客没有主人）。通过**弱联系**（双线菱形）挂到它依赖的强实体上，照常标联系类型，一般强实体端 `1`、弱实体端 `*` |
| 把"实体—菱形—实体"整片框住的大矩形 | **聚合**：这一片合起来当一个东西，别的联系连的是整块，不是框里某个实体 |
| `表名(属性1，属性2，…)` | **关系模式**：以名称和属性名表示一个关系 |
| 下划线 / 属性名后加 `#` | 主键 / 外键 |

原话｜主键：不能为空，能唯一标识当前关系的属性。外键：其他关系模式的主键或者为空；外键可以有多个。

本篇文本记号：`[实体]`、`[[弱实体]]`、`〈联系〉`、`(属性)`、`┌聚合┐`；紧挨哪个框写的 `1` 或 `*` 就是那一端的标注。

三问形态固定：①补充 E-R 图；②补充关系模式（有时附"及完整性约束"，即各表主键、外键）；③情景问答——给一段新需求，要求新增实体/联系并改关系模式。有时把"主键、外键"单拎成一问，共四问，内容不变。第 1 问是重中之重：图连错，后两问跟着错。

## 二、解题步骤

1. **先读关系模式，再看图。** 关系模式和 E-R 图是同一件事的两种写法，互为答案：图上缺的，关系模式里往往已写着。**联系表里有几个外键，图上那个菱形就该连几条边、连到谁**。图与给出的关系模式对不上时，以给出的关系模式为准。
2. **数图上零件**：几个实体、几个菱形，哪些已连、哪些孤立。两个同名菱形不是印重——例：`[A公司] 1 ──〈管理〉── * [员工]` 已连，另一个〈管理〉孤立，需求写"统一管理 A 公司和 B 公司的员工"，则它连 B 公司和员工。
3. **补图——先定连谁。** 看需求里一句话同时点了几方：两方＝二元联系；三方且缺一方这件事就不成立＝**三元联系**（三个实体连同一个菱形）。例："由一位教练在某门店为会员安排一节私教课"→〈私教课〉连教练、门店、会员三端。
4. **补图——再定标注。** 口诀：**把另一头定死一个，这一头最多能有几个，就写在这一头。** 二元问两遍，三元问三遍（"另一头"换成"另外两头"）。
   - 例：`[部门] ? ──〈属于〉── ? [员工]`。定死一个部门→员工多个→`*` 写在员工端；定死一个员工→需求给的是"所属部门号"，只属一个→`1` 写在部门端。结果 `[部门] 1 ──〈属于〉── * [员工]`。
   - 需求里的数量词直接对应标注："若干/多个"→`*`，"一个/一位/只属于一个"→`1`。
   - 常见颠倒：心里念"一个部门多个员工"就把 `*` 写到部门端。`*` 永远落在"多"的那一端。
5. **补图后自查。** ①原来两个实体之间的联系必须还在，能从一端查到另一端；②补的边数常与该问分值一致（二元联系一行算两条边），对不上多半漏了；③有聚合时，连线接在聚合大框上。
6. **补关系模式——先对齐。** 把需求里"××信息包括……"那句与给出的关系模式逐字对齐，缺哪个补哪个。例：需求"员工信息包括工号、姓名、所属部门号和一个手机号"，给出 `员工(工号，姓名，(a)，手机号)`→(a)＝所属部门号。
7. **补关系模式——对齐之后还缺，才套转换规则。** 顺序不能反，否则会把已经印好的列重复写一遍。

   | 联系类型 | 怎么落表 | 联系的属性放哪 |
   |---|---|---|
   | 实体 | 各成一表 | — |
   | 1:1 | 并进任意一端，放另一端的主键 | 跟着并进去的那端 |
   | 1:N | 把 1 端的主键放进 N 端 | N 端表 |
   | M:N | 单独建表，放齐两端主键 | 这张联系表 |
   | 三元（多元） | 单独建表，放齐各端主键 | 这张联系表 |
   | 连聚合的联系 | 放聚合那一块的主键 | 这张联系表 |

   例：需求"团课包括课程编号、课程名称和时长；一门团课由一位教练开设"，给出 `团课(课程编号，课程名称，时长，(b))`。对齐给不出答案，"开设"是 1:N，教练是 1 端→(b)＝教练工号。
   若某联系表要细到"一份订单里的某个商品由谁采购"，则除了订单号还要放商品条码——落表的粒度跟着需求里"分开记"的那一层走。
8. **定主键——先排两三行数据试重复。** 把需求里的"若干/多个"代进表里排几行，看打算当主键的那一列会不会重复。例：`选课(学号，课程号，成绩)`，一个学生选多门课：

   ```
   学号  课程号  成绩
   S1    C1      90
   S1    C2      85     ← 同一学生第二门课
   S2    C1      70
   ```
   学号重复、课程号也重复→主键是（学号，课程号）。反过来，"一个部门有多名员工"不等于员工表要组合主键——员工号不重复，照样单列。M:N 与三元联系转来的表通常是组合主键。
9. **写外键——写全。** 一列可以既是主键的一部分又是外键，两处都要写。外键用 `#` 或"外键：×××"标明。互验：联系表有 n 个外键，图上菱形就连 n 条边。

## 三、新增需求：改 E-R 与关系模式

先答"要不要新增实体"，再给理由和改动。判据是**新属性依赖谁**：

| 新属性依赖 | 改法 |
|---|---|
| 某一对（或几方）实体的组合，如"哪个学生在哪门课上的成绩" | **不新增实体**。属性椭圆连到它们之间的**联系菱形**上（联系也可以带属性，连到某个实体上是错的）；在该联系表末尾加这两列，写出改后的整条关系模式 |
| 某个实体自身，但一个实体可以有多组，如"顾客可保存多个收货地址""会员可登记多个紧急联系人" | **新增弱实体**（双线长方形），挂到强实体上，强实体端 `1`、弱实体端 `*`；弱实体的关系模式主键**必须含强实体的主键**，如 `紧急联系人(会员卡号#，联系人序号，姓名，电话)`，主键（会员卡号，联系人序号），否则两位会员的"1 号联系人"分不开 |
| 新属性被别的联系引用（如运送要指定送到哪个地址） | 在引用它的联系表里加外键，如 `运送(…，顾客地址#，…)`；原有外键若需求仍要用到就保留 |

菱形起什么名字不影响结果（写"联系"两个字也行）。这一问的要点就三块：要不要新增的结论、图上挂对位置、改后的关系模式写完整。

作答要点：补空只写要填的词，不重抄整行；几分写几条，可以多写，但每条都要能指到需求里的一句原话；补 E-R 图须在图上作答（机考怎么画，讲义 48 列为待确认）。

## 速记

- 先读关系模式再看图：联系表几个外键，菱形就连几条边；两者冲突以关系模式为准
- 一句话同时点了三方且缺一不可＝三元联系；聚合的连线接整块
- 标注口诀：另一头定死一个，这一头最多几个，写在这一头；二元问两遍、三元问三遍
- 补空两步：先逐字对齐"××信息包括……"，还缺再套规则（1:1 并任一端；1:N 放进 N 端；M:N、三元单独建表放齐各端主键）
- 主键先排两三行数据试重复；外键写全，主键里的列也可能同时是外键
- 新属性依赖一对实体→挂到联系菱形上、加进联系表；一个实体可有多组→新增弱实体
- 弱实体＝双线长方形，经弱联系（双线菱形）挂到强实体，强端 `1`、弱端 `*`；主键必含强实体主键
