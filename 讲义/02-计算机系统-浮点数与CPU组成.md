# 02 · 计算机系统：浮点数与 CPU 组成

> 真题：浮点数 2022下/2024上/2025上、CPU 组成（PC 职责）2021上/2024上；部件细分职责年份待核实｜有计算（对阶），阶段B｜已讲 2026-08-04

## 第 0 层 · 定位

**这一课回答**：小数怎么装进 0/1（浮点数的阶码与尾数、对阶四步），以及 CPU 里到底是哪个部件在算（运算器/控制器各部件职责）。

**前后关系**：承接 01 的整数表示；「取指→译码→执行」三步是 03 寻址方式和 06 流水线的地基。

**分值与去向**：板块 5–7 分，本课约 2 分；下午不考。浮点对阶要算（阶段B），CPU 组成靠一张表加口诀。

## 第 1 层 · 理解

### 一句话

> 上一课把整数塞进了定长的 0/1；这一课先让**小数点"浮"起来**，把「能表示多大」和「能表示多准」拆成两笔账分开管（浮点数）；然后翻到硬件那一面——**到底是哪个部件在执行这些运算，又是谁在指挥它**（CPU 的运算器与控制器）。

### 痛点：范围和精度在抢同一批比特

假设给你固定的 32 个比特，小数点位置**钉死**在中间（定点数）：

- 想表示 10²⁰ 这么大的数？**没戏**，整数部分的位数是固定的。
- 想表示 0.000000001 这么小的数？**精度全丢**，小数部分的位数也是固定的。
- 想两样都要？**位数不够分**——范围和精度在抢同一批比特，此消彼长。

**程序员的共鸣点**：`float` 明明能表示到 3.4×10³⁸ 这么大，为什么还"不精确"？因为它的 32 位是**分账**的——8 位阶码买了**范围**，23 位尾数买了**精度**，谁也不能白拿。你要更准就得换 `double`（阶码 11 位、尾数 52 位），拿更多比特分别加钱。

再往下一层：**这些运算最终是哪个部件在做？** 溢出了你怎么知道？——答案就是 CPU 里那个 **PSW 状态字寄存器**的溢出标志位。面试常问的"怎么检测整数溢出"，硬件层面就是读它。

**最容易拍脑袋拍错的四处**：

1. 对阶时**尾数左移**：只要是"尾数左移"就一定错——左移会把最高有效位挤出去，结果彻底作废（**用户 2026-08-05 正是栽在移位方向上：选了 C「小阶向大阶、尾数左移」，对阶方向答对、移位方向记反，错题本 #004**）
2. 以为"**阶码位数增加 → 精度提高**"——错，阶码管的是**范围**
3. **PC 和 IR 混淆**——PC 存的是**下一条指令的地址**，IR 存的是**当前指令本身**
4. 把 **PSW 归到控制器**——教程把它归在**运算器**

### 一条主线

```
第1课的定点数：小数点位置钉死 → 范围和精度抢同一批比特，互相挤压
   ↓ 借用科学计数法的思路：让小数点"浮"起来
【浮点数】N = 尾数 M × 2^阶码 E   —— 一笔钱拆成两笔账
        阶码 E 管【范围】：位数越多，能表示的数越大 / 越小
                 常用【移码】表示，为的是能当无符号数直接比大小
                 ← 第1课学的移码，就是在这儿派上用场的
        尾数 M 管【精度】：位数越多，有效数字越多
                 常用原码 / 补码表示
   ↓ 新麻烦：同一个数写法不唯一（0.1011×2³ = 0.01011×2⁴ = 0.001011×2⁵ = …）
【规格化】强制把尾数写成 0.1xxx（即 1/2 ≤ |M| < 1）
        好处一：表示唯一，机器不会为同一个数产生多种编码
        好处二：最高位一定是有效数字 1，不浪费尾数位（不浪费 = 精度最大化）
   ↓ 再一个麻烦：两个浮点数阶码不同时，尾数根本不能直接对位相加
       （0.101×2³ 和 0.110×2¹，小数点的"实际位置"不在一处）
【浮点加减四步】对阶 → 尾数运算 → 结果规格化 → 舍入与溢出判断
        为什么必须"小阶向大阶看齐、尾数右移"：
           右移丢掉的是【低位】→ 只损失一点精度，结果仍然近似正确
           若反过来大阶向小阶、尾数左移 → 挤掉的是【最高有效位】→ 结果直接错
        第③步为什么还要再规格化一次：相加可能进位溢出、相减可能高位变 0，都破坏了 0.1xxx 形式
   ↓ 关键一问：这四步不是纸上算法，得有真实硬件去执行 —— 谁执行、谁指挥？
【CPU 组成】按"干活的"和"指挥的"拆成两半，各自设计更简单、也更容易并行提速：
        ▸ 运算器 = 干活的
             ALU  真正做移位（对阶）和相加（尾数运算）
             AC   累加器，暂存操作数与中间结果
             DR   数据缓冲寄存器，内存 ↔ CPU 的数据中转站
             PSW  程序状态字，记进位 / 溢出 / 零等标志
                  ←【浮点第④步"溢出判断"落到硬件上，就是这里的一个标志位】
        ▸ 控制器 = 指挥的
             PC   程序计数器，存【下一条】指令的【地址】，取指后自动 +1
             IR   指令寄存器，存【当前正在执行】的指令本身
             ID   指令译码器，翻译 IR 里的操作码，决定"这条指令要干什么"
             AR   地址寄存器，存要访问的内存地址
             时序部件  打拍子，决定"每一步什么时候发生"
   ↓ 两边怎么配合？
【指令执行三步】取指（按 PC 从内存取指令放进 IR，PC 自动 +1）
             → 分析（ID 译码，看懂要干什么）
             → 执行（指挥 ALU 运算 / 访存）
        —— 这三步就是第3课"寻址方式"和第6课"流水线"的起点：
           流水线做的事，就是把这三步拆开、让多条指令重叠着走
```

## 第 2 层 · 考点：考试怎么问

### 考点① 对阶原则（最高频陷阱，用户已错过一次）

**题目长相**：
> "浮点数相加时需先对阶，对阶的原则是（ ）。A.大阶向小阶看齐，尾数左移　B.小阶向大阶看齐，尾数右移　C.小阶向大阶看齐，尾数左移　D.大阶向小阶看齐，尾数右移"

四个选项就是"向大 / 向小"× "左移 / 右移"的全排列，**必须两个都答对**。

**怎么解**：**小阶向大阶看齐，尾数右移**。

配套的一句话理由（记住理由就不会记反）：**阶码调大几位，尾数就得右移几位来补偿**——因为 M×2^E 的乘积要保持不变，E 变大，M 就必须变小。
十进制类比最好使：`0.65×10¹ = 0.065×10²`，**阶码变大，数字往右挪**。

**陷阱**：
- ⚠️ **两个"尾数左移"选项（A、C）都是坑**，其中 **C「小阶向大阶看齐、尾数左移」最阴险**——它把对阶方向写对了，只在移位方向上下套，**用户 2026-08-05 选的正是 C**（错题本 #004）。为什么左移绝对不行：左移会把尾数的**最高有效位**顶出寄存器，那是数值最大的一部分，丢了结果就彻底错；而右移丢的是**低位**，只损失一点点精度。
- ⚠️ 记法要连着记：**"向大 + 右移"是一对**，拆开单记就容易错配。

### 考点② 阶码 vs 尾数的分工（范围 / 精度）

**题目长相**：
> "关于浮点数表示，正确的是（ ）。A.阶码位数增加，精度提高　B.尾数位数增加，范围扩大　C.阶码位数增加，范围扩大　D.尾数位数增加，范围缩小"

**怎么解**：一句话——**阶码定范围，尾数定精度**。

- 阶码 E 是 2 的指数，指数每多一位，能表示的数量级就翻倍 → 管**范围**
- 尾数 M 是有效数字本身，多一位就多一位有效数字 → 管**精度**

**陷阱**：
- ⚠️ 出题人就是把"阶码/尾数"和"范围/精度"**交叉配错**来设选项，四个选项里通常只有一个配对正确。做题时先在草稿上写下"阶=范围，尾=精度"再逐项对，不要凭语感。
- ⚠️ 变体问法："欲扩大浮点数的表示范围，应该增加（ ）的位数" → 答**阶码**。

### 考点③ 浮点加减四步的顺序

**题目长相**：
> "浮点数加减运算的正确步骤是（ ）"，四个选项是四步的不同排列。

**怎么解**：**对阶 → 尾数运算 → 结果规格化 → 舍入与溢出判断**。

每一步为什么在这个位置（顺序是被逻辑决定的，不是硬背的）：
1. **对阶**必须最先——阶码不一致，尾数根本不能对位相加
2. **尾数运算**——阶码统一之后才谈得上加减
3. **结果规格化**——相加可能进位（尾数溢出到整数位）、相减可能高位归零，都破坏了 `0.1xxx` 形式，得调回来
4. **舍入与溢出判断**——规格化过程中右移会丢位，需要舍入；阶码调整后可能超出阶码能表示的范围，这才判上溢/下溢

**陷阱**：
- ⚠️ 把"规格化"放到"对阶"之前——错，参与运算的数本来就已经是规格化的，需要重新规格化的是**运算结果**。
- ⚠️ 漏掉第 4 步，或把"溢出判断"提前。

### 考点④ PC 与 IR 的职责区分【真题·2021上 有据】

**题目长相**：
> "在 CPU 中，用于跟踪下一条要执行指令地址的寄存器是（ ）。A.指令寄存器 IR　B.程序计数器 PC　C.累加器 AC　D.地址寄存器 AR"

**怎么解**：

| 寄存器 | 存的是什么 | 一句话 |
|---|---|---|
| **PC 程序计数器** | **下一条**要执行指令的**地址** | 指路的，取指后**自动 +1** |
| **IR 指令寄存器** | **当前正在执行**的指令**本身**（指令内容） | 手上正在办的那张单子 |
| AR 地址寄存器 | 要访问的**内存单元地址**（数据地址） | 访存时用 |
| AC 累加器 | 操作数和运算结果（**属运算器**） | 干活的草稿纸 |

**陷阱**：
- ⚠️ **PC 存"地址"，IR 存"内容"**——最经典的一对混淆项。题干出现"**地址**"就往 PC / AR 上想，出现"**指令本身 / 正在执行的指令**"就选 IR。
- ⚠️ **PC 和 AR 都存地址，怎么分**：PC 存的是**指令的**地址，AR 存的是**要访问的数据（或指令）单元**地址，题干里的"下一条要执行的指令"是 PC 的独家标志词。
- ⚠️ 关于命题形式的诚实说明：**PC 的职责本身是高频考点【真题·2021上/2024上】**；但"PC / IR 对比型设错项"这种具体命题形式**未查到确切原题**，属合理推断，**非直接证实**（沿用 2026-08-14 核实结论）。

### 考点⑤ 部件归属：运算器还是控制器

**题目长相**：
> "下列部件中，不属于运算器的是（ ）"，或"CPU 中的（ ）负责产生节拍信号"。

**怎么解**：背这两张表 + 一句口诀。

**运算器**（负责执行算术 / 逻辑运算）：

| 部件 | 职责 |
|---|---|
| ALU 算术逻辑单元 | 加减乘除、与或非 |
| AC 累加器 | 暂存操作数和运算结果 |
| DR 数据缓冲寄存器 | 内存 ↔ CPU 之间数据的中转站 |
| **PSW 程序状态字** | 进位、溢出、零等标志位（**属运算器**，易错点，**以教程为准**） |

**控制器**（负责指挥全机）：

| 部件 | 职责 |
|---|---|
| PC 程序计数器 | 存**下一条**要执行指令的**地址**，取指后自动 +1 |
| IR 指令寄存器 | 存**当前正在执行**的指令本身 |
| ID 指令译码器 | 翻译 IR 中的**操作码** |
| AR 地址寄存器 | 存要访问的内存地址 |
| 时序部件 | 产生节拍信号 |

整体结构：**CPU = 运算器 + 控制器 + 寄存器组 + 内部总线**。

**陷阱**：
- ⚠️ **PSW 最容易被划到控制器**（因为"状态"听起来像管理职能）。记住：它记录的是**运算结果**的进位/溢出/零，所以跟着运算器走。
- ⚠️ **ID 指令译码器只翻译"操作码"**，不负责取操作数、更不负责运算。
- ⚠️ "产生节拍信号"是**时序部件**，不是 ID、不是 PC。

### 考点⑥ 规格化尾数的形式

**题目长相**：
> "浮点数的尾数采用规格化表示，其目的是（ ）"，或"下列尾数中，属于规格化形式的是（ ）"。

**怎么解**：规格化尾数写成 **`0.1xxx…`**，即 **1/2 ≤ |M| < 1**（最高有效位必须是 1）。目的有两条：**① 表示唯一 ② 不浪费尾数位，精度最大化**。

> 补充（教程第5版，了解层面）：上面说的 `0.1xxx` 是**原码表示的尾数**的规格化形式；若尾数用**补码**表示，规格化的判据是**符号位与最高数值位相反**。软考中级以原码形式的判据为主。

**陷阱**：
- ⚠️ **规格化和 IEEE 754 的形式不一样**，别串：软考常规讲法是 `0.1xxx × 2^E`；**IEEE 754 是 `1.xxx × 2^E`，且那个最高位的 1 是隐含的、不存储**。题干说"隐含位"就是在问 IEEE 754。
- ⚠️ 目的问成"提高运算速度"是错的，规格化的目的是**唯一性 + 精度**。

### 考点⑦ IEEE 754 单精度格式（了解层面，偶考）

**题目长相**：
> "IEEE 754 单精度浮点数的阶码采用移码表示，其偏移量是（ ）"、"IEEE 754 中尾数隐含的是（ ）"。

**怎么解**：单精度共 32 位，分三段：

| 符号 | 阶码 | 尾数 |
|---|---|---|
| 1 位 | 8 位（存的是「真实阶码 + **127**」） | 23 位（`1.M` 里 M 的部分，**最高位的 1 隐含不存**） |

**陷阱**：
- ⚠️ 最常问的两点就是：**隐含的是什么**（尾数最高位的那个 1）、**偏移量是多少**（单精度 **127**）。
- ⚠️ 别把偏移量 127 记成 128。

## 第 3 层 · 完整算例

### 算例 1：把 5.5 化成规格化浮点形式

```
① 十进制 → 二进制：5.5 的整数部分 5 = 101；小数部分 0.5 = .1
   → 5.5 = 101.1 ₂
② 规格化 = 把小数点挪到最高有效位 1 的【左边】，挪几位阶码就加几：
   101.1 → 小数点左移 3 位 → 0.1011，阶码 = 3
   → 5.5 = 0.1011 × 2³
```
**验算习惯**：把结果乘回去 —— `0.1011`₂ = 0.5+0.125+0.0625 = 0.6875；0.6875 × 2³ = 0.6875 × 8 = **5.5** ✓

### 算例 2：浮点加法完整四步（0.101×2³ + 0.110×2¹）

先把两个数换算成十进制，方便最后验算：`0.101`₂=0.625 → 0.625×2³ = **5**；`0.110`₂=0.75 → 0.75×2¹ = **1.5**。预期结果 **6.5**。

```
① 对阶：两个阶码是 3 和 1，小阶(2¹) 向大阶(2³) 看齐
        阶码从 1 调到 3，调大了 2 → 尾数必须【右移 2 位】补偿
        0.110 × 2¹  →  0.00110 × 2³
        （校验这一步：0.00110₂ = 0.1875，0.1875 × 8 = 1.5 ✓ 数值没变，只是换了写法）

② 尾数相加：两数现在同阶，尾数可以直接对位相加
          0.10100      ← 0.101 补齐到 5 位小数
        + 0.00110
        ---------
          0.11010

③ 结果规格化：0.11010 的最高位已经是 1，符合 0.1xxx 形式，无需调整
        （若相加进位成 1.xxxx，要尾数右移 1 位、阶码 +1；
          若相减后变成 0.0xxx，要尾数左移、阶码相应减）

④ 舍入与溢出判断：本例尾数没有超出字长、阶码 3 也在范围内，无需舍入、无溢出

结果 = 0.11010 × 2³ = 0.1101 × 2³
```
**验算习惯**：把结果换回十进制对答案 —— `0.1101`₂ = 0.5+0.25+0.0625 = 0.8125；0.8125 × 2³ = 0.8125 × 8 = **6.5**。与预期的 5 + 1.5 = 6.5 **一致 ✓**

### 算例 3：IEEE 754 单精度表示 -12.5

```
① 符号：负数 → 符号位 S = 1
② 数值 → 二进制：12.5 = 8+4+0.5 → 1100.1 ₂
③ 化成 IEEE 754 要求的 1.xxx 形式（注意不是 0.1xxx）：
   1100.1 → 小数点左移 3 位 → 1.1001 × 2³   → 真实阶码 e = 3
④ 阶码域 = 真实阶码 + 偏移量 127 = 3 + 127 = 130
   130 → 二进制 8 位 = 1000 0010
⑤ 尾数域 = 取 1.1001 中【小数点后面】的部分 = 1001，右侧补 0 补满 23 位
   （最高位那个 1 是隐含的，不存储）
   → 1001 0000 0000 0000 0000 000

⑥ 拼装（1 + 8 + 23 = 32 位）：
   1 | 1000 0010 | 1001 0000 0000 0000 0000 000
   按 4 位一组重排 → 1100 0001 0100 1000 0000 0000 0000 0000
                   →   C    1    4    8    0    0    0    0
   = 0xC1480000
```
**验算习惯**：反着解一遍 —— 阶码域 `1000 0010` = 130，减偏移 127 得真实阶码 3；尾数域 `1001…` 前面补回隐含的 1 得 `1.1001`；`1.1001`₂ = 1.5625，1.5625 × 2³ = 12.5，符号位 1 → **-12.5** ✓

**考试实际问的**：一般不让你拼完整 32 位，而是问**隐含的是什么**（尾数最高位的 1）、**偏移量是多少**（127）。

## 第 4 层 · 速记

> **浮点数**
> - 浮点数 N = 尾数 × 2^阶码；**阶码定范围，尾数定精度**
> - 规格化尾数：`0.1xxx…`（1/2 ≤ |尾数| < 1）；**IEEE 754 是 `1.xxx` 且最高位 1 隐含不存**
> - 浮点加减四步：**对阶 → 尾数运算 → 规格化 → 舍入/溢出**
> - 对阶原则：**小阶向大阶看齐，尾数右移**（右移丢低位，损失小；左移丢最高位，结果全错）
> - 十进制记法助记：`0.65×10¹ = 0.065×10²`——**阶码变大，数字右挪**
> - IEEE 754 单精度：1 位符号 + 8 位阶码（偏移 **127**）+ 23 位尾数
>
> **CPU 组成**
> - CPU = **运算器 + 控制器** + 寄存器组 + 内部总线
> - 运算器四件套：**ALU、AC 累加器、DR 数据缓冲寄存器、PSW 状态字**（**PSW 属运算器——易错！**）
> - 控制器五件套：**PC、IR、ID 译码器、AR 地址寄存器、时序部件**
> - **PC 存下一条指令的地址**（取指后自动 +1）；**IR 存当前正在执行的指令本身**；ID 只翻译操作码；时序部件打拍子
> - 指令执行三步：**取指 → 分析（译码）→ 执行**
> - 口诀：**算累数状归运算；程指译址时序管控制**
>   （ALU / AC / DR / PSW → 运算器；PC / IR / ID / AR / 时序 → 控制器）

**解**：**B**。小阶向大阶看齐；阶码调大 n，尾数就右移 n 位作补偿（保持 M×2^E 不变）。记法：十进制 `0.65×10¹ = 0.065×10²`，**阶码变大、数字右挪**。凡是"尾数左移"的选项（A、C）都致命：左移会把尾数的最高有效位挤出去，结果彻底错，而右移只丢低位。**用户当时选的是 C**——对阶方向答对了，栽在移位方向上（错题本 #004）。

## 自测练习

1. 【模拟】把十进制 6.25 写成规格化浮点形式 `0.1xxx × 2^E`，并说明 E 是多少。
2. 【模拟】计算 `0.1100 × 2² + 0.1000 × 2⁰`，写出对阶、尾数相加、规格化三步，并用十进制验算结果。
3. 【模拟】下列部件中，**不属于**控制器的是（ ）A. 指令译码器 ID　B. 程序状态字 PSW　C. 程序计数器 PC　D. 时序部件

### 参考答案

1. **6.25 = 110.01₂ → 0.11001 × 2³，E = 3**。步骤：整数 6 = 110，小数 0.25 = .01 → 110.01；小数点左移 3 位到最高有效位 1 的左边，阶码就取 3。**验算**：`0.11001`₂ = 0.5+0.25+0.03125 = 0.78125，×2³ = **6.25** ✓
2. **结果 = 0.1110 × 2²（十进制 3.5）**。
   ① 对阶：小阶 2⁰ 向大阶 2² 看齐，阶码调大 2 → 尾数右移 2 位：`0.1000 × 2⁰ → 0.001000 × 2²`；
   ② 尾数相加：`0.110000 + 0.001000 = 0.111000`；
   ③ 规格化：最高位已是 1，无需调整 → `0.1110 × 2²`。
   **验算**：`0.1100`₂=0.75，×2²=3；`0.1000`₂=0.5，×2⁰=0.5；3+0.5=**3.5**。而 `0.1110`₂=0.875，×2²=**3.5** ✓
3. **B**。**PSW 程序状态字属于运算器**（它记录的是运算结果的进位/溢出/零标志），ID、PC、时序部件都属控制器。口诀对照：**算累数状归运算**（ALU/AC/DR/PSW），**程指译址时序管控制**（PC/IR/ID/AR/时序）。
