## 第 1 层 · 理解

### 一句话

> 栈和队列不是新结构，是给线性表装上闸门——**只准从这头进、从那头出**。限制本身就是功能：它一次换来两样东西，**所有基本操作都变成 O(1)**，以及**一套天生自带的处理顺序**。

### 痛点：你早就在用，只是没把它当成"数据结构"

- 递归写深了报 `StackOverflowError`——**爆的就是这个栈**；函数调用一层层压入、返回时一层层弹出，正是 LIFO。
- 编辑器的 Undo：撤销的永远是**最近**那一步，不是最早那一步——这就是"后进先出"。
- 消息队列、线程池的任务队列、操作系统的作业调度：谁先来谁先被处理——"先进先出"。
- 用数组手写一个队列，`head` 一直往后爬，前面出队腾出的格子再也用不上，最后数组"满了"但其实前半段全是空的——这个坑有个正式名字，叫**假溢出**。

拍脑袋会错的地方：以为"出队要把后面所有元素往前挪，所以是 O(n)"（**错**，有队头指针就不用挪）；以为"出栈必须等所有元素都入栈完"（**错**，入栈出栈可以交替进行，这正是出栈序列判定题的全部玄机）。

### 一条主线

```
线性表太自由：任意位置都能插、都能删、都能查
   ↓ 自由的代价：想表达"该先处理谁"这类【顺序规则】，线性表一个字也说不出来
   ↓ 办法很土，就是把出入口【焊死】，只留端点：
        ├── 进和出都在【同一端】 ──→ 后进先出 LIFO ──→ 【栈】（一摞盘子）
        └── 一端进、【另一端】出 ──→ 先进先出 FIFO ──→ 【队列】（排队买票）
   ↓ 限制换来的红利①：只动端点，永远不用遍历
        入栈/出栈/入队/出队 全是 O(1)
        —— 顺序栈、链栈、顺序队列、链队列，四种实现【都一样】  ← 直接考点
   ↓ 限制换来的红利②：结构自带一套处理顺序，算法拿来就用
        栈 = "最近的先了结" → 函数调用栈、递归、括号匹配、表达式求值、DFS
        队列 = "先来先服务" → 缓冲区、作业/进程调度、BFS
   ↓ 但限制也有【副作用】，而考试考的恰恰就是这些副作用：
     副作用①：LIFO 反过来限死了元素【能以什么顺序离开】
               不是随便一个排列都凑得出来
               → 给你入栈序列 + 一个声称的出栈序列，判断可不可能
               → 解法只有一个：拿栈【模拟】一遍
     副作用②：栈能把"运算符优先级 / 括号嵌套"这种麻烦事，
               降级成"最近的先算"这种傻规则
               → 先把中缀表达式转成后缀（把优先级信息固化进顺序里）
               → 再用一个栈从左到右扫一遍就算完，不用再看优先级
     副作用③：队列用数组实现时，front 和 rear 只会【单向往后爬】
               → 前面出队腾出的格子再也用不上 → 明明有空位却报满 = 【假溢出】
               → 补救：让下标取模绕回开头 = 【循环队列】
               → 绕回来又生新麻烦：front == rear 时分不清"空"还是"满"
               → 再补救：牺牲一个存储单元不用，或者另加一个计数器
```

## 第 2 层 · 考点：考试怎么问

### 考点① 栈/队列的基本特性与操作复杂度（高频，含【真题·2025上】已核实考点）

**题目长相**：
> "关于顺序队列/链队列的入队、出队操作时间复杂度，下列正确的是（ ）"
> "栈的操作特点是（ ）" / "下列结构中，元素的插入和删除只能在同一端进行的是（ ）"

**怎么解**：
- **栈 Stack**：类比一摞盘子，只能从最上面拿、从最上面放——插入（push/入栈）和删除（pop/出栈）**只在栈顶**进行，最后进去的最先出来，即**后进先出 LIFO**（Last In First Out）。
- **队列 Queue**：类比排队买票，**队尾入队、队头出队**，即**先进先出 FIFO**。
- **复杂度**：只要维护了**队头指针和队尾指针**（栈则维护栈顶指针），入队就是在队尾直接挂一个元素，出队就是在队头直接摘一个元素——**都不需要遍历，全部 O(1)**。
- **实现无关**：顺序栈、链栈、顺序队列、链队列，四种实现的基本操作**都是 O(1)**。

**陷阱**：
- ❌"入队 O(1)、出队 O(n)"或反过来 —— 都是错的。出题人指望你以为"出队后要把后面的元素整体往前挪一格"，**有队头指针就根本不用挪**。
- ❌"队列只能用顺序存储" / "栈必须用数组实现" —— 两者都既可顺序存储也可链式存储。
- ⚠️ 顺序队列若**不做循环处理**，出队确实会浪费前段空间（假溢出），但那是**空间**问题，不是**时间复杂度**问题——别被绕进去。

### 考点② 出栈序列合法性判断（高频，对应已核实考点"栈的应用"）

**题目长相**：
> "元素 1,2,3,4 依次入栈，出栈序列**不可能**是（ ）"
> "已知入栈顺序为 a,b,c,d，判断 `xxxx` 是否为合法的出栈序列"

**为什么会考这个**：栈的"后进先出"天然**限制了元素能以什么顺序离开**——不是任意排列都能通过入栈出栈操作凑出来。这类题考的是你有没有真正理解这个约束，而不是会不会念"后进先出"四个字。

**怎么解**（唯一解法：用栈**模拟**）：
1. 按入栈顺序依次压栈；
2. 每压一个就检查：**栈顶元素是不是"当前需要弹出的下一个数"**，是就立刻弹；
3. 弹完继续压、继续查；
4. 如果需要弹某个数时，**栈顶不是它、而且已经没有元素可压了 → 卡住 → 不合法**；
5. 全部顺利弹完 → 合法。

**陷阱**：
- ❌ 以为"必须全部入栈完才能开始出栈" —— **入栈和出栈是可以交替进行的**，这正是 `2,4,3,1` 这种序列能成立的原因。
- ❌ 凭直觉判断 —— 直觉在 n=4 以上基本失效，**老老实实模拟，一步一行写出来**，考场上也就 20 秒。
- 关键识别信号：**一个较小的数被压在较大的数下面，却要求它先出来** → 必然不合法（如 `3,1,4,2`：弹了 3 之后，1 被压在 2 下面，不可能先于 2 出来）。
  > **把它变成一条不用模拟也能查的判据**（想快速排除选项时用）：在出栈序列里任取一个元素 x，**排在 x 后面、又比 x 小的那些元素，必须按从大到小的顺序出现**；只要出现一次"先小后大"，就不合法。
  > 道理：x 出栈那一刻，所有比 x 小、还没出栈的元素全都还压在栈里，且**入栈早的在下面**，所以只能自上而下、由大到小地弹。
  > 验一遍：`3,1,4,2` —— 取 x=3，后面比 3 小的是 `1, 2`，是"先小后大" → **不合法** ✓；`2,4,3,1` —— 取 x=4，后面比 4 小的是 `3, 1`，从大到小 ✓，其余元素同理 → **合法** ✓。
  > 稳妥起见，考场上仍以模拟为准，这条只当**快速筛选**用。

> 补充（原文件未含，属真实数学结论，**是否为本考试常考待核实**）：n 个不同元素依次入栈，可能的出栈序列共有 **C(2n, n) / (n+1)** 种（卡特兰数）——n=3 时 5 种，n=4 时 **14** 种。若题目问"共有多少种出栈序列"，用这个式子；问"下列哪个不可能"，仍然老实模拟。

### 考点③ 后缀表达式（逆波兰式）求值（高频计算类，阶段B）

**题目长相**：
> "后缀表达式 `3 4 2 × +` 的值是（ ）"
> "表达式 `a+b×c` 对应的后缀式是（ ）"
> "用栈对后缀表达式求值，运算数栈中**最多同时保存**（ ）个操作数"（"表达式求值中操作数个数"是 `计划/00-总体计划.md` 归入已核实考点"栈的应用"的一种问法，与出栈序列判定同源）

**为什么需要后缀表达式**：人写的是**中缀表达式**（如 `3+4×2`），要先看运算符优先级、可能还有括号，计算机从左到右扫一遍根本算不对（不知道该先算加还是先算乘）。**后缀表达式**把运算符挪到操作数后面（`3 4 2 × +`），好处是：**只要从左到右扫一遍，配合一个栈，完全不用再考虑优先级和括号**——优先级信息已经固化进符号的先后顺序里了。这是编译器/计算器内部实际算表达式的思路。

**怎么解（求值）**：
1. 从左到右扫描；
2. 遇**数字** → **压栈**；
3. 遇**运算符** → **弹出栈顶两个数**计算，**先弹出的是右操作数，后弹出的是左操作数**，结果**压回栈**；
4. 扫描结束，栈里剩下的唯一元素就是答案。

**怎么解（中缀 → 后缀，补充题型）**：按运算优先级给中缀表达式加满括号，再把每对括号里的运算符**移到该括号的右边**，最后去掉括号。
例：`a+b×c` → `a+(b×c)` → `a (b c ×) +` → **`a b c × +`**。
例：`(a+b)×c` → `(a b +) c ×` → **`a b + c ×`**。

**怎么解（变式：栈里最多同时存几个操作数）**：没有公式，就是**把求值过程走一遍，记录每一步栈内元素个数的最大值**。规律很土：遇数字栈深 +1，遇运算符弹二压一、栈深 −1，所以**最大深度出现在最长的一段连续数字之后**。

```
① 3 4 2 × +          ② 1 2 + 3 4 + ×      （= (1+2)×(3+4) = 21）
   3 → [3]      1        1 → [1]        1
   4 → [3,4]    2        2 → [1,2]      2
   2 → [3,4,2]  3 ←最大   + → [3]        1
   × → [3,8]    2        3 → [3,3]      2
   + → [11]     1        4 → [3,3,4]    3 ←最大
   最多 3 个              + → [3,7]      2
   （操作数总数也是 3）    × → [21]       1
                          最多 3 个，但操作数总数是 4 —— 两者不相等
```

**陷阱**：
- ❌ **左右操作数弄反**：对 `−` 和 `÷` 是致命的。`9 4 −` 算的是 **9−4=5**，不是 4−9；`8 2 ÷` 是 **8÷2=4**，不是 2÷8。记法：**后弹出的在前面（当左操作数）**。
- ❌ 把"**栈内最多同时存放的操作数个数**"和"**表达式里操作数的总个数**"当成一回事 —— 见上面例②，前者 3、后者 4。前者必须模拟着数栈深。
- ❌ **纯算术粗心**（本课已有前科：把 2+3 算成 6，见文末批改记录）——每一步把栈的内容抄在草稿上，别在脑子里过。
- ❌ 把后缀式当中缀读：`3 4 2 × +` 不是 `3×4+2`。
- ✅ **验算习惯**：算完把后缀式还原成中缀，用常规算术再算一遍对不对。

### 考点④ 循环队列（假溢出、队空/队满判定）

**题目长相**：
> "循环队列的队满条件是（ ）"
> "容量为 MaxSize 的循环队列，front 和 rear 分别为…，当前队列中元素个数为（ ）"

**怎么解**：
- **为什么要循环**：用顺序表（数组）实现队列时，队头出队腾出的位置如果不能复用，就会出现**假溢出**——明明前面有空位，却因为 rear 已经走到数组末尾而报"满"。循环队列用取模运算让下标**绕回数组开头**继续用空位。
- **指针推进**：入队 `rear = (rear + 1) % MaxSize`；出队 `front = (front + 1) % MaxSize`。
- **空满冲突**：绕回来之后，`front == rear` 既可能是空、也可能是满，**分不清**。两种标准解法：
  1. **牺牲一个存储单元**（最常考）：始终留一个格子不用。
     - **队空**：`front == rear`
     - **队满**：`(rear + 1) % MaxSize == front`
     - 此时实际最多只能存 `MaxSize − 1` 个元素。
  2. **另加一个计数器**记录元素个数：count == 0 为空，count == MaxSize 为满，此时 MaxSize 个格子都能用。
- **元素个数**（牺牲一个单元的约定下）：`(rear − front + MaxSize) % MaxSize`。

**陷阱**：
- ❌ 只写 `(rear+1) % MaxSize` 就说是"队满" —— **必须写成 `(rear+1) % MaxSize == front`**，而且这个判据**只在"牺牲一个单元"的约定下成立**（本次校订订正的就是这一处）。
- ❌ 忘了"牺牲一个单元"意味着**容量 MaxSize 的循环队列实际只能装 MaxSize − 1 个元素**——考题很爱问"最多能存多少个"。
- ❌ 算元素个数时忘了 `+ MaxSize` 再取模，rear < front 时会算出负数。

## 第 3 层 · 完整算例

### 算例 1：出栈序列合法（入栈 1,2,3,4，判断 `2,4,3,1`）

```
目标出栈序列：2 → 4 → 3 → 1

push 1, push 2  → 栈[1,2]，需要弹 2，栈顶 = 2 → pop 2 ✓   栈[1]
push 3, push 4  → 栈[1,3,4]，需要弹 4，栈顶 = 4 → pop 4 ✓  栈[1,3]
                  需要弹 3，栈顶 = 3 → pop 3 ✓             栈[1]
                  需要弹 1，栈顶 = 1 → pop 1 ✓             栈[]
全部匹配、栈空 → 【合法】
```
> 注意第 2 行：**弹出 2 之后又继续压 3、4**——入栈出栈交替进行，这就是考点②第一个陷阱说的事。

### 算例 2：出栈序列不合法（入栈 1,2,3,4，判断 `3,1,4,2`）

```
目标出栈序列：3 → 1 → 4 → 2

push 1,2,3 → 栈[1,2,3]，需要弹 3，栈顶 = 3 → pop 3 ✓   栈[1,2]
             需要弹 1，但栈顶是 2（1 被压在 2 下面，拿不到）
             想把 1 露出来就得先弹 2，可 2 还不该出去
             继续压 4 也没用（4 只会压得更深）
→ 卡住 → 【不合法】
```
**通用识别**：出栈序列里若出现"**某个小数排在压着它的大数前面**"（这里 1 排在 2 前面，而 1 比 2 先入栈、被 2 压住），必然不合法。

### 算例 3：后缀表达式求值 `3 4 2 × +`（对应中缀 `3+4×2`）

```
扫描 3 → 数字，压栈           栈 [3]
扫描 4 → 数字，压栈           栈 [3,4]
扫描 2 → 数字，压栈           栈 [3,4,2]
扫描 × → 弹出 2（右操作数）、弹出 4（左操作数）
         算 4 × 2 = 8，压回     栈 [3,8]
扫描 + → 弹出 8（右）、弹出 3（左）
         算 3 + 8 = 11，压回    栈 [11]
扫描结束，栈中唯一元素 = 11
验算：还原中缀 3 + 4×2 = 3 + 8 = 11 ✓
答案：11
```

### 算例 4：循环队列元素个数与空满判定

> 某循环队列容量 MaxSize = 6（采用"牺牲一个单元"的约定），当前 front = 1，rear = 4，求队中元素个数；再问什么情况下判定为队满。

```
第1步 元素个数 = (rear − front + MaxSize) % MaxSize
              = (4 − 1 + 6) % 6
              = 9 % 6
              = 3
第2步 手工核对：占用的下标是 1、2、3（front 指向队头元素，rear 指向下一个可写位置）
              共 3 个 ✓
第3步 队满判定：(rear + 1) % 6 == front 时为满
              若 front = 1，则 rear = 0 时满 —— 此时占用下标 1,2,3,4,5 共 5 个
              = MaxSize − 1 = 5 ✓（牺牲了下标 0 这一个单元）
答案：元素个数 3；队满时最多装 5 个
```
> 提醒：不同教材对 rear 的定义有两种（指向队尾元素 / 指向队尾下一个空位），**做题时先看题目给的入队语句**是"先移指针后写入"还是"先写入后移指针"，再决定用哪套公式。上式采用最常见的"rear 指向下一个可写位置"。

## 第 4 层 · 速记

> **栈**：后进先出 LIFO，只动栈顶（push 入栈 / pop 出栈）
> **队列**：先进先出 FIFO，队尾进、队头出
> **顺序栈 / 链栈 / 顺序队列 / 链队列，入栈出栈入队出队全是 O(1)** —— 别被"要遍历"的陷阱选项带偏
> **出栈序列判断**：拿栈**模拟**，能顺利走完就合法，卡住就不合法；入栈出栈**可以交替**
> 快速识别不合法：**小数排在压着它的大数前面 → 不合法**；可查判据——**任取一个元素，排在它后面又比它小的那些数必须从大到小出现**，出现"先小后大"即不合法
> n 个元素的出栈序列种数 = C(2n,n)/(n+1)（卡特兰数，n=4 → 14 种）【频率待核实】
> **后缀求值**：遇数压栈，遇运算符弹两个算一个再压回；**后弹出的是左操作数**（减、除会翻车）
> **栈内最多存几个操作数**：模拟一遍数最大栈深（遇数 +1、遇运算符 −1），**≠ 表达式里操作数的总个数**
> **中缀→后缀**：加满括号 → 运算符移到括号右边 → 去括号
> **循环队列**：入队 `rear=(rear+1)%MaxSize`；**队空 `front==rear`**；**队满 `(rear+1)%MaxSize==front`**（前提：牺牲一个单元，实际只装 MaxSize−1 个）
> 元素个数 = `(rear − front + MaxSize) % MaxSize`
> 假溢出：不循环的顺序队列，前面有空位却报满

## 考题回顾

**1.【模拟】**（对应已核实考点"队列操作复杂度"【真题·2025上】，非原题原文）
关于顺序队列/链队列的入队、出队操作时间复杂度，下列正确的是（ ）
A. 入队 O(1)，出队 O(n)　B. 入队 O(n)，出队 O(1)　C. 入队和出队都是 O(1)　D. 入队和出队都是 O(n)

**解**：**C**。只要维护了队头指针和队尾指针，入队就是在队尾挂一个、出队就是在队头摘一个，**两个操作都不需要遍历**。A/B 的迷惑点在于让人误以为"出队后要把后面的元素整体前移一格"——有队头指针就不用移。D 全错。
