## 定位

这一课回答「一对多」的层级关系怎么存、怎么算。第一、二节把结点、度、层次这些词认全，并说清为什么只研究二叉树；第三节数出四条能算的性质，第四节讲两种存法和下标公式，第五节讲四种遍历和由序列反推树形。第六节掉个头，拿一组权值造哈夫曼树、写编码、算 WPL；第七节是查找用的二叉排序树与平衡二叉树。前五节跟同一棵六结点的二叉树走，第六节要带权值才换成一组字符。

## 开讲：画一棵目录树，再把它数清楚

全课跟着一棵树走。先画出来：

```
            A
         /  |  \
        B   C   D
       / \      |
      E   F     G
```

把它想成一个项目目录：`A` 是根目录，下面三个条目 `B`、`C`、`D`；`C` 是文件，没有下级；`B`、`D` 是子目录，`B` 里有 `E`、`F`，`D` 里有 `G`。它后面会被裁成二叉树当全课主角，先用它把词认全。

### 一、先把词认全

**结点**就是图上一个圆圈（这里用字母代替），装着数据；结点之间的连线叫**边**。整棵树只有一个没有上级的结点，叫**根结点**，这里是 A。除根之外，每个结点头上都恰好有一条边连下来——这是树的硬规则：**每个结点只有一个上级，且不许绕回去成环**。

顺着这条边看，上面的叫**双亲**（父结点），下面的叫**孩子**。A 是 B、C、D 的双亲，B、C、D 互为**兄弟**（同一个双亲）。把 B 连同它下面的 E、F 整个拎出来，本身又是一棵树，叫 A 的一棵**子树**。

树就是这么递归定义的：**一个根，加上 m（m ≥ 0）棵互不相交的子树**——「互不相交」就是「一个文件不会同时属于两个父目录」；m = 0 时这个根自己就是一片叶子。结点数 n = 0 的情况也算，叫**空树**。

**结点的度 = 它有几个孩子。** A 度 3、B 度 2、D 度 1，C、E、F、G 一个孩子都没有、度 0。**整棵树的度 = 所有结点里最大的那个度**，这里是 3。

度为 0 的结点叫**叶子结点**（也叫终端结点），这里 C、E、F、G 共 4 个；度不为 0 的叫**分支结点**（也叫非终端结点），这里是 A、B、D。容易混的是：**内部结点 = 分支结点里除掉根**，也就是 B、D——A 是分支结点，但不是内部结点。（有的资料把这两个词当同义词，看清题目问哪一个。）

**层次**：**软考口径，根结点是第 1 层**，根的孩子是第 2 层，往下依次加一。A 在第 1 层，B、C、D 在第 2 层，E、F、G 在第 3 层。**树的高度（也叫深度）= 最大层数**，这棵树是 3。

> **根是第 1 层，不是第 0 层。** 数组下标从 0 起，很多人下意识把根当第 0 层，后面所有高度公式的答案就会整体差 1。本课全部公式都建立在「根 = 第 1 层」上。

还有两个词。**有序树**：孩子从左到右的次序固定、不能交换；**无序树**可以交换。**森林**：m 棵互不相交的树凑在一起——把上图的根 A 删掉，剩下 B、C、D 三棵树就是一片森林；反过来给森林加一个共同的根，又变回一棵树。

### 二、为什么考试只研究二叉树

上面这棵树有个麻烦：孩子个数不限，A 有 3 个、D 有 1 个。想写一条「n 个结点的树有多少层」的公式根本写不出来——层数取决于每个结点有几个孩子，而这个数是自由的。要能算，就得先把它管住：**限死每个结点最多 2 个孩子**。

**二叉树**：每个结点最多 2 个孩子，并且**左右有别**——左孩子和右孩子是两个不同的位置，交换了就是另一棵树。

它和「度为 2 的树」差在两处。**第一个**是左右有别：普通树里只有一个孩子时不分左右，二叉树里必须说清是左是右。**第二个**是结点数：二叉树可以是空树、也可以只有一个根，而「度为 2 的树」既然有度为 2 的结点，至少得 3 个结点。所以二叉树**不是**「度为 2 的树」的特例，是两个概念，常出判断题。

我们的 A 有 3 个孩子，超标了。**把 C 摘掉**（C 是叶子，摘掉它不影响任何其他结点的关系），剩下的就是一棵二叉树，记作 **T**，全课后面都用它：

```
        A
       / \
      B   D
     / \    \
    E   F    G
```

约定：B 是 A 的**左**孩子、D 是**右**孩子；E、F 是 B 的左、右孩子；G 是 D 的**右**孩子（D 没有左孩子）。

二叉树里有两个「标尺形状」要单独命名，因为一切估算都拿它们当参照。

**满二叉树**：每一层都住满，一个空位都没有。像这样：

```
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

**完全二叉树**：定义用「填格子」说最清楚——从上到下、每层从左到右，一个格子一个格子连续地填，填到第 n 个就停手。这样得到的形状就是完全二叉树。换句话说：**前面每一层都必须满，只允许最后一层不满，而且最后一层必须从左边连续排，中间不许跳空。**

T 是不是完全二叉树？按格子编号：A=1、B=2、D=3、E=4、F=5，D 的左孩子位是 6 号（空着），G 在 7 号。**6 号空着而 7 号有人，跳空了，所以 T 不是完全二叉树。** 把 6 号补上，T 就成了 7 结点的完全二叉树，而且每层都满——**满二叉树一定是完全二叉树，反之不然**（只填到 5 号就停，是完全的但不满）。

### 三、四条能算出来的性质

现在树被管住了，可以开始数了。

**性质 1：第 i 层最多有 2^(i−1) 个结点。**

不给公式，先数满二叉树上图：第 1 层 1 个，第 2 层 2 个，第 3 层 4 个。为什么翻倍？因为每个结点最多带 2 个孩子，所以下一层最多是上一层的 2 倍。写成 2 的幂：1 = 2⁰，2 = 2¹，4 = 2²。**第 i 层的指数是 i−1，不是 i**——因为第 1 层对应 2⁰。这就是「根是第 1 层」这个约定的直接后果。

**性质 2：高度为 h 的二叉树最多有 2ʰ − 1 个结点**（**最少只要 h 个**——每层只挂一个，就是一条单支链；「最少 2^(h−1) 个」那条只对完全二叉树成立，别串）。

把每层的上限加起来：h = 3 时是 1 + 2 + 4 = 7；h = 4 时是 1 + 2 + 4 + 8 = 15。7 = 2³ − 1，15 = 2⁴ − 1。为什么总是差 1 就到 2 的整幂？因为二进制里 `111` 再加 1 就进位成 `1000`，所以 1+2+4+…+2^(h−1) = 2ʰ − 1。这个上限只有满二叉树能取到。

**性质 3：n 个结点的完全二叉树，高度 h = ⌊log₂n⌋ + 1。**

先猜一个：**一棵有 100 个结点的完全二叉树，有几层？先别算。** 很多人凭直觉说 5 层或 6 层，因为「100 也不算多」。

真算一遍。完全二叉树是连续填的，高度为 h 时结点数被夹在两个数之间：最少是「前 h−1 层填满、第 h 层只放 1 个」，即 2^(h−1) − 1 + 1 = **2^(h−1)**；最多是「h 层全满」，即 **2ʰ − 1**。于是

```
2^(h−1) ≤ n ≤ 2ʰ − 1
```

拿 100 去试：h = 6 要求 n ≤ 2⁶ − 1 = 63，100 > 63，不够；h = 7 要求 64 ≤ 100 ≤ 127 ✓。**答案是 7 层。**（前 6 层已装 63 个，第 7 层还要装 100 − 63 = 37 个，而第 7 层最多能装 2⁶ = 64 个，37 ≤ 64，自洽。）

公式就从这个夹逼里长出来：把右边的 2ʰ − 1 写成 n < 2ʰ，不等式变成 2^(h−1) ≤ n < 2ʰ，三边取以 2 为底的对数得 h − 1 ≤ log₂n < h。也就是说 h − 1 正好是 log₂n 向下取整的结果，所以

```
h = ⌊log₂n⌋ + 1
```

验算 100：2⁶ = 64 ≤ 100 < 128 = 2⁷，故 ⌊log₂100⌋ = 6，h = 7 ✓，与夹逼一致。**两种算法必须给出同一个数，对不上就是取整或层号错了。**

**性质 4：n₀ = n₂ + 1。** 记号：n₀ 是度为 0 的结点数（叶子数），n₁ 是度为 1 的，n₂ 是度为 2 的。

再猜一次：**一棵二叉树里，叶子多还是「有两个孩子的结点」多？多几个？** 直觉上会觉得「看形状而定」，其实这条跟形状完全无关，永远差 1。

推法是**把边数从两头各数一遍**。

- 从「入边」数：除了根，每个结点头上都恰好有一条边连下来，所以**边数 = n − 1**，这里 n = n₀ + n₁ + n₂。
- 从「出边」数：度为 0 的结点向下发 0 条边，度为 1 的发 1 条，度为 2 的发 2 条，所以**边数 = n₁ + 2n₂**。

同一堆边，两种数法结果必须相等：

```
(n₀ + n₁ + n₂) − 1 = n₁ + 2n₂
n₀ + n₂ − 1 = 2n₂
n₀ = n₂ + 1
```

**n₁ 在推导中被消掉了**，所以题目给「度为 1 的结点有几个」纯属干扰项。拿主角 T 验一遍：A 度 2、B 度 2、D 度 1、E/F/G 度 0，所以 n₀ = 3、n₁ = 1、n₂ = 2，3 = 2 + 1 ✓。再交叉核对边数：n − 1 = 6 − 1 = 5，n₁ + 2n₂ = 1 + 4 = 5 ✓。

> 考试这样问：n 个结点的完全二叉树高度（深度）是多少；高度为 h 的二叉树最多、最少有几个结点；第 i 层最多几个；度为 2 的结点给了几个，问叶子有几个。

### 四、树怎么存进内存

**顺序存储：一个一维数组，按「填格子」的编号放。** 结点 i 的位置关系（编号从 1 开始）：

```
左孩子 = 2i      右孩子 = 2i + 1      双亲 = ⌊i/2⌋      i = 1 时是根，无双亲
（编号从 0 起时整体挪一位：左 = 2i+1、右 = 2i+2、双亲 = ⌊(i−1)/2⌋）
```

为什么是 2i？编号 2 以后的结点全都是别人的孩子。第 1 到 i−1 号这 i−1 个结点各带 2 个孩子、共 2(i−1) 个，占掉编号 2 到 2i−1；紧接着的 2i 号就轮到第 i 个结点的左孩子。

验一下：i = 1 的左孩子是 2 ✓，i = 3 的左右孩子是 6、7 ✓。还要判有没有孩子：**2i ≤ n 才有左孩子，2i+1 ≤ n 才有右孩子**。

这套编号只对完全二叉树严丝合缝。T 不是完全二叉树，存进数组是 `A B D E F _ G`——6 号格空着，**必须留着这个「虚结点」的空位**，否则下标关系就乱了。

T 只浪费 1 格还能忍，最坏情况很可怕：10 个结点的右单支链（每个结点只有右孩子），最深那个编号是 2¹⁰ − 1 = **1023**，要开 1023 格去装 10 个结点。**所以顺序存储只适合完全二叉树，一般二叉树要用链式存储。**

**链式存储**：每个结点做成一个带指针的结构体。放 `左孩子指针 + 数据 + 右孩子指针` 的叫**二叉链表**；再多存一个 `双亲指针`（方便往上找）的叫**三叉链表**。

这里有一个能直接出题的数：**n 个结点的二叉链表里有 n + 1 个空指针。** 数一遍就明白：一共 2n 个指针槽，非空的恰好对应树里的每条边、共 n − 1 条，所以空的有 2n − (n − 1) = n + 1 个。

T 有 6 个结点，空指针 7 个 ✓（E 左右、F 左右、D 左、G 左右）。三叉链表同理：3n 个槽，非空的是 n−1 条向下的边加 n−1 个向上的双亲指针，空的 3n − 2(n−1) = **n + 2** 个，T 是 8 个。

> 考试这样问：结点 i 的左孩子编号是多少（先看清编号从 0 起还是从 1 起）；给一棵树问顺序存储的数组至少要开多大；n 个结点的二叉链表、三叉链表各有几个空指针。

### 五、把树读成一串：遍历

树是二维的，输出、比较、存盘都要一维的序列，所以要**遍历**——按某种固定顺序把每个结点不重不漏访问一遍。

一棵非空二叉树就三块：根、左子树、右子树。约定**左子树永远排在右子树前面**，那么变的只有根的位置，于是有三种，名字里的「前/中/后」指的就是**根被访问的位置**：

- **前序（先序）：根 → 左 → 右**
- **中序：左 → 根 → 右**
- **后序：左 → 右 → 根**

每一种都是对每棵子树念同一句口令，递归下去。拿主角 T 走一遍：

```
        A
       / \
      B   D
     / \    \
    E   F    G

前序（根左右）：A 先出来 → 进左子树 B：B 先出、再 E、再 F → 进右子树 D：D 先出、无左孩子、再 G
              = A, B, E, F, D, G

中序（左根右）：左子树 B 交出 E, B, F → 根 A → 右子树 D 无左孩子，故 D 在前、G 在后
              = E, B, F, A, D, G

后序（左右根）：左子树 B 交出 E, F, B → 右子树 D 交出 G, D → 最后才是根 A
              = E, F, B, G, D, A
```

还有第四种，**层次遍历**：从上到下、每层从左到右，= **A, B, D, E, F, G**。它不是递归的，实现要用**队列**（先进先出：出队一个就把它的孩子排到队尾）；前三种是递归的，本质上借的是系统**栈**。

**反过来，给两个序列还原树。** 关键：**前序的第一个、后序的最后一个都是根**，但只知道根还不够，还得知道左右子树各包含哪些结点——这正是**中序**能提供的：在中序序列里找到根，它左边的全是左子树、右边的全是右子树。所以**中序必须参与**。

用 T 的前序 `A,B,E,F,D,G` 和中序 `E,B,F,A,D,G` 还原：

```
① 前序首位 A = 根
② 中序里 A 左边 [E,B,F] 是左子树（3 个），右边 [D,G] 是右子树（2 个）
③ 左子树取前序接下来的 3 个 [B,E,F]，首位 B = 左子树的根；
   中序段 [E,B,F] 里 B 的左边 [E]、右边 [F] → E 是左孩子、F 是右孩子
④ 右子树取前序剩下的 [D,G]，首位 D = 右子树的根；
   中序段 [D,G] 里 D 的左边为空、右边 [G] → G 是【右】孩子
还原结果与原树一致 ✓
```

**本例两层就到底了，一般要递归**：切出来的左右两段各自又是一棵树，**对每一段重复 ①–④**，直到每段只剩一个结点为止。层数多的题就是把这四步多做几轮。

**为什么前序 + 后序不行？** 就看第 ④ 步：D 只有一个孩子时，前序里它总紧跟在根后面、后序里总紧挨在根前面，左右分不出来。**所以前序+后序不能唯一确定二叉树，中序+前序、中序+后序都可以。** 验算见本节末的推演，跳过不影响后面。

> 考试这样问：给一棵树写出前/中/后序序列；给前序+中序求后序（或中序+后序求前序）；哪两种遍历能唯一确定一棵二叉树。

#### 顺便把空指针用起来：线索二叉树

回到第四节那 **n + 1 个空指针**。链式存储只能回答「你的左右孩子是谁」，答不了刚学的这个问题：「按中序遍历排在你前一个、后一个的是谁」——想跳到中序后继，只能从根重新遍历一遍。硬加两个指针域要多花 2n 个指针，太浪费；而二叉链表里**本来就闲着 n+1 个空槽**，拿它们存前驱后继，一分钱不多花。

代价是要能分清一个指针里装的到底是孩子还是前驱后继，于是每个结点加两个 1 位标志：

```
| ltag | lchild | data | rchild | rtag |

ltag = 0 → lchild 指左孩子      ltag = 1 → lchild 指（该遍历次序下的）前驱
rtag = 0 → rchild 指右孩子      rtag = 1 → rchild 指（该遍历次序下的）后继
```

（这是教材与培训资料的口径：**0 是孩子、1 是线索**。个别资料把 0/1 反过来定义，做题时以题面给出的说明为准。）

这些指向前驱、后继的指针就叫**线索**，装了线索的链表叫**线索链表**，对应的二叉树叫**线索二叉树**；按哪种遍历顺序穿，就叫前序/中序/后序线索二叉树。

拿 T 按中序穿一遍（中序 E, B, F, A, D, G）：E 的右指针空着，指向中序后继 B，rtag 置 1；F 的左指针空着，指向中序前驱 B，ltag 置 1；G 的右指针空着，但 G 是中序最后一个、没有后继，只能仍然指空。

#### 推演 · 穷举验算：和前序+后序同时相符的树有几棵

把 G 改挂成 D 的**左**孩子，前序仍是 `A,B,E,F,D,G`、后序仍是 `E,F,B,G,D,A`，两串一字不变。穷举 6 个结点的全部二叉树，与这两串同时相符的恰好 2 棵；换成前序+中序则只剩 1 棵。

### 六、反过来造一棵树：哈夫曼树

前五节都是「给一棵树，读出数字」，这一节反过来：**给一组数字，造一棵树**。既然要从权值出发，就没法再沿用主角 T，换一组带权的字符——注意下面的**小写 a、b、c、d 是字符**，和前面树上的大写结点无关。

**实际问题**：一个文件只用 4 种字符，a 出现 2 次、b 4 次、c 5 次、d 7 次，要编成 0/1 存起来。最省事的是**定长编码**：4 种字符 2 位就够（00/01/10/11），共 (2+4+5+7) × 2 = **36 位**。但 d 出现 7 次和 a 出现 2 次一样只配 2 位，明显不划算——**常用的编短、罕见的编长**，就像摩斯电码里 E 是一个点、Q 是四下。

**关键翻译**：把字符放在一棵二叉树的叶子上，规定**从根往下走，走左记 0、走右记 1**，那么走到某个字符沿途的 0/1 串就是它的编码，而**编码有多长就等于这个字符在树里有多深**。于是「让高频字符编码短」等价于「让权值大的结点离根近」。

几个套定义的词先认下来，考试考过这几句的原文表述：

- **路径**：一个结点到另一个结点之间的通路。
- **结点的路径长度**：这条路上的**分支（边）数目**。
- **树的路径长度**：教材口径是**根到每一个结点**的路径长度之和；也有资料只统计**根到每一个叶子结点**。两种口径都不影响下面 WPL 的算法（WPL 只统计叶子）。
- **权**：结点代表的值，这里就是出现次数。
- **结点的带权路径长度**：该结点到根的路径长度 × 它的权值。
- **树的带权路径长度 WPL**（也叫树的代价）：**所有叶子结点的带权路径长度之和**。WPL 最小的那棵树就叫**最优二叉树**，也叫**哈夫曼树**。

**注意这里换了一套数法**：**本节的「深」一律数边数**，和前面「根是第 1 层」的层数差 1（叶子在第 3 层 = 从根走 2 条边 = 编码 2 位）。用边数是因为编码长度天然等于边数，但**两套数法在同一道题里绝不能混用**，这是本课最容易自己把自己算错的地方。

**同一组权值，形状不同 WPL 差多少？** 把 2、4、5、7 摆成三种形状（深度沿用上面的边数口径）：

```
(a) 四个字符全放在同一层，各深 2   → WPL = 2×(2+4+5+7)          = 36   （等于定长编码）
(b) a 深3、b 深3、c 深2、d 深1     → WPL = 3×(2+4) + 5×2 + 7×1   = 35
(c) a 深1、d 深2、b 深3、c 深3     → WPL = 3×(4+5) + 7×2 + 2×1   = 43   （把权大的放深了，反而更差）
```

(c) 把最轻的 a 放在最浅处、把重的 b、c 压到最深，就多花了 8 位。**(b) 的 35 是这组权值的最小值**，下面用哈夫曼算法把它造出来。

**构造法（贪心，五步，一步不能跳）**：

1. 把所有字符当成独立结点，扔进一个待合并集合。
2. 取出**当前权值最小的两个**结点，合并成一个新结点，新结点权值 = 两者之和。
3. **把新结点放回集合**（最容易漏的一步），让它参与后面的比较。
4. 重复 2–3，直到集合里只剩一个结点，它就是根。
5. 标边：**左 0 右 1**（左右约定可以反，但同一题必须自始至终统一）；为了得到标准形态，合并时把**权小的放左边**。

**为什么「每次挑最小的两个」就一定最优？** 一句话：最深的那个位置码长最大，就该让最轻的去站。完整理由见本节末的推演，跳过不影响照着五步做题。

跑一遍 a=2, b=4, c=5, d=7：

```
初始：{ a(2), b(4), c(5), d(7) }
第1轮：最小两个是 a(2)、b(4) → 合并成 ab(6)，放回     → { c(5), ab(6), d(7) }
第2轮：最小两个是 c(5)、ab(6) → 合并成 cab(11)，放回  → { d(7), cab(11) }
       （注意此时 d=7 比 6 大，所以它这一轮没被选中）
第3轮：只剩两个，合并 d(7)、cab(11) → 根(18)，结束
```

```
            根(18)
         0 /     \ 1
       d(7)     cab(11)
              0 /     \ 1
            c(5)     ab(6)
                   0 /   \ 1
                 a(2)   b(4)
```

| 字符 | 权值 | 编码 | 码长（= 从根走的边数） |
|---|---|---|---|
| d | 7 | 0 | 1 |
| c | 5 | 10 | 2 |
| b | 4 | 111 | 3 |
| a | 2 | 110 | 3 |

权值最大的 d 最短、最小的 a 最长 ✓。**WPL = 7×1 + 5×2 + 4×3 + 2×3 = 35**，与上面 (b) 对上了。比定长 36 位只省 1 位——**省得少是因为这组权值差距不大**，权值越悬殊越省（题库第 4 题那道真题里 a 占 45%、f 只占 5%，省的比例大得多）。

**三条能拿来验算的性质**（考场上算完顺手对一遍）：

- **WPL = Σ(权值 × 码长) = 所有内部结点权值之和。** 这里内部结点是 6、11、18，加起来 6+11+18 = 35，和上面一致 ✓。两条路对不上就是构造错了。
- **n 个字符（叶子）的哈夫曼树共 2n − 1 个结点，且没有度为 1 的结点。** 来历：n 个叶子要合并 n−1 次、每次多出一个结点，n + (n−1) = 2n−1。n = 4 时 2×4−1 = 7：a、b、c、d、ab、cab、根 ✓。每次合并都造出一个恰有 2 个孩子的父结点，度为 1 的不可能出现。
- **权值最大的字符码长最短、最小的最长**（并列权值时可能等长，所以严格说是「不长于/不短于」）。

**为什么字符只能放叶子？** 假设 a 编成 `0`、b 编成 `01`，收到 `01` 就有两种读法（一个 a 后面接别的，还是一个 b），没法译。**一个编码是另一个编码的前缀，就会出歧义。** 字符全放叶子就天然避免了：到达任何叶子途中经过的都是不放字符的分岔点，谁也借不了谁的道。这种任一编码都不是另一编码前缀的方案叫**前缀编码**（前缀码），哈夫曼编码就是一种前缀编码。

**译码**：拿着 0/1 串**从根开始走**，遇 0 往左、遇 1 往右，**一走到叶子就输出该字符，并立刻回到根**继续读下一位。译 `1111100`：

```
1 → cab ； 1 → ab ； 1 → b（叶子）⇒ 输出 b，回根
1 → cab ； 1 → ab ； 0 → a（叶子）⇒ 输出 a，回根
0 → d（叶子）                      ⇒ 输出 d，回根
原文 = "bad"
```

验算：b(3位) + a(3位) + d(1位) = 7 位，与输入串一致 ✓。**若走到串尾停在中间结点（没落到叶子），就是译错了或串被截断。** 顺带一件事：`bad` 定长只要 6 位，哈夫曼反而用了 7 位——哈夫曼只保证**按给定权值统计的整体总长最短**，个别片段可能更长，这是常见误解。

> 考试这样问：给一组权值求 WPL 或结点总数；求某个字符的编码、码长、编码总长；给编码表把一串 0/1 译回原文。

#### 推演 · 为什么「每次挑最小的两个」就一定最优

最深那一层必然站着两个叶子——若只剩一根独苗，把它往上提一层，WPL 只会更小，说明原来那棵本就不是最优的。既然最深处总要站两个字符，就该让**最轻的两个**去站：那个位置的码长最大，让最轻的去乘代价最小。合并成新结点再放回，等于把「这两个已经安排好」压成一个虚拟字符，问题规模减一；重复到底，就是全局最优。

### 七、给查找排的树：二叉排序树与平衡二叉树

最后一类树，目的不是压缩而是**查找**。

**二叉排序树**（又叫二叉查找树、查找二叉树、BST）：每个结点存一个值，并且满足**左子树上所有结点的值都小于该结点，右子树上所有结点的值都大于该结点**。

注意是「整棵子树」而不是「左右那两个孩子」，只比直接孩子远远不够（培训资料写的「所有左孩子结点值」指的就是整棵左子树）。这样查一个数就像翻字典：比当前结点小往左、大往右，一路砍掉一半。

**怎么把一串数建成二叉排序树**（题目常给一串关键码问能不能建出图上那棵树，「**关键码**」就是拿来比大小的那个值，这里就是结点里存的数）。规则只有三句：**空树就当根；比当前结点小往左走、大往右走；走到空位就挂上去。**

拿 23、17、31、11、19、27 依次插一遍：

```
插 23  空树，直接当根
插 17  17<23 往左，左边空 → 挂 23 的左
插 31  31>23 往右，右边空 → 挂 23 的右
插 11  11<23 往左到 17；11<17 再往左 → 挂 17 的左
插 19  19<23 往左到 17；19>17 往右 → 挂 17 的右
插 27  27>23 往右到 31；27<31 往左 → 挂 31 的左

              23
            ／    ＼
          17        31
         ／  ＼     ／
       11     19  27
```

它和第五节直接接得上：**对二叉排序树做中序遍历（左→根→右），得到的正好是从小到大的有序序列**——上面这棵中序读出来是 11、17、19、23、27、31，确实升序 ✓。这是判断一棵树是不是二叉排序树最快的办法。

问题在于**查找效率完全取决于树的深度**：每比较一次下降一层，最多比较「树高」次。同样 n 个结点，形状可以差很多——关键码若按升序一个个插进去，每个新数都比前面所有数大，就会挂成一条**单支树**（退化成链表），高度 n、要比较 n 次，效率最差；**深度最小的形状**查得最快——把深度按住，正是平衡二叉树要干的事。

**平衡二叉树（AVL 树）**就是为了把深度压住：它或者是空树，或者**左右子树都是平衡二叉树，且左右子树的高度之差的绝对值不超过 1**。定义**平衡因子 BF = 该结点左子树的高度 − 右子树的高度**，那么平衡二叉树上**每个结点的平衡因子只能是 −1、0、+1**；只要有**一个**结点的平衡因子绝对值大于 1，整棵树就不平衡。

⚠️ **这里的「高度」回到第一节的层数口径**（第六节为了算码长临时改成数边数，那是第六节的事）：**空子树的高度记 0，单个结点记 1。** 这两条不写明，碰上一边是空的结点就会算错。

拿上面那棵树逐个算一遍：

```
结点 23：左子树 {17,11,19} 高 2，右子树 {31,27} 高 2  → BF = 2 − 2 = 0
结点 17：左 {11} 高 1，右 {19} 高 1                    → BF = 1 − 1 = 0
结点 31：左 {27} 高 1，右子树是空的、高 0              → BF = 1 − 0 = +1
结点 11、19、27：都是叶子，左右都空                     → BF = 0 − 0 = 0
```

全部 |BF| ≤ 1，所以这棵树**是**平衡二叉树。注意 31 那一行：右边空着按 0 算，不是按 −1。

插入或删除后如果失衡，靠**旋转**转回来，按失衡结点与「闯祸的那个新结点」的相对位置分 LL、RR、LR、RL 四型，名字要认得；各是朝哪边转、转几次见本节末的深入，跳过不影响做题。中级考试极少要求你手工转出结果，绝大多数只问「这棵树是不是平衡二叉树」「某结点的平衡因子是多少」，会算 BF 就够了。

一句话把三种「有序」的树分清：**二叉排序树管的是「值的大小关系」，平衡二叉树在此基础上再管「高度差」，完全二叉树管的是「形状连续不跳空」，三者互不蕴含**——一棵完全二叉树上的值可以乱放，一棵平衡二叉树也可以形状不完全。

> 考试这样问：给一棵树问它是不是二叉排序树、是不是平衡二叉树，某结点的平衡因子是多少；给几组关键码插入序列，问哪一组建不出图上这棵树。

#### 深入 · 失衡之后的四种旋转

**LL 型**：左子树的左边太深，做一次右旋。**RR 型**：右子树的右边太深，做一次左旋。**LR 型**：左子树的右边太深，先左旋再右旋。**RL 型**：右子树的左边太深，先右旋再左旋。

## 速记

- **根是第 1 层**（不是第 0 层）；度 = 孩子个数，叶子度 0；高度 = 深度 = 最大层数；森林 = 砍掉根剩下的那堆树
- 第 i 层最多 **2^(i−1)** 个；高度 h 最多 **2ʰ − 1** 个（满二叉树）；完全二叉树 **2^(h−1) ≤ n ≤ 2ʰ − 1**，**h = ⌊log₂n⌋ + 1**；边界 n=63→h=6、n=64→h=7
- **n₀ = n₂ + 1**（边数两头数得来，n₁ 是干扰项）；满 ⇒ 完全，反之不成立
- 顺序存储（编号从 1 起）：左 **2i**、右 **2i+1**、双亲 **⌊i/2⌋**；从 0 起则为 2i+1 / 2i+2 / ⌊(i−1)/2⌋
- 二叉链表空指针 **n+1**（线索二叉树就用它存前驱后继，ltag/rtag 区分），三叉链表 **n+2**
- 遍历：前/中/后指**根的位置**，左永远在右前；层次用**队列**；**中序必须参与才能唯一还原**（前序+后序不行）
- 哈夫曼：每次合并**最小的两个**、合并完**放回**；字符只放叶子（前缀码）；**WPL = Σ权×码长 = 内部结点权值和**；n 个叶子共 **2n−1** 个结点、无度 1 结点；权大码短；**只有 WPL 唯一**，树形/编码串/码长在权值并列时都可能不唯一
- 二叉排序树中序升序、效率看深度、升序插入退化成单支树；平衡二叉树 **BF = 左高 − 右高 ∈ {−1,0,+1}**，失衡靠 LL/RR/LR/RL 四种旋转
