# 38 · 操作系统：存储管理——分区、分页与段页式

## 定位

内存怎么分给进程、程序看到的地址怎么翻译成内存条上的位置。五节按「每一步补上一步的短板」串起来：分区（整块搬）→ 分页（等分、不必连续）→ 快表（补分页多一次访存）→ 分段（按逻辑切，便于共享保护）→ 段页式（两者合一）。前置：04 的局部性原理、05 的十六进制换算；39 接着讲页框满了换出谁。

全课跟着同一个程序 **report**：19KB，逻辑上三块——代码 8KB、打印模块 6KB、数据 5KB；盯住其中一个字节，逻辑地址 **0x2F6A**（十进制 12138），每种方式都算一遍它落在哪。

| 地址 | 别名 | 是什么 |
|---|---|---|
| **逻辑地址** | 虚地址、相对地址 | 程序自己认为的地址，每个程序都从 0 编号；`printf("%p", ptr)` 打出的就是它 |
| **物理地址** | 实地址、绝对地址 | 内存条上真正的位置 |

两个进程可以打印出同一个地址值而互不干扰，因为各拿各的逻辑地址。

## 一、分区存储管理

### （概念）两种分区与两种碎片

分区法＝**整存**：进程运行所需内存**整体一起**分配，装完再执行。**作业**＝等着上机运行的那个程序。

| 方式 | 怎么划 | 留下的碎片 |
|---|---|---|
| **固定分区** | 静态划分，开机就切成若干固定大小的分区 | report 占一块 24KB 分区，剩 5KB 已登记在它名下却用不上 → **内部碎片** |
| **可变分区** | 动态划分，作业进来时按实际大小划（report 就划 19KB） | 装卸几轮后，主存里一堆**还没分给任何人**、但太小又不相邻的小块 → **外部碎片** |
| **可重定位分区** | 把已分配区域整体往一头搬，缝隙合并成一大块（也叫紧凑、内存拼接） | 专治外部碎片；搬完各程序起始位置变了，地址要跟着换算（＝重定位），代价大，只在有作业申请空间却满足不了时才做 |

**易混对 内部碎片 vs 外部碎片**
- 判据｜定长切分、块里填不满 → 内部；变长堆放、块与块之间留缝 → 外部。
- 例子｜19KB 装进 24KB 固定分区，废 5KB → 内部；可变分区里切完剩 2KB、谁也用不上 → 外部。

「内存拼接」是搬内存；后面地址翻译里「页框号拼接偏移」是拼二进制位，两回事。

### （计算）四种分配算法

report 申请 19K，空闲块按地址从低到高如下（本课设定的数据）：

| 空闲块 | 起始地址 | 大小 |
|---|---|---|
| 块1 | 0K | 32K |
| 块2 | 100K | 24K |
| 块3 | 200K | 48K |
| 块4 | 300K | 21K |

| 算法 | 规则 | 结果 | 特点 |
|---|---|---|---|
| **首次适应** | 按地址从头找，第一个 ≥19K 的 | **块1**，剩 13K | 找得快；低地址被反复切碎 |
| **最佳适应** | 空闲块从小到大排，第一个 ≥19K 的（够用里最小的） | **块4**，剩 **2K** | 本次最省，但剩下的小块再也没人要，最易产生细小外部碎片 |
| **最差适应** | 挑最大的切 | **块3**，剩 29K | 剩余仍够大，预防细小碎片；大块很快被啃光，大作业来了没地方 |
| **循环首次适应** | 判据同首次适应，起点是**上次分配停下处**（设上次刚分完块1，从块2 起） | **块2**，剩 5K | 空闲块被均匀使用，不总在低地址切 |

分区法的死穴：程序必须**整个装入**且占**连续**空间。可内存常装不下整个程序，且大部分代码这次运行根本执行不到。后两节就是拆这两个前提。

## 二、分页存储管理（计算）

物理内存和程序都切成**等大**的格子，一格一格放，放哪都行、用到哪块装哪块，同时甩掉「连续」和「全装入」。

| 术语 | 别名 | 是什么 |
|---|---|---|
| **页** | 页面 | 逻辑地址空间等分出的一块 |
| **页框** | 物理块、页帧 | 物理内存等分出的一块；与页**必须等大**，任意页才能塞进任意空闲页框 |

report 19KB、页大小 4KB → 5 页（页 0～4），最后一页只装 3KB。**外部碎片消灭**（任何空闲页框都能用），代价是每进程最后一页平均浪费半页的**内部碎片**。培训资料记的优点「利用率高、碎片小、分配及管理简单」即此。

**算例：地址拆分。** 0x2F6A（12138），页大小 4K：

```
页号     = 12138 ÷ 4096 = 2
页内偏移 = 12138 − 2×4096 = 3946（余数）
```

4096 = 2¹²，除以 2¹² 就是右移 12 位，余数就是被移掉的低 12 位——所以不用真做除法，**从低位第 12 位处切一刀：低 12 位是页内偏移，高位是页号**。页大小永远取 2 的幂就是为此。

> **页内偏移位数 = log₂(页大小)**　　**逻辑地址位数 = 页号位数 + 页内偏移位数**　　最多页数 = 2^页号位数

- 十六进制：1 位十六进制 = 4 位二进制，12 ÷ 4 = 3 → 0x2F6A 低 3 位 `F6A` 是偏移，高位 `2` 是页号。页大小 1KB = 2¹⁰，10 不是 4 的倍数，切不出整齐的十六进制位，只能走除法。
- 单位：1K = 2¹⁰、1M = 2²⁰、1G = 2³⁰；如 16MB = 2⁴ × 2²⁰ = 2²⁴，即 24 位地址。
- 逻辑地址是页号与偏移的高低位**拼接**，不是数值相加。

**算例：位数。** report 所在机器逻辑地址 **16 位**（64KB 空间）→ 页号 16 − 12 = **4 位**，最多 16 页；物理内存 **1MB** → 物理地址 **20 位**，页框号 20 − 12 = **8 位**，共 256 个页框。**页号位数和页框号位数不必相等，只有偏移位数两边必须一样**（页与页框等大）。

**页表与页表寄存器。**
- **页表**：每进程一张，记「第几页放在哪个页框」，一行叫**页表项**。页放进哪个页框取决于装入时哪个空着，**页号和页框号不按顺序对应**，所以必须查表，不能拿页号直接算。
- 页表项除页框号外还有：**有效位**（此页此刻在不在内存，也叫**状态位**）、**访问位**（最近是否被读写）、**修改位**（调入后是否被改过，改过的换出时要写回磁盘）。
- 页表本身也在内存里，CPU 靠**页表寄存器**找它：存页表始址 B 和页表长度 L（本进程共几页）。页号 ≥ L → **越界中断**。report 的 L = 5，0x6F6A（页号 6）会被拦下。

report 的页表：

| 页号 | 页框号 |
|---|---|
| 0 | 0x0C |
| 1 | 0x07 |
| **2** | **0x1A** |
| 3 | 0x2F |
| 4 | 0x11 |

**算例：翻译 0x2F6A。**

1. **切**：偏移 `F6A`，页号 `2`。
2. **查**：2 < L=5 不越界；页 2 → 页框 **0x1A**。
3. **拼**：页框号接上原封不动的偏移 → **0x1AF6A**。

验算：0x1AF6A = 110442，0x2F6A = 12138，差 98304 = (26 − 2) × 4096，正好 24 个整页。

规则：**页号换成页框号，页内偏移一个字都不动。** 十进制写法：物理地址 = 页框号 × 页大小 + 偏移；验算式 **物理 − 逻辑 = (页框号 − 页号) × 页大小**。

**请求分页与缺页。** 程序不必整个装入，**用到哪页才从磁盘调哪页**，叫**请求分页**。
1. 页表项有效位为「无效」→ CPU 发出**缺页中断**（要用的页还在磁盘上）。
2. 处理程序去磁盘找到该页：有空闲页框直接调入；没有则先按置换算法换出一页（FIFO/LRU/OPT 见 39）。
3. 回填页表，**重新执行**被打断的那条指令（不是跳过）。

**驻留集**＝系统分给进程的那几个页框（它此刻在内存里的页）。驻留集太小，刚换出的页马上又要用，CPU 大半时间耗在搬页上 → **抖动**。培训资料记的缺点「增加系统开销、可能产生抖动」即此。FIFO「页框越多、缺页反而越多」是 **Belady 异常**，不是抖动（培训资料在置换一节把它也叫抖动，见 39）。

## 三、快表 TLB

### （概念）快表是什么

页表在内存里，取一个数要**访存两次**（查页表 + 取数），速度砍半。解法照抄 Cache：把**最近用过的页表项**复制到一小块高速存储里。

| 术语 | 是什么 |
|---|---|
| **快表（TLB）** | 缓存最近用过的页表项；教材也叫**联想存储器 / 相联存储器**，按内容并行比对，一次比完所有项 |
| **慢表** | 内存里那张完整页表 |
| 为何有效 | 局部性原理（04）：一段时间内翻来覆去就用那几页，命中率高 |
| 引入目的 | 加快地址变换，减少查页表带来的额外访存（不是扩大内存，也不是缓存数据） |

**易混对① 快表 vs Cache**
- 判据｜Cache 缓存数据和指令本身；快表缓存页表项，即地址翻译的结果。
- 例子｜原话｜培训资料「快表是将页表存于 Cache 中」是借「高速缓存」打比方；实际 TLB 是地址翻译部件里独立的一块相联存储器，不是数据 Cache。按「快表快、慢表在内存、慢表要两次访存」理解。

**易混对② 快表未命中 vs 缺页**
- 判据｜未命中＝这条翻译没被缓存，页多半还在内存，去查慢表即可；缺页＝页真的不在内存，触发缺页中断。
- 例子｜快表没有页 2 的项、页表里页 2 有效位为 1 → 只是未命中；有效位为 0 → 缺页。

### （计算）有效访问时间 EAT

快表访问 λ = 20ns，内存访问 t = 100ns，命中率 a = 90%：

| 情况 | 概率 | 耗时 |
|---|---|---|
| 快表命中 | 0.9 | 查快表 20 + 取数 100 = **120ns** |
| 快表未命中 | 0.1 | 查快表 20（扑空）+ 查页表 100 + 取数 100 = **220ns** |

EAT = 0.9 × 120 + 0.1 × 220 = 108 + 22 = **130ns**（不是 120：10% 未命中每次多 100ns，摊下来 10ns）。

> **EAT = a(λ + t) + (1 − a)(λ + 2t) = λ + (2 − a)·t** = 20 + 1.1 × 100 = 130ns
> 忽略快表访问时间（λ = 0）：**EAT = (2 − a)·t** = 110ns。

- 未命中也是先查过快表才发现扑空，λ 两条路都要加。
- 不设快表每次 200ns，130ns 快了 35%。
- 验算：EAT 必落在 λ+t 与 λ+2t 之间（本例 120～220ns）。
- 本式默认忽略未命中后把页表项写回快表的时间（主流资料如此）；个别资料把它算进去写成 λ + t + λ + t。

## 四、分段存储管理

分页的切分点是机械定的，一个函数可能被腰斩进两页：想共享打印模块，必须正好整页才对得齐；一页里代码数据混杂，没法分别设只读 / 可写。改按**段**切：一段＝一个逻辑单位（主程序、子程序、数组、栈）。

### （计算）段表与地址翻译

report 三段（**基址**＝该段装入内存的起始位置，装入时由系统定，各段可不相邻）：

| 段号 | 内容 | 段长 | 基址 | 逻辑区间（讲解用） |
|---|---|---|---|---|
| 0 | 代码 | 8192（8KB） | 52000 | 0 ～ 8191 |
| 1 | 打印模块 | 6144（6KB） | 100000 | 8192 ～ 14335 |
| 2 | 数据 | 5120（5KB） | 73000 | 14336 ～ 19455 |

段变长，所以**段表**每行要**基址 + 段长**两个字段（段长用来判越界）。**段表寄存器**存段表始址和段表长度。

**算例：翻译 0x2F6A（12138）。**

1. 写成分段地址：12138 − 8192 = 3946 → **(1, 3946)**。
2. 第一道检查：段号 1 < 段表长度，不越界。
3. 查段表：段 1 基址 100000、段长 6144。
4. 第二道检查：3946 < 6144，不越界。
5. **相加**：100000 + 3946 = **103946**。

最后一步是加法不是拼接：段基址是任意值（100000 ÷ 4096 余 1696，不对齐），没有高低位可拼。**分页拼接、分段相加。**

越界检查：分段查**两道**——段号 vs 段表长度（同分页的页号 vs L）、段内偏移 vs **段长**（分段独有，段长可变不比不知道）。分页只查第一道，偏移是按固定页大小截出来的，天生超不出一页；不是「分页什么都不检查」。

### （概念）分页 vs 分段

| 对比点 | 分页 | 分段 |
|---|---|---|
| 划分依据 | 物理上机械等分，与程序逻辑无关 | 按程序的逻辑功能模块 |
| 长度 | 固定 | 可变 |
| 对用户 | **不可见**，硬件自动切 → 地址空间**一维** | **可见**，程序显式给段号 → 地址空间**二维** |
| 地址结构 | 页号 + 页内偏移（一个数） | 段号 + 段内偏移（两个数） |
| 表字段 | 页表：页号 → 页框号 | 段表：段号 → 基址 + 段长 |
| 物理地址 | 页框号与偏移**拼接** | **基址 + 段内偏移** |
| 越界检查 | 一道 | 两道 |
| 共享与保护 | 不便按逻辑单位 | 按段共享、按段设权限 |
| 碎片 | 页内（**内部**） | 段间（**外部**，同可变分区） |

**易混对 分页地址也分两部分，为何是一维**
- 判据｜偏移会不会进位到前一部分：会 → 页号和偏移本是同一个数的高低位 → 一维；不会、直接越界 → 段号是选择器，每段从 0 各自编号 → 二维。
- 例子｜页 2 的偏移加到 4096 自动变成页 3 偏移 0（2×4096 + 4096 = 3×4096）→ 一维；段 1 偏移加到 6144 不会变成段 2 偏移 0，而是越界中断 → 二维。

分页时程序员只写 `0x2F6A` 一个数，不知道有页这回事；分段时段长只有编译器、链接器知道，硬件无法从一个数里切出段号，(1, 3946) 只能由程序显式给出。

「各段从 0 编号」也解释了培训资料记的分段优点——**各段程序修改互不影响**：打印模块改大 1KB，其他段地址不动（分页那条直线中间插 1KB，后面地址全挪）；一整段是完整逻辑单位，可整段共享、整段设只读。缺点「内存利用率低、内存碎片浪费大」指外部碎片回来了。

## 五、段页式存储管理（计算）

分段得了共享和保护，分页消灭了外部碎片；**先按逻辑分段，段内再按物理分页**。逻辑地址三段：**段号 + 段内页号 + 页内偏移**。

**碎片账（report，页 4KB）**：外部碎片没了（每段整页放），内部碎片变重——每段最后一页都填不满。

```
段 0  8KB → 2 页，浪费 0
段 1  6KB → 2 页，浪费 2KB
段 2  5KB → 2 页，浪费 3KB
合计 6 页 24KB 装 19KB，废 5KB；纯分页 5 页 20KB，只废 1KB
```

**算例：翻译 0x2F6A。**

1. 按段定位：段 **1**，段内偏移 12138 − 8192 = **3946**。
2. 段内按页切：3946 ÷ 4096 = 0 余 3946 → 段内页号 **0**，页内偏移 **0xF6A**。
3. **先查段表**：段页式段表项记的是**该段页表的始址 + 页表长度**（段内是页、不连续，不再记基址 + 段长）→ 拿到段 1 的页表。**再查页表**：页 0 → 页框 **0x1A**。
4. **拼**：0x1A 接 F6A → **0x1AF6A**。

结果和第二节相同是刻意把段 1 页 0 也放在 0x1A，不是必然——换一套映射表，落到哪个页框由表说了算。必然相同的是最后一步：**页框号接上原封不动的页内偏移**（纯分段最后一步是相加，段页式回到拼接）。

**访存次数：**

| 方式 | 取一个数 | 快表命中 |
|---|---|---|
| 分区 | 1（不查表） | — |
| 分页 | 2（页表 + 取数） | 1 |
| 分段 | 2（段表 + 取数） | 1 |
| 段页式 | 3（段表 + 页表 + 取数） | 1 |

培训资料记段页式：优点「空间浪费小、存储共享容易、存储保护容易、能动态链接」；缺点「管理软件增加、复杂性和开销增加、硬件需求增加、执行速度大大下降」——速度下降就是访存三次的后果。

四种方式是一条换取链：分区简单但要连续、要全装入；分页去外部碎片、硬件自动切，多查一次表（于是有快表）；分段得共享保护，外部碎片回来；段页式两者兼得，访存三次。没有哪种全赢，某方式的缺点都在这条链里。

## 速记

- **偏移位数 = log₂(页大小)；页号位数 = 地址位数 − 偏移位数；最多页数 = 2^页号位数**；页框号位数可与页号不同，偏移位数两边必须一样
- 翻译：**页号换页框号，偏移不动**；4KB 切低 3 位十六进制，否则 ÷页大小取商余；验算 物理 − 逻辑 = (页框号 − 页号) × 页大小
- 分配：首次=从头第一个够的、最佳=够用里最小的、最差=最大的、循环首次=从上次停处往下
- 碎片：**定长→内部（固定分区、分页、段页式）；变长→外部（可变分区、分段）**；紧凑只治外部
- **分页不可见、一维、拼接；分段可见、二维、基址+段内偏移相加**；段表记基址+段长
- 快表缓存**页表项**（Cache 缓存数据）；**EAT = λ + (2−a)·t**，λ=0 时 (2−a)·t
