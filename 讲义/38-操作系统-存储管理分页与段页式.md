## 开讲：跟着一个字节，看它怎么落到内存条上

你在代码里 `printf("%p", ptr)` 打出来的那个地址，不是内存条上的位置。它叫**逻辑地址**（也叫虚地址、相对地址）——程序自己认为的地址，每个程序都从 0 开始编号。内存条上真正的那个位置叫**物理地址**（也叫实地址、绝对地址）。两个进程可以各自打印出同一个地址值却互不干扰，就因为它们拿的是两张各自为政的假地图。这一课讲的就是：这张假地图按什么粒度切、靠什么表翻译成真地址。

全课跟着同一个程序走：一个报表程序 **report**，编译完 **19KB**，逻辑上是三块——代码 8KB、打印模块 6KB、数据 5KB。再盯住其中同一个字节：逻辑地址 **0x2F6A**（十进制 12138）。四种管理方式轮流上场，每次都算一遍这个字节落在哪。

### 一、最朴素的办法：整块搬进去（分区存储管理）

分区法的思路一句话：**整存**——进程运行所需的内存**整体一起**分配给它，装完再执行。

**固定分区**是静态划分：开机就把主存切成若干个大小固定的分区。report 要 19KB，系统把一块 **24KB** 的分区整个划给它，剩下的 5KB 谁也用不了——因为这块分区已经登记在 report 名下了。这种"分给你了、你却填不满、废在块内部"的浪费叫**内部碎片**。

**可变分区**是动态划分：作业（＝等着上机运行的那个程序，教材和考题都用这个词）进来时才按它的实际大小划，report 就划 19KB，一点不多给，内部碎片没了。但装了卸、卸了装几轮之后，主存被切成许多互不相邻的小块。这些小块**还没分给任何人**，只是各自太小、又连不起来，谁也用不上——这叫**外部碎片**。

两种碎片的归属，一句话记死：**定长切分，里面填不满 → 内部碎片；变长堆放，块与块之间留缝 → 外部碎片。**

**可重定位分区**是给外部碎片开的药：把已经分配出去的区域整体往一头搬，让中间的缝隙合并成一大块（也叫紧凑、内存拼接；注意别和后面地址翻译时"页框号拼接偏移"的拼接混为一谈，那是拼二进制位，这是搬内存）。搬完之后每个程序的起始位置都变了，程序里那些"跳到第几号地址"得跟着换算一遍，"重定位"就是指这个换算——这也是搬家很贵的原因，所以只在有作业申请空间却满足不了时才做一次。

**四种分配算法。** 现在 report 要 19KB，内存里按地址从低到高有这些空闲块（培训资料这里只有一张示意图、没给数值，下面这组数是**本课设定**，不是真题数据；后面练习 6 用的是同一组）：

| 空闲块 | 起始地址 | 大小 |
|---|---|---|
| 块1 | 0K | 32K |
| 块2 | 100K | 24K |
| 块3 | 200K | 48K |
| 块4 | 300K | 21K |

先别往下看：**你觉得该给哪一块？** 这题没有唯一答案，四种算法给出四个不同的块，而这正是考点。

- **首次适应法**：按地址顺序从头找，第一个 ≥19K 的就切给它 → **块1**（32K），剩 13K。找得快，但低地址那头被反复切碎。
- **最佳适应法**：把所有空闲块按从小到大排，找第一个 ≥19K 的，也就是够用里最小的那个 → **块4**（21K），剩 **2K**。名字叫"最佳"，指的是本次最省；可留下的这 2K 小到再也没人要，它反而最擅长制造细小的外部碎片。
- **最差适应法**：挑最大的那块切 → **块3**（48K），剩 29K。剩下的还够大、还能再分，专门用来预防细小碎片；代价是大块很快被啃光，来个大作业就没地方了。
- **循环首次适应法**：和首次适应同一个判据，只是**起点不是表头，而是上次分配停下的地方**。假设上一次刚分完块1，这次就从块2 往下找 → **块2**（24K），剩 5K。好处是空闲块被均匀地用起来，不会总在低地址反复切。

分区法的死穴就在"整存"两个字：程序必须**整个装进内存**，还必须占**一段连续**的空间。可现实是内存往往装不下整个程序，而且程序绝大部分代码这一次运行根本不会执行到。下面两节就是拆这两个前提。

### 二、把内存切成等大的格子：分页存储管理

要同时甩掉"连续"和"全装进来"这两个要求，办法是把物理内存机械地切成**大小相等**的格子，程序也按同样大小切开，然后一格一格地放，放哪儿都行，用到哪块才装哪块。

- **页**（page，也叫页面）：逻辑地址空间被等分出来的一块。
- **页框**（frame，也叫物理块、页帧）：物理内存被等分出来的一块。页和页框**大小必须相等**，这样任意一页都能塞进任意一个空闲页框。

report 19KB，页大小取 4KB → 切成 5 页（页 0～4），最后一页只装了 3KB，剩 1KB 空着。**外部碎片被彻底消灭了**（任何一个空闲页框都能用，不存在"太小用不上"），代价是每个进程最后一页平均浪费半页的**内部碎片**。培训资料给分页记的优点"利用率高、碎片小、分配及管理简单"，说的就是这件事。

**地址为什么天然能拆成两段。** 页大小 4K，逻辑地址 0x2F6A，页号是多少？先别算，想想该从哪儿切。

逻辑地址 0x2F6A（十进制 12138）要回答两个问题：在第几页？页内第几个字节？

```
第几页   = 12138 ÷ 4096 = 2
页内第几 = 12138 − 2×4096 = 3946（余数）
```

关键在于 4096 = **2¹²**——页大小永远取 2 的幂，就是为了下面这句话成立：在二进制里，除以 2¹² 就是**右移 12 位**，余数就是被移掉的那低 12 位。也就是说这个除法和取余根本不必真做，**把地址从低位数第 12 位处切一刀就行：低 12 位是页内偏移，高位是页号**。

两条公式就是这么长出来的，不是背来的规定：

> **页内偏移位数 = log₂(页大小)**　　**逻辑地址位数 = 页号位数 + 页内偏移位数**

十六进制更省事：1 个十六进制位 = 4 个二进制位，12 ÷ 4 = 3，所以 **0x2F6A 的低 3 位十六进制 `F6A` 就是页内偏移，高位 `2` 就是页号**，连算都不用算。反过来注意：页大小 1KB = 2¹⁰，10 不是 4 的倍数，就切不出整齐的十六进制位，只能老老实实走除法。

给 report 补上机器参数：逻辑地址 **16 位**（程序眼里是一片 64KB 的连续空间）→ 页号占 16 − 12 = **4 位**，最多 16 页；机器物理内存 **1MB** → 物理地址 **20 位**，页框号占 20 − 12 = **8 位**，共 256 个页框。**页号位数和页框号位数不必相等**，只有页内偏移那 12 位两边必须一样——因为页和页框一样大。

**页表**是每个进程一张的对照表，记"我的第几页放在哪个页框"，表里的一行叫**页表项**。哪一页放进哪个页框，取决于装入那一刻哪个页框空着，所以**页号和页框号不按顺序对应**（下表里页 0 落在 0x0C、页 1 反而落在更小的 0x07）——正因如此才非查表不可，绝不能拿页号直接算出物理地址。考试计算题只用"页号 → 页框号"这一列，实际的页表项还有有效位（这一页此刻在不在内存，题面里也常写作**状态位**，两个词是一回事）、访问位（最近有没有被读写过）、修改位（调进来之后有没有被改过，改过的换出时要写回磁盘）。页表自己也躺在内存里，CPU 靠**页表寄存器**找到它：一个字段存页表始址 B，另一个存页表长度 L（本进程一共几页）。取出页号先和 L 比一下，页号 ≥ L 说明这个地址不属于本进程 → **越界中断**。report 的 L = 5，所以 0x6F6A（页号 6）会被当场拦下。

| 页号 | 页框号 |
|---|---|
| 0 | 0x0C |
| 1 | 0x07 |
| **2** | **0x1A** |
| 3 | 0x2F |
| 4 | 0x11 |

翻译 0x2F6A，三步：

1. **切**：低 3 位十六进制是偏移 `F6A`，高位是页号 `2`。
2. **查**：页号 2 < L=5，不越界；查页表得页框号 **0x1A**。
3. **拼**：页框号接上**原封不动**的偏移 → 物理地址 **0x1AF6A**。

验算：0x1AF6A = 110442，0x2F6A = 12138，差 98304 = (26 − 2) × 4096，正好 24 个整页。**只换了块号，块内相对位置分毫未动**——这就是整节的核心口径：**页号换成页框号，页内偏移一个字都不动。**

那页不在内存呢？这正是开头说的第二个前提被拆掉的地方：程序不必整个装进内存，**用到哪一页才把哪一页从磁盘调进来**，这种做法有个专名叫**请求分页**（后面讲义 39 和真题题干都直接用这个词）。具体机制是：页表项的有效位标着"无效"，CPU 就发出**缺页中断**（要用的页还在磁盘上而触发的中断）。处理程序去磁盘找到这一页：有空闲页框就直接调进来，没有就先按置换算法赶走一页腾地方（FIFO/LRU/OPT 在讲义 39）；回填页表之后**重新执行**刚才被打断的那条指令，这一次就正常了。系统分给一个进程的那几个页框、也就是它此刻在内存里的那些页，叫它的**驻留集**。驻留集给得太小，刚换出去的页马上又要用，CPU 大半时间耗在搬页上，这就是**抖动**——培训资料给分页记的缺点"增加系统开销、可能产生抖动"，后半句指的是它。

> 培训资料在页面置换那一节把 FIFO 的"分配的页框越多、缺页反而越多"也叫抖动，那其实是 **Belady 异常**，和这里的抖动是两回事，别混；具体见讲义 39。

### 三、页表自己也在内存里：快表 TLB

上一节留了个大窟窿：页表放在内存里，所以 CPU 取一个数据要**访存两次**——第一次去内存查页表拿页框号，第二次才真正取到数据。有效速度直接砍半，这个代价没法接受。

解法照抄 Cache 的思路：把**最近用过的那几条页表项**复制一份到一小块高速存储里，这块东西叫**快表（TLB）**，教材也叫**联想存储器 / 相联存储器**——它按内容并行比对，一次把所有项比完，所以快。相对地，内存里那张完整页表就叫**慢表**。它之所以有效，靠的是局部性原理（讲义 04）：程序一段时间内翻来覆去就用那么几页，缓存下来命中率很高。

和 Cache 是同一个道理，但**缓存的东西不同**：**Cache 缓存数据和指令本身，快表缓存的是页表项，也就是地址翻译的结果。**

> 培训资料写"快表是将页表存于 Cache 中"，是借用"高速缓存"这个词打的比方。实际 TLB 是地址翻译部件里独立的一块相联存储器，不是数据 Cache。考试按"快表快、慢表在内存、慢表要两次访存"作答即可，别答成"快表和 Cache 是同一个部件"。

**有效访问时间 EAT。** 快表访问 20ns，内存访问 100ns，命中率 90%。命中一次是 20+100 = 120ns——那 EAT 是不是就约等于 120ns？先猜一下。

分两条路算：

| 情况 | 概率 | 耗时 |
|---|---|---|
| 快表命中 | a = 0.9 | 查快表 λ=20 + 访存取数 t=100 = **120ns** |
| 快表未命中 | 1−a = 0.1 | 查快表 20（扑空）+ 访内存查页表 100 + 访存取数 100 = **220ns** |

EAT = 0.9 × 120 + 0.1 × 220 = 108 + 22 = **130ns**。不是 120——那 10% 的未命中每次要多花 100ns，摊到平均里就是 10ns。把两行合并整理：

> **EAT = a(λ + t) + (1 − a)(λ + 2t) = λ + (2 − a)·t** = 20 + 1.1 × 100 = 130ns ✔
> 题目若说"忽略快表访问时间"（λ = 0，考试很常见）：**EAT = (2 − a)·t** = 110ns。

和完全不设快表比：每次都要"查页表 + 取数" = 200ns，130ns 相当于快了 35%，这就是快表存在的全部理由。验算习惯：EAT 一定落在 λ+t 与 λ+2t 之间（本例 120～220ns），命中率再高也省不掉"查快表 + 取数"，再低也不会超过"查快表 + 查页表 + 取数"；算出来跑出这个区间，一定错了。

最后分清一件事：**快表未命中 ≠ 缺页**。未命中只说明这条翻译没被缓存，那一页多半好端端在内存里；页真的不在内存，那才是缺页中断。两者是两层完全不同的"没找到"。

### 四、按逻辑切：分段存储管理

分页有个改不掉的毛病：切分点是**机械**定的，和程序逻辑毫无关系，一个函数很可能被腰斩进两页。后果有两个：想让两个进程共用同一份打印模块代码，共用的必须正好是整页，对不齐就没法共享；想给代码设只读、给数据设可写，可一页里既有代码又有数据，权限没法设。

那就换个切法：按**段**切——一段就是一个逻辑单位，主程序、子程序、数组、栈各成一段。report 天然是三段（**基址**＝这一段被装到内存里哪个位置起头，由系统装入时定，三段可以彼此不挨着）：

| 段号 | 内容 | 段长 | 基址 | 在逻辑空间里的区间 |
|---|---|---|---|---|
| 0 | 代码 | 8192（8KB） | 52000 | 0 ～ 8191 |
| 1 | 打印模块 | 6144（6KB） | 100000 | 8192 ～ 14335 |
| 2 | 数据 | 5120（5KB） | 73000 | 14336 ～ 19455 |

**段表**和页表长得不一样：段是变长的，光知道"这段放在哪"不够，还得知道"这段有多长"（越界要靠它判），所以段表每一行有**基址**和**段长**两个字段——上表中间那两列就是段表本体，最后一列是为讲解补的。

**翻译一个分段地址。** 同一个字节 0x2F6A（12138），分段里写成 **(1, 3946)**——"段 1 的第 3946 字节"（段 0 占了 0～8191，12138 − 8192 = 3946）。查段表：段 1 基址 100000、段长 6144，3946 < 6144 不越界 → **物理地址 = 100000 + 3946 = 103946**。最后一步是**加法**，不是分页那种拼接：段基址是任意值（100000 除以 4096 余 1696，压根不对齐），没有"高位低位"可言，只能实打实地加。**分页拼接、分段相加**，这是两者落地方式的分水岭。

**这里是本课最值钱的一对概念。** 分页时程序员只写 `0x2F6A` 一个数，硬件按固定页大小自动切成"页 2 + 偏移 F6A"，他根本不知道有页这回事，眼里就是一条从 0 到 64K 的连续直线——所以**分页对用户不可见，作业地址空间是一维的**。分段时段是变长的，硬件没法从一个数里切出段号（切在哪儿取决于每段多长，而这只有编译器和链接器知道），(1, 3946) 这两个数只能由程序**显式**给出——所以**分段对用户可见，作业地址空间是二维的**。

读到这儿多半会冒出一个反驳：**分页的地址不也拆成"页号 + 页内偏移"两部分吗，凭什么它叫一维？** 这个反驳正是本考点最常见的翻车点，值得当场答死。判据是**偏移会不会进位到前一段**：

- 分页里，页 2 的偏移一直加，加到 4096 就自动变成"页 3 的偏移 0"（2×4096 + 4096 = 12288 = 3×4096）。**页号和偏移不是两个独立的坐标，它们本来就是同一个数的高位和低位**——只是被硬件临时拆开看了一眼，加减法照样能一路做下去。所以它始终是一条直线上的一个刻度：**一维**。
- 分段里，段 1 的偏移加到 6144（段 1 的段长），**不会**变成"段 2 的偏移 0"，而是直接越界中断。段号根本不是"更高的位"，它是一个选择器：先用它挑出一条线，再在这条线上走多远。**每段都从 0 重新编号，各是各的直线**，一叠互不相通的直线要用两个坐标才能定位：**二维**。

这个"各段各自从 0 编号"顺手解释了培训资料给分段记的那条优点——**各段程序修改互不影响**：打印模块改大了 1KB，它自己的地址仍是 0 起步，代码段和数据段的地址一个都不用动；换成分页那条连续直线，中间插进 1KB，后面所有地址全得跟着挪。共享和按段设权限也是同一个道理：一整条线就是一个完整的逻辑单位，可以整条拿去共享、整条设成只读。

越界检查也跟着分家，而且分段要查**两道**。和分页的页表寄存器对应，分段也有**段表寄存器**，存段表始址和段表长度：第一道，段号和段表长度比，段号超了说明这个段压根不属于本进程 → 越界中断（这道和分页的"页号 vs 页表长度 L"是同一件事）；第二道，段内偏移和查出来的**段长**比，3946 < 6144 才放行 → 这道是分段独有的，因为段长是变的，不比不知道。分页只有第一道：页内偏移是按固定页大小截出来的，取值天生就超不出一页，不用比；但别把"分页不做偏移越界检查"记成"分页什么都不检查"。

碎片也换了一边：段是变长的，装装卸卸之后段与段之间留缝，**外部碎片又回来了**，和可变分区一个毛病。培训资料给分段记的缺点"内存利用率低、内存碎片浪费大"，指的就是这个；而它记的那两条优点，上面那段已经解释过了。

### 五、两边都要：段页式存储管理

分段拿到了共享和保护，分页消灭了外部碎片。想都要，就**先按逻辑分段，每段内部再按物理分页**。

逻辑地址因此变成三段：**段号 + 段内页号 + 页内偏移**。

段与段之间不再留缝（每段都是整页整页地放），**外部碎片没了**；但内部碎片变严重了——纯分页时整个进程只有最后一页填不满，段页式是**每段的最后一页都填不满**。拿 report 数一遍：段 0 是 8KB 正好 2 页不浪费，段 1 是 6KB 要 2 页、第 2 页只装 2KB 浪费 **2KB**，段 2 是 5KB 也要 2 页、浪费 **3KB**，合计 6 页 24KB 装 19KB，废掉 **5KB**；而第二节纯分页只要 5 页 20KB，只废 **1KB**。段越多，这笔账越贵——这是段页式的代价之一。

还是那个字节 0x2F6A：

1. 先按段定位：段 **1**，段内偏移 12138 − 8192 = **3946**。
2. 段内偏移再按页切：3946 ÷ 4096 = 0 余 3946 → 段内页号 **0**，页内偏移 **0xF6A**。
3. **先查段表**：段页式的段表项和纯分段又不一样了——纯分段记"基址 + 段长"，段页式的段里装的是页、不再连续，所以记的是**这一段的页表存在哪里**（页表始址 + 页表长度）。段 1 → 拿到它那张页表。**再查这张页表**：页 0 → 页框号 **0x1A**。
4. 拼：0x1A 接上 F6A → 物理地址 **0x1AF6A**。

这里刻意把段 1 的页 0 也安排在页框 0x1A，物理地址才和第二节纯分页一模一样——**这是为对比而设，不是必然**：换一种管理方式就是换一套映射表，同一个逻辑地址落到哪个页框，完全由那套表说了算。真正必然相同的是**最后一步**：不管前面拆成两段还是三段，落地时永远是"页框号接上原封不动的页内偏移"（注意这也是段页式与纯分段的一处差别——纯分段最后一步是基址相加，段页式最后一步又回到了拼接）。

**访存次数**是段页式的固定考点，把四种方式排在一起看：分区不查表，取数 **1 次**；分页查页表 1 次 + 取数 1 次 = **2 次**；分段查段表 1 次 + 取数 1 次 = 同样 **2 次**；段页式查段表 1 次 + 查页表 1 次 + 取数 1 次 = **3 次**；有快表且命中时，翻译一步到位，分页、分段、段页式一律降到 **1 次**。培训资料给段页式记的优点是"空间浪费小、存储共享容易、存储保护容易、能动态链接"，缺点是"管理软件增加、复杂性和开销增加、硬件需求增加、执行速度大大下降"——最后这条"速度下降"，就是访存三次的直接后果。

四种办法排成一条线：分区整块搬，简单，但要连续、要全装进来；分页把物理内存机械等分，外部碎片没了、地址由硬件自己切，代价是多查一次表（于是有了快表）；分段按逻辑切，共享和保护有了，外部碎片又回来了；段页式把两条线拧在一起，代价是访存三次。每一步都是拿上一步的短板换来的，没有哪一种全赢——考试问"某某方式的缺点"，答案基本都在这条线的换取关系里。

## 考试怎么考

**考点① 分区分配算法。** 题目给一张内存空闲块图或表，加一个申请大小，问某算法分到哪一块。四句话解决：首次 = 从表头起第一个够的；最佳 = 够用的里面最小的；最差 = 最大的；循环首次 = 从**上次停下的位置**往下第一个够的。常见错法：把"最佳"望文生义成"最合适"而挑大块；循环首次仍从表头开始找；问固定分区的浪费答成外部碎片（固定分区是定长切分，答内部碎片）。

**考点② 地址结构位数拆分。** 问"页号占几位""最多多少页"。三步：页大小写成 2ᵏ，k 就是页内偏移位数；地址总位数由题目给出或从空间大小换算（16MB = 2⁴ × 2²⁰ = 2²⁴，是 24 位不是 20 位）；页号位数 = 总位数 − k，最多页数 = 2^页号位数。常见错法：单位换算漏项（1K = 2¹⁰、1M = 2²⁰、1G = 2³⁰）；把页大小和地址空间两个数代反；以为"逻辑地址 = 页号 + 偏移"是数值相加（是高低位**拼接**）；以为页框号位数必须等于页号位数（物理内存和逻辑空间可以不一样大，只有偏移位数两边相同）。验算：页号位数 + 偏移位数还原回总位数就没错。

**考点③ 逻辑地址 → 物理地址。** 口径一句话：页号换成页框号，偏移原样照抄。**十六进制题面**：页大小是 2^(4 的倍数) 时直接切十六进制位（4KB → 低 3 位是偏移），把高位换成页框号即可，不要换十进制。**十进制题面**：地址 ÷ 页大小 = 商（页号）余（偏移），物理地址 = 页框号 × 页大小 + 偏移。常见错法：页大小 1KB = 2¹⁰，10 不是 4 的倍数却硬切十六进制位；拿页号乘页大小当物理地址（忘了查表）；直接把逻辑地址当答案（选项里一定埋着这个原数）。验算：物理地址 − 逻辑地址 = (页框号 − 页号) × 页大小。

**考点④ 分页 vs 分段辨析。** 四个选项里通常有两条是把下表某一行**说反**，逐条对表，说反的排除：

| 对比点 | 分页 | 分段 |
|---|---|---|
| 划分依据 | 物理上机械等分，与程序逻辑无关 | 按程序的逻辑功能模块划分 |
| 长度 | 固定（页与页框必须等大） | 可变（各段长度可不同） |
| 对用户 | **不可见**，硬件自动切 → 地址空间**一维** | **可见**，必须自己给段号 → 地址空间**二维** |
| 地址结构 | 页号 + 页内偏移（一个数） | 段号 + 段内偏移（两个数） |
| 对照表字段 | 页表：页号 → 页框号 | 段表：段号 → **基址** + **段长** |
| 算物理地址 | 页框号与偏移**拼接**（偏移原样照抄） | **基址 + 段内偏移**，是真加法（段基址不对齐，没法拼） |
| 越界检查 | 只查一道：页号与页表长度 L 比（偏移是定长截出来的，天生超不出去） | 查两道：段号与段表长度比、段内偏移与**段长**比 |
| 共享与保护 | 不便按逻辑单位共享 | 便于按段共享、按段设权限 |
| 碎片 | 页内碎片（**内部**） | 段间碎片（**外部**） |

术语同义提醒：页 = 页面；页框 = 物理块 = 页帧。题面换词是同一个东西。

**考点⑤ 段页式。** 记死两句：地址三段是**段号 + 页号 + 页内偏移**（段在最高位）；**先查段表拿页表，再查页表拿页框**，共访存 3 次，快表命中降到 1 次。常见错法：查表顺序说成"先页表后段表"；最低位写成"段内偏移"（最终落地的是页，是**页内**偏移）；写成纯分页的两段式，漏掉分段那一层。

**考点⑥ 快表与 EAT。** EAT = λ + (2 − a)·t；题目说忽略快表访问时间就是 (2 − a)·t。最主要的失分点是**未命中时忘了访存两次**（查页表 + 取数）。λ 给了就两条路都要加，未命中同样是先查过快表才发现扑空。另有一处口径差异要心里有数：本式默认**忽略未命中后把新页表项写回快表的时间**（主流资料都这么处理），个别资料把它算进去写成 λ + t + λ + t，选项对不上时按题目自己的说法走，别急着判自己算错。问"引入快表的主要目的"，答"加快地址变换、减少访问页表带来的额外访存"，不是"扩大内存"也不是"缓存数据"。

**考点⑦ 中断辨析与缺页流程。** 页不在内存 → **缺页中断**；页号 ≥ 页表长度、段号 ≥ 段表长度、段内偏移 ≥ 段长，这三种都是 → **越界中断**。缺页处理完是**重新执行**被打断的那条指令，不是跳过它；有空闲页框时**不需要**置换。

### 参考答案

1. **B**。页大小 4K = 2¹² → 十六进制低 3 位是页内偏移：1D16H 拆成页号 `1`、偏移 `D16`；查表页 1 → 物理块号 3；把高位换成 3，偏移照抄 → **3D16H**。A 取的是页 0 那一行、偏移也没有照抄；C、D 分别是查错成页 2、页 3 那一行的结果。
2. **B**。段表题只考一件事：**段内偏移必须小于段长**。A、C 都含 (0，1597)，而 0 段段长只有 600，越界；D 含 (4，1066)，4 段段长 960，也越界。B 的三个地址 128<600、30<50、1390<2988 全部合法。合法之后再算物理地址，用的就是"基址 + 段内偏移"：1598+128 = 1726、486+30 = 516、1327+1390 = 2717——**相加，不是拼接**，这一步和分页彻底分道。
3. **B**。页大小 2KB = 2¹¹ → 偏移 11 位；16MB = 2⁴ × 2²⁰ = 2²⁴ → 地址 24 位；页号 = 24 − 11 = 13 位。C、D 把 16MB 错算成 22 位，A 把偏移位数当成了页号位数。
4. **A**。1KB = 2¹⁰，10 不是 4 的倍数，走除法：2100 ÷ 1024 = 商 2 余 52 → 页号 2、偏移 52；页 2 → 框 9；物理地址 = 9 × 1024 + 52 = **9268**。B 是没查页表，C 是把偏移丢了，D 是把页框号错取成 1。
5. **B**。三段式是段号 + 页号 + **页内**偏移，先用段号查段表找到该段的页表，再用页号查页表得页框号。A 偏移写错且顺序反了，C 组成顺序和查表顺序都错，D 漏掉分段那一层。
6. **B**。四种算法各自的结果：首次→块1（第一个 ≥19K 的），最佳→块4（够用里最小的 21K），最差→块3（最大的 48K），循环首次→块2（上次停在块1，从块2 往下第一个够的）。只有 B 的两条都对得上。
7. **C**。命中 0.9 × (20+100) = 108，未命中 0.1 × (20+100+100) = 22，合计 **130**。A 是把快表访问时间漏掉了（那是 λ=0 的口径），B 是只算了命中那条路，D 是完全不设快表的情况。
8. **D**。A 把划分依据说反；B 把维数说反（分页由硬件按固定页大小自动切，程序员只写一个地址，是一维；分段必须显式给段号，是二维）；C 错在页大小固定、页表不需要段长字段。D 正确：定长切分留内部碎片，变长堆放留外部碎片。
9. 8KB = 2¹³ → 偏移 13 位；页号 = 30 − 13 = **17 位**；最多 2¹⁷ = **131 072 页**。验算：2¹⁷ × 2¹³ = 2³⁰，与 30 位地址空间一致 ✔
10. 4KB = 2¹² → 低 3 位十六进制是偏移：页号 `2`、偏移 `A20`；页 2 → 框 15 = **F**；物理地址 = **FA20H**（= 64032）。验算：64032 − 10784 = 53248 = (15 − 2) × 4096 ✔
11. **3 次**（查段表、查页表、取数）；快表命中时省掉查段表和查页表两次，只剩 **1 次**取数。
12. 分区已经登记在这个程序名下、填不满而废在块内部 → **内部碎片**；那 2KB 还没分给任何人，只是太小又不相邻 → **外部碎片**。

## 速记

- **页内偏移位数 = log₂(页大小)；页号位数 = 逻辑地址位数 − 偏移位数；最多页数 = 2^页号位数**；页框号位数可以和页号位数不同，只有偏移位数两边必须一样
- 翻译口径：**页号换页框号，偏移一个字都不动**；十进制"÷页大小得商余"，十六进制"4KB 切低 3 位"；验算 **物理 − 逻辑 = (页框号 − 页号) × 页大小**
- 分配算法：首次=从头第一个够的、最佳=够用里最小的、最差=最大的、循环首次=从上次停处往下
- 碎片：**定长切→内部（固定分区、分页）；变长堆→外部（可变分区、分段）**；紧凑只治外部碎片
- **分页对用户不可见、一维**（硬件自动切）；**分段对用户可见、二维**（自报段号+段内偏移）；页表只记页框号→物理地址靠**拼接**，段表记基址+段长→物理地址靠**基址+段内偏移相加**
- 快表 TLB 缓存**页表项**（Cache 缓存数据），内存里的完整页表叫慢表；**EAT = λ + (2−a)·t**，忽略 λ 时 (2−a)·t，未命中要访存两次
- 段页式：**段号+页号+页内偏移**，**先段表后页表**；访存次数 分区 1 / 分页 2 / 分段 2 / 段页式 3，快表命中一律 1
- 中断：页不在内存=**缺页中断**（处理完**重新执行**原指令，有空闲页框不用置换）；页号≥页表长度、段号≥段表长度、段内偏移≥段长，三者都是**越界中断**；快表未命中 ≠ 缺页
