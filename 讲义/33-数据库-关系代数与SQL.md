## 开讲：你会写 SQL，只是从来没数过行和列

全课只用下面三张小表，所有运算和 SQL 都在它们身上做，行数列数你都能自己数。

```
S（学生）4行3列   C（课程）3行2列   SC（选课）5行3列
学号 姓名 年龄    课程号 课程名     学号 课程号 成绩
S01  张三  20     C01   数据库      S01  C01   85
S02  李四  22     C02   操作系统    S01  C02   70
S03  王五  20     C03   英语        S02  C01   90
S04  赵六  19                       S02  C02   60
                                    S03  C01   55
```

留意两处空缺：**赵六一门课没选，英语一个人没选**——第四节讲外连接全靠它俩。

先把词对上。数据库里的一张表，理论里叫**关系**；一行叫**元组**（一条记录），一列叫**属性**（一个字段），某属性允许取值的范围叫**域**（"年龄"的域是 0–150 的整数）；只写"表叫什么、有哪些列"的骨架叫**关系模式**，写作 S(学号, 姓名, 年龄)。

**关系代数**是一组作用在表上的运算，核心设定只有一条：**输入是表，输出还是表**，所以能像四则运算那样层层嵌套。而 SQL 是**声明式**的——只说"要什么"不说"怎么算"，数据库拿到它正是翻译成一串关系代数动作去执行。所以这一课是**把已经会写的 SQL 拆回底下那几个动作**，拆开之后"为什么 WHERE 里不能写 AVG()""为什么自然连接的列数要减一下"就不用背了。

### 一、一张表只能两个方向切：选择 σ 与投影 π

**选择 σ（读 sigma）＝ 横着切、挑行 ＝ SQL 的 WHERE。** σ<sub>条件</sub>(R) 把满足条件的元组留下，**一列不动**。σ<sub>年龄=20</sub>(S) 逐行验：S01 张三 20 ✓、S02 李四 22 ✗、S03 王五 20 ✓、S04 赵六 19 ✗，结果 **2 行 3 列**，对应 `SELECT * FROM S WHERE 年龄=20`。

**投影 π（读 pai）＝ 竖着切、挑列 ＝ SQL 里 SELECT 后面那串列名。** π<sub>列名</sub>(R) 只留指定的列，一行不筛——但有个附带动作：π<sub>年龄</sub>(S) 只留年龄列得 20、22、20、19，而**关系是集合，不允许有重复元素**，所以要去重 → {20, 22, 19}，**3 行 1 列**（原表 4 行）。

⚠ 这是关系代数和 SQL 最要紧的一处对不上：`SELECT 年龄 FROM S` 返回 **4 行**且**不去重**，写 `SELECT DISTINCT 年龄 FROM S` 才是 3 行、才等价于 π。这条差别常被做成叙述题的错误项。

两个下标不能装错：**σ 的下标必须是条件，π 的下标必须是列名**（也可写列号，π<sub>1,3</sub> 即第 1、3 列——真题就这么出）。

顺序也不能反：要"20 岁学生的姓名"，正确写法是 **π<sub>姓名</sub>(σ<sub>年龄=20</sub>(S))**，先挑行再挑列；反过来写 σ<sub>年龄=20</sub>(π<sub>姓名</sub>(S)) 非法——π 出来的表只剩姓名一列，年龄列已被扔掉，外层拿什么去比？

### 二、两张表怎么凑一起：笛卡尔积 ×

**笛卡尔积 R×S**：左表每一行去配右表每一行，配出的每条把两边的列**全部拼起来**。

先把 S 削小一点好数：S′ = π<sub>学号,姓名</sub>(σ<sub>学号='S01'∨学号='S02'</sub>(S))，**2 行 2 列**（换小表只为让 10 行铺得下，规则一模一样，数完就换回全表）。S′ × SC：

```
S′的行｜SC 的行   学号对得上吗    S′的行｜SC 的行   学号对得上吗
S01 张三｜S01 C01 85    ✓        S02 李四｜S01 C01 85    ✗
S01 张三｜S01 C02 70    ✓        S02 李四｜S01 C02 70    ✗
S01 张三｜S02 C01 90    ✗        S02 李四｜S02 C01 90    ✓
S01 张三｜S02 C02 60    ✗        S02 李四｜S02 C02 60    ✓
S01 张三｜S03 C01 55    ✗        S02 李四｜S03 C01 55    ✗
```

**行数 = 2×5 = 10，列数 = 2+3 = 5。** 推广：R 有 m 行 a 列、S 有 n 行 b 列，则 **R×S 有 m×n 行、a+b 列**。换回全表：S×SC = 4×5 = **20 行**、3+3 = **6 列**。

10 行里只有 4 行有意义，其余 6 行全是**错配**（张三配了李四的成绩）。所以笛卡尔积几乎不单独用，它是连接的原料——SQL 里 `FROM S, SC` 忘了写条件，出来的就是它。

### 三、连接 ⋈ 就是笛卡尔积后面接一个选择

**θ 连接（读 theta，即条件连接）** R ⋈<sub>条件</sub> S：先做笛卡尔积，再用 σ 筛出满足条件的行，即 σ<sub>条件</sub>(R×S)。条件里的比较符全是等号时特称**等值连接**；等值连接再去掉重复列就是自然连接——三者一层套一层，θ 最宽、自然最窄。S′ ⋈<sub>S′.学号=SC.学号</sub> SC 就是从上表留下打 ✓ 的 4 行：

```
S′.学号 姓名 SC.学号 课程号 成绩    ← 5 列，学号出现了两次
S01    张三   S01    C01   85       S02   李四   S02   C01   90
S01    张三   S01    C02   70       S02   李四   S02   C02   60
```

**学号列出现了两次**，内容完全一样。等值连接不管这件事，列数仍是 a+b = **5 列**。

**自然连接 R ⋈ S** 就是把这尾巴收拾干净的版本，规则固定成两条：① 按**两表全部同名属性**取值相等来连（不用写条件）；② 结果里**同名属性只留一份**。于是上表变成 4 行 4 列：学号、姓名、课程号、成绩。

**先别往下看：S(学号,姓名,年龄) 是 3 列，SC(学号,课程号,成绩) 也是 3 列，S ⋈ SC 有几列？**

多数人脱口而出 6。数一遍：学号、姓名、年龄、课程号、成绩，**5 列**——公共属性"学号"两边各带一份，按规则②扔掉一份。公式于是自己长出来了：

> **笛卡尔积、等值连接：列数 = a + b**（重复列全保留）
> **自然连接：列数 = a + b − 公共属性个数**

**行数没有公式，只能看实际匹配。** S ⋈ SC = **5 行**（赵六一门课没选，配不上任何行，直接消失）；三表连起来 S ⋈ SC ⋈ C = **5 行 6 列**（3+3+2 减掉学号、课程号两个公共属性）。**列数才有公式，行数必须数。**

> 考试这样问：给两个关系模式，问自然连接后的属性列有几个、是几元关系。这个减号是本课上午题最高频的考点。

（还有个除运算 ÷，回答"选修了全部课程的学生"这类问题，中级几乎不考，认脸即可。）

### 四、落单的行怎么办：外连接

自然连接把赵六**弄丢了**。他确实一门课没选，但"全校学生选课情况一览"这种报表里他不该凭空消失。

**外连接**：连接结果之外把落单的行也留下，另一边的列用 **NULL**（空值，"没有值/未知"，既不等于 0 也不等于空串）填上。三个变种：**左外连接 R ⟕ S** 保留左表全部行、**右外连接 R ⟖ S** 保留右表全部行、**全外连接 R ⟗ S** 两边落单的都保留。

**先别往下看：S 有 4 行，S 左外连接 SC 有几行？**

不是 4。匹配上的仍是 5 行（张三 2 门、李四 2 门、王五 1 门），再加赵六补 NULL 的 1 行，共 **6 行**：

```
S01 张三 20｜C01 85    S03 王五 20｜C01 55
S01 张三 20｜C02 70    S04 赵六 19｜NULL NULL  ← 落单的赵六被留下，右半边补空值
S02 李四 22｜C01 90
S02 李四 22｜C02 60
```

同一对表**右外连接只有 5 行**——SC 每一行都能在 S 里找到学生，右边一行不落单，所以这里全外连接也等于左外的 6 行。要看出三者真不同，得找一对"两边各有落单行"的表，见本节末的推演；跳过不影响后面。

SQL 写法是 `LEFT JOIN` / `RIGHT JOIN` / `FULL JOIN`，加不加 OUTER 都一样；不带方向的 `JOIN … ON` 就是上一节的 θ/等值连接，也叫**内连接**，**落单行一律丢掉**。

#### 推演 · 左外、右外、全外什么时候才真的不同

从贯穿表里各切一块，就能凑出一对"两边各有落单行"的关系：甲 = π<sub>学号,姓名</sub>(σ<sub>年龄=20</sub>(S)) = {(S01,张三), (S03,王五)}，乙 = π<sub>学号,成绩</sub>(σ<sub>课程号='C02'</sub>(SC)) = {(S01,70), (S02,60)}。

按学号连：**内连接**（只留两边都配上的行，也就是前面讲的等值/自然连接）**1 行**，只有 S01 两边都在；**左外 2 行**（多出 S03 王五 NULL）、**右外 2 行**（多出 S02 NULL 60）、**全外 3 行**。

### 五、把表当集合看：并、交、差

**前提先说，这是最常考的一句。** ∪、∩、− 要求两关系**相容**（并相容）：**属性个数相同，且对应位置的属性取自同一个域**。道理很直白——并起来的还得是张合法的表；把 3 列的学生表和 2 列的课程表并起来，新表第三格填什么？注意只要求个数与域一致，**列名可以不同**。

拿两个从**不同表**切出来、都只剩"学号"一列的关系演示（相容不要求同源）：A = π<sub>学号</sub>(σ<sub>课程号='C02'</sub>(SC)) = {S01, S02}（选了操作系统的），B = π<sub>学号</sub>(σ<sub>年龄=20</sub>(S)) = {S01, S03}（20 岁的）。

- **并 A∪B**：两边的行合起来，**重复的只留一份** → {S01, S02, S03}，**3 行**。SQL 的 `UNION` 去重，`UNION ALL` 不去重（同样两句得 4 行）。
- **交 A∩B**：两边都有的 → {S01}，**1 行**（SQL `INTERSECT`）。交还能用差写出来：A−(A−B) 也得 {S01}，所以交不算基本运算。
- **差 A−B**：在 A 不在 B → {S02}（选了操作系统但不满 20 岁）。**差没有交换律**：B−A = {S03}（20 岁但没选操作系统），完全是另一行（SQL `EXCEPT`）。

### 六、SQL 的执行顺序：一条队伍推出所有规则

语句骨架：

```
SELECT [ALL|DISTINCT] <目标列表达式>[,…]   FROM <表名或视图名>[,<表名或视图名>]
[WHERE <条件表达式>]   [GROUP BY <列名1> [HAVING <条件表达式>]]   [ORDER BY <列名2> [ASC|DESC]]
```

写的顺序 SELECT 打头，**算的顺序不是**：

```
FROM  →  WHERE →  GROUP BY →  HAVING →  SELECT →  ORDER BY
从哪来 →  删行  →   分堆    →   删堆  →   挑列  →   排序
```

对回关系代数：FROM 是 ×/连接，WHERE 是 σ，SELECT 是 π；GROUP BY、HAVING、ORDER BY 是代数之外的扩展。

两个词先说清。**聚合函数**：把一堆值压成一个值——COUNT 计数、SUM 求和、AVG 平均、MAX 最大、MIN 最小。**分组 GROUP BY**：按指定列把行分成若干堆，每堆算一次聚合，**一堆出一行**。

在 SC 上按学号分堆：S01 {85,70}、S02 {90,60}、S03 {55}，各算平均得 **77.5、75、55**，各算 COUNT 得 2、2、1。

**HAVING 就是"分组之后的那个 σ"**：σ 删行，HAVING 删**堆**。走一遍：

```sql
SELECT 学号, AVG(成绩) FROM SC GROUP BY 学号 HAVING AVG(成绩)>=75;
① FROM SC → 5 行  ② 无 WHERE 不删行  ③ 分成 3 堆  ④ 各算平均 77.5/75/55
⑤ HAVING 删掉 55 那一堆 → 结果 S01 77.5、S02 75
```

**先别往下看：把 `HAVING AVG(成绩)>=75` 换成 `WHERE 成绩>=75`，结果一样吗？**

不一样。WHERE 排在分组**前面**，它先把 70、60、55 这三**行**删掉，只剩 S01 的 85 和 S02 的 90，再分堆算平均 → **S01 85、S02 90**。同一批数据，一个算出 77.5、一个算出 85。**WHERE 删的是行、删在算平均之前；HAVING 删的是组、删在算完之后**——绝不是"写哪个都行"。

队伍一旦记住，四条规则全变成推论：

- **WHERE 里不能用聚合函数**——它跑的时候还没分组，AVG 无从算起，数据库直接报错
- **WHERE / GROUP BY / HAVING 里不能用 SELECT 起的别名**——别名在 SELECT 那一步才诞生，前面的步骤看不见（标准 SQL 口径，各家宽严不一，考试按此记）
- **ORDER BY 里可以用别名**——它排在 SELECT 之后
- **SELECT 里的非聚合列必须出现在 GROUP BY 里**——一堆只出一行，堆内各行不同的列取哪个值都说不清

两个子句混用时必须严格按队伍走：`… WHERE 成绩>=70 GROUP BY 学号 HAVING COUNT(*)>=2` ——① WHERE 删行，留下 S01 的 85、70 和 S02 的 90；② 分堆，S01 两行、S02 一行（S03 没行，不成堆）；③ HAVING 删掉只有一行的 S02 堆 → 只剩 **S01，2 门**。

> 考试这样问：给一条含 WHERE + GROUP BY + HAVING 的 SQL 问结果有哪几行；下午题 2 则把这条 SQL 挖 1–3 个空让你填。

**子查询**：把一条 SELECT 的结果当另一条 SELECT 的条件用，括号里那条就是子查询。两种写法要认脸：

```sql
-- IN：内层独立算出一个集合，外层看值在不在里面
SELECT 姓名 FROM S WHERE 学号 IN (SELECT 学号 FROM SC WHERE 课程号='C01');
-- EXISTS：对外层每一行跑一次内层，看"是否存在至少一行"；内层引用外层的 S.学号，叫相关子查询
SELECT 姓名 FROM S WHERE EXISTS (SELECT * FROM SC WHERE SC.学号=S.学号 AND SC.课程号='C01');
```

两句在本讲表上都得 **张三、李四、王五**。换成 **NOT EXISTS** 就是"没选数据库的学生"→ **赵六**，下午题里"没……过"的问法基本都靠它。**内层漏写关联条件 `SC.学号=S.学号`，就退化成"只要表里有任何一条数据库成绩，全体学生都命中"**。

**多表连接有两种写法，下午题都出现**：`SELECT 姓名,课程名,成绩 FROM S JOIN SC ON S.学号=SC.学号 JOIN C ON C.课程号=SC.课程号`，或老式的把连接条件塞进 WHERE：`… FROM S, SC, C WHERE S.学号=SC.学号 AND C.课程号=SC.课程号`。两句结果完全相同，都是 **5 行 3 列**（张三-数据库-85 …… 王五-数据库-55）。

而**第二种漏掉 WHERE 里的连接条件就退化成笛卡尔积**（4×5×3 = 60 行垃圾）——这正是"连接 = × 后接 σ"在 SQL 里的落地。

其余零碎语法，认脸即可：

- **SQL 关键字不区分大小写**，`select` 与 `SELECT` 等价；`AS` 起别名；`DISTINCT` 去重
- `LIKE` 匹配字符串，**`%` 配任意多个字符、`_` 配任意一个字符**（`姓名 LIKE '张%'` 得张三，`LIKE '_四'` 得李四）
- `ORDER BY 列 [ASC|DESC]` **默认升序，降序必须写 DESC**

### 七、SQL 的三张面孔，以及谁能碰这些表

这一节没有要算的东西，要分清三组：语句归哪一类、视图和索引各是什么、权限语句的每个零件管什么。权限语句先把零件图摆出来，后面按零件逐个判：

```sql
GRANT SELECT, UPDATE ON TABLE S TO U1 WITH GRANT OPTION;
--  ↑动词  ↑权限        ↑对象     ↑被授人  ↑能不能转授
GRANT ALL PRIVILEGES ON TABLE S TO PUBLIC;   -- 把全部权限授给全体用户
REVOKE UPDATE ON TABLE S FROM U1 CASCADE;    -- 连同 U1 转授出去的一并收回
```

**反查表（题干里看见左边，就答右边）**

| 题干里的词 | 答什么 |
|---|---|
| `CREATE TABLE` / `ALTER TABLE`（加列）/ `DROP TABLE` / `CREATE INDEX` / `CREATE VIEW` | **DDL 数据定义**——管表的骨架 |
| `SELECT` 查 / `INSERT INTO 表 VALUES(…)` 插 / `UPDATE 表 SET 列=值 WHERE…` 改 / `DELETE FROM 表 WHERE…` 删 | **DML 数据操纵**——管表里的数据 |
| `GRANT` / `REVOKE` | **DCL 数据控制**——管谁能碰 |
| `PRIMARY KEY()` / `FOREIGN KEY()` / `NOT NULL` / `UNIQUE` | 建表时写的约束：主键 / 外键 / 不许为空 / 不许重复（属 DDL） |
| "不存数据""每次查才去跑底下那条 SQL""虚表" | **视图 view**；它对应三级模式里的**外模式** |
| 问视图有什么用 | 两个用处：**简化复杂查询**；**安全——只把该看的行列开放给某个用户**（薪资列不写进视图就查不到） |
| "另建一份排好序的目录""查这列不必全表扫" | **索引 index**；代价是增删改要维护、额外占存储，不是越多越好 |
| 语句的**动词**是 GRANT 还是 REVOKE | GRANT＝授权、REVOKE＝收回；介词跟着变：**GRANT…TO，REVOKE…FROM** |
| `ON TABLE S`、`ON 视图名` | 授权**对象**可以是表，也可以是视图；**被授人**是具体用户或 PUBLIC |
| **WITH GRANT OPTION** | 允许被授人把权限**再转授**给别人 |
| **权限**写的是 SELECT / INSERT / UPDATE / DELETE 之一 | 就只有那一项权；写 **ALL PRIVILEGES** 才是全部权限 |
| **PUBLIC** | 全体用户 |
| **CASCADE** | REVOKE 时**级联收回**被转授出去的那些权限；不写它而被授人已转授过，这次收回会被拒绝 |
| "把权限转授回授权链的上游" | 不允许——**任何情况下都不允许循环授权** |

**易混对 1：DDL ↔ DML**

- 判据｜动的是表的骨架（列、索引、视图这些对象的定义）＝DDL；动的是表里的行＝DML。
- 例子｜`ALTER TABLE S ADD 班级 CHAR(8)` 给 S 加一列，是 DDL；改成 `UPDATE S SET 年龄=21 WHERE 学号='S01'` 只动一格数据，就成了 DML。
- 错法｜把 `CREATE INDEX`、`CREATE VIEW` 归进 DML（它们建的是对象不是数据）；把 `SELECT` 排除在 DML 之外。

**易混对 2：WITH GRANT OPTION ↔ ALL PRIVILEGES**

- 判据｜前者管"能不能转授"，后者管"权限有多大"，两件事互不相干——WITH GRANT OPTION **与权限大小无关**。
- 例子｜`GRANT SELECT ON TABLE S TO U1 WITH GRANT OPTION`＝U1 只能查，但能把查询权转授给别人；把 SELECT 换成 ALL PRIVILEGES、去掉尾巴，就变成 U1 增删改查全能却不能转授。
- 错法｜把 WITH GRANT OPTION 读成"授予全部权限"；看见 `GRANT SELECT` 就选"能对该表做任何操作"；介词写反（GRANT 配 TO、REVOKE 配 FROM）。

**易混对 3：REVOKE 带不带 CASCADE**

- 判据｜被收回的人已经转授出去过，就必须写 CASCADE，否则这次收回被拒绝。
- 例子｜U1 有 WITH GRANT OPTION 且已授给 U2，`REVOKE SELECT ON TABLE S FROM U1;` 会被拒；补上 CASCADE，U1、U2 的权限一并收回。
- 错法｜以为不写 CASCADE 就"只收 U1、留下 U2"——U2 那份会成无源之水，系统不允许。

**易混对 4：视图 ↔ 索引**

- 判据｜**视图 view** 存的是一条查询语句，**本身不存数据**，每次查才现跑，所以又叫**虚表**；**索引 index** 存的是真数据的一份排好序的目录，查这列时不必全表扫。
- 例子｜`CREATE VIEW V_优秀 AS SELECT S.学号,姓名,课程号,成绩 FROM S,SC WHERE S.学号=SC.学号 AND 成绩>=80;` 查它得 2 行：张三 C01 85、李四 C01 90；把李四那门成绩改成 79，再查视图就只剩 1 行——它没有副本，底下数据变它跟着变。`CREATE UNIQUE INDEX IX_S ON S(姓名)` 建唯一索引，顺带禁止姓名重复。
- 错法｜给视图安上"存了一份数据副本"；给索引安上"越多越好/不占空间"——实际代价是**增删改时要维护索引，反而变慢，还额外占存储**。

其余认名即可：`ALL PRIVILEGES` 与 `PUBLIC` 常同句出现（`GRANT ALL PRIVILEGES ON TABLE S TO PUBLIC;`＝把全部权限授给全体用户）；建表约束 `NOT NULL`、`UNIQUE` 认字面意思即可，卷面考的是它们属 DDL。

## 速记

- σ 挑行＝WHERE，π 挑列＝SELECT；**σ 下标是条件、π 下标是列名，先 σ 后 π**；π 自动去重＝`SELECT DISTINCT`
- **笛卡尔积：m×n 行、a+b 列**；等值连接列数还是 a+b（重复列保留）；**自然连接 = a+b−公共属性个数**；**行数没有公式，只能数**
- 无公共属性时自然连接退化成笛卡尔积；外连接把落单行留下、对面补 NULL，左外/右外/全外分别保左表/右表/两边
- 并交差要求**属性个数相同、对应属性同域**；并去重；**差没有交换律**；A∩B = A−(A−B)
- 执行顺序 **FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY**：从哪来→删行→分堆→删堆→挑列→排序
- **WHERE 删行在算之前、HAVING 删组在算之后**；WHERE 不认聚合也不认别名，ORDER BY 认别名；SELECT 的非聚合列必须进 GROUP BY；IN 内层独立算完给外层用，EXISTS 逐行判有无且内层必须写关联条件
- DDL 定义 / DML 操纵 / DCL 控制；视图是**虚表不存数据**、对应外模式；索引**快查询、慢增删改、占空间**
- **GRANT…TO / REVOKE…FROM**；**WITH GRANT OPTION = 可转授**、ALL PRIVILEGES = 全部权限、PUBLIC = 全体用户、CASCADE = 级联收回；不许循环授权
