# 33 · 数据库：关系代数与 SQL

## 定位

这一课讲表建好了怎么查。一至五节是关系代数：σ 和 π 是仅有的两把刀，× 是唯一的粘合剂，连接是它俩的组合，并交差把表当集合看，核心是算"结果有几行几列"。第六节把这些动作对回 SQL，一条执行顺序推出所有语法规则；第七节讲 SQL 三大分类、视图与索引、GRANT/REVOKE。

全课只用三张小表：

```
S（学生）4行3列   C（课程）3行2列   SC（选课）5行3列
学号 姓名 年龄    课程号 课程名     学号 课程号 成绩
S01  张三  20     C01   数据库      S01  C01   85
S02  李四  22     C02   操作系统    S01  C02   70
S03  王五  20     C03   英语        S02  C01   90
S04  赵六  19                       S02  C02   60
                                    S03  C01   55
```

两处空缺：**赵六一门课没选，英语一个人没选**——外连接靠它俩。

术语：表＝**关系**；一行＝**元组**（一条记录）；一列＝**属性**（一个字段）；属性允许取值的范围＝**域**（"年龄"的域是 0–150 的整数）；只写表名和列的骨架＝**关系模式**，如 S(学号, 姓名, 年龄)。

**关系代数**是一组作用在表上的运算，**输入是表，输出还是表**，所以能层层嵌套。SQL 是**声明式**的——只说"要什么"不说"怎么算"，数据库把它翻译成一串关系代数动作执行。

## 一、选择 σ 与投影 π

**选择 σ（sigma）＝横着切、挑行＝WHERE。** σ<sub>条件</sub>(R) 留下满足条件的元组，**一列不动**。σ<sub>年龄=20</sub>(S)：S01 ✓、S02 ✗、S03 ✓、S04 ✗ → **2 行 3 列**，即 `SELECT * FROM S WHERE 年龄=20`。

**投影 π（pai）＝竖着切、挑列＝SELECT 后的列名。** π<sub>列名</sub>(R) 只留指定列、不筛行，但**关系是集合、不允许重复元素**，所以要去重：π<sub>年龄</sub>(S) 得 20、22、20、19 → {20, 22, 19}，**3 行 1 列**（原表 4 行）。

⚠ SQL 不自动去重：`SELECT 年龄 FROM S` 返回 **4 行**，`SELECT DISTINCT 年龄 FROM S` 才是 3 行、才等价于 π。

规则：
- **σ 的下标是条件，π 的下标是列名**（也可写列号，π<sub>1,3</sub> 即第 1、3 列）。
- **先 σ 后 π**："20 岁学生的姓名"＝π<sub>姓名</sub>(σ<sub>年龄=20</sub>(S))；σ<sub>年龄=20</sub>(π<sub>姓名</sub>(S)) 非法——π 后只剩姓名列，外层没有年龄可比。

## 二、笛卡尔积 ×

**R×S**：左表每一行配右表每一行，两边的列**全部拼起来**。

算例：取 S′ = π<sub>学号,姓名</sub>(σ<sub>学号='S01'∨学号='S02'</sub>(S))，**2 行 2 列**（小表只为铺得下，规则相同）。S′ × SC：

```
S′的行｜SC 的行   学号对得上吗    S′的行｜SC 的行   学号对得上吗
S01 张三｜S01 C01 85    ✓        S02 李四｜S01 C01 85    ✗
S01 张三｜S01 C02 70    ✓        S02 李四｜S01 C02 70    ✗
S01 张三｜S02 C01 90    ✗        S02 李四｜S02 C01 90    ✓
S01 张三｜S02 C02 60    ✗        S02 李四｜S02 C02 60    ✓
S01 张三｜S03 C01 55    ✗        S02 李四｜S03 C01 55    ✗
```

行数 = 2×5 = **10**，列数 = 2+3 = **5**。

规则：R 有 m 行 a 列、S 有 n 行 b 列 → **R×S 有 m×n 行、a+b 列**。全表 S×SC = 4×5 = **20 行**、3+3 = **6 列**。

10 行里只有 4 行有意义，其余 6 行是**错配**（张三配了李四的成绩）。所以笛卡尔积几乎不单独用，是连接的原料——SQL 里 `FROM S, SC` 忘写条件，得到的就是它。

## 三、连接 ⋈

**θ 连接（条件连接）** R ⋈<sub>条件</sub> S ＝ σ<sub>条件</sub>(R×S)：先笛卡尔积，再选择。比较符全是等号＝**等值连接**；等值连接再去掉重复列＝**自然连接**。三者一层套一层，θ 最宽、自然最窄。

算例：S′ ⋈<sub>S′.学号=SC.学号</sub> SC ＝ 上表打 ✓ 的 4 行：

```
S′.学号 姓名 SC.学号 课程号 成绩    ← 5 列，学号出现了两次
S01    张三   S01    C01   85       S02   李四   S02   C01   90
S01    张三   S01    C02   70       S02   李四   S02   C02   60
```

等值连接保留重复列，列数仍是 a+b = **5 列**。

**自然连接 R ⋈ S** 两条规则：① 按**两表全部同名属性**取值相等来连（不写条件）；② 结果中**同名属性只留一份**。上表变成 4 行 4 列：学号、姓名、课程号、成绩。

全表：S(学号,姓名,年龄) 3 列、SC(学号,课程号,成绩) 3 列，S ⋈ SC 是学号、姓名、年龄、课程号、成绩 **5 列**（不是 6）——公共属性"学号"扔掉一份。

> **笛卡尔积、等值连接：列数 = a + b**（重复列全保留）
> **自然连接：列数 = a + b − 公共属性个数**；无公共属性时退化成笛卡尔积

**行数没有公式，只能数实际匹配。** S ⋈ SC = **5 行**（赵六配不上任何行，消失）；S ⋈ SC ⋈ C = **5 行 6 列**（3+3+2 减去学号、课程号两个公共属性）。

除运算 ÷ 回答"选修了全部课程的学生"这类问题，认名即可。

## 四、外连接

自然连接把赵六丢了，但"全校学生选课一览"里他不该消失。**外连接**把落单的行也留下，另一边的列填 **NULL**（空值，"没有值/未知"，不等于 0 也不等于空串）。

| 运算 | 符号 | 保留 | SQL |
|---|---|---|---|
| 左外连接 | R ⟕ S | 左表全部行 | `LEFT JOIN` |
| 右外连接 | R ⟖ S | 右表全部行 | `RIGHT JOIN` |
| 全外连接 | R ⟗ S | 两边落单的都保留 | `FULL JOIN` |

SQL 里加不加 OUTER 都一样；不带方向的 `JOIN … ON` 是θ/等值连接，也叫**内连接**，**落单行一律丢掉**。

算例：S 左外连接 SC ＝ 匹配上的 5 行 + 赵六补 NULL 1 行 = **6 行**（不是 4）：

```
S01 张三 20｜C01 85    S03 王五 20｜C01 55
S01 张三 20｜C02 70    S04 赵六 19｜NULL NULL  ← 右半边补空值
S02 李四 22｜C01 90
S02 李四 22｜C02 60
```

同一对表**右外连接只有 5 行**——SC 每行都能找到学生，右边没有落单；全外连接也等于左外的 6 行。

#### 推演 · 三者真正不同的情形

两边各有落单行：甲 = π<sub>学号,姓名</sub>(σ<sub>年龄=20</sub>(S)) = {(S01,张三), (S03,王五)}，乙 = π<sub>学号,成绩</sub>(σ<sub>课程号='C02'</sub>(SC)) = {(S01,70), (S02,60)}。按学号连：**内连接 1 行**（只有 S01）；**左外 2 行**（多 S03 王五 NULL）；**右外 2 行**（多 S02 NULL 60）；**全外 3 行**。

## 五、并、交、差

前提：∪、∩、− 要求两关系**相容**（并相容）：**属性个数相同，且对应属性取自同一个域**——并出来的还得是合法的表。**列名可以不同**，也不要求来自同一张表。

算例：A = π<sub>学号</sub>(σ<sub>课程号='C02'</sub>(SC)) = {S01, S02}（选了操作系统），B = π<sub>学号</sub>(σ<sub>年龄=20</sub>(S)) = {S01, S03}（20 岁）。

| 运算 | 含义 | 结果 | SQL |
|---|---|---|---|
| A∪B | 合起来，**重复只留一份** | {S01, S02, S03}，3 行 | `UNION` 去重；`UNION ALL` 不去重（4 行） |
| A∩B | 两边都有 | {S01}，1 行 | `INTERSECT` |
| A−B | 在 A 不在 B | {S02} | `EXCEPT` |
| B−A | 在 B 不在 A | {S03} | **差没有交换律** |

交不是基本运算：A∩B = A−(A−B) = {S01, S02}−{S02} = {S01}。

## 六、SQL 执行顺序

语句骨架：

```
SELECT [ALL|DISTINCT] <目标列表达式>[,…]   FROM <表名或视图名>[,<表名或视图名>]
[WHERE <条件表达式>]   [GROUP BY <列名1> [HAVING <条件表达式>]]   [ORDER BY <列名2> [ASC|DESC]]
```

写的顺序 SELECT 打头，**执行顺序**是：

```
FROM  →  WHERE →  GROUP BY →  HAVING →  SELECT →  ORDER BY
从哪来 →  删行  →   分堆    →   删堆  →   挑列  →   排序
```

对回关系代数：FROM 是 ×/连接，WHERE 是 σ，SELECT 是 π；GROUP BY、HAVING、ORDER BY 是代数之外的扩展。

**聚合函数**把一堆值压成一个值：COUNT 计数、SUM 求和、AVG 平均、MAX 最大、MIN 最小。**GROUP BY** 按指定列把行分堆，每堆算一次聚合，**一堆出一行**。SC 按学号分堆：S01 {85,70}、S02 {90,60}、S03 {55}，AVG 得 **77.5、75、55**，COUNT 得 2、2、1。

**HAVING 是分组之后的 σ**：σ 删行，HAVING 删**堆**。

算例 1（HAVING）：

```sql
SELECT 学号, AVG(成绩) FROM SC GROUP BY 学号 HAVING AVG(成绩)>=75;
① FROM SC → 5 行  ② 无 WHERE 不删行  ③ 分成 3 堆  ④ 各算平均 77.5/75/55
⑤ HAVING 删掉 55 那一堆 → 结果 S01 77.5、S02 75
```

算例 2（换成 `WHERE 成绩>=75`）：① WHERE 先删掉 70、60、55 三行，剩 S01 的 85、S02 的 90；② 分堆算平均 → **S01 85、S02 90**。结果与算例 1 不同：**WHERE 删行、在算聚合之前；HAVING 删组、在算完之后**。

算例 3（混用）：`… WHERE 成绩>=70 GROUP BY 学号 HAVING COUNT(*)>=2`：① WHERE 留下 S01 的 85、70 和 S02 的 90；② 分堆，S01 两行、S02 一行（S03 无行，不成堆）；③ HAVING 删掉 S02 堆 → **S01，2 门**。

由执行顺序推出的四条规则：
- **WHERE 里不能用聚合函数**——那时还没分组，数据库直接报错
- **WHERE / GROUP BY / HAVING 里不能用 SELECT 起的别名**——别名在 SELECT 那一步才产生（标准 SQL 口径，各家宽严不一，按此记）
- **ORDER BY 里可以用别名**——它排在 SELECT 之后
- **SELECT 里的非聚合列必须出现在 GROUP BY 里**——一堆只出一行，堆内各行不同的列无法取值

**子查询**：把一条 SELECT 的结果当另一条 SELECT 的条件，括号里那条即子查询。

```sql
-- IN：内层独立算出一个集合，外层看值在不在里面
SELECT 姓名 FROM S WHERE 学号 IN (SELECT 学号 FROM SC WHERE 课程号='C01');
-- EXISTS：对外层每一行跑一次内层，看"是否存在至少一行"；内层引用外层的 S.学号，叫相关子查询
SELECT 姓名 FROM S WHERE EXISTS (SELECT * FROM SC WHERE SC.学号=S.学号 AND SC.课程号='C01');
```

两句结果都是 **张三、李四、王五**。换成 **NOT EXISTS** 得"没选数据库的学生"→ **赵六**，"没……过"类查询基本都靠它。**内层漏写关联条件 `SC.学号=S.学号`，就退化成"只要表里有任何一条数据库成绩，全体学生都命中"**。

**多表连接两种写法**：`SELECT 姓名,课程名,成绩 FROM S JOIN SC ON S.学号=SC.学号 JOIN C ON C.课程号=SC.课程号`，或把连接条件写进 WHERE：`… FROM S, SC, C WHERE S.学号=SC.学号 AND C.课程号=SC.课程号`。结果相同，**5 行 3 列**（张三-数据库-85 …… 王五-数据库-55）。第二种**漏掉 WHERE 里的连接条件就退化成笛卡尔积**（4×5×3 = 60 行）——即"连接 = × 后接 σ"。

其余语法认名即可：
- **SQL 关键字不区分大小写**；`AS` 起别名；`DISTINCT` 去重
- `LIKE`：**`%` 配任意多个字符、`_` 配任意一个字符**（`姓名 LIKE '张%'` 得张三，`LIKE '_四'` 得李四）
- `ORDER BY 列 [ASC|DESC]` **默认升序，降序必须写 DESC**

## 七、SQL 分类、视图与索引、权限

权限语句零件图：

```sql
GRANT SELECT, UPDATE ON TABLE S TO U1 WITH GRANT OPTION;
--  ↑动词  ↑权限        ↑对象     ↑被授人  ↑能不能转授
GRANT ALL PRIVILEGES ON TABLE S TO PUBLIC;   -- 把全部权限授给全体用户
REVOKE UPDATE ON TABLE S FROM U1 CASCADE;    -- 连同 U1 转授出去的一并收回
```

**速查表**

| 关键词 | 是什么 / 属于哪类 |
|---|---|
| `CREATE TABLE` / `ALTER TABLE`（加列）/ `DROP TABLE` / `CREATE INDEX` / `CREATE VIEW` | **DDL 数据定义**——管表的骨架 |
| `SELECT` 查 / `INSERT INTO 表 VALUES(…)` 插 / `UPDATE 表 SET 列=值 WHERE…` 改 / `DELETE FROM 表 WHERE…` 删 | **DML 数据操纵**——管表里的数据 |
| `GRANT` / `REVOKE` | **DCL 数据控制**——管谁能碰 |
| `PRIMARY KEY()` / `FOREIGN KEY()` / `NOT NULL` / `UNIQUE` | 建表约束：主键 / 外键 / 不许为空 / 不许重复（属 DDL） |
| 不存数据、每次查才跑底下那条 SQL、虚表 | **视图 view**，对应三级模式的**外模式** |
| 视图的用处 | **简化复杂查询**；**安全——只开放该看的行列**（薪资列不写进视图就查不到） |
| 另建一份排好序的目录、查这列不必全表扫 | **索引 index**；代价是增删改要维护、额外占存储，不是越多越好 |
| GRANT / REVOKE | 授权 / 收回；**GRANT…TO，REVOKE…FROM** |
| `ON TABLE S`、`ON 视图名` | 授权**对象**可以是表或视图；**被授人**是具体用户或 PUBLIC |
| **WITH GRANT OPTION** | 允许被授人**再转授** |
| SELECT / INSERT / UPDATE / DELETE | 只授那一项权；**ALL PRIVILEGES** 才是全部权限 |
| **PUBLIC** | 全体用户 |
| **CASCADE** | REVOKE 时**级联收回**转授出去的权限；不写而被授人已转授过，收回被拒绝 |
| 转授回授权链上游 | 不允许——**任何情况下都不允许循环授权** |

**易混对 1：DDL ↔ DML**

- 判据｜动表的骨架（列、索引、视图等对象的定义）＝DDL，所以 `CREATE INDEX`、`CREATE VIEW` 属 DDL；动表里的行＝DML，`SELECT` 也属 DML。
- 例子｜`ALTER TABLE S ADD 班级 CHAR(8)` 给 S 加一列，是 DDL；改成 `UPDATE S SET 年龄=21 WHERE 学号='S01'` 只动一格数据，就是 DML。

**易混对 2：WITH GRANT OPTION ↔ ALL PRIVILEGES**

- 判据｜前者管"能不能转授"，后者管"权限有多大"，互不相干——WITH GRANT OPTION **与权限大小无关**，`GRANT SELECT` 只给查询权。
- 例子｜`GRANT SELECT ON TABLE S TO U1 WITH GRANT OPTION`＝U1 只能查，但能把查询权转授；把 SELECT 换成 ALL PRIVILEGES、去掉尾巴，就变成 U1 增删改查全能却不能转授。

**易混对 3：REVOKE 带不带 CASCADE**

- 判据｜被收回的人已经转授出去过，就必须写 CASCADE，否则收回被拒绝——系统不允许只收 U1、留下无源的 U2。
- 例子｜U1 有 WITH GRANT OPTION 且已授给 U2，`REVOKE SELECT ON TABLE S FROM U1;` 被拒；补上 CASCADE，U1、U2 的权限一并收回。

**易混对 4：视图 ↔ 索引**

- 判据｜**视图**存的是一条查询语句，**本身不存数据**（没有副本），每次查才现跑，故称**虚表**；**索引**存的是真数据的一份排好序的目录，查这列不必全表扫，但**增删改时要维护索引、反而变慢，还额外占存储**。
- 例子｜`CREATE VIEW V_优秀 AS SELECT S.学号,姓名,课程号,成绩 FROM S,SC WHERE S.学号=SC.学号 AND 成绩>=80;` 查它得 2 行：张三 C01 85、李四 C01 90；把李四那门成绩改成 79，再查视图只剩 1 行——底下数据变它跟着变。`CREATE UNIQUE INDEX IX_S ON S(姓名)` 建唯一索引，顺带禁止姓名重复。

其余认名即可：`GRANT ALL PRIVILEGES ON TABLE S TO PUBLIC;`＝把全部权限授给全体用户；`NOT NULL`、`UNIQUE` 按字面理解，属 DDL。

## 速记

- σ 挑行＝WHERE，π 挑列＝SELECT；**σ 下标是条件、π 下标是列名，先 σ 后 π**；π 自动去重＝`SELECT DISTINCT`
- **笛卡尔积：m×n 行、a+b 列**；等值连接列数还是 a+b（重复列保留）；**自然连接 = a+b−公共属性个数**；**行数没有公式，只能数**
- 无公共属性时自然连接退化成笛卡尔积；外连接把落单行留下、对面补 NULL，左外/右外/全外分别保左表/右表/两边
- 并交差要求**属性个数相同、对应属性同域**；并去重；**差没有交换律**；A∩B = A−(A−B)
- 执行顺序 **FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY**：从哪来→删行→分堆→删堆→挑列→排序
- **WHERE 删行在算之前、HAVING 删组在算之后**；WHERE 不认聚合也不认别名，ORDER BY 认别名；SELECT 的非聚合列必须进 GROUP BY；IN 内层独立算完给外层用，EXISTS 逐行判有无且内层必须写关联条件
- DDL 定义 / DML 操纵 / DCL 控制；视图是**虚表不存数据**、对应外模式；索引**快查询、慢增删改、占空间**
- **GRANT…TO / REVOKE…FROM**；**WITH GRANT OPTION = 可转授**、ALL PRIVILEGES = 全部权限、PUBLIC = 全体用户、CASCADE = 级联收回；不许循环授权
