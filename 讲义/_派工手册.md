**并发**：**持续保持 3 个 agent 在跑**（2026-09-08 用户要求，取代原先的「一批三篇、做完再开下一批」）。一有位子空出来立刻补，排队优先级：**① 已交付写手稿的审核轮 → ② 下一篇的写手**。写手与审核跨篇混跑没问题，不必等同一批写完。每篇仍须走完第二节的五步才算定稿。用户叫停时，把在跑的三个跑完、收尾推送后再停。

| 坑 | 怎么防 |
|---|---|
| **对照表有盲区**：`_知识点对照表.md` 是自下而上从转录本建的，「转录本没有、只在总体计划里出现」的考点会整个掉出去（讲义 16 丢过「软件体系结构风格」整块） | 写手与审核**都要**对照 `计划/00-总体计划.md` 分课清单核一遍 |

| **静默篡改原件**（精简引文、换标点字符、改「磁盘」为「磁带」、给题干加引号、**截短题干或引文**） | 审核逐字比对被引用的每一段。**另加「截断检测」**：逐条检查"引文收尾处，原文是不是也收尾"——讲义 25 的常规复算 136 项全过、却靠这一招抓出 2 处（"UML 2.0 图…了解即可"后面切掉了同句的"，总分类如下："，正是这半句在指认那张图；4+1 表把"它是逻辑视图的一次执行实例"改成"是…"而该列表头写着"原文的定义句"）。**常规逐字比对只能发现"改了的字"，发现不了"少了的半句"。** |

| **导师任务书本身可能错**（讲义 09 的出栈序列照抄了学习日志里记串的数据） | 写手/审核对任务书的反驳要认真复核，不默认导师对 |
| **额度中断的残留有三种形态，别只看 `git status`** | ①**一个字没写**（最常见：agent 死在读材料/识图/核年份阶段，工作区干净）；②**半截文件**（写到一半断电，缺章节或围栏不配对）；③**正文写完、但没交出自查报告**（讲义 34 就是这样：13,495 字符、骨架齐全、练习答案 1–10 对齐，唯独一句自查结论都没有）。第三种最危险，因为它**看起来是一篇完整的成品**。判据：`git status` 只告诉你改没改，要再跑一遍字符数 + `grep -n '^#\{2,3\} '` 看骨架齐不齐、练习与答案编号对不对得上。第三种按「已交付草稿」处理进审核轮，但**任务书里必须写明「这篇稿子没有经过任何自我核验，按最不可信的稿子审」**。 |
| **agent 会反复死在同一个前置阶段，正文一个字都产不出** | 讲义 35 的写手连派四轮，前三轮全死在「读材料 → 识图 → 联网核年份」这一段，文件始终是旧版。**联网核实是最耗时且最容易卡死的一步。**派工模板里要加时限约束：**先把正文写出来，年份核实放最后做；联网不通或超时就直接标「年份待核实」并在报告里说明，不许反复重试。**先有完整的稿子，再谈打磨。 |
| **外部识图工具的结论不可复现** | 某轮 agent 用第三方识图服务读出了分布式体系结构图上「映像1~4」的位置，结论后来验下来是对的，但**本项目要求任何图上结论都可被下一个 agent 独立复核**。处置：把已有结论写进任务书当「可带着去验的线索」，同时**要求接手的 agent 自己打开图再验一遍**，不得直接采信。 |
