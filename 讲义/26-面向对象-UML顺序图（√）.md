## 定位

**这一课回答**：办成一件事的时候，系统里的对象按什么次序互相调用——顺序图和通信图这两张图怎么读、怎么互换、组合片段怎么算。

## 开讲：类图画完了，"员工提交一张报销单"到底谁先调谁

还是讲义 15、21 那套内部报销系统。**类图**——把系统里有哪些类、类和类之间连着什么线画出来的那张静态图——你已经画完了：报销单界面、审批服务、账务服务、银行网关四个类，谁关联谁一目了然。

现在产品经理问你一句：**"员工点了'提交'之后，到底是谁先干活？谁在等谁？"** 类图一个字也答不出来。它画的是"有谁、谁认识谁"，不是"这一次他们怎么配合"。

**最朴素的办法只有一个：写一段话。**

> 员工在界面上提交报销单，审批服务先校验金额，再逐条核对费用明细，通过就调账务服务打款，打完通知员工。

你自己读没问题，交给三个程序员就出事。**它在六个地方不够用，这一课的全部名词就是这六个坑各自的补丁**：

- ① 谁是发起方、谁在等结果、谁发完就不管了——这段话一个字没说；
- ② 对象"正在忙"的那一段时间在纸上没有位置；对象什么时候被创建出来、什么时候被销毁，更没地方写；
- ③ "金额超 5000 走二级审批，否则走直属主管"这种**二选一**，写成一句话就得分行，画成一条直线就画不下；
- ④ "逐条核对费用明细"——一张单子挂 3 条明细就要重复画 3 遍一模一样的消息，挂 30 条呢；
- ⑤ "如果附了电子发票，就顺手调一次发票查验"——这种**可有可无**的步骤，画进去像必做的，不画又漏了；
- ⑥ 我要看的根本不是时间先后，而是"谁跟谁之间有连线、哪条消息挂在哪条线上"。

前五条是同一张图的事，第⑥条要换一张图。

### 一、坑①的补丁：顺序图——把时间画成纵轴

培训资料的定义照录：**序列图：即顺序图，动态图，是场景的图形化表示，描述了以时间顺序组织的对象之间的交互活动。**里面两个词先说清："动态图"是画**过程**的图，跟画结构的静态图（类图那种）相对；"场景"就是一次具体的业务过程，比如"员工提交一张 8000 元的报销单"。

它治歧义的办法很直白：**横着一排放对象，每个对象往下垂一条虚线叫生命线**（表示这个对象在这段时间里活着），**纵轴就是时间，越靠上发生越早**；对象之间的调用画成横向箭头，叫**消息**。对象框里写 `对象名:类名` 并加下划线，比如 `zhang:Employee`；不关心是哪一个具体对象时省掉对象名，写成 `:AuditService`，叫匿名对象。

**先猜一下。** 报销系统里这三件事，图上该画成哪种箭头：

1. 界面调审批服务的 `submit(报销单)`，**要等**审批服务返回受理结果才能刷新页面；
2. 审批服务把"打款指令"丢进消息队列，**丢完就继续干自己的事**，不等银行回话；
3. 审批服务把"受理成功"这个结果**交回**给界面。

资料给的三种消息，一句原文管三件事：有**同步消息**（进行阻塞调用，调用者中止执行，等待控制权返回，需要等待返回消息，用实心三角箭头表示）、**异步消息**（发出消息后继续执行，不引起调用者阻塞，也不等待返回消息，由空心箭头表示）、**返回消息**（由从右到左的虚线箭头表示）三种。

所以答案是：1 同步，2 异步，3 返回。**判据只有一个字：等不等。** 三种画法要按扫描原图认，不能只背文字：

- **同步消息**：实线 + **涂黑的实心三角**箭头。原图上 `setAction (a,d,o)`、`setValues (3,4)` 都是这种。
- **异步消息**：实线 + **没有涂黑的线状箭头**（就是普通的 `>` 形箭尾）。原图上那条 `message` 是这种。资料写的"空心箭头"指的就是它，**不是**类图里泛化关系（子类指向父类那种"一般/特殊"的连线）用的那种空心三角形，两者别混。
- **返回消息**：**虚线** + 线状箭头。原图上那条 `commited`（原件如此拼写，标准英文是 committed）是这种。

这里有个分寸要说清：资料那句"由从右到左的虚线箭头表示"，说的是**它下面那张图里的情形**——调用方 `c:Client` 画在左边，结果自然是从右往左回。返回消息真正的规矩是**回到调用方**，调用方要是画在右边，箭头就是从左往右。**认虚线，不认方向。**

顺序图还能反着读出一件事：**箭头指向谁，谁所属的类就必须实现这个方法**；从它发出去的消息、以及回给别人的返回消息都不算它的方法。2013 年下半年和 2014 年上半年连着两次考这一刀——给一张银行账户的序列图，问 Account 类必须实现哪些方法。**要数得不多不少**：2013 下的干扰项多算，把返回消息和别的类负责的方法也塞了进去；2014 上的干扰项少算，漏掉了一条指向 Account 的消息。

### 二、坑②的补丁：激活期、创建消息与销毁标记

生命线只说明"对象活着"，说不出"它此刻正在干活"。补丁是在生命线上套一根**细长的竖条**，叫**激活期**（也叫执行发生），竖条的上下沿就是这个对象这一段处理的起止——相当于调用栈上这一帧压进去又弹出来。

对象也不都是一开始就存在的。**创建**：从调用方发一条箭头指向新对象的**对象框**，箭头上标 `«create»`，被创建的对象框画在图的中间偏下，它的生命线**从这一刻才开始**。**销毁**：生命线末端画一个大**✕**，✕ 以下就没有生命线了。

培训资料这张原图六样东西全占齐了，跟着箭头从上往下读一遍：

![培训资料原图：序列图（对象、对象生命线、调用消息、返回消息、异步消息、对象销毁）](../外部资源/转录md/images/fig_d14_s019.png)

`c:Client` 先发 `«create»`（原图印作 `<<create >>`）造出 `:Transaction`（注意 `:Transaction` 的框不在顶上，就在箭头指到的那个高度）→ 发同步消息 `setAction (a,d,o)`，`:Transaction` 的激活期从这里开始 → `:Transaction` 向 `p:ODBCProxy` 发同步消息 `setValues (3,4)`，再发异步消息 `message` → 虚线把 `commited` 回给 `c:Client` → 最后 `destroy` 把 `:Transaction` 的生命线掐断，末端画 ✕，图上标着"对象销毁"。

图上那条指着 `«create»` 箭头的引线，标的是"**调用消息**"——调用消息就是"我调你、我等你返回"的那种消息，和资料正文里的"同步消息"说的是同一件事，只是换了个叫法；图注用的是"调用消息／返回消息／异步消息"这一套，正文用的是"同步／异步／返回"那一套，两套名字要都认得。消息还能画给自己：箭头从一条生命线出去、绕个小弯又回到**同一条**生命线，叫**自消息**，表示对象调用自己的方法。

图上的细长竖条一共**四根**：`c:Client` 一根从头贯到尾，`:Transaction` 一根（`setAction` 进来时开始，把 `commited` 回出去就收；再往下它的生命线是虚线，直到 `destroy` 处的 ✕），`p:ODBCProxy` 两根（`setValues` 一根、`message` 一根——被调用两次就画两段）。这四根就是激活期。**注意：资料的正文和图注都没给这根竖条起名字**，"激活期"这个词是本讲义按教材补的；考试问到时它可能叫激活期、执行发生、控制焦点，指的都是这根竖条。

### 三、坑③④⑤的补丁：组合片段

上面这套画法只能画"一条道走到底"的固定剧本。真实逻辑里有 `if`、有 `while`，早期的 UML 表达不了，只能画成好几张图。UML 2.0 给的答案是**组合片段**：在图上**圈出一个矩形框**，**左上角一个小五边形写操作符**（说明这块按什么逻辑执行），**方括号里写守卫条件**（决定走不走、走哪条的那个判断式，比如 `[金额>5000]`）。框里罩住的那几条消息，就按操作符说的规矩执行。（培训资料 2-8、2-9 两节一个字都没提组合片段，这一节按《软件设计师教程》第 5 版补，例子对着 2023 上半年实考那道题的问法设计。）

**alt 补坑③——多分支互斥选一，等价于 `if / else`。** 一个框用虚线横着分成几块（每一块叫一个**分区**，装着这一支要执行的消息），每块顶上一个守卫条件，最后一块可以写 `[else]` 兜底，**任何一次执行只有一块生效**。报销系统的审批分流：

```
   :审批服务                    :主管审批    :二级审批
      ┊                            ┊            ┊
  ┌ alt ────────────────────────────────────────────┐
  │ [金额 ≤ 5000]                                   │
  │   ┊──提交直属主管审批────────▶┊            ┊    │
  ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
  │ [else]                                          │
  │   ┊──提交二级审批──────────────────────────▶┊   │
  └─────────────────────────────────────────────────┘
```

金额 3000 走上半块，8000 走下半块，5000 整**不大于 5000**，也走上半块——边界是最容易看走眼的地方：写 `≤` 时 5000 留在上半块，写 `<` 时 5000 就掉进 `[else]` 了。

**loop 补坑④——循环，等价于 `while` 或 `for`。** 框内的消息反复执行。两种写法：`loop [守卫条件]` 每轮开始前判一次，为真就再来一遍；`loop(min, max)` 按次数限定，最少 min 遍、最多 max 遍——**画图工具常把这个区间印成 `loop(min..max)`**，2023 年上半年那道真题图上写的就是 `Loop(1..2)`，意思一样：至少 1 遍、至多 2 遍。报销系统逐条核对明细：

```
   :审批服务                        :规则引擎
      ┊                                ┊
  ┌ loop [还有未核对的费用明细] ───────────────┐
  │   ┊──校验明细(第 i 条)──────────────▶┊    │   框内
  │   ┊◀─ ─ ─ ─ ─ 校验结果 ─ ─ ─ ─ ─ ─ ─┊    │   框内
  └────────────────────────────────────────────┘
      ┊──汇总审批结论────────────────────▶┊        框外，只执行一次
```

**先别往下看：一张单子挂 3 条明细，上面这张图要画几条箭头？** 第一反应多半是 6 条。答案是 **2 条**——**图上只画一轮，执行时才按守卫条件转多轮**：图上永远是那 2 条箭头（一条调用、一条返回），实际发生的才是 3×2 = 6 条消息。**"图上几条"和"实际几条"不是一回事**，这正是 2023 年上半年考的那一刀。

**opt 补坑⑤——单条件可选，等价于没有 `else` 的 `if`。** 只有一块分区、一个守卫、没有兜底：条件为真执行框内，为假**整块跳过**，框外的消息照常执行。

```
   :审批服务                        :发票查验
      ┊                                ┊
  ┌ opt [附了电子发票] ────────────────────────┐
  │   ┊──查验发票真伪───────────────────▶┊    │   框内
  └────────────────────────────────────────────┘
      ┊──生成审批任务────────────────────▶┊        框外，一定执行
```

没附发票时，"查验发票真伪"整条跳过，但"生成审批任务"在框外，照做不误。**这里有个固定的设错点：把本该无条件执行的消息误圈进 opt 框，条件一假就被一起跳掉了。**

**alt 和 opt 一句话分家**：要在**几种情况里挑一种**（哪怕只有"否则"那一种）→ alt，框内至少两块分区；只关心"**满足条件就多做一步，不满足什么都不做**" → opt，框内只有一块。

标准里还有 **par**（框内几块分区**并行**执行）、**break**（守卫成立就跳出外层片段），以及 **ref**（框内不画消息，只写另一张交互图的名字，相当于调一个公共函数）。历年软设上午题里没见过直接考它们的，**认得符号即可，不必展开**。

### 四、坑⑥的补丁：通信图——把时间藏进序号

前面三节都在同一套坐标里：纵轴是时间。可有时候你要看的是**结构**——报销系统上线后要排查"审批服务到底跟哪几个服务有直接调用"，顺序图上这信息被时间轴打散了，一个对象跟谁通信要从上到下扫一遍才数得清。

补丁是把同一次交互**换个角度重画**：对象随便摆，有直接通信关系的两个对象之间连一条线，消息挂在线上。培训资料的定义照录：**通信图：动态图，即协作图，强调参加交互的对象的组织。**（UML 1.x 里它就叫协作图，2.0 起改名通信图，考题两个名字都用。）

它只有三样东西：**对象**（方框，写法和顺序图一样是 `对象名:类名`）、**链**（两个对象之间那条光秃秃的连线，表示"这俩之间有通信"）、**消息**（贴在链旁边的带箭头短线，**前面必须带序号**）。时间信息全靠序号带：

![培训资料原图：通信图（链、对象、消息、序号）](../外部资源/转录md/images/fig_d14_s020.png)

这张图和上一节那张序列图是**同一个场景的两种画法**。`c:Client` 到 `:Transaction` 那条链上挂着 `1:create ()`、`2:setActions (a,d,o)`、`3:destroy ()`；`:Transaction` 到 `p:ODBCProxy` 那条链上挂着 `2.1:setValues (d,3.4)`、`2.2:message`。（两张原图的印刷对不齐：序列图上是 `setAction (a,d,o)`、`setValues (3,4)`，通信图上却成了 `setActions`、`setValues (d,3.4)`——`3` 和 `4` 之间那一点，对着序列图看应该是逗号。这是资料的排印出入，不影响读图，考试也不考名字拼写。）

**序号的读法是本节的核心考点。** 按小数点分段比大小排出执行次序：1 → 2 → 2.1 → 2.2 → 3。**带小数点的是嵌套**：2.1 和 2.2 表示它们是在处理消息 2 的过程中发出去的子消息，处理完了才轮到 3。所以这张图读出来的次序是：先 create，再 setActions，setActions 内部先后调了 setValues 和 message，最后 destroy——**和序列图上从上往下的读法完全一致**（序列图多一条返回消息 `commited`，通信图里省掉了）。2018 年上半年那道汽车导航题就是这么考的：图上四个候选序号，选"Mapping 对象获取汽车当前位置"的那条，答案是嵌套序号 `2. 1: getCarLocation()`。

**两张图语义等价，可以互相转换**，差的只是强调什么。培训资料另一处把这层关系写得最直白：**通信图：是顺序图的另一种表示方法，也是由对象和消息组成的图，只不过不强调时间顺序，只强调事件之间的通信，而且也没有固定的画法规则，和顺序图统称为交互图。** 这句里冒出来的**交互图**是个家族名——专门画"对象之间怎么互相发消息"的那一族图，顺序图和通信图都算成员，家族里还有谁放到第五节说。考试的判据就三条：

| 判据 | 顺序图 | 通信图 |
|---|---|---|
| 题干的措辞 | 时间、时序、次序、先后 | 组织、结构、关系、连接 |
| 图上认什么 | 对象下面垂着**竖直虚线**（生命线），消息**没有编号** | 对象之间是**光秃秃的链**，消息**必须带 1、2.1 这种编号** |
| 它答得好的问题 | 这一步之后是哪一步 | 这个对象一共跟谁打交道 |

收口：**六条短板对四类补丁**。谁调谁、谁等谁不清楚 → 顺序图的生命线加三种消息；谁在忙、谁生谁灭不清楚 → 激活期加 `«create»` 加 ✕；二选一、要重复、可有可无 → alt / loop / opt 三个组合片段；只想看谁跟谁有连线 → 换成通信图。选图题就是从题干里读出它问的是这四类里的哪一类。

### 五、不在这条链上，认得即可

**交互图**这个家族名要认得：顺序图和通信图都是交互图，2014 年下半年直接考过"哪个不是交互图"，正确答案是**对象图**——对象图画的是某一时刻的一张对象快照，属于静态图，归 25。同族里还有**定时图**（强调消息跨对象的实际时间刻度）和**交互概览图**（活动图和顺序图的混合物），这两个在软设真题里是当干扰项出现的，记住名字即可。

还有一处分工要记死：**顺序图展示的是"一个用例、多个对象"的行为**——**用例**就是用户能做成的一件完整的事，比如"员工提交一张报销单"，这一件事里几个对象怎么配合，正是顺序图画的；2019 年上半年直接考了这句话。而状态图展示的是"单个对象跨多个用例"的行为，那张图归 27。两句话正好对调着设错。

## 考试怎么考

**考点①（收①） 三种消息的判别。** 题目要么给一张图指着某条箭头问是哪种消息，要么给一句描述让你选名字。**先看虚实：虚线一定是返回消息**；实线再看箭头黑不黑，涂黑的实心三角是同步（要等），没涂黑的线状箭头是异步（不等）。错项的固定造法是把"返回消息"说成"带实心三角箭头的实线"，或者把异步说成"阻塞调用"。

**考点②（收②） 元素认名字。** 生命线是那条竖直虚线，表示对象在这段时间存在；激活期是套在生命线上的细长竖条，表示对象正在执行；`«create»` 指向对象框、被创建对象的生命线从那里才开始；生命线末端的 ✕ 表示对象被销毁。常见错法是把生命线和激活期的定义对调。同一张图还会追问**某个类必须实现哪些方法**，数指向它的那些消息就行，返回消息和别的类接的消息都不算，指向它的也一条都不能漏（2013下、2014上）。

**考点③（收③④⑤） 组合片段。** 两种问法。一是**给业务描述选操作符**：出现"如果……否则……"选 alt，出现"重复/逐一/对每个"选 loop，出现"若……则额外……"且没有否则分支选 opt。二是**给图算执行序列**，2023 年上半年考的就是这个——判据是**先分清哪些消息在框内、哪些在框外**，框内的按操作符重复或跳过，框外的无论如何都执行一次，然后按纵向次序把序列拼出来。

**考点④（收⑥） 认图与读序号。** 图上消息带 `1`、`2.1` 这种编号就是通信图，带竖直虚线生命线就是顺序图。读序号先按小数点分段排序，带小数点的是嵌套子消息。问"某某对象取某某数据的消息是哪条"，就到图上找那条链、对号入座。

**考点⑤ 图族归属的叙述判断。** 顺序图、通信图、定时图、交互概览图都是交互图，**对象图不是**；通信图在 UML 1.x 里叫协作图；顺序图强调时序、通信图强调对象的组织结构，这两句互换就是错项。

### 参考答案

1. **D、C**。（41）四个选项分别是用例图、对象图、活动图、序列图的定义，图上有生命线和横向消息，选 D。（42）关键是分清框内框外：`a`、`b` 在 `Loop(1..2)` 框内，`c` 在框外。跑 1 遍是 a→b→c，跑 2 遍是 a→b→a→b→c；四个选项里只有 C 落在这两种合法序列里，选 C。D 是把 `c` 也当成循环体、连着跑两遍（a→b→c 再一遍）；A 是同一个错法，还漏了末尾那条 c；B 等于一遍都不跑，可 `Loop(1..2)` 的下界是 1，不许零遍。**这道题不难，难在把框外那条 c 也当成了循环体。**
2. **B**。交互图这一族是序列图、通信图、定时图、交互概览图；对象图画的是某一时刻的对象快照，属于静态图，所以它是唯一的答案。D 的"时序图"是定时图（timing diagram）的另一个中文译名，也有资料拿它当序列图的别名——两种读法都落在交互图里，不影响选 B。
3. **A、C、D、B**。前三空按定义对号：对系统的使用方式分类是用例图，显示类及其相互关系是类图，类似流程图显示活动是活动图。第四空是本课的正题——**与通信图类似、但强调顺序而不是连接**的就是顺序图，两张图信息等价，差别只在强调时序还是强调连接。
4. **C**。返回消息是**虚线**加线状箭头；"实线 + 实心三角"是同步消息，D 说的才对。A、B 是资料原话。
5. **B**。序号按小数点分段读：`2.2` 是处理消息 2 时发出的第二条子消息，排序在 2.1 之后、3 之前，和"第 22 条"没有关系。通信图的序号表示的是先后次序，不是并行，也和消息类型无关。
6. **D**。"单个对象在多个用例中的行为"是状态图的活儿；顺序图是"一个用例、多个对象"。A、B、C 都对。
7. **B、C**。opt 框只有一块分区、没有兜底分支，守卫为假时整块跳过，所以"查验发票真伪"不执行；"生成审批任务"在框外，照常执行。选 alt 的话至少要有两块分区。
8. 图上**2 条**（一条同步调用、一条返回），实际执行 3 轮 × 2 = **6 条**。loop 框在图上只画一轮。
9. 用 **alt**，至少 **2 块**分区（`[金额 ≤ 5000]` 和 `[else]`）。5000 满足"≤ 5000"，走**直属主管**那一块。
10. **通信图**。次序 1 → 1.1 → 1.2 → 2：先发 1，处理 1 的过程中依次发出子消息 1.1 和 1.2，全部处理完才轮到 2。

## 速记

- 顺序图：横排对象、竖挂生命线、纵轴是时间；对象框写 `对象名:类名`，激活期是套在生命线上的细长竖条，被调几次就画几段
- 三种消息：虚线＝返回；实线＋涂黑实心三角＝同步（等）；实线＋没涂黑的线状箭头＝异步（不等）。图注另一套名字：调用消息＝同步消息
- `«create»` 指对象框、生命线从那里开始；生命线末端画 ✕ 是销毁
- 组合片段：框 + 左上角五边形写操作符 + 方括号写守卫。**loop 循环、alt 二选一（≥2 块分区，可带 `[else]`）、opt 可有可无（1 块、无 else）**；par 并行、break 跳出、ref 引用别的图，认得即可
- 执行序列＝框内（按操作符重复／跳过）＋框外（各一次）；`loop(1..2)` 下界是 1，零遍不合法
- 通信图 = 协作图（UML 1.x 旧名）：对象 + 链 + 带序号的消息；序号按小数点分段排序，带点的是嵌套子消息
- 两图语义等价、可互换，差别只在强调时序还是强调对象的组织结构，合称交互图
- 交互图含顺序图、通信图、定时图、交互概览图；**对象图不是交互图**。顺序图管"一个用例多个对象"，状态图管"单个对象多个用例"
