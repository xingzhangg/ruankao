## 第 1 层 · 理解

### 一句话

> 这一章讲的是：**你写的一行 `http.get(url)`，数据从本机网卡出发、到对方进程手里，中间要过哪几道关卡，每道关卡各管一件什么事**。分层模型是那张关卡地图，TCP/UDP 和端口号是最后两道关卡的细节。

### 痛点：没有这张地图，网络问题只能靠猜

程序员每天都在撞这几件事，但如果脑子里没有分层地图，就只能瞎试：

- **"接口调不通"** —— 到底是网线/网卡的事、是路由不通、还是对方端口没开？三种毛病在三个不同的层，排查手段完全不同。没有分层，只会一遍遍重启。
- **"为什么 ssh 是 22、https 是 443、ftp 要开两个口"** —— 你天天在防火墙上放行这些数字，却说不出它们为什么存在（因为 IP 只送到"机器"，还得有个门牌号找到"进程"）。
- **`netstat` 里一堆 TIME_WAIT / CLOSE_WAIT** —— 不懂四次挥手就永远解释不了这些状态是怎么来的。
- **"直播为什么用 UDP，下载为什么必须 TCP"** —— 拍脑袋答"UDP 快"是不够的，考试要的是"可靠性代价 vs 实时性需求"的取舍。

### 一条主线

```
把数据交到另一台机器的某个进程手里，要解决的麻烦太多：
电信号怎么编？丢了怎么办？跨网络怎么找路？到了机器给哪个程序？
   ↓  一个协议全干 = 设计不出来、也维护不了
【分层】：每层只解决一个麻烦，用下层的服务、给上层提供服务
   → 这就是 OSI 七层（物·数·网·传·会·表·应）
   ↓
分完层，"某个设备属于哪一层"立刻有了唯一判据：
   【它能看懂第几层的信息，就工作在第几层】
      只会放大电平        → 中继器 / 集线器（物理层）
      能读帧里的 MAC 转发 → 网桥 / 交换机（数据链路层）
      能读 IP 跨网段选路  → 路由器（网络层）
      要做协议转换        → 网关（传输层及以上高层）
   ↓
但 OSI 是理论标准，真跑在互联网上的是务实的 TCP/IP 四层
   （OSI 的 5/6/7 合成"应用层"，1/2 合成"网络接口层"）→ 考两模型怎么对应
   ↓
整条链上最关键的是【传输层】。因为网络层的 IP 只做到"送到那台机器"，
还剩两个问题它管不了：
   ┌ 问题一：机器上跑着几十个进程，这包给谁？
   │     答案 = 【端口号】16 位门牌号，常用服务约定成公认端口
   │             （FTP 21/20、SSH 22、HTTP 80、HTTPS 443…… 纯记忆）
   └ 问题二：IP 是尽力而为、可能丢可能乱序，要不要保证送达？
         这是【业务取舍】，所以传输层给了两个协议、不是一个：
            要不丢不错 → TCP：建连接、编序号、确认、重传、流控（慢、头 20 字节起）
            要快要实时 → UDP：拿起来就发、不管到没到（快、头仅 8 字节）
   ↓
既然 TCP 承诺"可靠"，那它传第一个字节之前就必须先落实两件事：
   ① 确认双方的"收"和"发"四项能力都正常  ② 交换初始序号（后面确认重传全靠它）
   → 【三次握手】SYN → SYN+ACK → ACK
      （少一次就有"旧的滞留 SYN 让服务器白建连接"的坑）
   ↓
连接是【全双工】的——两个方向是两条独立的单向流，关闭要分别关：
   我发完了不代表你发完了，收到你的 FIN 我得先回 ACK，
   把我这边剩下的数据发完，才能发我自己的 FIN
   → ACK 与 FIN 中间隔着数据，合并不了 → 【四次挥手】比握手多一次
      FIN → ACK →（发完剩余数据）→ FIN → ACK
```

### 考点① 常用协议与默认端口【真题·2021上/2022下/2024下】

**题目长相**（三种问法，年年换汤不换药）：
- "SMTP 协议的默认端口是（ ）。A. 21 B. 23 C. 25 D. 110"
- "以下协议与默认端口的对应关系中，**错误**的是（ ）。"
- "下列协议中，采用 UDP 作为传输层协议的是（ ）。"

**怎么解**：这是**纯记忆题**，没有推导余地，只能把下表背下来。理解一句就够了——IP 定位到机器，**端口号（16 位，0–65535）定位到机器上的具体程序**，常用服务把端口固定成"公认端口"，客户端才不用先问一句"你在哪个口"。

| 协议 | 默认端口 | 传输层 | 用途 |
|---|---|---|---|
| FTP（数据连接） | **20** | TCP | 文件传输的**数据**通道 |
| FTP（控制连接） | **21** | TCP | 文件传输的**命令**通道 |
| SSH | **22** | TCP | 加密远程登录 |
| Telnet | **23** | TCP | 明文远程登录（不安全） |
| SMTP | **25** | TCP | **发**邮件 |
| DNS | **53** | UDP/TCP | 域名解析（**查询走 UDP**，区域传送走 TCP） |
| DHCP | 67 / 68 | UDP | 自动分配 IP（**67 服务器、68 客户端**） |
| TFTP | 69 | UDP | 简单文件传输 |
| HTTP | **80** | TCP | 网页 |
| POP3 | **110** | TCP | **收**邮件（下载到本地） |
| IMAP | **143** | TCP | **收**邮件（在服务器端管理） |
| SNMP | 161 | UDP | 网络设备管理 |
| HTTPS | **443** | TCP | 加密网页（HTTP + SSL/TLS） |

**陷阱**（错误选项就爱在下面这几处做手脚）：
1. **"FTP—21"就完了 → 不完整**。FTP 占**两个**端口：**21 走命令**（登录、列目录），**20 走实际文件数据**。题目问"FTP 数据连接"时选 20 才对。
2. **"SSH—23" → 错**，SSH 是 **22**，23 是 Telnet。两个数字相邻，是最常见的错误配对。记法：**SSH 安全，所以先行一步（22 在 23 前面）**。
3. **"SMTP 用来收邮件" → 错**。SMTP(25) 只管**发**；**收**是 POP3(110) 或 IMAP(143)。
4. 传输层归属也考：**走 UDP 的是 DNS(查询)、DHCP、TFTP、SNMP 这"四兄弟"**，其余常见协议（HTTP/HTTPS/FTP/SMTP/POP3/Telnet/SSH）都走 TCP。

### 考点② 层与设备对应【真题·2022下】

**题目长相**："在网络互连设备中，工作在数据链路层的是（ ）。A. 中继器 B. 交换机 C. 路由器 D. 网关"，或反过来问"路由器工作在 OSI 的第几层"。

**怎么解**：**一条判据通吃——设备能看懂第几层的信息，它就工作在第几层。** 不用死记表格，想一下它靠什么做转发决策：

| 设备 | 它靠什么做决策 | 所在层 |
|---|---|---|
| 中继器、**集线器** | 只把电信号放大/复制到所有口，看不懂任何地址 | **物理层（1）** |
| 网桥、**交换机** | 读帧里的 **MAC 地址**决定转发到哪个口 | **数据链路层（2）** |
| **路由器**（及三层交换机） | 读 **IP 地址**跨网段选路 | **网络层（3）** |
| **网关** | 在不同体系结构的网络间做**协议转换** | **传输层及以上高层** |

**陷阱**：
- **集线器 ≠ 交换机**。选项里两个一起出现时，集线器是物理层、交换机是数据链路层，混一起就错。
- **网关不是"某一层"的设备**，规范说法是"工作在**传输层及以上**的高层"，选项写"网关工作在网络层"是错的。
- 三层交换机是网络层设备，别因为名字里有"交换机"就归到二层。

### 考点③ OSI 七层与 TCP/IP 四层（层序、职责、传输单位、两模型对应）

**题目长相**："OSI 参考模型中，负责端到端（进程到进程）数据传输的是（ ）层"；"数据链路层的传输单位是（ ）"；"TCP/IP 模型的应用层对应 OSI 的哪几层"。

**怎么解**：先记住**自下而上**的七层顺序（口诀在第 4 层），再按下表定位职责与单位。

| 层 | 职责一句话 | 传输单位 | 典型协议 | 典型设备 |
|---|---|---|---|---|
| 1 物理层 | 在介质上传输原始**比特流**（电压/光信号） | **比特** | RS-232、各类线缆标准 | **中继器、集线器** |
| 2 数据链路层 | 把比特组装成**帧**，用 **MAC 地址**在相邻结点间传送，差错控制 | **帧** | PPP、以太网(802.3) | **网桥、交换机** |
| 3 网络层 | 用 **IP 地址**跨网络选路，把分组从源送到目的 | **分组(包)** | IP、ICMP、ARP | **路由器**（及三层交换机） |
| 4 传输层 | 提供**端到端（进程到进程）**的数据传输，可靠或不可靠 | **报文段** | TCP、UDP | — |
| 5 会话层 | 建立、管理、终止**会话**（对话控制、同步点） | — | — | — |
| 6 表示层 | 数据**格式转换、加密解密、压缩** | — | — | — |
| 7 应用层 | 直接为用户应用提供网络服务 | — | HTTP、FTP、SMTP、DNS 等 | **网关**（规范说法：工作在**传输层及以上**的高层，不专属应用层） |

**TCP/IP 四层与 OSI 的对应**（考"合并关系"）：

| TCP/IP 四层 | 对应 OSI 层 | 该层协议 |
|---|---|---|
| 应用层 | 应用层 + 表示层 + 会话层（**5/6/7**） | HTTP、FTP、SMTP、POP3、DNS、DHCP、Telnet、SNMP |
| 传输层 | 传输层（**4**） | TCP、UDP |
| 网际层 | 网络层（**3**） | IP、ICMP、IGMP、ARP/RARP |
| 网络接口层 | 数据链路层 + 物理层（**1/2**） | 以太网、PPP 等 |

**陷阱**：
- **"端到端"专指传输层**（进程到进程）。数据链路层是"**相邻结点**之间"，网络层是"源主机到目的主机"，别把这三个说法混用——选项常拿"网络层提供端到端进程通信"来骗人。
- 传输单位对应关系是送分点，但**网络层是"分组/包"不是"帧"**；帧是二层的。
- **加密压缩在表示层**，不在应用层（虽然实际系统里常写在应用里）。
- TCP/IP 里叫"**网际层**"，OSI 里叫"网络层"，同一层两个名字。

### 考点④ TCP vs UDP 的取舍

**题目长相**："某视频直播应用选择 UDP 而非 TCP，最主要的原因是（ ）"；"关于 TCP 与 UDP 的叙述，错误的是（ ）"。

**怎么解**：抓住一句话——**可靠是有代价的**，选谁取决于业务能不能接受这个代价。

| 对比项 | TCP | UDP |
|---|---|---|
| 连接 | **面向连接**（先握手再传数据） | **无连接**（拿起来就发） |
| 可靠性 | **可靠**：确认应答、超时重传、序号排序、流量控制（滑动窗口）、拥塞控制 | **不可靠**：发出去不管到没到 |
| 数据形式 | **字节流** | 数据报 |
| 首部开销 | 大（**20 字节起**） | 小（**8 字节**） |
| 速度 | 慢 | 快 |
| 典型场景 | 不丢不错优先：网页(HTTP)、文件传输(FTP)、邮件(SMTP) | 实时优先、丢一点无所谓或应用层自兜底：视频/语音、DNS 查询、DHCP、SNMP、TFTP |

**理解**（这段能让选项一眼看穿）：UDP 不是"劣质版 TCP"——**直播丢一帧画面没人在意，但为了重传等半秒卡顿谁都受不了**；DNS 一问一答一个包搞定，为它建连接再拆连接纯属浪费。

**陷阱**：错误选项几乎都是把两者的属性**对调**——
- "UDP 传输更可靠" → 反了；
- "UDP 能自动纠错/自动重传" → 没有，纠错重传要应用层自己做；
- "UDP 首部比 TCP 大" → 反了，8 < 20；
- "TCP 是面向数据报的" → 反了，TCP 是**字节流**，UDP 才是数据报。

### 考点⑤ 三次握手与四次挥手（报文顺序 + 为什么）

**题目长相**："TCP 建立连接的三次握手过程中，**第二个报文段**包含的标志位是（ ）。A. SYN B. ACK C. SYN+ACK D. FIN"；或"TCP 释放连接需要几次报文交换"；或简答式"为什么挥手比握手多一次"。

**怎么解**：把两张图刻进脑子，报文顺序题直接对号入座。

**三次握手（建立连接）**：
```
客户端                          服务器
  |------ ① SYN, seq=x ------->|   我想建立连接，我的初始序号是 x
  |<-- ② SYN+ACK, seq=y,ack=x+1-|   同意；确认收到你的 x，我的初始序号是 y
  |------ ③ ACK, ack=y+1 ------>|   确认收到你的 y
        （连接建立，开始传数据）
```
- **SYN**(synchronize) = 请求建连、同步序号的标志位；**ACK**(acknowledge) = 确认标志位。
- **为什么必须三次、两次不行？** 两次的话，服务器发完 ② 就单方面认为连接建好了。设想客户端一个**早已作废的旧 SYN** 在网络里滞留很久才到达服务器（客户端那边早就放弃了），服务器回 ② 后就白白建立连接、分配资源干等。第三次 ACK 的意义是：让服务器确认"**客户端此刻真的在，而且能收到我发的包**"。
  本质是要确认**双方各自的"收""发"共四项能力**都正常，三次是最少次数：① 证明客户端能发，② 证明服务器能收也能发，③ 证明客户端能收。

**四次挥手（断开连接）**：
```
客户端                          服务器
  |------ ① FIN -------------->|   我的数据发完了，请求关闭
  |<----- ② ACK ---------------|   知道了（但我这个方向可能还有数据没发完）
  |        …服务器把剩余数据发完…
  |<----- ③ FIN ---------------|   我也发完了，请求关闭
  |------ ④ ACK -------------->|   知道了
              （连接关闭）
```
- **FIN**(finish) = 请求关闭**本方向**连接的标志位。
- **为什么四次？** TCP 是**全双工**，两个方向的数据流要**分别关闭**。收到对方 FIN 时本方可能还有数据没发完，只能先回 ACK 表示"我知道你要关了"，等自己发完再发 FIN——**ACK 和 FIN 中间隔着数据，合并不成一个报文**，于是比握手多一次。

**陷阱**：
- 问"**第二个**报文的标志位"，答 **SYN+ACK**（两个标志位同时置位），只选 SYN 或只选 ACK 都是错的。
- **FIN 只出现在挥手**，握手过程里没有 FIN——选项拿 FIN 混进握手题是常见干扰项。
- "挥手可以像握手一样合并成三次" → 错，理由就是上面那条（全双工 + 中间还要发数据）。

## 第 4 层 · 速记

> **七层顺序**：物理→数据链路→网络→传输→会话→表示→应用 —— 口诀 **「物数网传会表应」**
> **传输单位**：**比特—帧—包(分组)—报文段**
> **设备对层**：**一层中继集线，二层网桥交换，三层路由，高层网关**（判据：看得懂第几层就在第几层）
> **TCP/IP 四层**：网络接口层(=OSI 1/2)、网际层(=3)、传输层(=4)、应用层(=5/6/7)
> **TCP 三特征**：面向连接、可靠、**字节流**，首部 **20 字节起**
> **UDP 三特征**：无连接、不可靠、快，首部 **8 字节**，是**数据报**
> **走 UDP 的四兄弟**：**DNS、DHCP、TFTP、SNMP**
> **握手三步**：**SYN → SYN+ACK → ACK**；**挥手四步**：**FIN → ACK → FIN → ACK**
> **挥手多一次的理由**：**「全双工分别关，ACK 与 FIN 分开发」**
> **端口串记**：**20/21 FTP 数据与控制，22 SSH，23 Telnet，25 发信 SMTP，53 DNS，80 HTTP，110 POP3 收信，143 IMAP，443 HTTPS**（另：67/68 DHCP、69 TFTP、161 SNMP）
> **三大陷阱**：FTP 占**两个**端口；SSH 是 **22** 不是 23；**"端到端"专指传输层**

## 考题回顾

**1.【模拟·重现2022下考点】** 在网络互连设备中，工作在数据链路层的是（ ）。
A. 中继器　B. 交换机　C. 路由器　D. 网关

> **答案：B**。判据是"看得懂哪层信息就工作在哪层"：中继器只放大信号→物理层；交换机按帧中 **MAC 地址**转发→数据链路层；路由器按 **IP 地址**选路→网络层；网关做协议转换→传输层及以上高层。

**2.【模拟·重现2021上考点】** SMTP 协议的默认端口是（ ）。
A. 21　B. 23　C. 25　D. 110

> **答案：C**。SMTP = **25**（发邮件）。干扰项：A 是 FTP 控制连接，B 是 Telnet，D 是 POP3（收邮件）——正好把"发/收"和"文件/登录"四类混在一起考。

**3.【模拟·重现2024下考点】** 以下协议与默认端口的对应关系中，**错误**的是（ ）。
A. HTTP—80　B. HTTPS—443　C. FTP 控制连接—21　D. SSH—23

> **答案：D**。SSH 默认端口是 **22**，23 是 Telnet。A、B、C 均正确（补一句：FTP 除控制连接 21 外，数据连接是 20）。

**4.【模拟】**（三次握手为大纲固定内容，计划文件标注具体真题年份**待核实**）TCP 建立连接的三次握手过程中，第二个报文段包含的标志位是（ ）。
A. SYN　B. ACK　C. SYN+ACK　D. FIN

> **答案：C**。顺序为 **SYN → SYN+ACK → ACK**。第二个报文由服务器发出，既要确认客户端的 SYN（带 **ACK**，ack=x+1），又要同步自己的初始序号（带 **SYN**，seq=y），两个标志位**同时置位**。FIN 只在断开连接（挥手）时出现，属于典型干扰项。

**5.【模拟】** 某视频直播应用选择 UDP 而非 TCP 作为传输层协议，最主要的原因是（ ）。
A. UDP 传输更可靠　B. UDP 无需建立连接、开销小、实时性好　C. UDP 能自动纠错　D. UDP 首部比 TCP 大

> **答案：B**。直播要求实时，丢个别包可以容忍，但 TCP 的重传/确认机制带来的延迟不可容忍；UDP 无连接、首部仅 8 字节、不重传，正合适。A、C 把可靠性说反了（UDP 不可靠、不纠错），D 把首部大小说反了（UDP 8 字节 < TCP 20 字节）。

3. 【模拟】TCP 断开连接为什么需要四次挥手，而不能像握手一样三次完成？（一句话说清关键原因）

### 参考答案

1. **传输层**（第 4 层）。代表协议：**TCP**（面向连接、可靠）与 **UDP**（无连接、不可靠但快）。
2. **21 为控制连接**（传登录、操作命令），**20 为数据连接**（传实际文件内容与目录列表数据）。
3. 因为 TCP 是**全双工**，两个方向要分别关闭：被动关闭方收到 FIN 时可能还有数据没发完，只能先回 ACK、把剩余数据发完再发自己的 FIN，**ACK 与 FIN 无法合并**为一个报文，故共四次。
