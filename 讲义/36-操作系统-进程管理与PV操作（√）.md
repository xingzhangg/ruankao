## 开讲：中午十二点的食堂

整课只用一个场景。**一个打饭窗口**（只有一位师傅，同一时刻只能招呼一个人）对应 **CPU**；**排队的学生**对应**进程**；师傅背后那个分成 n 格的**保温台**（后厨炒好一份就搁一格）对应进程之间传数据用的**缓冲区**。从三态一路讲到调度算法，都在这个食堂里发生。

### 一、先认食堂经理：操作系统在管什么

**操作系统**的定义（选择题照抄）：能有效地组织和管理系统中的各种软/硬件资源，合理地组织计算机系统工作流程，控制程序的执行，并向用户提供一个良好的工作环境和友好的接口。**两个作用**：**通过资源管理提高系统效率**（对机器）、**改善人机界面给用户友好的工作环境**（对人）。

**四个特征**放进食堂看：**并发性**——几个学生"在打饭这件事上同时推进"；并发不等于并行，单窗口任一**瞬间**只有一个人，是宏观同时、微观轮流，并行才是真开两个窗口。**共享性**——窗口、保温台、餐盘被多人共用。**虚拟性**——只有一个窗口，每个学生却觉得"归我用"，一个物理实体变成多个逻辑实体（一个 CPU 虚拟成多个虚拟处理机，物理内存虚拟成更大的虚存）。**不确定性**——谁先到、哪道菜先卖完、事件按什么次序发生事先无法确定，但条件相同时结果应当相同。

**五大功能**按"管什么"记：**进程管理**管处理机的**时间**（进程控制、同步、通信、调度）；**存储管理**管主存的**空间**（分配回收、存储保护、地址映射、主存扩充）；**文件管理**管**信息**（存储空间管理、目录管理、读写管理、存取控制）；**设备管理**管**硬件**（I/O 设备的分配、启动、完成、回收）；**作业管理**管**人机**（任务与界面管理、人机交互、图形界面、语音控制、虚拟现实）。

**六类系统**：**批处理**分单道和多道，多道的好处是主机与外设可并行；**分时**是一台机连多个终端，把 CPU 时间切成很短的时间片轮流为各终端服务；**实时**要求对外来信息足够快地响应、在被控对象允许的时间内做出反应，**对交互能力要求不高但要求可靠性有保障**（最爱考的一句）；**网络操作系统**让联网计算机方便有效地共享网络资源，分集中、客户端/服务器、对等三种模式；**分布式**里的计算机**无主次之分**，任意两台都能通信交换信息；**微机操作系统**即 Windows、Mac OS、Linux。

**嵌入式操作系统**五特点：**微型化**（占用资源和代码量少）、**可定制**（能跑在不同微处理器平台、可按硬件裁剪配置）、**实时性**（用于过程控制、数据采集、传输通信等要迅速响应的场合）、**可靠性**（关键领域还要容错和防故障）、**易移植性**（靠硬件抽象层和板级支撑包实现）。**初始化**自底向上、从硬件到软件：**片级 → 板级 → 系统**。

### 二、排队的人叫进程

**程序**是菜谱，静态的一串指令躺在磁盘上不动；**进程是程序的一次执行过程**，动态的，有创建、运行、消亡的生命周期。同一份菜谱三个师傅同时照着做就是三个进程——**一个程序可以对应多个进程**。**进程由三块组成**：**PCB（进程控制块）——进程的唯一标志**，操作系统靠它认人、记状态、记它占了哪些资源；**程序**，描述这个进程要做什么；**数据**，存放进程执行时所需的数据。

**三态**别背定义，背一句判据：**"现在把窗口空出来给他，他能不能马上开始打饭？"** **运行态**＝正站在窗口前打饭（单 CPU 同一时刻**最多 1 个**）；**就绪态**＝在队伍里站着，万事俱备只欠窗口；**阻塞态**（等待态）＝要的红烧肉卖完了，到旁边等补菜——**此刻就算窗口空着他也打不了**。

```
    ┌────┐ ──被调度程序选中（分派）─▶ ┌────┐
    │就绪│ ◀─时间片到 / 被高优先级抢占─ │运行│
    └────┘                          └────┘
       ▲                               │
  事件发生了（补菜到了、别人 V 了）  等待某事件（等 I/O、P 申请不到）
       │        ┌────┐                 │
       └─────── │阻塞│ ◀───────────────┘
                └────┘
```

**先别往下看：「就绪 → 阻塞」这条箭头存在吗？**

**不存在。** 就绪态的学生还在队伍里，压根没到窗口跟前，没机会开口问"红烧肉还有吗"——**只有正在运行的进程，才有能力把自己变成阻塞**。同理**「阻塞 → 运行」也不存在**：补菜到了他只能回队尾重新排（回就绪队列）。这两条"不存在的箭头"是选择题最爱的错误选项。四条真箭头里还有一组对比：**运行→就绪是外因、被动**（窗口被收走，他本人随时能打）；**运行→阻塞是自因、主动**（自己要等一件事，给窗口也没用）——这条区别就是考点本身。

**五态图**在三态外加**新建态**（正在创建、还没进就绪队列）和**终止态**（执行完或被撤销、等待回收）：新建 → 就绪 → 运行 → 终止，运行与阻塞之间那两条不变。

### 三、两个人同时改一块黑板：PV 是怎么长出来的

窗口旁挂着块小黑板写着"红烧肉剩余份数"，现在是 **1**。学生甲和乙几乎同时来买最后一份，师傅处理一单的动作是三步：**读黑板 → 减 1 → 写回黑板**。单 CPU 下时间片随时会到，这三步中间可以被打断，于是可能这样交错：

```
时刻  甲                乙              黑板
 1   读到 1                              1
 2                    读到 1             1
 3   算 1−1=0                            1
 4   写回 0，卖给甲                        0
 5                    算 1−1=0           0
 6                    写回 0，卖给乙        0
```

**一份肉卖了两次**，黑板还显示 0，这就是不加锁写 `count--` 翻的那种车。根子不在减法算错，在**这三步之间不该被别人插进来**。由此得到四个词：**临界资源**＝各进程之间必须以**互斥方式**访问的资源（这里是黑板，机器里是共享变量、打印机、磁带机）；**临界区**＝进程中**对临界资源实施操作的那一段程序**，是**代码**不是资源，上面"读—减—写"三行就是；**互斥**＝某资源**同一时间内只能由一个任务单独使用**，用前加锁、用完解锁（打印机是标准例子）；**同步**＝**多个任务可以并发执行、只是速度有差异**，某些情况下停下来等一等，**不存在资源独占不独占的问题**（培训资料比作自行车和汽车：各走各的，只是快慢不同，某些路口互相等一下）。

**最朴素的办法**：黑板旁挂个牌子 `busy`，来人先看牌子，空闲就翻成"占用中"，用完翻回来。**先别往下看：这个办法解决问题了吗？**

**没有，只是把 bug 推后了一格。** "看牌子"和"翻牌子"仍是两步，甲看完（空闲）还没来得及翻，乙也瞄了一眼（还是空闲），两人一起进去。要让它成立，"看 + 翻"必须合成一个**不可打断的动作**——这就是**原子操作**：一旦开始执行就不会被中途打断的操作。硬件确实有这种指令，但还剩两件事：① **没抢到的人怎么办**？站在原地反复看牌子（忙等）占着窗口空转，纯浪费 CPU，正确做法是让他**离开窗口、进阻塞态睡着**，资源来了再叫醒；② **资源不止一份怎么办**？食堂微波炉有 2 台，牌子只有"占用/空闲"两态，表达不了"还剩几台"。

所以我们要的东西必须同时做到三件、且这三件本身是原子的：**能计数**、**能把进程按下去睡**、**能把睡着的叫醒**。它叫**信号量（semaphore）**：一个整数变量 S，**只能**被两个原子操作 P 和 V 访问（这两个操作也叫**原语**，即不可打断的操作）。

P = Passeren（申请）、V = Vrijgeven（释放），Java 的 `Semaphore.acquire()/release()` 就是它的工程成品。

- **P(S)：申请资源，S = S − 1**。若 **S ≥ 0**，执行 P 的进程继续跑；若 **S < 0**，把自己置为阻塞态、插入 S 的阻塞队列。
- **V(S)：释放资源，S = S + 1**。若 **S > 0**，直接继续；若 **S ≤ 0**，从阻塞队列**唤醒一个**进程放进就绪队列，然后自己继续跑。

**S 的取值到底什么意思？别背表，从推演里数出来。** 食堂有 **2 台微波炉**，用一个信号量 S 管，初值就是资源数 **2**。四个学生依次来热饭，之后前两个用完走人：

| 动作 | S | 判断 → 结果 |
|---|---|---|
| 初始 | **2** | 2 台空着 |
| P1 P(S) | 2→**1** | 1 ≥ 0 → 拿到一台 |
| P2 P(S) | 1→**0** | 0 ≥ 0 → 拿到一台（刚好用完） |
| P3 P(S) | 0→**−1** | < 0 → 阻塞排队 |
| P4 P(S) | −1→**−2** | < 0 → 阻塞排队 |
| P1 V(S) | −2→**−1** | ≤ 0，有人在等 → 唤醒 P3 |
| P2 V(S) | −1→**0** | ≤ 0 → 唤醒 P4；此后无人再等 |

三条结论从表里读出来，不是背的：前两步 S 是正的——**S > 0 就是"还有 S 个资源可用"**；第 2 步末 S = 0 是恰好用完且**没有人在等**；第 3、4 步 S 转负，负几就有几个人在等——**S < 0 时 |S| 就是阻塞队列里的进程数**。

**自检式**：`S = 初值 − P 的次数 + V 的次数`，上表末步 2 − 4 + 2 = 0，与表一致。

**先别往下看：换成 S 初值 1（只有 1 台微波炉），三个学生依次执行 P，被阻塞的是几个？**

是 **2 个，不是 3 个**。第一个学生 P 完 S = 0，**0 不小于 0，他成功拿到了微波炉**；只有第二、三个人把 S 压到 −1、−2 才睡下。常见错法就是把"执行了几次 P"直接当成"阻塞了几个"。

顺手把两个符号钉死：**P 判的是 S < 0，V 判的是 S ≤ 0**——V 之后 S 恰好等于 0 仍然要唤醒一个人，因为它是从 −1 加上来的，说明队里确实有人。

**信号量分两种，区别只在初值**：**互斥信号量**管"同一时刻只能一个人用"的东西，**初值恒为 1**（钥匙只有一把）；**同步信号量**管"还剩几个"，**初值 = 共享资源的数量**（微波炉例子里是 2）。

### 四、保温台：生产者-消费者

场景升级。后厨（**生产者**）炒好一份菜就放进保温台的一个空格；学生（**消费者**）从保温台取走一份；保温台一共 **n 个格子**。要同时保证三件事：① 格子满了后厨得等；② 一份菜都没有学生得等；③ 同一时刻只能有一个人伸手动保温台。**三件事就是三个信号量，一个都不能省**：

| 信号量 | 初值 | 管哪件事 | 谁 P / 谁 V |
|---|---|---|---|
| **S0（mutex）** | **1** | 保温台独占使用权（互斥信号量） | 后厨和学生**都**：动手前 P，离手后 V |
| **S1（empty）** | **n** | 还剩几个空格（同步信号量） | 后厨放菜前 P（占一格）；学生取走后 V（还一格） |
| **S2（full）** | **0** | 已放了几份菜（同步信号量） | 学生取菜前 P；后厨放完后 V |

培训资料用 S0/S1/S2 命名，教材和多数题目用 mutex/empty/full，是同一组东西，题目给哪套写哪套。这套东西你天天在用——`BlockingQueue`：`put()` 满了会阻塞、`take()` 空了会阻塞、内部还线程安全，正是这三个信号量的成品封装。

```
后厨（生产者）：            学生（消费者）：
while(true){              while(true){
  生产一份菜;                 P(S2);  // P(full) 没菜就等
  P(S1);  // P(empty) 占一格  P(S0);  // P(mutex)
  P(S0);  // P(mutex)        取出一份;
  放进空格;                   V(S0);  // V(mutex)
  V(S0);  // V(mutex)        V(S1);  // V(empty) 还一格
  V(S2);  // V(full)         吃掉;
}                         }
```

**填空只看两句话**：① **看方向**——**消耗什么就 P 什么，产出什么就 V 什么**。后厨消耗空格、产出菜，只可能是 `P(empty)` 和 `V(full)`；学生反过来是 `P(full)` 和 `V(empty)`。让后厨去 `P(full)`（自己申请自己还没做出来的菜）一眼就假，但选项里一定有。② **看位置**——**先 P 资源信号量（empty/full），后 P 互斥信号量（mutex）**；出来时先 `V(mutex)` 再 V 资源信号量。

第 ② 条为什么是铁律？**先别往下看：假设后厨写反了，先 `P(mutex)` 再 `P(empty)`，而此刻保温台正好满了（n=3，empty=0，full=3，mutex=1），会发生什么？**

```
后厨  P(mutex)：mutex 1→0   ≥0 通过 —— 锁到手了
后厨  P(empty)：empty 0→−1  <0 阻塞 —— 抱着锁睡着了
学生  P(full) ：full  3→2   ≥0 通过
学生  P(mutex)：mutex 0→−1  <0 阻塞 —— 锁在后厨手里，进不去
```

后厨等学生腾出一个空格（等 `V(empty)`），学生等后厨放开锁（等 `V(mutex)`），**互相等待，死锁**。对照正确顺序，同样是保温台满：后厨 `P(empty)` 0→−1 阻塞，**但手里没有锁**；学生 `P(full)` 3→2、`P(mutex)` 1→0 都通过，取走一份并 `V(empty)` 把后厨叫醒。

**口诀：先申请资源，后申请互斥。** 两个 V 的先后**不会**引起死锁（V 从不阻塞），但标准写法仍是先 V(mutex)。

> **培训资料这处有错，别照抄**：转录件第 4-3 节那张"生产者流程/消费者流程"表把 `P(S0)` 写在 `P(S1)`／`P(S2)` **前面**，正是刚推演出会死锁的错序。

### 五、两张图：前趋图与进程资源图

**前趋图**是一张有向无环图，回答两件事：**哪些任务可以并行执行、哪些任务之间有先后顺序**，箭头 A → B 读作"A 做完 B 才能开始"。食堂开档前的洗菜、切配、熬汤、炒菜、开档原本排成一条线；画成前趋图就看出洗菜、切配、熬汤可以三人同时干，三件都完了才能炒菜，炒完才能开档。

把"互斥"换成"先后"，同一套 PV 立刻能用。**三步法**：① **每条边设一个信号量，初值 0**（0 的含义是"前趋还没做完"）；② 前趋任务**结束时** V 一下这条边的信号量（宣布"我完成了"）；③ 后继任务**开始前** P 一下这条边的信号量（前趋没完成就阻塞等着）。拿一张四条边的图走一遍（A 先做；B、C 都要等 A；D 要等 B 和 C）：

```
  A     4 条边 → 4 个信号量、初值全 0：S1(A→B) S2(A→C) S3(B→D) S4(C→D)
 ↙ ↘    A：执行A; V(S1); V(S2);   // 0 入边→不 P；2 出边→V 两次
B   C   B：P(S1); 执行B; V(S3);   // 1 入 1 出
 ↘ ↙   C：P(S2); 执行C; V(S4);   // 1 入 1 出
  D     D：P(S3); P(S4); 执行D;   // 2 入边→P 两次；0 出边→不 V
```

**验算（写完必做）**：几条边就该有几对配对的 P/V——本例 4 条边对 4 个 V（A 两、B 一、C 一）和 4 个 P（B 一、C 一、D 二）；再逐个任务核对**入边数 = 开头 P 的个数，出边数 = 结尾 V 的个数**：A(0/2)、B(1/1)、C(1/1)、D(2/0) 全部对上。

**进程资源图**画得像前趋图但意思完全不同：它表示**进程和资源之间的分配与请求关系**，是讲义 37 判死锁用的图示法——**本课只要求认得这张图、读得懂上面的箭头**，怎么拿它判死锁是 37 的正题。这张图不必套食堂——考试直接把图给你，要的是一套读图规则：**P 圆圈代表进程，R 方框代表资源，方框里画几个圆球就表示有几个这种资源**（叫资源实例）；**R → P** 表示 R 已分配一个实例给 P；**P → R** 表示 P 还在请求一个 R 才能继续。两种箭头的方向千万别看反。

读出来的第一件事是**每个进程是不是被卡住了**，判据只有一句：**看它请求的那类资源还有没有剩**。培训资料那张图（R1 有 2 个实例、R2 有 3 个实例）六条边：R1→P1、R1→P3、R2→P2、R2→P3（已分配），P2→R1、P1→R2（请求）。

R1 共 2 个分给了 P1、P3 → **剩 0**；R2 共 3 个分给了 P2、P3 → **剩 1**。

于是 **P2** 请求 R1 而 R1 一个不剩 → **阻塞节点**（所请求的资源已全部分配完毕，无法获取，进程被阻塞）；**P1** 请求 R2 还剩 1 个 → **非阻塞节点**（所请求的资源还有剩余，可分配给它继续运行）；**P3** 没有向外的请求边 → 也是非阻塞节点。数空闲量时注意一个方框里可以有多个圆球。

**当一个进程资源图中所有进程都是阻塞节点时，即陷入死锁状态**——本图还有非阻塞节点，所以不死锁。接下来怎么靠"化简"这张图正式判定系统死不死锁，见**讲义 37**，本课到认图为止。

### 六、谁先上窗口：进程调度

**调度方式**回答"有更高优先级的进程来了怎么办"：**可剥夺（抢占式）**是强行把 CPU 从正在运行的进程手里收走给高优先级的；**不可剥夺（非抢占式）**是高优先级的必须等当前进程自己释放 CPU。

**三级调度**——一个作业从提交到完成要过三道关，考点就是三个名字对三个动作：**高级调度**（长调度／作业调度／接纳调度）决定**输入池里哪个后备作业可以调入主系统**、变成一组就绪进程（＝"放不放你进食堂门"），**一个作业只经历一次高级调度**；**中级调度**（中程调度／对换调度）决定**交换区里哪个就绪进程可以调入内存**、从而有资格竞争 CPU（＝"进了门人太多，先在门厅待着"）；**低级调度**（短程调度／进程调度）决定**内存里哪个就绪进程可以占用 CPU**，是操作系统中**最活跃、最重要**的调度程序，平常说的"进程调度算法"就是它。

**五种算法**横着比更容易记住谁对谁错：

| 算法 | 怎么挑下一个 | 强在哪 ／ 弱在哪 |
|---|---|---|
| **FCFS 先来先服务** | 按到达顺序排队，非抢占 | 最简单最公平，用于宏观调度 ／ 有利于**长作业和 CPU 繁忙型**，短作业排长作业后面干等 |
| **SJF 短作业优先** | 估计运行时间最短的先上 | **平均周转时间最短** ／ 长作业可能排不上（**饥饿**＝一直等不到资源）；还需预先知道运行时间 |
| **时间片轮转** | 轮流用一个**时间片**（一小段固定长度的 CPU 时间），大小相同 | 公平、响应及时，**适合分时交互**，用于微观调度 ／ 片**过大退化成 FCFS**，**过小则上下文切换**（保存再恢复现场）**开销大** |
| **优先级调度** | 优先级高的先上，分抢占与非抢占 | 能表达紧急程度 ／ 静态优先级让低优先级**饥饿**，靠动态优先级（等越久越升）缓解 |
| **多级反馈队列** | 多个就绪队列、优先级与时间片长度各不相同；新进程进队列 1 末尾按 FCFS 走，用完时间片没做完降到队列 2 末尾，依此类推 | 轮转 + 优先级的结合，**兼顾长短作业与响应时间** ／ 实现最复杂 |

**周转时间 = 完成时间 − 到达（提交）时间**，就是这个学生从站到队尾到端着饭离开一共花了多久，**包含排队干等的时间**；**带权周转时间 = 周转时间 ÷ 服务时间**（服务时间是它真正占着 CPU 干活的那段），衡量"等得亏不亏"，值恒 **≥ 1**，等于 1 表示一点没等，越大说明排队时间相对它自己的工作量越离谱。

四个学生到窗口，到达时间／服务时间为 P1(0/3)、P2(1/6)、P3(2/2)、P4(3/1)。**先别往下看：FCFS 和 SJF，哪个平均周转时间短？差多少？**

**FCFS**——按到达顺序一个接一个：`[P1 0→3] [P2 3→9] [P3 9→11] [P4 11→12]`，逐个套两个公式：

| | P1 | P2 | P3 | P4 | 平均 |
|---|---|---|---|---|---|
| 完成 | 3 | 9 | 11 | 12 | |
| 周转＝完成−到达 | 3−0=**3** | 9−1=**8** | 11−2=**9** | 12−3=**9** | 29/4=**7.25** |
| 带权＝周转÷服务 | 3÷3=**1** | 8÷6≈**1.333** | 9÷2=**4.5** | 9÷1=**9** | ≈**3.958** |

P4 只干 1 分钟活却等了 9 分钟，带权 9——短作业被长作业堵死，这就是 FCFS 的病。

**SJF（非抢占）**——关键细节：**只在 CPU 空出来的那一刻，从"当时已经到达"的进程里挑服务时间最短的**。t=0 只有 P1 到，照样先跑 0→3；t=3 时 P2(6)、P3(2)、P4(1) 都已到达，挑最短的 P4；t=4 再挑 P3；最后轮到 P2：`[P1 0→3] [P4 3→4] [P3 4→6] [P2 6→12]`。套同样两个公式：周转 3−0=**3**、4−3=**1**、6−2=**4**、12−1=**11**，带权依次 **1、1、2、≈1.833**；平均周转 19/4 = **4.75**，平均带权 ≈ **1.458**。比 FCFS 的 7.25 少了 2.5——"平均周转时间最短"就是这么来的，代价是长作业 P2 被推到最后。

同一组数据换**优先级调度**（非抢占，P2 最高、P4 次之、P1 第三、P3 最低）：`[P1 0→3] [P2 3→9] [P4 9→10] [P3 10→12]`，周转 3、8、7、10，平均 **7.0**。三种算法 **FCFS 7.25 / SJF 4.75 / 优先级 7.0**——只换挑人规则，活一点没少干，变的只是谁在等。

### 七、一个学生分身：线程

传统进程身上压了两个属性：**既是可拥有资源的独立单位，又是可独立调度和分配的基本单位**。麻烦在于创建、撤销、切换一个进程的时空开销很大（建 PCB、分内存、换页表），所以系统里**进程数目不宜过多、切换频率不宜太高**，并发程度就上不去。

**线程**把这两个属性拆开：**线程作为调度和分配的基本单位，进程作为独立分配资源的单位**。一个学生（进程）领一个餐盘（资源），伸出三只手（线程）去打饭、盛汤、拿餐具——被调度的是手，盘子是共有的。

线程是进程中的一个实体，**基本上不拥有资源**，只拥有运行中必不可少的一点点：**程序计数器、一组寄存器和栈**。

同一进程内的线程**共享**进程的全部资源——公共数据、全局变量、代码、打开的文件；但**不能共享线程各自独有的那部分**，比如各自的栈指针等标识数据。这正好解释了写 Java 的两条经验：多个线程改同一个静态变量会打架（共享），局部变量天然线程安全（各在各自的栈上）。

**用户级线程与内核级线程**（教材内容，培训资料未展开）：**用户级线程**的创建和调度全在用户空间由线程库完成，内核不知道线程存在，切换不必陷入内核所以**快**，但**一个线程发起阻塞式系统调用会堵住整个进程**，也无法把同进程的线程分到多个 CPU 上真并行；**内核级线程**由内核直接管理调度，一个线程阻塞不影响兄弟线程、能真正多核并行，代价是**每次切换都要陷入内核，开销比用户级大**。

回头看这个食堂：窗口稀缺，于是排队的人分成三种状态；黑板会被两个人同时改，于是要有一个能计数、又能让人睡下和被叫醒的原子设施；保温台既怕满又怕空还怕抢，于是一个信号量变成三个；把「谁也别抢」换成「你做完我才开始」，同一套 PV 立刻画出前趋图；把「谁先上窗口」单拎出来就是调度算法；把一个学生拆成几只手就是线程。整课新东西只有信号量一样，其余都是它换个用法。

## 考试怎么考

**考点① 信号量 S 的推演与读数。** 三种问法：给一串 P/V 问当前 S；给当前 S 问几个进程在等；问"S 的取值范围"——n 个进程共享 m 个资源时最大 m、最小 m − n，写作 m, m−1, …, −(n−m)。

**考点② 生产者-消费者填空。** 给 mutex=1、empty=n、full=0 和一段挖空代码选 P/V，选项就在 `P(empty)/V(full)/P(full)/V(empty)/P(mutex)` 之间打转。错项三种造法：**方向反了**（让生产者 `P(full)`）、**P/V 反了**（`V(empty)` 放在放产品之前）、**顺序反了**（`P(mutex)` 提到 `P(empty)` 前面）——最后一种最像对的，也是唯一要动脑的。

**考点③ 调度算法辨析与周转时间计算。** 辨析题抓场景关键词：交互/分时/响应时间 → 时间片轮转；平均周转最短 → SJF；公平简单 → FCFS；紧急任务 → 优先级。计算题不画完甘特图就下笔是最主要的失分来源。错法：忘减到达时间；带权分母错成到达时间；SJF 把还没到达的也拉进来比；"时间片越小越好"。

**考点④ 三态与状态转换。** 给三态图问某条箭头的原因，或问"下列转换中不可能发生的是"，两条假箭头是错项常客。错法：看到"释放了某资源"就以为等它的进程立刻变运行态，其实只能变就绪。

**考点⑤ 用 PV 实现前趋图同步。** 给一张前趋图加一段挖空程序框图，通常一连三问；也有直接问"进程 D 的代码开头应执行什么"。错项三种造法：**方向反了**（把结尾的 V 搬到开头，那是通知不是等待）、**拿错信号量**（填的不是自己的入边）、**初值填 1**（前趋不用做完就放行）。

**考点⑥ 原句默写题。** 概述与线程那堆结论几乎年年出一道，题干就是把原句改一个词让你挑错，逐条对照速记末条。

### 参考答案

1. **A、C**。让 P1 离开运行态又不涉及别人动作的只有"时间片到"，P1 → 就绪；P2 接住让出的 CPU → 运行；P3、P4 等的打印机、扫描仪没被释放（P1 释放的是 CPU），仍是等待。D 项会让 P1 进终止态而非就绪态。
2. **B、D**。3 台打印机 → S 初值 3，最大 3；n 个进程全执行过 P 时最小 3 − n = −(n−3)。S = −3 按 |S| 读数，**3** 个在等。
3. **C、B、B**。逐格套「开头 P 入边、结尾 V 出边」：a（P1 尾，2 出边）→ `V(S1) V(S2)`、b（P2 尾，出边 S3）→ `V(S3)`，选 C；c（P3 头，入边 S2）→ `P(S2)`、d（P3 尾，出边 S4）→ `V(S4)`，选 B；e（P4 尾，出边 S5）→ `V(S5)`、f（P5 头，入边 S4/S5）→ `P(S4) P(S5)`，选 B。验算：5 条边 ↔ 5 个 P、5 个 V，配平。
4. **A**。生产者消耗空槽、产出产品，① `P(empty)`、② `V(full)`。B 方向反；C 把 P/V 用反；D 只管互斥不管计数，缓冲区满了照塞不误。
5. **D**。时间片越小切换越频繁，每次切换都要保存和恢复现场，**系统开销越大**。
6. **B**。t=0 只有 J1 到，跑 0→4；t=4 时 J2(2)、J3(1) 都已到达，挑短的 J3：4→5；再 J2：5→7。周转 4、5−2=3、7−1=6，平均 13/3 ≈ **4.33**。三个错项各对应一种错法：**7/3** 是服务时间的平均；**14/3** 是按 FCFS 排（J1 0→4、J2 4→6、J3 6→7）；**16/3** 是忘减到达时间、直接平均完成时间。
7. **B**。A 说反了：**进程**拥有资源、**线程**是调度和分配的基本单位。C 错：线程切换只换 PC、寄存器和栈，开销远小于进程切换。D 错：**用户级**线程内核不可见，一个线程阻塞式系统调用堵住整个进程，能"互不影响"的是内核级线程。
8. **S = −2，阻塞 2 个**（第 1 个 P 完 S = 0，不小于 0 就拿到了资源）。／9. **mutex = 1，empty = 1，full = 0**。／10. 运行→就绪是**外因、被动**，CPU 被收走但进程随时能跑（时间片用完、被抢占）；运行→阻塞是**自因、主动**，自己要等一件事，给 CPU 也跑不动（发起磁盘 I/O、执行 P 时 S<0）。／11. **片级 → 板级 → 系统初始化**。

## 速记

- **三态**：运行＝正占 CPU（单核最多 1 个）／就绪＝只欠 CPU／阻塞＝在等事件，给 CPU 也跑不动。**阻塞→运行、就绪→阻塞不存在**；运行→就绪外因、运行→阻塞自因。五态多新建与终止
- **PV**：P 减 1、**S<0** 自己阻塞；V 加 1、**S≤0** 唤醒一个。S>0 剩 S 个资源，**S<0 则 |S| 个在等**。自检 `S = 初值 − P次数 + V次数`；互斥信号量初值 1，同步信号量初值 = 资源数
- **生产者-消费者**：mutex=1／empty=n／full=0；**消耗什么 P 什么、产出什么 V 什么**；**先 P 资源后 P 互斥**，反了则缓冲区满时死锁
- **前趋图**：一边一信号量、初值全 0，前趋结束 V、后继开始 P；验算「入边数 = 开头 P 数，出边数 = 结尾 V 数」
- **进程资源图**：R→P 已分配、P→R 在请求（别看反）；请求的那类还有剩 = 非阻塞，一个不剩 = 阻塞；**全是阻塞节点才死锁**。化简判死锁见讲义 37
- **调度**：三级 = 作业进系统（高）／进程进内存（中）／进程上 CPU（低，最活跃）。**周转 = 完成 − 到达；带权 = 周转 ÷ 服务**（恒 ≥ 1）；SJF 只在**已到达**的里挑最短
- **线程**：进程拥有资源、线程被调度；线程只拥有 PC、寄存器、栈，其余全共享。用户级快但一堵全堵，内核级能真并行但切换要陷内核
- **原句题**：四特征（并发/共享/虚拟/不确定）、五功能对时间/空间/信息/硬件/人机、实时"交互要求不高但可靠性有保障"、分布式"无主次之分"、嵌入式**片级→板级→系统**、唯一标志 **PCB**
