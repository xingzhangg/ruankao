# 20 · 软件工程：软件质量与维护

> 真题：维护四类型 2021上/2022下/2023上、可移植性设计 2023上；质量六特性、CMMI 五级待核实｜无计算｜未讲（自学讲义）

---

## 第 0 层 · 定位

**这一课回答**：软件做出来之后怎么评判好不好（质量六特性）、交付后怎么持续改（维护四类型）、一家公司做软件靠不靠谱（CMMI 五级）。

**前后关系**：软件工程板块前五课讲「怎么做出来」，本课是唯一讲「做出来之后」的；22 接着讲更后面的复用与系统转换。

**分值与去向**：板块 11–13 分，本课稳定 1–2 题，「维护四类型」几乎年年考；下午不考。零计算。

## 第 1 层 · 理解

### 一句话

> 软件上线不是终点，是**成本大头的起点**——这一课就是给"上线之后"配一套语言：用什么维度说它好不好（质量六特性），用什么分类管后续的修改（维护四类型），以及怎么在设计阶段就让日后的修改变便宜。

### 痛点

两句你一定听过的空话：

- **"这个系统质量不行。"** —— 不行在哪？响应慢？还是老崩？还是改不动？说不清就没法验收、没法比较、没法立项改进。
- **"上线就完事了。"** —— 教材口径：**维护占整个软件生命周期成本的 60% 以上**。真正花钱的部分在上线之后，而这部分几乎没人提前规划。

这一课就是把这两句空话变成**可分类、可打分的东西**。

### 一条主线（四块内容是一条链，不是四个孤立知识点）

```
软件交付了 ——「做出来」结束，「养起来」开始
   │
   ├─① 怎么说清"这软件好不好"？
   │      → 把"质量"拆成 6 个能逐项打分的维度：质量模型六特性
   │        （功能性 可靠性 易用性 效率 维护性 可移植性）
   │            ↓ 注意：六个里有两个（维护性、可移植性）说的根本不是
   │              "现在好不好用"，而是"以后好不好改、好不好搬"
   │              —— 这就是链条往下走的接口
   ├─② 交付后必然要改，改的动机有哪几种？
   │      → 维护四类型：改正 / 适应 / 完善 / 预防
   │            ↓ 想让"改"这件事便宜，不能等到要改时才想办法
   ├─③ 设计阶段就该做的事 → 可移植性设计规则（平台相关代码集中隔离）
   │
   └─④ 视角拔高：单个项目做好是偶然，一家公司次次做好才是能力
          → CMMI 五级：乱 → 项目管 → 组织标准 → 数字管 → 持续优
```

**看懂这条链，四块内容就不是四张要背的表，而是一个问题的逐步展开。**

## 第 2 层 · 考点：考试怎么问

### 考点① 质量六特性——给描述认特性（考频**待核实**，见抬头）

**题目长相**："系统在部分组件故障时仍能维持核心业务运行，描述的是软件的（ ）"——给你一句话，选六特性之一。

**六特性**（ISO/IEC 9126 口径；后续标准 25010 扩到八特性，考试主线仍按六特性）：

| 特性 | 一句话 | 子特性 | 认领信号词 |
|---|---|---|---|
| **功能性** | 做的事**对不对、全不全** | 适合性、准确性、互用性、依从性、安全性 | "满足需求""计算结果精确""能与其他系统交换数据""防未授权访问" |
| **可靠性** | 出故障**扛不扛得住** | 成熟性、容错性、易恢复性 | "长时间运行不出错""部分故障仍能服务""崩溃后能恢复" |
| **易用性** | 用户**上手容不容易** | 易理解性、易学性、易操作性 | "界面直观""新手很快学会""操作简便" |
| **效率** | **快不快、省不省** | 时间特性、资源特性 | "响应时间""吞吐量""内存/CPU 占用" |
| **维护性** | **改起来容不容易** | 易分析性、易改变性、稳定性、易测试性 | "定位缺陷方便""修改代价小""改动不牵一发动全身" |
| **可移植性** | **换环境还能不能跑** | 适应性、易安装性、遵循性、易替换性 | "换 OS/数据库仍可运行""安装部署方便""便于被替换" |

**陷阱（考题最爱在这几对之间设）**：
- "计算结果**准确**" → **功能性**（准确性），**不是**可靠性。可靠性管的是"故障"，不管"业务逻辑算错"。
- "**容错**、故障后可恢复" → **可靠性**，**不是**维护性。维护性说的是**人去改代码**容不容易。
- 可移植性的子特性也叫"**适应性**"，和维护类型里的"适应性维护"是两码事：前者是软件适应新环境的**能力**，后者是为适应环境而做的**活动**。

### 考点② 维护四类型——给场景认类别（本课最高频，几乎年年考）

| 类型 | 动机 | 典型场景 |
|---|---|---|
| **改正性维护** | 修正**交付后才暴露**的错误 | 上线后用户反馈"月底结算金额算错"，排查 bug 并修复 |
| **适应性维护** | **外部环境变了**（OS / 数据库 / 硬件 / 外部接口 / 数据格式 / 法规格式），软件跟着变 | 数据库从 Oracle 迁到 MySQL，数据访问层需相应修改 |
| **完善性维护** | 用户提出**新需求**：扩充功能、增强性能、改善易用性 | 运营要求"报表页增加按地区筛选和导出 Excel" |
| **预防性维护** | **还没出问题，先为将来铺路**：提高可维护性、可靠性 | 把年久失修但还能跑的模块重构、补齐文档，方便日后接手 |

**解题三问法（背这个就够了）**：
> ① **现在有错吗？** 有 → 改正性
> ② 没错，那**是谁变了**？ **环境**变 → 适应性；**用户要求**变 → 完善性
> ③ 谁都没变，纯粹未雨绸缪 → 预防性

**占比考点**：四类中 **完善性维护工作量占比最大（约 50% 以上）**——用户的新要求源源不断，远多于修错。

**最易错的一对**：适应性 vs 完善性 —— "浏览器内核升级导致页面不兼容要改"是**环境逼的**（适应性）；"用户嫌页面丑要改版"是**人要的**（完善性）。判据是**改动的驱动方是环境还是人**。

### 考点③ 可移植性设计规则（选"有助于/无助于"）

**核心一句话**：**把平台相关的代码集中隔离**，其余代码通过统一接口访问——换环境只改隔离层。

四条规则：
1. 依赖具体平台（硬件 / OS / 数据库）的代码**集中到少数模块**，其余经统一接口/中间层访问
2. 使用**标准化的语言和标准库**，避免特定编译器/厂商的私有扩展
3. **不依赖具体机器特性**：不假定字长、字节序、内存布局、路径分隔符
4. **配置外部化**：路径、地址、端口放配置文件，不写死在代码里

**反面选项长相**（无助于可移植性）：直接调用特定 OS 私有 API、把某数据库独有的 SQL 方言散布全身、按特定硬件字长做位运算假设。

### 考点④ CMMI 五级——给描述认级别

| 级别 | 名称 | **关键词（认这个就行）** | 画像 |
|---|---|---|---|
| 1 | **初始级** | 混乱、**依赖个人英雄** | 成不成事看有没有大牛，过程不可预测 |
| 2 | **已管理级** | **项目级**制度（需求管理、项目计划、监控、配置管理） | 单个项目有章法，同类项目可重复 |
| 3 | **已定义级** | **组织级**标准过程 | 全公司统一标准，项目从标准裁剪 |
| 4 | **量化管理级** | **定量 / 统计**手段控制质量 | 用数据度量和控制，质量可预测 |
| 5 | **优化级** | **持续过程改进** | 基于量化反馈不断优化、主动预防缺陷 |

**台阶递进逻辑（比背名字有用）**：没人管 → 项目里有人管 → 全公司一个标准管 → 用数字管 → 越管越好。
**快速认级**：见"依赖个人"选 1，"项目级"选 2，"组织级标准"选 3，"定量/统计"选 4，"持续改进"选 5。

### 考点⑤ 软件文档三类（低频，扫一眼）

软件 = 程序 + 数据 + **文档**。按用途分三类：

| 类别 | 给谁用 | 例子 |
|---|---|---|
| **开发文档** | 开发过程的依据与记录 | 可行性研究报告、需求规格说明书、概要/详细设计说明书、测试计划 |
| **产品文档** | 交付给使用者/运维者 | 用户手册、操作手册、安装手册、培训教材 |
| **管理文档** | 项目管理用 | 项目开发计划、进度报告、会议纪要、配置管理计划 |

**判法**：问"这份文档没了谁着急"——开发人员着急→开发文档；用户/运维着急→产品文档；项目经理着急→管理文档。

## 第 4 层 · 速记

> 六特性口诀：**功能可靠又易用，效率维护可移植**
> 特性认领：算得对→功能；扛故障→可靠；上手快→易用；快又省→效率；好修改→维护；换环境→移植
> 维护三问：**有错改正、环境适应、需求完善、未雨预防**；**完善性占比最大（50%+）**
> 维护占生命周期成本 **60% 以上**
> 文档三类：**开发、产品、管理**（谁着急归谁）
> CMMI 爬台阶：**乱(1) → 项目管(2) → 组织标准(3) → 数字管(4) → 持续优(5)**
> 可移植性一句话：**平台相关的代码，圈起来关小黑屋**

## 考题回顾

**1.【模拟·重现2023上考点】** 某系统因公司统一将数据库由 Oracle 更换为 MySQL 而需修改数据访问代码，属于（ ）维护。
A. 改正性　B. 适应性　C. 完善性　D. 预防性
**解**：三问法——有错吗？没有。谁变了？**环境**（数据库平台）。→ **B 适应性**。

**2.【模拟·重现2022下考点】** 系统上线半年后用户提出增加"数据批量导出"功能并实现，属于（ ）维护。
A. 改正性　B. 适应性　C. 完善性　D. 预防性
**解**：无错误、环境未变，是**用户提出新需求** → **C 完善性**。

**3.【模拟】** "系统在部分组件发生故障时，仍能维持核心业务运行"描述的是（ ）。
A. 功能性　B. 可靠性　C. 维护性　D. 效率
**解**：**B**。"故障时仍能服务"= 容错性，属可靠性。别选维护性——那是"人去改软件"容不容易。

**4.【模拟·重现2023上考点】** 最有助于提高软件可移植性的是（ ）。
A. 业务代码中直接调用操作系统私有 API 以提升性能
B. 将与操作系统相关的代码集中封装在独立模块中，业务代码经统一接口访问
C. 利用特定数据库的私有 SQL 方言编写全部查询
D. 按目标机器字长对数据结构做定制化位运算
**解**：**B**。核心规则就是"平台相关代码集中隔离"；A、C、D 都是把软件和平台绑得更死。

**5.【模拟】** 某企业建立了全组织统一的标准软件过程，各项目在此基础上裁剪使用，但尚未采用统计技术定量控制过程质量。按 CMMI 阶段式表示处于（ ）。
A. 已管理级　B. 已定义级　C. 量化管理级　D. 优化级
**解**：**B**。"组织级标准过程"→ 3 级已定义；"尚未定量"说明没到 4 级；已管理级只到"项目级"。

## 自测练习

1. 【模拟】"新版浏览器内核不再支持某旧接口，前端页面需相应改造"与"用户反映页面加载慢、要求优化到 2 秒内"分别属于哪类维护？
2. 【模拟】"软件易于安装、且更换同类软件时便于被替换"描述的是六特性中的哪一个？
3. 【模拟】某公司开发全凭几位骨干的个人经验，项目成败难以预测。按 CMMI 属第几级？升到第 2 级关键要建立什么层面的管理？

### 参考答案

1. 前者是**环境**（浏览器内核）变化逼的 → **适应性维护**；后者是用户对**性能**提出更高要求（增强性能属扩充完善）→ **完善性维护**。
2. **可移植性**——"易安装"对应易安装性，"便于被替换"对应易替换性。
3. **第1级（初始级）**，混乱、依赖个人英雄；升 2 级的关键是建立**项目级**管理制度（需求管理、项目计划、项目监控、配置管理），使同类项目的成功可以重复。
