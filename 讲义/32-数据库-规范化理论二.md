# 32 · 数据库：规范化理论(二)——BCNF、4NF、依赖集等价与模式分解

## 定位

这一课把范式往上推两级。第一节从一张 3NF 却仍在重复的表引出 BCNF；第二、三节分清属性闭包 X⁺ 与依赖集闭包 F⁺，并用两者之间的桥梁判依赖集等价；第四、五节是拆表的两笔代价：无损连接与保持依赖；第六节把同一个动作套到多值依赖上，得到 4NF。

贯穿例子（一至五节）：学校排课，一门课可由多位教师各开一个班，**每位教师只教一门课**；学生选定一门课后被分到该课的某一位教师名下。

**STJ(学生S, 教师T, 课程J)**

| S 学生 | T 教师 | J 课程 |
|---|---|---|
| 张三 | 王老师 | 数据库 |
| 李四 | 王老师 | 数据库 |
| 王五 | 王老师 | 数据库 |
| 张三 | 李老师 | 操作系统 |

**F = { (S,J)→T，T→J }**：某学生的某门课对应唯一一位教师；教师只教一门课。(S,J)→T 是**一条**联合依赖，不是 `S→T`、`S→J` 两条（依赖图里 S、J 两条线先汇到一点再指向 T，就是这个意思）。

## 一、BCNF：把要求从"非主属性"挪到"每条依赖的左边"

**问题**：STJ 满足 3NF，却把"王老师教数据库"抄了三遍。

**算例**（按讲义 31 的步骤）：

1. 求候选码：S 只在左边出现 ⇒ 必在码中；T、J 待定。(S)⁺={S} 不够；(S,J)⁺ 用 (S,J)→T 收 T ⇒ 全体 ✓；(S,T)⁺ 用 T→J 收 J ⇒ 全体 ✓。**候选码两个：SJ、ST**。
2. 分主/非主：S、T、J 都进过某个候选码 ⇒ **全是主属性，没有非主属性**。
3. 2NF、3NF 的条件都是"**非主属性**对码不许部分/传递依赖"，没有非主属性就无从违反 ⇒ **STJ 自动满足 3NF**。
4. 冗余仍在：王老师每多带一个学生，"王老师教数据库"多抄一行（更新异常）；王老师没人选时，师课对应关系没地方存（插入异常）。

**病灶**：2NF、3NF 只管非主属性，不管主属性之间互相决定。`T→J` 两头都是主属性，躲在 3NF 视线之外。(T)⁺={T,J} 缺 S，"王老师"钉不住一整行，只能寄生在别人的行里，有多少行抄多少遍；若每个决定因素（依赖 X→Y 的左边 X）都能钉住一整行，它决定的东西每组只出现一次。

**规则**：**BCNF（Boyce-Codd 范式）**：R∈1NF，且 F 中**每一条非平凡函数依赖 X→Y**（Y 不是 X 的子集）的决定因素 X 都是**超码**（X⁺ = 全体属性）。

原话｜"每一个依赖的左边决定因素都必然包含候选键"（包含某个候选码 ⇔ 是超码）；"在第三范式的基础上进一步消除主属性对于码的部分函数依赖和传递依赖"。

**判法＝逐条算依赖左边的属性闭包**：

```
(S,J)→T ：(SJ)⁺ = {S,J,T} = 全体属性 ⇒ SJ 是超码 ✓
T→J     ：(T)⁺  = {T,J}   ≠ 全体属性 ⇒ T 不是超码 ✗
```

STJ 是 3NF、不是 BCNF，违反点 `T→J`。分解：把病灶依赖连同决定因素整个搬出去——

```
TJ(教师, 课程)   码 T，唯一依赖 T→J 的左边就是码 ⇒ BCNF
ST(学生, 教师)   码 (S,T)，没有非平凡依赖 ⇒ BCNF
```

"王老师教数据库"只存一行，插入异常消失。

**分界线**：3NF 允许"非超码的决定因素决定主属性"，BCNF 不允许。某个主属性反过来决定另一个主属性，就是典型的 **3NF 但非 BCNF**。

另一条路是改语义为 `TS→J`，F={SJ→T, ST→J}，左边 SJ、ST 各是候选码，确属 BCNF。但这是**改业务规则，不是分解**；培训资料"其左边决定因素就包含了候选键之一 S"要打折——S 单独不是候选码（(S)⁺={S}），起作用的是 TS 合起来等于候选码 ST。

## 二、属性闭包 X⁺ 与依赖集闭包 F⁺

| | 是什么 | 例子 |
|---|---|---|
| **属性闭包 X⁺** | 从 X 出发用 F 能推出的**全部属性**（属性的集合） | (T)⁺ = {T,J} |
| **函数依赖集闭包 F⁺** | F 能推出的**全部函数依赖**，含 F 自身（依赖的集合） | `T→J`、`SJ→T`、`ST→J`、`S→S`…… |

F 能推出某条依赖＝**逻辑蕴含**，推导规则是 **Armstrong 公理系统**：

- **自反律**：Y⊆X ⇒ X→Y（平凡依赖）
- **增广律**：X→Y ⇒ XZ→YZ
- **传递律**：X→Y 且 Y→Z ⇒ X→Z
- 推论：**合并**（X→Y 且 X→Z ⇒ X→YZ）、**分解**（X→Y 且 Z⊆Y ⇒ X→Z）、**伪传递**（X→Y 且 WY→Z ⇒ XW→Z）
- 公理系统**完备**：F⁺ 里每一条都能由三条律反复推出。

**F⁺ 有多大**：R(A,B,C)，F={A→B, B→C}，左右各有 7 个非空子集，逐对验：**含平凡依赖 35 条，非平凡 16 条**。属性一多 F⁺ 爆炸，所以不列 F⁺，只判"某条依赖在不在 F⁺ 里"：

> **X→Y ∈ F⁺ ⇔ Y ⊆ X⁺**

X⁺ 就是握着 X 能推出的一切属性，Y 全在里面才推得出。这条桥梁把 F⁺ 的问题全转成 X⁺ 的计算，三～五节都靠它。

例：F={A→B, AB→C, D→AC, D→E}，`AB→DE`？(AB)⁺={A,B,C}（没有 D，后两条用不上），D、E 不在 ⇒ **推不出**。

## 三、依赖集等价：F⁺ = G⁺

**问题**：同一套规则，一人写全、一人删掉冗余条目，两个依赖集约束能力是否相同（**依赖集等价**，F⁺ = G⁺）。

> **F⁺ = G⁺ ⇔ F ⊆ G⁺ 且 G ⊆ F⁺**

只验原始条目就够：F 的每条都能由 G 推出，F 推出的任何东西 G 都能沿同一路径推出，故 F⁺ ⊆ G⁺；反向同理。操作：**对 F 的每条 X→Y 用 G 求 X⁺，看 Y 在不在里面**；再反过来。

**算例（等价）**：F = {A→B, B→C, A→C}，G = {A→B, B→C}。

```
验 F⊆G⁺（用 G 算）：A→B：(A)⁺_G={A,B,C} ⊇{B} ✓
                     B→C：(B)⁺_G={B,C}   ⊇{C} ✓
                     A→C：(A)⁺_G={A,B,C} ⊇{C} ✓   ← A→C 靠 A→B→C 传递推出
验 G⊆F⁺（用 F 算）：A→B：(A)⁺_F={A,B,C} ✓ ； B→C：(B)⁺_F={B,C} ✓
两方向都过 ⇒ F⁺=G⁺
```

**算例（不等价）**：F = {A→B, B→C}，H = {A→B, A→C}。验 F⊆H⁺，B→C：(B)⁺_H = {B}（H 两条左边都要 A），C 推不出 ⇒ **不等价**，反方向不必再算。H 只知道"A 同时决定 B 和 C"，没有"B 自己决定 C"的依据。

**规则**：一条不过立刻判不等价；F 是 G 的子集时 F⊆G⁺ 天然成立，只验反方向；判某条是否冗余＝删掉它再验等价。

## 四、无损连接：连回去会不会多出假行

**问题**：拆表默认能连回来，不一定。

**算例**：STJ 拆成 **SJ(学生,课程)** + **ST(学生,教师)**，取张三两行：

```
原表                        SJ 表              ST 表
张三 王老师 数据库           张三 数据库         张三 王老师
张三 李老师 操作系统          张三 操作系统        张三 李老师
```

1. 按公共属性 S 自然连接（公共属性值相同的行两两拼接）：2×2 = **4 行**。
2. 多出"张三-王老师-操作系统""张三-李老师-数据库"两行原表没有的**假元组**；前者还违反 `T→J`。

**分解后自然连接能精确还原原表、不多不少＝无损连接分解**（只会多，不会少）。多出来是因为公共属性相同的行两两全配；若公共属性能唯一确定至少一边的剩余部分，那一边只剩一行可配，就不会多配。

> **两表判据**：X = R1∩R2。**X→(R1−X)** 或 **X→(R2−X)** 成立（"或"，不是"且"）⇒ 无损；都不成立 ⇒ 有损。是否成立仍靠算 X⁺。

```
SJ + ST：X={S}，(S)⁺={S}，推不出 J 也推不出 T ⇒ 有损（与实验一致）
ST + TJ：X={T}，(T)⁺={T,J} ⊇ {J} = TJ−T ⇒ 无损
```

同一张表，公共属性取 S 就散架，取 T 就完好。**公共属性为空必有损。**

**三张及以上：表格法（追踪法）**。例：成绩(学号,姓名,课程号,课程名,分数)，F={学号→姓名，课程号→课程名，(学号,课程号)→分数}，拆成 成绩(学号,课程号,分数)、学生(学号,姓名)、课程(课程号,课程名)。

1. 画"子表 × 属性"表：子表含该属性打 √（该格能确定为原表该列的值），不含打 ×。
2. 用 F 反复传染：**X→Y 的 X 列上几行取值完全相同，其中一行 Y 是 √，其余行 Y 都改 √**。
3. 某行全 √ ⇒ 无损；传染到不再变化仍无全 √ 行 ⇒ 有损。

```
初始          学号 姓名 课程号 课程名 分数        用 学号→姓名：成绩行与学生行的学号列相同(都是√)，
成绩(学,课,分) √    ×    √     ×     √         学生行姓名是√ ⇒ 成绩行姓名改√
学生(学,姓)    √    √    ×     ×     ×         用 课程号→课程名：成绩行与课程行的课程号列相同，
课程(课,课名)  ×    ×    √     √     ×         课程行课程名是√ ⇒ 成绩行课程名改√

结果          学号 姓名 课程号 课程名 分数
成绩          √    √    √     √     √   ← 整行全 √ ⇒ 无损
```

## 五、保持函数依赖：原来的约束还看得住吗

**问题**：无损的 ST(S,T) + TJ(T,J) 里，`(S,J)→T` 的 S 在 ST、J 在 TJ，两头分散，谁也没法单独检查。

**算例**：赵老师也开数据库班（T→J 允许一门课多位教师）。往 TJ 插 (赵老师,数据库)，往 ST 插 (张三,赵老师)：ST 无非平凡依赖，合法；TJ 仍满足 T→J，合法。连起来看，张三的数据库课同时挂着王老师和赵老师，`(S,J)→T` 被违反——只能靠应用层代码或触发器兜底。

> **保持函数依赖**：分解后，F 里每条依赖都能**只看某一张子表自身的数据**验证，不必连回去。

**判法**：

1. 充分条件：**依赖的左右两边同在一张子表**。`T→J` 同在 TJ ✓；`(S,J)→T` 不同框 ✗ ⇒ ST+TJ **无损但不保持依赖**。
2. 不同框的依赖仍可能被其余子表联手推出。例：R(A,B,C)，F={A→B，B→C，A→C}，拆成 R1(A,B)、R2(B,C)：A→B 在 R1、B→C 在 R2；A→C 两头分开，但它是**冗余依赖**（A→B、B→C 传递可得），故仍保持依赖；交集 {B}，(B)⁺={B,C} ⊇ R2−{B}={C}，也无损。
3. 通用算法：对每条 α→β，令 `result=α`，反复对每张子表 Ri 做 `result = result ∪ ((result∩Ri)⁺ ∩ Ri)`，直到不再变化，看 β ⊆ result。

**结论**：

- **BCNF 分解总能无损连接，但不一定保持函数依赖**（ST+TJ）
- **3NF 分解有算法可同时无损连接 + 保持依赖**

"规范化到 3NF 就够了"的含义：再往上走要拿约束保持去换。无损与保持依赖**互相独立**：可以无损不保持（ST+TJ）、两者兼得（R1(A,B)+R2(B,C)）、也可两头落空。判分解性质时两项各验一遍。

## 六、多值依赖与 4NF

**这里换例子**：STJ 的依赖都是"一个 X 定死一个 Y 值"，造不出"一个 X 对应一整组 Y"的冗余。

仓库表 **WPM(仓库W, 保管员P, 产品M)**：一个仓库有多名保管员、多种产品，**保管员不按产品分工**，每名保管员负责本仓库全部产品。

| 仓库 | 保管员 | 产品 |
|---|---|---|
| W1 | 张三 | 螺丝 |
| W1 | 张三 | 螺母 |
| W1 | 李四 | 螺丝 |
| W1 | 李四 | 螺母 |

行数是**乘积**：3 名保管员 × 4 种产品 = 12 行，新来一名保管员要插 4 行，漏一行数据就不完整；5×8 = 40 行，拆开只要 5+8 = 13 行。这张表**一条非平凡函数依赖都没有**，唯一候选码是 (W,P,M)，BCNF 条件无从违反 ⇒ **WPM 已是 BCNF**，冗余照旧。

**速查表**

| 特征 / 关键词 | 是什么 |
|---|---|
| 对 X 的每个取值，Y 对应**一整组**值，且只跟 X 有关、与其余属性 Z=U−X−Y 无关 | **多值依赖 X→→Y**（"X 多值决定 Y"） |
| "每名保管员负责全部产品""保管员和产品之间没有对应关系" | 存在 W→→P、W→→M |
| 行数是"保管员数 × 产品数"式的乘积重复 | 多值依赖造成的冗余，BCNF 管不了 |
| 成对出现 | 写成 X→→Y\|Z，这里 W→→P\|M |
| Y⊆X，或 Z 为空（Y 占全剩下的属性） | **平凡多值依赖**，不产生冗余 |
| 只存在平凡多值依赖 | 自动满足 4NF |
| 每个非平凡多值依赖 X→→Y 的 X 都是超码 | **4NF 定义**（在 BCNF 基础上再加这条） |
| 在 BCNF 基础上消除非平凡且**非函数依赖**的多值依赖 | 4NF 的教材写法（是函数依赖的那部分已由 BCNF 管住） |
| 两组互不相干的多值属性各自带走 | 4NF 分解：WP(仓库,保管员) + WM(仓库,产品) |

**易混对 1：函数依赖 X→Y ↔ 多值依赖 X→→Y**

判据｜X 定死**一个** Y 值＝函数依赖；X 对应**一整组** Y 值、且与其余属性无关＝多值依赖。**函数依赖是多值依赖的特例**（"一整组"退化成一个值）：X→Y 成立则 X→→Y 必成立，反过来不成立。
例子｜W→→P：W1 对应 {张三,李四}，与存什么产品无关；W→→M：W1 对应 {螺丝,螺母}，与谁保管无关。改成"每名保管员只管指定的几种产品"，这组值就跟 M 有关，多值依赖不成立。

**易混对 2：BCNF ↔ 4NF**

判据｜BCNF 查每条非平凡**函数**依赖的左边是否超码，4NF 查每条非平凡**多值**依赖的左边是否超码，补法同一个动作。台阶是 **BCNF→4NF**，不是 3NF→4NF。
例子｜WPM 无非平凡函数依赖 ⇒ 已是 BCNF；(W)⁺ 推不出全体属性，W 不是超码 ⇒ 非 4NF，拆成 WP + WM 才到 4NF，新增保管员只在 WP 加一行。此分解无损（两表无损定理对多值依赖同样成立：公共属性 W 满足 W→→P）。

其余认名即可：WP、WM 里各自只剩平凡多值依赖（Z 为空），已是 4NF，不用再拆。

1NF～3NF 管非主属性，BCNF 把要求提到每条函数依赖的左边，4NF 再套到多值依赖上：**补法是同一个动作，被检查的对象一次比一次宽**；每上一级都靠拆表，拆表都要回头验无损与保持依赖。

## 速记

- BCNF：**每条非平凡依赖的决定因素都是超码**；判法＝逐条算左边 X⁺，有一条不是全体属性就不满足
- 3NF 非 BCNF 的典型形态：**没有非主属性（自动过 3NF）＋ 某主属性反过来决定别的属性**；候选码常有两个
- **X⁺ 装属性，F⁺ 装依赖**；桥梁 **X→Y ∈ F⁺ ⇔ Y ⊆ X⁺**；Armstrong 三律自反、增广、传递，三推论合并、分解、伪传递
- 等价**双向**：F 的每条用 **G** 算闭包，G 的每条用 **F** 算；一条不过即否决；F⊆G 时只验反方向
- 无损（两表）：**交集决定至少一方的独有部分**，满足其一即可，交集为空必有损；三表以上用表格法，**某行全 √ 即无损**
- 保持依赖：**依赖左右两边同框**（不同框再用通用算法）
- **BCNF 分解保无损、不保依赖；3NF 分解可以两全**；两条性质互相独立
- 多值依赖：**一个 X 对应一整组 Y，与其余属性无关**，行数是乘积；**函数依赖是多值依赖的特例**；台阶 **BCNF→4NF**
