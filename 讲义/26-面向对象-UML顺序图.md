## 第 1 层 · 理解

### 一句话

> 类图告诉你"系统里有谁"，顺序图告诉你"这一次他们是怎么配合把事办成的"——把一次交互按时间从上往下摊开，画成一张剧本。

### 痛点：静态图画不出"过程"

类图、用例图回答的都是"有谁、谁和谁有关系"——**静态的**。但下面这种问题，静态图一个字也答不出来：

> "用户点了登录按钮之后，到底**哪个对象先干活**？它又**叫谁**干活？结果**怎么传回来**？"

这是**一次交互的完整过程**，必须有时间轴才画得出来。

**程序员的等价物**：你在 debugger 里打断点跟一次请求，看到调用栈一层层压入、弹出——**顺序图就是把这次跟踪画在纸上**。

### 一条主线

```
静态图（类图/用例图）画不出"过程"
   ↓
顺序图 = 一次交互【按时间摊开的剧本】
   横轴：每个对象站一列   纵轴：时间自上而下流逝
   ↓
骨架只有三样东西：
   生命线（垂直虚线 = 对象在这段时间活着）
   激活条（细长矩形 = 这个对象此刻正在执行，占着调用栈）
   消息  （带箭头的线 = 谁在什么时候对谁说了什么）
   ↓
消息为什么分好几种？判据只有一个：【发送方等不等结果】
   同步 = 等（实线+实心三角）  异步 = 不等（实线+开放箭头）
   返回 = 把结果交回去（虚线+开放箭头）
   ↓
但光有这些，只能画"一条道走到底"的固定剧本 ——
   真实逻辑里有 if、有 while，UML 1.x 表达不了
   ↓
UML 2.0 的答案：【组合片段】—— 把 if / while 直接画进图里
   loop = while ｜ alt = if-else ｜ opt = 没有 else 的 if ｜ ref = 调公共函数
```

**看懂最后那一行的对照关系，组合片段就不用背了**——你本来就会写 if 和 while。

## 第 2 层 · 考点：考试怎么问

### 考点① 顺序图的定义与要素（上午送分）

**题目长相**："强调按时间顺序描述对象之间消息交互的图是（ ）"，或"关于顺序图要素的叙述，错误的是（ ）"。

**要素表**：

| 要素 | 画法 | 含义 |
|---|---|---|
| 对象 | 顶部矩形，写 `对象名:类名`（如 `zhang:User`）；可省对象名写 `:类名`（匿名对象） | 参与交互的对象 |
| **生命线** | 对象框下垂的**垂直虚线** | 对象在这段时间内**存在** |
| **激活条**（执行规格） | 生命线上的**细长矩形** | 对象**正在执行**操作 |
| 时间 | **纵轴，自上而下** | 越靠上发生越早 |

### 考点② 消息类型——判据是"等不等结果"（高频陷阱）

| 消息类型 | 画法 | 含义 | 代码对应 |
|---|---|---|---|
| **同步消息** | **实线 + 实心三角箭头** | 发送方**等待**接收方处理完 | `r = obj.method()` |
| **异步消息** | **实线 + 开放（枝状）箭头** | 发送方**不等待**，继续自己的事 | 投递消息队列、启动线程 |
| **返回消息** | **虚线 + 开放箭头** | 把结果交回发送方 | `return r` |
| 自消息 | 箭头绕回自己的生命线 | 调用自身方法 | `this.check()` |
| 创建消息 | 箭头指向新对象的**对象框**，标 «create» | 新对象诞生，**生命线从此刻才开始** | `new Order()` |
| 销毁消息 | 标 «destroy»，生命线末端画大 **×** | 对象被销毁 | 析构 / 释放 |

**最常见的错误选项**："返回消息用带**实心三角箭头的实线**表示" → **错**。返回消息是**虚线 + 开放箭头**；"实线+实心三角"是**同步消息**。

**基本图示（用户登录）**：
```
 zhang:User      :LoginUI          :AuthService
    |               |                   |
    |--1 login(u,p)->|                  |
    |               |--2 verify(u,p)--->|       ← 同步消息（实心箭头）
    |               |                 ┃激活条┃   ← AuthService 正在执行
    |               |<- -3 result- - - |        ← 返回消息（虚线）
    |<- -4 提示成功- -|                  |
```

### 考点③ 组合片段（本课重点，下午题必考）

**画法通则**：在图上**圈出一个矩形区域**，左上角小五边形标签写**操作符**，**守卫条件写在方括号里**。

#### loop —— 循环（= while / for）

两种写法：`loop(min, max)` 按**次数**限定（`loop(1,3)` = 至少1次至多3次，如"重试至多3次"）；`loop [条件]` 按**守卫条件**循环（条件为真就继续，= while）。

```
 :收银台               :商品库
    ╔═ loop ═[还有商品未扫描]═══════╗
    ║ |--查询价格(条码)---->|        ║
    ║ |<- - 单价 - - - - - |         ║
    ║ |--累加小计(自消息)   |         ║
    ╚══════════════════════════════╝
    |--显示总价              |
```
框内三步反复执行，直到守卫不成立才跳出，继续框下方的消息。

#### alt —— 多分支互斥选一（= if / else if / else）

一个大框用**虚线**分隔成多个分区，每个分区带一个守卫条件，最后可放 `[else]` 兜底。**任何时刻只有守卫为真的那一个分区执行**。

```
 :订单服务              :账户服务
    |--发起扣款(金额)------>|
    ╔═ alt ═[余额 ≥ 金额]═══════════╗
    ║ |<- - 扣款成功 - - - |         ║
    ║ |--更新订单为已支付   |         ║
    ╟┄┄┄┄┄[else]┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄╢  ← 虚线分隔互斥分区
    ║ |<- - 余额不足 - - - |         ║
    ║ |--更新订单为支付失败 |         ║
    ╚═══════════════════════════════╝
```

#### opt —— 单条件可选（= 没有 else 的 if）

只有一个分区、一个守卫条件、**没有 else**——条件为真执行框内，为假整块跳过。

```
 :LoginUI              :CookieService
    ╔═ opt ═[用户勾选了"记住我"]═════╗
    ║ |--写入免登凭证------->|       ║
    ╚═══════════════════════════════╝
    |--跳转首页              |
```

> **alt vs opt 一句话**：要在**多种情况里选一种**（含"否则怎样"）→ **alt**；只关心"**满足条件才多做一步**，不满足什么都不做" → **opt**。

#### ref —— 引用另一张图（= 调公共函数）

框内**不画消息**，只写被引用的交互图名字。作用是**复用**：公共流程（如身份校验）画成独立顺序图，别处放个 ref 框就行。

> 另有 **par**（各分区**并行**执行）、**break**（满足条件则中断）可作了解。核心仍是 loop / alt / opt。

#### 组合片段 ↔ 代码对照总表（背这张最省事）

| 组合片段 | 等价代码 |
|---|---|
| `loop [c]` / `loop(min,max)` | `while(c){…}` / 限次 `for` |
| `alt [c1] / [c2] / [else]` | `if(c1){…} else if(c2){…} else{…}` |
| `opt [c]` | `if(c){…}`（**无 else**） |
| `ref 某图` | 调用抽出去的公共函数 |
| `par` | 多线程 / 并发执行 |

### 考点④ 代码 ↔ 顺序图 双向翻译（理解到这层就稳了）

```java
class OrderService {
    void placeOrder(Cart cart) {
        boolean ok = stock.check(cart);      // ① 同步调用并等结果
        if (ok) {                            // ② 条件 → opt 片段
            Order o = new Order(cart);       // ③ 创建对象 → 创建消息
            mq.send("发货通知");              // ④ 不等结果 → 异步消息
        }
    }
}
```

| 代码 | 图上对应 |
|---|---|
| ① `stock.check(cart)` | 向 stock 画**实线+实心箭头**同步消息；stock 激活条结束处画**虚线**返回 ok |
| ② `if (ok)` | 一个 **`opt [ok]`** 片段罩住后续消息 |
| ③ `new Order(cart)` | 指向 `o:Order` 对象框的 **«create»** 消息，Order 生命线**从这一行才开始** |
| ④ `mq.send(...)` | 向 mq 画**开放箭头**异步消息，OrderService **不等待**，激活条继续往下 |

**反向也成立**：下午题给你顺序图，你要能在脑中还原成这样一段代码。**读顺序图 = 读一次调用栈的执行录像**。

### 考点⑤ 下午题3 顺序图部分的三类填空 + 解题技巧

1. **补对象名**：生命线头上的框空着 → 看它收发什么消息，回说明文字里找"**谁负责干这件事**"
2. **补消息名**：箭头上空着 → 看前后消息 + 说明文字的动作描述，**尽量抄题干原词**，不要自造叫法
3. **补片段操作符 / 判断消息顺序**：认左上角标签，守卫条件对应说明里"如果 / 否则 / 重复"的措辞

**解题技巧**：
> 先把说明文字里的流程句子**按先后编号**，再与图中已有消息对齐——空缺处自然对应说明里"落单"的那个动作。
> 遇到组合片段：先看守卫条件，再回说明里找"**如果**……"（opt/alt）、"**否则**……"（alt）、"**重复/逐一/每个**……"（loop）。

## 第 4 层 · 速记

> **实心箭头同步等，开放箭头异步飞，虚线回头是返回**
> **loop 转圈，alt 选一，opt 可有可无，ref 抄别处**
> 守卫条件写方括号，else 兜底放末尾
> 创建指框生命始（«create»），销毁画叉生命终（«destroy»）
> 读图**自上而下 = 时间流逝**
> 下午题补空**先抄题干原词**，不自造消息名
> 生命线 = 活着；激活条 = 正在执行

## 考题回顾

**1.【模拟·重现2022下考点】** UML 中，强调按时间顺序描述对象之间消息交互的图是（ ）。
A. 类图　B. 用例图　C. 顺序图　D. 部署图
**解**：**C**。"按时间顺序 + 消息交互"是顺序图的定义性特征。

**2.【模拟·重现2021上考点】** 关于顺序图要素的叙述，**错误**的是（ ）。
A. 生命线表示对象在一段时间内存在
B. 激活条表示对象正在执行操作的时期
C. 返回消息用带实心三角箭头的实线表示
D. 对象排在图的顶部，时间沿纵轴自上而下推进
**解**：**C**。返回消息是**虚线 + 开放箭头**；"实线+实心三角"是同步消息。

**3.【模拟】** 某组合片段含两个由虚线分隔的分区，守卫条件分别为 `[库存充足]` 和 `[else]`，操作符应为（ ）。
A. loop　B. alt　C. opt　D. ref
**解**：**B**。多分区 + 互斥守卫 + else 兜底 = alt。opt 只有单分区无 else。

**4.【模拟】** 发送方发出消息后不等待接收方处理、立即继续自身后续行为，这种消息是（ ）。
A. 同步消息　B. 异步消息　C. 返回消息　D. 自消息
**解**：**B**。"不等待"= 异步，画作实线 + 开放箭头。

**5.【模拟·下午题风格】** 在线购票退票流程：会员在票务界面上发起退票，票务界面向订单服务提交退票申请；订单服务校验订单状态（自身操作）；**若订单状态为"已出票"**，订单服务调用支付网关执行退款，支付网关返回退款结果；订单服务将订单状态更新为"已退票"（自身操作）。求 (a) 组合片段操作符、(b) 片段内第一条消息。

```
 :票务界面        :订单服务         :支付网关
    |--退票申请---->|                 |
    |               |--校验订单状态    |
    ╔═ (a) ═[订单状态=已出票]═════════╗
    ║               |----(b)-------->|║
    ║               |<- -退款结果- - |║
    ║               |--更新为已退票   |║
    ╚═════════════════════════════════╝
```
**解**：(a) **opt**——只有一个守卫、无 else，"满足才做、不满足跳过"；(b) **执行退款**（抄题干原词）。注意"更新为已退票"是**自消息**，不发给别人。

## 自测练习

1. 【模拟】`loop(1,3)` 与 `loop [队列非空]` 两种写法语义上有何区别？
2. 【模拟】"用户提交表单后，仅当填写了发票信息才调用发票服务开票；无论是否开票，最后都发送确认邮件。"——"开票"应放哪种组合片段？"发送确认邮件"画在片段内还是片段外？
3. 【模拟】把 `for(Item i : cart){ price = catalog.getPrice(i); total += price; }` 描述成顺序图结构（用什么片段、守卫写什么、框内哪几条消息、各是什么类型）。

### 参考答案

1. `loop(1,3)` 按**次数**限定，最少 1 遍最多 3 遍（如"重试至多3次"）；`loop [队列非空]` 按**守卫条件**循环，每轮开始前判断，为真继续（= while）。**前者管次数，后者管条件。**
2. "开票"放 **opt** 片段，守卫 `[填写了发票信息]`（单条件、无否则分支）。"发送确认邮件"画在**片段外（框的下方）**——无论条件真假都要执行的消息**不能圈进 opt 框**，否则条件为假时会被一起跳过。
3. 用 **loop** 片段，守卫写 `[购物车还有未处理商品]`。框内三条：①向 catalog 发**同步消息** `getPrice(i)`（实线实心箭头，要等结果）；②catalog 的**返回消息** `price`（虚线）；③自身累加 total 的**自消息**。循环结束跳出框。
