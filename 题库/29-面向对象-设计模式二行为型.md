## 考试怎么考

**考点① 第 44–47 这四分有两种长相。** 一种是**一道四空大题**（2017下、2018下、2020下、2021上）：一段业务场景 + 一张类图 + 四个空——**认模式名 / 认角色（哪个类扮演哪个角色）/ 判分类（行为型对象模式）/ 选适用场景**；另一种是**拆成两三道小题**（2019上、2022下、2023上），不给类图，直接甩意图原句或场景让你认模式名，最多再追问分类和适用场景。四空大题里各空难度天差地别：第一空和第三空只要背了意图和分类就能拿，第二空要看类图，第四空要认得几个模式各自的适用场景描述。**保 45 分的打法是稳拿一三两空**，第二空按"角色名里带 State 的都是状态类、客户程序用的是上下文"这类常识排除，第四空对照下面考点②的意图句反推。

**考点② 给意图句选模式名。** 考卷上的意图句和培训资料"定义"栏那 11 句同出一源（都译自 GoF 原著），意思一样，但用词常差一两个虚词——同一句状态模式的意图，培训资料写"允许一个对象在其内部状态改变时改变它的行为"，2017 下的卷面写"一个对象在其内部状态改变时改变其行为"。所以要认的是**关键词组合**，不是背整句。最容易搞错的三句：看见"**一对多 + 自动更新**"选观察者，不要选中介者；看见"**顺序访问 + 不暴露内部表示**"选迭代器，不要选**组合（Composite）模式**（那是结构型，在讲义 28；本篇正文里说的"对象组合"是另一回事）；看见"**排队 / 日志 / 撤销**"选命令，不要选备忘录。

**考点③ 分类判断。** 答案要把两个坐标叠起来写：只有正好考解释器或模板方法时才填"行为型类模式"，其余一律"行为型对象模式"。

**考点④ 五对易混，各有一句判据。**

| 容易混的一对 | 一句话判据 | 报销系统里的例子 |
|---|---|---|
| 策略 vs 状态 | **谁来换**：外面挑一个塞进来是策略；对象自己走到下一步是状态 | 财务换一套审批规则（策略）vs 单子从草稿变成待审批（状态） |
| 职责链 vs 命令 | **传下去** vs **存起来**：沿链找第一个能办的是职责链；把请求变成能排队能撤销的对象是命令 | 组长批不了转经理（职责链）vs 主管撤回自己刚才那次审批（命令） |
| 观察者 vs 中介者 | **一对多广播** vs **多对多调停**：全体收到同一条是观察者；谁跟谁说话都得过中间人是中介者 | 单子通过后短信台账报表全收到（观察者）vs 四个模块互相通信都走中介（中介者） |
| 模板方法 vs 策略 | **继承改一步** vs **组合换整套**：骨架焊死只让子类填某步是模板方法；整个算法作为对象被替换是策略 | 审批四步流程只换"算级别"那步（模板方法）vs 整套算级别的规则换掉（策略） |
| 迭代器 vs 访问者 | **遍历** vs **加操作**：只是把元素挨个取出来是迭代器；在不改元素类的前提下加新操作是访问者 | 挨个读报销单的明细（迭代器）vs 给明细加"按税种汇总"（访问者） |

**考点⑤ 错误选项的三种造法。** 一是**同类互换**——把中介者的"降低多个对象通信复杂性"安到观察者头上；二是**跨类混排**——四个候选里既摆行为型也摆结构型，2022 下那道"统一驱动接口"题就是三个行为型（中介者、访问者、观察者）陪着一个结构型的适配器，答案偏偏是那个结构型（该题归讲义 28）；三是**分类写错**——模式名对了，但"该模式属于"那一空给你"结构型对象""行为型类"。三种造法认出来，逐字比对的功夫能省一半。

### 参考答案

1. **A、D、C**。第一空"连成一条链、沿链传递、直到有一个对象处理为止"是职责链定义的原句；第二空"顺序访问聚合对象各元素、不暴露内部表示"是迭代器定义的原句。第三空最容易丢分：责任链和迭代器都靠对象组合（链上对象互相持有引用、迭代器持有被遍历的聚合对象），不是继承，所以是**行为型对象模式**，D 的"行为型类模式"只轮得到解释器和模板方法。
2. **D**。A 是迭代器的适用场景，B 是中介者的（"减少通信复杂性"＝多对多收成星形），C 是备忘录的。这道题正是"意图句反着认"的标准形态：四个选项各是一个行为型模式的适用场景，只有 D 出现了"一对多 + 自动得到通知"。
3. **A、D**。"根据季节、节假日推出不同定价包"＝有一族算法要按情况挑一个，是从**外面**挑，不是旅行包自己变，所以选策略不选状态。第二空 D 是策略定义的原句；A 是命令、B 是观察者、C 是状态——四个选项刚好是第一空四个候选的意图句，这是命题人最偏爱的配对方式。
4. **B、B、D、C**。第一空题干把"库存、货币量、找零能力"这些**内部状态**列出来，说不同状态下同一个"投币并选择"的行为不同——是状态模式；策略是干扰项，但售货机没有"外面挑一套算法"这回事。第二空不看图也能排除：另外三个选项都以 State 结尾，是三个状态类，而客户程序用的是**上下文**那个角色，四个里只有 Buy 不是状态类，选 B。第三空状态模式靠组合，是**行为型对象模式**，选 D（注意这里 D 才是"行为型对象"，选项顺序和第 1、5 题不同，别背位置）。第四空 C 是状态模式的意图原句，A 是观察者、B 是备忘录、D 是命令。
5. **B、A、D、C**。第一空："对购物车里每个物品做汇总"＝对一个对象结构中的各元素施加操作，且 Manual / Auto 是两种不同的汇总方式——访问者。第二空不看图也能定：`accept(Checkout)` 是**元素**交给访问者的那个口子，Checkout 是访问者，Item 才是元素，选 A；Manual 和 Auto 是具体访问者。第三空同样是**行为型对象模式**（本题 D）。第四空 C 是访问者的适用场景原句，A 是备忘录、B 是职责链、D 是命令。
6. **A、A、D、B**。第一空题干整句就是命令模式的定义。第二空"声明执行操作的接口"指的是**抽象命令**这一层，四个候选里 Operation 是抽象层、sellOperation 那一串是具体命令、Broker 是调用者、Stock 是接收者，选 A。第三空仍是行为型对象（本题 D）。第四空 B"抽象出待执行的动作以参数化某对象"是命令的适用场景；A 是观察者、C 是状态、D 是中介者。
7. **A、B、B**。"检查、能处理就处理、否则传给下一个"就是职责链的做法，题干里"多个前后连接的对象都有机会处理请求""避免请求的发送者和接收者之间的耦合关系"两句更是把定义摊开了摆在眼前。第二空：链上对象靠互相持有引用组装，是**行为型对象**。第三空日志链可以随配置增删几级，所以选"对象集合应被动态指定"；A 说的是过滤器（Filter），它压根不在 GoF 那 23 个模式里，是纯干扰项；C 是备忘录的适用场景，D 是策略的（"多种行为以多个条件语句的形式出现"正是策略要拆掉的那坨 if-else）。
8. **B、B**。稳定的元素结构 + 不断新增的操作，是访问者的教科书场景；代价是元素类必须各留一个 `accept` 口子。若答迭代器，那只解决了"怎么把明细一个个取出来"，没解决"新统计写在哪"。
9. 第一个是**模板方法**（父类把四步骨架焊死，子类只覆盖"算级别"那一步，靠**继承**）；第二个是**策略**（把整套算级别的算法做成对象，运行时整体替换，靠**组合**）。
10. **C**。享元是结构型（讲义 28），解释器、备忘录、中介者都在行为型 11 个里。
11. **解释器**和**模板方法**。判据是它们靠继承在编译期定死关系（子类覆盖父类方法），其余九个都靠持有别的对象、运行时委托，只能是对象模式。
