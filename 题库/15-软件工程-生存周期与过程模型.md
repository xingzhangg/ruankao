# 15 · 软件工程：软件生存周期与过程模型 · 题库

## 考试怎么考

**考点① 给场景选模型。** 先问题干里的项目最怕哪一条晚，再对名字：

| 题干说 | 最怕什么 | 选 |
|---|---|---|
| 功能有清晰定义、需求明确稳定、交付时间严格 | 什么都不怕，按部就班 | 瀑布 |
| 用户说不清需求、先做雏形试用 | 需求定不下来 | 原型 |
| 核心功能先交付、分批追加 | 看不到能用的东西 | 增量 |
| 规模庞大、风险高、每阶段先评估风险 | 变化和风险晚爆 | 螺旋 |
| 开发与测试对称、测试尽早准备 | 测试设计太晚 | V 模型 |
| 面向对象、阶段无明显界限、迭代无缝 | | 喷泉 |
| 用例驱动、以体系结构为中心、迭代增量 | | RUP |
| 固定长度冲刺、自组织小组、按优先级 | | Scrum |

容易混的一对是原型和螺旋：螺旋里也有原型思想，只有出现"风险分析、风险驱动"才选螺旋，题干不提风险就选原型。

**考点② "以下叙述不正确的是"。** 四个选项三个抄定义、一个反着写。错项只有三种造法：把弱点反写成优点（"螺旋成本低适合小项目"）、把适用场景写反（"原型适用于需求明确的项目"）、张冠李戴（把"风险驱动"安到增量头上，把"无缝迭代"安到 V 模型头上）。认出造法就不用逐字比对。

**考点③ 阶段归属与产出物。** "编写需求规格说明书"是需求分析；"划分模块、定接口"是概要设计，"模块内部算法"是详细设计，这一对最常互换设错；"系统分析阶段结束的产品"答系统方案建议书，"系统测试完成后的产品"答操作手册（第一节末尾说过原因）；"成本最高的阶段"是维护，不是编码。

**考点④ RUP。** 三特点里混入的假选项常是"以文档为中心""瀑布式推进"；四阶段口诀"初细构交"，里程碑按"目标、架构、初始运作、发布"对上，架构基线在细化阶段。

**考点⑤ 开发方法的叙述判断。** 结构化方法"比面向对象更适合大规模特别复杂的项目"是错的；结构化"很少考虑数据结构""自顶向下逐层分解"是对的；原型法"是一种完整的方法论"是错的；敏捷家族按讲义第三节那张表认名字（XP 代码质量与反馈、Scrum 固定冲刺、水晶每项目一套、FDD 中小型、ASD 适应性），XP 的四个价值观是封闭清单，结对编程、持续集成是实践不是价值观；Scrum 只有三个角色，没有"项目经理"。

## 练习

**1.【真题·2012上】** 假设某软件公司与客户签订合同开发一个软件系统，系统的功能有较清晰的定义，且客户对交付时间有严格要求，则该系统的开发最适宜采用（ ）。A.瀑布模型 B.原型模型 C.V 模型 D.螺旋模型
**2.【真题·2017上】** 以下关于螺旋模型的叙述中，不正确的是（ ）。
A.它是风险驱动的，要求开发人员必须具有丰富的风险评估知识和经验　B.它可以降低过多测试或测试不足带来的风险　C.它包含维护周期，因此维护和开发之间没有本质区别　D.它不适用于大型软件开发
**3.【真题·2014下】** 以下关于结构化开发方法的叙述中，不正确的是（ ）。
A.总的指导思想是自顶向下，逐层分解　B.基本原则是功能的分解与抽象　C.与面向对象方法相比，更适合于大规模、特别复杂的项目　D.特别适合于数据处理领域的项目
**4.【真题·2016下】** 在敏捷过程的开发方法中，（ ）使用了迭代的方法，其中，把每段时间（30 天）一次的迭代称为一个"冲刺"，并按需求的优先级别来实现产品，多个自组织和自治的小组并行地递增实现产品。A.极限编程 XP B.水晶法 C.并列争球法 D.自适应软件开发
**5.【真题·年份待核实】** （ ）是系统分析阶段结束后得到的工作产品，（ ）是系统测试阶段完成后的工作产品。
　　（本题录自培训资料，**疑非软设卷**：检索历年软件设计师上午卷未见同题。）
　　第一空：A.系统设计规格说明 B.系统方案建议书 C.程序规格说明 D.单元测试数据　　第二空：A.验收测试计划 B.测试标准 C.系统测试计划 D.操作手册
**6.【模拟】** 某项目开发前用户仅能描述大致业务目标，无法给出明确的功能需求；开发方决定先构造一个可演示的系统雏形让用户试用，通过反馈逐步明确需求。该做法采用的开发模型是（ ）。A.瀑布 B.原型 C.V 模型 D.螺旋
**7.【模拟】** 统一过程中，"建立系统体系结构基线、消除影响最大的风险"主要在（ ）阶段完成，该阶段的里程碑是（ ）。A.初始／生命周期目标 B.细化／生命周期体系结构 C.构建／初始运作能力 D.交付／产品发布
**8.【模拟】** 不属于极限编程四大价值观的是（ ）。A.沟通 B.简单性 C.效率 D.勇气
**9.【模拟】** Scrum 中负责维护产品待办事项列表并确定优先级的角色是（ ）。A.Scrum Master B.产品负责人 C.开发团队 D.项目经理

**自测**：
10.【模拟】某银行核心系统改造规模庞大、风险很高，要求每个阶段开始前先评估风险再决定是否继续投入。最适合的模型？
11.【模拟】6 人创业团队开发需求频繁变化的 App，两周一个迭代、每日站会、迭代末演示可用版本。属于哪类方法？"两周一个迭代"叫什么？
12.【模拟】把下列活动填入阶段：①写软件需求规格说明书；②划分模块并定义接口；③设计模块内部算法。

### 参考答案

1. **A**。"功能清晰"就是需求明确，瀑布的关键词。
2. **D**。螺旋恰恰适合大型高风险项目，D 把适用场景写反了。B 对，因为每圈有风险分析和客户评估，测多测少随风险调整；C 对，维护就是再转一圈。
3. **C**。结构化面向数据流、自顶向下，A、B、D 都对；更适合大型复杂项目的是面向对象方法。
4. **C**。固定长度冲刺、自组织小组是 Scrum 的标志；ASD 强调适应性，XP 强调四价值观和测试先行。
5. **B、D**。用阶段归属排除：系统设计规格说明属设计阶段，程序规格说明属详细设计或编码，单元测试数据属测试阶段，只剩系统方案建议书落在分析阶段。第二空同样排除：验收测试计划、测试标准、系统测试计划都是测试前就该定的，"完成后的工作产品"只能是操作手册。
6. **B**。"无法给出明确需求 + 构造雏形试用"是原型的定义原文，题干不提风险，不选螺旋。
7. **B**。体系结构基线四个字锁定细化阶段。
8. **C**。四价值观是沟通、简单性、反馈、勇气。
9. **B**。产品负责人管"做什么、先做什么"，Scrum Master 管流程，团队管"怎么做"，Scrum 没有项目经理。
10. **螺旋模型**。11. **敏捷（Scrum）**，冲刺 Sprint。12. ①需求分析 ②概要设计 ③详细设计。
