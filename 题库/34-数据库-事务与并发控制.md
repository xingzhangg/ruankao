## 考试怎么考

**考点① 给一段时序，判是哪一类并发问题。** 拿到表先数"有几个事务在写同一个数据"，两个都写、且后写的那个在前写之前就把值读走了，直接选丢失更新；只有一个写就去找 `ROLLBACK` 和 `COMMIT`：看见回滚往读脏上想，看见提交且读方读了两次往不可重复读上想。三个错项的造法固定：把丢失更新说成脏读（其实两边都在写）、把已提交的修改说成脏读（脏的定义要求"未提交且随后撤销"）、把只读一次的场景说成不可重复读（不重复读两次就谈不上"不可重复"）。

**考点② 锁相容判定。** 题干给若干事务分别持有 S 锁/X 锁，问某个事务还能不能加锁。做法机械：把每份数据当前被谁锁着、锁的是哪种，列成一行，再逐个选项拿"只有 S+S 相容"去核。两个必踩的坑：**别人持 S 锁时，你还能加 S 锁**（"任何锁都加不上"是错的）；**"先加 S 锁再升级成 X 锁"绕不过相容表**，升 X 一样要求没有别人持锁，别人的 S 锁还在就升不上去。

**考点③ 封锁协议的级别归属。** 题干只会改一句话，盯住两处：读加不加锁（不加＝一级），以及 S 锁读完就放（二级）还是持到事务结束（三级）。问"**至少**要哪一级"就答能覆盖该问题的最低那级：丢失更新→一级、读脏→二级、不可重复读→三级。最高频的错项是"一级封锁协议可以防止读脏数据"——一级对读不加锁，防不住。

**考点④ 两段锁协议挑错。** 四个选项里三个抄定义、一个反着写，错项只有两种造法：**把充分条件说成必要条件**（"可串行化的调度一定遵守两段锁协议"），**把可串行化说成不死锁**（"遵守两段锁协议的事务不会发生死锁"）。另一种低级造法是把两段的顺序说反（"先集中放锁再集中加锁"）。

**考点⑤ ACID 对号入座。** 给一句场景描述选特性。抓手：出现"撤销、回滚、要么全做要么全不做"选原子性；出现"总额不变、约束仍成立"选一致性；出现"别的事务看不见、互不干扰"选隔离性；出现"提交之后断电也不丢"选持久性（＝持续性）。A 与 C 的分界线是**机制 vs 结果**，题干描述动作选 A、描述约束选 C。

### 参考答案

1. **D**。把当前锁状态列出来：D1 被 T1 加了 S 锁，D2 被 T2 加了 X 锁，D3 被 T3 加了 X 锁。逐项核：A 要 T1 对 D2、D3 加 X 锁成功，但那两份数据上都挂着别人的 X 锁，X 与任何锁都不相容，失败；B 前半句对（加 X 锁确实都失败），后半句要 T2、T3 对 D1 加 X 锁成功，D1 上有 S 锁，S 与 X 不相容，失败；C 要 T1 对 D2、D3 加 S 锁成功，同样被别人的 X 锁挡住，失败。只剩 D：前半句"加共享锁都失败"成立，后半句"对 D1 加共享锁成功"也成立，因为四格里唯一相容的就是 S+S。
2. **C**。"对其他事务都是不可见的"——关键词是"其他事务"，管的是并发时互不干扰，正是隔离性。原子性管的是自己有没有留下半截，持久性管的是提交之后丢不丢，一致性管的是做完之后账对不对，都不涉及"别人看不看得见"。
3. **D、C**。第一空：D2、D3 上分别有 T2、T3 的 X 锁，T1 无论申请 X 还是 S 都不相容，全部失败 → D。第二空：D1 上是 T1 的 S 锁，T2 申请 S 锁与之相容，成功；D3 上是 T3 的 X 锁，T2 申请 X 锁不相容，失败 → C。两空都只用同一张相容表。
4. **B、A、A**。沿时间线走：T1 和 T2 都在第一步读到 100；T1 写回 100−30=70；T2 手里还是那份 100，写回 100−50=**50**，把 70 盖掉了。两笔都生效应为 100−30−50=20，实际 50，丢的正是 T1 那 30 → 两个事务都写同一数据、后写覆盖先写，是**丢失更新**。一级封锁协议就够：要改数据先拿 X 锁并持到事务结束，T2 的"读—改—写"整段被推到 T1 之后，读到的是 70，写回 20，覆盖不再发生。
5. **C、B**。T1 没写任何东西，只是前后读了两次，中间被已提交的 T2 改掉，值本身完全合法，只是"变了"——是不可重复读，不是脏读（脏读要求对方未提交且随后回滚）。第二空：能挡住它的唯一办法是让 T1 的 S 锁一直持到事务结束（三级封锁协议），二级恰恰是"读完即放"，两次读之间没有任何锁保护。A 不对，T1 只读不写，本来就不该加 X 锁；C 说反了，T2 提交了才叫不可重复读；D 不对，题干没有给出 T1 的加锁放锁次序，判不了它守没守 2PL。
6. **C**。A 是 2PL 的定义，对；B 是 2PL 那条定理，对；D 是"充分不必要"的另一半，对。C 错：T1 锁 A 再申请 B、T2 锁 B 再申请 A，两个事务都还在扩展阶段、一把锁没放过，完全遵守协议，却互相等成环。**2PL 保证结果可串行化，不保证不卡住。**
7. **B**。查相容表：S 与 S 相容，T2 可以再加一把 S 锁一起读。A 不行，X 与 S 不相容。C 是最诱人的错项——"升级为 X 锁"同样要通过相容表这一关，T1 的 S 锁还挂着就升不上去，仍要等。D 与 S+S 相容矛盾。
8. ①**原子性**（失败后把已做的部分撤销，是"要么全做要么全不做"的机制）；②**一致性**（描述的是一条业务约束在事务前后都成立，是结果不是机制）；③**隔离性**（"别人看到的"）；④**持久性/持续性**（"提交之后断电也不丢"）。①②这一对就是 A 与 C 最常互换的地方，判据是机制 vs 结果。
9. 因为二级封锁协议的 S 锁**读完就释放**。T1 第一次读完立刻放锁，T2 马上就能拿到 X 锁把数据改掉并提交，等 T1 第二次读，值已经变了——**两次读之间那段时间是没有锁保护的**。三级把 S 锁持到事务结束，这段空档才被堵上。
10. **没有违反**。两个事务都只在"申请"，一把锁都还没释放，全都处在扩展阶段，严格遵守两段锁协议。结果是**死锁**：T1 等 T2 手里的 B，T2 等 T1 手里的 A，等待图上出现环，不外力介入永远解不开（实际系统靠超时法或等待图检测，挑一个事务回滚掉）。这说明**两段锁协议保证的是调度可串行化，它对死锁无能为力**——可串行化和无死锁是两个独立的问题。
