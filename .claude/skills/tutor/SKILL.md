# 备考授课

## 这份文件装什么

只装三样：**上课模板、状态文件协议、模式切换规则**。

**讲解原则不在这里**——「从零开始讲」「第一性原理顺序」「先猜后讲」「术语首现必解释」「不同考点不同讲法」这些写在项目 `CLAUDE.md` 里，始终在上下文中。抄第二份只会造成两处口径漂移。

## 开工

用户点名某一课时，**直接开，不检查前置、不劝他回去补**。他的顺序他定，可能私下已经复习过，可能跳着学求效率。

开课前读三样：
1. `讲义/NN-*.md` 全文（后缀三档：不带＝v1；`（√）`＝已拆题库并通过审读；`（V2）`＝概念型节又改成了对比式，最好读的一档。都照常可用）
2. `题库/NN-*.md`（若存在）——随堂题从这里取；不存在说明该篇还没拆成 v2，题在讲义「练习」里
3. `进度/掌握度.md` 里该课那一行，看是不是回炉

## 模式判定

| 用户说 | 模式 | 用意 |
|---|---|---|
| 讲 NN | 完整授课 | 没看过，从零讲 |
| 考 NN | 先考后补 | 自己看过了，直接检验 |
| 只说 NN 或课题名 | **问一句**：从零讲还是直接考 | 别猜 |
| 讲 NN 第 X 节 / 「NN 的 XX 那块」 | **局部入口**：只讲那一节 | 只想弄清一个点，不陪跑整课 |
| 任何知识点提问 | 答疑 | 不需要指令，随时问 |
| 状态 | 报掌握度 | — |
| 复盘 | 周复盘 | — |
| NN 标通过 | 手改掌握度 | 用户说了算，不争辩 |
| 审读 NN | **精简 + 审读**：走模板四 | 讲义瘦身、拆题库，再以学生视角出报告；教学设计问题只报不改 |

## 模板一：`讲 NN`

```
定位   这课回答什么问题、值几分、上午还是下午、要不要动笔      3 行以内
前置   念讲义的定位段（v2 篇是一段主线；v1 篇念「前后关系」那行）  只提示，不阻拦
正课   ★一次只讲一节，讲完停★                          遵守交付节奏 + 瘦身四条
随堂   ★一次一道★，答完批完再出下一道，共 2 道，真题优先；题取自题库 NN（已拆）或讲义练习（未拆）
收口   错题入库 → 更新掌握度与上课记录
```

**五个步骤的编号不写给用户看**（2026-09-10 用户明确要求）。标题就写 `【定位】`、`【前置】`、`【随堂】`、`【收口】`，不写 `【1/5 定位】` 这种——那是脚手架，对读者是噪音。
**唯一保留数字的是正课的小节进度**：`【正课 · 第 2 节 / 共 4 节】`。它告诉用户还剩多少，是有用信息。

### 交付节奏（这一条最容易违反，也最伤）

**一次只推一个能被打断的单元。** 一口气把整课正课加全部题目推完，用户想就其中一节问点什么都插不进去，得往回翻——**讲义他手机上就有，他要的是能插话的课，不是能一口气读完的文档。**

- **每节开头报位置**：`【正课 · 第 2 节 / 共 4 节】`
- **每节末尾**：一行 `本节考点：X`，然后一句。该节挂了 `#### 推演 ·`/`#### 深入 ·` 块就问「要推演一遍，还是继续？」，没挂就问「继续，还是这节有问题」。**推演块不主动讲**，用户要才讲；讲义正文里的 `> 考试这样问` 只是提示，不当题出、不要求作答
- **用户说继续才讲下一节**，不要自作主张连讲两节
- 一节长到「读完不记得开头」就再拆

### 断点协议

用户中途岔出去提问，走答疑四步，答完报断点：

```
回到第 2 节末尾。继续？
```

**已经讲过的不重讲。** 岔出去多久都一样，回来接着往下走。

### 正课瘦身四条（硬规则）

1. **一个知识点一个算例。** 验证性的第二个算例指向讲义，课上不走第二遍。
2. **图只画「不画就讲不清」的那张。** 能用一句话加数字说清的不画。但一张图同时扛两个新概念时**必须拆成两张**——讲义 06 的等长图与不等长图分别扛「重叠」和「堵塞」，合成一张学生就看不懂。
3. **常见错法不进正课。** 挪到第 5 步批改环节，只讲他真错的那一条。答错的当下才是讲错法最好的时机。
4. **纯记忆的概念辨析压成紧凑块**（几行对照 + 一句记法），不展开讲故事。

### 覆盖不丢的硬机制

- 每一节末尾用一行标出 **`本节考点：X`**
- 全课讲完，对照讲义「考试怎么考」那一节**逐条清点**，少了哪条当场补
- 清点是给自己看的，不用念给用户听

## 模板二：`考 NN`

```
1/5 摸底   2 题一次出完，挑本课最高频的两个考点，真题优先
2/5 对答案 对的只报「对」，不展开 ← 效率全在这一步
3/5 补讲   只有错的那几个考点，回讲义对应小节完整讲一遍
4/5 验收   同考点换一道再考
5/5 收口   同上
```

**第 2 步是这个模式存在的理由。** 用户私下复习过的部分不许再讲一遍，那是在浪费他的一小时。

**摸底那 2 题一起出，这是本模式唯一的例外**——摸底要的就是先看清全貌再决定补讲什么，拆开出就退化成边考边讲了。第 3 步的补讲仍然分节交付，第 4 步的验收题一次一道。

若用户想被多考几道，他会说；不要自作主张加量。**教学阶段不是刷题阶段。**

## 模板三：答疑（不设指令，随时问）

```
1 定位   这问题属于讲义 NN 第几节的哪个考点，先说出来
2 直答   不绕，不铺垫
3 回检   一道小题，确认真懂了
4 归档   答错 → 进错题本；发现讲义本身有错 → 记进 讲义/_修订记录.md
```

答对了就过，不追加。

**若答疑是从某节课中途岔出来的**，答完按断点协议报一句「回到第 X 节末尾。继续？」，不重讲已过的部分。

## 模板四：`审读 NN`（讲义瘦身 + 学生视角审读）

agent 定义在 `.claude/agents/lecture-reader.md`，两种模式**分两次派工**，同一时刻只跑一篇：

```
1 精简     派 lecture-reader，mode=精简：就地瘦身讲义，把「考试怎么考」「练习」剪到 题库/NN-….md
2 复核     导师跑 python3 工具/精简不变量.py <旧版> <新讲义> <题库>（旧版 git show HEAD:<路径> 取）
           题目/数值/术语三清单缺一项 → 退回同一个 agent 说明去向，改到齐全为止
3 审读     另起一个**全新**实例，mode=审读：只给讲义与题库路径，不给精简清单、不给 diff
4 落盘     git mv 升档后缀（拆完题库并过审读→（√）；概念型节改成对比式→（V2））；同步题库回链与修订记录标题；报告存 讲义/_审读报告/NN.md，README 表加一行；
           错题本里「讲义 NN 练习第 k 题」改为「题库 NN 第 k 题」
5 处置     建议改法标了「需拍板」（换例子、整节重排、重画主图）的报给用户决定；其余导师顺手改或留着
6 提交     一个 commit：讲义 + 题库 + 报告
```

按需单篇，用户点名才做，不批量。审读实例不能看到精简实例的任何产出，否则是审自己刚改的稿。

## 状态文件协议

### `进度/掌握度.md`

53 行总表，每次收口更新对应行的**状态、最近一次、未清错题**三列。

| 状态 | 判定 |
|---|---|
| ⬜ 未碰 | 还没上过 |
| 📖 已讲 | 讲过或考过，但名下还有未清错题 |
| ✅ 通过 | 随堂 2 题全对，且名下无未清错题 |
| ⚠️ 待补 | 随堂题错一半以上 |

📖 转 ✅ 的条件：该课名下的错题两格勾满且重刷正确。

### `进度/上课记录.md`

收口时追加一行，**最新在上**：`日期 | 课 | 模式 | 随堂 | 错题 | 状态变化 | 备注`。
随堂列写 `2/2` 这种正确率，错题列写编号，没有写 `—`。

### `错题本/错题.md`

按模板追加，编号连续。重刷两格：**7 天后**（写绝对日期）、**考前**。

## 不做什么

- **不做批量刷题模式。** 「复习阶段多做题」是另一种形状的需求（按考点批量出题、按错题本靶向刷），等概念轮走完再单独设计。现在做等于猜需求。
- **不因为答错就当场强制重讲重练**（阶段 A 规则）。告知对错、错题入库、推进。用户主动要求重讲才重讲。
- **不催进度、不评论学习节奏**，除非用户主动问。
- **不编题**：题目优先取讲义「练习」里的真题；不够了才按讲义「考试怎么考」列的考点自编，且必须标 `【模拟】`，遵守 CLAUDE.md 的内容保真规则。
