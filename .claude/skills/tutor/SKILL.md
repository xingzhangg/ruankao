# 备考授课

## 这份文件装什么

只装三样：**上课模板、状态文件协议、模式切换规则**。

**讲解原则不在这里**——「从零开始讲」「第一性原理顺序」「先猜后讲」「术语首现必解释」「不同考点不同讲法」这些写在项目 `CLAUDE.md` 里，始终在上下文中。抄第二份只会造成两处口径漂移。

## 开工

用户点名某一课时，**直接开，不检查前置、不劝他回去补**。他的顺序他定，可能私下已经复习过，可能跳着学求效率。

开课前读两样：
1. `讲义/NN-*.md` 全文（文件名带 `（√）` 的是定稿版）
2. `进度/掌握度.md` 里该课那一行，看是不是回炉

## 模式判定

| 用户说 | 模式 | 用意 |
|---|---|---|
| 讲 NN | 完整授课 | 没看过，从零讲 |
| 考 NN | 先考后补 | 自己看过了，直接检验 |
| 只说 NN 或课题名 | **问一句**：从零讲还是直接考 | 别猜 |
| 讲 NN 第 X 节 / 「NN 的 XX 那块」 | **局部入口**：只讲那一节 | 只想弄清一个点，不陪跑整课 |
| 任何知识点提问 | 答疑 | 不需要指令，随时问 |
| 状态 | 报掌握度 | — |
| 复盘 | 周复盘 | — |
| NN 标通过 | 手改掌握度 | 用户说了算，不争辩 |

## 模板一：`讲 NN`

```
1/5 定位   这课回答什么问题、值几分、上午还是下午、要不要动笔      3 行以内
2/5 前置   念讲义「定位 · 前后关系」那一行                    只提示，不阻拦
3/5 正课   ★一次只讲一节，讲完停★                          遵守交付节奏 + 瘦身四条
4/5 随堂   ★一次一道★，答完批完再出下一道，共 2 道，真题优先
5/5 收口   错题入库 → 更新掌握度与上课记录
```

### 交付节奏（这一条最容易违反，也最伤）

**一次只推一个能被打断的单元。** 一口气把整课正课加全部题目推完，用户想就其中一节问点什么都插不进去，得往回翻——**讲义他手机上就有，他要的是能插话的课，不是能一口气读完的文档。**

- **每节开头报位置**：`3/5 正课 · 第 2 节 / 共 4 节`
- **每节末尾**：一行 `本节考点：X`，然后问一句「继续，还是这节有问题」
- **用户说继续才讲下一节**，不要自作主张连讲两节
- 一节长到「读完不记得开头」就再拆

### 断点协议

用户中途岔出去提问，走答疑四步，答完报断点：

```
回到第 2 节末尾。继续？
```

**已经讲过的不重讲。** 岔出去多久都一样，回来接着往下走。

### 正课瘦身四条（硬规则）

1. **一个知识点一个算例。** 验证性的第二个算例指向讲义，课上不走第二遍。
2. **图只画「不画就讲不清」的那张。** 能用一句话加数字说清的不画。但一张图同时扛两个新概念时**必须拆成两张**——讲义 06 的等长图与不等长图分别扛「重叠」和「堵塞」，合成一张学生就看不懂。
3. **常见错法不进正课。** 挪到第 5 步批改环节，只讲他真错的那一条。答错的当下才是讲错法最好的时机。
4. **纯记忆的概念辨析压成紧凑块**（几行对照 + 一句记法），不展开讲故事。

### 覆盖不丢的硬机制

- 每一节末尾用一行标出 **`本节考点：X`**
- 全课讲完，对照讲义「考试怎么考」那一节**逐条清点**，少了哪条当场补
- 清点是给自己看的，不用念给用户听

## 模板二：`考 NN`

```
1/5 摸底   2 题一次出完，挑本课最高频的两个考点，真题优先
2/5 对答案 对的只报「对」，不展开 ← 效率全在这一步
3/5 补讲   只有错的那几个考点，回讲义对应小节完整讲一遍
4/5 验收   同考点换一道再考
5/5 收口   同上
```

**第 2 步是这个模式存在的理由。** 用户私下复习过的部分不许再讲一遍，那是在浪费他的一小时。

**摸底那 2 题一起出，这是本模式唯一的例外**——摸底要的就是先看清全貌再决定补讲什么，拆开出就退化成边考边讲了。第 3 步的补讲仍然分节交付，第 4 步的验收题一次一道。

若用户想被多考几道，他会说；不要自作主张加量。**教学阶段不是刷题阶段。**

## 模板三：答疑（不设指令，随时问）

```
1 定位   这问题属于讲义 NN 第几节的哪个考点，先说出来
2 直答   不绕，不铺垫
3 回检   一道小题，确认真懂了
4 归档   答错 → 进错题本；发现讲义本身有错 → 记进 讲义/_修订记录.md
```

答对了就过，不追加。

**若答疑是从某节课中途岔出来的**，答完按断点协议报一句「回到第 X 节末尾。继续？」，不重讲已过的部分。

## 状态文件协议

### `进度/掌握度.md`

53 行总表，每次收口更新对应行的**状态、最近一次、未清错题**三列。

| 状态 | 判定 |
|---|---|
| ⬜ 未碰 | 还没上过 |
| 📖 已讲 | 讲过或考过，但名下还有未清错题 |
| ✅ 通过 | 随堂 2 题全对，且名下无未清错题 |
| ⚠️ 待补 | 随堂题错一半以上 |

📖 转 ✅ 的条件：该课名下的错题两格勾满且重刷正确。

### `进度/上课记录.md`

收口时追加一行，**最新在上**：`日期 | 课 | 模式 | 随堂 | 错题 | 状态变化 | 备注`。
随堂列写 `2/2` 这种正确率，错题列写编号，没有写 `—`。

### `错题本/错题.md`

按模板追加，编号连续。重刷两格：**7 天后**（写绝对日期）、**考前**。

## 不做什么

- **不做批量刷题模式。** 「复习阶段多做题」是另一种形状的需求（按考点批量出题、按错题本靶向刷），等概念轮走完再单独设计。现在做等于猜需求。
- **不因为答错就当场强制重讲重练**（阶段 A 规则）。告知对错、错题入库、推进。用户主动要求重讲才重讲。
- **不催进度、不评论学习节奏**，除非用户主动问。
- **不编题**：题目优先取讲义「练习」里的真题；不够了才按讲义「考试怎么考」列的考点自编，且必须标 `【模拟】`，遵守 CLAUDE.md 的内容保真规则。
